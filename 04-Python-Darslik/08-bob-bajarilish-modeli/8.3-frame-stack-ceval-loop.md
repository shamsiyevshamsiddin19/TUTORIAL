# Frame stack va ceval loop — VM ichida sayohat

## Bu darsda nimalarni o'rganasiz

- **Frame object** (freym obyekti) nima ekanini va u qaysi ma'lumotlarni saqlashini bilib olasiz
- **Call stack** (chaqiruvlar stack'i) qanday ishlashini va rekursiya bilan qanday bog'liqligini tushunasiz
- CPython'ning markaziy ijro sikli — **ceval loop** (`_PyEval_EvalFrameDefault`) qanday ishlashini bilib olasiz
- `sys._getframe()` va `traceback` moduli orqali freymlar bilan amaliy ishlashni o'rganasiz

## Nazariy qism

### Frame object — "hozir men qayerdaman"

8.1-darsda code obyekt — kompilyatsiyaning **statik** natijasi (o'zgarmas bytecode va metama'lumotlar) ekanini ko'rdik. Lekin funksiya bir necha marta, hattoki bir vaqtning o'zida (rekursiya orqali) chaqirilishi mumkin — va har bir chaqiruv o'zining **joriy holati**ga ega bo'lishi kerak: qaysi lokal o'zgaruvchilarga qanday qiymat berilgan, bytecode'ning qaysi qatorida turibmiz, stack'da hozir nima bor. Aynan shu **dinamik, har bir chaqiruvga xos** holatni saqlaydigan tuzilma — **frame object** (freym obyekti) deb ataladi.

**Manba:** Ushbu dars CPython'ning rasmiy `InternalDocs/interpreter.md` va `InternalDocs/frames.md` hujjatlari asosida tuzilgan.

Soddalashtirib aytganda: **code object — "retsept"**, **frame object — "retsept bo'yicha pishirilayotgan, aynan hozirgi taomning holati"**. Bitta retseptdan bir vaqtning o'zida bir necha marta (masalan, rekursiv chaqiruvlarda) foydalanish mumkin, va har birining o'z, mustaqil holati bo'ladi.

```python
def rekursiv_faktorial(n):
    if n <= 1:
        return 1
    return n * rekursiv_faktorial(n - 1)

# rekursiv_faktorial(5) chaqirilganda, BITTA code obyektidan foydalangan holda
# BESHTA alohida frame object yaratiladi (n=5, n=4, n=3, n=2, n=1 uchun),
# har biri o'zining "n" qiymatini alohida saqlaydi!
```

### Call stack — freymlarning "uyumi"

Har safar funksiya chaqirilganda, yangi frame object yaratiladi va **call stack**ka (chaqiruvlar stack'iga) qo'yiladi (push). Funksiya tugagach (yoki `return` qaytarganda), uning freymi stack'dan olib tashlanadi (pop), va boshqaruv uni chaqirgan freymga qaytadi. Bu — nafaqat Python'da, balki deyarli **barcha** dasturlash tillarida (C, Java, ...) funksiya chaqiruvlarining universal mexanizmi.

```python
def uchinchi():
    # bu yerda call stack: [modul, birinchi, ikkinchi, uchinchi]
    print("Eng chuqurda")

def ikkinchi():
    uchinchi()

def birinchi():
    ikkinchi()

birinchi()
```

`Traceback` (xatolik yuz berganda ko'rsatiladigan "qatorlar zanjiri") — aynan shu call stack'ning **shu paytdagi holatining** aks etishi:

```python
def c():
    raise ValueError("Xatolik shu yerda!")

def b():
    c()

def a():
    b()

a()
```

Xato yuz berganda ko'rasiz:

```
Traceback (most recent call last):
  File "misol.py", line 10, in <module>
    a()
  File "misol.py", line 8, in a
    b()
  File "misol.py", line 5, in b
    c()
  File "misol.py", line 2, in c
    raise ValueError("Xatolik shu yerda!")
ValueError: Xatolik shu yerda!
```

Bu — aynan chaqiruvlar stack'ining, eng eskisidan (`a()` chaqirilishi) eng yangisigacha (`raise` qatori) bosqichma-bosqich ko'rsatilishi.

### Frame object ichida nima bor

Frame object, boshqa narsalar qatori, quyidagilarni saqlaydi:

- **`f_code`** — bu freym qaysi code obyekt asosida ishlayotgani
- **`f_locals`** — bu freymning lokal o'zgaruvchilari (dict ko'rinishida taqdim etiladi)
- **`f_globals`** — modul darajasidagi global o'zgaruvchilar
- **`f_back`** — bu freymni **chaqirgan** freymga havola (aynan shu maydon call stack'ni "bog'langan ro'yxat" — linked list — sifatida ushlab turadi!)
- **`f_lasti`** — hozir bajarilayotgan bytecode buyrug'ining ofseti (traceback'da qator raqamini hisoblash uchun ishlatiladi)
- Qiymat stack'i (value stack) — 8.2-darsda ko'rgan `LOAD_FAST`/`BINARY_OP` kabi opcode'lar ishlatadigan vaqtinchalik stack

```python
import sys

def ichki_funksiya():
    x = 42
    freym = sys._getframe()   # HOZIRGI freymning o'zini olish (odatda faqat debugging uchun)
    print("Lokal o'zgaruvchilar:", freym.f_locals)
    print("Chaqirgan freym:", freym.f_back.f_code.co_name)
    print("Hozirgi qator:", freym.f_lineno)

def tashqi_funksiya():
    ichki_funksiya()

tashqi_funksiya()
```

**Diqqat:** `sys._getframe()` — nomidagi pastki chiziq (`_`) ko'rsatib turganidek, bu **ichki, "yarim-rasmiy"** API — u asosan debugger va profiler kabi vositalar tomonidan ishlatiladi, oddiy dastur mantig'ida ishlatilishi tavsiya etilmaydi.

### Ceval loop — VM'ning "yuragi"

Endi eng muhim savolga kelamiz: bytecode'ni **kim, qanday** bajaradi? Javob — CPython manba kodidagi `Python/ceval.c` faylida joylashgan **`_PyEval_EvalFrameDefault`** funksiyasi, norasmiy ravishda **"ceval loop"** deb ataladi. Bu — mohiyatan, katta **`while` sikli**, uning ichida **`switch` operatori** bor, va har bir iteratsiyada:

1. Joriy freymning `f_lasti` ko'rsatib turgan bytecode buyrug'i o'qiladi.
2. Buyruqning opcode'i (masalan `LOAD_FAST`) va argumenti aniqlanadi.
3. `switch` operatorida shu opcode'ga mos **case** blokiga o'tiladi va tegishli amal (masalan, qiymat stack'ga qo'yiladi) bajariladi.
4. `f_lasti` keyingi buyruqqa siljiydi (yoki, sakrash buyrug'i bo'lsa, ko'rsatilgan boshqa joyga o'tadi).
5. Sikl davom etadi — **funksiya `RETURN_VALUE`ga yetguncha yoki istisno (`raise`) yuz berguncha**.

Soddalashtirilgan psevdokod (haqiqiy C kodi ancha murakkab va optimallashtirilgan, lekin mantiq shu):

```c
// juda soddalashtirilgan psevdokod, HAQIQIY ceval.c emas!
while (1) {
    opcode = freym->bytecode[freym->f_lasti];
    switch (opcode) {
        case LOAD_FAST:
            stack_push(freym->locals[arg]);
            break;
        case BINARY_OP:
            b = stack_pop();
            a = stack_pop();
            stack_push(a + b);   // (soddalashtirilgan — aslida turlar tekshiriladi)
            break;
        case RETURN_VALUE:
            return stack_pop();
        // ... yana o'nlab case'lar
    }
    freym->f_lasti += 1;
}
```

Funksiya boshqa funksiyani chaqirganda (`CALL` opcode'i), ceval loop **yangi freym** yaratadi va (soddalashtirib aytganda) shu yangi freym uchun **o'zini rekursiv chaqiradi** (yoki, yangi versiyalarda, ichki "frame almashtirish" orqali samaraliroq amalga oshiriladi) — shu tarzda call stack ham, C darajasidagi haqiqiy chaqiruvlar zanjiri ham parallel ravishda o'sib boradi.

### Nega chuqur rekursiya `RecursionError` beradi

Python'ning standart rekursiya chegarasi (odatda 1000 ga yaqin) — aynan **call stack**ning cheksiz o'smasligini ta'minlash uchun mavjud. Har bir Python darajasidagi funksiya chaqiruvi, ma'lum darajada, C darajasidagi stack chuqurligiga ham ta'sir qiladi, va operatsion tizim C stack'ining o'lchami cheklangan — agar chegara bo'lmasa, juda chuqur rekursiya dasturni halokatli tarzda "segmentation fault" bilan yiqitishi mumkin edi. `RecursionError` — bu halokatdan **oldin**, boshqariladigan tarzda to'xtash imkonini beradi.

```python
import sys

print("Standart rekursiya chegarasi:", sys.getrecursionlimit())

def cheksiz_rekursiya(n=0):
    return cheksiz_rekursiya(n + 1)

try:
    cheksiz_rekursiya()
except RecursionError as e:
    print("RecursionError ushlandi:", e)
```

## Amaliy misol

Call stack'ni qo'lda, `traceback` moduli yordamida tekshirish va rekursiya chuqurligini kuzatish:

```python
# frame_demo.py
import sys
import traceback


def joriy_stackni_korsat(chuqurlik_nomi):
    """Hozirgi call stack'ning to'liq zanjirini ko'rsatadi."""
    print(f"\n--- {chuqurlik_nomi} nuqtasida call stack ---")
    for qator in traceback.format_stack():
        print(qator, end="")


def daraja_uch():
    joriy_stackni_korsat("daraja_uch")


def daraja_ikki():
    daraja_uch()


def daraja_bir():
    daraja_ikki()


def rekursiya_chuqurligi_hisoblash(n=0):
    """Har chaqiruvda o'zining chuqurligini chop etadi va freymlar
    orasidagi bog'lanishni (f_back) kuzatadi."""
    freym = sys._getframe()
    chuqurlik = 0
    joriy = freym
    while joriy is not None:
        chuqurlik += 1
        joriy = joriy.f_back
    if n < 5:
        print(f"n={n}: hozirgi call stack chuqurligi (f_back orqali sanaldi) = {chuqurlik}")
        rekursiya_chuqurligi_hisoblash(n + 1)


if __name__ == "__main__":
    daraja_bir()
    print("\n" + "=" * 60)
    rekursiya_chuqurligi_hisoblash()
```

Bu dastur ikki narsani ko'rsatadi: birinchisi — `traceback.format_stack()` orqali, hozirgi ijro nuqtasidagi to'liq chaqiruvlar zanjirini; ikkinchisi — `f_back` havolalari orqali, freymlarning haqiqatan **bog'langan ro'yxat** (linked list) sifatida saqlanishini, chunki har safar chuqurlik funksiyasi o'zi va o'zidan oldingi barcha freymlarni sanab chiqadi.

## Keng tarqalgan xatolar

**Xato 1:** `sys._getframe()` yoki `f_locals`ni oddiy dastur mantig'ida (masalan, o'zgaruvchi qiymatlarini "sehrli" tarzda o'qish uchun) ishlatish.
❌
```python
def funksiya():
    x = 10
    freym = sys._getframe()
    y = freym.f_locals['x'] * 2   # ishlaydi, lekin bu KODNI TUSHUNARSIZ va MO'RT qiladi
```
✅ To'g'ri: `sys._getframe()` va freym introspektsiyasi — faqat debugger, profiler yoki maxsus vositalar yozish uchun mo'ljallangan. Oddiy dasturda o'zgaruvchini shunchaki to'g'ridan-to'g'ri ishlating (`y = x * 2`). Bundan tashqari, `f_locals` ba'zi hollarda (masalan optimallashtirilgan freymlarda) faqat **nusxa**, uni o'zgartirish haqiqiy o'zgaruvchiga ta'sir qilmasligi mumkin.

**Xato 2:** Chuqur rekursiyani (masalan, katta ro'yxatni qayta ishlash uchun) hech qanday chegarasiz ishlatish.
❌
```python
def royxat_yigindisi(royxat):
    if not royxat:
        return 0
    return royxat[0] + royxat_yigindisi(royxat[1:])   # 10000 elementli ro'yxatda RecursionError!
```
✅ To'g'ri: katta ma'lumot bilan ishlaganda, rekursiya o'rniga sikl (`for`/`while`) ishlatish yoki (agar rekursiya shart bo'lsa) generatorlar/iterativ algoritmlardan foydalanish tavsiya etiladi — Python'da, ba'zi funksional tillardan farqli, **tail-call optimization** (oxirgi chaqiruvni siklga aylantirish) yo'q, shuning uchun har bir rekursiv chaqiruv haqiqatan yangi freym yaratadi.

**Xato 3:** `traceback`dagi qator raqamlarini "aniq, hech qachon noto'g'ri bo'lmaydigan" deb hisoblash, ayniqsa ko'p qatorli ifodalarda.
❌ Uzun, ko'p qatorli ifodada xatolik chiqqanda, traceback ko'rsatgan qatorni "bevosita, boshqa joyni tekshirmasdan" xato manbai deb hisoblash.
✅ To'g'ri: Python 3.11+da traceback'lar sezilarli aniqlashtirildi (endi hattoki bitta qator ichida qaysi **aniq submodul** (masalan, `a.b.c` zanjiridagi qaysi nuqta) xato berganini ko'rsatadi), lekin baribir kontekstni — atrofdagi kodni — ko'rib chiqish har doim foydali, chunki ba'zan haqiqiy sabab boshqa, oldingi qatorda bo'ladi (masalan, noto'g'ri boshlang'ich qiymat berilgan bo'lishi mumkin).

## Mashq/topshiriq

**(Oson)** `sys.getrecursionlimit()` va `sys.setrecursionlimit()` funksiyalarini ishlatib, standart chegarani chop eting, so'ng uni vaqtincha `100`ga o'zgartirib, cheksiz rekursiya qanchalik tezroq `RecursionError` berishini kuzating.

**(O'rtacha)** Uch darajali funksiya chaqiruvlar zanjiri yozing (`a() -> b() -> c()`), va `c()` ichida `traceback.format_stack()` yordamida to'liq call stack'ni chop eting. Nechta qatorli natija chiqishini va nima uchun aynan shuncha ekanligini tushuntiring.

**(Qiyin)** Rekursiv Fibonachchi funksiyasini (`fib(n) = fib(n-1) + fib(n-2)`) yozing va `sys._getframe().f_back` zanjiri orqali, `fib(5)` chaqirilganda **eng chuqur** nuqtada call stack qanchalik chuqur bo'lishini hisoblang (izoh: bu oddiy `n` emas, chunki fib rekursiyasi **daraxt** shaklida, chiziqli emas). Natijani `dis.dis(fib)` bilan chiqargan bytecode'dagi `CALL` opcode'i sonini hisoblash bilan solishtiring va farqni izohlang.

## Qisqacha xulosa

Har bir funksiya chaqiruvi CPython'da yangi **frame object** yaratadi — bu obyekt o'sha aniq chaqiruvning lokal o'zgaruvchilari, joriy bytecode pozitsiyasi va o'zini chaqirgan freymga havolani (`f_back`) saqlaydi, va aynan shu `f_back` zanjiri **call stack**ni tashkil qiladi (bu — traceback'larning manbai). Bu freymlar ustida bytecode'ni bajaradigan markaziy mexanizm — **ceval loop** (`_PyEval_EvalFrameDefault`, `Python/ceval.c` faylida) — bu, mohiyatan, har bir opcode uchun mos amalni bajaradigan katta `switch` operatorli sikl. Rekursiya chegarasi (`RecursionError`) — aynan shu call stack'ning cheksiz o'sib, dasturni halokatga olib kelishining oldini olish uchun mavjud.
