# 14.1. Birinchi C kengaytma modulini yozish

## Bu darsda nimalarni o'rganasiz

- Python C API nima va u nima uchun mavjud
- `Python.h`, `PyObject*`, `PyMethodDef`, `PyModuleDef` — asosiy qurilish bloklari
- `PyArg_ParseTuple()` bilan Python argumentlarini C qiymatlariga o'girish
- `Py_BuildValue()` bilan C qiymatlarini Python obyektlariga qaytarish
- Kengaytmani `setuptools` bilan qurish va Python'dan oddiy modul kabi import qilish

## Nazariy qism

**Manba:** [Python rasmiy dokumentatsiyasi — Extending Python with C or C++](https://docs.python.org/3/extending/extending.html), [Real Python — Building a Python C Extension Module](https://realpython.com/build-python-c-extension-module/).

### Nima uchun C API mavjud

Ushbu darslikning 7-13-boblarida CPython'ning ichki qurilishini — obyektlar, reference counting, bytecode, GIL — "tashqaridan" o'rgandik. Bu bobda esa teskari tomondan qaraymiz: **o'zimiz** C tilida CPython bilan to'g'ridan-to'g'ri "gaplasha oladigan" kod yozamiz. Aynan shu mexanizm orqali NumPy, lxml, kriptografiya kutubxonalari va son-sanoqsiz boshqa yuqori unumdorlikdagi Python paketlari qurilgan.

Python C API — bu CPython interpretatori taqdim etadigan funksiyalar, makrolar va tiplar to'plami bo'lib, C (yoki C++) kodiga Python obyektlarini yaratish, ularning metodlarini chaqirish, xatolarni ko'tarish va — eng muhimi — **Python'dan chaqirilishi mumkin bo'lgan yangi funksiya va modullar yaratish** imkonini beradi. 13.3-darsda ko'rgan `ctypes`/`cffi` **mavjud** C kutubxonalarini chaqirish uchun edi; C API esa aksincha — **Python'ning o'zi uchun** yangi, native kengaytma yaratish uchun ishlatiladi.

### `PyObject*` — hamma narsaning asosi

7-bobda ko'rganimizdek, CPython'da **har bir** Python qiymati (`int`, `str`, `list`, funksiya, hattoki `None`) xotirada `PyObject` sarlavhasi bilan boshlanadigan struktura sifatida yashaydi. C API darajasida bu haqiqat yanada aniqroq ko'rinadi: deyarli barcha C API funksiyalari `PyObject*` (Python obyektiga ko'rsatkich) qabul qiladi yoki qaytaradi — bu C kodi va Python interpretatori orasidagi "universal til".

```c
#include <Python.h>

// Bu funksiya ikkita Python obyektini (odatda int yoki float) qabul qilib,
// ularning yig'indisini Python obyekti sifatida qaytaradi.
static PyObject* mening_qoshish(PyObject* self, PyObject* args) {
    double a, b;
    if (!PyArg_ParseTuple(args, "dd", &a, &b)) {
        return NULL;  // xato — PyArg_ParseTuple allaqachon mos istisno o'rnatgan
    }
    return Py_BuildValue("d", a + b);
}
```

### `PyArg_ParseTuple()` — Python argumentlarini C'ga o'girish

Python'dan `mening_modul.qoshish(3.5, 2.1)` deb chaqirilganda, C funksiyasi `args` parametri sifatida bitta `PyObject*` (Python `tuple`, `(3.5, 2.1)`) oladi. `PyArg_ParseTuple()` bu tuple'ni "format satri" asosida C o'zgaruvchilariga ajratib beradi:

- `"d"` — `double`
- `"i"` — `int`
- `"s"` — `const char*` (Python `str`, UTF-8 kodlangan C satrga)
- `"O"` — xom `PyObject*` (o'zgartirishsiz)

Format satridagi har bir belgi keyingi argumentga (`&a`, `&b` kabi, ko'rsatkich orqali) mos keladi. Agar Python tomonidan uzatilgan argumentlar mos kelmasa (masalan, satr uzatilgan bo'lsa-yu, `"dd"` ikkita son kutayotgan bo'lsa), `PyArg_ParseTuple()` avtomatik ravishda `TypeError` o'rnatadi va `0` (yolg'on) qaytaradi — shuning uchun C kodi bu holatni tekshirib, `NULL` qaytarishi shart.

### `Py_BuildValue()` — C qiymatlarini Python'ga qaytarish

`Py_BuildValue()` — `PyArg_ParseTuple()`ning "teskarisi": C qiymatlaridan yangi Python obyektini quradi, xuddi shunday format belgilaridan foydalanib:

```c
Py_BuildValue("d", 5.6);           // Python float 5.6
Py_BuildValue("i", 42);            // Python int 42
Py_BuildValue("(ii)", 1, 2);       // Python tuple (1, 2)
Py_BuildValue("s", "salom");       // Python str "salom"
```

### `PyMethodDef` — modulda qanday funksiyalar borligini e'lon qilish

Har bir C funksiyasi Python'dan ko'rinishi uchun, uni **`PyMethodDef`** massivida ro'yxatga olish kerak — bu Python nomini C funksiya ko'rsatkichiga, chaqiruv konventsiyasiga va docstring'ga bog'laydi:

```c
static PyMethodDef MeningMetodlarim[] = {
    {"qoshish", mening_qoshish, METH_VARARGS, "Ikkita sonni qo'shadi."},
    {NULL, NULL, 0, NULL}  // ro'yxat tugashini bildiruvchi "sentinel" yozuv
};
```

`METH_VARARGS` bayrog'i — funksiya oddiy `(self, args)` imzosiga ega, pozitsion argumentlarni tuple sifatida qabul qilishini bildiradi (`METH_KEYWORDS` kalit so'z argumentlarini ham qo'shadi, `METH_NOARGS` — argumentsiz funksiyalar uchun).

### `PyModuleDef` — modulning o'zini e'lon qilish

```c
static struct PyModuleDef mening_modulim = {
    PyModuleDef_HEAD_INIT,
    "mening_modulim",        // modul nomi (Python'da import qilinadigan nom)
    "Mening birinchi C kengaytma modulim.",  // modul docstring
    -1,                       // modul holati hajmi (-1 = global holat)
    MeningMetodlarim
};

PyMODINIT_FUNC PyInit_mening_modulim(void) {
    return PyModule_Create(&mening_modulim);
}
```

`PyInit_<modul_nomi>` funksiyasi — bu **majburiy** nomlanish qoidasi: Python import tizimi (11-bobda ko'rganimizdek) kengaytma modulini yuklaganda, aynan shu nomdagi funksiyani qidiradi va chaqiradi. Agar modul nomi `mening_modulim` bo'lsa, ishga tushirish funksiyasi aynan `PyInit_mening_modulim` deb nomlanishi **shart**.

### Qurish: `setuptools` orqali kompilyatsiya

```python
# setup.py
from setuptools import setup, Extension

modul = Extension("mening_modulim", sources=["mening_modulim.c"])

setup(
    name="mening_modulim",
    version="1.0",
    ext_modules=[modul],
)
```

```bash
python setup.py build_ext --inplace
```

Bu buyruq C kompilyatorini (GCC, Clang yoki MSVC) chaqirib, `.c` faylni platformaga xos dinamik kutubxonaga (`.so` Linux'da, `.pyd` Windows'da) aylantiradi — natijada hosil bo'lgan fayl oddiy Python moduli kabi `import mening_modulim` bilan yuklanadi, va u ichida sof C tezligida bajariladigan `qoshish()` funksiyasi mavjud bo'ladi.

## Amaliy misol

To'liq, ishlaydigan C kengaytma moduli — matematik `tezkor_fibonacci` funksiyasini C'da amalga oshiramiz (13.3-darsda Cython bilan solishtirilgan g'oyaning "xom" C API versiyasi):

```c
/* fib_module.c — C API'da fibonacci hisoblovchi kengaytma moduli. */
#include <Python.h>

static PyObject* fib_hisobla(PyObject* self, PyObject* args) {
    long n;
    if (!PyArg_ParseTuple(args, "l", &n)) {
        return NULL;
    }
    if (n < 0) {
        PyErr_SetString(PyExc_ValueError, "n manfiy bo'lmasligi kerak");
        return NULL;
    }

    long a = 0, b = 1;
    for (long i = 0; i < n; i++) {
        long keyingi = a + b;
        a = b;
        b = keyingi;
    }
    return Py_BuildValue("l", a);
}

static PyMethodDef FibMetodlar[] = {
    {"hisobla", fib_hisobla, METH_VARARGS,
     "n-chi Fibonachchi sonini C tezligida hisoblaydi."},
    {NULL, NULL, 0, NULL}
};

static struct PyModuleDef fib_modul = {
    PyModuleDef_HEAD_INIT,
    "fib_module",
    "C tezligidagi Fibonachchi hisoblagichi.",
    -1,
    FibMetodlar
};

PyMODINIT_FUNC PyInit_fib_module(void) {
    return PyModule_Create(&fib_modul);
}
```

```python
# setup.py
from setuptools import setup, Extension

setup(
    name="fib_module",
    ext_modules=[Extension("fib_module", sources=["fib_module.c"])],
)
```

```bash
python setup.py build_ext --inplace
```

```python
# ishlatish_demo.py
import time
import fib_module


def fibonacci_python(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a


boshlanish = time.perf_counter()
for _ in range(200_000):
    fibonacci_python(30)
vaqt_python = time.perf_counter() - boshlanish

boshlanish = time.perf_counter()
for _ in range(200_000):
    fib_module.hisobla(30)
vaqt_c = time.perf_counter() - boshlanish

print(f"Sof Python: {vaqt_python:.3f}s")
print(f"C kengaytma: {vaqt_c:.3f}s")
print(f"Tezlashish: {vaqt_python / vaqt_c:.1f}x")
```

Chiqishi taxminan:

```
Sof Python: 1.842s
C kengaytma: 0.089s
Tezlashish: ~20.7x
```

## Keng tarqalgan xatolar

1. **`PyInit_<nom>` funksiyasi nomini modul nomiga mos qilib yozmaslik.** Agar `Extension("fib_module", ...)` deb e'lon qilingan bo'lsa-yu, C faylida `PyInit_boshqa_nom` deb yozilgan bo'lsa, import paytida `ImportError: dynamic module does not define module export function` xatosi chiqadi.

2. **`PyArg_ParseTuple()` muvaffaqiyatsiz bo'lganda `NULL` qaytarishni unutish.** Agar funksiya `PyArg_ParseTuple()` `0` qaytarganidan keyin ham davom etsa, C kodi haqiqiy qiymatlarga ega bo'lmagan (initsializatsiya qilinmagan) o'zgaruvchilar bilan ishlashga urinadi — bu noaniq xatti-harakat (undefined behavior) yoki segmentation fault'ga olib kelishi mumkin.

3. **`setup.py`da manba fayl yo'lini yoki nomini xato yozish.** `Extension()`ning birinchi argumenti (modul nomi) va `sources` ro'yxatidagi haqiqiy `.c` fayl bir-biriga mos, to'g'ri yo'lda bo'lishi kerak — aks holda `build_ext` kompilyatsiya xatosi bilan to'xtaydi.

## Mashq/topshiriq

1. `fib_module.c`ga yangi funksiya qo'shing: `kvadrat(x)` — bitta `long` qabul qilib, uning kvadratini qaytaradi. `PyMethodDef` massiviga yangi yozuv qo'shishni unutmang.

2. `fib_hisobla` funksiyasini `n` juda katta (masalan, 100) bo'lganda C `long` overflow qilishini payqab, `PyErr_SetString(PyExc_OverflowError, ...)` bilan mos xato qaytaradigan qilib o'zgartiring (`n > 90` bo'lsa xato qaytaring, chunki 90-Fibonachchi soni allaqachon 64-bitli `long`ga sig'maydigan darajaga yaqinlashadi).

3. Nima uchun `Py_BuildValue("l", a)` chaqirilganda, C tomonidagi `long a` qiymati Python tomoniga "nusxalanadi", lekin Python tomonidagi obyekt C tomonidagi `a`ning o'zi (xotira manzili) BILAN bog'lanmasligini tushuntiring — bu 7-bobdagi immutability tushunchasi bilan qanday bog'liq?

**Javoblar:**

1.
```c
static PyObject* fib_kvadrat(PyObject* self, PyObject* args) {
    long x;
    if (!PyArg_ParseTuple(args, "l", &x)) {
        return NULL;
    }
    return Py_BuildValue("l", x * x);
}

static PyMethodDef FibMetodlar[] = {
    {"hisobla", fib_hisobla, METH_VARARGS, "n-chi Fibonachchi sonini hisoblaydi."},
    {"kvadrat", fib_kvadrat, METH_VARARGS, "Sonning kvadratini qaytaradi."},
    {NULL, NULL, 0, NULL}
};
```

2.
```c
static PyObject* fib_hisobla(PyObject* self, PyObject* args) {
    long n;
    if (!PyArg_ParseTuple(args, "l", &n)) {
        return NULL;
    }
    if (n < 0) {
        PyErr_SetString(PyExc_ValueError, "n manfiy bo'lmasligi kerak");
        return NULL;
    }
    if (n > 90) {
        PyErr_SetString(PyExc_OverflowError, "n juda katta — natija long chegarasidan oshadi");
        return NULL;
    }
    long a = 0, b = 1;
    for (long i = 0; i < n; i++) {
        long keyingi = a + b;
        a = b;
        b = keyingi;
    }
    return Py_BuildValue("l", a);
}
```

3. `Py_BuildValue("l", a)` chaqirilganda, CPython C darajasidagi `long a` qiymatini o'qiydi va shu qiymat asosida **butunlay yangi**, mustaqil Python `int` obyektini (xotirada alohida joylashgan `PyLongObject`) yaratadi. Bu — **qiymatning nusxasi**, C o'zgaruvchisi `a`ning o'ziga (uning stack'dagi xotira manziliga) hech qanday havola emas. Bu aynan 7-bobda ko'rgan immutability tamoyiliga mos keladi: Python `int` obyektlari o'zgarmas (immutable) bo'lgani uchun, ularni "tashqi", C darajasidagi o'zgaruvchiga bog'lash umuman ma'nosiz bo'lardi — agar keyinchalik C funksiyasi qaytib chiqib, uning stack freymi yo'q qilinsa (va `a` o'zgaruvchisi "yo'qolsa"), Python tomonidagi obyekt baribir **mustaqil, o'z holicha** yashashda davom etadi, chunki u allaqachon o'zining alohida, reference-counted xotira joyiga ega.

## Qisqacha xulosa

Python C API — CPython bilan to'g'ridan-to'g'ri C tilida "gaplashish" imkonini beruvchi funksiyalar va makrolar to'plami. Har bir C kengaytma funksiyasi `PyObject* funksiya(PyObject* self, PyObject* args)` imzosiga ega bo'lib, `PyArg_ParseTuple()` orqali Python argumentlarini C qiymatlariga o'giradi va `Py_BuildValue()` orqali natijani qaytadan Python obyektiga aylantiradi. `PyMethodDef` massivi qaysi funksiyalar Python'ga qanday nom bilan ochilishini belgilaydi, `PyModuleDef` va `PyInit_<nom>` esa modulning o'zini e'lon qiladi — bu nomlanish qoidasi import tizimi tomonidan qat'iy talab qilinadi. `setuptools`ning `Extension` klassi va `build_ext` buyrug'i C faylni platformaga xos dinamik kutubxonaga aylantirib, uni oddiy Python modulidek import qilinadigan qiladi — natijada sof C tezligidagi kod Python'dan tabiiy ravishda chaqiriladi. Keyingi darsda xotira boshqaruvi (`Py_INCREF`/`Py_DECREF` C kengaytmalar ichida), istisnolar bilan ishlash va real loyihalarda uchraydigan tipik xatolarni chuqurroq ko'rib chiqamiz.
