# 13.1. `cProfile` va `timeit` bilan profilash

## Bu darsda nimalarni o'rganasiz

- Nima uchun "avval o'lchash, keyin optimallashtirish" qoidasi muhim
- Deterministik profilash (`cProfile`) va statistik profilash o'rtasidagi farq
- `cProfile` chiqishini o'qish: `ncalls`, `tottime`, `cumtime`, `percall`
- `timeit` bilan kichik kod bo'laklarini aniq o'lchash
- `line_profiler` va `memory_profiler` kabi qo'shimcha vositalarga qisqacha kirish

## Nazariy qism

**Manba:** [Python rasmiy dokumentatsiyasi — The Python Profilers](https://docs.python.org/3/library/profile.html), [Real Python — Profiling in Python: How to Find Performance Bottlenecks](https://realpython.com/python-profiling/).

### "Oldindan optimallashtirish — barcha yovuzliklarning ildizi"

Donald Knuth'ning mashhur so'zlari — "premature optimization is the root of all evil" — Python dasturchilari uchun ayniqsa dolzarb. Sabab-natija intuitsiyasi (masalan, "bu tsikl sekin ko'rinadi") ko'pincha noto'g'ri bo'ladi — real dasturlarda vaqtning 80-90%'i odatda kodning kichik 10-20% qismida (bitta funksiya, bitta tsikl) sarflanadi, va bu qism ko'pincha dasturchi kutgan joy emas. Shuning uchun professional yondashuv: avval **o'lchash** (profilash), keyin faqat isbotlangan "qattiqroq (hot) yo'l"larni optimallashtirish.

### Deterministik vs statistik profilash

**Deterministik profilash** (`cProfile`, `profile` modullari) — har bir funksiya chaqiruvi va qaytishini **kuzatib boradi** (interpretator darajasida "hook" o'rnatiladi). Bu 100% aniq ma'lumot beradi (har bir chaqiruv sanaladi), lekin o'zi ma'lum darajada overhead qo'shadi — ayniqsa juda ko'p mayda funksiya chaqiruvlari bo'lgan kodda, profilashning o'zi dasturni sezilarli sekinlashtirishi mumkin.

**Statistik profilash** (masalan, `py-spy`, `austin` kabi tashqi vositalar) dasturni muntazam oraliqlarda (masalan, har millisekundda) "suratga oladi" (sample) — qaysi funksiya o'sha paytda bajarilayotganini yozib boradi. Bu kamroq overhead beradi (real vaqt ishlab turgan production dasturlarni ham profilash mumkin), lekin natija statistik taxmin, 100% aniq emas.

### `cProfile` — standart deterministik profiler

```python
import cProfile

def sekin_funksiya():
    natija = sum(i ** 2 for i in range(1_000_000))
    return natija

cProfile.run("sekin_funksiya()")
```

Chiqish jadvalidagi ustunlar:

- **`ncalls`** — funksiya necha marta chaqirilgani (agar rekursiya bo'lsa, `jami/primitiv` shaklida ko'rsatiladi).
- **`tottime`** — funksiyaning **o'zi ichida** (ichki chaqirilgan boshqa funksiyalarni hisobga olmasdan) sarflagan umumiy vaqt.
- **`percall`** (birinchi) — `tottime / ncalls`.
- **`cumtime`** — funksiya va u chaqirgan **barcha** funksiyalar (rekursiv ravishda) sarflagan umumiy vaqt.
- **`percall`** (ikkinchi) — `cumtime / ncalls` (faqat primitiv chaqiruvlar uchun).

`tottime` bo'yicha saralash odatda "aynan qaysi funksiyaning o'zi ko'p vaqt yeyapti" degan savolga javob beradi — bu optimallashtirish uchun eng foydali ko'rsatkich. `cumtime` esa "qaysi chaqiruv zanjiri umuman eng ko'p vaqt olyapti" degan savolga javob beradi.

```python
import cProfile
import pstats

profiler = cProfile.Profile()
profiler.enable()
sekin_funksiya()
profiler.disable()

stats = pstats.Stats(profiler)
stats.sort_stats(pstats.SortKey.TOTTIME)
stats.print_stats(10)  # eng "og'ir" 10 ta funksiyani ko'rsatish
```

### `timeit` — kichik kod bo'laklarini aniq o'lchash

`cProfile` butun dasturni yoki katta funksiyani profilash uchun mos, lekin "qaysi ikkita yozuv usuli tezroq" kabi mikro-o'lchov (micro-benchmark) uchun mos emas — chunki uning overhead'i kichik operatsiyalar farqini "yashiradi". `timeit` moduli buning uchun maxsus yaratilgan: u bergan kodni ko'p marta (standart holatda avtomatik tanlangan son) ishga tushiradi va eng ishonchli natijani qaytaradi, GC'ni vaqtincha o'chirib (natijaning "shovqin"ini kamaytirish uchun):

```python
import timeit

# str birlashtirish usullarini solishtirish
vaqt_join = timeit.timeit(
    "''.join(str(i) for i in range(100))",
    number=100_000,
)
vaqt_plus = timeit.timeit(
    "s = ''\nfor i in range(100): s += str(i)",
    number=100_000,
)
print(f"join: {vaqt_join:.3f}s, += : {vaqt_plus:.3f}s")
```

Buyruq qatoridan ham ishlatish mumkin:

```bash
python -m timeit -s "s = list(range(1000))" "sorted(s)"
```

### Qo'shimcha vositalar: `line_profiler` va `memory_profiler`

`cProfile` faqat **funksiya** darajasida ma'lumot beradi — agar bitta funksiya ichida qaysi **aniq qator** eng ko'p vaqt olayotganini bilish kerak bo'lsa, uchinchi tomon `line_profiler` kutubxonasi (`@profile` dekoratori bilan) qator-qator vaqtni ko'rsatadi. Xuddi shunday, `memory_profiler` xotira sarfini qator-qator kuzatish imkonini beradi. Bular standart kutubxonaga kirmaydi (`pip install line_profiler memory_profiler` orqali o'rnatiladi).

## Amaliy misol

```python
"""
profiling_demo.py — cProfile va timeit'ni birga ishlatish demosi.
"""
import cProfile
import pstats
import timeit
from io import StringIO


def fibonacci_rekursiv(n: int) -> int:
    if n < 2:
        return n
    return fibonacci_rekursiv(n - 1) + fibonacci_rekursiv(n - 2)


def fibonacci_memoized(n: int, kesh: dict | None = None) -> int:
    if kesh is None:
        kesh = {}
    if n < 2:
        return n
    if n in kesh:
        return kesh[n]
    natija = fibonacci_memoized(n - 1, kesh) + fibonacci_memoized(n - 2, kesh)
    kesh[n] = natija
    return natija


def dastur():
    a = fibonacci_rekursiv(24)
    b = fibonacci_memoized(24)
    assert a == b
    return a


def cprofile_demo():
    profiler = cProfile.Profile()
    profiler.enable()
    dastur()
    profiler.disable()

    oqim = StringIO()
    stats = pstats.Stats(profiler, stream=oqim)
    stats.sort_stats(pstats.SortKey.TOTTIME)
    stats.print_stats(5)
    print(oqim.getvalue())


def timeit_demo():
    vaqt_rekursiv = timeit.timeit(lambda: fibonacci_rekursiv(20), number=50)
    vaqt_memo = timeit.timeit(lambda: fibonacci_memoized(20), number=50)
    print(f"fibonacci_rekursiv(20) x50: {vaqt_rekursiv:.4f}s")
    print(f"fibonacci_memoized(20) x50: {vaqt_memo:.4f}s")
    print(f"Tezlashish: {vaqt_rekursiv / vaqt_memo:.1f}x")


if __name__ == "__main__":
    print("=== cProfile natijasi ===")
    cprofile_demo()
    print("=== timeit natijasi ===")
    timeit_demo()
```

Chiqishi taxminan ko'rsatadiki, `fibonacci_rekursiv` uchun `ncalls` juda katta son (chunki eksponensial rekursiya), `tottime` ham katta bo'ladi, `fibonacci_memoized` esa `ncalls` va `tottime` jihatidan sezilarli kichikroq — bu profiling orqali aniq ko'rinadi, taxmin qilish shart emas.

## Keng tarqalgan xatolar

1. **Butun dasturni "his qilish" asosida optimallashtirish, profilashsiz.** Ko'pincha dasturchi "sekin" deb o'ylagan joy aslida umumiy vaqtning kichik qismini tashkil qiladi, real "og'ir" joy esa boshqa yerda bo'ladi. Har doim avval o'lchang.

2. **`timeit` bilan juda kichik `number` qiymatidan foydalanish.** Agar kod juda tez bajarilsa va `number` kichik bo'lsa, o'lchov natijasi tizim shovqiniga (boshqa jarayonlar, kesh holati) ko'proq bog'liq bo'lib qoladi. `timeit.timeit()`ning parametrsiz chaqirilishi (yoki `python -m timeit`) odatda avtomatik ravishda yetarlicha katta takrorlash sonini tanlaydi.

3. **`cProfile` natijasidagi `cumtime`ni `tottime` o'rniga optimallashtirish maqsadi qilib olish.** `cumtime` yuqori funksiya, odatda `main()` kabi, deyarli har doim eng yuqori `cumtime`ga ega bo'ladi (chunki u hammasini o'z ichiga oladi) — bu ma'lumot bermaydi. Qaysi funksiyaning **o'zi** (ichki chaqiruvlarsiz) ko'p vaqt yeyotganini bilish uchun `tottime`ga qarang.

## Mashq/topshiriq

1. `dastur()` funksiyasini `cProfile.run("dastur()")` bilan (obyekt yaratmasdan, to'g'ridan-to'g'ri) profilab, natijani `pstats.SortKey.CUMULATIVE` bo'yicha saralang va farqni tushuntiring.

2. `timeit`dan foydalanib, `list` va `tuple`da elementga indeks orqali murojaat qilish tezligini solishtiring (`lst[500]` vs `tpl[500]`, har biri 1000 elementli). Natija va sababini bir gapda tushuntiring (10-bobda ko'rgan list/tuple ichki tuzilishiga tayanib).

3. Nima uchun `cProfile`ning o'zi qo'shadigan overhead ba'zan "qaysi funksiya tezroq" degan **nisbiy** taqqoslashga unchalik ta'sir qilmasligini, lekin **mutlaq** vaqt qiymatlarini (masalan, "bu funksiya 2 sekund oladi") ishonchli o'lchov sifatida ishlatib bo'lmasligini tushuntiring.

**Javoblar:**

1.
```python
cProfile.run("dastur()", sort="cumulative")
```
`CUMULATIVE` bo'yicha saralanganda `dastur()`ning o'zi va `fibonacci_rekursiv`ning eng tashqi chaqiruvi eng yuqorida chiqadi (chunki ular barcha ichki chaqiruvlarni o'z ichiga oladi), `TOTTIME` bo'yicha esa eng ko'p **shaxsiy** vaqt sarflagan (odatda eng ko'p marta chaqirilgan, eng chuqur rekursiya darajasidagi) funksiya chiqishi mumkin — ikkalasi ham `fibonacci_rekursiv`ga ishora qilishi mumkin, lekin katta, ko'p funksiyali dasturlarda bu ikki saralash butunlay boshqa-boshqa funksiyalarni "birinchi o'ringa" chiqarishi mumkin.

2. `list` va `tuple`ning ikkalasi ham 10-bobda ko'rganimizdek CPython ichida **bir xil turdagi** ko'rsatkichlar massivi (array of pointers) sifatida saqlanadi, va indeks orqali murojaat (`__getitem__`) ikkalasida ham O(1) — to'g'ridan-to'g'ri xotira manzilini hisoblab, ko'rsatkichni o'qish. Shuning uchun `timeit` natijasi ikkalasi uchun deyarli **bir xil** vaqt ko'rsatadi (farq bo'lsa ham, u statistik shovqin darajasida, tuple'ning engilroq obyekt sarlavhasi tufayli juda oz ustunligi bo'lishi mumkin) — `tuple`ning "o'zgarmasligi" indekslash tezligiga sezilarli ta'sir qilmaydi, chunki bu operatsiya hech qachon obyektni o'zgartirmaydi.

3. `cProfile` har bir funksiya chaqiruvi va qaytishida qo'shimcha "hook" kodini ishga tushiradi — bu barcha o'lchangan funksiyalarga **deyarli bir xilda** qo'shimcha vaqt qo'shadi (funksiya chaqiruvlari soniga proportsional). Shuning uchun agar funksiya A haqiqatda funksiya B'dan 3 marta tezroq bo'lsa, profiler ostida ham taxminan shu nisbat saqlanadi (ikkalasiga ham mutanosib overhead qo'shiladi) — nisbiy taqqoslash odatda ishonchli qoladi. Lekin profiler qo'shadigan **mutlaq** qo'shimcha vaqt (masalan, funksiya boshiga necha mikrosekund) profillanmagan (haqiqiy) ishga tushirish vaqtidan sezilarli farq qilishi mumkin — ayniqsa juda ko'p mayda chaqiruvli kodda profiler natijasidagi mutlaq vaqt haqiqiy production vaqtidan bir necha barobar katta bo'lishi mumkin.

## Qisqacha xulosa

Optimallashtirish har doim o'lchovdan boshlanishi kerak — intuitsiya ko'pincha aldaydi. `cProfile` — deterministik, funksiya darajasidagi profiler bo'lib, `tottime` (funksiyaning o'zi sarflagan vaqt) va `cumtime` (funksiya va uning barcha chaqiruvlari sarflagan umumiy vaqt) orqali "qattiq yo'l"larni aniq ko'rsatadi. `timeit` esa kichik kod bo'laklarini ko'p marta ishga tushirib, ishonchli mikro-benchmark natijasi beradi, GC kabi shovqin manbalarini nazorat qiladi. Qator darajasidagi yoki xotira profilash uchun `line_profiler` va `memory_profiler` kabi uchinchi tomon vositalar qo'llaniladi. Keyingi darsda profilash orqali topilgan "sekin" joylarni **qanday** tushunish va tuzatish kerakligini — algoritmik murakkablik nuqtai nazaridan — ko'rib chiqamiz.
