# 13.3. `ctypes`, `cffi` va Cython'ga kirish

## Bu darsda nimalarni o'rganasiz

- Nima uchun ba'zan sof Python yetarli tezlikni bera olmaydi
- `ctypes` — mavjud C kutubxonalarini Python'dan to'g'ridan-to'g'ri chaqirish
- `cffi` — `ctypes`ga muqobil, ko'proq "C-native" yondashuv
- Cython — Python-ga o'xshash sintaksis bilan C tezligiga erishish
- Uchtasini qachon, qaysi holatda tanlash kerakligi

## Nazariy qism

**Manba:** Python rasmiy dokumentatsiyasi (`ctypes` moduli), Cython rasmiy dokumentatsiyasi, `cffi` rasmiy dokumentatsiyasi.

### Nega C bilan integratsiya kerak bo'ladi

13.2-darsda ko'rganimizdek, ba'zan algoritmik va Python darajasidagi optimallashtirish yetarli bo'lmaydi — sof Python interpretatsiya overhead'i (har bir operatsiya uchun tip tekshiruvi, bytecode dispetcherlash, reference counting) haddan tashqari katta bo'lib qoladi, ayniqsa millionlab marta takrorlanadigan raqamli hisoblashlarda. Bunday holatlarda uchta asosiy yo'l mavjud: mavjud C kutubxonasini chaqirish (`ctypes`/`cffi`), yoki Python'ga o'xshash kodni to'g'ridan-to'g'ri C'ga kompilyatsiya qilish (Cython).

### `ctypes` — standart kutubxonadagi C ko'prigi

`ctypes` — Python'ning standart kutubxonasiga kiritilgan modul bo'lib, u **dinamik kutubxonalar** (`.so` Linux'da, `.dll` Windows'da, `.dylib` macOS'da) bilan hech qanday kompilyatsiya bosqichisiz, to'g'ridan-to'g'ri ishlashga imkon beradi:

```python
import ctypes

# Standart C kutubxonasidan funksiya chaqirish
libc = ctypes.CDLL("libc.so.6")  # Linux uchun; Windows'da ctypes.windll ishlatiladi
libc.printf(b"Salom, %s!\n", b"C dunyosi")
```

`ctypes` C funksiya imzolarini (argument va qaytish tiplarini) qo'lda belgilashni talab qiladi (`argtypes`, `restype`), chunki Python dinamik kutubxona faylidan tip ma'lumotini avtomatik o'qiy olmaydi:

```python
libm = ctypes.CDLL("libm.so.6")
libm.sqrt.argtypes = [ctypes.c_double]
libm.sqrt.restype = ctypes.c_double
natija = libm.sqrt(16.0)  # 4.0
```

`ctypes`ning asosiy afzalligi — hech narsa kompilyatsiya qilish shart emas, faqat mavjud `.so`/`.dll` faylni ishlatasiz. Kamchiligi — C tiplari va Python tiplari orasidagi mos kelishni qo'lda, batafsil belgilash kerak, bu murakkab strukturalar (masalan, `struct`) uchun ancha ko'p boilerplate kod talab qiladi, va xatolar segmentation fault kabi qattiq (hard) yiqilishlarga olib kelishi mumkin.

### `cffi` — muqobil, ko'proq "C-native" yondashuv

`cffi` (C Foreign Function Interface) — `ctypes`ga muqobil uchinchi tomon kutubxona bo'lib, C funksiya imzolarini Python sintaksisi bilan qo'lda qayta yozish o'rniga, **haqiqiy C deklaratsiya sintaksisidan** foydalanishga ruxsat beradi:

```python
from cffi import FFI

ffi = FFI()
ffi.cdef("""
    double sqrt(double x);
""")
libm = ffi.dlopen("libm.so.6")
natija = libm.sqrt(16.0)  # 4.0
```

`cffi`ning ikki rejimi bor: **ABI rejimi** (`ctypes`ga o'xshash, runtime'da dinamik yuklash) va **API rejimi** (build vaqtida C kompilyatori yordamida haqiqiy kengaytma moduli yaratadi — tezroq, lekin kompilyator talab qiladi). `cffi` ko'pincha C deklaratsiyalarini to'g'ridan-to'g'ri header fayllardan nusxalash imkoni tufayli `ctypes`ga qaraganda qulayroq hisoblanadi.

### Cython — Python-ga o'xshash sintaksis, C tezligi

`ctypes`/`cffi` mavjud C kodini chaqirish uchun mo'ljallangan. **Cython** esa boshqacha muammoni hal qiladi: agar sizda C kodi yo'q bo'lsa-yu, faqat Python kodingizni tezlashtirishni xohlasangiz-chi? Cython — Python'ning kengaytirilgan versiyasi bo'lib, unda ixtiyoriy ravishda **statik tip annotatsiyalari** qo'shish mumkin, va bu kod haqiqiy C'ga kompilyatsiya qilinadi:

```cython
# fib_cython.pyx fayli
def fibonacci(int n):
    cdef int a = 0
    cdef int b = 1
    cdef int i
    for i in range(n):
        a, b = b, a + b
    return a
```

`cdef int` bilan e'lon qilingan o'zgaruvchilar endi Python obyekti (`PyObject`, reference counting, dinamik tip tekshiruvi bilan) emas, balki **xuddi C'dagidek**, to'g'ridan-to'g'ri protsessor registrida yoki stack'da saqlanadigan tub (native) `int` — bu reference counting, tip tekshiruvi va bytecode dispetcherlash overhead'ini butunlay yo'q qiladi.

Cython faylini `.py`dan `.pyx`ga aylantirib, `setup.py` yoki `cythonize` orqali kompilyatsiya qilish kerak:

```python
# setup.py
from setuptools import setup
from Cython.Build import cythonize

setup(ext_modules=cythonize("fib_cython.pyx"))
```

```bash
python setup.py build_ext --inplace
```

Natijada `fib_cython` moduli oddiy Python moduli kabi import qilinadi (`import fib_cython`), lekin ichida C darajasida bajariladigan kod ishlaydi — tsikl-og'ir hisoblashlarda 10x-100x tezlashish odatiy hol.

Cython'ning muhim afzalligi — **bosqichma-bosqich** optimallashtirish mumkinligi: oddiy `.py` faylni deyarli o'zgartirmasdan `.pyx`ga aylantirib, faqat eng "og'ir" o'zgaruvchilarga `cdef` qo'shib, qolgan qismini Python semantikasida qoldirish mumkin. `cython -a fayl.pyx` buyrug'i HTML hisobot yaratadi, unda qaysi qatorlar hali ham "sekin" Python obyekt operatsiyalariga bog'liqligini sariq rang bilan ko'rsatadi — bu qaerga `cdef` qo'shish kerakligini aniqlashda yordam beradi.

### Uchtasini qachon tanlash

| Vosita | Qachon ishlatiladi |
|---|---|
| `ctypes` | Mavjud C kutubxonasini (tez-tez o'zgarmaydigan, oddiy API) tez chaqirish kerak, kompilyator o'rnatish istalmasa |
| `cffi` | Mavjud C kodi bilan ishlash, lekin `ctypes`dan qulayroq/tezroq (API rejimi) sintaksis kerak |
| Cython | O'zingizning Python algoritmingizni (yangi C kodi yozmasdan) tezlashtirish, yoki C kutubxonasi bilan Python orasida "ko'prik" (wrapper) yozish kerak |

Amaliyotda katta ilmiy hisoblash kutubxonalari (NumPy, pandas, scikit-learn) ko'pincha Cython'dan ichki qismlarni yozishda foydalanadi.

## Amaliy misol

```python
"""
ctypes_demo.py — ctypes bilan libm.sqrt'ni chaqirish
va sof Python bilan tezlikni solishtirish.
"""
import ctypes
import math
import platform
import timeit


def ctypes_demo():
    if platform.system() == "Linux":
        libm = ctypes.CDLL("libm.so.6")
    elif platform.system() == "Darwin":
        libm = ctypes.CDLL("libm.dylib")
    else:
        print("Bu demo faqat Linux/macOS uchun; Windows uchun msvcrt ishlatiladi.")
        return

    libm.sqrt.argtypes = [ctypes.c_double]
    libm.sqrt.restype = ctypes.c_double

    print("ctypes orqali sqrt(16.0):", libm.sqrt(16.0))
    print("math.sqrt(16.0):", math.sqrt(16.0))

    # Tezlikni solishtirish (odatda deyarli bir xil, chunki math.sqrt
    # allaqachon C darajasida ishlaydi — ctypes qo'shimcha overhead qo'shadi)
    vaqt_ctypes = timeit.timeit(lambda: libm.sqrt(2.0), number=1_000_000)
    vaqt_math = timeit.timeit(lambda: math.sqrt(2.0), number=1_000_000)
    print(f"ctypes.sqrt: {vaqt_ctypes:.4f}s (1M chaqiruv)")
    print(f"math.sqrt:   {vaqt_math:.4f}s (1M chaqiruv)")
    print("(math.sqrt odatda tezroq, chunki u to'g'ridan-to'g'ri CPython C-API")
    print(" orqali chaqiriladi, ctypes esa har chaqiruvda qo'shimcha marshalling qiladi.)")


def fibonacci_sof_python(n: int) -> int:
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a


def sof_python_benchmark():
    """
    Cython bilan solishtirish uchun andoza (baseline).
    Haqiqiy Cython kompilyatsiyasi build muhitini talab qiladi,
    shuning uchun bu yerda faqat sof Python vaqti o'lchanadi —
    Cython versiyasi bilan qiyoslash uchun izohlarga qarang.
    """
    vaqt = timeit.timeit(lambda: fibonacci_sof_python(100_000), number=100)
    print(f"Sof Python fibonacci(100_000) x100: {vaqt:.4f}s")
    print("(Cython versiyasi, cdef int bilan yozilganda, odatda 20-50x tezroq")
    print(" bo'ladi, chunki 'a', 'b' endi PyObject emas, C darajasidagi 'long'.)")


if __name__ == "__main__":
    ctypes_demo()
    print()
    sof_python_benchmark()
```

## Keng tarqalgan xatolar

1. **`ctypes` bilan `argtypes`/`restype`ni belgilamaslik.** Standart holatda `ctypes` barcha argumentlarni `int` deb hisoblaydi va qaytish qiymatini `int` deb talqin qiladi — agar haqiqiy funksiya `double` yoki `struct` bilan ishlasa, bu **noto'g'ri natija yoki segmentation fault**ga olib keladi. Har doim `argtypes`/`restype`ni aniq belgilang.

2. **Cython'da hamma narsani `cdef` qilishga urinib, Python semantikasidan (masalan, dinamik ro'yxatlar, `dict`) voz kechish kerak deb o'ylash.** Aslida Cython'ning kuchi aynan **aralash** rejimda — faqat "issiq" (hot) tsikllarni va sonli o'zgaruvchilarni `cdef` qilib, qolgan qismini oddiy Python kodida qoldirish mumkin. Hammasi darhol C tipiga o'girish shart emas.

3. **`ctypes`/`cffi` orqali C funksiyasini chaqirishda xotira egaligini (ownership) noto'g'ri boshqarish.** Agar C funksiyasi xotira ajratsa (`malloc`) va Python tomonidan bu xotira hech qachon bo'shatilmasa (yoki aksincha, ikki marta bo'shatilsa) — xotira sizib chiqishi (memory leak) yoki double-free xatosi yuz beradi. `ctypes`da bunday holatlarda mos `free` funksiyasini ham chaqirish kerakligini unutmaslik lozim.

## Mashq/topshiriq

1. `ctypes` yordamida `libc`dan `strlen` funksiyasini chaqirib (`argtypes = [ctypes.c_char_p]`, `restype = ctypes.c_size_t`), Python'ning ichki `len()` funksiyasi bilan tezlikni solishtiring va nima uchun `len()` deyarli har doim tezroq ekanini tushuntiring.

2. Cython o'rnatilgan muhitda (agar mavjud bo'lsa) yuqoridagi `fibonacci_sof_python` funksiyasini `.pyx` fayliga ko'chirib, `cdef long a, b` bilan qayta yozing, kompilyatsiya qiling va haqiqiy tezlashish koeffitsientini o'lchang.

3. Nima uchun NumPy kabi kutubxonalar ichida Cython (yoki to'g'ridan-to'g'ri C) ishlatilishi, lekin tashqi (foydalanuvchi) API'si hamon "sof Python"dek ko'rinishini (`import numpy as np; np.array(...)`) tushuntiring.

**Javoblar:**

1.
```python
import ctypes
libc = ctypes.CDLL("libc.so.6")
libc.strlen.argtypes = [ctypes.c_char_p]
libc.strlen.restype = ctypes.c_size_t

satr = b"salom dunyo" * 100
vaqt_ctypes = timeit.timeit(lambda: libc.strlen(satr), number=1_000_000)
vaqt_len = timeit.timeit(lambda: len(satr), number=1_000_000)
```
`len()` deyarli har doim tezroq bo'ladi, chunki Python `bytes`/`str` obyektlari o'zlarining uzunligini `ob_size` maydonida (`PyVarObject` strukturasida, 7-bobda ko'rilgan) allaqachon saqlab qo'yadi — `len()` chaqirilganda hech qanday hisoblash kerak emas, faqat shu maydonni o'qish, ya'ni O(1) va **hech qanday funksiya chaqiruv overhead'isiz** (built-in sifatida to'g'ridan-to'g'ri C darajasida). `ctypes.strlen` esa har safar: (1) Python `bytes`dan C `char*` ko'rsatkichga marshalling qiladi, (2) chinakam C funksiya chaqiruvini bajaradi (bu funksiya haqiqatda satrni belgisi `\0`gacha **skanerlab chiqadi**, ya'ni O(n)), (3) natijani qaytadan Python `int`ga o'giradi — bu ancha ko'p qo'shimcha ish.

2.
```cython
# fib_cython.pyx
def fibonacci_cython(int n):
    cdef long a = 0
    cdef long b = 1
    cdef int i
    for i in range(n):
        a, b = b, a + b
    return a
```
Kompilyatsiyadan keyin (`cythonize` + `build_ext --inplace`) bu funksiya sof Python versiyasidan odatda 15-40x tezroq ishlaydi, chunki `a`, `b`, `i` endi PyObject emas — hech qanday reference counting, hech qanday dinamik tip tekshiruvi, to'g'ridan-to'g'ri protsessor registrlarida/stack'da ishlaydigan C `long`/`int`.

3. NumPy tashqi API darajasida (`np.array`, `arr.sum()` kabi) oddiy Python funksiya/metod chaqiruvlaridek ko'rinadi — foydalanuvchi hech qanday C yoki Cython bilishi shart emas. Lekin bu funksiyalarning **ichki amalga oshirilishi** (implementation) Cython yoki to'g'ridan-to'g'ri C/C++ bilan yozilgan — massiv ustida amalga oshiriladigan haqiqiy tsikllar (masalan, million elementni qo'shish) to'liq C tezligida, hech qanday Python bytecode interpretatsiyasisiz bajariladi. Bu — "yuqori darajadagi qulaylik + past darajadagi tezlik" arxitekturasi: Python interfeys sifatida, C/Cython esa "motor" sifatida ishlaydi. Foydalanuvchi buni sezmaydi, chunki u faqat `.pyx`dan kompilyatsiya qilingan `.so` kengaytma modulini oddiy `import` orqali ishlatadi.

## Qisqacha xulosa

Sof Python yetarli tezlik bermagan holatlarda uchta asosiy yo'l bor: `ctypes` (standart kutubxonada, mavjud dinamik kutubxonalarni kompilyatsiyasiz chaqirish, lekin qo'lda tip belgilash talab qiladi), `cffi` (muqobil, ko'proq C-native sintaksis va ABI/API rejimlari bilan), va Cython (Python-ga o'xshash sintaksisga ixtiyoriy statik tiplar qo'shib, haqiqiy C'ga kompilyatsiya qilish — o'z algoritmingizni tezlashtirish uchun eng qulay yo'l). Cython ayniqsa qadriyatli, chunki u bosqichma-bosqich, kodning faqat "issiq" qismlarini optimallashtirish imkonini beradi, va bu yondashuv aynan NumPy, pandas kabi ilmiy hisoblash kutubxonalarining o'zagida qo'llaniladi — foydalanuvchiga sof Python interfeys, ichkarida esa C tezligi.
