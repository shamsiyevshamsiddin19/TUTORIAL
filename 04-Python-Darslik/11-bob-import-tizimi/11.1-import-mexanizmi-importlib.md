# `sys.modules`, finder va loader'lar, `importlib` mexanizmi

## Bu darsda nimalarni o'rganasiz

- `import` kalit so'zi yozilganda, "parda ortida" aynan nechta bosqich sodir bo'lishini bilib olasiz
- `sys.modules` — modullar keshi nima ekanini va u nega bir modul faylini **hech qachon ikki marta** ishlatmasligini ta'minlashini tushunasiz
- **Finder** va **Loader** rollarini, va `sys.meta_path` qanday ishlashini bilib olasiz
- `importlib` moduli orqali importni **qo'lda, dinamik** tarzda boshqarishni o'rganasiz

## Nazariy qism

### `import` — bu ham, aslida, funksiya chaqiruvi

3.3-darsda `import modul_nomi` yozishni o'rgangan bo'lsangiz-da, bu — aslida **maxsus sintaksis** bo'lib, uning ortida `builtins.__import__()` funksiyasi chaqiriladi (garchi amalda siz to'g'ridan-to'g'ri shu funksiyani chaqirmasangiz ham). Import jarayoni — bir nechta aniq, tartiblangan bosqichlardan iborat murakkab mexanizm.

**Manba:** Ushbu dars Python rasmiy hujjatlari (`docs.python.org/3/reference/import.html` — "The import system") va `importlib` moduli hujjatlari asosida tuzilgan.

### 1-bosqich: `sys.modules` — birinchi va eng muhim tekshiruv

`import nimadir` bajarilganda, Python **eng avval** `sys.modules` lug'atini tekshiradi — bu, dastur ishga tushgandan beri **allaqachon import qilingan barcha modullarning keshi**. Agar modul u yerda bo'lsa, Python **hech qanday qo'shimcha ish qilmasdan**, to'g'ridan-to'g'ri o'sha keshdagi modul obyektini qaytaradi:

```python
import sys

print("math" in sys.modules)   # False (agar hali import qilinmagan bo'lsa)

import math
print("math" in sys.modules)   # True — endi keshda

import math   # IKKINCHI marta import qilinganda — FAYL QAYTA O'QILMAYDI!
               # sys.modules'dan darhol qaytariladi
```

Aynan shu tufayli, agar dasturingizning 10 xil joyida `import math` yozilgan bo'lsa ham, `math` moduli **faqat bir marta**, dastur birinchi marta unga murojaat qilganda, haqiqiy ravishda yuklanadi va ishga tushiriladi — qolgan barcha `import math` qatorlari shunchaki keshdan olib beradi.

```python
print(len(sys.modules))   # dastur ishga tushgan zahoti ham, o'nlab modul allaqachon yuklangan bo'ladi
                            # (Python o'zining ishlashi uchun ko'plab ichki modulni oldindan yuklaydi)
```

### 2-3-bosqich: Finder va Loader — "qidiruvchi" va "yuklovchi"

Agar modul `sys.modules`da **topilmasa**, Python uni **topishi va yuklashi** kerak. Bu ish ikki alohida rolga bo'lingan:

- **Finder** (qidiruvchi) — "bu modul **qayerda**?" degan savolga javob beradi (masalan, qaysi faylda, yoki u standart kutubxonaning bir qismimi).
- **Loader** (yuklovchi) — Finder topgan joydan, modulni **haqiqatan yuklaydi va ishga tushiradi** (fayl bo'lsa — o'qib, kompilyatsiya qilib, bajarib).

Finderlar `sys.meta_path` ro'yxatida saqlanadi — bu ro'yxat **tartib bilan**, birma-bir tekshiriladi, birinchi mos finder ishlatiladi:

```python
import sys

for finder in sys.meta_path:
    print(finder)
# Odatda quyidagilarga o'xshash chiqadi:
# <class '_frozen_importlib.BuiltinImporter'>    -> Python'ga o'rnatilgan (built-in) modullar
# <class '_frozen_importlib.FrozenImporter'>      -> "muzlatilgan" (frozen) modullar
# <class '_frozen_importlib_external.PathFinder'>  -> oddiy .py fayllarni topuvchi (eng ko'p ishlatiladigan)
```

**`PathFinder`** — bu, aksariyat hollarda ishlatiladigan finder: u `sys.path`da ko'rsatilgan papkalarni **tartib bilan** ko'rib chiqadi, va modul nomiga mos `.py` fayl (yoki paket — `__init__.py`li papka) qidiradi:

```python
import sys
print(sys.path)
# ['', '/usr/lib/python3.12', ..., papkalar ro'yxati]
# '' — joriy ishlab turgan direktoriya (yoki skript joylashgan papka)
# Python bu papkalarni AYNAN SHU TARTIBDA, birinchi mos kelgunicha qidiradi!
```

### To'liq jarayon — bir joyda

```
import mening_modulim

1. "mening_modulim" nomi sys.modules'da bormi?
   ├── HA -> shu yerdan qaytar, TUGADI
   └── YO'Q -> davom et
2. sys.meta_path'dagi har bir finder'ni tartib bilan so'ra:
   "sen 'mening_modulim'ni topa olasanmi?"
   ├── PathFinder sys.path bo'ylab qidiradi
   └── Mos fayl topilsa (masalan mening_modulim.py), tegishli loader qaytariladi
3. Loader modulni YUKLAYDI:
   a. Yangi, BO'SH modul obyekti yaratiladi
   b. Bu bo'sh modul DARHOL sys.modules'ga qo'shiladi (rekursiv import muammosini
      oldini olish uchun — pastda ko'ramiz!)
   c. Modul faylining kodi 8.1-darsda ko'rgan quvur bo'yicha (AST -> bytecode)
      kompilyatsiya qilinadi va MODUL OBYEKTINING __dict__'i ustida BAJARILADI
   d. Bajarish tugagach, to'liq to'ldirilgan modul obyekti qaytariladi
4. Import qatoridagi nom (mening_modulim) shu modul obyektiga bog'lanadi
```

### `sys.modules`ga "bo'sh modul darhol qo'shilishi" — nega muhim

3-bosqichning (b) qismi — muhim, nozik tafsilot: modul **hali to'liq bajarilmasdan turib**, uning **bo'sh** (yoki qisman to'ldirilgan) versiyasi allaqachon `sys.modules`ga qo'shiladi. Bu — **aylanma import** (circular import) holatlarida nima uchun ba'zan **qisman** ishlashi, ba'zan `ImportError`ga olib kelishini tushuntiradi:

```python
# a.py
import b
print("a.py: b dan X qiymati:", b.X)

def funksiya_a():
    return "A funksiyasi"


# b.py
import a   # AYLANMA IMPORT! a hali TO'LIQ yuklanmagan
X = 10
print("b.py: a dan funksiya_a:", a.funksiya_a)   # bu YANGLISHIB ISHLAMASLIGI MUMKIN,
                                                    # chunki 'a' moduli hali TO'LIQ bajarilmagan,
                                                    # unda funksiya_a hali aniqlanmagan bo'lishi mumkin!
```

Bu holatda, agar `a.py` avval ishga tushirilsa: `a.py` `import b`ga yetganda, `b.py` yuklana boshlaydi; `b.py` o'z navbatida `import a`ga yetganda, Python `sys.modules`da **allaqachon (hali bo'sh/to'liq bo'lmagan holatda) mavjud** `a` modulini topadi va **shuni qaytaradi** — lekin bu paytda `a` modulida hali `funksiya_a` aniqlanmagan bo'lishi mumkin (chunki `a.py`da `import b` qatori `def funksiya_a` qatoridan **oldin** joylashgan bo'lsa)! Bu — `AttributeError`ga olib keladi.

**Bu — nega aylanma importlardan qochish, yoki agar shart bo'lsa, importni funksiya ichiga (kechiktirilgan import) ko'chirish tavsiya etilishining texnik sababidir.**

### `importlib` — importni dasturiy (qo'lda) boshqarish

`importlib` moduli — yuqorida tasvirlangan butun mexanizmni **dasturiy ravishda** ishga tushirish imkonini beradi, bu ayniqsa modul nomi **runtime'da, dinamik** ravishda aniqlanadigan holatlarda (masalan, plagin tizimlarida) foydali:

```python
import importlib

# Oddiy 'import json' ga TENG, lekin modul nomi O'ZGARUVCHIDA:
modul_nomi = "json"
json_moduli = importlib.import_module(modul_nomi)
print(json_moduli.dumps({"kalit": "qiymat"}))

# Allaqachon import qilingan modulni QAYTA yuklash (development'da foydali,
# masalan modulni tahrirlab, dasturni qayta ishga tushirmasdan sinash uchun):
importlib.reload(json_moduli)
```

### Nomlangan import: `from x import y` va `import x as y`

`from modul import nom` — aslida, ichkarida, **avval butun modulni import qiladi** (yuqoridagi to'liq jarayon bo'yicha), so'ng shunchaki o'sha modul obyektidan `nom` atributini "chiqarib oladi" va joriy nomlar maydoniga bog'laydi:

```python
from math import sqrt
# ICHKARIDA aslida: import math; sqrt = math.sqrt (sodda taqqoslash uchun)

import math as m
# ICHKARIDA: import math; m = math (faqat NOM o'zgargan, math ALLAQACHON sys.modules'da)
```

## Amaliy misol

Import jarayonini `sys.modules` va `importlib` yordamida qo'lda kuzatish, va aylanma import muammosini o'z ko'zi bilan ko'rish:

```python
# import_demo.py
import sys
import importlib
import time


def sys_modules_kuzatish():
    print("=== sys.modules keshi ===")
    print(f"Boshida yuklangan modullar soni: {len(sys.modules)}")

    "json" in sys.modules and print("json ALLAQACHON yuklangan edi")

    boshlanish = time.perf_counter()
    import json
    birinchi_import_vaqti = time.perf_counter() - boshlanish

    boshlanish = time.perf_counter()
    import json  # IKKINCHI marta — kesh ishlashi kerak
    ikkinchi_import_vaqti = time.perf_counter() - boshlanish

    print(f"Birinchi 'import json': {birinchi_import_vaqti * 1000:.4f} millisoniya")
    print(f"Ikkinchi 'import json' (keshdan): {ikkinchi_import_vaqti * 1000:.6f} millisoniya")
    print(f"Kesh {birinchi_import_vaqti / max(ikkinchi_import_vaqti, 1e-9):.0f}x tezroq!")


def dinamik_import_demo():
    print("\n=== importlib bilan dinamik import ===")
    modul_nomlari = ["os", "sys", "json", "random"]

    for nom in modul_nomlari:
        modul = importlib.import_module(nom)
        print(f"'{nom}' dinamik import qilindi: {modul}")


def meta_path_korish():
    print("\n=== sys.meta_path (finderlar ro'yxati) ===")
    for finder in sys.meta_path:
        print(f"  - {finder}")

    print("\n=== sys.path (PathFinder qidiradigan papkalar, birinchi 5 tasi) ===")
    for yol in sys.path[:5]:
        print(f"  - {yol!r}")


if __name__ == "__main__":
    sys_modules_kuzatish()
    dinamik_import_demo()
    meta_path_korish()
```

## Keng tarqalgan xatolar

**Xato 1:** Modul faylini tahrirlab, dastur uni "avtomatik qayta yuklaydi" deb kutish (uzun ishlab turgan dasturda, masalan Jupyter yoki interaktiv sessiyada).
❌ Modul faylini o'zgartirib, `import modul_nomi`ni qayta yozib, o'zgarishlar ko'rinishini kutish.
✅ To'g'ri: `import` — allaqachon `sys.modules`da mavjud modulni **hech qachon qayta yuklamaydi**. O'zgarishlarni ko'rish uchun yoki dasturni qaytadan ishga tushirish, yoki qo'lda `importlib.reload(modul)` chaqirish kerak (garchi `reload` ba'zi murakkab holatlarda, masalan `from x import y` orqali olingan nomlar bilan, to'liq ishonchli bo'lmasligi mumkin).

**Xato 2:** Ikki modulni bir-biriga "to'liq" bog'liq qilib, aylanma import yaratish.
❌
```python
# modul_a.py
from modul_b import funksiya_b
# modul_b.py
from modul_a import funksiya_a   # AYLANMA IMPORT — ImportError xavfi katta!
```
✅ To'g'ri: agar ikki modul haqiqatan bir-biriga muhtoj bo'lsa, (1) umumiy funksionallikni uchinchi, mustaqil modulga ajrating, yoki (2) importni **funksiya ichiga** ko'chiring (kechiktirilgan/"lazy" import — bu import faqat funksiya **chaqirilganda**, ya'ni ikkala modul allaqachon to'liq yuklanib bo'lgandan keyin, bajariladi):
```python
# modul_b.py
def funksiya_b():
    from modul_a import funksiya_a   # funksiya CHAQIRILGANDA import qilinadi, modul yuklanayotganda EMAS
    return funksiya_a() + " (b dan)"
```

**Xato 3:** `sys.path`ga papkalarni tartibsiz, o'ylamasdan qo'shib, kutilmagan modul "soyalanishi" (shadowing)ga duch kelish.
❌
```python
sys.path.insert(0, "/mening/maxsus/papkam")
import json   # agar /mening/maxsus/papkam ichida O'ZINGIZNING json.py faylingiz bo'lsa,
                # standart kutubxonadagi json O'RNIGA O'ZINGIZNIKI yuklanadi!
```
✅ To'g'ri: `sys.path` — **tartib bilan** qidiriladi, va birinchi mos fayl ishlatiladi. Agar loyihangizda tasodifan standart kutubxona nomlari bilan bir xil nomdagi fayl (masalan `json.py`, `random.py`) bo'lsa, bu **standart modulni "soyalab qo'yishi"** (shadowing) va tushunarsiz xatolarga olib kelishi mumkin — shuning uchun standart kutubxona nomlari bilan bir xil nomda fayl yaratishdan saqlaning.

## Mashq/topshiriq

**(Oson)** `sys.modules` lug'atining uzunligini dastur boshida va `import` qilingan uchta yangi modul (masalan `csv`, `datetime`, `re`)dan keyin solishtiring.

**(O'rtacha)** Ikkita fayl yarating: `modul_a.py` va `modul_b.py`, ularda aylanma import muammosini **ataylab** hosil qiling (yuqoridagi misoldagi kabi) va qaysi xatolik (`ImportError` yoki `AttributeError`) chiqishini kuzating. Keyin muammoni **kechiktirilgan import** orqali tuzating.

**(Qiyin)** `importlib.import_module()` yordamida, berilgan papkadagi barcha `.py` fayllarni (masalan `plaginlar/` papkasida) **avtomatik** topib, ularning har birini import qilib, agar ularda `RO_YXATGA_OLISH` nomli o'zgaruvchi bo'lsa, uni markaziy ro'yxatga yig'uvchi oddiy "plagin yuklovchi" tizim yozing (izoh: `os.listdir()` yoki `pathlib` bilan papka ichini ko'rish, va modul nomini fayl nomidan `.py`ni olib tashlab hosil qilish kerak bo'ladi).

## Qisqacha xulosa

`import` jarayoni — avval `sys.modules` keshini tekshirish (bu, aynan shu tufayli, har bir modul faylini dastur davomida **faqat bir marta** ishga tushirishni kafolatlaydi), topilmasa, `sys.meta_path`dagi **finder**lar orqali modulni topish (odatda `PathFinder`, `sys.path` bo'ylab), va **loader** orqali uni yuklab, bajarish (bu vaqtda modul **darhol, hali to'liq bo'lmasa ham** `sys.modules`ga qo'shiladi — bu aylanma importlarning nozik xatti-harakatining sababi). `importlib` moduli bu butun jarayonni dasturiy, dinamik ravishda boshqarish (masalan, plagin tizimlari uchun) imkonini beradi. Keyingi darsda biz bu jarayonning yana bir muhim qismi — `.pyc` fayllar va bytecode keshlashni ko'ramiz.
