# 11.2. `__pycache__`, `.pyc` fayllar va bytecode keshlash

## Bu darsda nimalarni o'rganasiz

- Python nima uchun `.py` fayllarni har safar qayta kompilyatsiya qilmaydi
- `__pycache__` papkasi va `.pyc` fayl nomlanish qoidasi (`modul.cpython-312.pyc`)
- `.pyc` faylning ichki tuzilishi: magic number, bit maydon, timestamp/hash, hajm
- Timestamp-asosli va hash-asosli (PEP 552) invalidatsiya rejimlari
- `.pyc` keshni qo'lda boshqarish: `py_compile`, `compileall`, `PYTHONDONTWRITEBYTECODE`

## Nazariy qism

**Manba:** [PEP 552 — Deterministic pycs](https://peps.python.org/pep-0552/), [Real Python — What Is the __pycache__ Folder in Python?](https://realpython.com/python-pycache/), Python rasmiy dokumentatsiyasi (`import` tizimi bo'limi).

### Nega bytecode keshlanadi

10-11-boblarda ko'rganimizdek, `.py` fayl ishga tushirilishidan oldin AST'ga, so'ng bytecode'ga (code object) kompilyatsiya qilinadi. Bu kompilyatsiya jarayoni — leksik tahlil, parsing, AST optimizatsiyasi, bytecode generatsiyasi — hisoblash jihatidan arzon emas. Agar siz katta loyihada `import pandas` desangiz va Python har safar dasturni ishga tushirganda pandas'ning minglab qatorlarini qayta kompilyatsiya qilishi kerak bo'lsa, dastur ishga tushishi sezilarli darajada sekinlashadi.

Shu sababli CPython bir marta kompilyatsiya qilingan bytecode'ni diskka saqlaydi — bu **`.pyc`** (compiled Python) fayllardir. Keyingi safar shu modul import qilinganda, Python manba faylni qayta tahlil qilish o'rniga, agar keshlangan `.pyc` hali "yaroqli" (valid) bo'lsa, to'g'ridan-to'g'ri undan bytecode'ni yuklaydi.

Muhim: bu keshlash faqat **import qilingan modullar** uchun ishlaydi. To'g'ridan-to'g'ri ishga tushiriladigan skript (`python script.py`) uchun `.pyc` yaratilmaydi — u har doim qayta kompilyatsiya qilinadi (chunki bunday skript odatda faqat bir marta ishga tushiriladi).

### `__pycache__` papkasi va nomlanish

Python 3.2'gacha `.pyc` fayllar manba fayl bilan bir xil papkada, xuddi shu nom bilan saqlanardi (`modul.pyc`). Bu bir nechta muammoni keltirib chiqarardi: turli Python versiyalari (2.7, 3.8, 3.12) bir xil `.pyc` nomini talab qilardi va bir-birining keshini buzib qo'yardi.

PEP 3147 bu muammoni **`__pycache__`** papkasi bilan hal qildi. Endi har bir manba fayl uchun kesh alohida papkada, versiyaga xos nom bilan saqlanadi:

```
loyiha/
├── main.py
├── utils.py
└── __pycache__/
    ├── utils.cpython-312.pyc
    └── main.cpython-312.pyc   # (odatda yaratilmaydi, chunki main.py to'g'ridan-to'g'ri ishga tushiriladi)
```

Nom formati: `{modul_nomi}.{implementatsiya}-{versiya}.pyc` — masalan `utils.cpython-312.pyc` degani CPython 3.12 tomonidan yaratilgan `utils.py` keshi. Bu bir nechta Python versiyasini bitta muhitda ishlatish imkonini beradi — har biri o'z keshini yozadi, boshqasiga tegmaydi.

### `.pyc` faylning ichki tuzilishi

**Manba:** [PEP 552 — Deterministic pycs](https://peps.python.org/pep-0552/).

`.pyc` fayl ikki qismdan iborat: sarlavha (header) va marshallangan (serialized) code object. Sarlavha to'rtta 32-bitli so'zdan (word) iborat:

1. **Magic number** — Python versiyasi va bytecode formatini kodlaydi. Har bir Python relizi (ba'zan hatto patch versiyalarida ham, agar bytecode formati o'zgargan bo'lsa) o'zining magic raqamiga ega. Agar `.pyc` faylning magic raqami joriy Python interpretatorining kutgan raqamiga mos kelmasa, kesh butunlay e'tiborsiz qoldiriladi va manba qayta kompilyatsiya qilinadi.
2. **Bit maydon (flags)** — qaysi invalidatsiya rejimi ishlatilganini bildiradi.
3. **Timestamp yoki hash** — bit maydonga qarab.
4. **Fayl hajmi yoki qo'shimcha ma'lumot** — bit maydonga qarab.

### Ikki xil invalidatsiya rejimi

**1. Timestamp-asosli (an'anaviy, standart rejim)**

Bit maydon 0 bo'lsa, uchinchi va to'rtinchi so'zlarda manba faylning oxirgi o'zgartirilgan vaqti (`mtime`) va hajmi (baytlarda) saqlanadi. Modul import qilinganda, Python:

1. `.pyc` fayl mavjudligini va magic raqami mosligini tekshiradi.
2. `.py` manba faylning joriy `mtime` va hajmini o'qiydi.
3. Bu qiymatlarni `.pyc` sarlavhasida saqlangan qiymatlar bilan solishtiradi.
4. Agar mos kelsa — kesh **yaroqli**, bytecode to'g'ridan-to'g'ri yuklanadi (manba fayl hatto o'qilmaydi ham).
5. Agar mos kelmasa (fayl tahrirlangan) — manba qayta kompilyatsiya qilinadi va yangi `.pyc` yoziladi.

Bu tezkor, lekin bitta kamchiligi bor: agar fayl tizimi (masalan, versiya nazorati tizimidan checkout qilinganda) `mtime`'ni saqlamasa yoki noto'g'ri o'rnatsa, kesh noto'g'ri invalidatsiya qilinishi (yoki aksincha, eskirgan kesh ishlatilib qolishi) mumkin.

**2. Hash-asosli (PEP 552, Python 3.7+)**

Bit maydonning eng past biti o'rnatilgan bo'lsa, uchinchi so'zda manba faylning **64-bitli SipHash**'i (mtime o'rniga) saqlanadi. Bu rejimning ikki varianti bor:

- **Tekshiriladigan (checked) hash-asosli**: `check_source` bayrog'i o'rnatilgan. Import vaqtida Python manba faylni o'qiydi, uning hash'ini hisoblaydi va saqlangan hash bilan solishtiradi — agar mos kelsa, kesh ishlatiladi.
- **Tekshirilmaydigan (unchecked) hash-asosli**: `check_source` bayrog'i o'rnatilmagan. Python hech qanday tekshiruvsiz `.pyc`'ni ishonch bilan yuklaydi — bu tashqi tizim (masalan, paket menejeri yoki build tizimi) kesh va manba mosligini allaqachon kafolatlaganida foydalidir (masalan, reproducible build'lar uchun).

Hash-asosli rejim odatda `py_compile.compile(..., invalidation_mode=...)` orqali qo'lda tanlanadi; standart holatda Python hamon timestamp-asosli rejimni ishlatadi, chunki u tezroq (fayl mazmunini hash qilish o'qishni talab qiladi, mtime esa `stat()` chaqiruvi bilan darhol olinadi).

### Amaliyotda kuzatish

```python
import py_compile
import importlib.util

# Modulni qo'lda kompilyatsiya qilish va .pyc yo'lini olish
py_compile.compile("utils.py")
kesh_yoli = importlib.util.cache_from_source("utils.py")
print(kesh_yoli)  # __pycache__/utils.cpython-312.pyc
```

## Amaliy misol

```python
"""
pycache_tekshiruv.py — .pyc keshni real vaqtda kuzatish demosi.
"""
import importlib.util
import os
import py_compile
import struct
import time


def pyc_sarlavhasini_oqish(pyc_yoli: str) -> dict:
    """.pyc faylning 16 baytlik sarlavhasini qo'lda parslash (PEP 552 formati)."""
    with open(pyc_yoli, "rb") as f:
        magic = f.read(4)
        bit_maydon = struct.unpack("<I", f.read(4))[0]
        ikkinchi_maydon = struct.unpack("<I", f.read(4))[0]
        uchinchi_maydon = struct.unpack("<I", f.read(4))[0]

    hash_asosli = bool(bit_maydon & 0b1)
    natija = {
        "magic_raw": magic.hex(),
        "bit_maydon": bit_maydon,
        "rejim": "hash-asosli" if hash_asosli else "timestamp-asosli",
    }
    if hash_asosli:
        natija["check_source"] = bool(bit_maydon & 0b10)
        natija["hash"] = uchinchi_maydon
    else:
        natija["mtime"] = ikkinchi_maydon
        natija["fayl_hajmi"] = uchinchi_maydon
    return natija


def demo():
    manba = "namuna_modul.py"
    with open(manba, "w", encoding="utf-8") as f:
        f.write("def salom():\n    return 'Salom, Python!'\n")

    # 1-bosqich: kompilyatsiya qilish (timestamp-asosli, standart)
    py_compile.compile(manba, doraise=True)
    kesh_yoli = importlib.util.cache_from_source(manba)
    print("Kesh yaratildi:", kesh_yoli)
    print("Sarlavha (timestamp-asosli):", pyc_sarlavhasini_oqish(kesh_yoli))

    # 2-bosqich: hash-asosli (tekshiriladigan) rejimda qayta kompilyatsiya
    py_compile.compile(
        manba,
        doraise=True,
        invalidation_mode=py_compile.PycInvalidationMode.CHECKED_HASH,
    )
    print("Sarlavha (hash-asosli, checked):", pyc_sarlavhasini_oqish(kesh_yoli))

    # 3-bosqich: manba faylni o'zgartirmasdan mtime'ni orqaga suramiz —
    # timestamp-asosli rejimda bu keshni "eskirgan" deb ko'rsatadi,
    # lekin hash-asosli rejimda mazmun o'zgarmagani uchun kesh yaroqli qoladi.
    py_compile.compile(manba, doraise=True)  # yana timestamp-asosli qaytaramiz
    eski_vaqt = time.time() - 10_000
    os.utime(manba, (eski_vaqt, eski_vaqt))
    print("Manba mtime orqaga surildi, endi qayta import qilamiz...")

    # importlib orqali haqiqiy yuklashni sinash
    spec = importlib.util.spec_from_file_location("namuna_modul", manba)
    modul = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(modul)
    print(modul.salom())

    os.remove(manba)


if __name__ == "__main__":
    demo()
```

### `compileall` va joylashtirish (deployment)

Katta loyihalarni joylashtirishda (Docker image qurish, paket tayyorlash) barcha `.pyc` fayllarni oldindan generatsiya qilish foydali — bu birinchi ishga tushirishni tezlashtiradi:

```bash
python -m compileall .              # joriy papkadagi barcha .py fayllarni oldindan kompilyatsiya qilish
python -m compileall -o 2 .         # optimallashtirilgan (-OO) versiyani ham yaratish
```

### `.pyc` keshni o'chirish

```bash
PYTHONDONTWRITEBYTECODE=1 python main.py   # .pyc fayl yozilishini butunlay o'chirish
```

Bu odatda konteynerlarda (Docker) yoki faqat bir marta ishga tushadigan skriptlarda ishlatiladi — chunki keshni yozish keraksiz disk yozuvlari va I/O sarflaydi.

## Keng tarqalgan xatolar

1. **`__pycache__`'ni versiya nazoratiga (Git) qo'shib qo'yish.** Bu kesh fayllar mashinaga, Python versiyasiga xos va deterministik emas (agar hash-asosli bo'lmasa). `.gitignore` fayliga `__pycache__/` va `*.pyc` qo'shilishi shart.

2. **"`.pyc` faylni tahrirlasam, dastur o'zgaradi deb o'ylash."** `.pyc` — bu faqat kesh. Agar mos `.py` fayl mavjud bo'lsa va yangiroq bo'lsa, Python `.pyc`'ni e'tiborsiz qoldirib qayta kompilyatsiya qiladi. `.pyc`'ni qo'lda tahrirlash amalda hech narsaga ta'sir qilmaydi.

3. **Docker qatlamlarida (layer) `.pyc`'larni keshlashga urinish, lekin manba fayl konteyner ichida boshqa vaqt belgisi (mtime) bilan nusxalanishini unutish.** Ko'p CI/CD tizimlarida fayllar `git clone` qilinganda barchasi bir xil `mtime` oladi — bu holatda timestamp-asosli kesh baribir ishlaydi (chunki nisbiy taqqoslash), lekin agar fayllar alohida-alohida nusxalansa, tartib buzilishi mumkin. Reproducible build kerak bo'lsa, hash-asosli (unchecked) rejim afzalroq.

## Mashq/topshiriq

1. `pycache_tekshiruv.py` skriptidagi `pyc_sarlavhasini_oqish()` funksiyasini kengaytirib, agar `rejim == "hash-asosli"` bo'lsa, `hash` maydonini SipHash sifatida emas, balki oddiy 16-lik (hex) ko'rinishda chiqaring.

2. `compileall` modulini ishlatib, ikkita papkali (`paket_a/`, `paket_b/`) sun'iy loyiha yarating va `python -m compileall -q .` buyrug'i qancha `.pyc` fayl yaratganini sanab chiqing.

3. `UNCHECKED_HASH` invalidatsiya rejimida kompilyatsiya qiling, so'ng manba faylni **mazmunini o'zgartirib** (lekin `.pyc`'ni qayta yaratmasdan) import qiling. Nima uchun Python eskirgan bytecode'ni "sezmasdan" ishlatib yuborishini tushuntiring.

**Javoblar:**

1.
```python
if hash_asosli:
    natija["hash_hex"] = hex(uchinchi_maydon)
```

2.
```python
import compileall
compileall.compile_dir(".", quiet=1)
# natija: paket_a/__pycache__/*.pyc va paket_b/__pycache__/*.pyc — odatda 2 ta fayl
# (agar __init__.py fayllar bo'lsa, ular ham hisoblanadi)
```

3. `UNCHECKED_HASH` rejimida Python **hech qanday tekshiruv o'tkazmasdan** `.pyc`'dagi bytecode'ni ishonch bilan yuklaydi — bu rejim aynan shuning uchun mavjud: tekshiruvni (hash hisoblash, fayl o'qish) butunlay o'tkazib yuborish orqali import tezligini oshirish. Bu ishonchni tashqi tizim (masalan, paket menejeri yoki build pipeline) "men manba va kesh mos kelishini allaqachon kafolatlaganman" deb bergan holatlarda xavfsiz. Lekin qo'lda, tasodifan manba faylni o'zgartirib, `.pyc`'ni yangilamasangiz — Python **eskirgan bytecode'ni jimgina ishlatadi**, hech qanday xato yoki ogohlantirish bermaydi. Shuning uchun bu rejim ehtiyotkorlik bilan, faqat mos build jarayoni bo'lganda ishlatilishi kerak.

## Qisqacha xulosa

CPython har bir import qilingan modulning bytecode'ini `__pycache__/modul.cpython-XY.pyc` shaklida keshlaydi, shu bilan takroriy kompilyatsiyadan qochadi. `.pyc` sarlavhasi magic number (versiya), bit maydon (invalidatsiya rejimi) va yoki timestamp+hajm, yoki manba hash'ini saqlaydi. Standart — timestamp-asosli rejim (tez, lekin fayl tizimi vaqt belgisiga bog'liq); PEP 552 bilan kiritilgan hash-asosli rejim (checked/unchecked) deterministik build'lar uchun muqobil beradi. `compileall` bilan oldindan kompilyatsiya qilish va `PYTHONDONTWRITEBYTECODE` bilan keshni o'chirish — ishlab chiqarish muhitida tez-tez ishlatiladigan vositalar. `__pycache__` papkasini hech qachon versiya nazoratiga qo'shmang.
