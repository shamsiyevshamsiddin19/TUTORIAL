# 12.4. `asyncio` ichki mexanizmi

## Bu darsda nimalarni o'rganasiz

- Koroutinalar (`async def`) generatorlardan qanday farq qiladi va ularning ichki tuzilishi
- Voqealar sikli (event loop) qanday ishlaydi: hodisalar navbati, `select`/`epoll`
- `Task` obyekti, `await` amalda nima qiladi, koroutina holatlari
- `asyncio` yagona oqimda qanday minglab bir vaqtdagi operatsiyani boshqaradi
- `asyncio` vs `threading` vs `multiprocessing` — qachon nimani tanlash

## Nazariy qism

**Manba:** Python rasmiy dokumentatsiyasi (`asyncio` moduli, "Event loop" bo'limi), CPython manba kodi (`Lib/asyncio/`, `Objects/genobject.c`).

### Koroutina — maxsus generator

8-bobda ko'rgan generatorlar (`yield` ishlatuvchi funksiyalar) `asyncio`ning fundamenti hisoblanadi. `async def` bilan e'lon qilingan funksiya chaqirilganda, u darhol bajarilmaydi — o'rniga **koroutina obyekti** qaytaradi, xuddi generator funksiyasi generator obyekti qaytargani kabi. Ichki darajada koroutina — bu maxsus bayroq (`CO_COROUTINE`) bilan belgilangan code object asosida yaratilgan, `send()`, `throw()`, `close()` metodlariga ega maxsus obyekt (`PyCoroutine`), generator bilan deyarli bir xil C strukturaga ega.

`await` kalit so'zi, aslida, "boshqa bir kutish mumkin bo'lgan (awaitable) obyektga `yield from` qil" degani bilan deyarli bir xil ma'noni bildiradi (tarixiy jihatdan, `async`/`await` sintaksisi Python 3.5'da kiritilishidan oldin, dasturchilar xuddi shu narsani `@asyncio.coroutine` dekoratori va `yield from` bilan qo'lda yozishardi).

### Voqealar sikli (event loop) — yuragi

`asyncio`ning markazida **voqealar sikli (event loop)** yotadi — bu yagona oqimda ishlaydigan, cheksiz tsikl bo'lib, quyidagilarni bajaradi:

1. Bajarilishga tayyor bo'lgan vazifalar (callback'lar) navbatini tekshiradi.
2. Har birini navbat bilan bajaradi (bitta koroutina keyingi `await` nuqtasigacha, yoki tugaguncha).
3. I/O kutilayotgan operatsiyalarni (masalan, tarmoq socket'i o'qishga tayyor bo'lishini) operatsion tizimning samarali kutish mexanizmi (Linux'da `epoll`, macOS'da `kqueue`, Windows'da IOCP) orqali kuzatadi — bularning barchasi **`selectors`** moduli orqali abstraktsiyalanadi.
4. Kutilayotgan I/O tayyor bo'lganda, tegishli koroutinani "uyg'otib", navbatga qo'shadi.

Bu mexanizmning kaliti: event loop hech qachon "band kutish" (busy-waiting, CPU'ni behuda band qilib tekshirish) qilmaydi. U operatsion tizimga "menga quyidagi 500 ta socket'dan qaysi biri tayyor bo'lsa xabar ber" deb so'raydi (`epoll_wait()` kabi tizim chaqiruvi) va shu paytda protsessor butunlay bo'sh (yoki boshqa ishga band) bo'lishi mumkin — bu `asyncio`ni minglab bir vaqtdagi ulanishni (masalan, veb-server'da) juda kam resurs bilan boshqarishga qodir qiladi.

### `await` amalda nima qiladi

```python
async def maʼlumot_olish():
    natija = await tarmoq_sorovi()
    return natija
```

`await tarmoq_sorovi()` bajarilganda:

1. `tarmoq_sorovi()` koroutinasi ishga tushadi va birinchi `await`igacha (yoki past darajadagi I/O kutish nuqtasigacha) bajariladi.
2. Agar natija darhol tayyor bo'lmasa (masalan, socket hali ma'lumot yubormagan), koroutina o'zini **to'xtatadi (suspend)** — bu xuddi generator `yield` qilgani kabi, joriy bajarilish holati (mahalliy o'zgaruvchilar, bytecode pozitsiyasi) to'liq saqlanadi.
3. Boshqaruv event loop'ga qaytadi. Event loop endi **boshqa** tayyor vazifani bajarishga o'tadi — hech narsa "kutib" bo'sh turmaydi.
4. Qachonki kutilayotgan I/O tayyor bo'lsa (operatsion tizim xabar bersa), event loop to'xtatilgan koroutinani xuddi shu joydan **davom ettiradi** (`send()` chaqiruvi orqali, generator mexanizmiga o'xshab).

Bu — **kooperativ ko'p vazifalilik (cooperative multitasking)**: `threading`dan farqli o'laroq, bu yerda operatsion tizim yoki GIL bir koroutinani majburan to'xtatib boshqasiga o'tkazmaydi — har bir koroutina o'zi, faqat `await` nuqtasida, ixtiyoriy ravishda boshqaruvni bo'shatadi. Shuning uchun `asyncio`da poyga sharoiti (race condition) `threading`ga qaraganda kamroq — chunki ikkita koroutina orasida almashinuv faqat aniq, ko'zga ko'ringan `await` nuqtalarida sodir bo'ladi, istalgan bytecode instruksiyada emas.

### `Task` — koroutinani rejalashtirilgan qilish

Faqat koroutina yaratish (`koroutina = maʼlumot_olish()`) uni **hali ishga tushirmaydi** — bu shunchaki obyekt. Uni haqiqatan ham bajarish uchun yo uni `await` qilish kerak, yoki `asyncio.create_task()` bilan **`Task`**ga o'rash kerak:

```python
task = asyncio.create_task(maʼlumot_olish())  # darhol event loop navbatiga qo'shiladi
# ... boshqa ishlarni davom ettirish mumkin, task fonda ishlaydi ...
natija = await task  # faqat shu yerda natijani kutamiz
```

`Task` — `Future`ning quyi klassi bo'lib, koroutinani event loop bilan bog'laydi va uning holatini (`PENDING`, `RUNNING`, `DONE`, `CANCELLED`) kuzatib boradi. `asyncio.gather()` bir nechta `Task`/koroutinani parallel (bir vaqtda kooperativ) ishga tushirib, barchasi tugashini kutish uchun ishlatiladi:

```python
natijalar = await asyncio.gather(
    maʼlumot_olish(),
    boshqa_sorov(),
    uchinchi_sorov(),
)
```

### Nega `asyncio` GIL bilan "kelisha oladi"

`asyncio` odatda **bitta OS oqimida** ishlaydi — shuning uchun GIL bu yerda umuman muammo emas (12.1-darsda ko'rganimizdek, GIL faqat bir nechta oqim raqobatlashganda ta'sir qiladi). Barcha koroutinalar bir xil oqimda, ketma-ket, faqat `await` nuqtalarida almashinib ishlaydi — bu esa `asyncio`ni I/O-bog'liq, yuqori parallellik talab qiladigan ishlarda (minglab bir vaqtdagi tarmoq ulanishi) juda samarali qiladi, chunki hech qanday oqim yaratish yoki GIL almashinuvi overhead'i yo'q.

Muhim ogohlantirish: agar koroutina ichida **CPU-bog'liq, uzoq davom etadigan sinxron kod** (masalan, `time.sleep()` — `await asyncio.sleep()` emas, yoki og'ir sof-Python hisoblash) bo'lsa, bu **butun event loop'ni bloklab qo'yadi** — chunki hech qanday `await` nuqtasi yo'q, event loop boshqa hech qanday koroutinaga o'tolmaydi. Bunday CPU-bog'liq ishlarni `loop.run_in_executor()` orqali alohida oqim yoki jarayon puliga yuborish kerak.

## Amaliy misol

```python
"""
asyncio_demo.py — event loop, Task, gather va CPU-bloklash
xatosini ko'rsatuvchi demo.
"""
import asyncio
import time


async def sorov_simulyatsiyasi(nom: str, kechikish: float) -> str:
    print(f"[{time.strftime('%H:%M:%S')}] {nom}: so'rov boshlandi")
    await asyncio.sleep(kechikish)  # I/O kutish simulyatsiyasi — event loop'ni BLOKLAMAYDI
    print(f"[{time.strftime('%H:%M:%S')}] {nom}: so'rov tugadi")
    return f"{nom} natijasi"


async def ketma_ket_demo():
    boshlanish = time.perf_counter()
    natija_1 = await sorov_simulyatsiyasi("So'rov-1", 1.0)
    natija_2 = await sorov_simulyatsiyasi("So'rov-2", 1.0)
    print(f"Ketma-ket: {time.perf_counter() - boshlanish:.2f}s")


async def parallel_demo():
    boshlanish = time.perf_counter()
    natijalar = await asyncio.gather(
        sorov_simulyatsiyasi("So'rov-A", 1.0),
        sorov_simulyatsiyasi("So'rov-B", 1.0),
        sorov_simulyatsiyasi("So'rov-C", 1.0),
    )
    print(f"Parallel (gather): {time.perf_counter() - boshlanish:.2f}s")
    print("Natijalar:", natijalar)


async def cpu_bloklash_muammosi():
    """CPU-bog'liq kod event loop'ni qanday bloklashini ko'rsatadi."""

    async def yaxshi_fon_vazifasi():
        for i in range(3):
            print(f"Fon vazifasi ishlayapti: {i}")
            await asyncio.sleep(0.3)  # boshqaruvni bo'shatadi

    def cpu_bogliq_sinxron_ish():
        # DIQQAT: bu yerda hech qanday await yo'q — bloklaydi!
        natija = sum(i * i for i in range(20_000_000))
        return natija

    # Noto'g'ri usul: to'g'ridan-to'g'ri chaqirish fon vazifasini bloklaydi
    fon = asyncio.create_task(yaxshi_fon_vazifasi())
    await asyncio.sleep(0.05)  # fon vazifasi boshlanishiga imkon berish
    print("CPU-bog'liq ishni SINXRON bajaramiz (event loop bloklanadi)...")
    cpu_bogliq_sinxron_ish()
    await fon  # fon vazifasi CPU ish davomida "muzlab qolgan" bo'lardi

    # To'g'ri usul: executor'ga yuborish
    fon2 = asyncio.create_task(yaxshi_fon_vazifasi())
    loop = asyncio.get_running_loop()
    print("CPU-bog'liq ishni run_in_executor orqali bajaramiz (event loop bloklanmaydi)...")
    await loop.run_in_executor(None, cpu_bogliq_sinxron_ish)
    await fon2


async def main():
    await ketma_ket_demo()
    print("---")
    await parallel_demo()
    print("---")
    await cpu_bloklash_muammosi()


if __name__ == "__main__":
    asyncio.run(main())
```

Chiqishi (qisqartirilgan, vaqt belgilari bilan) taxminan:

```
Ketma-ket: 2.00s          # ikkala so'rov birin-ketin, umumiy 2 soniya
---
Parallel (gather): 1.00s  # uchala so'rov BIR VAQTDA kutilmoqda, umumiy 1 soniya
---
Fon vazifasi ishlayapti: 0
CPU-bog'liq ishni SINXRON bajaramiz (event loop bloklanadi)...
# <-- bu yerda "Fon vazifasi ishlayapti: 1" BIR NECHA SONIYA KECHIKADI,
#     chunki CPU-bog'liq kod event loop'ni to'liq bloklab qo'ydi
Fon vazifasi ishlayapti: 1
Fon vazifasi ishlayapti: 0
CPU-bog'liq ishni run_in_executor orqali bajaramiz (event loop bloklanmaydi)...
Fon vazifasi ishlayapti: 1
Fon vazifasi ishlayapti: 2
```

## Keng tarqalgan xatolar

1. **Koroutinani yaratib, lekin `await` yoki `create_task()` qilishni unutish.** `maʼlumot_olish()` deb yozish (parenthesis bilan chaqirish) hech narsani bajarmaydi — faqat koroutina obyekti yaratadi. Python bunda odatda `RuntimeWarning: coroutine '...' was never awaited` ogohlantirishini beradi.

2. **`asyncio.sleep()` o'rniga `time.sleep()` ishlatish koroutina ichida.** `time.sleep()` **butun event loop'ni** bloklaydi (yuqoridagi misolda ko'rganimizdek), `asyncio.sleep()` esa boshqaruvni event loop'ga qaytarib, boshqa vazifalarga ishlash imkonini beradi.

3. **`asyncio`ni CPU-bog'liq parallellik uchun ishlatishga urinish.** `asyncio` yagona oqimda ishlaydi — u hech qachon haqiqiy CPU parallelligini bermaydi (`multiprocessing`dan farqli o'laroq). U faqat I/O-bog'liq kutishni samarali boshqaradi. CPU-bog'liq ishlarni `run_in_executor` bilan `ProcessPoolExecutor`ga yo'naltirish kerak.

## Mashq/topshiriq

1. `parallel_demo()` funksiyasidagi `asyncio.gather()` o'rniga uchta `asyncio.create_task()` chaqirib, keyin har birini alohida `await` qiling. Umumiy vaqt qanday o'zgarishini (yoki o'zgarmasligini) tekshiring va sababini tushuntiring.

2. `asyncio.wait_for()` yordamida `sorov_simulyatsiyasi("Sekin", 5.0)`ni 1 soniyalik timeout bilan chaqirib, `asyncio.TimeoutError` qanday ko'tarilishini ko'rsating.

3. Nima uchun bitta `asyncio` dasturida yuz minglab `Task` yaratish mumkin (masalan, yuz minglab bir vaqtdagi ulanishni boshqaruvchi server), lekin yuz minglab `threading.Thread` yaratish amalda mumkin emasligini (yoki juda resurstalab ekanini) tushuntiring.

**Javoblar:**

1.
```python
async def create_task_demo():
    boshlanish = time.perf_counter()
    t1 = asyncio.create_task(sorov_simulyatsiyasi("A", 1.0))
    t2 = asyncio.create_task(sorov_simulyatsiyasi("B", 1.0))
    t3 = asyncio.create_task(sorov_simulyatsiyasi("C", 1.0))
    await t1
    await t2
    await t3
    print(f"create_task + ketma-ket await: {time.perf_counter() - boshlanish:.2f}s")
```
Umumiy vaqt baribir ~1.0s bo'ladi (2-savoldagi `gather()` bilan bir xil), chunki `create_task()` koroutinani **darhol** event loop navbatiga qo'shadi va ishga tushiradi — birinchi `await t1` chaqirilgunga qadar allaqachon uchalasi ham fonda parallel (kooperativ) ishlay boshlagan bo'ladi. `gather()` shunchaki bir nechta `Task` yaratib, ularning barchasi tugashini kutishni qulay qiladigan yordamchi funksiya, xolos — asosiy mexanizm bir xil.

2.
```python
async def timeout_demo():
    try:
        natija = await asyncio.wait_for(sorov_simulyatsiyasi("Sekin", 5.0), timeout=1.0)
    except asyncio.TimeoutError:
        print("Vaqt tugadi — 1 soniyada javob kelmadi")
```

3. Har bir `threading.Thread` operatsion tizim darajasidagi to'liq oqim bo'lib, unga OS tomonidan alohida stack xotirasi (odatda bir necha megabayt) ajratiladi, va OS scheduler har birini boshqarish uchun qo'shimcha xarajat (kontekst almashinuvi) sarflaydi — yuz minglab oqim amalda operatsion tizim resurslarini tugatib qo'yadi (xotira va scheduler overhead'i). `asyncio.Task` esa OS oqimi emas — bu shunchaki Python darajasidagi yengil obyekt (koroutina holati + event loop navbatidagi yozuv), hech qanday alohida OS stack yoki kontekst almashinuvi talab qilmaydi. Bitta OS oqimi ichida minglab `Task` bemalol "yashashi" mumkin, chunki ularning har biri atigi bir necha o'nlab-yuzlab baytlik Python obyekti, OS resursi emas.

## Qisqacha xulosa

`asyncio` koroutinalarni (generatorlarning maxsus turi) yagona OS oqimida, kooperativ ko'p vazifalilik orqali boshqaradi: `await` nuqtasida koroutina o'z holatini saqlab, boshqaruvni event loop'ga qaytaradi, event loop esa operatsion tizimning samarali `epoll`/`kqueue` kabi mexanizmlari orqali qaysi I/O tayyor bo'lganini kuzatib, tegishli koroutinani davom ettiradi. Bu yondashuv GIL bilan hech qanday ziddiyatga kirmaydi (bitta oqim ishlatilgani uchun) va minglab bir vaqtdagi I/O-bog'liq operatsiyani juda kam resurs bilan boshqarishga imkon beradi — lekin CPU-bog'liq sinxron kod (blocking call) butun event loop'ni to'xtatib qo'yadi, shuning uchun bunday ishlarni `run_in_executor` orqali alohida oqim yoki jarayonga yuborish zarur. Umumiy tanlov qoidasi: I/O-bog'liq, ko'p sonli, yengil vazifalar uchun `asyncio`; I/O-bog'liq, nisbatan kam sonli, "bloklaydigan" kutubxonalar bilan ishlash kerak bo'lganda `threading`; CPU-bog'liq, parallellashtiriladigan og'ir hisoblashlar uchun `multiprocessing`.
