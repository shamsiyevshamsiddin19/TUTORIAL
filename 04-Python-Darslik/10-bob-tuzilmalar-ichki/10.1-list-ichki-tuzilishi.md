# `list` ichida: dinamik massiv va amortizatsiyalangan o'sish

## Bu darsda nimalarni o'rganasiz

- Python `list`ining C darajasida aynan **qanday** saqlanishini bilib olasiz
- "Over-allocation" (zaxira bilan ortiqcha xotira ajratish) strategiyasi nima ekanini va u nega `append()`ni tez qilishini tushunasiz
- Nega `list`ning boshiga qo'shish (`insert(0, x)`) oxiriga qo'shishdan (`append(x)`) sekinroq ekanini isbotlaysiz
- `list` va `array`/`deque` orasidagi farqni, qachon qaysi birini tanlashni bilib olasiz

## Nazariy qism

### `list` — "havolalar massivi", "qiymatlar massivi" emas

Eng muhim tushunish kerak bo'lgan narsa: Python `list`i, C tilidagi massiv (array)dan farqli, **qiymatlarning o'zini emas, balki ularga havolalarni (ko'rsatkichlarni)** ketma-ket saqlaydi. `ro'yxat = [10, "salom", [1, 2], 3.14]` deganingizda, xotirada bitta uzluksiz **ko'rsatkichlar massivi** yaratiladi, va har bir ko'rsatkich alohida, xotiraning boshqa joyida yashovchi haqiqiy obyektga (7.1-darsda ko'rgan `PyObject`larga) ishora qiladi:

```
list obyekti:
┌─────────────────────────────────┐
│ ob_size = 4                     │
│ ob_item -> [ptr0, ptr1, ptr2, ptr3] │
└─────────────────────────────────┘
       │      │      │      │
       ▼      ▼      ▼      ▼
     [10] ["salom"] [[1,2]] [3.14]   <- alohida, xotiraning turli joylarida
```

**Manba:** Ushbu dars CPython'ning `Objects/listobject.c` fayli tuzilishi va "Python behind the scenes" turkumidagi (tenthousandmeters.com) list haqidagi tahlil asosida tuzilgan.

Aynan shu tufayli `list` **har xil turdagi** qiymatlarni bemalol saqlay oladi (7.1-darsda ko'rganingizdek, har bir Python qiymati — o'zi to'liq PyObject, o'lchamidan qat'iy nazar, "ko'rsatkich" — bu doim bir xil o'lchamli, 8 bayt 64-bitli tizimda).

### Over-allocation — nega `append()` "sehrli tarzda" tez

Agar `list` har safar `append()` chaqirilganda **aynan bitta elementga** yetadigan yangi xotira ajratsa (`realloc`), bu — juda sekin bo'lar edi, chunki har bir qo'shishda **butun massivni** yangi joyga ko'chirish kerak bo'lardi (eski xotira yetmay qolgani uchun). Buning o'rniga, CPython **over-allocation** (zaxira bilan ortiqcha ajratish) strategiyasini qo'llaydi: `list` kengayishga muhtoj bo'lganda, u faqat **kerakli** miqdorni emas, balki **kelajakdagi o'sishga zaxira bilan** biroz ko'proq xotira so'raydi.

CPython'ning o'sish formulasi (`listobject.c`dagi `list_resize` funksiyasida) taxminan quyidagicha (soddalashtirilgan):

```
yangi_hajm = (joriy_hajm + (joriy_hajm >> 3) + 6) & ~3
# ya'ni: joriy hajmga ~1/8 qismini qo'shib, biroz "yumaloqlab" o'sadi
```

Bu formulaning aniq raqamlari muhim emas — muhimi, **g'oya**: har safar kengayganda, `list` **kelajakda yana kengayishi mumkinligini hisobga olib**, biroz ortiqcha joy ham ajratadi. Shu tufayli, ko'p hollarda, keyingi bir nechta `append()` chaqiruvi uchun **umuman yangi xotira ajratish kerak bo'lmaydi** — yangi element shunchaki, allaqachon zaxirada turgan bo'sh joyga yoziladi.

```python
import sys

ro_yxat = []
oldingi_hajm = sys.getsizeof(ro_yxat)
for i in range(20):
    ro_yxat.append(i)
    joriy_hajm = sys.getsizeof(ro_yxat)
    if joriy_hajm != oldingi_hajm:
        print(f"{i}-element qo'shilganda xotira O'SDI: {oldingi_hajm} -> {joriy_hajm} bayt")
        oldingi_hajm = joriy_hajm
    else:
        print(f"{i}-element qo'shildi, xotira O'ZGARMADI (zaxiradan foydalanildi)")
```

Natijada siz ko'rasiz: xotira **har elementda emas**, balki "sakrab-sakrab" o'sadi — bu aynan over-allocation strategiyasining amaldagi ko'rinishi.

### Amortizatsiyalangan O(1) — nima degani

Bu strategiya tufayli, `append()`ning **har bir alohida chaqiruvi** ba'zan (kamdan-kam) sekinroq (butun massiv ko'chirilganda), lekin **ko'pchilik chaqiruvlar** juda tez (zaxiradan foydalanilganda) bo'ladi. Agar siz N ta elementni ketma-ket qo'shsangiz, **umumiy** vaqt N ga chiziqli proportsional (O(N)) bo'ladi — ya'ni **o'rtacha, "amortizatsiyalangan" holda**, har bir `append()` — O(1) (doimiy vaqt) hisoblanadi, garchi ayrim alohida chaqiruvlar boshqalaridan sekinroq bo'lsa ham.

### Nega ro'yxatning **boshiga** qo'shish sekin

Ro'yxat elementlari xotirada **uzluksiz** joylashgani uchun, agar siz ro'yxatning **boshiga** yangi element qo'shsangiz (`insert(0, x)`), CPython **barcha mavjud elementlarni bir pozitsiyaga siljitishi** kerak — bu O(N) operatsiya (ro'yxat qanchalik uzun bo'lsa, shunchalik sekin):

```python
import timeit

def oxiriga_qoshish(n):
    ro_yxat = []
    for i in range(n):
        ro_yxat.append(i)     # O(1) amortizatsiyalangan — HAR DOIM tez

def boshiga_qoshish(n):
    ro_yxat = []
    for i in range(n):
        ro_yxat.insert(0, i)  # O(N) HAR SAFAR — n oshgani sari TOBORA sekinlashadi

n = 10_000
vaqt_oxir = timeit.timeit(lambda: oxiriga_qoshish(n), number=5)
vaqt_bosh = timeit.timeit(lambda: boshiga_qoshish(n), number=5)

print(f"Oxiriga qo'shish ({n} marta): {vaqt_oxir:.4f} soniya")
print(f"Boshiga qo'shish ({n} marta): {vaqt_bosh:.4f} soniya")
# boshiga_qoshish ODATDA ko'p ONLAB marta sekinroq bo'ladi!
```

### Yechim: `collections.deque` — ikki tomondan tez

Agar sizga **ro'yxatning ham boshidan, ham oxiridan** tez qo'shish/olib tashlash kerak bo'lsa (masalan, navbat — queue — tuzilmasi uchun), Python standart kutubxonasidagi `collections.deque` (double-ended queue — ikki uchli navbat) — bu holat uchun to'g'ri tanlov. `deque` ichida — bog'langan bloklar zanjiri (linked list of fixed-size blocks) sifatida amalga oshirilgan bo'lib, u ikkala uchida ham O(1) qo'shish/olib tashlashni ta'minlaydi, lekin **o'rtadan** elementga tasodifiy murojaat (`deque[5000]`) `list`ga qaraganda sekinroq (O(N), `list`da esa O(1)):

```python
from collections import deque
import timeit

def deque_boshiga_qoshish(n):
    d = deque()
    for i in range(n):
        d.appendleft(i)   # O(1) — deque UCHUN bu HAR DOIM tez!

n = 10_000
vaqt_deque = timeit.timeit(lambda: deque_boshiga_qoshish(n), number=5)
print(f"deque.appendleft ({n} marta): {vaqt_deque:.4f} soniya")
# Bu list.insert(0, x) dan SEZILARLI tezroq bo'ladi
```

### `list` o'lchamini oldindan bilish — `list(range(...))` vs sikl

Agar yakuniy ro'yxat o'lchami **oldindan ma'lum** bo'lsa, CPython ba'zi holatlarda (masalan `list(iterable)` yoki list comprehension) o'lchamni oldindan hisoblab, **bitta martalik**, to'g'ri o'lchamdagi xotira ajratishi mumkin — bu, alohida `append()` chaqiruvlari ketma-ketligidan ko'ra, ko'pincha biroz samaraliroq (garchi over-allocation tufayli farq odatda katta bo'lmasa ham):

```python
# Ikkalasi ham to'g'ri ishlaydi, lekin list comprehension odatda biroz tezroq,
# chunki CPython ba'zan hajmni oldindan taxmin qilib, kamroq marta qayta ajratadi:
royxat1 = [i * 2 for i in range(100000)]   # comprehension

royxat2 = []
for i in range(100000):
    royxat2.append(i * 2)   # sikl + append
```

## Amaliy misol

`list`ning o'sish naqshini vizual kuzatish va turli operatsiyalarning haqiqiy vaqt murakkabligini o'lchash:

```python
# list_ichki_demo.py
import sys
import timeit
from collections import deque


def osish_naqshini_korsat(soni=50):
    print("--- list o'sish naqshi (xotira sakrashlari) ---")
    ro_yxat = []
    oldingi = sys.getsizeof(ro_yxat)
    sakrashlar = []
    for i in range(soni):
        ro_yxat.append(i)
        joriy = sys.getsizeof(ro_yxat)
        if joriy != oldingi:
            sakrashlar.append((i, oldingi, joriy))
            oldingi = joriy
    for element_soni, eski, yangi in sakrashlar:
        print(f"  {element_soni}-elementda: {eski} -> {yangi} bayt "
              f"(+{yangi - eski} bayt zaxira bilan)")


def tezlik_taqqoslash():
    print("\n--- Operatsiyalar tezligi taqqoslashi (10,000 element) ---")
    n = 10_000

    vaqt = timeit.timeit(
        lambda: [i for i in range(n)],  # append ekvivalenti
        number=100
    )
    print(f"  Oxiriga qo'shish (comprehension): {vaqt:.4f} soniya (100 marta)")

    def boshiga_list():
        d = []
        for i in range(1000):  # kamroq son, chunki juda sekin
            d.insert(0, i)

    def boshiga_deque():
        d = deque()
        for i in range(1000):
            d.appendleft(i)

    vaqt_list = timeit.timeit(boshiga_list, number=20)
    vaqt_deque = timeit.timeit(boshiga_deque, number=20)
    print(f"  list.insert(0, x) x1000: {vaqt_list:.4f} soniya")
    print(f"  deque.appendleft(x) x1000: {vaqt_deque:.4f} soniya")
    print(f"  deque {vaqt_list / vaqt_deque:.1f}x tezroq!")


if __name__ == "__main__":
    osish_naqshini_korsat()
    tezlik_taqqoslash()
```

## Keng tarqalgan xatolar

**Xato 1:** Katta ro'yxatni sikl ichida `insert(0, x)` bilan "teskari tartibda" qurish.
❌
```python
natija = []
for element in manba:
    natija.insert(0, element)   # HAR SAFAR O(N) — umumiy vaqt O(N^2)!
```
✅ To'g'ri: elementlarni oddiy `append()` bilan qo'shib, oxirida bir marta `natija.reverse()` chaqiring (yoki `reversed()` bilan teskari tartibda iteratsiya qiling) — bu O(N) umumiy vaqt beradi, `insert(0, x)`ning O(N²) o'rniga.

**Xato 2:** `list`ni navbat (queue) sifatida, ikkala uchidan ham tez-tez foydalanib ishlatish.
❌
```python
navbat = []
navbat.append(yangi_element)      # oxiriga qo'shish — OK
birinchi = navbat.pop(0)            # BOSHIDAN olib tashlash — O(N), SEKIN!
```
✅ To'g'ri: agar navbat mantig'i kerak bo'lsa (FIFO — birinchi kirgan, birinchi chiqadi), `collections.deque` ishlating: `navbat.append(x)` va `navbat.popleft()` — ikkalasi ham O(1).

**Xato 3:** `list`ning xotira sarfini "elementlar sonini elementlarning o'lchamiga ko'paytirish" orqali noto'g'ri hisoblash.
❌ "1000 ta `int` bor, har biri 28 bayt, demak ro'yxat 28000 bayt" deb hisoblash.
✅ To'g'ri: `list`ning o'zi faqat **ko'rsatkichlar massivi**ni saqlaydi (odatda 8 bayt/element, 64-bitli tizimda), + over-allocation zaxirasi. Ichidagi haqiqiy obyektlar (masalan `int`lar) — **alohida** xotira egallaydi, va agar ular boshqa joylarda ham (masalan, 7.4-darsda ko'rgan kichik sonlar keshida) ishlatilayotgan bo'lsa, ularning xotirasi "qayta hisoblanmasligi" ham mumkin. To'g'ri o'lchash uchun 7.3-darsda ko'rgan `sys.getsizeof()` va `tracemalloc`dan foydalaning.

## Mashq/topshiriq

**(Oson)** Bo'sh ro'yxatga 0 dan 100 gacha elementlarni birma-bir `append()` bilan qo'shing va `sys.getsizeof()` yordamida xotira qachon "sakrashini" (necha marta va qaysi elementlarda) aniqlang.

**(O'rtacha)** `timeit` yordamida, 5000 elementli ro'yxatning **oxiridan** (`pop()`) va **boshidan** (`pop(0)`) elementlarni birma-bir olib tashlashni solishtiring. Qaysi biri tezroq ekanini va nima uchun ekanini tushuntiring.

**(Qiyin)** "Oxirgi N ta faoliyat" (masalan, oxirgi 10 ta chat xabari) saqlanadigan tizim yozing: yangi element qo'shilganda, agar ro'yxat uzunligi 10 dan oshsa, eng eskisi (boshidagi) avtomatik olib tashlansin. Buni ikki usulda amalga oshiring: (1) oddiy `list` bilan (`pop(0)` ishlatib), (2) `collections.deque(maxlen=10)` bilan (bu parametr avtomatik "eskini chiqarib tashlash" mantig'ini o'z ichiga oladi). `timeit` bilan 100,000 marta qo'shish operatsiyasida ikkalasini solishtiring.

## Qisqacha xulosa

CPython `list`i xotirada elementlarning o'zini emas, balki ularga **ko'rsatkichlarni** uzluksiz massivda saqlaydi, va kengayish kerak bo'lganda **over-allocation** (kelajakka zaxira bilan ortiqcha ajratish) strategiyasidan foydalanadi — aynan shu tufayli `append()` **amortizatsiyalangan O(1)** tezlikda ishlaydi. Lekin bu uzluksizlik narxi ham bor: ro'yxatning **boshiga** qo'shish/olib tashlash O(N) (barcha qolgan elementlarni siljitish kerak), shuning uchun ikkala uchidan ham tez-tez foydalaniladigan navbat (queue) uchun `collections.deque` — to'g'ri, samarali tanlov hisoblanadi.
