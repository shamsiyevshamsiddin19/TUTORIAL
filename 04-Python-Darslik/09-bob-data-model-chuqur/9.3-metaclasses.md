# Metaclasses — `type` nima va klasslar qanday yaratiladi

## Bu darsda nimalarni o'rganasiz

- "Klass — bu ham obyekt" degani nimani anglatishini va `type`ning haqiqiy rolini tushunasiz
- Klass qanday yaratilishini (`type()` ni to'g'ridan-to'g'ri chaqirish orqali) qo'lda ko'rasiz
- **Metaclass** nima ekanini va qachon (kamdan-kam, lekin kuchli holatlarda) foydali bo'lishini bilib olasiz
- `__new__` va `__init__` orasidagi farqni, va `__init_subclass__` kabi zamonaviy alternativalarni o'rganasiz

## Nazariy qism

### "Hamma narsa obyekt" — klasslar ham shu jumladan

7.1-darsda "Python'da hamma narsa obyekt" degan tamoyilni ko'rdik. Bu tamoyil **klasslarning o'ziga ham** taalluqli: `MeningKlassim` deb yozganingizda, siz shunchaki "andoza" emas, balki **o'zi ham to'liq huquqli obyekt** bo'lgan narsa yaratasiz:

```python
class Mashina:
    pass

print(type(Mashina))          # <class 'type'> — Mashina klassining O'ZI ham bir obyekt,
                                # va uning turi — 'type'!
print(isinstance(Mashina, type))   # True
print(isinstance(Mashina, object))  # True — klass ham object'dan meros oladi
```

**Manba:** Ushbu dars Python rasmiy hujjatlari (`docs.python.org`dagi data model bo'limi) va CPython manba kodidagi `Objects/typeobject.c` tuzilishi asosida tuzilgan.

### `type` — "klasslarning klassi"

`type` — bu maxsus, o'z-o'ziga ishora qiluvchi tuzilma: u **klasslarni yaratuvchi klass**. Har qanday oddiy klass (`Mashina`, `int`, `str`, `list`...) — `type`ning **instance**i (obyekti):

```python
print(type(5))          # <class 'int'>       — 5 ning turi int
print(type(int))         # <class 'type'>       — int'ning turi type!
print(type("salom"))     # <class 'str'>        — "salom"ning turi str
print(type(str))          # <class 'type'>       — str'ning turi ham type!
print(type(type))          # <class 'type'>       — type'ning o'zi ham o'z-o'zining turi!
```

Bu — Python'ning tur tizimidagi eng chuqur "aylana": `type` — o'zi `type`ning instance'i. Bu, aslida, ko'plab dinamik tillarning umumiy dizayn xususiyati — biror joyda "meta-daraja" tugashi kerak, va Python'da bu `type` bilan tugaydi.

### `type()`ni funksiya sifatida VA klass yaratish vositasi sifatida ishlatish

`type()`ning ikkita mutlaqo boshqa qo'llanilishi bor:

1. **Bitta argument bilan** — obyektning turini qaytaradi (buni ko'p ishlatgansiz: `type(5)`).
2. **Uchta argument bilan** — `type(nom, ota_klasslar, nomlar_maydoni)` — **yangi klass yaratadi**, `class` kalit so'zi bilan yozilgan har qanday klassga ekvivalent!

```python
# Oddiy usul:
class Nuqta:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def masofa(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5


# type() orqali AYNAN SHU KLASSNI qo'lda yaratish:
def __init__(self, x, y):
    self.x = x
    self.y = y

def masofa(self):
    return (self.x ** 2 + self.y ** 2) ** 0.5

Nuqta2 = type(
    "Nuqta2",                                # klass nomi
    (object,),                                # ota-klasslar (tuple)
    {"__init__": __init__, "masofa": masofa}  # nomlar maydoni (metodlar, atributlar)
)

n = Nuqta2(3, 4)
print(n.masofa())   # 5.0 — xuddi oddiy klassdek ishlaydi!
print(type(Nuqta2))   # <class 'type'>
```

Bu — muhim tushuncha: `class Nuqta: ...` sintaksisi — bu shunchaki **`type()` chaqiruvi uchun qulay, o'qilishi oson "shakar" (syntactic sugar)**. Python interpretatori `class` blokini o'qib, klass tanasini (metodlar, atributlar) bajarib, natijada hosil bo'lgan nomlar maydonini yig'ib, oxirida **aynan xuddi shunday** `type(nom, ota_klasslar, nomlar_maydoni)` chaqiruvini amalga oshiradi.

### Metaclass — "klass yaratuvchi klass" ni o'zgartirish

Endi asosiy savolga kelamiz: agar `type` — klasslarni yaratuvchi bo'lsa, nima bo'ladi, agar biz **`type`ning o'zini** almashtirsak — ya'ni klass yaratilish jarayonining o'zini nazorat qilsak? Aynan shu — **metaclass** tushunchasi: **metaclass — bu klasslarni yaratuvchi klass**, xuddi oddiy klass obyektlarni yaratganidek.

```python
class MeningMetaklassim(type):
    """type'dan meros oladi va klass yaratilish jarayonini "ushlab qoladi"."""

    def __new__(mcs, nom, ota_klasslar, nomlar_maydoni):
        print(f"[METACLASS] '{nom}' nomli klass yaratilmoqda...")
        print(f"[METACLASS] Metodlar: {[k for k in nomlar_maydoni if not k.startswith('__')]}")
        return super().__new__(mcs, nom, ota_klasslar, nomlar_maydoni)


class MeningKlassim(metaclass=MeningMetaklassim):
    def metod_1(self):
        pass

    def metod_2(self):
        pass

# Konsolda darhol chiqadi:
# [METACLASS] 'MeningKlassim' nomli klass yaratilmoqda...
# [METACLASS] Metodlar: ['metod_1', 'metod_2']
```

Diqqat qiling: bu kod **klass yaratilgan zahoti** (`MeningKlassim` e'lon qilinganda, hali hech qanday instance yaratilmasdan!) ishlaydi — chunki metaclass klass **qurilish jarayoni**ni o'zgartiradi, oddiy `__init__` esa faqat **instance** yaratilganda ishlaydi.

### Nega metaclass kerak bo'lishi mumkin (kamdan-kam, lekin real holatlar)

Metaclass — Python'dagi eng "ilg'or" (va eng kam ishlatiladigan) vositalardan biri. Amaliy foydalanish holatlari:

- **Avtomatik ro'yxatga olish (registry):** yangi klass yaratilganda uni avtomatik markaziy ro'yxatga qo'shish (masalan, plugin tizimlarida).
- **Interfeys/qoidalarni majburlash:** klass yaratilishida majburiy metodlar borligini tekshirish (garchi buning uchun odatda `abc.ABC` — 4.5-darsda ko'rgan — yetarli, chunki u ham metaclass orqali ishlaydi).
- **ORM tizimlari** (masalan, Django ORM, SQLAlchemy) — klass darajasida e'lon qilingan atributlarni (`nom = CharField()`) ma'lumotlar bazasi sxemasiga avtomatik aylantirish uchun metaclass ishlatiladi.

```python
# Sodda "avtomatik ro'yxatga olish" misoli
RO_YXAT = {}

class RoyxatgaOluvchiMeta(type):
    def __new__(mcs, nom, ota_klasslar, nomlar_maydoni):
        yangi_klass = super().__new__(mcs, nom, ota_klasslar, nomlar_maydoni)
        if nom != "Bazaviy":   # bazaviy klassning o'zini ro'yxatga olmaymiz
            RO_YXAT[nom] = yangi_klass
        return yangi_klass


class Bazaviy(metaclass=RoyxatgaOluvchiMeta):
    pass


class PlaginA(Bazaviy):
    pass


class PlaginB(Bazaviy):
    pass


print(RO_YXAT)   # {'PlaginA': <class 'PlaginA'>, 'PlaginB': <class 'PlaginB'>}
# — HAR BIR yangi "plagin" klassi AVTOMATIK, __init__ ga tegilmasdan ro'yxatga qo'shildi!
```

### Zamonaviy alternativa: `__init_subclass__`

Ko'p oddiy holatlarda (masalan, yuqoridagi avtomatik ro'yxatga olish misolida), to'liq metaclass yozish **ortiqcha murakkablik** bo'lishi mumkin. Python 3.6'dan boshlab, ko'p holatlarda **`__init_subclass__`** klass metodi bir xil natijani, ancha soddaroq beradi:

```python
class Bazaviy:
    RO_YXAT = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Bazaviy.RO_YXAT[cls.__name__] = cls


class PlaginA(Bazaviy):
    pass


class PlaginB(Bazaviy):
    pass


print(Bazaviy.RO_YXAT)   # {'PlaginA': ..., 'PlaginB': ...} — metaclass'siz, xuddi shu natija!
```

**Amaliy qoida:** agar sizga faqat "klass yaratilganda biror amal bajarish" kerak bo'lsa — `__init_subclass__` yetarli va soddaroq. Metaclass faqat **klass yaratilish jarayonining o'zini** (masalan, qaysi asos klasslar ishlatiladi, nomlar maydoni qanday tuziladi) chuqur o'zgartirish kerak bo'lganda ishlatilishi kerak.

### `__new__` vs `__init__` — farq nimada

4-bobda `__init__`ni ko'rgan bo'lsangiz-da, `__new__` haqida to'liq gapirilmagan edi. Farq muhim:

- **`__new__(cls, ...)`** — **yangi obyektni yaratadi** va uni **qaytaradi** (bu — `staticmethod`, garchi maxsus tarzda ishlov beriladi). Bu — obyekt xotirada **paydo bo'lishidan** oldingi bosqich.
- **`__init__(self, ...)`** — **allaqachon yaratilgan** obyektni **boshlang'ich holatga keltiradi**. Hech narsa qaytarmaydi (`None` qaytarishi shart).

```python
class Kuzatuvchi:
    def __new__(cls, *args, **kwargs):
        print("1. __new__ chaqirildi — obyekt HALI YO'Q")
        instance = super().__new__(cls)
        return instance

    def __init__(self, qiymat):
        print("2. __init__ chaqirildi — obyekt ALLAQACHON mavjud, endi sozlanmoqda")
        self.qiymat = qiymat


k = Kuzatuvchi(42)
```

`__new__` odatiy holatlarda deyarli hech qachon qayta yozilmaydi (`object.__new__` yetarli), lekin u **immutable turlarni** (masalan, `int`, `str`, `tuple`ning subklasslarini) sozlashda **shart** — chunki immutable obyektning qiymati `__init__`da emas, balki **yaratilish paytida** (`__new__`da) belgilanadi:

```python
class IjobiySon(int):
    def __new__(cls, qiymat):
        if qiymat <= 0:
            raise ValueError("Faqat musbat sonlar!")
        return super().__new__(cls, qiymat)   # int qiymati AYNAN SHU YERDA belgilanadi


son = IjobiySon(5)
print(son, type(son))   # 5 <class 'IjobiySon'>

try:
    IjobiySon(-5)
except ValueError as e:
    print("Xatolik:", e)
```

## Amaliy misol

`__init_subclass__` yordamida, barcha "buyruq" (command) klasslarini avtomatik ro'yxatga oluvchi, va ularni nomi bo'yicha chaqiruvchi kichik CLI-uslubidagi tizim:

```python
# metaclass_yoki_init_subclass_demo.py

class Buyruq:
    """Barcha buyruqlar shundan meros oladi; har biri AVTOMATIK ro'yxatdan o'tadi."""
    REYESTR = {}

    def __init_subclass__(cls, nom=None, **kwargs):
        super().__init_subclass__(**kwargs)
        buyruq_nomi = nom or cls.__name__.lower()
        Buyruq.REYESTR[buyruq_nomi] = cls
        print(f"[RO'YXATGA OLINDI] '{buyruq_nomi}' -> {cls.__name__}")

    def bajar(self, *args):
        raise NotImplementedError


class SalomBuyrugi(Buyruq, nom="salom"):
    def bajar(self, *args):
        ism = args[0] if args else "Dunyo"
        return f"Salom, {ism}!"


class HisoblaBuyrugi(Buyruq, nom="hisobla"):
    def bajar(self, *args):
        sonlar = [float(a) for a in args]
        return f"Yig'indi: {sum(sonlar)}"


def buyruqni_bajar(nom, *args):
    klass = Buyruq.REYESTR.get(nom)
    if klass is None:
        return f"Noma'lum buyruq: {nom}"
    return klass().bajar(*args)


print("\n--- Buyruqlarni bajarish ---")
print(buyruqni_bajar("salom", "Shamsiddin"))
print(buyruqni_bajar("hisobla", "10", "20", "30"))
print(buyruqni_bajar("nomavjud"))
```

Bu naqsh — real dasturlarda (masalan, `click` yoki `argparse` asosidagi murakkab CLI vositalar, yoki Django'dagi model/forma tizimlari) juda keng qo'llaniladi: yangi "buyruq" yoki "modul" qo'shish uchun **markaziy ro'yxatga qo'lda yozish shart emas** — shunchaki yangi klass yozish kifoya, u o'zini-o'zi ro'yxatga oladi.

## Keng tarqalgan xatolar

**Xato 1:** Har qanday muammoni metaclass bilan hal qilishga urinish.
❌ Oddiy avtomatik ro'yxatga olish yoki tekshiruv uchun to'liq, murakkab metaclass yozish.
✅ To'g'ri: Tim Peters (Python jamoasining faxriysi)ning mashhur so'zlariga ko'ra — "Metaclasses are deeper magic than 99% of users should ever worry about" (Metaclasslar — foydalanuvchilarning 99%i hech qachon o'ylashi shart bo'lmagan chuqur sehr). Avval `__init_subclass__`, dekoratorlar (5.4-dars) yoki oddiy funksiyalar bilan yechim izlang — metaclass faqat ular yetarli bo'lmagan, chinakam noyob holatlarda kerak.

**Xato 2:** Bir nechta metaclassdan meros olishga urinish, ular mos kelmasa.
❌
```python
class MetaA(type): pass
class MetaB(type): pass

class Klass(metaclass=MetaA):
    pass

class Boshqa(metaclass=MetaB):
    pass

class Muammoli(Klass, Boshqa):   # TypeError: metaclass conflict!
    pass
```
✅ To'g'ri: agar sizga ikkita turli metaclass funksionalligini birlashtirish kerak bo'lsa, ulardan meros oluvchi **yangi, uchinchi** metaclass yarating (`class MetaC(MetaA, MetaB): pass`), va uni ishlating.

**Xato 3:** `__new__` va `__init__`ni chalkashtirib, `__new__`da instance holatini sozlashga urinish (odatdagi, mutable klasslar uchun).
❌
```python
class Nuqta:
    def __new__(cls, x, y):
        instance = super().__new__(cls)
        instance.x = x   # bu YOMON amaliyot — bu ish __init__ ga tegishli!
        instance.y = y
        return instance
```
✅ To'g'ri: oddiy, mutable klasslar uchun `self.x = x` kabi sozlashlarni **`__init__`da** qiling. `__new__`ni faqat immutable turlarni subklasslashda, yoki obyekt yaratilishini o'zi nazorat qilish kerak bo'lganda (masalan, Singleton naqshida) qayta yozing.

## Mashq/topshiriq

**(Oson)** `type()` funksiyasini uch argument bilan chaqirib, `Hayvon` nomli, `ovoz_chiqar` metodi bor klass yarating (metod ichida `"..."` chop etsin). Yaratilgan klassdan instance oling va metodni chaqiring.

**(O'rtacha)** `__init_subclass__` yordamida, har bir subklass albatta `versiya` nomli klass atributiga ega bo'lishini **majburlaydigan** bazaviy klass yozing (agar `versiya` yo'q bo'lsa, `TypeError` chiqarsin — klass e'lon qilinayotgan **paytda**, hali instance yaratilmasdan).

**(Qiyin)** Oddiy **Singleton** naqshini `__new__` orqali amalga oshiring — ya'ni, klassdan nechta marta `Klass()` chaqirilmasin, har doim **bir xil, bitta** instance qaytarilsin. Buni sinash uchun ikkita alohida chaqiruv natijasini `is` bilan solishtiring va ular bir xil ekanini isbotlang.

class Singleton:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            print("Yangi instance yaratilmoqda...")
            cls._instance = super().__new__(cls)
        else:
            print("Mavjud instance qaytarilmoqda...")
        return cls._instance

    def __init__(self, qiymat=None):
        # E'TIBOR: __init__ HAR DOIM chaqiriladi, hattoki instance eski bo'lsa ham!
        if qiymat is not None:
            self.qiymat = qiymat


a = Singleton(1)
b = Singleton(2)
print(a is b)         # True — bir xil obyekt!
print(a.qiymat, b.qiymat)   # 2 2 — ikkalasi ham BITTA obyektga ishora qilgani uchun

## Qisqacha xulosa

Python'da klasslarning o'zi ham obyekt bo'lib, ular `type` — "klasslarni yaratuvchi klass" (metaclass)ning instance'lari hisoblanadi; `class` kaliti bilan yozilgan har qanday klass, aslida, `type(nom, ota_klasslar, nomlar_maydoni)`ning qulay yozuv shakli, xolos. **Metaclass** — `type`dan meros olib, klass yaratilish jarayonining o'zini nazorat qiluvchi mexanizm bo'lib, u kuchli, ammo kamdan-kam kerak bo'ladigan vosita — ko'p oddiy holatlarda (masalan, avtomatik ro'yxatga olish) zamonaviy, soddaroq `__init_subclass__` yetarli bo'ladi. `__new__` (obyekt yaratish) va `__init__` (obyektni sozlash) orasidagi farq esa — ayniqsa immutable turlarni subklasslashda va Singleton kabi naqshlarda muhim ahamiyat kasb etadi.
