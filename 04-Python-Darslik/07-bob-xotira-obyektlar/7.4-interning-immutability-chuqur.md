# Interning, kichik butun sonlar keshi va immutability chuqur

## Bu darsda nimalarni o'rganasiz

- **Interning** nima ekanini va CPython uni qaysi obyektlar uchun avtomatik qo'llashini bilib olasiz
- Kichik butun sonlar keshi (-5 dan 256 gacha) va uning aynan nima uchun mavjudligini tushunasiz
- Satrlarning interning qoidalarini (`sys.intern()` bilan qo'lda interning ham) o'rganasiz
- "Immutable (o'zgarmas) obyekt" degani C darajasida nimani anglatishini, va bu nega interning uchun **shart** ekanini tushunasiz

## Nazariy qism

**Manba:** [Python rasmiy dokumentatsiyasi — sys.intern()](https://docs.python.org/3/library/sys.html#sys.intern), CPython manba kodi (`Objects/longobject.c` — kichik butun sonlar keshi, `Objects/codeobject.c` — kompilyatsiya vaqtidagi satr interning qoidalari).

### Interning nima va nega u mumkin

7.1-darsda `is` operatori ikkita o'zgaruvchi **aynan bitta xuddi shu obyektga** ishora qilishini tekshirishini ko'rdik. Odatda, ikkita alohida `[1, 2, 3]` yaratsangiz, ular xotirada ikki xil joyda yashaydi. Lekin ba'zi holatlarda CPython **ataylab** bir xil qiymatga ega bo'lgan obyektlarni **qayta ishlatadi** — bu jarayon **interning** deb ataladi.

Interning faqat **immutable** (o'zgarmas) turlar uchun mumkin — chunki agar ikkita o'zgaruvchi bitta obyektga ishora qilsa-yu, biri uni o'zgartirsa, ikkinchisi ham "kutilmagan" tarzda o'zgargan bo'lardi. `int`, `str`, `float`, `bool`, `tuple` — immutable, `list`, `dict`, `set` — mutable (o'zgaruvchan) va shuning uchun **hech qachon** interned bo'lmaydi.

```python
a = [1, 2, 3]
b = [1, 2, 3]
print(a is b)   # HAR DOIM False — list mutable, interning imkonsiz

a = (1, 2, 3)
b = (1, 2, 3)
print(a is b)   # implementatsiyaga bog'liq — ba'zan True (kichik, literal tuple'lar uchun)
```

### Kichik butun sonlar keshi (small integer cache)

CPython dastur ishga tushganda, **-5 dan 256 gacha** bo'lgan barcha butun sonlarni **oldindan, bir marta** yaratib, doimiy saqlab qo'yadi. Bu son diapazoni tanlangan, chunki amaliyotda dasturlarda eng ko'p ishlatiladigan kichik sonlar (masalan, sikl indekslari, kichik hisoblagichlar, `True`/`False`ning ichki qiymatlari) aynan shu oraliqda joylashadi:

```python
a = 100
b = 100
print(a is b)   # True — ikkalasi ham xuddi o'sha "keshdagi 100" obyektiga ishora qiladi

a = 1000
b = 1000
print(a is b)   # odatda False — 256 dan katta, har biri (ehtimol) alohida obyekt

a = -5
b = -5
print(a is b)   # True — -5 ham keshning chekka nuqtasi

a = -6
b = -6
print(a is b)   # odatda False — kesh -5 dan boshlanadi
```

**Muhim ogohlantirish:** bu — Python tilining rasmiy kafolati **EMAS**, balki CPython'ning ichki optimallashtirish tafsiloti. Boshqa Python implementatsiyasida (PyPy, Jython) yoki hattoki kelajakdagi CPython versiyasida bu xatti-harakat o'zgarishi mumkin. Shuning uchun **hech qachon** kodda `is` orqali sonlarni solishtirmang — har doim `==` ishlating.

### Nega aynan -5..256

Bu chegara CPython manba kodida (`Objects/longobject.c`) qat'iy belgilangan doimiy son. Tanlovning mantig'i — bu diapazon kichik sonlarning **statistik jihatdan eng ko'p ishlatiladigan** qismini qamrab oladi (indekslash, hisoblash, kichik konstantalar), va uni **doimiy** ushlab turish narxi (256 + 5 + 1 ta obyekt uchun xotira) juda kichik, lekin foyda (millionlab qayta yaratishning oldini olish) katta.

### Satr interning — qoidalar biroz murakkabroq

Satrlar (`str`) uchun interning qoidalari sonlardan farqli, biroz murakkabroq va **CPython versiyasiga qarab** o'zgarishi mumkin. Umumiy qoida: **kompilyatsiya vaqtida (compile-time) ma'lum bo'ladigan, faqat harflar/raqamlar/pastki chiziqdan iborat qisqa satrlar** (Python identifikatorlariga o'xshash — masalan `"salom"`, `"x"`, `"nom_1"`) odatda avtomatik interned bo'ladi, chunki interpretator ularni o'zgaruvchi nomlari, funksiya nomlari va shu kabi narsalar sifatida juda tez-tez ishlatadi va interning xotirani sezilarli tejaydi:

```python
a = "salom"
b = "salom"
print(a is b)   # odatda True — bu satr Python identifikatoriga o'xshaydi (harflar, pastki chiziq)

a = "salom dunyo!"   # bo'shliq va undov belgisi bor
b = "salom dunyo!"
print(a is b)   # implementatsiyaga bog'liq, ko'pincha False (runtime'da "birlashtirilgan" bo'lmasa)

a = "".join(["sal", "om"])   # runtime'da DINAMIK yaratilgan satr
b = "salom"
print(a is b)   # odatda False — hatto qiymatlar bir xil bo'lsa ham, dinamik yaratilgan satr avtomatik interned emas
print(a == b)   # True — albatta, qiymatlar bir xil
```

### `sys.intern()` — qo'lda interning

Agar sizning dasturingiz millionlab bir xil, lekin dinamik yaratiladigan satrlar bilan ishlasa (masalan, katta matn faylini so'z-so'z tahlil qilayotgan bo'lsangiz, va ko'plab so'zlar takrorlansa), siz `sys.intern()` yordamida **qo'lda** interning qilib, xotirani tejashingiz mumkin:

```python
import sys

so'zlar_royxati = ["salom", "dunyo", "salom", "python", "dunyo", "salom"]
interned = [sys.intern(soz) for soz in so'zlar_royxati]

# Endi "salom" so'zining har uchta nusxasi AYNAN BITTA xotiradagi obyektga ishora qiladi,
# uch marta alohida saqlanish o'rniga
print(interned[0] is interned[2] is interned[5])   # True

# Bu nafaqat xotirani tejaydi, balki solishtirishni ham tezlashtiradi:
# interned satrlarni == bilan solishtirishda, avval "is" tekshiruvi (juda tez,
# faqat manzillarni solishtirish) qilinishi mumkin, va agar is True bo'lsa,
# butun satrni belgi-belgi solishtirish shart emas.
```

### Immutability C darajasida nimani anglatadi

"O'zgarmas (immutable)" degani C darajasida — obyekt yaratilgandan keyin, uning **ichidagi qiymat maydonlari** hech qachon o'zgartirilmasligi kerakligi haqidagi **kelishuv** (invariant), chunki CPython interpretatori interning, keshlash va boshqa optimallashtirishlarni aynan shu kafolatga tayanib quradi. Masalan `int` obyektining ichidagi raqamlar massivi (`ob_digit`) yaratilgandan keyin **hech qachon** o'zgartirilmaydi — `x = x + 1` deganingizda, mavjud `x` obyekti o'zgartirilmaydi, balki **yangi** `int` obyekti yaratilib, `x` o'zgaruvchisi shu yangi obyektga qayta bog'lanadi:

```python
x = 5
print(id(x))   # masalan: 140234...728
x = x + 1
print(id(x))   # BOSHQA manzil — chunki yangi obyekt yaratildi, eskisi o'zgartirilmadi!

# Solishtirish uchun — mutable obyekt:
royxat = [1, 2, 3]
print(id(royxat))   # masalan: 140234...900
royxat.append(4)
print(id(royxat))   # XUDDI O'SHA manzil — mavjud obyekt o'zgartirildi (mutated)!
```

Bu farq — Python'da **funksiyaga argument uzatish** (5-bobda ko'rgan "pass by reference" tushunchasi) qanday ishlashini tushunish uchun **hal qiluvchi** ahamiyatga ega: mutable obyekt funksiyaga uzatilsa, funksiya ichida uni o'zgartirish tashqaridagi obyektga ham ta'sir qiladi (chunki bu **bitta xuddi shu** obyekt), immutable obyekt esa funksiya ichida "o'zgartirilganda" aslida yangi obyekt yaratiladi va tashqarisiga hech qanday ta'sir qilmaydi.

```python
def royxatga_qosh(r):
    r.append(100)   # MAVJUD ro'yxatni o'zgartiradi (mutation)

def songa_qosh(s):
    s = s + 100      # YANGI son yaratadi, lokal s ni qayta bog'laydi — tashqarisiga ta'sir yo'q

mening_royxatim = [1, 2, 3]
royxatga_qosh(mening_royxatim)
print(mening_royxatim)   # [1, 2, 3, 100] — o'zgardi!

mening_sonim = 5
songa_qosh(mening_sonim)
print(mening_sonim)   # 5 — o'zgarmadi!
```

## Amaliy misol

Interning ta'sirini xotira va tezlik nuqtai nazaridan kuzatish:

```python
# interning_demo.py
import sys
import time


def small_int_cache_demo():
    print("--- Kichik butun sonlar keshi ---")
    for son in [-6, -5, 0, 100, 256, 257, 1000]:
        a = son
        b = int(str(son))   # ataylab "dinamik" yaratamiz (str -> int), keshni chetlab o'tish uchun urinish
        natija = "BIR XIL obyekt (kesh ishladi)" if a is b else "BOSHQA obyekt"
        print(f"{son:>6}: {natija}")


def string_interning_demo():
    print("\n--- Satr interning ---")
    a = "python_darsi"        # identifikatorga o'xshaydi -> avtomatik interned bo'lishi mumkin
    b = "python_darsi"
    print("Statik, bir xil ikkita literal satr:", a is b)

    c = "".join(["python", "_", "darsi"])   # dinamik yaratilgan
    print("Dinamik yaratilgan (join orqali):", a is c, "  (qiymat baribir teng:", a == c, ")")

    d = sys.intern(c)
    print("sys.intern() dan keyin:", a is d)


def intern_tezlik_taqqoslash(soni=2_000_000):
    print(f"\n--- {soni:,} ta satrni solishtirish: intern qilingan vs oddiy ---")

    oddiy = [str(i % 1000) for i in range(soni)]
    interned = [sys.intern(str(i % 1000)) for i in range(soni)]

    boshlanish = time.perf_counter()
    for i in range(len(oddiy) - 1):
        _ = oddiy[i] == oddiy[i + 1]
    oddiy_vaqt = time.perf_counter() - boshlanish

    boshlanish = time.perf_counter()
    for i in range(len(interned) - 1):
        _ = interned[i] == interned[i + 1]
    interned_vaqt = time.perf_counter() - boshlanish

    print(f"Oddiy satrlar bilan solishtirish: {oddiy_vaqt:.4f} soniya")
    print(f"Interned satrlar bilan solishtirish: {interned_vaqt:.4f} soniya")


if __name__ == "__main__":
    small_int_cache_demo()
    string_interning_demo()
    intern_tezlik_taqqoslash()
```

## Keng tarqalgan xatolar

**Xato 1:** Kodda `is` ni sonlar yoki satrlarni solishtirish uchun ishlatish, "chunki test qilganimda ishladi".
❌
```python
if foydalanuvchi_id is 12345:   # xavfli! kichik sonlar keshiga tasodifan tushib qolgani uchun "ishlaydi"
    ...
if foydalanuvchi_nomi is "admin":   # yana ham xavfliroq — bu deyarli har doim False bo'lishi mumkin
    ...
```
✅ To'g'ri: har doim `==` ishlating. `is` faqat `None`, `True`, `False` va "aynan shu bitta obyektmi" degan maxsus, ataylab qilingan tekshiruvlar uchun.

**Xato 2:** Immutable obyektni "o'zgartirdim" deb o'ylab, aslida uni to'g'ri yangilamaslik.
❌
```python
def satrni_kattalashtir(s):
    s.upper()   # bu YANGI satr QAYTARADI, lekin s o'zgaruvchisini o'zgartirmaydi!
    return s

natija = satrni_kattalashtir("salom")
print(natija)   # hali ham "salom", "SALOM" emas!
```
✅ To'g'ri: immutable obyektlarning metodlari (masalan `str.upper()`) har doim **yangi** obyekt qaytaradi, mavjudini o'zgartirmaydi — natijani albatta qaytarish yoki qayta tayinlash kerak: `return s.upper()`.

**Xato 3:** Katta miqdordagi noyob (deyarli hech qachon takrorlanmaydigan) satrlarni `sys.intern()` bilan interning qilib, xotirani "tejashga" urinish.
❌ Har bir foydalanuvchi tomonidan kiritilgan, deyarli hech qachon takrorlanmaydigan matnni `sys.intern()` qilish.
✅ To'g'ri: interning faqat **ko'p marta takrorlanadigan** qiymatlar uchun foydali (masalan, katta faylni tokenlashtirishda ko'p takrorlanuvchi so'zlar, yoki lug'at kalitlari sifatida ishlatiladigan cheklangan to'plamdagi satrlar). Noyob satrlarni interning qilish faqat qo'shimcha ishlov vaqtini oshiradi, hech qanday foyda bermaydi (chunki takrorlanish bo'lmasa, qayta ishlatish ham bo'lmaydi).

## Qisqacha xulosa

Interning — CPython ba'zi **immutable** obyektlarni (kichik butun sonlar -5..256, va identifikatorga o'xshash qisqa satrlar) yagona nusxada saqlab, qayta-qayta ishlatishi, va bu — faqat immutability tufayli xavfsiz bo'lgan optimallashtirish; bu Python tilining rasmiy kafolati emas, shuning uchun kodda hech qachon qiymat solishtirish uchun `is` emas, `==` ishlatilishi kerak. Immutable obyektning "o'zgargandek" ko'rinishi aslida har doim **yangi** obyekt yaratilishini anglatadi (eskisi o'zgarmaydi), mutable obyektlar esa joyida o'zgartiriladi (mutated) — bu farq funksiyalarga argument uzatish xatti-harakatini tushunish uchun asosiy kalitdir.
