# PyObject, reference counting va `id()` ning haqiqiy ma'nosi

## Bu darsda nimalarni o'rganasiz

- Python'da **mutlaqo hamma narsa** — son, satr, funksiya, klass — nega "ob'ekt" ekanini, va bu ob'ekt C darajasida qanday ko'rinishini tushunasiz
- `PyObject` va `PyTypeObject` tuzilmalarining vazifasini bilib olasiz
- Reference counting (havolalar sonini sanash) qanday ishlashini va nega Python'da xotira "o'zi" tozalanishini tushunasiz
- `id()`, `sys.getrefcount()` va `is` operatorining haqiqiy, past darajadagi ma'nosini bilasiz

## Nazariy qism

### Nega bu dars muhim

Oldingi 6 bobda siz Python'da **qanday yozish kerakligini** o'rgandingiz. Endi savol o'zgaradi: `x = 5` deb yozganingizda, kompyuter xotirasida **aynan nima sodir bo'ladi**? Bu savolga javob bermasdan, Python dasturchisi hech qachon "nega mening dasturim sekin ishlayapti", "nega bu ikki ro'yxat bir xil ko'rinsa ham `is` bilan solishtirilganda `False` beradi" yoki "nega xotira sarfi kutilganidan ko'p" kabi savollarga chuqur javob bera olmaydi. 07-14-boblar aynan shu — Python tilining "old tomoni" ostida yotgan **CPython** (Python'ning eng ko'p ishlatiladigan, C tilida yozilgan rasmiy implementatsiyasi) haqida.

**Manba:** Ushbu bob CPython loyihasining rasmiy `InternalDocs/` hujjatlari (https://github.com/python/cpython/tree/main/InternalDocs) va CPython manba kodi (`Include/object.h`) asosida tuzilgan.

### Python'da "hamma narsa ob'ekt" degani nima

Boshqa ba'zi tillarda (masalan C yoki Java'ning primitiv turlari) son — bu shunchaki xotiradagi bir necha bayt, hech qanday "qobiq"siz. Python'da esa **hatto eng oddiy `5` soni ham** to'liq huquqli ob'ekt: uning turi (`type`), qiymati va — eng muhimi — **nechta joyda ishlatilayotgani (reference count)** haqida ma'lumot saqlaydi.

CPython manba kodida (`Include/object.h`) har bir ob'ekt boshida quyidagi tuzilma turadi (soddalashtirilgan):

```c
typedef struct _object {
    Py_ssize_t ob_refcnt;      // nechta joydan bu obyektga havola bor
    PyTypeObject *ob_type;      // bu obyekt qaysi turga tegishli (int, str, MyClass...)
} PyObject;
```

Ya'ni **har qanday** Python qiymati — `5`, `"salom"`, `[1, 2, 3]`, sizning `Talaba` klassingizning obyekti — xotirada shu ikkita maydondan boshlanadigan katta C tuzilmasi sifatida saqlanadi. `int` uchun bu tuzilma qo'shimcha ravishda sonning o'zini ham saqlaydi, `list` uchun — ichidagi elementlarga ko'rsatkichlar massivini, va hokazo. Lekin ular barchasi **bitta umumiy "boshlanish"** — `PyObject` qismiga ega, va aynan shu tufayli Python funksiyalari (masalan `print()`) har qanday turdagi qiymatni bir xilda qabul qila oladi: ular faqat `PyObject*` (PyObject'ga ko'rsatkich) bilan ishlaydi.

```python
import sys

x = 5
print(type(x))              # <class 'int'> — ob_type maydoni shuni ko'rsatadi
print(sys.getrefcount(x))   # necha joydan x ga havola bor (bu funksiyaning o'zi ham vaqtincha +1 qiladi)
```

### `PyTypeObject` — "bu ob'ekt nima qila oladi"

Har bir ob'ektning `ob_type` maydoni — `PyTypeObject`ga ko'rsatkich, ya'ni "bu obyekt qaysi turga tegishli va shu tur nima qila oladi" degan katta jadval. `PyTypeObject` ichida, boshqa ko'p narsa qatori, quyidagilar bor:

- `tp_name` — turning nomi (`"int"`, `"list"`, ...)
- `tp_new`, `tp_init` — yangi obyekt qanday yaratiladi
- `tp_dealloc` — obyekt yo'q qilinganda nima qilish kerak
- `tp_hash`, `tp_richcompare` — `hash()` va `==`/`<` kabi solishtirishlar qanday ishlaydi
- `tp_as_number`, `tp_as_sequence`, `tp_as_mapping` — `+`, `[]`, `len()` kabi operatorlar qanday ishlaydi

Bu — 9-bobda chuqur ko'rib chiqiladigan **data model**ning C darajasidagi poydevori: Python'da `obj + obj2` yozganingizda, interpretator aslida `type(obj).tp_as_number->nb_add`ni chaqiradi. Ya'ni Python'ning butun "magic metodlar" tizimi (`__add__`, `__len__`, `__getitem__`...) — bu shunchaki `PyTypeObject` jadvalidagi C funksiya ko'rsatkichlarining Python darajasidagi "yuzi".

```python
print(type(5).__name__)          # int — tp_name
print(hasattr(int, '__add__'))    # True — tp_as_number->nb_add mavjud
print((5).__add__(3))             # 8 — aynan shu C funksiyani chaqiryapmiz, qo'lda
```

### Reference counting — Python xotirani qanday tozalaydi

CPython'ning asosiy xotira boshqarish strategiyasi — **reference counting** (havolalar sonini sanash). Har bir ob'ektning `ob_refcnt` maydoni — "hozir nechta joydan (o'zgaruvchi, ro'yxat elementi, funksiya argumenti...) bu obyektga havola qilinyapti" degan sonni saqlaydi.

- Yangi havola yaratilganda (`y = x`, ro'yxatga qo'shilganda, funksiyaga argument sifatida uzatilganda) — `ob_refcnt` **oshiriladi** (`Py_INCREF`).
- Havola yo'qolganda (o'zgaruvchi boshqa qiymatga qayta tayinlanganda, funksiya tugaganda lokal o'zgaruvchi yo'qolganda, `del` qilinganda) — `ob_refcnt` **kamaytiriladi** (`Py_DECREF`).
- `ob_refcnt` **nolga tushgan zahoti** — hech kim endi bu obyektga muhtoj emas, demak CPython uni **darhol**, hech qanday kutishsiz, xotiradan o'chiradi (`tp_dealloc` chaqiriladi).

Bu — Java yoki Go'dagi "tracing garbage collector"dan tubdan farq qiladi: u yerda GC vaqti-vaqti bilan, alohida jarayon sifatida ishlaydi va qachon yig'ishtirish bo'lishini oldindan bilib bo'lmaydi. CPython'da esa (oddiy holatlarda) obyekt **darhol**, refcount nolga tushgan zahoti o'chadi — bu **deterministik** xotira boshqaruvi deb ataladi.

```python
import sys

a = [1, 2, 3]
print(sys.getrefcount(a))   # 2 (a o'zi + getrefcount funksiyasining vaqtinchalik argumenti)

b = a                        # yangi havola — Py_INCREF chaqiriladi
print(sys.getrefcount(a))   # 3

del b                        # havola yo'qoladi — Py_DECREF chaqiriladi
print(sys.getrefcount(a))   # 2 ga qaytdi

del a                        # oxirgi havola ham yo'qoladi -> refcnt = 0 -> obyekt DARHOL o'chiriladi
```

**Muhim eslatma:** `sys.getrefcount(x)` doim kutilganidan **1 ta ko'p** ko'rsatadi, chunki funksiyaning o'ziga argument sifatida uzatishning o'zi vaqtinchalik yana bitta havola yaratadi.

### Nega reference counting yetarli emas — sikllar muammosi

Reference counting ajoyib ishlaydi, lekin bitta jiddiy zaif tomoni bor: **o'zaro (sikllik) havolalar**. Agar ikki obyekt bir-biriga havola qilsa, ularning refcounti hech qachon 0'ga tushmaydi — hatto tashqi dunyoda ularga hech kim murojaat qilmasa ham:

```python
class Tugun:
    def __init__(self, nom):
        self.nom = nom
        self.bogliq = None

a = Tugun("A")
b = Tugun("B")
a.bogliq = b     # a -> b
b.bogliq = a     # b -> a  (sikl hosil bo'ldi!)

del a
del b
# Endi a va b o'zgaruvchilari yo'q, lekin ikki Tugun obyekti
# hali ham BIR-BIRIGA havola qilib turibdi -> refcnt hech qachon 0 bo'lmaydi!
# Faqat reference counting bilan bu ikkovi XOTIRADA ABADIY QOLIB KETARDI.
```

Aynan shu muammoni hal qilish uchun CPython'da **ikkinchi**, qo'shimcha mexanizm bor — **siklik garbage collector** (`gc` moduli), u aynan shunday "orfan sikllar"ni topib, tozalaydi. Buni keyingi darsda (7.2) batafsil ko'ramiz.

### `id()` va `is` — obyektning "manzili"

`id()` funksiyasi — CPython'da obyektning xotiradagi **manzilini** (pointer qiymatini) butun son sifatida qaytaradi. `is` operatori esa "ikkala o'zgaruvchi **aynan bitta xuddi shu obyektga** ishora qilyaptimi" (ya'ni `id()`lari tengmi) degan savolga javob beradi — bu `==` (qiymatlar tengmi)dan **butunlay boshqa** narsa:

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)   # True  — qiymatlari bir xil
print(a is b)   # False — lekin bular XOTIRADA IKKI XIL obyekt
print(a is c)   # True  — c aynan a bilan bitta xuddi shu obyektga ishora qiladi
print(id(a), id(b), id(c))   # a va c bir xil manzil, b boshqa manzil
```

Bu farqni tushunmaslik — Python'dagi eng ko'p uchraydigan tushunmovchiliklardan biri, va u 7.4-darsda ko'radigan **interning** hodisasi bilan yanada chalkashadi (ba'zan kichik sonlar yoki qisqa satrlar uchun `is` ham `True` chiqishi mumkin — bu Python'ning "kafolati" emas, balki ichki optimallashtirish natijasi).

## Amaliy misol

Reference counting va sikllar muammosini o'z ko'zingiz bilan kuzatish:

```python
# refcount_demo.py
import sys
import gc


class Kuzatuvchi:
    """Obyekt yaratilganda va o'chirilganda xabar beradi."""

    def __init__(self, nom):
        self.nom = nom
        print(f"[YARATILDI] {self.nom}")

    def __del__(self):
        # __del__ — obyekt DARHAQIQAT xotiradan o'chirilayotganda chaqiriladigan magic metod
        print(f"[O'CHIRILDI] {self.nom}")


print("--- 1. Oddiy holat: refcount 0 bo'lishi bilan darhol o'chadi ---")
obj = Kuzatuvchi("Yolg'iz")
print(f"Refcount: {sys.getrefcount(obj) - 1}")   # -1: getrefcount'ning o'z hissasini olib tashlaymiz
del obj                                            # darhol "[O'CHIRILDI] Yolg'iz" chiqadi

print("\n--- 2. Sikllik havola: refcounting YETARLI EMAS ---")
a = Kuzatuvchi("A")
b = Kuzatuvchi("B")
a.juft = b
b.juft = a
del a
del b
print("a va b o'chirildi deb aytdik, lekin hali '[O'CHIRILDI]' chiqmadi!")
print("Chunki A va B bir-biriga hali ham havola qilib turibdi (refcount > 0).")

print("\n--- 3. Siklik GC ularni topib, majburan tozalaydi ---")
gc.collect()   # bu chaqiruvdan keyin "[O'CHIRILDI] A" va "[O'CHIRILDI] B" chiqadi
print("gc.collect() sikllarni topib, ularni majburiy tozaladi.")
```

Bu dasturni ishga tushirsangiz, aniq ko'rasiz: oddiy obyekt refcounti 0'ga tushgan zahoti **darhol** o'chadi, lekin sikldagi ikkita obyekt faqat `gc.collect()` chaqirilgandan keyingina o'chadi — chunki ularning refcounti oddiy `del` bilan hech qachon 0'ga tushmaydi.

## Keng tarqalgan xatolar

**Xato 1:** `is` ni `==` o'rniga qiymatlarni solishtirish uchun ishlatish.
❌
```python
if ism is "Ali":     # satrlarni is bilan solishtirish — noto'g'ri va CPython versiyasiga bog'liq xatti-harakat
    ...
```
Bu ba'zan ishlaydi (chunki CPython qisqa, o'zgarmas satrlarni "intern" qiladi — 7.4-darsda ko'ramiz), lekin bu **kafolatlangan emas** va boshqa Python implementatsiyasida (PyPy) yoki uzunroq satrlarda ishlamasligi mumkin.
✅ To'g'ri: qiymatlarni har doim `==` bilan solishtiring, `is` ni faqat `None`, `True`, `False` bilan yoki "aynan shu bitta obyektmi" degan maxsus holatlarda ishlating: `if ism == "Ali":`, `if natija is None:`.

**Xato 2:** `sys.getrefcount()` natijasidan "-1" qilishni unutish.
❌
```python
print(sys.getrefcount(mening_royxatim))   # bu doim kutilganidan 1 ta ko'p chiqadi
```
✅ To'g'ri: `sys.getrefcount(x) - 1` — chunki funksiyaning o'ziga `x`ni argument sifatida uzatishning o'zi vaqtinchalik qo'shimcha havola yaratadi.

**Xato 3:** `__del__` metodiga "obyekt qachon o'chirilishini men to'liq nazorat qilaman" deb ishonib, unda muhim resurslarni (fayl, tarmoq ulanishi) yopishga tayanish.
❌
```python
class FaylBoshqaruvchi:
    def __del__(self):
        self.fayl.close()   # sikl bo'lsa, bu KECHIKISHI yoki HECH QACHON chaqirilmasligi mumkin!
```
✅ To'g'ri: resurslarni yopish uchun `__del__`ga tayanmang — buning o'rniga `with` operatori va context manager (5.2-dars) ishlating, chunki `__del__`ning **qachon** (yoki hattoki umuman) chaqirilishi kafolatlanmagan (ayniqsa sikllar bo'lsa).

## Mashq/topshiriq

**(Oson)** `sys.getrefcount()` yordamida quyidagini tekshiring: `a = [1, 2]` yarating, so'ng `b = a` va `c = a` qiling. Har bir qadamdan keyin (`-1` tuzatish bilan) refcount qanday o'zgarishini chop eting.

**(O'rtacha)** Ikki klass (`Ota` va `Bola`) yarating, ularda `__del__` metodini qo'shing (o'chirilganda xabar chiqarsin). `Ota` obyektiga `Bola` obyektini, `Bola` obyektiga esa orqaga `Ota`ga havola bering (sikl hosil qiling). `del` bilan ikkalasini ham o'chirib ko'ring va `__del__` darhol chaqirilmasligini kuzating; keyin `gc.collect()` chaqirib, farqni ko'ring.

**(Qiyin)** `id()` va `is` yordamida quyidagi eksperimentni o'tkazing: turli xil kichik butun sonlar (`-5` dan `256` gacha) va katta sonlar (masalan `1000` va `10000`) uchun ikkita alohida o'zgaruvchi yaratib, `is` natijasini solishtiring. Nima uchun kichik sonlar uchun natija boshqacha chiqishi mumkinligi haqida faraz yozing (to'liq javobni 7.4-darsda topasiz).

## Qisqacha xulosa

CPython'da mutlaqo hamma qiymat — `PyObject` deb ataluvchi, har biri o'z turi (`ob_type` → `PyTypeObject`) va havolalar sonini (`ob_refcnt`) o'zida saqlovchi C tuzilmasi sifatida yashaydi; obyektga yangi havola paydo bo'lganda refcount oshadi, havola yo'qolganda kamayadi, va refcount aynan 0'ga tushgan zahoti obyekt **darhol** xotiradan o'chiriladi — bu deterministik, "tracing GC"siz xotira boshqaruvining asosi. Lekin bu mexanizm **o'zaro (sikllik) havolalarni** yolg'iz o'zi hal qila olmaydi, shuning uchun CPython'da ikkinchi, qo'shimcha mexanizm — siklik garbage collector — mavjud, u keyingi darsning mavzusi.
