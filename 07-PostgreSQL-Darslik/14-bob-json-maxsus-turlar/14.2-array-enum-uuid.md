# 14.2. `ARRAY`, `ENUM` va `UUID` — boshqa maxsus ma'lumot turlari

## Bu darsda nimalarni o'rganasiz

- PostgreSQL massiv (`ARRAY`) turi bilan ishlashni — yaratish, indeksga murojaat, qidirish — o'rganasiz
- `ENUM` turi bilan "ruxsat etilgan qiymatlar ro'yxati"ni `CHECK` cheklovisiz qanday ta'minlashni bilasiz
- `ENUM` qiymatlarining **ta'rif tartibi bo'yicha** saralanishini tushunasiz
- `UUID` turi va uni avtomatik generatsiya qilishni (`gen_random_uuid()`) o'rganasiz
- Har bir tur qachon mos, qachon mos emasligini baholay olasiz

## Nazariy qism

### `ARRAY` — bitta ustunda bir nechta qiymat

PostgreSQL — ko'pchilik boshqa relyatsion bazalardan farqli o'laroq, **massiv** turini o'rnatilgan holda qo'llab-quvvatlaydi: bitta ustun, bitta qatorda, **bir nechta** qiymatni saqlashi mumkin.

```sql
CREATE TABLE mahsulot_teglari (
    id SERIAL PRIMARY KEY,
    nomi TEXT,
    teglar TEXT[]
);

INSERT INTO mahsulot_teglari (nomi, teglar) VALUES
('Noutbuk', ARRAY['elektronika', 'ish', 'yangi']),
('Kitob', ARRAY['ta''lim', 'kitob']);

SELECT nomi, teglar FROM mahsulot_teglari;
```

```
   nomi   |          teglar          
----------+---------------------------
 Noutbuk | {elektronika,ish,yangi}
 Kitob   | {ta'lim,kitob}
```

`TEXT[]` — "matn massivi" turi (`INTEGER[]`, `NUMERIC[]` kabi istalgan asosiy turdan massiv yasash mumkin). `ARRAY[...]` — massiv literalini yozish sintaksisi; natijada massiv `{...}` shaklida ko'rsatiladi (JSON massividan farqli, kvadrat qavs emas, jingalak qavs bilan).

### Massiv elementiga murojaat va uzunlik

```sql
SELECT nomi, teglar[1] AS birinchi_teg FROM mahsulot_teglari;
```

```
   nomi   | birinchi_teg 
----------+--------------
 Noutbuk | elektronika
 Kitob   | ta'lim
```

> **Muhim farq JSON massividan:** PostgreSQL massivlarida indeksatsiya **`1`dan** boshlanadi (`teglar[1]` — birinchi element), 14.1-darsdagi JSON massivlaridan farqli, ular `0`dan boshlanadi (`xususiyatlar -> 'portlar' -> 0`). Bu — ikkita turli tizim, ikkita turli konventsiya bo'lgani uchun, ularni chalkashtirmaslik muhim.

Elementlar sonini bilish uchun:

```sql
SELECT nomi, array_length(teglar, 1) AS teglar_soni FROM mahsulot_teglari;
```

```
   nomi   | teglar_soni 
----------+-------------
 Noutbuk |           3
 Kitob   |           2
```

(`array_length(massiv, o'lcham_raqami)`ning ikkinchi argumenti — ko'p o'lchamli massivlar uchun; oddiy, bir o'lchamli massivda har doim `1` yoziladi.)

### Massiv ichidan qidirish — `ANY()` va `@>`

```sql
SELECT nomi FROM mahsulot_teglari WHERE 'ish' = ANY(teglar);
```

```
   nomi   
----------
 Noutbuk
```

`qiymat = ANY(massiv)` — "berilgan qiymat massiv ichida bormi" degan eng tabiiy tekshiruv (bu, kontseptual jihatdan, 2.1-darsdagi `IN`ga o'xshaydi, faqat massiv ustuni bilan ishlaydi).

Muqobil, JSON'dagi `@>`ga o'xshash yondashuv:

```sql
SELECT nomi FROM mahsulot_teglari WHERE teglar @> ARRAY['elektronika'];
```

```
   nomi   
----------
 Noutbuk
```

`@>` bu yerda ham "containment" ma'nosini beradi — "chap massiv, o'ng massivning barcha elementlarini o'z ichiga oladimi" (bu, agar bir nechta teg mavjudligini bir vaqtda tekshirish kerak bo'lsa, foydaliroq: `teglar @> ARRAY['elektronika', 'yangi']`).

### `ENUM` — ruxsat etilgan qiymatlar ro'yxati

8.2-darsda `CHECK (holati IN ('yangi', 'jarayonda', ...))` kabi cheklov bilan "ruxsat etilgan qiymatlar ro'yxati"ni ta'minlash mumkinligini ko'rgan edik. `ENUM` — bu vazifaning **maxsus, ma'lumot turi darajasidagi** yechimi:

```sql
CREATE TYPE buyurtma_holati_enum AS ENUM ('yangi', 'jarayonda', 'yetkazildi', 'bekor_qilindi');

CREATE TABLE test_enum_demo (
    id SERIAL PRIMARY KEY,
    holati buyurtma_holati_enum NOT NULL DEFAULT 'yangi'
);

INSERT INTO test_enum_demo (holati) VALUES ('jarayonda'), (DEFAULT);
SELECT * FROM test_enum_demo;
```

```
 id |  holati   
----+------------
  1 | jarayonda
  2 | yangi
```

Avval `CREATE TYPE ... AS ENUM (...)` bilan **yangi tur** e'lon qilinadi (bu — bazaning o'ziga, bitta joyga, "mumkin bo'lgan qiymatlar ro'yxati"ni yozib qo'yish), so'ng bu tur oddiy `INTEGER`/`TEXT` kabi, ustun turi sifatida ishlatiladi. Ro'yxatdan tashqari qiymat kiritishga urinsak:

```sql
INSERT INTO test_enum_demo (holati) VALUES ('notogri_holat');
```

```
ERROR:  invalid input value for enum buyurtma_holati_enum: "notogri_holat"
```

Bu xato — `CHECK (holati IN (...))` bergan xatoga o'xshash, lekin `ENUM`ning `CHECK`dan ustunligi bor: **bir nechta jadval** shu turdan foydalanishi mumkin, va ro'yxatni o'zgartirish uchun har bir jadvaldagi cheklovni emas, faqat **bitta joyda**, `ALTER TYPE ... ADD VALUE` bilan yangilash kifoya.

### `ENUM`ning kutilmagan xususiyati — ta'rif tartibi bo'yicha saralash

`ENUM` haqida bilish zarur bo'lgan eng muhim, ko'pincha kutilmagan xususiyat — uning **saralash tartibi**:

```sql
INSERT INTO test_enum_demo (holati) VALUES ('yetkazildi'), ('bekor_qilindi');
SELECT * FROM test_enum_demo ORDER BY holati;
```

```
 id |    holati     
----+----------------
  2 | yangi
  1 | jarayonda
  3 | yetkazildi
  4 | bekor_qilindi
```

Diqqat qiling — natija **alifbo tartibida emas** (`bekor_qilindi` alifboda birinchi bo'lardi)! `ENUM` qiymatlari, `CREATE TYPE`da **ular yozilgan tartib** bo'yicha saralanadi: `'yangi'` → `'jarayonda'` → `'yetkazildi'` → `'bekor_qilindi'`. Bu — aslida **foyda**, kamchilik emas: buyurtma holatlari kabi "tabiiy ketma-ketlikka" ega bo'lgan qiymatlar uchun, `ENUM`ning o'zi sizga `ORDER BY holati` orqali **mantiqiy jarayon tartibida** saralashni beradi — buni oddiy `TEXT` ustuni bilan qo'shimcha `CASE WHEN` yozmasdan qo'lga kiritib bo'lmas edi.

### `UUID` — universal noyob identifikator

8-bobda `PRIMARY KEY` uchun asosan `SERIAL`/avtomatik o'suvchi sonlardan foydalandik. Ba'zi holatlarda, ayniqsa **taqsimlangan tizimlar** (bir nechta server bir vaqtda yozuv yaratayotganda, ID to'qnashuvi bo'lmasligi kerak bo'lganda) yoki **ID'ni tashqi dunyoga oshkor qilish xavfsiz bo'lmagan** holatlarda (`id=1`, `id=2`... ketma-ketligi orqali "nechta foydalanuvchi bor" kabi ma'lumotni oson taxmin qilish mumkin), o'rniga `UUID` (Universally Unique Identifier) ishlatiladi:

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE mijozlar_uuid (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    nomi TEXT
);

INSERT INTO mijozlar_uuid (nomi) VALUES ('Birinchi'), ('Ikkinchi');
SELECT * FROM mijozlar_uuid;
```

```
                  id                  |   nomi   
---------------------------------------+----------
 43dd6824-7862-4d6a-a7a3-20cc6ca9f3bb | Birinchi
 b35eb31d-7654-4870-8d50-adabbe64fb47 | Ikkinchi
```

`gen_random_uuid()` — `pgcrypto` kengaytmasi (extension) orqali kelgan funksiya, 128-bitli, deyarli hech qachon takrorlanmaydigan tasodifiy identifikator generatsiya qiladi (`CREATE EXTENSION`lar haqida 15-bobda ko'proq o'rganamiz). `SERIAL`ga solishtirganda:

| | `SERIAL` (avtomatik o'suvchi son) | `UUID` |
|---|---|---|
| **Ko'rinishi** | `1, 2, 3, ...` | `43dd6824-7862-4d6a-...` |
| **Taxmin qilish oson** | Ha (keyingi ID nima bo'lishini bilish oson) | Yo'q (amalda taxmin qilib bo'lmaydi) |
| **Bir nechta serverda mustaqil yaratish** | Muammoli (to'qnashish xavfi) | Xavfsiz (deyarli hech qachon to'qnashmaydi) |
| **Hajmi** | 4-8 bayt | 16 bayt |
| **Indeks samaradorligi** | Yuqoriroq (ketma-ket qiymatlar indeksda "yaxshi joylashadi") | Bir oz pastroq (tasodifiy qiymatlar indeksni "tarqoq" qiladi) |

Amaliy qoida: agar ID **faqat ichki**, bitta baza ichida ishlatilsa va ketma-ketlik muammo tug'dirmasa — `SERIAL`/`GENERATED ALWAYS AS IDENTITY` (6.1-dars) yetarli va samaraliroq. Agar ID **tashqariga**, masalan URL'ga yoki API javobiga chiqariladigan bo'lsa, yoki tizim bir nechta mustaqil qismdan (mikroservislar) iborat bo'lsa — `UUID` afzalroq.

## Amaliy misol

**Vazifa:** `mahsulotlar` jadvaliga o'xshash, `ENUM` bilan mahsulot toifasini, `ARRAY` bilan esa uning mavjud ranglarini saqlaydigan jadval loyihalang.

```sql
CREATE TYPE mahsulot_toifa_enum AS ENUM ('elektronika', 'mebel', 'kiyim');

CREATE TABLE mahsulot_katalogi (
    id SERIAL PRIMARY KEY,
    nomi TEXT NOT NULL,
    toifa mahsulot_toifa_enum NOT NULL,
    mavjud_ranglar TEXT[]
);

INSERT INTO mahsulot_katalogi (nomi, toifa, mavjud_ranglar) VALUES
('Noutbuk', 'elektronika', ARRAY['kulrang', 'qora']),
('Stul', 'mebel', ARRAY['jigarrang']);

SELECT nomi, toifa, mavjud_ranglar FROM mahsulot_katalogi
WHERE 'qora' = ANY(mavjud_ranglar);
```

## Keng tarqalgan xatolar

**Xato 1:** JSON massivi indeksi (`0`dan boshlanadi) bilan PostgreSQL `ARRAY` indeksini (`1`dan boshlanadi) chalkashtirish.
❌ `teglar[0]` — PostgreSQL massivida bu **hech qanday xato bermaydi**, shunchaki `NULL` qaytaradi (bu ayniqsa chalkash, chunki jim xato).
✅ PostgreSQL massivlarida har doim `1`dan boshlang: `teglar[1]` — birinchi element.

**Xato 2:** `ENUM` ro'yxatini keyinchalik tez-tez o'zgartirishga muhtoj bo'ladigan holatlar uchun ishlatish.
❌ `ALTER TYPE ... ADD VALUE` mavjud bo'lsa-da, `ENUM`dan qiymat **o'chirish** yoki tartibini o'zgartirish ancha murakkab (butun turni qayta yaratishni talab qiladi).
✅ Agar ruxsat etilgan qiymatlar ro'yxati tez-tez o'zgarishi kutilsa, alohida "lookup" jadval (masalan, `toifalar` jadvali, `FOREIGN KEY` bilan bog'langan — 8.3-dars) ko'proq moslashuvchan.

**Xato 3:** Har bir jadvalda `UUID`ni "default va xavfsizroq" deb, hamma joyda ishlatish.
❌ `UUID` katta hajmdagi jadvallarda indeks samaradorligini pasaytirishi mumkin, va o'qish uchun ancha noqulay (`SELECT * FROM buyurtmalar WHERE id = 5` ga solishtiring `WHERE id = '43dd6824-...'`).
✅ `UUID`ni faqat haqiqiy zarurat bo'lganda (taqsimlangan tizim, tashqi ko'rinuvchanlik) tanlang; aks holda `SERIAL`/`IDENTITY` yetarli.

## Mashq/topshiriq

**(Oson)** `test_mavsum_enum` nomli `ENUM` tur yarating (`'bahor', 'yoz', 'kuz', 'qish'`), va shu turdagi ustunga ega jadval yaratib, bir nechta qator kiriting, so'ng `ORDER BY` bilan saralab, tartib alifboda emasligini tasdiqlang.

**(O'rtacha)** `xodimlar`ga o'xshash test jadvali yarating, unda `koniklamalar TEXT[]` (ko'nikmalar ro'yxati) ustuni bo'lsin. Kamida uchta xodim qo'shing, turli ko'nikmalar bilan, so'ng `'SQL'` ko'nikmasiga ega bo'lgan xodimlarni `ANY()` bilan toping.

**(Qiyin)** `pgcrypto` kengaytmasidan foydalanib, `UUID` asosiy kalitli jadval yarating, unga bir nechta qator qo'shing, so'ng ikkita qatorning `UUID`lari haqiqatan **hech qachon** takrorlanmasligini tushuntirib bering (nazariy javob — nechta mumkin bo'lgan UUID borligini hisoblang yoki tushuntiring).

## Qisqacha xulosa

`ARRAY` — bitta ustunda bir nechta qiymatni saqlash imkonini beradi (`1`dan indekslanadi, JSON massividan farqli), `ENUM` — ruxsat etilgan qiymatlar ro'yxatini butun bazada bir joyda ta'minlaydi va **ta'rif tartibi bo'yicha** saralanadi (foydali xususiyat, "tabiiy ketma-ketlikka" ega qiymatlar uchun), `UUID` esa — taqsimlangan tizimlar yoki tashqariga oshkor qilinadigan identifikatorlar uchun `SERIAL`ning muqobili. Bu — 14-bobni yakunlaydi: `JSONB`, `ARRAY`, `ENUM` va `UUID` bilan tuzilmasiz va maxsus ma'lumotlarni saqlashni o'rgandingiz. Keyingi, 15-bobda **xavfsizlik va zaxira nusxa**ni — foydalanuvchilar/rollar, `GRANT`/`REVOKE`, va `pg_dump`/tiklashni — o'rganamiz.
