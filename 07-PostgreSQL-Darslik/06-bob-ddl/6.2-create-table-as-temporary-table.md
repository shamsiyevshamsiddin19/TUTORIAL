# 6.2. `CREATE TABLE AS` va `TEMPORARY TABLE`

## Bu darsda nimalarni o'rganasiz

- `CREATE TABLE AS` bilan mavjud so'rov natijasidan yangi, doimiy jadval yaratishni bilasiz
- Bu usulda yaratilgan jadval asl jadval(lar) bilan **hech qanday jonli bog'lanishga ega emasligini** (statik nusxa ekanini) tushunasiz
- `TEMPORARY TABLE` (vaqtinchalik jadval)ning nima ekanini, va u faqat joriy sessiya davomida yashashini bilasiz
- Ikkalasini qachon (hisobot, oraliq hisob-kitob, murakkab so'rovni bosqichlarga bo'lish) ishlatish maqsadga muvofiqligini tushunasiz

## Nazariy qism

### `CREATE TABLE AS` — so'rov natijasidan jadval yaratish

`CREATE TABLE AS SELECT` (ko'pincha "CTAS" deb qisqartiriladi) — istalgan `SELECT` so'rovining natijasini **yangi, alohida jadvalga** saqlab qo'yadigan buyruq:

```sql
CREATE TABLE yangi_jadval AS
SELECT ustunlar
FROM mavjud_jadval(lar)
WHERE shart;
```

Masalan, "Elektronika" kategoriyasidagi mahsulotlarning "hisobot nusxasi"ni alohida jadval sifatida saqlaymiz:

```sql
CREATE TABLE elektronika_hisoboti AS
SELECT nomi, narxi, ombordagi_soni
FROM mahsulotlar
WHERE kategoriya = 'Elektronika';
```

Bu buyruq bajarilgach, `elektronika_hisoboti` — odatiy `CREATE TABLE` bilan yaratilgan jadvaldan **hech qanday farqi yo'q** to'liq mustaqil jadval: unga `INSERT`, `UPDATE`, `DELETE` qilish, indeks qo'shish, hatto `DROP TABLE` bilan o'chirish mumkin — xuddi oddiy jadval kabi.

### Muhim tushuncha: statik nusxa, jonli bog'lanish EMAS

Bu — `CREATE TABLE AS`ning eng muhim xususiyati, va uni 5-bobda (Subquery/CTE'lar) ko'ramiz VIEW bilan solishtirganda yanada aniq bo'ladi: **`CREATE TABLE AS` natijasi — so'rov bajarilgan paytdagi ma'lumotlarning "suratga olingan" (snapshot) statik nusxasi.** Agar asl `mahsulotlar` jadvalida keyinchalik narx o'zgarsa, yangi mahsulot qo'shilsa yoki o'chirilsa — `elektronika_hisoboti` jadvali bundan **umuman xabardor bo'lmaydi**, u o'zgarishsiz qoladi, chunki ular orasida hech qanday "jonli" bog'lanish yo'q. Agar sizga har doim **eng yangi** ma'lumotni aks ettiradigan "virtual jadval" kerak bo'lsa, `CREATE TABLE AS` emas, balki `VIEW` (11-bobda chuqur) kerak bo'ladi — bu ikkovi orasidagi farqni tushunish juda muhim.

**Amaliy qo'llanilishi:** `CREATE TABLE AS` odatda quyidagi holatlarda foydali: (1) og'ir, murakkab hisob-kitobni **bir marta** bajarib, natijasini keyingi tezkor so'rovlar uchun "keshlash" (masalan, oylik hisobot uchun); (2) ma'lum bir vaqtdagi ma'lumotlarning tarixiy "surati"ni saqlash (masalan, "2024-yil yanvar oyi oxiridagi inventar holati"); (3) murakkab, ko'p bosqichli tahlilni kichikroq, boshqarish osonroq oraliq jadvallarga bo'lish.

### `WITH DATA` / `WITH NO DATA`

Ba'zan sizga faqat jadvalning **strukturasini** (ustunlar va turlarini) nusxalash kerak, ma'lumotning o'zi kerak emas — masalan, bo'sh "shablon" jadval yaratish uchun:

```sql
CREATE TABLE mahsulotlar_shablon AS
SELECT * FROM mahsulotlar
WITH NO DATA;
```

Bu — `mahsulotlar`ning barcha ustunlari va turlariga ega, lekin **bo'sh** (0 qatorli) jadval yaratadi. (`WITH DATA` — standart xatti-harakat, uni alohida yozish shart emas.)

### `TEMPORARY TABLE` (`TEMP TABLE`) — sessiya davomida yashaydigan jadval

Oddiy `CREATE TABLE` doimiy jadval yaratadi — u ma'lumotlar bazasida siz uni o'zingiz `DROP TABLE` bilan o'chirmaguningizcha, hattoki server qayta ishga tushirilsa ham, saqlanib qoladi. `TEMPORARY TABLE` (yoki qisqacha `TEMP TABLE`) esa butunlay boshqacha "hayot davri"ga ega:

```sql
CREATE TEMPORARY TABLE vaqtinchalik_hisob AS
SELECT kategoriya, sum(narxi * ombordagi_soni) AS jami_qiymat
FROM mahsulotlar
GROUP BY kategoriya;
```

**Vaqtinchalik jadvalning asosiy xususiyatlari:**

- U faqat **joriy sessiya** (ya'ni, siz `psql`ni yopib, qayta ulanguningizcha bo'lgan davr) davomida mavjud bo'ladi — sessiya tugagach, jadval **avtomatik ravishda o'chib ketadi**, hech qanday `DROP TABLE`siz.
- U **faqat uni yaratgan sessiyaga ko'rinadi** — boshqa foydalanuvchilar yoki boshqa parallel ulanishlar uni umuman ko'ra olmaydi, hattoki bir xil nom bilan boshqa vaqtinchalik jadval yaratsalar ham (ular bir-biriga aralashmaydi).
- Ichki ravishda alohida, maxsus sxemada (`pg_temp_N`) saqlanadi, lekin odatiy nom bilan (`sxema` prefiksisiz) murojaat qilish mumkin.

**Amaliy qo'llanilishi:** vaqtinchalik jadvallar ayniqsa murakkab hisobotlarni bir nechta bosqichga bo'lish uchun juda foydali — masalan, katta va sekin ishlaydigan oraliq so'rov natijasini avval vaqtinchalik jadvalga saqlab, so'ng unga bir nechta boshqa (tezroq) so'rovlarni qo'llash mumkin, bu ba'zan katta murakkab so'rovni bitta gigant so'rov sifatida yozishdan ko'ra tezroq va tushunarliroq bo'ladi.

```sql
-- 1-qadam: og'ir hisob-kitobni bir marta bajarib, vaqtinchalik jadvalga saqlash
CREATE TEMPORARY TABLE mijoz_xarid_statistikasi AS
SELECT mj.id, mj.ism, count(bu.id) AS buyurtmalar_soni, 
       coalesce(sum(be.soni * be.narx), 0) AS jami_xarid
FROM mijozlar mj
LEFT JOIN buyurtmalar bu ON mj.id = bu.mijoz_id
LEFT JOIN buyurtma_elementlari be ON bu.id = be.buyurtma_id
GROUP BY mj.id, mj.ism;

-- 2-qadam: endi bu (kichik, tez) jadval ustida istalgancha tezkor so'rov yuritish mumkin
SELECT * FROM mijoz_xarid_statistikasi WHERE jami_xarid > 1000000 ORDER BY jami_xarid DESC;
SELECT avg(jami_xarid) FROM mijoz_xarid_statistikasi;
```

### `ON COMMIT` — tranzaksiya bilan bog'liq xatti-harakat

Vaqtinchalik jadval uchun, uni faqat **joriy tranzaksiya davomida** yashashini ham sozlash mumkin (13-bobda tranzaksiyalarni chuqur o'rganganimizda bu ancha ma'noliroq bo'ladi):

```sql
CREATE TEMPORARY TABLE vaqtinchalik_hisob (...) ON COMMIT DROP;
```

`ON COMMIT DROP` — tranzaksiya `COMMIT` qilinishi bilan jadval avtomatik o'chib ketadi; `ON COMMIT DELETE ROWS` — jadval strukturasi qoladi, lekin barcha qatorlar o'chiriladi; standart xatti-harakat (`ON COMMIT PRESERVE ROWS`) — hech narsa avtomatik o'chmaydi, jadval butun sessiya davomida saqlanadi.

## Amaliy misol

**Vazifa:** Har bir bo'limning joriy xodimlar soni va jami oylik maosh fondini "2026-yil avgust holatiga" hisobot sifatida alohida doimiy jadvalga saqlang (kelajakda solishtirish uchun).

```sql
CREATE TABLE bolim_hisoboti_2026_08 AS
SELECT b.id, b.nomi, count(x.id) AS xodimlar_soni, coalesce(sum(x.ish_haqi), 0) AS jami_fond
FROM bolimlar b
LEFT JOIN xodimlar x ON b.id = x.bolim_id
GROUP BY b.id, b.nomi;
```

Bu jadval endi doimiy — kelajakda `xodimlar` jadvalidagi maoshlar o'zgarsa ham, `bolim_hisoboti_2026_08` o'sha vaqtdagi "muzlatilgan" holatni saqlab qoladi, va buni keyinchalik yangi hisobot bilan solishtirish mumkin bo'ladi.

## Keng tarqalgan xatolar

**Xato 1:** `CREATE TABLE AS` bilan yaratilgan jadvalning asl ma'lumot bilan avtomatik yangilanib turishini kutish.
❌ `mahsulotlar` jadvalida narx o'zgargandan keyin, `elektronika_hisoboti`da ham avtomatik yangilanish bo'ladi deb o'ylash — bu noto'g'ri.
✅ Agar "har doim yangi" natija kerak bo'lsa, `VIEW` (11-bobda) ishlating; `CREATE TABLE AS` — faqat bir martalik statik surat.

**Xato 2:** Vaqtinchalik jadval nomini boshqa (doimiy) jadval nomi bilan bir xil qilib, keyin qaysi biriga murojaat qilinayotganidan adashish.
✅ PostgreSQL vaqtinchalik jadvalni doimiy jadvaldan **ustunroq** qo'yadi (agar ikkalasi ham bir xil nomda bo'lsa, vaqtinchalik jadval "ustunlik" qiladi) — bu chalkashlikning oldini olish uchun vaqtinchalik jadvallarga aniq, boshqacha (masalan, `tmp_` prefiksli) nom berish tavsiya etiladi.

**Xato 3:** Sessiya tugagach vaqtinchalik jadvaldagi ma'lumot "yo'qolib qolganidan" hayron bo'lish.
✅ Bu — `TEMPORARY TABLE`ning **kutilgan, loyihalangan** xatti-harakati, xato emas; doimiy saqlash kerak bo'lsa, oddiy `CREATE TABLE` ishlating.

## Mashq/topshiriq

**(Oson)** `mahsulotlar` jadvalidan faqat `ombordagi_soni = 0` bo'lgan mahsulotlarni `tugagan_mahsulotlar` nomli yangi doimiy jadvalga `CREATE TABLE AS` bilan saqlang.

**(O'rtacha)** `mijozlar` jadvali strukturasidan (ma'lumotisiz) `mijozlar_arxiv_shablon` nomli bo'sh jadval yarating (`WITH NO DATA` bilan), va `\d mijozlar_arxiv_shablon` orqali uning `mijozlar` bilan bir xil ustunlarga ega, lekin `0` qatorli ekanini tekshiring.

**(Qiyin)** `TEMPORARY TABLE` yordamida, avval har bir mijozning jami xarid summasini vaqtinchalik jadvalga hisoblang, so'ng shu vaqtinchalik jadval asosida "eng ko'p xarid qilgan 3 ta mijoz"ni chiqaring. So'ng, nima uchun bu yondashuv (ikki bosqichli) ba'zan bitta katta, ichma-ich subquery'li so'rovdan (9-bobda ko'ramiz) o'qilishi osonroq bo'lishi mumkinligini tushuntiring.

## Qisqacha xulosa

`CREATE TABLE AS` — istalgan `SELECT` so'rovining natijasini yangi, mustaqil jadvalga aylantiradi — bu statik "surat" bo'lib, asl ma'lumot manbasi bilan hech qanday jonli bog'lanishga ega emas. `TEMPORARY TABLE` esa faqat joriy sessiya (yoki hatto faqat joriy tranzaksiya, `ON COMMIT` orqali) davomida yashaydigan, boshqa sessiyalarga ko'rinmaydigan jadval bo'lib, murakkab hisobotlarni bosqichlarga bo'lish uchun juda qulay vosita. Keyingi darsda mavjud jadval strukturasini o'zgartirish — `ALTER TABLE` (ustun qo'shish, o'chirish, nomini o'zgartirish)ni o'rganamiz.
