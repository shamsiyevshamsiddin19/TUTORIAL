# 7.4. `COPY` — ommaviy import va eksport

## Bu darsda nimalarni o'rganasiz

- `COPY ... TO` bilan jadval (yoki so'rov natijasi)ni CSV faylga eksport qilishni bilasiz
- `COPY ... FROM` bilan CSV fayldan ma'lumotni ommaviy import qilishni bilasiz
- `COPY`ning ko'plab alohida `INSERT`lardan nima uchun sezilarli tezroq ekanini tushunasiz
- Server tomonidagi `COPY` va mijoz tomonidagi `\copy` (psql meta-buyrug'i) orasidagi muhim farqni bilasiz

## Nazariy qism

### Nega `COPY` kerak — ommaviy operatsiyalar uchun maxsus vosita

7.1-darsda ko'p qatorli `INSERT INTO ... VALUES (...), (...), ...`ni ko'rgan edik — bu o'nlab, hattoki yuzlab qator uchun yaxshi ishlaydi. Lekin agar sizga **minglab yoki millionlab** qatorni tashqi manbadan (masalan, boshqa tizimdan eksport qilingan CSV fayldan) tezkor import qilish kerak bo'lsa, `INSERT`lar (hatto ko'p qatorli bo'lsa ham) sekin bo'lib qoladi. PostgreSQL'ning `COPY` buyrug'i aynan shu vazifa uchun maxsus optimallashtirilgan — u ma'lumotni ancha samaraliroq, kam xarajat bilan (masalan, kamroq tranzaksiya log yozuvlari, soddaroq parser) o'qiydi/yozadi.

### `COPY ... TO` — eksport qilish

```sql
COPY (SELECT nomi, narxi, kategoriya FROM mahsulotlar ORDER BY id)
TO '/tmp/mahsulotlar_eksport.csv'
WITH (FORMAT csv, HEADER true);
```

```
COPY 10
```

Bu buyruq istalgan `SELECT` so'rovining (yoki oddiy `COPY jadval TO ...` yozilsa, butun jadvalning) natijasini CSV faylga yozadi. Hosil bo'lgan faylning tarkibi:

```
nomi,narxi,kategoriya
Noutbuk Lenovo IdeaPad,8500000.00,Elektronika
Sichqoncha Logitech,150000.00,Elektronika
Klaviatura mexanik,450000.00,Elektronika
"Monitor Samsung 24""",2200000.00,Elektronika
Ofis stuli,1200000.00,Mebel
Ish stoli,2500000.00,Mebel
Kofe mashinasi,3500000.00,Maishiy texnika
Muzlatgich,6800000.00,Maishiy texnika
Kitob tokchasi,900000.00,Mebel
Bosma printer,1800000.00,Elektronika
```

Diqqat qiling — `"Monitor Samsung 24"""` qatoriga: mahsulot nomida `24"` (dyuym belgisi, qo'sh tirnoq) borligi sababli, CSV formatining standart qoidasiga ko'ra butun qiymat qo'sh tirnoq ichiga olindi, ichidagi haqiqiy `"` belgisi esa ikkilanib (`""`) "escape" qilindi — bu standart CSV formatining o'zi talab qiladigan qoida, PostgreSQL buni avtomatik to'g'ri bajaradi.

### `WITH (...)` — formatlash parametrlari

| Parametr | Ma'nosi |
|---|---|
| `FORMAT csv` | Vergul bilan ajratilgan format (standart — `text`, tabsimon) |
| `HEADER true` | Birinchi qatorga ustun nomlarini yozish/o'qish |
| `DELIMITER ','` | Ajratuvchi belgini o'zgartirish (masalan, `';'` yoki tab) |
| `QUOTE '"'` | Qiymatlarni o'rab turuvchi belgi |
| `NULL 'NULL'` | `NULL` qiymat CSV'da qanday matn bilan ifodalanishini belgilash (standart — bo'sh satr) |

### `COPY ... FROM` — import qilish

```sql
COPY jadval (ustun1, ustun2, ...)
FROM '/yol/fayl.csv'
WITH (FORMAT csv, HEADER true);
```

```sql
CREATE TEMPORARY TABLE mahsulot_import (nomi TEXT, narxi NUMERIC, kategoriya TEXT);

\copy mahsulot_import FROM '/tmp/mahsulotlar_eksport.csv' WITH (FORMAT csv, HEADER true)

SELECT count(*) FROM mahsulot_import;
```

```
COPY 10
 count 
-------
    10
```

### `COPY` vs `\copy` — MUHIM farq

Bu — ko'pincha chalkashtiriladigan, lekin amaliyotda juda muhim texnik farq:

- **`COPY`** (backslashsiz) — bu **SQL buyrug'i**, u **serverning o'zida** bajariladi. Fayl yo'li (`/tmp/mahsulotlar_eksport.csv` kabi) — **server** kompyuteridagi fayl tizimiga ishora qiladi, sizning mahalliy kompyuteringizga emas! Bundan tashqari, xavfsizlik sabablariga ko'ra, oddiy foydalanuvchilar (superuser bo'lmagan rollar) odatda `COPY ... TO/FROM fayl` ishlatishga **ruxsatga ega emas** — faqat superuser yoki maxsus `pg_read_server_files`/`pg_write_server_files` rolига ega foydalanuvchilar buni bajara oladi.
- **`\copy`** (backslash bilan) — bu **`psql`ning o'z meta-buyrug'i** (SQL emas!), u fayl yo'lini **mijoz** (siz `psql`ni ishga tushirgan kompyuter) tomonida talqin qiladi, va serverga ma'lumotni tarmoq orqali oqim sifatida uzatadi. `\copy` odatiy foydalanuvchi huquqlari bilan ham ishlaydi (chunki server nuqtai nazaridan bu oddiy `INSERT`/`SELECT` oqimi kabi ko'rinadi, fayl tizimiga bevosita kirish emas).

**Amaliy qoida:** agar siz `psql` orqali, o'zingizning **mahalliy** kompyuteringizdagi fayl bilan ishlayotgan bo'lsangiz (eng keng tarqalgan holat), deyarli har doim `\copy` ishlating. `COPY` (SQL buyrug'i) faqat serverning o'zida ishlaydigan skriptlar yoki ma'muriy vazifalar uchun mos.

### Nega `COPY` tezroq — qisqacha (17-bobda chuqurroq)

`INSERT`larning har biri (hatto bitta tranzaksiya ichida bo'lsa ham) SQL parserini, so'rov rejalashtiruvchisini va bir qator boshqa umumiy mexanizmlarni alohida-alohida o'tishi mumkin. `COPY` esa ma'lumotni **oqim** (stream) sifatida, minimal umumiy xarajat bilan, to'g'ridan-to'g'ri jadval saqlash formatiga yaqin usulda yozadi — bu, ayniqsa o'nlab minglab va undan ko'p qator uchun, sezilarli tezlik farqini beradi (real amaliyotda ko'pincha 5-10 baravar yoki undan ham ko'proq tezroq).

## Amaliy misol

**Vazifa:** Butun `xodimlar` jadvalini CSV formatida (sarlavha bilan) eksport qiling, so'ng shu faylni o'qib, nechta qator borligini tekshiring.

```sql
\copy (SELECT * FROM xodimlar ORDER BY id) TO '/tmp/xodimlar_eksport.csv' WITH (FORMAT csv, HEADER true)
```

Bu — kompaniyaning HR bo'limi Excel'da ochib ko'rishi mumkin bo'lgan, standart CSV formatidagi hisobot fayli yaratadi.

## Keng tarqalgan xatolar

**Xato 1:** `COPY` (SQL buyrug'i)ni oddiy foydalanuvchi bilan, o'zining mahalliy kompyuteridagi fayl uchun ishlatishga urinish.
❌ `COPY jadval FROM '/Users/men/fayl.csv';` — agar server boshqa kompyuterda (yoki hatto bir xil kompyuterda, lekin boshqa fayl tizimi nuqtai nazarida) ishlasa, bu yo'l topilmaydi yoki ruxsat xatosi beradi.
✅ Mahalliy fayllar uchun `\copy` ishlating (`psql` ichida).

**Xato 2:** CSV faylning birinchi qatorida sarlavha (ustun nomlari) borligini, lekin `HEADER true` parametrini unutish — natijada sarlavha qatorining o'zi ma'lumot sifatida import qilinib, keyin turlar mos kelmasligi sababli xato beradi.
✅ Agar faylda sarlavha bo'lsa, har doim `HEADER true`ni unutmang.

**Xato 3:** Import paytida CSV'dagi ustunlar soni/tartibi jadvaldagi bilan mos kelmasligini oldindan tekshirmaslik.
✅ Import qilishdan oldin, `COPY jadval (aniq_ustunlar) FROM ...` shaklida ustunlarni aniq ko'rsating — bu, `INSERT`dagi kabi, kelajakdagi sxema o'zgarishlariga chidamlilikni oshiradi.

## Mashq/topshiriq

**(Oson)** `mijozlar` jadvalini `\copy` bilan `/tmp/mijozlar.csv` fayliga (sarlavha bilan) eksport qiling.

**(O'rtacha)** Yangi vaqtinchalik jadval (`CREATE TEMPORARY TABLE`) yarating, u `mahsulotlar`ning `nomi` va `narxi` ustunlariga mos kelsin, so'ng 7.4-darsdagi eksport qilingan `mahsulotlar_eksport.csv`dan faqat shu ikkita ustunni import qiling (`COPY jadval (nomi, narxi) FROM ...` — faylda uchinchi `kategoriya` ustuni ham borligini hisobga oling, bu qanday muammo tug'dirishi mumkinligini o'ylab ko'ring).

**(Qiyin)** Nega ko'p minglab qatorli ma'lumotni import qilishda, bitta katta `COPY` (yaxlit tranzaksiya sifatida) o'nlab mingta alohida `INSERT`ga qaraganda nafaqat tezroq, balki **xatolarni boshqarish nuqtai nazaridan ham** boshqacha xulq-atvorga ega ekanini (barcha-yoki-hech narsa printsipi) tushuntirib bering.

## Qisqacha xulosa

`COPY` — ommaviy import/eksport uchun maxsus optimallashtirilgan, `INSERT`larga qaraganda sezilarli tezroq ishlaydigan vosita; CSV va boshqa formatlarni qo'llab-quvvatlaydi. Server tomonidagi `COPY` (SQL buyrug'i, server fayl tizimiga kirish huquqi talab qiladi) va mijoz tomonidagi `\copy` (`psql` meta-buyrug'i, mahalliy fayllar uchun, maxsus huquq talab qilmaydi) orasidagi farqni bilish amaliy ishda juda muhim — aksariyat kundalik holatlarda `\copy` kerak bo'ladi. Bu bilan 07-bob (DML) yakunlanadi — keyingi, 08-bobda esa ma'lumotlar yaxlitligini ta'minlovchi cheklovlarni (`NOT NULL`, `UNIQUE`, `CHECK`, `FOREIGN KEY` va boshqalar) chuqur o'rganamiz.
