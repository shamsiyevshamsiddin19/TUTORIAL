# 11.1. `VIEW` va `MATERIALIZED VIEW`

## Bu darsda nimalarni o'rganasiz

- `CREATE VIEW` bilan "virtual jadval" yaratishni bilasiz
- `VIEW`ning har doim **jonli**, real vaqtdagi ma'lumotni aks ettirishini — va bu 6.2-darsdagi `CREATE TABLE AS`dan qanday farq qilishini — chuqur tushunasiz
- `MATERIALIZED VIEW` — natijani jismonan saqlab qo'yuvchi, lekin qo'lda yangilanishi kerak bo'lgan view turini bilasiz
- `REFRESH MATERIALIZED VIEW` bilan materiallashtirilgan view'ni yangilashni bilasiz

## Nazariy qism

### `VIEW` — "saqlangan so'rov", virtual jadval

**`VIEW`** — bu, mohiyatan, **nomlangan, saqlab qo'yilgan `SELECT` so'rovi**. U jadval kabi ko'rinadi va so'raladi, lekin ichida haqiqiy ma'lumot saqlamaydi — u faqat **so'rovning o'zini** eslab qoladi, va har safar `VIEW`ga murojaat qilinganda, PostgreSQL o'sha so'rovni **qaytadan** bajaradi.

```sql
CREATE VIEW xodim_bolim_royxati AS
SELECT x.id, x.ism, x.familiya, b.nomi AS bolim, x.ish_haqi
FROM xodimlar x
JOIN bolimlar b ON x.bolim_id = b.id;
```

```sql
SELECT * FROM xodim_bolim_royxati ORDER BY id LIMIT 3;
```

```
 id |   ism   | familiya | bolim |  ish_haqi   
----+---------+----------+-------+-------------
  1 | Aziz    | Karimov  | IT    | 25000000.00
  2 | Dilnoza | Yusupova | Sotuv | 15000000.00
  3 | Sardor  | Aliyev   | IT    | 12000000.00
```

Bu — 3.1-darsda ko'rgan `JOIN`ni har safar qo'lda yozish o'rniga, uni bir marta `xodim_bolim_royxati` nomi ostida "eslab qolib", keyin oddiy `SELECT * FROM xodim_bolim_royxati` bilan ishlatish imkonini beradi.

### `VIEW` — har doim **jonli**, real vaqtdagi ma'lumot (6.2-dars bilan hal qiluvchi farq)

Bu — bu darsning eng muhim tushunchasi, va 6.2-darsda `CREATE TABLE AS`ni ko'rib chiqqanda aynan shu farqni keyinroq tushuntirishga va'da bergan edik. Keling, `xodim_bolim_royxati`dagi ma'lumot asl jadval o'zgarganda nima bo'lishini ko'ramiz:

```sql
UPDATE xodimlar SET ish_haqi = 26000000 WHERE ism = 'Aziz';
SELECT * FROM xodim_bolim_royxati WHERE ism = 'Aziz';
```

```
 id | ism  | familiya | bolim |  ish_haqi   
----+------+----------+-------+-------------
  1 | Aziz | Karimov  | IT    | 26000000.00
```

Diqqat qiling — **hech qanday** qo'shimcha amal (masalan, view'ni "yangilash") bajarilmadi, lekin `xodim_bolim_royxati` darhol yangi qiymatni ko'rsatdi! Sabab — 6.2-darsda aytilganidek — `VIEW` hech qanday ma'lumotni o'zida saqlamaydi, u har safar so'ralganda **asl jadval(lar)ga qarab, so'rovni qaytadan bajaradi**. Bu — `CREATE TABLE AS`ning statik "surat"idan **tubdan farq qiladi**: `CREATE TABLE AS` bilan yaratilgan jadval asl ma'lumot o'zgarganda o'zgarishsiz qoladi, `VIEW` esa har doim **eng yangi** ma'lumotni ko'rsatadi.

### `VIEW`ning amaliy foydasi

`VIEW`ning asosiy qo'llanilishi: (1) **murakkab, tez-tez takrorlanadigan so'rovlarni** soddalashtirish — foydalanuvchilar (yoki hattoki boshqa dasturchilar) murakkab `JOIN`/`GROUP BY` mantig'ini bilishlari shart emas, ular shunchaki `SELECT * FROM view_nomi` yozadilar; (2) **xavfsizlik/ma'lumotni yashirish** — masalan, `xodimlar` jadvalidagi sezgir ustunlarni (masalan, `ish_haqi`) chiqarib tashlab, faqat kerakli ustunlarni ko'rsatuvchi view yaratib, unga faqat shu view'ga kirish huquqini berish mumkin (rollar va ruxsatlar haqida 15-bobda); (3) **mantiqiy abstraksiya** — agar kelajakda asl jadval strukturasi o'zgarsa (masalan, `xodimlar` ikkiga bo'linsa), `VIEW`ning ta'rifini yangilab, uni ishlatuvchi barcha kod o'zgarishsiz qolishi mumkin.

### `MATERIALIZED VIEW` — natijani jismonan saqlaydigan view

Oddiy `VIEW`ning kamchiligi — agar u orqasidagi so'rov **og'ir** (murakkab `JOIN`, katta agregatsiya) bo'lsa, har safar `VIEW`ga murojaat qilinganda bu og'ir so'rov **qaytadan** bajariladi, bu sekin bo'lishi mumkin. `MATERIALIZED VIEW` bu muammoni hal qiladi: u so'rov natijasini, xuddi 6.2-darsdagi `CREATE TABLE AS` kabi, **jismonan diskda saqlab qo'yadi**:

```sql
CREATE MATERIALIZED VIEW bolim_statistika AS
SELECT b.nomi, count(x.id) AS xodimlar_soni, avg(x.ish_haqi)::numeric(12,2) AS ortacha_maosh
FROM bolimlar b
LEFT JOIN xodimlar x ON b.id = x.bolim_id
GROUP BY b.id, b.nomi;

SELECT * FROM bolim_statistika ORDER BY nomi;
```

```
   nomi    | xodimlar_soni | ortacha_maosh 
-----------+---------------+---------------
 IT        |             3 |   16000000.00
 Kadrlar   |             1 |    9500000.00
 Marketing |             2 |    8750000.00
 Moliya    |             1 |   10000000.00
 Sotuv     |             3 |   10166666.67
```

### `MATERIALIZED VIEW` — "eskiradi", `REFRESH` kerak

Endi asl ma'lumotni o'zgartiramiz va `MATERIALIZED VIEW`ning **oddiy `VIEW`dan tubdan farqli** xatti-harakatini ko'ramiz:

```sql
UPDATE xodimlar SET ish_haqi = 30000000 WHERE ism = 'Aziz';
SELECT * FROM bolim_statistika WHERE nomi = 'IT';
```

```
 nomi | xodimlar_soni | ortacha_maosh 
------+---------------+---------------
 IT   |             3 |   16000000.00
```

Diqqat qiling — `ortacha_maosh` **hali ham eski** qiymat (`16000000.00`)! `MATERIALIZED VIEW` — o'z tabiatiga ko'ra, aynan `CREATE TABLE AS` kabi, "muzlatilgan surat" — u avtomatik yangilanmaydi. Yangilash uchun aniq `REFRESH` buyrug'i kerak:

```sql
REFRESH MATERIALIZED VIEW bolim_statistika;
SELECT * FROM bolim_statistika WHERE nomi = 'IT';
```

```
 nomi | xodimlar_soni | ortacha_maosh 
------+---------------+---------------
 IT   |             3 |   17666666.67
```

Endi qiymat yangilandi. `REFRESH MATERIALIZED VIEW` — butun so'rovni **qaytadan** bajarib, natijani yangilaydi (odatiy holda bu vaqtda view vaqtincha o'qish uchun bloklanadi; `CONCURRENTLY` kaliti bilan, agar view'da noyob indeks bo'lsa, bu bloklanishning oldini olish mumkin — bu mavzuga 21-bobda qaytamiz).

### `VIEW` vs `MATERIALIZED VIEW` — qachon qaysi birini tanlash

| | `VIEW` | `MATERIALIZED VIEW` |
|---|---|---|
| Ma'lumot | Saqlanmaydi, har safar hisoblanadi | Diskda jismoniy saqlanadi |
| Yangilik | Har doim **jonli**, real vaqtda | `REFRESH`gacha **eski** (stale) qoladi |
| Tezlik | Har safar so'rov qayta bajariladi (sekin bo'lishi mumkin) | O'qish tez (oddiy jadvaldek) |
| Qachon mos | Ma'lumot tez-tez o'zgaradi va har doim yangi natija kerak | Og'ir hisob-kitob, va biroz "eskirgan" natija (masalan, soatlik/kunlik yangilanadigan hisobot) qabul qilinadigan bo'lsa |

## Amaliy misol

**Vazifa:** Har bir mahsulot kategoriyasining umumiy ombor qiymatini (narx × son) ko'rsatuvchi oddiy `VIEW` yarating — bu tez-tez o'zgaruvchi ma'lumot (ombor holati) bo'lgani uchun, har doim jonli bo'lishi muhim.

```sql
CREATE VIEW kategoriya_ombor_qiymati AS
SELECT kategoriya, sum(narxi * ombordagi_soni) AS jami_qiymat
FROM mahsulotlar
GROUP BY kategoriya;

SELECT * FROM kategoriya_ombor_qiymati ORDER BY jami_qiymat DESC;
```

## Keng tarqalgan xatolar

**Xato 1:** `MATERIALIZED VIEW`ni oddiy `VIEW` kabi "har doim yangi" deb kutish.
✅ `MATERIALIZED VIEW`ni muntazam `REFRESH` qilish kerakligini unutmang (odatda `pg_cron` yoki tashqi vazifa rejalashtiruvchi orqali avtomatlashtirilgan holda — bu mavzuga 23-bobda qaytamiz).

**Xato 2:** Har doim eng yangi ma'lumot kerak bo'lgan holatda (masalan, real vaqtdagi ombor holati) `MATERIALIZED VIEW` ishlatish, natijada eskirgan ma'lumot asosida noto'g'ri qaror qabul qilish.
✅ Agar yangilik muhim bo'lsa, oddiy `VIEW` (yoki to'g'ridan-to'g'ri so'rov) ishlatilishi kerak.

**Xato 3:** Oddiy, arzon so'rov uchun keraksiz ravishda `MATERIALIZED VIEW` yaratish — bu qo'shimcha murakkablik (qachon `REFRESH` qilish kerakligini boshqarish) keltirib chiqaradi, hech qanday amaliy foyda bermasdan.
✅ `MATERIALIZED VIEW`ni faqat haqiqatan **og'ir** so'rovlar uchun, va "biroz eskirgan ma'lumot" qabul qilinadigan bo'lgan holatlarda ishlating.

## Mashq/topshiriq

**(Oson)** Har bir mijozning ismi va u bergan buyurtmalar sonini ko'rsatuvchi `mijoz_buyurtma_soni` nomli oddiy `VIEW` yarating.

**(O'rtacha)** Yuqoridagi `VIEW`ni yaratgach, yangi mijoz qo'shib (`INSERT`) va unga buyurtma berib (`INSERT`), view natijasi avtomatik yangilanganini tasdiqlang (keyin test ma'lumotlarini tozalang).

**(Qiyin)** `mahsulotlar` va `buyurtma_elementlari`ni birlashtirib, har bir mahsulotning jami sotilgan soni va jami tushumini hisoblovchi `MATERIALIZED VIEW` yarating, so'ng bitta yangi buyurtma elementi qo'shib (`INSERT`), `REFRESH`dan oldin va keyin natijalarni solishtiring.

## Qisqacha xulosa

`VIEW` — nomlangan, saqlangan `SELECT` so'rovi bo'lib, u hech qanday ma'lumotni o'zida saqlamaydi va har doim asl jadval(lar)dagi **eng yangi** ma'lumotni aks ettiradi — bu 6.2-darsdagi statik `CREATE TABLE AS`dan tubdan farq qiladi. `MATERIALIZED VIEW` esa natijani jismonan saqlaydi (tezroq o'qish uchun), lekin `REFRESH MATERIALIZED VIEW` bilan aniq yangilanmaguncha **eskirgan** holatda qoladi. Ikkalasini tanlashda asosiy savol — "menga har doim eng yangi ma'lumot kerakmi, yoki tezlik evaziga biroz eskirgan ma'lumot qabul qilinadimi". Keyingi darsda SQL'ning eng kuchli, ilg'or vositalaridan biri — window (oyna) funksiyalarini o'rganamiz.
