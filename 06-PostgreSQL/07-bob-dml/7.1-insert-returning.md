# 7.1. `INSERT` va `RETURNING`

## Bu darsda nimalarni o'rganasiz

- `INSERT INTO ... VALUES ...` bilan yangi qator(lar) qo'shishni bilasiz
- Bitta buyruqda bir nechta qatorni birdaniga kiritishni o'rganasiz
- `RETURNING` bilan yangi kiritilgan ma'lumotni (masalan, avtomatik yaratilgan `id`ni) darhol qaytarib olishni bilasiz
- Ustun ro'yxatini aniq ko'rsatishning nima uchun har doim yaxshiroq amaliyot ekanini tushunasiz
- `SERIAL`/`IDENTITY` ustunlar bo'yicha sequence "bo'shliqlari" (gaps) normal hodisa ekanini bilasiz

## Nazariy qism

### `INSERT` — asosiy sintaksis

```sql
INSERT INTO jadval (ustun1, ustun2, ...)
VALUES (qiymat1, qiymat2, ...);
```

```sql
INSERT INTO bolimlar (nomi, joylashuv) VALUES ('Yuridik', 'Toshkent');
```

```
INSERT 0 1
```

(`INSERT 0 1` — PostgreSQL'ning ichki javobi: `0` — eskirgan OID qiymati, amaliy ahamiyati yo'q; `1` — kiritilgan qatorlar soni.)

### Bir nechta qatorni bitta buyruqda kiritish

```sql
INSERT INTO bolimlar (nomi, joylashuv)
VALUES ('IT-Qollab', 'Toshkent'), ('Xavfsizlik', 'Samarqand');
```

```
INSERT 0 2
```

Bu — ikkita alohida `INSERT` buyrug'ini yozishdan **sezilarli tezroq** (ayniqsa ko'p qator kiritilganda), chunki PostgreSQL barcha qatorlarni **bitta** tranzaksiya va bitta tarmoq round-trip (agar masofaviy ulanish bo'lsa) ichida qayta ishlaydi.

### Nega ustun ro'yxatini har doim aniq yozish kerak

Texnik jihatdan, ustun ro'yxatini tashlab, faqat `VALUES`ni yozish ham mumkin:

```sql
-- ISHLAYDI, lekin TAVSIYA ETILMAYDI
INSERT INTO bolimlar VALUES (11, 'Test', 'Namangan');
```

Bu holatda PostgreSQL qiymatlarni jadvalning **fizik ustunlar tartibi** bo'yicha mos qo'yadi. Bu — juda **xavfli** amaliyot: agar kelajakda jadvalga yangi ustun qo'shilsa yoki ustunlar tartibi o'zgarsa (masalan, `ALTER TABLE` orqali), bu `INSERT` yoki xato beradi, yoki — eng yomoni — **xato ustunlarga noto'g'ri qiymatlar yozib, sezilmagan holda ma'lumotni buzadi**. Shu sababli, amaliyotda **har doim** ustun ro'yxatini aniq ko'rsatish qat'iy tavsiya etiladi:

```sql
-- Tavsiya etiladi — har doim ustunlarni aniq ko'rsating
INSERT INTO bolimlar (nomi, joylashuv) VALUES ('Test', 'Namangan');
```

Bunday yozilganda, agar jadvalga yangi ustun (masalan, `tavsif`) qo'shilsa ham, bu `INSERT` xatosiz, to'g'ri ishlashda davom etadi (yangi ustun uchun standart qiymat yoki `NULL` qo'yiladi).

### `SERIAL`/`IDENTITY` ustunlarga qiymat berish shart emas

6.1-darsda ko'rganimizdek, `id SERIAL PRIMARY KEY` ustuni avtomatik to'ldiriladi — uni `INSERT`ning ustun ro'yxatida **umuman ko'rsatmaslik** kerak (agar aniq, maxsus qiymat majburlashni xohlamasangiz):

```sql
INSERT INTO bolimlar (nomi, joylashuv) VALUES ('Yuridik', 'Toshkent');
-- id avtomatik: keyingi mavjud sequence qiymati beriladi
```

### `RETURNING` — kiritilgan ma'lumotni darhol qaytarib olish

Odatda, `INSERT`dan keyin siz yangi yaratilgan qatorning avtomatik `id`sini (yoki boshqa avtomatik hisoblangan ustun qiymatini) bilishni xohlaysiz — masalan, ilovada "yangi buyurtma yaratildi, uning ID'si nima" degan savolga darhol javob kerak. Buning uchun alohida `SELECT` yozish shart emas — PostgreSQL'ning o'ziga xos `RETURNING` bandi buni bitta buyruqda amalga oshiradi:

```sql
INSERT INTO bolimlar (nomi, joylashuv)
VALUES ('Yuridik', 'Toshkent')
RETURNING id, nomi;
```

```
 id |  nomi   
----+---------
 10 | Yuridik
(1 row)
```

(Sizning muhitingizda boshqa `id` raqami chiqishi mumkin — bu haqda pastda alohida tushuntiramiz.) `RETURNING *` yozib, barcha ustunlarni qaytarish ham mumkin:

```sql
INSERT INTO bolimlar (nomi, joylashuv) VALUES ('Test', 'Farg''ona') RETURNING *;
```

`RETURNING` — nafaqat `INSERT`da, balki `UPDATE` va `DELETE`da ham ishlaydi (7.2 va 7.3-darslarda ko'ramiz), va bu — PostgreSQL'ning ko'plab boshqa DBMS'larda mavjud bo'lmagan, juda qulay kengaytmasi (odatda buning o'rniga alohida `SELECT ... WHERE id = LAST_INSERT_ID()` kabi noqulay ikki bosqichli usul kerak bo'lardi).

### Sequence "bo'shliqlari" (gaps) — bu normal, xato emas

Yuqoridagi misolda `id = 10` chiqdi, garchi bizning `bolimlar` jadvalida atigi 5 ta doimiy qator bo'lsa ham. Bu — **muhim va tez-tez chalkashtiriladigan** tushuncha: `SERIAL`/`IDENTITY` ustunining "orqasidagi" sequence generatori **tranzaksiyadan mustaqil** ishlaydi. Agar avval (masalan, sinov maqsadida) bir nechta qator kiritilib, keyin `ROLLBACK` qilingan yoki `DELETE` bilan o'chirilgan bo'lsa ham, sequence **avtomatik orqaga qaytmaydi** — u faqat oldinga siljiydi. Natijada, vaqt o'tishi bilan `id` qiymatlarida "bo'shliqlar" (masalan, 5, 6, 10, 11 — 7, 8, 9 yo'q) paydo bo'lishi **butunlay normal** holat va bu hech qanday ma'lumot yaxlitligi muammosini bildirmaydi (bu mavzuni 16-bobda sequence'larning ichki mexanizmi orqali chuqurroq tushunamiz). **Amaliy xulosa:** `id` qiymatlariga hech qachon "ular albatta ketma-ket, bo'shliqsiz bo'ladi" degan taxmin asosida mantiq qurmang.

## Amaliy misol

**Vazifa:** Yangi mijoz ro'yxatdan o'tkazing va uning avtomatik yaratilgan `id`sini darhol oling (masalan, shu ID bilan birinchi buyurtmasini yaratish uchun).

```sql
INSERT INTO mijozlar (ism, email, shahar, royxatdan_otgan_sana)
VALUES ('Sarvar Ibragimov', 'sarvar.i@example.uz', 'Toshkent', CURRENT_DATE)
RETURNING id, ism;
```

Ilova darajasida, endi bu so'rovdan qaytgan `id`ni darhol keyingi `INSERT INTO buyurtmalar (mijoz_id, ...) VALUES (<yuqoridagi id>, ...)` so'rovida ishlatish mumkin — bu ikki bosqichli jarayonni ancha soddalashtiradi.

## Keng tarqalgan xatolar

**Xato 1:** Ustun ro'yxatisiz `INSERT INTO jadval VALUES (...)` yozish odatiga tushib qolish.
✅ Har doim ustun nomlarini aniq ko'rsating — bu kodning kelajakdagi sxema o'zgarishlariga chidamliligini oshiradi.

**Xato 2:** `SERIAL`/`IDENTITY` ustuniga qo'lda, aniq qiymat kiritish (masalan, `id`ni ham `VALUES`da ko'rsatish), so'ng sequence bilan to'qnashuvga duch kelish.
❌ `INSERT INTO bolimlar (id, nomi, joylashuv) VALUES (3, 'Yangi', 'Toshkent');` — agar `id=3` band bo'lsa xato, band bo'lmasa ham, sequence bu qo'lda kiritilgan qiymatdan xabardor bo'lmay qoladi va kelajakda to'qnashuv xavfini oshiradi.
✅ `SERIAL`/`IDENTITY` ustunlarga odatda qiymat berilmaydi — avtomatik to'ldirilishiga ruxsat bering.

**Xato 3:** `id`larning ketma-ket, bo'shliqsiz bo'lishini kutish va sequence "bo'shliqlarini" xato deb hisoblash.
✅ Bu — normal PostgreSQL xatti-harakati; agar sizga haqiqatan ketma-ket raqamlash kerak bo'lsa (masalan, hisob-faktura raqamlari uchun), bu alohida, maxsus mantiq talab qiladigan vazifa (sequence emas).

## Mashq/topshiriq

**(Oson)** `mahsulotlar` jadvaliga yangi mahsulot ("Simsiz quloqchin", narxi 850000, kategoriya "Elektronika", ombordagi soni 25) qo'shing va uning avtomatik `id`sini `RETURNING` bilan oling.

**(O'rtacha)** Bitta `INSERT` buyrug'ida `bolimlar` jadvaliga ikkita yangi bo'lim ("Logistika", "Andijon") va ("Sifat nazorati", "Buxoro") qo'shing, `RETURNING`da ikkalasining ham `id` va `nomi`sini chiqaring.

**(Qiyin)** Yangi mijoz qo'shing va `RETURNING` yordamida olingan `id`dan foydalanib, xuddi shu tranzaksiya (`BEGIN`/`COMMIT`) ichida darhol shu mijoz uchun yangi buyurtma yarating (`buyurtmalar` jadvaliga). (Eslatma: haqiqiy ilovada bu ikki qadam ilova kodida ketma-ket bajariladi — `psql`da buni qo'lda, birinchi so'rovning natijasidagi `id`ni ko'zdan kechirib, ikkinchi so'rovga qo'lda kiritib bajaring.)

## Qisqacha xulosa

`INSERT INTO jadval (ustunlar) VALUES (...)` — yangi qator(lar) qo'shishning asosiy vositasi; ustun ro'yxatini har doim aniq yozish kelajakdagi sxema o'zgarishlariga chidamlilikni ta'minlaydi. `RETURNING` — PostgreSQL'ning kuchli kengaytmasi bo'lib, kiritilgan (yoki 7.2/7.3-darslarda ko'radigan `UPDATE`/`DELETE`dagi o'zgargan/o'chirilgan) qatorning ustunlarini, ayniqsa avtomatik yaratilgan `id`ni, alohida `SELECT`siz darhol qaytarib beradi. `SERIAL`/`IDENTITY` ustunlaridagi raqamlar orasida "bo'shliqlar" paydo bo'lishi mumkinligini va bu normal hodisa ekanini yodda tuting. Keyingi darsda mavjud qatorlarni o'zgartirish — `UPDATE`ni chuqur o'rganamiz.
