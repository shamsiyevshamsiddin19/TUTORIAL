# 7.3. `DELETE` — qatorlarni o'chirish

## Bu darsda nimalarni o'rganasiz

- `DELETE FROM jadval WHERE shart` bilan qatorlarni o'chirishni bilasiz
- `WHERE`siz `DELETE` **barcha** qatorlarni o'chirishini (va nima uchun `UPDATE`dagi kabi xavfli ekanini) tushunasiz
- Tashqi kalit (`FOREIGN KEY`) cheklovi `DELETE`ni qanday to'sib qo'yishi mumkinligini bilasiz
- `DELETE ... USING` bilan boshqa jadval asosida o'chirishni bilasiz
- `DELETE` va `TRUNCATE` orasidagi farqni (6.4-darsdan) mustahkamlaysiz

## Nazariy qism

### `DELETE` — asosiy sintaksis

```sql
DELETE FROM jadval
WHERE shart;
```

```sql
INSERT INTO mahsulotlar (nomi, narxi, kategoriya, ombordagi_soni)
VALUES ('Sinov mahsuloti', 100000, 'Elektronika', 5);

DELETE FROM mahsulotlar WHERE nomi = 'Sinov mahsuloti' RETURNING nomi;
```

```
      nomi       
-----------------
 Sinov mahsuloti
(1 row)
```

`WHERE` bandi bu yerda ham 1.3-darsdagi bilan aynan bir xil mantiqda ishlaydi — faqat shartga mos qatorlar o'chiriladi.

### ⚠️ `WHERE`siz `DELETE` — `UPDATE`dagi kabi xavfli

Xuddi 7.2-darsdagi `UPDATE` kabi, `WHERE`ni unutish `DELETE`da ham **halokatli** oqibatlarga olib keladi:

```sql
-- ❌ JUDA XAVFLI — barcha qatorlarni o'chiradi!
DELETE FROM mahsulotlar;
```

Bu buyruq jadvalning **o'zini** saqlab qoladi (6.4-darsdagi `TRUNCATE`/`DROP` farqini eslang), lekin ichidagi **barcha** ma'lumotni o'chiradi. **Amaliy qoida — `UPDATE`dagi bilan bir xil:** `DELETE`dan oldin har doim aynan shu `WHERE` shart bilan `SELECT` yozib, qaysi qatorlar o'chirilishini oldindan ko'rib chiqing, va imkon qadar tranzaksiya (`BEGIN` ... `ROLLBACK`/`COMMIT`, 13-bobda chuqur) ichida ishlang.

### `FOREIGN KEY` cheklovi `DELETE`ni to'sib qo'yishi mumkin

Bu — 6.4-darsda `DROP TABLE`da ko'rgan himoya mexanizmining, endi **qator** darajasidagi versiyasi. Agar boshqa jadvaldagi qator sizning o'chirmoqchi bo'lgan qatoringizga `FOREIGN KEY` orqali ishora qilayotgan bo'lsa, PostgreSQL standart holda o'chirishga **yo'l qo'ymaydi**:

```sql
DELETE FROM mijozlar WHERE id = 1;
```

```
ERROR:  update or delete on table "mijozlar" violates foreign key constraint "buyurtmalar_mijoz_id_fkey" on table "buyurtmalar"
DETAIL:  Key (id)=(1) is still referenced from table "buyurtmalar".
```

Bu — **muhim va foydali** himoya: agar `mijoz_id = 1` o'chirilsa, `buyurtmalar` jadvalidagi unga tegishli qatorlar "yetim" (orphan) — mavjud bo'lmagan mijozga ishora qiluvchi — bo'lib qolar edi, bu esa ma'lumotlar yaxlitligini buzadi. Bu muammoni yechishning bir necha yo'li bor: (1) avval bog'liq qatorlarni (`buyurtmalar`dagi tegishli yozuvlarni) alohida o'chirish; (2) `FOREIGN KEY` yaratilganda `ON DELETE CASCADE` (8-bobda chuqur) belgilash, bu holda bosh yozuv o'chirilganda bog'liq yozuvlar **avtomatik** o'chadi; (3) `ON DELETE SET NULL` — bog'liq yozuvlardagi tashqi kalitni `NULL`ga o'rnatish. Bu strategiyalarni 8-bobda (Constraints) to'liq ko'rib chiqamiz — hozircha shuni bilish kifoya: **standart holatda PostgreSQL "yetim" yozuvlar paydo bo'lishiga yo'l qo'ymaydi**, bu — xato emas, balki yaxlitlikni himoya qiluvchi to'g'ri xatti-harakat.

### `DELETE ... USING` — boshqa jadval asosida o'chirish

Xuddi `UPDATE ... FROM`dagi kabi, `DELETE`da ham boshqa jadvaldagi ma'lumotga asoslanib o'chirish kerak bo'lishi mumkin. Buning uchun `DELETE ... USING` ishlatiladi:

```sql
DELETE FROM buyurtma_elementlari be
USING buyurtmalar bu
WHERE be.buyurtma_id = bu.id AND bu.holati = 'bekor qilindi'
RETURNING be.id, bu.id AS buyurtma_id;
```

```
 id | buyurtma_id 
----+-------------
  8 |           6
(1 row)
```

Bu so'rov "bekor qilindi" holatidagi buyurtmalarga tegishli barcha `buyurtma_elementlari` yozuvlarini o'chiradi — `USING`da ko'rsatilgan `buyurtmalar` jadvali faqat **qaysi qatorlarni o'chirish kerakligini aniqlash** uchun ishlatiladi, uning o'zidagi qatorlar hech qachon o'chirilmaydi (faqat `DELETE FROM`da ko'rsatilgan jadval — bu holda `buyurtma_elementlari` — o'zgaradi).

### `DELETE` vs `TRUNCATE` — qachon qaysi birini ishlatish

6.4-darsda ko'rganimizdek: agar sizga jadvaldagi **barcha** qatorlarni o'chirish kerak bo'lsa (shartsiz), `TRUNCATE` deyarli har doim `DELETE FROM jadval`dan (`WHERE`siz) tezroq va samaraliroq. `DELETE`ning ustunligi esa — u `WHERE` bilan **tanlab** o'chirishga imkon beradi, `TRUNCATE` esa faqat "hammasi yoki hech narsa" tamoyilida ishlaydi.

## Amaliy misol

**Vazifa:** Ombordagi soni `0` bo'lgan, va hech qachon birorta ham buyurtmada uchramagan (ya'ni hech qachon sotilmagan) mahsulotlarni bazadan tozalang — bu 3.2-darsdagi `LEFT ANTI JOIN` naqshini `DELETE`ga qo'llash.

```sql
DELETE FROM mahsulotlar m
WHERE m.ombordagi_soni = 0
  AND NOT EXISTS (
      SELECT 1 FROM buyurtma_elementlari be WHERE be.mahsulot_id = m.id
  )
RETURNING m.nomi;
```

(`NOT EXISTS` — 9-bobda chuqur o'rganiladigan subquery turi, bu yerda 2.1-darsda tilga olingan `NOT IN`ning xavfsizroq muqobili sifatida ishlatildi.)

## Keng tarqalgan xatolar

**Xato 1:** `WHERE`ni unutib, jadvaldagi barcha ma'lumotni tasodifan o'chirib qo'yish.
✅ `UPDATE`dagi bilan bir xil ehtiyot choralari: avval `SELECT` bilan tekshiring, tranzaksiya ichida ishlang.

**Xato 2:** `FOREIGN KEY` xatosiga duch kelganda, uni "tushunarsiz xato" deb, sabab-oqibatni tekshirmasdan `CASCADE` yechimlarini qidirishga shoshilish.
✅ Xato xabaridagi `DETAIL` qatorini diqqat bilan o'qing — u aynan qaysi jadval va qaysi qator bog'liqligini ko'rsatadi; faqat shundan keyin to'g'ri strategiyani (bog'liq yozuvlarni ham o'chirish, yoki `ON DELETE CASCADE` sozlash) tanlang.

**Xato 3:** `DELETE ... USING`da `WHERE`ga bog'lash shartini (`be.buyurtma_id = bu.id`) qo'shishni unutish — natijada `CROSS JOIN`ga o'xshash keng qamrovli, kutilmagan o'chirish yuz beradi.
✅ `UPDATE ... FROM`dagi kabi, `DELETE ... USING`da ham har doim to'g'ri bog'lash shartini unutmang.

## Mashq/topshiriq

**(Oson)** `bolimlar` jadvaliga vaqtincha "Sinov bo'limi" (joylashuvi "Namangan") qo'shing, so'ng uni `DELETE` bilan o'chirib tashlang.

**(O'rtacha)** `mijozlar` jadvalidan biror mijozni (masalan, "Bekzod Rahimov"ni, unga tegishli buyurtmalar borligi sababli) o'chirishga urinib ko'ring, xato xabarini o'qing va nega bu xato **foydali** himoya ekanini tushuntiring.

**(Qiyin)** `DELETE ... USING` yordamida, "kutilmoqda" holatidagi buyurtmalarga tegishli barcha `buyurtma_elementlari` yozuvlarini (tranzaksiya ichida, `ROLLBACK` bilan) o'chirishni sinab ko'ring, va `RETURNING` bilan nechta qator o'chirilganini tasdiqlang.

## Qisqacha xulosa

`DELETE FROM jadval WHERE shart` — qatorlarni o'chirishning asosiy vositasi; `WHERE`ni unutish `UPDATE`dagi kabi xavfli, barcha qatorlarni o'chirib yuborishi mumkin. `FOREIGN KEY` cheklovlari standart holda "yetim" yozuvlar paydo bo'lishiga yo'l qo'ymaydi — bu xato emas, balki ma'lumotlar yaxlitligini himoya qiluvchi mexanizm (8-bobda `ON DELETE CASCADE`/`SET NULL` bilan bu xatti-harakatni sozlashni o'rganamiz). `DELETE ... USING` esa boshqa jadval ma'lumotiga asoslanib tanlab o'chirish imkonini beradi. Keyingi darsda ma'lumotni ommaviy import/eksport qilish — `COPY`ni o'rganamiz.
