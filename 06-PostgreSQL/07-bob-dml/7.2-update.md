# 7.2. `UPDATE` — mavjud qatorlarni o'zgartirish

## Bu darsda nimalarni o'rganasiz

- `UPDATE ... SET ... WHERE ...` bilan mavjud qatorlarni o'zgartirishni bilasiz
- `WHERE`siz `UPDATE` **barcha** qatorlarni o'zgartirishini — va bu qanchalik xavfli ekanini — chuqur tushunasiz
- Yangi qiymatni eski qiymat asosida hisoblashni (`SET ustun = ustun * ...`) bilasiz
- `UPDATE ... FROM` bilan boshqa jadval ma'lumotlari asosida yangilashni o'rganasiz
- `RETURNING` bilan o'zgargan qatorlarni darhol ko'rishni bilasiz

## Nazariy qism

### `UPDATE` — asosiy sintaksis

```sql
UPDATE jadval
SET ustun1 = yangi_qiymat1, ustun2 = yangi_qiymat2, ...
WHERE shart;
```

```sql
UPDATE mahsulotlar
SET narxi = 8000000
WHERE nomi = 'Noutbuk Lenovo IdeaPad';
```

`WHERE` bandi bu yerda 1.3-darsdagi bilan **aynan bir xil** ishlaydi — u qaysi qatorlar o'zgartirilishini aniqlaydi.

### ⚠️ `WHERE`siz `UPDATE` — ENG XAVFLI SQL XATOLARIDAN BIRI

Bu — bu darsning eng muhim ogohlantirishi: agar `WHERE` bandini unutib qo'ysangiz, `UPDATE` **jadvaldagi BARCHA qatorlarni** o'zgartiradi:

```sql
-- ❌ JUDA XAVFLI — WHERE unutilgan!
UPDATE mahsulotlar SET narxi = 8000000;
```

Bu buyruq **barcha 10 ta mahsulotning** narxini 8,000,000 so'mga o'rnatib qo'yadi — bu deyarli har doim xato, ataylab qilingan harakat emas. Bu — real production baza(lar)ida eng ko'p uchraydigan, va ko'pincha eng katta zarar keltiradigan inson xatolaridan biri (internetda "forgot WHERE clause" degan qidiruv juda ko'p dahshatli voqealarni ko'rsatadi). **Amaliy qoida:** `UPDATE` yozishdan oldin, har doim avval **aynan shu `WHERE` shart bilan** `SELECT` yozib, qaysi qatorlar ta'sirlanishini oldindan ko'rib chiqing:

```sql
-- 1-qadam: avval SELECT bilan tekshiring
SELECT nomi, narxi FROM mahsulotlar WHERE kategoriya = 'Mebel';

-- 2-qadam: natija to'g'ri ekaniga ishonch hosil qilgach, UPDATE'ga aylantiring
UPDATE mahsulotlar SET narxi = narxi * 1.1 WHERE kategoriya = 'Mebel';
```

### Yangi qiymatni eski qiymat asosida hisoblash

`SET`ning o'ng tomonida ustunning **joriy** (o'zgarishdan oldingi) qiymatidan foydalanish mumkin — bu "barcha narxlarni X foizga oshirish" kabi vazifalarda juda keng qo'llaniladi:

```sql
UPDATE mahsulotlar
SET narxi = narxi * 1.1
WHERE kategoriya = 'Mebel'
RETURNING nomi, narxi;
```

```
      nomi      |   narxi    
----------------+------------
 Ofis stuli     | 1320000.00
 Ish stoli      | 2750000.00
 Kitob tokchasi |  990000.00
(3 rows)
```

Bu yerda `narxi * 1.1` — har bir qator uchun **o'zining** joriy narxi asosida (10% qo'shib) hisoblanadi, barcha uchta Mebel mahsuloti uchun alohida-alohida.

### Bir nechta ustunni birgalikda yangilash

```sql
UPDATE xodimlar
SET ish_haqi = 12000000, lavozim = 'Katta dasturchi'
WHERE ism = 'Sardor' AND familiya = 'Aliyev';
```

Vergul bilan ajratilgan holda istalgan sondagi ustunni bitta `UPDATE`da yangilash mumkin — bu ular alohida-alohida `UPDATE` buyruqlarida yangilanishidan farqli o'laroq, **bitta atomik amal** sifatida bajariladi (13-bobda tranzaksiyalar va atomiklikni chuqur o'rganamiz).

### `UPDATE ... FROM` — boshqa jadval ma'lumotlari asosida yangilash

Ba'zan yangilanadigan qiymat boshqa jadvaldagi ma'lumotga bog'liq bo'ladi — masalan, "Toshkentda joylashgan bo'limlardagi barcha xodimlarga 5% qo'shimcha maosh berish". Bu vazifa uchun `UPDATE ... FROM` ishlatiladi — bu, aslida, `UPDATE` ichiga "joylashtirilgan" `JOIN`:

```sql
UPDATE xodimlar x
SET ish_haqi = ROUND(ish_haqi * 1.05, 2)
FROM bolimlar b
WHERE x.bolim_id = b.id AND b.joylashuv = 'Toshkent'
RETURNING x.ism, b.nomi, x.ish_haqi;
```

```
   ism   |  nomi  |  ish_haqi   
---------+--------+-------------
 Aziz    | IT     | 26250000.00
 Dilnoza | Sotuv  | 15750000.00
 Sardor  | IT     | 12600000.00
 Malika  | Sotuv  |  8400000.00
 Nodira  | Moliya | 10500000.00
 Farrux  | IT     | 11550000.00
 Otabek  | Sotuv  |  7875000.00
(7 rows)
```

Bu yerda `UPDATE xodimlar x ... FROM bolimlar b WHERE x.bolim_id = b.id AND b.joylashuv = 'Toshkent'` shunday o'qiladi: "`xodimlar`ni yangila, lekin faqat `bolimlar` bilan bog'langan va `bolimlar.joylashuv = 'Toshkent'` bo'lgan qatorlarni" — natijada faqat Toshkentdagi 3 ta bo'lim (Sotuv, IT, Moliya)dagi 7 ta xodim yangilanadi, Marketing (Samarqand) va Kadrlar (Buxoro) bo'limidagi xodimlar **o'zgarishsiz** qoladi.

> **Diqqat:** `UPDATE ... FROM`dagi `WHERE` bandi ikkita **turli** vazifani bajaradi — bir qismi (`x.bolim_id = b.id`) `JOIN` shartidek ishlaydi (qaysi `bolimlar` qatori qaysi `xodimlar` qatoriga mos kelishini aniqlaydi), boshqa qismi (`b.joylashuv = 'Toshkent'`) esa filtr sifatida ishlaydi. Ikkalasi ham bitta `WHERE`da, `AND` bilan birlashtirilgan holda yoziladi — bu 3-bobdagi `JOIN ... ON` bilan solishtirganda boshqacharoq, lekin PostgreSQL'ning standart va keng qo'llaniladigan sintaksisi.

## Amaliy misol

**Vazifa:** Omborda soni 5 tadan kam qolgan barcha mahsulotlarni "kam qolgan" deb belgilash uchun, ularning `kategoriya` ustuniga vaqtinchalik `' (KAM QOLDI)'` qo'shimchasini qo'shing, va o'zgargan qatorlarni ko'ring.

```sql
UPDATE mahsulotlar
SET kategoriya = kategoriya || ' (KAM QOLDI)'
WHERE ombordagi_soni < 5 AND kategoriya NOT LIKE '%KAM QOLDI%'
RETURNING nomi, ombordagi_soni, kategoriya;
```

(`||` — matnlarni birlashtirish operatori; `AND kategoriya NOT LIKE '%KAM QOLDI%'` — bu `UPDATE`ni bir necha marta ishga tushirsak ham, belgi ikki marta qo'shilib ketmasligi uchun ehtiyot chorasi — bu kabi "idempotent" — bir necha marta bajarilsa ham natija bir xil bo'ladigan — buyruqlar yozish yaxshi amaliyot hisoblanadi.)

## Keng tarqalgan xatolar

**Xato 1:** `WHERE`ni unutib, barcha qatorlarni tasodifan o'zgartirib qo'yish (yuqorida batafsil ko'rsatilgan) — bu shu darsning eng muhim ogohlantirishi.
✅ Har doim avval `SELECT` bilan tekshiring, so'ng `UPDATE`ga aylantiring; imkon bo'lsa, tranzaksiya (`BEGIN`) ichida bajarib, natijani ko'rgach `COMMIT`/`ROLLBACK` qiling (13-bobda).

**Xato 2:** `UPDATE ... FROM`da `JOIN` shartini (`x.bolim_id = b.id`) yozishni unutish — natijada har bir `xodimlar` qatori `bolimlar`dagi **barcha** qatorlar bilan mos kelib, kutilmagan natija (yoki xato) beradi.
✅ `UPDATE ... FROM`dagi `WHERE`ga har doim to'g'ri bog'lash shartini kiritishni unutmang.

**Xato 3:** `SET ustun = ustun * X`ni ishlatishda, `ustun`ning `NULL` bo'lishi mumkinligini unutish — 2.3-darsda ko'rganimizdek, `NULL * X = NULL` bo'lib qoladi.
✅ Agar `NULL` qiymatlarni ham "nolga teng" deb hisoblash kerak bo'lsa, `COALESCE(ustun, 0) * X` ishlating.

## Mashq/topshiriq

**(Oson)** `xodimlar` jadvalida "Malika Rashidova"ning lavozimini "Katta sotuv menejeri"ga o'zgartiring, `RETURNING` bilan tasdiqlang.

**(O'rtacha)** `mahsulotlar` jadvalida "Maishiy texnika" kategoriyasidagi barcha mahsulotlarning narxini 15% ga tushiring (chegirma), so'ng natijani ko'rib, keyin narxlarni asl holatiga qaytaring (`/ 1.15` bilan).

**(Qiyin)** `UPDATE ... FROM` yordamida, "IT" bo'limidagi xodimlarning `lavozim` ustuniga, agar ularning bevosita boshlig'i "Bosh direktor" bo'lsa, `' (to'g'ridan-to'g'ri bo'ysunuvchi)'` qo'shimchasini qo'shing (o'z-o'ziga `JOIN` — 3.4-darsdagi `SELF JOIN` naqshini `UPDATE ... ## Qisqacha xulosa

`UPDATE ... SET ... WHERE ...` — mavjud qatorlarni o'zgartirishning asosiy vositasi; `WHERE`ni unutish — barcha qatorlarni tasodifan o'zgartirib qo'yadigan, eng xavfli va eng ko'p uchraydigan SQL xatolaridan biri, shuning uchun `UPDATE`dan oldin har doim mos `SELECT` bilan tekshirish odat qilinishi kerak. `SET`da ustunning joriy qiymatidan foydalanish (`ustun = ustun * X`) va `UPDATE ... FROM` orqali boshqa jadval ma'lumotlariga asoslanib yangilash — real loyihalarda tez-tez uchraydigan naqshlar. `RETURNING` esa `INSERT`dagi kabi, o'zgargan qatorlarni darhol, alohida `SELECT`siz ko'rish imkonini beradi. Keyingi darsda qatorlarni butunlay olib tashlash — `DELETE`ni chuqur o'rganamiz.
