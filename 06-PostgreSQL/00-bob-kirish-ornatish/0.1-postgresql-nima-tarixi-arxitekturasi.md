# 0.1. PostgreSQL nima, tarixi va arxitekturasi

## Bu darsda nimalarni o'rganasiz

- PostgreSQL nima ekanini va uni boshqa ma'lumotlar bazalaridan (MySQL, SQLite, Oracle) nima farqlashini tushunasiz
- PostgreSQL'ning qisqacha tarixini (Ingres → Postgres → PostgreSQL) bilib olasiz
- Klient-server arxitekturasini va asosiy jarayonlarni (`postmaster`, backend jarayonlar) tushunasiz
- Relyatsion ma'lumotlar bazasining asosiy tushunchalarini (jadval, qator, ustun, sxema, baza) bilasiz

## Nazariy qism

### PostgreSQL nima

**PostgreSQL** (talaffuzi: "post-gres-kyu-el", ko'pincha qisqacha "Postgres" deb ham ataladi) — ochiq manbali (open source), **obyekt-relyatsion** ma'lumotlar bazasi boshqaruv tizimi (Object-Relational Database Management System, ORDBMS). "Relyatsion" degani — ma'lumotlar **jadvallar** (tables) ko'rinishida, qatorlar (rows) va ustunlar (columns) shaklida saqlanadi, va jadvallar orasida **munosabatlar** (relations, masalan tashqi kalitlar orqali) o'rnatiladi. "Obyekt" qismi esa PostgreSQL'ning oddiy relyatsion modeldan tashqari, murakkab ma'lumot turlari (massivlar, JSON, geometrik turlar), meros (table inheritance) va kengaytiriladigan tur tizimini qo'llab-quvvatlashini bildiradi.

PostgreSQL nafaqat ma'lumotlarni saqlash vositasi — u to'liq huquqli **dasturlash muhiti**: unda saqlanadigan protseduralar (stored procedures), triggerlar, maxsus funksiyalar, hatto maxsus ma'lumot turlari va indeks turlarini ham yozish mumkin. Aynan shu kengaytiriluvchanlik tufayli PostgreSQL "dunyodagi eng ilg'or ochiq manbali ma'lumotlar bazasi" (the world's most advanced open source database) deb ataladi — bu PostgreSQL rasmiy veb-saytining o'zining shiori.

### Nega aynan PostgreSQL — qisqacha taqqoslash

| Xususiyat | PostgreSQL | MySQL | SQLite |
|---|---|---|---|
| Litsenziya | PostgreSQL litsenziyasi (MIT'ga o'xshash, erkin) | GPL (Community) / kommercheska | Public Domain |
| Arxitektura | Klient-server | Klient-server | Ichki (in-process), fayl asosida |
| ACID muvofiqlik | To'liq, kuchli | Storage motoriga bog'liq (InnoDB — ha) | To'liq (bitta yozuvchi bilan) |
| Murakkab so'rovlar (window functions, CTE, JSON) | Juda kuchli, boy | O'rtacha, so'nggi versiyalarda yaxshilangan | Cheklangan |
| Kengaytirilishi (extensions) | Juda kuchli (PostGIS, pgvector va h.k.) | Cheklangan | Yo'q |
| Tipik qo'llanish | Murakkab, katta hajmli, transaction-og'ir tizimlar | Veb-ilovalar, tez o'qish-yozish | Mobil, kichik, ichki ilovalar |

PostgreSQL, ayniqsa so'nggi yillarda, murakkab tahliliy so'rovlar, geografik ma'lumotlar (PostGIS kengaytmasi orqali), va hatto sun'iy intellekt bilan bog'liq vector qidiruv (`pgvector` kengaytmasi orqali) uchun sanoat standartiga aylangan — bu uning kengaytiriluvchan arxitekturasi tufayli mumkin bo'lgan.

### Qisqacha tarix

PostgreSQL'ning ildizlari 1980-yillarga borib taqaladi:

1. **Ingres** (1970-yillar oxiri) — Berkli universitetida Michael Stonebraker rahbarligida yaratilgan birinchi relyatsion DBMS loyihalaridan biri.
2. **Postgres** (1986-1994) — Stonebraker Ingres'dan keyin, "Post-Ingres" (Ingres'dan keyingi) nomi bilan yangi loyihani boshladi — bu loyiha obyekt-relyatsion konsepsiyalarni (murakkab turlar, meros) qo'shishga qaratilgan edi.
3. **Postgres95** (1995) — loyiha SQL so'rov tilini qo'llab-quvvatlash uchun qayta ishlangan va ochiq manbali qilib chiqarilgan.
4. **PostgreSQL** (1996-hozirgi kunga qadar) — nom "PostgreSQL" (SQL qo'llab-quvvatlanishini ta'kidlash uchun) deb o'zgartirildi, va o'shandan beri loyiha faol, ochiq hamjamiyat tomonidan rivojlantirilib kelinmoqda.

PostgreSQL'ning har yili (odatda sentabr-oktabr oylarida) yangi **major** versiyasi chiqadi. Ushbu darslik yozilgan vaqtda joriy barqaror versiya — **PostgreSQL 18** (2025-yil sentabrda chiqqan, hozirda 18.6 kabi patch-relizlarga ega), keyingi **PostgreSQL 19** esa beta bosqichida. Har bir major versiya odatda **5 yil** davomida rasmiy qo'llab-quvvatlanadi (xavfsizlik va xato tuzatishlari bilan).

### Klient-server arxitekturasi

PostgreSQL — klassik **klient-server** modelida ishlaydi:

```
┌─────────────┐      TCP/IP yoki Unix socket      ┌──────────────────────────┐
│   Klient    │ ───────────────────────────────►  │   PostgreSQL server      │
│ (psql, ilova,│                                    │                          │
│  pgAdmin...) │ ◄───────────────────────────────  │  postmaster + backendlar │
└─────────────┘         natijalar/xatolar           └──────────────────────────┘
```

Server tomonida bir nechta muhim jarayon ishlaydi:

- **`postmaster`** — asosiy, "boshqaruvchi" jarayon. Server ishga tushganda birinchi bo'lib ishga tushadi, TCP portini (standart holatda **5432**) tinglaydi va yangi klient ulanishini kutadi.
- **Backend jarayon** — har bir klient ulanishi uchun `postmaster` **alohida, mustaqil OS jarayonini** (process) "fork" qiladi (PostgreSQL — bu boshqa ba'zi DBMS'lardan farqli o'laroq, oqim (thread) emas, balki **jarayon** (process) asosida ishlaydi). Bu jarayon ulanish yashab turgan davomida shu klientning barcha so'rovlarini qayta ishlaydi.
- **Fon jarayonlari (background processes)** — `postmaster` bilan bir qatorda doimiy ishlab turadigan yordamchi jarayonlar: `checkpointer` (WAL nazorat nuqtalarini yozadi, 20-bobda batafsil), `background writer` (o'zgargan sahifalarni diskka yozadi), `autovacuum launcher` (17-bobda batafsil ko'radigan VACUUM jarayonini avtomatik boshqaradi), `WAL writer`, `stats collector` va boshqalar.

Bu arxitektura keyingi darslarda (ayniqsa 16-23-boblarda, PostgreSQL ichki qurilishiga bag'ishlangan qismda) qayta-qayta murojaat qilinadigan asosdir.

### Asosiy tushunchalar — jadval, qator, ustun, sxema, baza

Relyatsion ma'lumotlar bazasi ierarxiyasi quyidagicha:

```
PostgreSQL server (bir nechta bazani boshqaradi)
└── Database (baza, masalan "dokon_bazasi")
    └── Schema (sxema, masalan "public" — standart sxema)
        └── Table (jadval, masalan "mijozlar")
            └── Column (ustun, masalan "ism", "email")
            └── Row (qator — jadvaldagi bitta yozuv)
```

- **Baza (database)** — bir-biridan **to'liq izolyatsiya qilingan** ma'lumotlar to'plami. Bitta PostgreSQL serverida bir nechta baza bo'lishi mumkin, lekin bitta ulanish (connection) faqat bitta bazaga ishora qiladi — bazalar orasida to'g'ridan-to'g'ri `JOIN` qilib bo'lmaydi.
- **Sxema (schema)** — baza ichidagi mantiqiy "papka" — jadvallar, funksiyalar va boshqa obyektlarni guruhlashga xizmat qiladi. Har bir yangi bazada standart holatda **`public`** nomli sxema mavjud bo'ladi — bu darslikda, boshqacha ko'rsatilmaguncha, barcha jadvallar shu sxemada yaratiladi.
- **Jadval (table)** — ma'lumotlarning asosiy saqlanish birligi, qatorlar va ustunlardan iborat.
- **Ustun (column)** — jadvaldagi bitta "maydon", aniq ma'lumot turiga ega (masalan `integer`, `text`, `date`).
- **Qator (row / tuple / record)** — jadvaldagi bitta yozuv, har bir ustun uchun bitta qiymatga ega.

### Ushbu darslikda ishlatiladigan namuna baza

Butun darslik davomida (ayniqsa amaliy, 1-15-boblarda) bitta izchil, "do'kon" (savdo) mavzusidagi namuna baza ishlatiladi — bu real loyihalarga yaqin, tanish kontekst orqali har bir SQL buyrug'ini ma'noli misolda ko'rish imkonini beradi:

- **`bolimlar`** — kompaniya bo'limlari
- **`xodimlar`** — kompaniya xodimlari (bo'limga va boshlig'iga bog'langan)
- **`mijozlar`** — do'kon mijozlari
- **`mahsulotlar`** — sotiladigan mahsulotlar
- **`buyurtmalar`** — mijozlar tomonidan berilgan buyurtmalar
- **`buyurtma_elementlari`** — har bir buyurtmadagi aniq mahsulotlar va ularning soni

Bu jadvallar keyingi darslarda bosqichma-bosqich `CREATE TABLE` bilan quriladi (6-bobda) — hozircha faqat ularning **nima uchun** kerakligini va bir-biriga qanday bog'lanishini tasavvur qilib turing.

## Amaliy misol

PostgreSQL o'rnatilganini tekshirish va versiyasini ko'rish (keyingi darsda o'rnatishni batafsil ko'ramiz, bu yerda faqat natijaning qanday ko'rinishini tasavvur qilib turing):

```sql
SELECT version();
```

Natija (taxminan):

```
                                                  version
------------------------------------------------------------------------------------------------------
 PostgreSQL 18.0 on x86_64-pc-linux-gnu, compiled by gcc (Ubuntu 13.2.0-4ubuntu3) 13.2.0, 64-bit
(1 row)
```

Joriy ulangan bazani va foydalanuvchini ko'rish:

```sql
SELECT current_database(), current_user;
```

```
 current_database | current_user
-------------------+---------------
 dokon_bazasi      | postgres
(1 row)
```

## Keng tarqalgan xatolar

**Xato 1:** PostgreSQL'ni MySQL bilan aynan bir xil deb o'ylash, sintaksis va xatti-harakatlarda farq yo'q deb taxmin qilish.
❌ Masalan, MySQL'da satrlarni solishtirishda katta-kichik harf sezilmasligi mumkin (collation'ga qarab), PostgreSQL'da esa standart holatda **katta-kichik harf sezgir** (`'Ali' != 'ali'`).
✅ To'g'ri: PostgreSQL'ning o'z SQL standartiga yaqinroq, qat'iyroq xatti-harakatini alohida o'rganish kerak — bu darslik aynan shunga bag'ishlangan.

**Xato 2:** "Baza" (database) va "sxema" (schema) tushunchalarini aralashtirib yuborish.
❌ Ko'p boshqa DBMS'larda (masalan MySQL'da) "database" va "schema" amalda sinonim, lekin PostgreSQL'da bu ikkisi **butunlay boshqa** narsa — baza izolyatsiyalangan konteyner, sxema esa baza **ichidagi** mantiqiy guruhlash.
✅ To'g'ri: PostgreSQL'da bitta bazada bir nechta sxema bo'lishi mumkin (masalan `sotuv`, `bухgalteriya`), va ular orasida `JOIN` qilish mumkin — lekin turli **bazalar** orasida bunday emas.

**Xato 3:** PostgreSQL — faqat "yana bitta SQL bazasi" deb, uning kengaytiriluvchanligini (extensions, maxsus turlar, PL/pgSQL) e'tiborsiz qoldirish.
❌ Faqat asosiy `SELECT`/`INSERT`/`UPDATE` bilan cheklanib, PostgreSQL'ning JSON, window functions, CTE, trigger kabi kuchli imkoniyatlaridan foydalanmaslik.
✅ To'g'ri: bu darslik aynan shu "sodda SQL"dan tortib, PostgreSQL'ning eng chuqur ichki mexanizmlarigacha bo'lgan yo'lni bosib o'tishga mo'ljallangan — sabr bilan davom eting.

## Mashq/topshiriq

**(Oson)** PostgreSQL rasmiy veb-saytida (`postgresql.org`) joriy barqaror versiya raqamini toping va uni yozib qo'ying.

**(O'rtacha)** Relyatsion ma'lumotlar bazasi ierarxiyasini (server → baza → sxema → jadval → ustun/qator) o'z so'zlaringiz bilan, real hayotdan misol keltirib (masalan, kutubxona yoki universitet tizimi) tushuntirib bering.

**(Qiyin)** PostgreSQL va SQLite'ning arxitektura jihatidan asosiy farqini (klient-server vs in-process) tushuntiring va qaysi turdagi loyiha uchun qaysi biri ko'proq mos kelishini (kamida ikkita real misol bilan) asoslang.

<details>
<summary>Javoblarni ko'rish</summary>

1. Darslik yozilgan vaqtda bu **PostgreSQL 18** (18.x patch relizlari bilan) — lekin siz o'qiyotgan vaqtda yangiroq versiya chiqqan bo'lishi mumkin, shuning uchun buni doimo yangilab turish foydali odat.

2. Masalan, universitet tizimi: **server** — universitetning ma'lumotlar markazi; **baza** — "universitet_bazasi" (butun tizim uchun bitta izolyatsiyalangan konteyner); **sxema** — ichida "talabalar_bolimi", "kutubxona", "bухgalteriya" kabi mantiqiy guruhlar; **jadval** — "talabalar_bolimi" sxemasidagi "talabalar" jadvali; **ustun** — "ism", "fakultet", "kurs"; **qator** — bitta aniq talabaning yozuvi (masalan, "Aliyev Vali, Kompyuter fanlari, 2-kurs").

3. SQLite — **in-process** kutubxona: ma'lumotlar bazasi bitta oddiy fayl, dastur bevosita shu faylni o'qiydi/yozadi, alohida server jarayoni yo'q — bu uni mobil ilovalar (masalan, telefon ilovasining lokal keshi), kichik ish stoli dasturlari yoki testlash uchun ideal qiladi, chunki o'rnatish va boshqaruv deyarli talab qilinmaydi. PostgreSQL esa **klient-server**: alohida, doimiy ishlab turadigan server jarayoni bor, ko'plab klientlar (turli kompyuterlardan, hatto turli davlatlardan) bir vaqtning o'zida ulanishi, murakkab huquqlar tizimi va yuqori concurrency (bir vaqtda yuzlab foydalanuvchi yozishi) bilan ishlashi mumkin — bu uni veb-ilovalar backend'i, korporativ tizimlar yoki katta hajmli tahliliy tizimlar uchun mos qiladi. Masalan: mobil "eslatmalar" ilovasi — SQLite; onlayn-do'kon backend'i, bir vaqtda minglab foydalanuvchi bilan — PostgreSQL.

## Qisqacha xulosa

PostgreSQL — 1986-yildan buyon rivojlanib kelayotgan, ochiq manbali, klient-server arxitekturasiga ega, kuchli kengaytiriluvchanlikka (extensions, maxsus turlar, PL/pgSQL) ega obyekt-relyatsion ma'lumotlar bazasi bo'lib, ma'lumotlar server → baza → sxema → jadval → ustun/qator ierarxiyasida tashkil etiladi; har bir klient ulanishi serverda alohida, mustaqil OS jarayoni orqali xizmat ko'rsatiladi — bu arxitektura tushunchasi darslikning keyingi, ayniqsa ichki qurilishga bag'ishlangan bo'limlarida muntazam qayta ko'rib chiqiladi. Keyingi darsda PostgreSQL'ni real kompyuterga o'rnatish va `psql` buyruq qatori mijozi bilan ishlashni boshlaymiz.
