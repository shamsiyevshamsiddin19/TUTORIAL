# 15.2. Zaxira nusxa — `pg_dump` va `pg_restore`

## Bu darsda nimalarni o'rganasiz

- `pg_dump` bilan butun bazaning yoki bitta jadvalning zaxira nusxasini olishni o'rganasiz
- `pg_dump`ning turli formatlarini (`plain`, `custom`) va ular orasidagi farqni bilasiz
- `pg_restore` bilan zaxira nusxadan ma'lumotlarni tiklashni o'rganasiz
- `pg_dumpall`ning rollar va boshqa "global" ob'ektlarni zaxiralashdagi o'rnini tushunasiz
- Zaxira nusxalash strategiyasi bo'yicha amaliy tavsiyalarni bilasiz

## Nazariy qism

### Nega zaxira nusxa kerak

13-bobda ACID'ning "D" harfi — Durability (chidamlilik) — `COMMIT` qilingan ma'lumot server yiqilib tushsa ham yo'qolmasligini kafolatlaydi. Lekin bu — **apparat nosozligidan** himoya qiladi, **inson xatosidan** emas: agar kimdir ataylab yoki bilmasdan `DELETE FROM xodimlar;` (WHERE'siz — 7.3-darsda ko'rgan xato!) yozib yuborsa, WAL mexanizmi bu o'zgarishni ham "ishonchli" ravishda saqlab qoladi — chunki bu, texnik nuqtai nazardan, to'g'ri bajarilgan `COMMIT`. Bunday holatlardan himoyalanishning yagona yo'li — **muntazam zaxira nusxa** (backup).

### `pg_dump` — bitta bazaning zaxira nusxasi

```bash
pg_dump -d dokon_bazasi -F c -f dokon_bazasi_backup.dump
```

Bu buyruq — `dokon_bazasi` bazasining **to'liq** nusxasini (barcha jadvallar, ma'lumotlar, indekslar, cheklovlar, view'lar, funksiyalar, triggerlar) `dokon_bazasi_backup.dump` fayliga yozadi. `pg_dump` — **bitta baza** darajasida ishlaydi (butun serverni emas — buning uchun quyida ko'rilgan `pg_dumpall` kerak).

### `pg_dump` formatlari — `plain` vs `custom`

`-F` bayrog'i — chiqish formatini belgilaydi:

| Format | Bayroq | Xususiyati |
|---|---|---|
| **plain** (matn) | `-F p` (standart) | Oddiy `.sql` fayli — o'qilishi mumkin, `psql` bilan to'g'ridan-to'g'ri bajariladi |
| **custom** (ixcham) | `-F c` | Ikkilik, siqilgan format — faqat `pg_restore` bilan ochiladi, lekin ancha moslashuvchan |

`plain` formatning ko'rinishi (masalan, bitta jadval uchun):

```bash
pg_dump -d dokon_bazasi --table=mahsulotlar -F p
```

```sql
--
-- PostgreSQL database dump
--

SET statement_timeout = 0;
SET lock_timeout = 0;
...
CREATE TABLE public.mahsulotlar (
    id integer NOT NULL,
    ...
```

Bu — inson o'qiy oladigan, oddiy SQL buyruqlari to'plami: `psql -d yangi_baza -f dump.sql` bilan to'g'ridan-to'g'ri bajarilishi mumkin.

`custom` format esa ikkilik va siqilgan — uni to'g'ridan-to'g'ri o'qib bo'lmaydi, lekin uning katta afzalligi bor: `pg_restore` bilan tiklashda, **tanlab** (masalan, faqat ma'lum jadvallarni, yoki faqat ma'lumotni sxemasiz) tiklash mumkin, va u odatda ancha kichikroq fayl hosil qiladi (siqilgani uchun). Amaliyotda, ayniqsa katta bazalar uchun, `custom` format ko'proq tavsiya etiladi.

### `pg_restore` — `custom` formatdan tiklash

```bash
createdb dokon_bazasi_tiklangan
pg_restore -d dokon_bazasi_tiklangan dokon_bazasi_backup.dump
```

Avval **bo'sh** baza yaratiladi (`pg_restore` o'zi baza yaratmaydi — u faqat mavjud, bo'sh bazaga ma'lumot "quyadi"), so'ng `pg_restore` dump faylidagi barcha buyruqlarni shu bazada bajaradi. Tekshirib ko'ramiz:

```sql
SELECT count(*) FROM mahsulotlar;
```

```
 count 
-------
    10
```

```
\dt
```

```
                List of relations
 Schema |         Name         | Type  |  Owner   
--------+-----------------------+-------+----------
 public | bolimlar             | table | postgres
 public | buyurtma_elementlari | table | postgres
 public | buyurtmalar          | table | postgres
 public | mahsulotlar          | table | postgres
 public | mijozlar             | table | postgres
 public | xodimlar             | table | postgres
```

Barcha 6 ta jadval, to'liq ma'lumot bilan (`mahsulotlar`da aynan 10 qator — asl bazadagi bilan bir xil) muvaffaqiyatli tiklandi.

### `pg_dumpall` — rollar va boshqa "global" ob'ektlar

15.1-darsda yaratgan rollarimiz (`faqat_oquvchi`, `sotuv_xodimi`, `xodimlar_guruhi`) — bularning muhim xususiyati bor: ular **bitta bazaga tegishli emas**, balki butun PostgreSQL **serveriga** tegishli (bir nechta baza ularni baham ko'rishi mumkin). Shuning uchun oddiy `pg_dump` ularni **umuman saqlamaydi**. Rollarni zaxiralash uchun alohida vosita kerak:

```bash
pg_dumpall --roles-only
```

```sql
CREATE ROLE faqat_oquvchi;
ALTER ROLE faqat_oquvchi WITH NOSUPERUSER INHERIT NOCREATEROLE NOCREATEDB LOGIN NOREPLICATION NOBYPASSRLS PASSWORD 'SCRAM-SHA-256$...';
CREATE ROLE sotuv_xodimi;
ALTER ROLE sotuv_xodimi WITH NOSUPERUSER INHERIT NOCREATEROLE NOCREATEDB LOGIN NOREPLICATION NOBYPASSRLS PASSWORD 'SCRAM-SHA-256$...';
CREATE ROLE xodimlar_guruhi;
ALTER ROLE xodimlar_guruhi WITH NOSUPERUSER INHERIT NOCREATEROLE NOCREATEDB NOLOGIN NOREPLICATION NOBYPASSRLS;
GRANT xodimlar_guruhi TO sotuv_xodimi WITH INHERIT TRUE GRANTED BY postgres;
```

Diqqat qiling — parollar ochiq matnda emas, balki **shifrlangan** (`SCRAM-SHA-256$...`) holda saqlanadi, va oxirgi qatorda 15.1-darsda o'rnatgan rol a'zoligi (`GRANT xodimlar_guruhi TO sotuv_xodimi`) ham to'liq qayta tiklanadigan holda mavjud.

`pg_dumpall` (`--roles-only`siz) — butun serverdagi **barcha** bazalarni, bittalab, ketma-ket zaxiralaydi (bitta katta `plain` SQL fayl sifatida). Amalda, ko'pincha eng maqbul strategiya — `pg_dumpall --globals-only` (yoki `--roles-only`) bilan faqat rollarni, so'ng har bir baza uchun alohida `pg_dump -F c` bilan to'liq, moslashuvchan zaxira olish.

### Amaliy zaxira nusxalash strategiyasi

| Vaziyat | Tavsiya |
|---|---|
| Kichik-o'rta hajmdagi baza, kunlik zaxira | `pg_dump -F c` — moslashuvchan, kichik hajmli |
| Rollarni ham saqlash kerak | Qo'shimcha `pg_dumpall --roles-only` |
| Faqat bitta jadvalni tiklash kerak bo'ladigan holat | `pg_dump -F c` bilan zaxiralab, `pg_restore --table=jadval_nomi` bilan tanlab tiklash |
| Juda katta baza, doimiy o'zgarib turadigan | Fayl darajasidagi zaxira (`pg_basebackup`) + WAL arxivlash — bu 20-bobda chuqurroq o'rganiladi |
| Zaxirani qanchalik tez-tez olish kerak | "Qancha ma'lumotni yo'qotishga chidasa bo'ladi" savoliga bog'liq — kunlik/soatlik/WAL-asosida uzluksiz |

> **Oltin qoida:** zaxira nusxa — uni **tiklab ko'rmaguningizcha**, ishonchli emas. Muntazam ravishda (masalan, oyda bir marta) zaxiradan haqiqatan **tiklab**, natijani tekshirib turish — ko'pchilik real avariyalarda "zaxira bor edi, lekin u buzuq/eskirgan/ishlamaydigan bo'lib chiqdi" degan holatlarning oldini oladi.

## Amaliy misol

**Vazifa:** Faqat `mahsulotlar` jadvalining zaxira nusxasini olish va uni alohida, yangi jadval nomiga tiklash.

```bash
pg_dump -d dokon_bazasi --table=mahsulotlar -F c -f mahsulotlar_backup.dump
```

Bu fayl endi faqat `mahsulotlar` jadvalining strukturasi va ma'lumotlarini o'z ichiga oladi — butun bazani emas. Uni istalgan (bo'sh yoki mavjud) bazaga `pg_restore -d nishon_baza mahsulotlar_backup.dump` bilan tiklash mumkin.

## Keng tarqalgan xatolar

**Xato 1:** Faqat `pg_dump`ni ishlatib, rollarni (`pg_dumpall --roles-only`) unutish.
❌ Bazani tiklaganda, `GRANT`lar berilgan rollar mavjud bo'lmasa, ular bilan bog'liq huquqlar to'g'ri tiklanmaydi (yoki xato beradi).
✅ Har doim rollarni alohida, `pg_dumpall --roles-only` bilan ham zaxiralang.

**Xato 2:** `plain` formatdagi zaxirani `pg_restore` bilan ochishga urinish (yoki aksincha).
❌ `pg_restore` faqat `custom`/`directory`/`tar` formatlarni tushunadi, `plain` (`.sql`) fayllarni emas.
✅ `plain` format uchun — `psql -f fayl.sql`; `custom` format uchun — `pg_restore`.

**Xato 3:** Zaxirani faqat olib, hech qachon tiklab ko'rmaslik.
❌ Zaxira fayli buzilgan, to'liqsiz yoki eskirgan bo'lishi mumkin — buni faqat urinib ko'rgandagina bilib olasiz, va bu odatda haqiqiy avariya paytida, eng noqulay vaqtda ma'lum bo'ladi.
✅ Zaxira nusxalarni muntazam, real sharoitda (masalan, alohida test bazasiga) tiklab tekshirib turing.

## Mashq/topshiriq

**(Oson)** `mijozlar` jadvalining `plain` formatdagi (`-F p`) zaxira nusxasini oling va uning tarkibidagi birinchi 20 qatorini ko'rib chiqing.

**(O'rtacha)** `dokon_bazasi`ning to'liq `custom` formatdagi zaxira nusxasini oling, so'ng uni yangi, bo'sh `sinov_bazasi` nomli bazaga tiklang va barcha 6 ta jadval to'g'ri tiklanganini `\dt` bilan tasdiqlang.

**(Qiyin)** `pg_dumpall --roles-only` bilan barcha rollarni zaxiralang, so'ng shu fayldagi buyruqlarni o'qib, agar siz bu serverni "noldan" tiklamoqchi bo'lsangiz, qaysi tartibda (avval rollar, keyin bazami, yoki aksinchami) ishlarni bajarishingiz kerakligini tushuntirib bering.

## Qisqacha xulosa

`pg_dump` — bitta bazaning to'liq yoki qisman (bitta jadval) zaxira nusxasini oladi; `plain` format inson o'qiy oladigan SQL, `custom` format esa ixcham va moslashuvchan tiklash imkonini beradi. `pg_restore` — `custom` formatdagi zaxiradan ma'lumotni tiklaydi (bo'sh, oldindan yaratilgan bazaga). `pg_dumpall --roles-only` — rollar kabi, bazaga emas, butun serverga tegishli ob'ektlarni alohida zaxiralaydi, va tiklashda **rollar birinchi, ma'lumotlar ikkinchi** tartibida tiklanishi kerak. Bu — 15-bobni yakunlaydi: rollar, `GRANT`/`REVOKE`, Row-Level Security va zaxira nusxalashni o'rgandingiz — bular birgalikda ma'lumotlar bazasi xavfsizligi va ishonchliligining asosini tashkil qiladi. Bu — darslikning **amaliy** qismini yakunlaydi. Keyingi, 16-bobdan boshlab, biz PostgreSQL'ning **ichki arxitekturasiga** — xotira va saqlash tuzilmasi, MVCC, indekslash ichki mexanizmi, query planner va boshqa "ich-ichiga" mavzularga — chuqur kirib boramiz.
