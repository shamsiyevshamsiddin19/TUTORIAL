# 8.1. Cheklovlar asoslari — `NOT NULL`, `UNIQUE`, `DEFAULT`

## Bu darsda nimalarni o'rganasiz

- Cheklov (constraint) nima ekanini — ma'lumotlar bazasining o'zi ma'lumot yaxlitligini qanday himoya qilishini — tushunasiz
- `NOT NULL` bilan ustunni majburiy qilishni bilasiz
- `UNIQUE` bilan takrorlanmas qiymatlarni ta'minlashni, va u bir nechta ustunga birgalikda qanday qo'llanilishini bilasiz
- `DEFAULT` bilan standart qiymat belgilashni mustahkamlaysiz
- Nomlangan cheklovlar (`CONSTRAINT nom ...`) qanday va nima uchun foydali ekanini bilasiz

## Nazariy qism

### Cheklov (constraint) nima uchun kerak

Hozirgacha biz ma'lumotlar to'g'riligini asosan **ilova darajasida** (yoki o'zimiz diqqat bilan yozgan `INSERT`/`UPDATE` orqali) nazorat qilib keldik. Lekin haqiqiy loyihalarda ma'lumotlar bazasiga bir nechta turli ilova, skript, yoki hattoki qo'lda ishlaydigan administrator murojaat qilishi mumkin — va agar yaxlitlik qoidalari faqat ilova kodida bo'lsa, ulardan birortasi xato qilib, buzuq ma'lumot kiritib qo'yishi mumkin. **Cheklov (constraint)** — bu muammoni tubdan hal qiladi: qoida ma'lumotlar bazasining **o'zida** e'lon qilinadi, va PostgreSQL uni **har doim**, qaysi mijoz yoki qanday yo'l bilan yozilishidan qat'i nazar, avtomatik tekshiradi. Bu — "ma'lumotlar yaxlitligi bazaning mas'uliyati, ilovaning emas" degan muhim arxitektura tamoyili.

### `NOT NULL` — ustunni majburiy qilish

6.1-darsda ko'rgan `NOT NULL`ni endi rasman cheklov sifatida ko'rib chiqamiz:

```sql
CREATE TABLE test_constraints (
    id SERIAL PRIMARY KEY,
    ism TEXT NOT NULL,
    email TEXT UNIQUE,
    yosh INTEGER DEFAULT 18
);
```

Agar `NOT NULL` ustuniga `NULL` qiymat kiritishga urinilsa:

```sql
INSERT INTO test_constraints (ism, email) VALUES (NULL, 'a@test.com');
```

```
ERROR:  null value in column "ism" of relation "test_constraints" violates not-null constraint
DETAIL:  Failing row contains (1, null, a@test.com, 18).
```

PostgreSQL bu `INSERT`ni **butunlay rad etadi** — hech qanday qator kiritilmaydi. Diqqat qiling: xato xabari juda aniq va foydali — u qaysi ustun (`ism`), qaysi cheklov turi (`not-null constraint`), va hattoki **butun qatorning** qanday ko'rinishda bo'lishi kerak edi (`DETAIL`) haqida to'liq ma'lumot beradi.

### `UNIQUE` — takrorlanmaslikni ta'minlash

`UNIQUE` cheklovi ustunda (yoki ustunlar kombinatsiyasida) **hech qachon ikkita bir xil qiymat bo'lmasligini** kafolatlaydi (`NULL` bundan mustasno — pastda alohida tushuntiramiz):

```sql
INSERT INTO test_constraints (ism, email) VALUES ('Ali', 'dup@test.com');
INSERT INTO test_constraints (ism, email) VALUES ('Vali', 'dup@test.com');
```

```
INSERT 0 1
ERROR:  duplicate key value violates unique constraint "test_constraints_email_key"
DETAIL:  Key (email)=(dup@test.com) already exists.
```

Birinchi `INSERT` muvaffaqiyatli o'tdi, ikkinchisi esa — xuddi shu email allaqachon mavjudligi sababli — rad etildi. Bu — masalan, foydalanuvchi ro'yxatdan o'tish tizimida "bir xil email bilan ikki marta ro'yxatdan o'tib bo'lmasligi"ni ta'minlashning eng ishonchli usuli (ilova darajasidagi tekshiruv — masalan, "avval SELECT bilan email borligini tekshirish, keyin INSERT qilish" — parallel so'rovlar sababli **ishonchsiz**: ikkita foydalanuvchi bir vaqtda ro'yxatdan o'tishga urinsa, ikkalasi ham "email band emas" natijasini olib, ikkalasi ham muvaffaqiyatli `INSERT` qilib yuborishi mumkin — bu "race condition" deb ataladi, 13-bobda chuqurroq o'rganamiz; database darajasidagi `UNIQUE` cheklovi esa bunday holatni **kafolatlangan** tarzda oldini oladi).

### Bir nechta ustunga birgalikda `UNIQUE` — kompozit cheklov

Ba'zan takrorlanmaslik bitta ustunda emas, balki ustunlar **kombinatsiyasida** talab qilinadi — masalan, "bitta buyurtmada bitta mahsulot faqat bir marta uchrashi mumkin" (agar bir xil mahsulotdan ko'proq kerak bo'lsa, `soni` ustuni oshiriladi, yangi qator qo'shilmaydi):

```sql
ALTER TABLE buyurtma_elementlari
ADD CONSTRAINT unique_buyurtma_mahsulot UNIQUE (buyurtma_id, mahsulot_id);
```

Bu — `(buyurtma_id, mahsulot_id)` **juftligi** hech qachon takrorlanmasligini ta'minlaydi, garchi har bir ustunning o'zi alohida (masalan, bitta `mahsulot_id` ko'plab turli buyurtmada) ko'p marta uchrashi mumkin bo'lsa ham.

### `UNIQUE` va `NULL` — muhim nozik nuqta

2.3-darsda o'rgangan `NULL`ning "noma'lum qiymat" tabiati bu yerda ham namoyon bo'ladi: **`UNIQUE` cheklovi `NULL` qiymatlarni bir-biriga teng deb hisoblamaydi**, shuning uchun `UNIQUE` ustunida bir nechta `NULL` qiymatli qator bo'lishi **mumkin**:

```sql
CREATE TABLE test_unique_null (id SERIAL PRIMARY KEY, kod TEXT UNIQUE);
INSERT INTO test_unique_null (kod) VALUES (NULL);
INSERT INTO test_unique_null (kod) VALUES (NULL);  -- bu ham MUVAFFAQIYATLI o'tadi!
```

Bu — mantiqan izchil: agar `NULL` "noma'lum" degani bo'lsa, ikkita "noma'lum" qiymatning bir-biriga **teng** ekanini tasdiqlash mumkin emas, shuning uchun PostgreSQL ularni "to'qnashuv" deb hisoblamaydi. Agar sizga `NULL`larni ham cheklash kerak bo'lsa (masalan, faqat bitta `NULL` qiymatli qatorga ruxsat berish), bu maxsus, murakkabroq yechim (masalan, qisman indeks — 18-bobda) talab qiladi.

### `DEFAULT` — standart qiymat (6.1-darsdan mustahkamlash)

```sql
SELECT * FROM test_constraints;
```

```
 id | ism |    email     | yosh 
----+-----+--------------+------
  2 | Ali | dup@test.com |   18
```

`yosh` ustuniga qiymat berilmagani uchun, u avtomatik ravishda `DEFAULT 18`dan olingan `18` qiymati bilan to'ldirildi. `DEFAULT` — texnik jihatdan "cheklov" (constraint) emas, balki alohida xususiyat, lekin u ko'pincha boshqa cheklovlar (masalan, `NOT NULL`) bilan birga ishlatiladi — masalan, "ustun majburiy, lekin agar ko'rsatilmasa, oqilona standart qiymat qo'yiladi" degan naqsh juda keng tarqalgan.

### Nomlangan cheklovlar — nima uchun foydali

Yuqoridagi `UNIQUE (buyurtma_id, mahsulot_id)` misolida biz cheklovga aniq nom (`unique_buyurtma_mahsulot`) berdik. Agar nom berilmasa, PostgreSQL avtomatik nom generatsiya qiladi (masalan, `test_constraints_email_key`, yuqoridagi xato xabarida ko'rganimizdek — bu `<jadval>_<ustun>_key` andozasi bo'yicha avtomatik yaratiladi). Aniq nom berishning afzalligi: (1) xato xabarlarida tushunarli, ma'noli nom ko'rinadi (`unique_buyurtma_mahsulot` avtomatik generatsiya qilingan `buyurtma_elementlari_buyurtma_id_mahsulot_id_key`dan o'qilishi osonroq); (2) kelajakda cheklovni `ALTER TABLE ... DROP CONSTRAINT nom` bilan olib tashlash yoki o'zgartirish osonroq bo'ladi.

```sql
CREATE TABLE misol (
    id SERIAL PRIMARY KEY,
    kod TEXT,
    CONSTRAINT kod_unique UNIQUE (kod)
);
```

## Amaliy misol

**Vazifa:** `mahsulotlar` jadvaliga, har bir mahsulot uchun noyob "shtrix-kod" (`shtrix_kod`) ustuni qo'shing — u majburiy va takrorlanmas bo'lishi kerak, lekin mavjud mahsulotlar uchun hozircha standart qiymat sifatida `NULL`ga ruxsat berilsin (keyinroq to'ldiriladi deb faraz qilamiz — shuning uchun bu misolda `NOT NULL`ni **darhol** qo'ymaymiz, avval ustun qo'shib, ma'lumot to'ldirilgach cheklov qo'shish real hayotdagi ko'proq uchraydigan yondashuv).

```sql
ALTER TABLE mahsulotlar ADD COLUMN shtrix_kod VARCHAR(20);
ALTER TABLE mahsulotlar ADD CONSTRAINT shtrix_kod_unique UNIQUE (shtrix_kod);
```

## Keng tarqalgan xatolar

**Xato 1:** `UNIQUE`ning `NULL`larga nisbatan "istisno" xatti-harakatini bilmasdan, "nega bir nechta `NULL` qiymat o'tib ketdi" deb hayron bo'lish.
✅ Bu — standart va kutilgan SQL xatti-harakati; agar `NULL`larni ham cheklash kerak bo'lsa, maxsus yechim (qisman indeks) kerak.

**Xato 2:** Har bir cheklov uchun avtomatik generatsiya qilingan nomga tayanib, keyinchalik uni `ALTER TABLE ... DROP CONSTRAINT`da noto'g'ri taxmin qilish.
✅ Muhim cheklovlar uchun har doim aniq, ma'noli nom bering.

**Xato 3:** `NOT NULL`ni mavjud ma'lumotli jadvalga to'g'ridan-to'g'ri qo'shishga urinib, mavjud `NULL` qiymatlar tufayli xatoga duch kelish (6.3-darsda ko'rganimizdek).
✅ Avval mavjud `NULL`larni to'ldiring, keyin cheklovni qo'shing.

## Mashq/topshiriq

**(Oson)** `bolimlar` jadvalidagi `nomi` ustuniga `UNIQUE` cheklovini (agar hali yo'q bo'lsa) qo'shing, so'ng takrorlanuvchi nom bilan yangi bo'lim qo'shishga urinib, xato xabarini kuzating.

**(O'rtacha)** Yangi `mijoz_murojaatlari` jadvalini yarating: `id` (avtomatik), `mijoz_id` (majburiy), `mavzu` (majburiy matn), `holati` (standart qiymati `'yangi'` bo'lgan matn). Bo'sh `mavzu` bilan qator kiritishga urinib, `NOT NULL` xatosini ko'ring.

**(Qiyin)** `buyurtma_elementlari` jadvaliga `(buyurtma_id, mahsulot_id)` juftligi bo'yicha `UNIQUE` cheklovini qo'shishga urinib ko'ring — agar xato chiqsa (chunki bizning mavjud ma'lumotlarimizda haqiqatan takrorlanish yo'q, xato chiqmasligi kerak), muvaffaqiyatli qo'shilganini tasdiqlang, so'ng takroriy `(buyurtma_id, mahsulot_id)` juftligi bilan yangi qator kiritishga urinib, `UNIQUE` xatosini his qiling (keyin tozalash uchun `ROLLBACK` qiling).

## Qisqacha xulosa

Cheklovlar (constraints) — ma'lumotlar yaxlitligini ilova kodiga emas, bazaning o'ziga ishonib topshirishning asosiy vositasi. `NOT NULL` ustunni majburiy qiladi, `UNIQUE` takrorlanmaslikni (bir yoki bir nechta ustun bo'yicha) kafolatlaydi — lekin `NULL` qiymatlarga nisbatan alohida, "hech-narsaga-teng-emas" mantiqqa amal qiladi. `DEFAULT` esa qiymat ko'rsatilmaganda qo'llaniladigan standart qiymatni belgilaydi. Nomlangan cheklovlar xato xabarlarini tushunarli qiladi va kelajakda boshqarishni osonlashtiradi. Keyingi darsda eng muhim ikkita cheklov turini — `PRIMARY KEY` va `CHECK`ni — chuqur o'rganamiz.
