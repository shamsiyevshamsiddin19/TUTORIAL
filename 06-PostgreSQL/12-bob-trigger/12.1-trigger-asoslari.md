# 12.1. Trigger asoslari — `CREATE TRIGGER`, `NEW`/`OLD`, `BEFORE`/`AFTER`

## Bu darsda nimalarni o'rganasiz

- Trigger nima ekanini va u qanday muammoni yechishini tushunasiz
- Trigger funksiyasi (`RETURNS TRIGGER`) va oddiy funksiya (10-bob) orasidagi farqni bilasiz
- `NEW` va `OLD` maxsus o'zgaruvchilarini ishlatishni o'rganasiz
- `BEFORE` va `AFTER` triggerlar orasidagi farqni va qachon qaysi birini tanlashni bilasiz
- `FOR EACH ROW` va `FOR EACH STATEMENT` orasidagi farqni ko'rasiz
- `TG_OP` yordamida bitta trigger funksiyasida bir nechta amalni (INSERT/UPDATE/DELETE) boshqarishni o'rganasiz

## Nazariy qism

### Trigger nima va u nima uchun kerak

10-bobda `CREATE FUNCTION` bilan o'zingizning mantig'ingizni bazaga "joylashtirish"ni o'rgandik — lekin bu funksiyalarni chaqirish uchun kimdir ularni **qo'lda**, `SELECT funksiya_nomi(...)` orqali chaqirishi kerak edi. **Trigger** — bu muammoni yechadi: u jadvalda muayyan voqea (`INSERT`, `UPDATE` yoki `DELETE`) yuz berganda, funksiyani **avtomatik**, hech kim chaqirmasa ham ishga tushiradi.

Bu — quyidagi kabi vazifalar uchun juda foydali:

- Har safar qator o'zgartirilganda, "oxirgi yangilangan vaqt" ustunini avtomatik yangilash
- Muhim ma'lumotlar o'zgarganda, buni alohida "audit" (kuzatuv) jadvaliga avtomatik yozib borish
- Ma'lum shartlar bajarilmasa, o'zgartirish yoki o'chirishni bloklash
- Bir jadvaldagi o'zgarish boshqa jadvaldagi hisoblangan (denormallashtirilgan) qiymatni avtomatik yangilashi kerak bo'lganda (masalan, sotuv bo'lganda ombordagi mahsulot sonini kamaytirish)

### Trigger funksiyasi — `RETURNS TRIGGER`

Oddiy funksiyalardan farqli o'laroq, trigger funksiyasi **maxsus** `TRIGGER` turini qaytaradi va **hech qanday parametr qabul qilmaydi** (barcha kerakli ma'lumot maxsus o'zgaruvchilar orqali avtomatik beriladi):

```sql
CREATE OR REPLACE FUNCTION set_yangilangan_vaqti() RETURNS TRIGGER AS $$
BEGIN
    NEW.yangilangan_vaqti = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

Bu yerdagi eng muhim yangi tushuncha — `NEW`. Bu, PL/pgSQL trigger funksiyalari ichida avtomatik mavjud bo'ladigan, maxsus o'zgaruvchi.

### `NEW` va `OLD` — o'zgarayotgan qatorga murojaat

Trigger funksiyasi ichida ikkita maxsus "sohta qator" (pseudo-row) o'zgaruvchisi mavjud:

| O'zgaruvchi | `INSERT`da | `UPDATE`da | `DELETE`da |
|---|---|---|---|
| `NEW` | Qo'shilayotgan **yangi** qator | O'zgartirilgandan **keyingi** qator | Mavjud emas (`NULL`) |
| `OLD` | Mavjud emas (`NULL`) | O'zgartirilishdan **oldingi** qator | O'chirilayotgan qator |

`NEW.ustun_nomi = qiymat` — bu shunchaki oddiy o'zgaruvchiga qiymat berish emas, balki (agar `BEFORE` trigger bo'lsa) **haqiqatan bazaga yoziladigan qiymatni o'zgartiradi**. Yuqoridagi misolda `NEW.yangilangan_vaqti = NOW()` — bu "qatorni saqlashdan oldin, `yangilangan_vaqti` ustuniga joriy vaqtni majburan yoz" degani.

### Triggerni jadvalga bog'lash — `CREATE TRIGGER`

Funksiya o'zi hali hech narsaga ta'sir qilmaydi — uni **muayyan jadval va voqeaga** bog'lash kerak:

```sql
CREATE TABLE test_trigger_demo (
    id SERIAL PRIMARY KEY,
    nomi TEXT,
    yangilangan_vaqti TIMESTAMP
);

CREATE TRIGGER trg_yangilangan_vaqti
BEFORE UPDATE ON test_trigger_demo
FOR EACH ROW
EXECUTE FUNCTION set_yangilangan_vaqti();
```

Sinab ko'ramiz:

```sql
INSERT INTO test_trigger_demo (nomi) VALUES ('Birinchi yozuv');
SELECT * FROM test_trigger_demo;
```

```
 id |      nomi      | yangilangan_vaqti 
----+-----------------+-------------------
  1 | Birinchi yozuv |                   
```

`INSERT`dan keyin `yangilangan_vaqti` — `NULL` (trigger faqat `BEFORE UPDATE`ga bog'langan, `INSERT`ga emas). Endi qatorni yangilaymiz:

```sql
UPDATE test_trigger_demo SET nomi = 'Yangilangan yozuv' WHERE id = 1;
SELECT * FROM test_trigger_demo;
```

```
 id |       nomi        |     yangilangan_vaqti      
----+--------------------+----------------------------
  1 | Yangilangan yozuv | 2026-08-30 03:10:34.614229
```

`UPDATE` bajarilishi bilanoq, trigger avtomatik ishga tushdi va `yangilangan_vaqti`ni joriy vaqt bilan to'ldirdi — buni hech kim qo'lda chaqirmadi.

### `BEFORE` va `AFTER` — qachon qaysi birini tanlash kerak

`CREATE TRIGGER`da `BEFORE UPDATE` yoki `AFTER UPDATE` deb belgilash — trigger **qachon** ishga tushishini aniqlaydi, va bu tanlov amaliy jihatdan juda muhim:

| | `BEFORE` | `AFTER` |
|---|---|---|
| **Qachon ishlaydi** | Qator bazaga yozilishidan **oldin** | Qator bazaga yozilgandan **keyin** |
| **`NEW`ni o'zgartirish** | Mumkin — va bu o'zgarish **haqiqatan saqlanadi** | Mumkin, lekin bazaga yozishga **ta'sir qilmaydi** (allaqachon kech) |
| **Tipik ishlatilishi** | Qiymatni avtomatik to'ldirish/tozalash, validatsiya, amalni bloklash (`RAISE EXCEPTION`) | Boshqa jadvalga audit yozuvi qo'shish, bildirishnoma yuborish, tashqi tizimga signal berish |
| **Qaytarish qiymati** | `NEW` (yoki `OLD` — `DELETE`da) qaytarilishi **shart**, aks holda amal bekor bo'ladi | Odatda `NULL` qaytariladi (natija baribir e'tiborga olinmaydi) |

Qoida shunday: agar maqsad — **saqlanadigan qiymatni o'zgartirish yoki amalni bloklash** bo'lsa, `BEFORE` kerak. Agar maqsad — **allaqachon sodir bo'lgan voqeaga reaksiya** (masalan, boshqa jadvalga yozish) bo'lsa, `AFTER` kerak.

### `FOR EACH ROW` va `FOR EACH STATEMENT`

`CREATE TRIGGER`da yana bir muhim tanlov — trigger **har bir qator uchun alohida** ishlaydimi, yoki **butun ifoda uchun bir marta**:

```sql
CREATE TRIGGER trg_statement_log
AFTER INSERT ON test_himoyalangan
FOR EACH STATEMENT
EXECUTE FUNCTION statement_trigger_log();
```

```sql
INSERT INTO test_himoyalangan (nomi) VALUES ('A'), ('B'), ('C');
SELECT * FROM test_statement_log;
```

```
 id |            xabar            |            vaqt            
----+------------------------------+----------------------------
  1 | Statement bajarildi: INSERT | 2026-08-30 03:11:06.440428
```

Diqqat qiling: bitta `INSERT` ifodasi bilan **3 ta** qator qo'shildi, lekin `FOR EACH STATEMENT` trigger jadvalda faqat **bitta** yozuv qoldirdi — chunki u har bir qator uchun emas, butun ifoda uchun bir marta ishga tushadi. `FOR EACH STATEMENT` triggerlarida `NEW`/`OLD` mavjud emas (chunki qaysi qator haqida gap ketayotgani noaniq) — u ko'proq "shunchaki nimadir sodir bo'ldi" turidagi umumiy bildirishnomalar uchun ishlatiladi. Amaliyotda **`FOR EACH ROW`** ancha ko'p ishlatiladi, chunki u aynan qaysi qator o'zgarganini bilishga imkon beradi.

### `TG_OP` — bitta funksiyada bir nechta amalni boshqarish

Trigger funksiyasi ichida yana bir muhim maxsus o'zgaruvchi — `TG_OP` (matn sifatida `'INSERT'`, `'UPDATE'` yoki `'DELETE'` qiymatini oladi). Bu — bitta trigger funksiyasini bir nechta voqeaga bog'lab, ular orasida farqlash imkonini beradi:

```sql
CREATE OR REPLACE FUNCTION test_trigger_demo_log() RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO test_op_log (amal) VALUES (TG_OP);
    IF TG_OP = 'DELETE' THEN
        RETURN OLD;
    ELSE
        RETURN NEW;
    END IF;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_op_log
AFTER INSERT OR UPDATE OR DELETE ON test_trigger_demo
FOR EACH ROW
EXECUTE FUNCTION test_trigger_demo_log();
```

```sql
INSERT INTO test_trigger_demo (nomi) VALUES ('Ikkinchi');
UPDATE test_trigger_demo SET nomi = 'Ikkinchi (2)' WHERE nomi = 'Ikkinchi';
DELETE FROM test_trigger_demo WHERE nomi = 'Ikkinchi (2)';
SELECT * FROM test_op_log;
```

```
 id |  amal  |            vaqt            
----+--------+----------------------------
  1 | INSERT | 2026-08-30 03:10:50.722552
  2 | UPDATE | 2026-08-30 03:10:50.723378
  3 | DELETE | 2026-08-30 03:10:50.724030
```

Bitta `AFTER INSERT OR UPDATE OR DELETE` trigger va bitta funksiya — uch xil voqeaning har birini to'g'ri kuzatib, log jadvaliga yozib bordi. `TG_OP`ning `DELETE` holatida `RETURN OLD` yozilishiga e'tibor bering — chunki `DELETE`da `NEW` mavjud emas (`NULL`), shuning uchun `RETURN NEW` yozilsa xato beradi.

### Triggerni o'chirish

```sql
DROP TRIGGER trg_yangilangan_vaqti ON test_trigger_demo;
```

Diqqat qiling — `DROP TRIGGER`da **qaysi jadvalga** bog'langanini (`ON jadval_nomi`) ko'rsatish shart, chunki trigger nomlari faqat o'z jadvali doirasida noyob (turli jadvallarda bir xil trigger nomi bo'lishi mumkin). Trigger funksiyasining o'zi (`DROP FUNCTION funksiya_nomi()`) alohida o'chiriladi — `DROP TRIGGER` faqat bog'lanishni olib tashlaydi, funksiyani emas.

## Amaliy misol

**Vazifa:** Muhim deb belgilangan yozuvlarni o'chirishni bloklovchi trigger yarating.

```sql
CREATE TABLE test_himoyalangan (
    id SERIAL PRIMARY KEY,
    nomi TEXT,
    muhim BOOLEAN DEFAULT FALSE
);

INSERT INTO test_himoyalangan (nomi, muhim) VALUES ('Oddiy yozuv', FALSE), ('Muhim yozuv', TRUE);

CREATE OR REPLACE FUNCTION ochirishni_taqiqlash() RETURNS TRIGGER AS $$
BEGIN
    IF OLD.muhim THEN
        RAISE EXCEPTION 'Muhim deb belgilangan yozuvni o''chirib bo''lmaydi (id=%)', OLD.id;
    END IF;
    RETURN OLD;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_ochirishni_taqiqlash
BEFORE DELETE ON test_himoyalangan
FOR EACH ROW
EXECUTE FUNCTION ochirishni_taqiqlash();
```

Oddiy yozuvni o'chirish muvaffaqiyatli bo'ladi:

```sql
DELETE FROM test_himoyalangan WHERE nomi = 'Oddiy yozuv';
```
```
DELETE 1
```

Lekin muhim yozuvni o'chirishga urinsak:

```sql
DELETE FROM test_himoyalangan WHERE nomi = 'Muhim yozuv';
```
```
ERROR:  Muhim deb belgilangan yozuvni o'chirib bo'lmaydi (id=2)
CONTEXT:  PL/pgSQL function ochirishni_taqiqlash() line 4 at RAISE
```

Bu — `RAISE EXCEPTION`ning kuchi: `BEFORE DELETE` trigger ichida xato tashlash orqali, amalni **butunlay bekor qilish** mumkin — xuddi 8.3-darsdagi `FOREIGN KEY ... ON DELETE`ning `NO ACTION` xatti-harakati kabi, lekin bu safar mantiq to'liq sizning nazoratingizda.

## Keng tarqalgan xatolar

**Xato 1:** `BEFORE` trigger ichida `NEW`ni o'zgartirib, lekin oxirida `RETURN NEW` yozishni unutish.
❌ Agar funksiya `RETURN NULL` (yoki hech narsa) qaytarsa, `BEFORE` triggerda butun amal **bekor bo'ladi** — qator umuman saqlanmaydi!
✅ `BEFORE INSERT`/`BEFORE UPDATE` triggerlarida deyarli har doim `RETURN NEW;` bilan yakunlang (agar amalni ataylab bloklamoqchi bo'lmasangiz).

**Xato 2:** `DELETE` trigerida `RETURN NEW` yozish.
❌ `DELETE`da `NEW` mavjud emas — bu xatoga olib keladi.
✅ `DELETE` triggerlarida `RETURN OLD;` ishlating.

**Xato 3:** `AFTER` trigger ichida `NEW.ustun = qiymat` yozib, buni saqlanadi deb o'ylash.
❌ `AFTER` trigger ishga tushganda qator allaqachon bazaga yozilgan — `NEW`ni o'zgartirish endi hech narsaga ta'sir qilmaydi.
✅ Saqlanadigan qiymatni o'zgartirish kerak bo'lsa, har doim `BEFORE` trigger ishlating.

## Qisqacha xulosa

Trigger — jadvalda `INSERT`/`UPDATE`/`DELETE` yuz berganda, funksiyani avtomatik ishga tushiradigan mexanizm. Trigger funksiyasi `RETURNS TRIGGER` bilan e'lon qilinadi va `NEW`/`OLD` maxsus o'zgaruvchilar orqali o'zgarayotgan qatorga murojaat qiladi. `BEFORE` — saqlanadigan qiymatni o'zgartirish yoki amalni bloklash uchun; `AFTER` — allaqachon sodir bo'lgan voqeaga reaksiya (masalan, audit yozuvi) uchun ishlatiladi. `FOR EACH ROW` har bir qator uchun, `FOR EACH STATEMENT` esa butun ifoda uchun bir marta ishlaydi. `TG_OP` bitta funksiyani bir nechta voqea turi bilan ishlatish imkonini beradi. Keyingi darsda triggerlarning **amaliy naqshlarini** — audit jurnali, denormallashtirilgan hisoblagichlarni avtomatik saqlash va boshqa real hayotiy misollarni chuqurroq ko'rib chiqamiz.
