# 6.3. `ALTER TABLE` — jadval strukturasini o'zgartirish

## Bu darsda nimalarni o'rganasiz

- `ALTER TABLE ... RENAME TO` bilan jadval nomini o'zgartirasiz
- `ALTER TABLE ... RENAME COLUMN` bilan ustun nomini o'zgartirasiz
- `ALTER TABLE ... ADD COLUMN` bilan yangi ustun qo'shasiz
- `ALTER TABLE ... DROP COLUMN`, `ALTER COLUMN ... SET/DROP DEFAULT`, `SET/DROP NOT NULL` bilan mavjud ustunlarni boshqarasiz
- Nomlarni o'zgartirish jadval ichidagi avtomatik yaratilgan obyekt nomlariga (sequence, constraint) ta'sir qilmasligini bilasiz

## Nazariy qism

### Nega `ALTER TABLE` kerak

Loyiha rivojlanishi davomida talablar deyarli har doim o'zgaradi — yangi ustun qo'shish kerak bo'ladi, eski ustun keraksiz bo'lib qoladi, yoki nom noto'g'ri tanlangani ma'lum bo'ladi. Jadvalni butunlay o'chirib qayta yaratish (`DROP` + `CREATE`) — bu ichidagi **barcha mavjud ma'lumotni yo'qotadi**, shuning uchun amaliyotda deyarli hech qachon qo'llanilmaydi. `ALTER TABLE` esa jadval strukturasini **mavjud ma'lumotni saqlab qolgan holda** o'zgartirish imkonini beradi.

### Jadval nomini o'zgartirish

```sql
ALTER TABLE eski_nom RENAME TO yangi_nom;
```

```sql
ALTER TABLE test_alter RENAME TO test_alter_v2;
```

### Ustun nomini o'zgartirish

```sql
ALTER TABLE jadval RENAME COLUMN eski_ustun TO yangi_ustun;
```

```sql
ALTER TABLE test_alter_v2 RENAME COLUMN nomi TO nom_yangi;
```

### Yangi ustun qo'shish

```sql
ALTER TABLE jadval ADD COLUMN ustun_nomi tur [cheklovlar];
```

```sql
ALTER TABLE test_alter_v2 ADD COLUMN narxi NUMERIC(10,2);
ALTER TABLE test_alter_v2 ADD COLUMN yaratilgan DATE DEFAULT CURRENT_DATE;
```

Yangi qo'shilgan ustun mavjud qatorlar uchun, agar `DEFAULT` ko'rsatilmagan bo'lsa, avtomatik ravishda `NULL` qiymat bilan to'ldiriladi; agar `DEFAULT` bo'lsa, barcha mavjud qatorlar ham o'sha standart qiymat bilan to'ldiriladi. Natijaviy sxemani tekshiramiz:

```sql
\d test_alter_v2
```

```
                                    Table "public.test_alter_v2"
   Column   |         Type          | Collation | Nullable |                Default                 
------------+-----------------------+-----------+----------+----------------------------------------
 id         | integer               |           | not null | nextval('test_alter_id_seq'::regclass)
 nom_yangi  | character varying(50) |           |          | 
 narxi      | numeric(10,2)         |           |          | 
 yaratilgan | date                  |           |          | CURRENT_DATE
Indexes:
    "test_alter_pkey" PRIMARY KEY, btree (id)
```

**Diqqat qiling — muhim nozik nuqta:** garchi jadval hozir `test_alter_v2` deb nomlangan bo'lsa ham, uning ichidagi avtomatik yaratilgan obyektlar — `id` ustunining sequence'i (`test_alter_id_seq`) va asosiy kalit cheklovi (`test_alter_pkey`) — hali ham **eski** `test_alter` nomini olib yuribdi! Bu — PostgreSQL'ning kutilgan xatti-harakati: `RENAME TO` faqat jadvalning **o'zi**ning nomini o'zgartiradi, u yaratilgan paytda avtomatik generatsiya qilingan ichki obyekt nomlarini (sequence, standart cheklov nomlari, indeks nomlari) **qayta nomlamaydi**. Amaliyotda bu odatda muammo tug'dirmaydi (chunki bu nomlarga to'g'ridan-to'g'ri kamdan-kam murojaat qilinadi), lekin agar sizga izchillik muhim bo'lsa, ularni alohida `ALTER SEQUENCE ... RENAME TO ...` va `ALTER TABLE ... RENAME CONSTRAINT ... TO ...` buyruqlari bilan qo'lda qayta nomlash mumkin.

### Ustunni o'chirish

```sql
ALTER TABLE jadval DROP COLUMN ustun_nomi;
```

```sql
ALTER TABLE test_alter_v2 DROP COLUMN yaratilgan;
```

> **Ehtiyot bo'ling:** `DROP COLUMN` — **qaytarib bo'lmaydigan** amal, ustundagi barcha ma'lumot butunlay yo'qoladi (agar tranzaksiya ichida bo'lmasa va `ROLLBACK` qilinmasa — 13-bobda tranzaksiyalarni chuqur o'rganamiz). Production muhitda ustunni o'chirishdan oldin har doim zaxira nusxa (15-bobda) yoki hech bo'lmaganda `CREATE TABLE ... AS SELECT` orqali o'sha ustunning nusxasini olib qo'yish tavsiya etiladi.

### Standart qiymatni (`DEFAULT`) boshqarish

```sql
ALTER TABLE test_alter_v2 ALTER COLUMN narxi SET DEFAULT 0;
```

Bu — kelajakdagi `INSERT`larga ta'sir qiladi (agar `narxi` ko'rsatilmasa, endi `0` qo'yiladi); **mavjud** qatorlarni o'zgartirmaydi. Standart qiymatni olib tashlash uchun:

```sql
ALTER TABLE test_alter_v2 ALTER COLUMN narxi DROP DEFAULT;
```

### `NOT NULL` cheklovini qo'shish/olib tashlash

```sql
ALTER TABLE test_alter_v2 ALTER COLUMN nom_yangi SET NOT NULL;
```

**Muhim eslatma:** agar ustunda hozirda **allaqachon** `NULL` qiymatli qatorlar bo'lsa, `SET NOT NULL` **xato** beradi — chunki PostgreSQL mavjud ma'lumotni yangi cheklovga qarshi tekshiradi. Bunday holda avval barcha `NULL`larni haqiqiy qiymat bilan to'ldirish (`UPDATE`) kerak, so'ngina `SET NOT NULL` muvaffaqiyatli bo'ladi. Olib tashlash esa har doim shartsiz ishlaydi:

```sql
ALTER TABLE test_alter_v2 ALTER COLUMN nom_yangi DROP NOT NULL;
```

### Ustun turini o'zgartirish

```sql
ALTER TABLE jadval ALTER COLUMN ustun TYPE yangi_tur;
```

Masalan, `VARCHAR(50)`ni `TEXT`ga o'zgartirish (bu — xavfsiz kengaytirish, chunki `TEXT` cheklanmagan):

```sql
ALTER TABLE test_alter_v2 ALTER COLUMN nom_yangi TYPE TEXT;
```

Agar tur o'zgarishi **avtomatik aylantirilmasa** (masalan, `TEXT`dan `INTEGER`ga, agar matnda raqam bo'lmagan qiymatlar bo'lsa), PostgreSQL `USING` bandi bilan aniq aylantirish ifodasini talab qilishi mumkin:

```sql
ALTER TABLE jadval ALTER COLUMN ustun TYPE INTEGER USING ustun::INTEGER;
```

> **Ehtiyot bo'ling:** katta jadvallarda ustun turini o'zgartirish butun jadvalni qayta yozishni talab qilishi mumkin (bu — 16-19-boblarda chuqurroq o'rganiladigan ichki saqlash mexanizmi bilan bog'liq) — bu operatsiya vaqt talab qilishi va jadvalni vaqtincha bloklashi mumkin, shuning uchun katta production jadvallarda bunday o'zgarishlarni ehtiyotkorlik bilan, kam yuklama paytida bajarish tavsiya etiladi.

## Amaliy misol

**Vazifa:** `mahsulotlar` jadvaliga mahsulotning tavsifi (`tavsif TEXT`) va u chegirmaga ega yoki yo'qligini bildiruvchi (`chegirmada BOOLEAN DEFAULT FALSE`) ustunlarini qo'shing.

```sql
ALTER TABLE mahsulotlar ADD COLUMN tavsif TEXT;
ALTER TABLE mahsulotlar ADD COLUMN chegirmada BOOLEAN DEFAULT FALSE;
```

Bu ikkita buyruqdan so'ng, mavjud barcha 10 ta mahsulot qatori `tavsif = NULL` va `chegirmada = FALSE` bilan avtomatik yangilanadi — bironta ham mavjud ma'lumot yo'qolmaydi.

## Keng tarqalgan xatolar

**Xato 1:** `NULL` qiymatli qatorlar mavjud ustunga `SET NOT NULL` qo'llashga urinish.
❌ Agar `lavozim` ustunida ba'zi qatorlarda `NULL` bo'lsa, `ALTER TABLE xodimlar ALTER COLUMN lavozim SET NOT NULL;` xato beradi.
✅ Avval `UPDATE xodimlar SET lavozim = 'Nomalum' WHERE lavozim IS NULL;` bilan bo'shliqlarni to'ldiring, so'ng cheklovni qo'shing.

**Xato 2:** `DROP COLUMN`ni ishlab chiqarish (production) muhitida zaxira nusxasiz bajarish.
✅ Har doim avval zaxira nusxa oling yoki hech bo'lmaganda tranzaksiya ichida sinab ko'ring (13-bobda).

**Xato 3:** Jadval nomini o'zgartirgandan keyin, sequence/constraint nomlari ham avtomatik o'zgargan deb o'ylab, keyinchalik ularga eski nom bilan murojaat qilishda "topilmadi" xatosiga duch kelish.
✅ `RENAME TO` faqat jadvalning o'z nomini o'zgartiradi; kerak bo'lsa, ichki obyektlarni alohida qayta nomlang.

## Mashq/topshiriq

**(Oson)** `xodimlar` jadvaliga `telefon VARCHAR(20)` ustunini qo'shing.

**(O'rtacha)** `mijozlar` jadvalidagi `shahar` ustuni nomini `manzil_shahri`ga o'zgartiring, so'ng `\d mijozlar` bilan o'zgarishni tasdiqlang, so'ng nomni yana asl holiga (`shahar`) qaytaring.

**(Qiyin)** Yangi test jadvali yarating (`CREATE TABLE test_narx (id SERIAL, narx TEXT)`), unga bir nechta son ko'rinishidagi matn qiymatlarni (`INSERT INTO test_narx (narx) VALUES ('100'), ('250.50')`) kiriting, so'ng `narx` ustunining turini `NUMERIC(10,2)`ga `USING narx::NUMERIC(10,2)` bilan o'zgartiring va natijani tekshiring; oxirida test jadvalini o'chirib tashlang.

## Qisqacha xulosa

`ALTER TABLE` — mavjud ma'lumotni saqlab qolgan holda jadval strukturasini (nomi, ustunlari, ularning turi, standart qiymati va `NOT NULL` cheklovi) o'zgartirishning asosiy vositasi. Katta operatsiyalarni (ayniqsa `DROP COLUMN` yoki ustun turini o'zgartirish) production muhitida ehtiyotkorlik bilan, zaxira nusxa bilan bajarish tavsiya etiladi. Keyingi darsda jadval va ma'lumotlarni butunlay olib tashlash — `DROP TABLE` va `TRUNCATE TABLE` orasidagi farqni o'rganamiz.
