# 6.4. `DROP TABLE` va `TRUNCATE TABLE` — jadval va ma'lumotni olib tashlash

## Bu darsda nimalarni o'rganasiz

- `DROP TABLE` jadvalning o'zini (struktura + ma'lumot) butunlay yo'q qilishini bilasiz
- `TRUNCATE TABLE` faqat ma'lumotni tez tozalab, strukturani saqlab qolishini tushunasiz
- `TRUNCATE`ning oddiy `DELETE`dan nima uchun tezroq ekanini bilasiz
- `RESTART IDENTITY` bilan avtomatik hisoblagichni ham nolga qaytarish mumkinligini bilasiz
- `CASCADE` va tashqi kalit bog'lanishlari `DROP`ga qanday ta'sir qilishini tushunasiz

## Nazariy qism

### `DROP TABLE` — jadvalning o'zini yo'q qilish

```sql
DROP TABLE jadval_nomi;
```

Bu — eng qat'iy amal: jadvalning **o'zi** (struktura, barcha ustunlar, indekslar, cheklovlar) VA undagi **barcha ma'lumot** butunlay, qaytarib bo'lmas tarzda o'chiriladi. Agar jadval mavjud bo'lmasa, xato beriladi — buni oldini olish uchun `IF EXISTS` ishlatiladi:

```sql
DROP TABLE IF EXISTS jadval_nomi;
```

```sql
DROP TABLE IF EXISTS nonexistent_table;
```

```
NOTICE:  table "nonexistent_table" does not exist, skipping
DROP TABLE
```

### `CASCADE` — bog'liq obyektlarni ham olib tashlash

Agar boshqa jadval sizning jadvalingizga `FOREIGN KEY` orqali bog'langan bo'lsa, oddiy `DROP TABLE` **xato** beradi — PostgreSQL yaxlitlikni himoya qiladi:

```sql
CREATE TABLE test_parent (id SERIAL PRIMARY KEY, nomi TEXT);
CREATE TABLE test_child (id SERIAL PRIMARY KEY, parent_id INTEGER REFERENCES test_parent(id));
INSERT INTO test_parent (nomi) VALUES ('P1');
INSERT INTO test_child (parent_id) VALUES (1);

DROP TABLE test_parent;
```

```
ERROR:  cannot drop table test_parent because other objects depend on it
DETAIL:  constraint test_child_parent_id_fkey on table test_child depends on table test_parent
HINT:  Use DROP ... CASCADE to drop the dependent objects too.
```

PostgreSQL'ning o'zi aniq yechimni ko'rsatib turibdi (`HINT` qatorida): `CASCADE` kalit so'zi bilan, bog'liq cheklovlarni (bu holatda `test_child`dagi tashqi kalit cheklovini, **`test_child` jadvalining o'zini emas**) ham avtomatik olib tashlash mumkin:

```sql
DROP TABLE test_parent CASCADE;
```

```
NOTICE:  drop cascades to constraint test_child_parent_id_fkey on table test_child
DROP TABLE
```

> **Juda muhim ehtiyot chorasi:** `CASCADE` — nihoyatda kuchli va **xavfli** vosita, chunki u qanday bog'liq obyektlar borligini oldindan har doim aniq ko'rsatib bermaydi (murakkab sxemalarda `CASCADE` ko'plab jadval, view yoki funksiyaga "zanjir bo'ylab" tarqalib ketishi mumkin). Production muhitda `CASCADE`ni ishlatishdan oldin, avval oddiy `DROP TABLE`ni (`CASCADE`siz) sinab ko'rib, xato xabaridagi `DETAIL` qatorida **aniq nima bog'liqligini** o'qib chiqish, va faqat shundan keyin ongli ravishda qaror qabul qilish tavsiya etiladi.

### `TRUNCATE TABLE` — faqat ma'lumotni tozalash, strukturani saqlab

Ba'zan sizga jadvalning o'zi emas, faqat **ichidagi barcha ma'lumot** kerak emas — masalan, test ma'lumotlarini tozalab, jadval strukturasini (ustunlar, indekslar, cheklovlar) saqlab qolish. Buning uchun `DELETE FROM jadval` (7-bobda chuqur o'rganamiz) ham ishlaydi, lekin katta jadvallar uchun `TRUNCATE` ancha samaraliroq:

```sql
CREATE TABLE test_drop (id SERIAL PRIMARY KEY, nomi TEXT);
INSERT INTO test_drop (nomi) VALUES ('A'), ('B'), ('C');

TRUNCATE TABLE test_drop;

SELECT count(*) FROM test_drop;
```

```
 count 
-------
     0
```

Jadvalning o'zi (struktura, ustunlar, indekslar) **butunlay saqlanib qoladi** — faqat qatorlar yo'q bo'ladi:

```sql
INSERT INTO test_drop (nomi) VALUES ('D');
SELECT * FROM test_drop;
```

```
 id | nomi 
----+------
  4 | D
```

### Nega `TRUNCATE` `DELETE`dan tezroq (17-bobda chuqurroq tushuniladi)

`DELETE FROM jadval` (`WHERE`siz, barcha qatorlarni o'chirish uchun) har bir qatorni **birma-bir**, tranzaksiya jurnaliga (WAL) yozib, va agar indekslar bo'lsa ularni ham har bir qator uchun yangilab o'chiradi — katta jadvalda bu sekin bo'lishi mumkin. `TRUNCATE` esa butunlay boshqacha, ancha yengil mexanizm ishlatadi: u shunchaki jadvalning fizik saqlash fayllarini butunlay yangi, bo'sh fayllar bilan almashtiradi (16-bobda "fayl-asosidagi saqlash" tushunchasini chuqur o'rganganimizda bu aniqroq bo'ladi) — bu deyarli **oniy** operatsiya, jadval hajmidan qat'i nazar.

### `RESTART IDENTITY` — avtomatik hisoblagichni ham nolga qaytarish

Diqqat qiling — yuqoridagi misolda `TRUNCATE`dan keyin yangi qo'shilgan qator `id = 4` bo'ldi, **`id = 1` emas**! Bu — muhim va ko'pincha kutilmagan xatti-harakat: oddiy `TRUNCATE` jadval ma'lumotini tozalasa-da, unga bog'liq **sequence** (`SERIAL`ning "orqasidagi" hisoblagich, 6.1-darsda ko'rganimizdek) holatini **saqlab qoladi**. Agar sizga hisoblagichni ham `1`dan qayta boshlash kerak bo'lsa, `RESTART IDENTITY` qo'shilishi kerak:

```sql
CREATE TABLE test_drop2 (id SERIAL PRIMARY KEY, nomi TEXT);
INSERT INTO test_drop2 (nomi) VALUES ('A'), ('B'), ('C');

TRUNCATE TABLE test_drop2 RESTART IDENTITY;

INSERT INTO test_drop2 (nomi) VALUES ('D');
SELECT * FROM test_drop2;
```

```
 id | nomi 
----+------
  1 | D
```

Endi yangi qator to'g'ri ravishda `id = 1` bilan boshlandi.

### `DROP TABLE` vs `TRUNCATE TABLE` — qachon qaysi birini ishlatish

| | `DROP TABLE` | `TRUNCATE TABLE` |
|---|---|---|
| Jadval strukturasi | O'chiriladi | Saqlanadi |
| Ma'lumot | O'chiriladi | O'chiriladi |
| Sequence holati | Jadval bilan birga yo'qoladi | Standart holda saqlanadi (`RESTART IDENTITY` bilan tozalanadi) |
| Tezlik | Tez (struktura kichik) | Juda tez (hatto milliardlab qatorli jadvalda ham) |
| Qachon ishlatiladi | Jadval umuman kerak bo'lmay qolganda | Jadval strukturasi kerak, lekin ma'lumot tozalanishi kerak bo'lganda (masalan, test muhitini "asl holatga" qaytarish) |

## Amaliy misol

**Vazifa:** Test muhitida ishlatilgan vaqtinchalik statistika jadvalini har oy oxirida to'liq tozalab, hisoblagichni ham qayta boshlash kerak (lekin jadvalning o'zi va uning ustidagi ruxsatlar/indekslar saqlanib qolishi kerak).

```sql
TRUNCATE TABLE oylik_statistika RESTART IDENTITY;
```

Bu bitta buyruq — jadvalni butunlay qayta yaratishga (`DROP` + `CREATE`, bu holda barcha grant/ruxsatlarni ham qayta sozlash kerak bo'lardi) qaraganda ancha soddaroq va xavfsizroq yechim.

## Keng tarqalgan xatolar

**Xato 1:** `DROP TABLE`ni `TRUNCATE TABLE` o'rniga ishlatib, keyin jadvalni qaytadan yaratish, indekslar va ruxsatlarni (grant) yo'qotib qo'yish.
✅ Agar faqat ma'lumotni tozalash kerak bo'lsa, `TRUNCATE`, hech qachon `DROP` + `CREATE` ishlatmang.

**Xato 2:** `CASCADE`ni "shunchaki ishlaydi" deb, qanday bog'liqliklar borligini tekshirmasdan ishlatish.
✅ Har doim avval `CASCADE`siz sinab ko'ring, xato xabaridagi `DETAIL`ni diqqat bilan o'qing.

**Xato 3:** `TRUNCATE`dan keyin sequence qiymati saqlanib qolishini unutib, "id"lar nega ketma-ket boshlanmayotganidan hayron bo'lish.
✅ Agar hisoblagichni ham qayta boshlash kerak bo'lsa, `RESTART IDENTITY`ni unutmang.

**Xato 4:** Production ma'lumotlar bazasida `DROP TABLE`/`TRUNCATE`ni tasdiqlashsiz, zaxira nusxasiz bajarish.
✅ Bu ikkala amal ham qaytarib bo'lmas (agar tranzaksiya ichida bo'lib, hali `COMMIT` qilinmagan bo'lmasa) — production'da har doim ikki marta o'ylab, zaxira nusxa borligiga ishonch hosil qiling.

## Mashq/topshiriq

**(Oson)** `sinov_jadvali` nomli oddiy jadval yarating, unga 3 ta qator kiriting, so'ng `TRUNCATE` bilan tozalang va qatorlar soni `0` ekanini tasdiqlang.

**(O'rtacha)** Yuqoridagi jadvalga yana ma'lumot kiritib, endi `RESTART IDENTITY` bilan tozalang, so'ng yangi qator qo'shib, uning `id`si `1`dan boshlanganini tasdiqlang.

**(Qiyin)** Ikkita bog'liq jadval (`ota_jadval`, `bola_jadval`, tashqi kalit orqali bog'langan) yarating, ularga ma'lumot kiriting, so'ng avval `CASCADE`siz `DROP TABLE ota_jadval`ni sinab xato xabarini o'qing, keyin `CASCADE` bilan muvaffaqiyatli bajaring — va nima uchun bu ikki bosqichli yondashuv ("avval sinab ko'rish, keyin CASCADE") xavfsizroq ekanini tushuntiring.

1.
```sql
CREATE TABLE sinov_jadvali (id SERIAL PRIMARY KEY, matn TEXT);
INSERT INTO sinov_jadvali (matn) VALUES ('a'), ('b'), ('c');
TRUNCATE TABLE sinov_jadvali;
SELECT count(*) FROM sinov_jadvali;  -- 0
```

2.
```sql
INSERT INTO sinov_jadvali (matn) VALUES ('x'), ('y');
TRUNCATE TABLE sinov_jadvali RESTART IDENTITY;
INSERT INTO sinov_jadvali (matn) VALUES ('z');
SELECT * FROM sinov_jadvali;  -- id = 1
```

3.
```sql
CREATE TABLE ota_jadval (id SERIAL PRIMARY KEY, nomi TEXT);
CREATE TABLE bola_jadval (id SERIAL PRIMARY KEY, ota_id INTEGER REFERENCES ota_jadval(id));
INSERT INTO ota_jadval (nomi) VALUES ('Test');
INSERT INTO bola_jadval (ota_id) VALUES (1);

DROP TABLE ota_jadval;  -- xato, DETAIL qatorida aniq sabab ko'rsatiladi

DROP TABLE ota_jadval CASCADE;  -- endi muvaffaqiyatli
DROP TABLE bola_jadval;  -- qolgan jadvalni ham tozalash
```
Avval `CASCADE`siz sinab ko'rish xavfsizroq, chunki bu sizga **aniq nima** o'chirilishini (xato xabaridagi `DETAIL` orqali) oldindan ko'rish imkonini beradi — murakkab sxemalarda `CASCADE` kutilmagan boshqa jadval yoki view'larni ham "zanjir bo'ylab" o'chirib yuborishi mumkin, va buni oldindan bilish keyinchalik katta muammolarning oldini oladi.

## Qisqacha xulosa

`DROP TABLE` jadvalning o'zini (struktura + ma'lumot) butunlay yo'q qiladi, `TRUNCATE TABLE` esa faqat ma'lumotni tez tozalab, strukturani saqlab qoladi — ikkalasi ham qaytarib bo'lmas amallar bo'lgani uchun ehtiyotkorlik talab qiladi. `TRUNCATE` katta jadvallarda `DELETE`dan sezilarli tezroq ishlaydi, lekin standart holda sequence holatini saqlaydi — buni ham tozalash uchun `RESTART IDENTITY` kerak. `CASCADE` bog'liq obyektlarni avtomatik olib tashlaydi, lekin uni ishlatishdan oldin qanday bog'liqliklar borligini bilish muhim. Bu bilan 06-bob (DDL) yakunlanadi — keyingi, 07-bobda esa ma'lumotlarni o'zgartirish tili (DML) — `INSERT`, `UPDATE`, `DELETE`, `COPY`ni chuqur o'rganamiz.
