# 1.4. `LIMIT`, `FETCH` va `OFFSET` — natijalar sonini cheklash

## Bu darsda nimalarni o'rganasiz

- `LIMIT` bilan so'rov natijasidan faqat kerakli sondagi qatorni olishni bilasiz
- `OFFSET` bilan boshidan necha qatorni "tashlab o'tish"ni tushunasiz — sahifalash (pagination) uchun asos
- SQL standartiga mos `FETCH FIRST`/`FETCH NEXT` sintaksisini bilasiz va u nima uchun `LIMIT`dan afzalroq hisoblanishini tushunasiz
- `FETCH ... WITH TIES` orqali "chegaradosh" tenglashgan qatorlarni ham qamrab olishni bilasiz
- `LIMIT`/`OFFSET`ni `ORDER BY`siz ishlatishning xavfini tushunasiz

## Nazariy qism

### `LIMIT` — asosiy sintaksis

`LIMIT` — PostgreSQL'da (va MySQL, SQLite kabi bir qancha boshqa DBMS'larda) juda keng tarqalgan, lekin SQL standartining bir qismi **bo'lmagan** kengaytma bo'lib, so'rov natijasidan faqat birinchi *N* qatorni qaytarishga majburlaydi:

```sql
SELECT ustun1, ustun2
FROM jadval
ORDER BY ustun1
LIMIT N;
```

```sql
SELECT nomi, narxi
FROM mahsulotlar
ORDER BY narxi DESC
LIMIT 3;
```

Natija — eng qimmat 3 ta mahsulot:

```
          nomi          |   narxi    
------------------------+------------
 Noutbuk Lenovo IdeaPad | 8500000.00
 Muzlatgich             | 6800000.00
 Kofe mashinasi         | 3500000.00
(3 rows)
```

> **Muhim ogohlantirish:** `LIMIT`ni **har doim** `ORDER BY` bilan birga ishlating. Sababi 1.2-darsda ko'rganimiz — `ORDER BY`siz qatorlar tartibi kafolatlanmagan, demak `ORDER BY`siz `LIMIT 3` "istalgan" 3 ta qatorni qaytaradi, va bu tartib har safar so'rov ishga tushganda **o'zgarishi mumkin**. `ORDER BY`siz `LIMIT` — deyarli har doim xato belgisi.

### `OFFSET` — boshidan necha qatorni tashlab o'tish

`OFFSET` — natijaning boshidan necha qatorni **o'tkazib yuborish**ni bildiradi, odatda `LIMIT` bilan birga sahifalash (pagination) uchun ishlatiladi:

```sql
SELECT ustun1
FROM jadval
ORDER BY ustun1
LIMIT N OFFSET M;
```

Bu "M ta qatorni tashlab o't, keyin N ta qatorni qaytar" degani. Masalan, narx bo'yicha kamayuvchi tartiblangan ro'yxatning 4—6-o'rinlarini olish (ya'ni birinchi 3 tani tashlab o'tib, keyingi 3 tani olish):

```sql
SELECT nomi, narxi
FROM mahsulotlar
ORDER BY narxi DESC
LIMIT 3 OFFSET 3;
```

Natija:

```
        nomi         |   narxi    
---------------------+------------
 Ish stoli           | 2500000.00
 Monitor Samsung 24" | 2200000.00
 Bosma printer       | 1800000.00
(3 rows)
```

**Sahifalash formulasi:** agar har sahifada `sahifa_hajmi` ta element ko'rsatilsa, `sahifa_raqami`-sahifani (1-dan boshlab hisoblansa) olish uchun:

```sql
LIMIT sahifa_hajmi OFFSET (sahifa_raqami - 1) * sahifa_hajmi
```

Masalan, 4 tadan mahsulot ko'rsatiladigan 2-sahifa:

```sql
SELECT id, nomi
FROM mahsulotlar
ORDER BY id
LIMIT 4 OFFSET 4;
```

```
 id |      nomi      
----+----------------
  5 | Ofis stuli
  6 | Ish stoli
  7 | Kofe mashinasi
  8 | Muzlatgich
(4 rows)
```

> **Unumdorlik haqida eslatma (18—19-boblarda batafsil):** `OFFSET` katta bo'lganda (masalan, `OFFSET 1000000`) PostgreSQL baribir o'sha 1 million qatorni ichki ravishda **hisoblab, keyin tashlab yuborishi** kerak — bu katta jadvallarda sekinlashadi. Juda katta ma'lumotlar to'plamida sahifalash uchun ko'pincha "keyset pagination" (oxirgi ko'rilgan qatorning kalitidan boshlab `WHERE id > oxirgi_id` bilan davom etish) usuli tavsiya etiladi — bu mavzuni performance-ga bag'ishlangan bo'limda qaytadan ko'rib chiqamiz.

### SQL standart sintaksisi: `FETCH FIRST` / `FETCH NEXT`

`LIMIT`/`OFFSET` PostgreSQL, MySQL va boshqalarda ishlaydi, lekin **SQL standartining rasmiy qismi emas**. SQL:2008 standarti buning o'rniga `OFFSET ... FETCH` sintaksisini kiritdi, va PostgreSQL buni ham to'liq qo'llab-quvvatlaydi:

```sql
SELECT ustun1
FROM jadval
ORDER BY ustun1
OFFSET M ROWS
FETCH FIRST N ROWS ONLY;
```

```sql
SELECT nomi, narxi
FROM mahsulotlar
ORDER BY narxi DESC
OFFSET 3 ROWS
FETCH FIRST 3 ROWS ONLY;
```

Bu — yuqoridagi `LIMIT 3 OFFSET 3` bilan **aynan bir xil** natija beradi:

```
        nomi         |   narxi    
---------------------+------------
 Ish stoli           | 2500000.00
 Monitor Samsung 24" | 2200000.00
 Bosma printer       | 1800000.00
(3 rows)
```

`FETCH FIRST` o'rniga `FETCH NEXT` ham yozish mumkin — ular sinonim (odatda `FETCH FIRST` — birinchi chaqiriqda, `FETCH NEXT` — kursor bilan ishlaganda "keyingi" ma'nosida ishlatiladi, lekin funksional farqi yo'q):

```sql
SELECT nomi, narxi
FROM mahsulotlar
ORDER BY narxi DESC
FETCH NEXT 1 ROW ONLY;
```

```
          nomi          |   narxi    
------------------------+------------
 Noutbuk Lenovo IdeaPad | 8500000.00
(1 row)
```

`ROW`/`ROWS` va `FIRST`/`NEXT` — ixtiyoriy sinonimlar, faqat o'qilishni tabiiyroq qilish uchun (`FETCH FIRST 1 ROW ONLY` — birlik, `FETCH FIRST 3 ROWS ONLY` — ko'plik).

**Nega `FETCH` ni bilish kerak, agar `LIMIT` ham ishlasa?** Ikki sabab: (1) `FETCH` — ISO SQL standarti, shuning uchun Oracle, SQL Server (2012+), DB2 kabi boshqa DBMS'larga ko'chirsangiz ham ishlaydi, `LIMIT` esa ko'chmaydi; (2) ba'zi korporativ/ta'lim muhitlarida "faqat standart SQL" talab qilinadi. Amaliyotda PostgreSQL loyihalarining aksariyati `LIMIT`ni ishlatadi — u qisqaroq va PostgreSQL hamjamiyatida odat tusiga kirgan — lekin ikkalasini ham bilish va o'qiy olish zarur.

### `FETCH ... WITH TIES` — "tenglashgan" chegaradosh qatorlarni ham qamrab olish

Bu — faqat `FETCH` sintaksisida mavjud, `LIMIT`da **yo'q** bo'lgan qulaylik: `WITH TIES` oxirgi qaytarilgan qator bilan `ORDER BY` ustuni(lari) bo'yicha **teng** qiymatga ega bo'lgan barcha keyingi qatorlarni ham qo'shib qaytaradi, hatto bu N ta qatordan oshib ketsa ham:

```sql
SELECT nomi, kategoriya, narxi
FROM mahsulotlar
ORDER BY kategoriya
FETCH FIRST 3 ROWS WITH TIES;
```

Natija — kutilganidek 3 emas, balki **5** qator:

```
          nomi          | kategoriya  |   narxi    
------------------------+-------------+------------
 Noutbuk Lenovo IdeaPad | Elektronika | 8500000.00
 Sichqoncha Logitech    | Elektronika |  150000.00
 Klaviatura mexanik     | Elektronika |  450000.00
 Monitor Samsung 24"    | Elektronika | 2200000.00
 Bosma printer          | Elektronika | 1800000.00
(5 rows)
```

Bu shunday sodir bo'ldi, chunki `mahsulotlar` jadvalida jami 5 ta `'Elektronika'` qatori bor, va ular barchasi `ORDER BY kategoriya` bo'yicha bir xil qiymatga ega (alifbo tartibida birinchi kategoriya) — shuning uchun "birinchi 3 ta"ning chegarasi 3-qatorda emas, balki butun `'Elektronika'` guruhi tugagandan keyin, ya'ni 5-qatorda o'tadi. `WITH TIES` odatda `ORDER BY`da **qiymati noyob bo'lmagan** ustun (masalan, kategoriya, ball, reyting) ishlatilganda, "top-N, lekin chegaradagi durang natijalarni yo'qotmaslik uchun" holatlarda foydali — masalan, "eng yuqori 3 ta ball to'plagan o'yinchi" so'ralganda, agar 3—4—5-o'rinlar bir xil ballga ega bo'lsa, ularning barchasini ko'rsatish adolatli bo'ladi.

> **Eslatma:** `WITH TIES` ishlatilganda `ORDER BY` **majburiy** — aks holda PostgreSQL xato beradi, chunki "tenglik" tushunchasi faqat tartiblash ustuniga nisbatan ma'noga ega.

## Amaliy misol

**Vazifa:** Eng arzon 3 ta mahsulotni (nomi va narxi bilan) ikkita usulda — `LIMIT` va `FETCH` bilan — chiqaring, natijalar bir xil ekanligini solishtiring.

```sql
-- LIMIT bilan
SELECT nomi, narxi
FROM mahsulotlar
ORDER BY narxi ASC
LIMIT 3;

-- FETCH bilan (bir xil natija)
SELECT nomi, narxi
FROM mahsulotlar
ORDER BY narxi ASC
FETCH FIRST 3 ROWS ONLY;
```

Ikkalasi ham:

```
        nomi         |   narxi   
---------------------+-----------
 Sichqoncha Logitech |  150000.00
 Klaviatura mexanik  |  450000.00
 Kitob tokchasi      |  900000.00
(3 rows)
```

## Keng tarqalgan xatolar

**Xato 1:** `ORDER BY`siz `LIMIT` ishlatib, "eng yaxshi N ta" natija olishga umid qilish.
❌ `SELECT nomi, narxi FROM mahsulotlar LIMIT 3;` — bu istalgan 3 ta qatorni qaytaradi, "eng arzon" yoki "eng qimmat" degani emas.
✅ To'g'ri: har doim mos `ORDER BY` qo'shing: `... ORDER BY narxi ASC LIMIT 3;`.

**Xato 2:** `OFFSET`ni `LIMIT`dan oldin yozish deb o'ylab, `LIMIT`/`OFFSET` tartibida xatoga yo'l qo'yish.
PostgreSQL'da aslida ikkalasi ham qabul qilinadi (`LIMIT 3 OFFSET 3` yoki `OFFSET 3 LIMIT 3`), lekin izchillik va boshqa DBMS'lar bilan mosliK uchun standart `LIMIT ... OFFSET ...` tartibida yozish tavsiya etiladi.

**Xato 3:** `WITH TIES`ni `ORDER BY`siz yoki noyob ustun (masalan, `id`) bo'yicha ishlatib, uning hech qanday qo'shimcha qator qaytarmasligidan hayron bo'lish.
❌ `... ORDER BY id FETCH FIRST 3 ROWS WITH TIES;` — `id` har doim noyob bo'lgani uchun hech qachon tenglik bo'lmaydi, natija oddiy `FETCH FIRST 3`dan farq qilmaydi.
✅ `WITH TIES`ni faqat qiymati takrorlanishi mumkin bo'lgan ustunlarda (masalan, `kategoriya`, `ball`) ma'noli ishlating.

**Xato 4:** Sahifalash formulasida `OFFSET`ni noto'g'ri hisoblash (masalan, 1-sahifa uchun `OFFSET 0` o'rniga `OFFSET 1` yozish).
✅ Eslab qoling: 1-sahifa uchun `OFFSET = (1-1) * sahifa_hajmi = 0`, 2-sahifa uchun `OFFSET = (2-1) * sahifa_hajmi = sahifa_hajmi`, va hokazo.

## Mashq/topshiriq

**(Oson)** `xodimlar` jadvalidan maoshi eng yuqori 3 ta xodimning ism-familiyasi va maoshini `LIMIT` yordamida chiqaring.

**(O'rtacha)** Xuddi shu so'rovni endi SQL standart `FETCH FIRST ... ROWS ONLY` sintaksisi bilan qayta yozing va natijalar bir xil ekanligini tekshiring.

**(Qiyin)** `mahsulotlar` jadvalidagi barcha mahsulotlarni `id` bo'yicha o'suvchi tartiblab, ularni har birida 3 tadan mahsulot bo'lgan "sahifalar"ga bo'ling — 1, 2, 3 va 4-sahifalar uchun mos `LIMIT ... OFFSET ...` so'rovlarini yozing (jami 10 ta mahsulot borligini va oxirgi sahifada faqat 1 ta qator qolishini hisobga oling).

## Qisqacha xulosa

`LIMIT`/`OFFSET` (PostgreSQL'ga xos, keng tarqalgan) va SQL standart `FETCH FIRST`/`OFFSET ... FETCH` (ko'chma, boshqa DBMS'larda ham ishlaydi) — natijalar sonini cheklash va sahifalashning ikki teng kuchli usuli; `WITH TIES` esa faqat `FETCH` sintaksisida mavjud bo'lib, chegaradagi durang qiymatlarni yo'qotmaslikka yordam beradi. Ikkalasini ham `ORDER BY`siz ishlatish — deyarli har doim mantiqiy xato, chunki tartiblanmagan natijadan "birinchi N ta"ni olish hech narsani kafolatlamaydi. Bu bilan 01-bob (SELECT asoslari) yakunlanadi — keyingi, 02-bobda esa `IN`, `LIKE` va `NULL` bilan ishlash orqali filtrlashni yanada chuqurroq o'rganamiz.
