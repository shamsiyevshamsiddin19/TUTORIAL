# 2.2. `LIKE` va `ILIKE` — matn ichida naqsh bo'yicha qidirish

## Bu darsda nimalarni o'rganasiz

- `LIKE` operatorining `%` va `_` maxsus belgilaridan foydalanib matn naqshini qidirasiz
- `LIKE` katta-kichik harfga sezgir, `ILIKE` esa sezgir emasligini bilasiz
- Naqsh ichida haqiqiy `%`/`_` belgisini qidirish uchun `ESCAPE`dan foydalanasiz
- `LIKE`ning katta jadvallarda unumdorlik jihatidan qanday cheklovlari borligini (indekslash bilan bog'liq holda) tushunasiz

## Nazariy qism

### Asosiy sintaksis va ikkita maxsus belgi

`LIKE` — matn ustunini oddiy "naqsh" (pattern) bilan solishtirish uchun ishlatiladi. Naqsh ichida ikkita maxsus belgi bor:

| Belgi | Ma'nosi |
|---|---|
| `%` | **istalgan sondagi** (nol yoki undan ko'p) istalgan belgi |
| `_` | **aynan bitta** istalgan belgi |

```sql
SELECT ustun FROM jadval WHERE ustun LIKE 'naqsh';
```

**Prefiks (boshi bilan) qidirish** — `%` naqsh oxirida:

```sql
SELECT ism, familiya FROM xodimlar WHERE familiya LIKE 'A%';
```

```
  ism   | familiya 
--------+----------
 Sardor | Aliyev
(1 row)
```

**Ichida (contains) qidirish** — `%` naqshning ikkala tomonida:

```sql
SELECT nomi FROM mahsulotlar WHERE nomi LIKE '%stol%';
```

```
   nomi    
-----------
 Ish stoli
(1 row)
```

Diqqat qiling — `'%stol%'` faqat `"Ish stoli"`ni topdi, garchi `"Ofis stuli"` ham "stol" so'ziga yaqin bo'lsa-da (u yerda "stul" yozilgan, "stol" emas — `LIKE` **aniq harflarni**, hech qanday til bilimisiz, mexanik ravishda solishtiradi).

### `LIKE` — katta-kichik harfga **sezgir**

Bu — eng ko'p uchraydigan chalkashlik manbai. PostgreSQL'da (ba'zi boshqa DBMS'lardan farqli o'laroq) `LIKE` **case-sensitive**:

```sql
SELECT nomi FROM mahsulotlar WHERE nomi LIKE '%Stol%';   -- katta harf bilan
```

```
 nomi 
------
(0 rows)
```

Bo'sh natija! Chunki bazada `"stoli"` kichik harf bilan yozilgan, `'%Stol%'` esa katta `S` bilan qidirmoqda — ular **mos kelmaydi**.

### `ILIKE` — PostgreSQL'ga xos, katta-kichik harfga sezgir **emas**

`ILIKE` (case-**I**nsensitive `LIKE`) — SQL standartining qismi emas, PostgreSQL'ning o'ziga xos kengaytmasi, lekin amaliyotda juda foydali:

```sql
SELECT nomi FROM mahsulotlar WHERE nomi ILIKE '%stol%';
```

```
   nomi    
-----------
 Ish stoli
(1 row)
```

Bu safar ishladi, garchi naqsh (`stol`) kichik harfda, ma'lumot (`Ish stoli`) esa aralash registrda bo'lsa ham — `ILIKE` ikkalasini ham solishtirishdan oldin bir xil registrga keltiradi.

> **Amaliy maslahat:** foydalanuvchi kiritgan qidiruv so'zi bilan ishlaganda (masalan, veb-saytdagi qidiruv maydoni) deyarli har doim `ILIKE` afzalroq — foydalanuvchi katta-kichik harfni to'g'ri kiritishiga umid qilib o'tirish yaxshi UX emas.

### `_` — aynan bitta belgi

```sql
SELECT ism FROM xodimlar WHERE ism LIKE '_odira';
```

```
  ism   
--------
 Nodira
```

Bu yerda `_` aynan bitta belgi o'rnini bosdi (`N`), va `odira` qolgan qismga aynan mos keldi. Agar ism `Kodira` yoki `Sodira` bo'lganida ham mos kelgan bo'lardi — chunki `_` "bitta istalgan belgi" degani, aniq `N` emas.

### `NOT LIKE`

```sql
SELECT nomi FROM mahsulotlar WHERE nomi NOT LIKE '%stol%';
```

Natijada `"stol"` so'zi (kichik harflarda, aniq shu ketma-ketlikda) uchramaydigan barcha 9 ta mahsulot chiqadi.

### Haqiqiy `%` yoki `_` belgisini qidirish: `ESCAPE`

Agar sizga matn ichida haqiqatan `%` yoki `_` belgisining o'zini (maxsus ma'nosisiz) qidirish kerak bo'lsa — masalan, "50% chegirma" degan matnni — `ESCAPE` bandi bilan "qochish belgisi" (escape character) belgilanadi:

```sql
SELECT '50% chegirma' LIKE '%!%%' ESCAPE '!';
```

```
 ?column? 
----------
 t
(1 row)
```

Bu yerda naqsh `'%!%%'` shunday o'qiladi: birinchi `%` — "istalgan boshlanish", `!%` — qochish belgisi (`!`) orqali "haqiqiy `%` belgisi" ma'nosida, oxirgi `%` — "istalgan davomi". Natija — `TRUE` (`t`), chunki matnda haqiqatan `%` belgisi bor.

### `LIKE` va unumdorlik — qisqa eslatma (18-bobda batafsil)

`LIKE 'A%'` kabi **prefiks** naqshlar (boshida `%` yo'q) odatiy B-tree indeksdan foydalana oladi va tez ishlaydi. Lekin `LIKE '%stol%'` kabi naqshlar (boshida `%` bor) oddiy indeksdan **foydalana olmaydi** — PostgreSQL har bir qatorni to'liq skanerlashga majbur bo'ladi (bu — "sequential scan"). Katta jadvallarda tez-tez "ichida qidirish" kerak bo'lsa, PostgreSQL'ning maxsus **to'liq matnli qidiruv** (full-text search, `tsvector`/`tsquery`) yoki `pg_trgm` kengaytmasi (trigram-asosli indekslash) kabi vositalari ancha samaraliroq — bularga 18-bobda (indekslash chuqur) qaytamiz.

## Amaliy misol

**Vazifa:** Familiyasi `"ov"` bilan tugaydigan barcha xodimlarni (masalan, Karimov, Nazarov) toping — ILIKE bilan, katta-kichik harfdan qat'i nazar.

```sql
SELECT ism, familiya
FROM xodimlar
WHERE familiya ILIKE '%ov';
```

Natija — familiyasi "ov" bilan tugaydigan xodimlar (Karimov, Toshpulatov, Nazarov va h.k.).

## Keng tarqalgan xatolar

**Xato 1:** `LIKE`ning katta-kichik harfga sezgir ekanini unutib, mos natija topilmasligidan hayron bo'lish.
❌ `WHERE nomi LIKE '%Noutbuk%'` — agar bazada `noutbuk` kichik harf bilan yozilgan bo'lsa, hech narsa topilmaydi.
✅ To'g'ri: foydalanuvchi kiritgan yoki ishonchsiz registrdagi matn bilan ishlaganda `ILIKE` ishlating.

**Xato 2:** `%` va `_`ni MS Excel yoki wildcard fayl qidiruvidagi `*`/`?` bilan aralashtirib yuborish.
❌ `WHERE nomi LIKE '*stol*'` — bu SQL'da ishlamaydi, `*` hech qanday maxsus ma'noga ega emas.
✅ To'g'ri: SQL'da faqat `%` (ko'p belgi) va `_` (bitta belgi) maxsus.

**Xato 3:** `LIKE '%naqsh%'` (boshida `%`) katta jadvalda sekin ishlashidan xabarsiz bo'lish va nega so'rov "sekinlashib qoldi" deb hayron bo'lish.
✅ Katta hajmli "ichida qidirish" ehtiyoji uchun `pg_trgm` kengaytmasi yoki to'liq matnli qidiruv (18-bobda) haqida o'ylang.

## Mashq/topshiriq

**(Oson)** `mahsulotlar` jadvalidan nomi `"M"` harfi bilan boshlanadigan mahsulotlarni `LIKE` bilan toping.

**(O'rtacha)** `xodimlar` jadvalidan emaili (`email` ustuni) `"@"` belgisidan keyin `"mail.uz"` bilan tugaydigan xodimlarni `LIKE` bilan toping (email formatini avval `SELECT email FROM xodimlar LIMIT 3;` bilan ko'rib oling).

**(Qiyin)** Matn ichida haqiqiy `_` belgisini (masalan, `"foydalanuvchi_nomi"` degan satrni) qidirish uchun `LIKE` naqshini `ESCAPE` bilan yozing, va nega oddiy `LIKE '%_nomi%'` bunday holatda noto'g'ri natija berishi mumkinligini (chunki `_` maxsus belgi ekanini) tushuntiring.

1.
```sql

```

2. (natija sizning `email` ustunidagi haqiqiy qiymatlarga bog'liq; namuna sifatida)

3.

Oddiy `LIKE '%_nomi'` (escape'siz) ham amalda ko'p holatda ishlab ketishi mumkin, chunki `_` "istalgan bitta belgi" bo'lgani uchun undan oldingi harf (masalan, `i`) bilan ham mos keladi — lekin bu **tasodifiy** to'g'ri natija, mantiqiy jihatdan xato: agar so'zning oxiri `Xnomi` (istalgan X harfi) bo'lsa ham mos kelib qoladi, garchi siz aynan `_nomi` (pastki chiziqcha bilan) qidirmoqchi bo'lsangiz ham. `ESCAPE` bilan yozilgan variant esa faqat **aynan** pastki chiziqcha belgisini qidiradi — mantiqiy jihatdan to'g'ri va ishonchli usul shu.

</details>

## Qisqacha xulosa

`LIKE` va `ILIKE` — matn ichida oddiy naqsh (`%` — ko'p belgi, `_` — bitta belgi) bo'yicha qidirish uchun asosiy vositalar; `LIKE` katta-kichik harfga sezgir, `ILIKE` esa (PostgreSQL'ga xos) sezgir emas. Naqsh boshida `%` bo'lgan "ichida qidirish" so'rovlari katta jadvallarda sekin ishlashi mumkinligini va bunday holatlar uchun maxsus indekslash vositalari borligini yodda tuting. Keyingi darsda `NULL` qiymatlar bilan to'g'ri ishlashni — `IS NULL`, `IS NOT NULL` va `COALESCE`ni — chuqur o'rganamiz.
