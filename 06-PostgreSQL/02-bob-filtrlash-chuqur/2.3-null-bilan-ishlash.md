# 2.3. `NULL` bilan to'g'ri ishlash — `IS NULL`, `COALESCE`, `NULLIF`

## Bu darsda nimalarni o'rganasiz

- `NULL`ning "noma'lum qiymat" ekanini va u oddiy qiymat (masalan, `0` yoki `''`) emasligini chuqur tushunasiz
- `IS NULL` / `IS NOT NULL` operatorlaridan to'g'ri foydalanasiz
- `COALESCE()` bilan `NULL` o'rniga standart qiymat ko'rsatasiz
- `NULLIF()` bilan ma'lum bir qiymatni `NULL`ga aylantirasiz
- `NULL`ning agregat funksiyalar (`COUNT`, `SUM`, `AVG`) va arifmetik amallardagi xatti-harakatini bilasiz
- `IS DISTINCT FROM` bilan `NULL`-xavfsiz solishtirish qanday qilinishini bilasiz

## Nazariy qism

### `NULL` — "yo'q qiymat" emas, "noma'lum qiymat"

Bu darsning eng muhim tushunchasi, va 1.3 hamda 2.1-darslarda allaqachon ko'p marta duch kelgan tuzoqning ildizi: **`NULL` biror qiymat emas — u "bu yerda qiymat mavjudligi noma'lum yoki ma'lum emas" degan махsus belgi.** `NULL` — `0`ga teng emas, bo'sh matn (`''`)ga teng emas, hatto boshqa `NULL`ga ham teng **emas**:

```sql
SELECT NULL = NULL AS teng, NULL IS NULL AS is_null;
```

```
 teng | is_null 
------+---------
      | t
```

`NULL = NULL` natijasi — `NULL` (bo'sh, "noma'lum"), `TRUE` emas! Faqat maxsus `IS NULL` predikati `TRUE` beradi. Bu — SQL'ning "uch qiymatli mantiqi" (`TRUE` / `FALSE` / `NULL` — "noma'lum") deb ataladi, va deyarli har bir SQL bilan ishlaydigan dasturchi bu bilan bir marta "kuyib" o'rganadi.

`xodimlar` jadvalimizda `boshliq_id` ustuni `NULL` bo'lishi mumkin — bu bosh direktor Azizning **hech kimga bo'ysunmasligini**, ya'ni boshliq tushunchasi unga **qo'llanilmasligini** anglatadi (`0` yoki biror maxsus "boshliqsiz" ID emas — chunki bunday ID jadvalda haqiqiy ma'noga ega bo'lib qolishi mumkin edi).

### `IS NULL` / `IS NOT NULL`

1.3-darsda ko'rganimizdek, `= NULL` va `<> NULL` **hech qachon** `TRUE` bermaydi. `NULL`ni tekshirishning yagona to'g'ri yo'li:

```sql
SELECT ism, familiya, boshliq_id
FROM xodimlar
WHERE boshliq_id IS NULL;
```

```
 ism  | familiya | boshliq_id 
------+----------+------------
 Aziz | Karimov  |           
(1 row)
```

```sql
SELECT count(*)
FROM xodimlar
WHERE boshliq_id IS NOT NULL;
```

```
 count 
-------
     9
```

### `COALESCE()` — `NULL` o'rniga standart qiymat

`COALESCE(a, b, c, ...)` — argumentlarni chapdan o'ngga qarab tekshiradi va **birinchi `NULL` bo'lmagan qiymatni** qaytaradi. Eng ko'p ishlatiladigan holat — hisobot yoki interfeysda `NULL` o'rniga o'qilishi qulayroq matn ko'rsatish:

```sql
SELECT ism, COALESCE(boshliq_id::text, 'Boshliq yo''q') AS boshliq
FROM xodimlar
ORDER BY id;
```

```
   ism   |   boshliq   
---------+-------------
 Aziz    | Boshliq yo'q
 Dilnoza | 1
 Sardor  | 1
 Malika  | 2
 Jasur   | 1
 Nodira  | 1
 Farrux  | 3
 Sevara  | 1
 Otabek  | 2
 Kamola  | 5
(10 rows)
```

(Bu yerda `::text` — PostgreSQL'ning tur o'zgartirish (type cast) sintaksisi, chunki `COALESCE` barcha argumentlar bir xil turda bo'lishini talab qiladi; `boshliq_id` — `integer`, `'Boshliq yo''q'` — matn, shuning uchun sonni matnga aylantiramiz. Tur o'zgartirish haqida to'liqroq keyingi boblarda.)

`COALESCE` ikkitadan ortiq argument ham qabul qilishi mumkin — masalan, bir nechta manzil ustunidan birinchi bo'sh bo'lmaganini tanlashda foydali: `COALESCE(mobil_tel, uy_tel, ish_tel, 'Telefon kiritilmagan')`.

### `NULLIF()` — teskarisi: qiymatni `NULL`ga aylantirish

`NULLIF(a, b)` — agar `a = b` bo'lsa `NULL` qaytaradi, aks holda `a`ning o'zini qaytaradi. Eng klassik qo'llanilishi — nolga bo'lishdan (`division by zero` xatosidan) himoyalanish:

```sql
SELECT ombordagi_soni, NULLIF(ombordagi_soni, 0) AS nolsiz
FROM mahsulotlar
ORDER BY id;
```

```
 ombordagi_soni | nolsiz 
----------------+--------
             12 |     12
             ...
              0 |       
             10 |     10
(10 rows)
```

Diqqat qiling: `ombordagi_soni = 0` bo'lgan qatorda `nolsiz` ustuni `NULL` bo'lib qoldi. Buning amaliy foydasi — masalan, "har bir mahsulotning narxini ombordagi songa bo'lib, bir donaga to'g'ri keladigan qiymatni hisoblash" kabi formulalarda:

```sql
SELECT nomi, narxi / NULLIF(ombordagi_soni, 0) AS dona_narxi
FROM mahsulotlar;
```

Agar `NULLIF` bo'lmaganida, `ombordagi_soni = 0` bo'lgan qatorda `narxi / 0` ifodasi PostgreSQL'da **xato** (`division by zero`) tashlab, butun so'rovni to'xtatib qo'yardi. `NULLIF(ombordagi_soni, 0)` esa `0`ni `NULL`ga aylantiradi, va `narxi / NULL` xato emas, balki oddiygina `NULL` natija beradi — so'rov davom etadi.

### `NULL` arifmetik amallarda: "yuqtiruvchi" xususiyat

```sql
SELECT ism, ish_haqi, ish_haqi + NULL AS natija
FROM xodimlar WHERE ism = 'Aziz';
```

```
 ism  |  ish_haqi   | natija 
------+-------------+--------
 Aziz | 25000000.00 |       
```

**Har qanday** arifmetik amal (`+`, `-`, `*`, `/`) yoki matn birlashtirish (`||`) qatnashgan `NULL` — natijani ham `NULL` qiladi, "yuqtiruvchi" (contagious) xususiyatga ega: `25000000 + NULL = NULL`, `'Salom' || NULL = NULL`, va hokazo. Bu — mantiqan to'g'ri: "noma'lum songa 5 ni qo'shsak", natija ham noma'lum bo'lib qoladi.

### `NULL` agregat funksiyalarda: alohida qoida

Bu — muhim istisno, chuqurroq 4-bobda o'rganiladigan agregat funksiyalar bilan bog'liq: **`COUNT(ustun)`, `SUM()`, `AVG()`, `MAX()`, `MIN()` kabi agregat funksiyalar `NULL` qiymatlarni oddiygina "e'tiborsiz qoldiradi"** (yuqtirmaydi):

```sql
SELECT count(*) AS jami, count(boshliq_id) AS boshliqli
FROM xodimlar;
```

```
 jami | boshliqli 
------+-----------
   10 |         9
```

`count(*)` — jadvaldagi **barcha** qatorlarni sanaydi (10 ta), `count(boshliq_id)` esa faqat `boshliq_id`si `NULL` **bo'lmagan** qatorlarni sanaydi (9 ta, Aziz hisobga kirmadi). Xuddi shunday, `AVG(ustun)` faqat `NULL` bo'lmagan qiymatlarning o'rtachasini hisoblaydi — `NULL`larni "nolga" hisoblamaydi, balki ularni umuman **e'tiborga olmaydi**. Bu — boshlang'ich dasturchilar ko'pincha noto'g'ri tushunadigan nozik farq: `AVG` ustunda 3 ta qiymat va 2 ta `NULL` bo'lsa, o'rtacha 5 ta emas, balki 3 ta qiymat asosida hisoblanadi.

### `IS DISTINCT FROM` — `NULL`-xavfsiz tenglik solishtirish

Ba'zan sizga "aynan `NULL`-mantiqni e'tiborsiz qoldirib, oddiy dasturlash tilidagidek tenglikni" solishtirish kerak bo'ladi — ya'ni `NULL`ni ham "oddiy qiymat" sifatida solishtiradigan versiya. Buning uchun PostgreSQL'da `IS DISTINCT FROM` (va uning teskarisi `IS NOT DISTINCT FROM`) bor:

```sql
SELECT ism, boshliq_id
FROM xodimlar
WHERE boshliq_id IS DISTINCT FROM 1;
```

```
  ism   | boshliq_id 
--------+------------
 Aziz   |           
 Malika |          2
 Farrux |          3
 Otabek |          2
 Kamola |          5
(5 rows)
```

Diqqat qiling: `Aziz` (`boshliq_id IS NULL`) ham natijaga **kirdi** — chunki `NULL` haqiqatan `1`dan **farqli** (`IS DISTINCT`), oddiy `<>` operatoridan farqli o'laroq (`NULL <> 1` — `NULL`, ya'ni "noma'lum", `WHERE` uchun amalda yo'q). `IS DISTINCT FROM`/`IS NOT DISTINCT FROM` — `NULL`ni "oddiy qiymatdek" hisobga oladigan yagona solishtirish operatorlari.

## Amaliy misol

**Vazifa:** Barcha xodimlarni, ularning bevosita boshlig'ining ismi bilan birga chiqaring; agar xodimning boshlig'i bo'lmasa (ya'ni u — bosh direktor), `"Boshliq yo'q (Bosh direktor)"` deb ko'rsating.

```sql
SELECT x.ism AS xodim,
       COALESCE(b.ism, 'Boshliq yo''q (Bosh direktor)') AS boshliq
FROM xodimlar x
LEFT JOIN xodimlar b ON x.boshliq_id = b.id
ORDER BY x.id;
```

(Bu yerda o'z-o'ziga `LEFT JOIN` ishlatilmoqda — bu texnikani 3-bobda chuqur o'rganamiz; hozircha e'tibor `COALESCE`ning amaliy foydasiga qarating.)

## Keng tarqalgan xatolar

**Xato 1:** `WHERE ustun = NULL` yoki `WHERE ustun <> NULL` yozish (1.3 va 2.1-darslarda ham ko'rgan asosiy tuzoq).
✅ Har doim `IS NULL` / `IS NOT NULL` ishlating.

**Xato 2:** `AVG()`ni hisoblashda `NULL`lar "nolga" hisoblanadi deb o'ylash.
❌ Agar ustunda `[10, 20, NULL]` bo'lsa, `AVG` natijasi `10` emas (`(10+20+0)/3`), balki `15` (`(10+20)/2`, faqat `NULL` bo'lmagan qiymatlar hisobga olinadi).
✅ Agar sizga `NULL`larni **nol** sifatida hisoblash kerak bo'lsa, avval `COALESCE(ustun, 0)` bilan aylantiring: `AVG(COALESCE(ustun, 0))`.

**Xato 3:** Nolga bo'lish xavfi bor ifodada `NULLIF` ishlatmaslik.
❌ `SELECT narxi / ombordagi_soni FROM mahsulotlar;` — agar biror qatorda `ombordagi_soni = 0` bo'lsa, `division by zero` xatosi butun so'rovni to'xtatadi.
✅ `SELECT narxi / NULLIF(ombordagi_soni, 0) FROM mahsulotlar;` — xato o'rniga shunchaki `NULL` natija beradi.

## Mashq/topshiriq

**(Oson)** `xodimlar` jadvalidan `boshliq_id`si `NULL` bo'lmagan xodimlar sonini `COUNT`ning ikki xil shakli (`count(*)` va `count(boshliq_id)`) bilan solishtirib ko'ring va farqni tushuntiring.

**(O'rtacha)** `mahsulotlar` jadvalidagi har bir mahsulot uchun, agar `ombordagi_soni = 0` bo'lsa `"Omborda yo'q"`, aks holda haqiqiy sonni matn ko'rinishida ko'rsatadigan ustun yasang (`CASE` ishlatmasdan, faqat `NULLIF` va `COALESCE` kombinatsiyasi bilan).

**(Qiyin)** `ish_haqi` ustunidagi qiymatlardan ba'zilari (faraz qiling) `NULL` bo'lganida, `AVG(ish_haqi)` va `AVG(COALESCE(ish_haqi, 0))` orasidagi farqni sonli misolda (o'zingiz `UPDATE` bilan bitta qatorni vaqtincha `NULL` qilib) ko'rsating va natijani tushuntiring (ishni tugatgach `ROLLBACK` yoki asl qiymatni qaytaring — 13-bobda tranzaksiyalarni chuqur o'rganganimizda bu ancha qulay bo'ladi).

## Qisqacha xulosa

`NULL` — SQL'dagi "noma'lum qiymat" tushunchasi bo'lib, oddiy `=`/`<>` operatorlari bilan hech qachon to'g'ri solishtirilmaydi (buning o'rniga `IS NULL`/`IS NOT NULL` ishlatiladi), arifmetik amallarda "yuqtiruvchi" xususiyatga ega, lekin agregat funksiyalarda (`COUNT`, `AVG`, `SUM`) shunchaki e'tiborsiz qoldiriladi. `COALESCE()` — `NULL` o'rniga standart qiymat qo'yish, `NULLIF()` — ma'lum qiymatni `NULL`ga aylantirish (masalan, nolga bo'lishdan himoyalanish) uchun, `IS DISTINCT FROM` esa `NULL`ni "oddiy qiymatdek" hisobga oladigan yagona solishtiruvchi operator. Bu tushunchalarni chuqur bilish — SQL'dagi eng ko'p uchraydigan, va eng qiyin topiladigan xatolarning oldini oladi. Bu bilan 02-bob (Filtrlash chuqur) yakunlanadi — keyingi, 03-bobda esa `JOIN`larni — bir nechta jadvalni birlashtirishni — chuqur o'rganishni boshlaymiz.
