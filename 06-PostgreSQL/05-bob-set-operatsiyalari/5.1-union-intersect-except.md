# 5.1. To'plam amallari — `UNION`, `INTERSECT`, `EXCEPT`

## Bu darsda nimalarni o'rganasiz

- `UNION` va `UNION ALL` bilan ikkita so'rov natijasini vertikal birlashtirishni, va ular orasidagi (takrorlanishni olib tashlash) farqni bilasiz
- `INTERSECT` bilan ikkita natijaning **umumiy** qismini topasiz
- `EXCEPT` bilan bitta natijadan ikkinchisida bor qatorlarni **ayirasiz**, va tomonlar tartibi natijaga qanday ta'sir qilishini tushunasiz
- To'plam amallari ishlashi uchun ikkala so'rovning ustunlar soni va turi mos kelishi kerakligini bilasiz

## Nazariy qism

### To'plam amallari nima uchun kerak

Hozirgacha ko'rgan `JOIN`lar ikkita jadvalni **gorizontal** (yon-yonma, ustunlarni kengaytirib) birlashtirgan edi. To'plam amallari (`UNION`, `INTERSECT`, `EXCEPT`) esa butunlay boshqacha ishlaydi — ular ikkita **alohida `SELECT` so'rovining natijalarini vertikal** (qatorlarni bir-birining ustiga qo'yib) birlashtiradi, xuddi matematikadagi to'plamlar nazariyasi (set theory) amallari kabi: birlashma (∪), kesishma (∩), ayirma (−).

Buni ko'rsatish uchun ikkita mustaqil manbadan — mijozlar yashaydigan shaharlar (`mijozlar.shahar`) va kompaniya ofislari joylashgan shaharlar (`bolimlar.joylashuv`) — foydalanamiz:

```sql
SELECT DISTINCT shahar FROM mijozlar;
```
```
  shahar   
-----------
 Toshkent
 Samarqand
 Buxoro
 Andijon
```

```sql
SELECT DISTINCT joylashuv FROM bolimlar;
```
```
 joylashuv 
-----------
 Toshkent
 Samarqand
 Buxoro
```

### `UNION` — birlashma, takrorlanishlarni olib tashlab

`UNION` ikkita `SELECT`ning natijalarini birlashtiradi va **takrorlanuvchi qatorlarni avtomatik olib tashlaydi** (xuddi `DISTINCT` kabi):

```sql
SELECT shahar FROM mijozlar
UNION
SELECT joylashuv FROM bolimlar
ORDER BY shahar;
```

Natija — mijozlar VA ofislar joylashgan **barcha noyob** shaharlar:

```
  shahar   
-----------
 Andijon
 Buxoro
 Samarqand
 Toshkent
(4 rows)
```

`Toshkent` ikkala manbada ham (bir necha marta) uchrasa ham, natijada faqat **bir marta** ko'rinadi — `UNION`ning "avtomatik `DISTINCT`" xususiyati aynan shu.

### `UNION ALL` — birlashma, takrorlanishlarni saqlab

Agar sizga takrorlanishlarni olib tashlash kerak bo'lmasa (yoki ataylab **barcha** qatorlarni, hattoki takrorlansa ham, saqlab qolish kerak bo'lsa), `UNION ALL` ishlatiladi:

```sql
SELECT shahar FROM mijozlar
UNION ALL
SELECT joylashuv FROM bolimlar;
```

Bu — mijozlar jadvalidagi barcha 8 qator + bo'limlar jadvalidagi barcha 5 qator = jami **13** qator, hech qanday takrorlanish olib tashlanmasdan (`Toshkent` bir necha marta takrorlanadi).

> **Muhim unumdorlik farqi:** `UNION` ikkala natijani birlashtirgandan so'ng, takrorlanishlarni topish uchun **qo'shimcha saralash/solishtirish** ishini bajarishi kerak — bu katta natijalarda sezilarli xarajat bo'lishi mumkin. Agar sizga takrorlanishlar muhim bo'lmasa (masalan, ikkala manbada tabiiy ravishda takrorlanish bo'lishi mumkin emasligini bilsangiz) yoki ular ataylab kerak bo'lsa, `UNION ALL` har doim tezroq — chunki u hech qanday qo'shimcha ishlov bermaydi, shunchaki ikkala natijani ketma-ket "qo'shib qo'yadi". **Amaliy qoida:** agar aniq sabab bo'lmasa, standart tanlov sifatida `UNION ALL`ni ko'proq qo'llang, `UNION`ni esa faqat haqiqatan takrorlanishlarni olib tashlash zarur bo'lganda ishlating.

### `INTERSECT` — kesishma, ikkalasida ham bor qatorlar

`INTERSECT` faqat **ikkala** so'rov natijasida ham uchraydigan qatorlarni qaytaradi:

```sql
SELECT shahar FROM mijozlar
INTERSECT
SELECT joylashuv FROM bolimlar
ORDER BY shahar;
```

Natija — mijozlar VA ofislar **ikkalasi ham** mavjud shaharlar:

```
  shahar   
-----------
 Buxoro
 Samarqand
 Toshkent
(3 rows)
```

`Andijon` bu yerda yo'q — chunki u faqat `mijozlar`da bor, `bolimlar`da yo'q. Bu — "ikkala ro'yxatda ham bor narsalarni topish" degan klassik masala uchun juda qulay va o'qilishi oson yechim (muqobil ravishda `INNER JOIN` yoki `WHERE ... IN (...)` bilan ham yechish mumkin, lekin `INTERSECT` ko'pincha eng aniq va tushunarli variant).

### `EXCEPT` — ayirma, tartib muhim!

`EXCEPT` (ba'zi boshqa DBMS'larda, masalan Oracle'da, `MINUS` deb ham ataladi) birinchi so'rov natijasidan ikkinchi so'rov natijasida **ham bor** qatorlarni **ayiradi**:

```sql
SELECT shahar FROM mijozlar
EXCEPT
SELECT joylashuv FROM bolimlar
ORDER BY shahar;
```

Natija — mijoz bor, lekin ofis **yo'q** shaharlar:

```
 shahar  
---------
 Andijon
(1 row)
```

**Tomonlarning tartibi bu yerda hal qiluvchi ahamiyatga ega** — `A EXCEPT B` va `B EXCEPT A` odatda **butunlay boshqacha** natija beradi (matematik ayirmaning o'zi ham kommutativ emasligi kabi):

```sql
SELECT joylashuv FROM bolimlar
EXCEPT
SELECT shahar FROM mijozlar;
```

Bu — teskari savol: "ofis bor, lekin mijoz **yo'q** shaharlar". Bizning ma'lumotlarimizda bu so'rov **bo'sh natija** qaytaradi, chunki barcha uchta ofis shahri (Toshkent, Samarqand, Buxoro) da kamida bitta mijoz ham bor.

### Talab: ustunlar soni va turi mos kelishi shart

Barcha uchala to'plam amali (`UNION`, `INTERSECT`, `EXCEPT`) uchun umumiy qat'iy talab bor: **ikkala `SELECT`ning ustunlar soni bir xil, va mos keluvchi ustunlarning turlari bir-biriga mos (yoki avtomatik aylantirilishi mumkin) bo'lishi kerak.**

```sql
-- ❌ XATO: ustunlar soni mos kelmaydi
SELECT ism FROM mijozlar
UNION
SELECT ism, familiya FROM xodimlar;
```

```
ERROR:  each UNION query must have the same number of columns
```

Natijaviy ustunlarning **nomi** esa har doim **birinchi** `SELECT`dan olinadi — ikkinchi so'rovdagi ustun nomi (hatto boshqacha bo'lsa ham) e'tiborga olinmaydi:

```sql
SELECT shahar FROM mijozlar
UNION
SELECT joylashuv FROM bolimlar;
```

Bu yerda natija ustuni `shahar` deb nomlanadi (`joylashuv` emas) — chunki `shahar` birinchi `SELECT`da ko'rsatilgan.

### Uchtadan ortiq so'rovni zanjirlash

To'plam amallarini ketma-ket zanjirlash mumkin:

```sql
SELECT shahar FROM mijozlar
UNION
SELECT joylashuv FROM bolimlar
UNION
SELECT 'Namangan';  -- qo'lda qo'shilgan qiymat ham bo'lishi mumkin
```

Bu — uchta manbadan (ikkita jadval + bitta qo'lda kiritilgan qiymat) kelgan ma'lumotni bitta ustunga birlashtiradi.

## Amaliy misol

**Vazifa:** Kompaniyada ishlaydigan xodimlarning lavozimlari (`xodimlar.lavozim`) va mahsulot kategoriyalari (`mahsulotlar.kategoriya`) orasida umumiy so'z bor-yo'qligini tekshiring (bu — sof "mashq uchun mashq", amaliy ma'nosi yo'q, lekin `INTERSECT`ning ishlashini yaqqol ko'rsatadi).

```sql
SELECT lavozim AS nom FROM xodimlar
INTERSECT
SELECT kategoriya AS nom FROM mahsulotlar;
```

Bizning ma'lumotlarimizda bu so'rov **bo'sh natija** qaytaradi — chunki lavozimlar ("Dasturchi", "Sotuv boshligi" va h.k.) va mahsulot kategoriyalari ("Elektronika", "Mebel", "Maishiy texnika") orasida umuman bir xil matn yo'q. Bu — `INTERSECT`ning "hech narsa topilmasa, shunchaki bo'sh natija qaytaradi" xatti-harakatini ko'rsatadi (xato emas).

## Keng tarqalgan xatolar

**Xato 1:** `UNION`ni har doim standart tanlov sifatida ishlatib, `UNION ALL` tezroq bo'lishi mumkinligini unutish.
✅ Agar takrorlanishlar muammo emasligini bilsangiz (yoki ular umuman bo'lmasligini bilsangiz), `UNION ALL` ishlating.

**Xato 2:** `EXCEPT`da tomonlar tartibini e'tiborsiz qoldirib, natijani teskari talqin qilish.
❌ `A EXCEPT B` va `B EXCEPT A`ni bir xil deb o'ylash — bu **jiddiy** mantiqiy xato.
✅ Har doim "nimadan nimani ayiryapman" — deb, gap tuzilishini diqqat bilan o'qing: "birinchisi bor, ikkinchisida yo'q" = `birinchi EXCEPT ikkinchi`.

**Xato 3:** To'plam amali ustunlaridagi turlarni (masalan, `integer` va `text`) mos kelmasligini payqamaslik.
❌ `SELECT id FROM mijozlar UNION SELECT ism FROM mijozlar;` — `id` (integer) va `ism` (text) turlari bir-biriga to'g'ridan-to'g'ri mos kelmaydi, PostgreSQL xato beradi (yoki ba'zi hollarda kutilmagan avtomatik aylantirish sodir bo'lishi mumkin).
✅ Har doim ikkala tomonning ustun turlari mantiqan bir xil narsani ifodalashiga ishonch hosil qiling.

## Mashq/topshiriq

**(Oson)** `xodimlar.lavozim` va o'zingiz belgilagan uchta lavozim nomidan iborat qo'lda yozilgan ro'yxat (`SELECT 'Direktor' UNION SELECT 'Menejer' UNION SELECT 'Dasturchi'`) orasidagi `INTERSECT`ni toping.

**(O'rtacha)** `mijozlar.shahar` va `bolimlar.joylashuv` orasidagi barcha uchala to'plam amalini (`UNION`, `INTERSECT`, ikkala yo'nalishdagi `EXCEPT`) ketma-ket ishga tushirib, natijalarni solishtiring va har birining ma'nosini o'z so'zlaringiz bilan izohlang.

**(Qiyin)** `UNION ALL` yordamida, `mijozlar.shahar` va `bolimlar.joylashuv`ni birlashtirib, so'ng bu natijani `GROUP BY` bilan guruhlab, "har bir shahar mijoz sifatida va/yoki ofis sifatida jami necha marta uchraganini" hisoblang (bu — `UNION ALL` va `GROUP BY`ni birga ishlatishning amaliy namunasi).

```sql
SELECT shahar, count(*) AS jami_uchrash
FROM (

    SELECT joylashuv FROM bolimlar

GROUP BY shahar
ORDER BY jami_uchrash DESC;
```

## Qisqacha xulosa

To'plam amallari (`UNION`/`UNION ALL`, `INTERSECT`, `EXCEPT`) ikkita mustaqil `SELECT` so'rovining natijalarini matematik to'plamlar nazariyasi mantig'i bo'yicha vertikal birlashtiradi — mos ravishda birlashma, kesishma va ayirma sifatida. `UNION` takrorlanishlarni avtomatik olib tashlaydi (va shu sababli `UNION ALL`ga qaraganda sekinroq bo'lishi mumkin), `EXCEPT`da esa tomonlar tartibi natijaga tubdan ta'sir qiladi. Barcha uchala amal uchun ikkala tomonning ustunlar soni va turlari mos kelishi shart. Bu bilan 05-bob (To'plam operatsiyalari) yakunlanadi — keyingi, 06-bobda esa DDL (Data Definition Language) — `CREATE TABLE` va ma'lumotlar turlarini chuqur o'rganishni boshlaymiz.
