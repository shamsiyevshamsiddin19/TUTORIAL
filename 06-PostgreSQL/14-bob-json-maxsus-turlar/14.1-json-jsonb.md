# 14.1. `JSON` va `JSONB` — tuzilmasiz ma'lumotlar bilan ishlash

## Bu darsda nimalarni o'rganasiz

- `JSON` va `JSONB` turlari orasidagi farqni tushunasiz
- `->`, `->>`, `#>`, `#>>` operatorlari bilan JSON ichidan qiymat olishni o'rganasiz
- `@>` (containment) va `?` (mavjudlik) operatorlari bilan JSON bo'yicha filtrlashni bilasiz
- `jsonb_set()` bilan ichki qiymatni yangilashni, `-` operatori bilan kalitni o'chirishni o'rganasiz
- `jsonb_agg()`/`jsonb_build_object()` bilan oddiy SQL natijasidan JSON yasashni ko'rasiz

## Nazariy qism

### Nega bazada JSON kerak

Ushbu darslikning boshidan beri biz **qat'iy tuzilmali** (structured) ma'lumotlar bilan ishladik — har bir jadval oldindan aniq belgilangan ustunlarga ega edi (6-bob). Lekin real hayotda ba'zan ma'lumotning **tuzilmasi qatordan-qatorga farq qiladi** — masalan, turli toifadagi mahsulotlarning har biri o'zining noyob xususiyatlar to'plamiga ega bo'lishi mumkin (noutbukda "protsessor" bor, kitobda "muallif" bor). Buning uchun har bir mumkin bo'lgan xususiyat uchun alohida ustun ochish — g'ayritabiiy va noqulay bo'lar edi. PostgreSQL'ning `JSON`/`JSONB` turlari — bunday **yarim-tuzilmali** (semi-structured) ma'lumotni, qat'iy relyatsion jadval ichida, moslashuvchan tarzda saqlash imkonini beradi.

### `JSON` va `JSONB` — asosiy farq

```sql
SELECT '{"b": 1, "a": 2}'::json AS json_natija, '{"b": 1, "a": 2}'::jsonb AS jsonb_natija;
```

```
   json_natija    |   jsonb_natija   
-------------------+------------------
 {"b": 1, "a": 2} | {"a": 2, "b": 1}
```

Bu natija ikkalasi orasidagi asosiy farqni aniq ko'rsatadi:

| | `JSON` | `JSONB` |
|---|---|---|
| **Saqlash usuli** | Matn sifatida, **aynan kiritilgan holida** (bo'sh joylar, kalitlar tartibi saqlanadi) | Ikkilik (binary), **tahlil qilingan va qayta tartiblangan** holda |
| **Kalitlar tartibi** | Kiritilganidek saqlanadi | Ichki, samarali tartibga solinadi (yuqoridagi misolda `b, a` → `a, b`ga aylandi) |
| **Takroriy kalitlar** | Ruxsat etiladi (oxirgisi ishlatiladi, lekin barchasi saqlanadi) | Faqat oxirgisi saqlanadi |
| **Yozish tezligi** | Tezroq (shunchaki matn sifatida saqlanadi) | Sekinroq (yozishda tahlil qilinadi) |
| **O'qish/qidirish tezligi** | Sekinroq (har safar qayta tahlil qilinishi kerak) | Tezroq (allaqachon ikkilik formatda, indekslash ham mumkin — 18-bobda) |
| **Tavsiya** | Deyarli hech qachon (faqat original matnni **aynan** saqlash kerak bo'lgan noyob holatlarda) | **Amaliyotda deyarli har doim** `JSONB` ishlatiladi |

Shu sababli, ushbu darsning qolgan qismida faqat `JSONB`ga e'tibor qaratamiz — u amaliy PostgreSQL loyihalarida standart tanlov hisoblanadi.

### Jadval yaratish va JSON ma'lumot kiritish

```sql
CREATE TABLE mahsulot_xususiyatlari (
    id SERIAL PRIMARY KEY,
    nomi TEXT,
    xususiyatlar JSONB
);

INSERT INTO mahsulot_xususiyatlari (nomi, xususiyatlar) VALUES
('Noutbuk', '{"protsessor": "Intel i7", "ram_gb": 16, "rangi": "kulrang", "portlar": ["USB-C", "HDMI", "USB-A"]}'),
('Telefon', '{"protsessor": "Snapdragon 8", "ram_gb": 8, "rangi": "qora", "portlar": ["USB-C"]}');
```

Diqqat qiling — bitta ustun (`xususiyatlar`) ichida ikkita mahsulot **turli** to'plamdagi maydonlarni saqlamoqda, va bu 6-bobdagi qat'iy `CREATE TABLE` tuzilmasi bilan hech qanday ziddiyatga kelmaydi.

### `->` va `->>` — JSON ichidan qiymat olish

```sql
SELECT nomi,
       xususiyatlar -> 'protsessor' AS protsessor_json,
       xususiyatlar ->> 'protsessor' AS protsessor_matn,
       (xususiyatlar ->> 'ram_gb')::int AS ram_son
FROM mahsulot_xususiyatlari;
```

```
   nomi   | protsessor_json | protsessor_matn | ram_son 
----------+------------------+------------------+---------
 Noutbuk | "Intel i7"       | Intel i7         |      16
 Telefon | "Snapdragon 8"   | Snapdragon 8     |       8
```

`->` va `->>` orasidagi farq — **qaytariladigan tur**: `->` natijani `jsonb` turida qaytaradi (shuning uchun `"Intel i7"` tirnoqlar bilan ko'rinadi — bu JSON matn qiymati), `->>` esa uni to'g'ridan-to'g'ri PostgreSQL `text` turiga aylantiradi (tirnoqlarsiz). Agar JSON ichidagi qiymat bilan **matn** sifatida ishlashni yoki uni boshqa turga (`::int`, `::numeric`) aylantirishni xohlasangiz — `->>` kerak. Agar JSON ob'ekti/massivini olib, **yana bir operator bilan davom ettirmoqchi** bo'lsangiz (masalan, ichki massiv elementiga chuqurroq kirish) — `->` kerak.

### Ichki (nested) qiymatlarga chuqur murojaat

```sql
SELECT nomi, xususiyatlar -> 'portlar' -> 0 AS birinchi_port,
       xususiyatlar #>> '{portlar,0}' AS birinchi_port_matn
FROM mahsulot_xususiyatlari;
```

```
   nomi   | birinchi_port | birinchi_port_matn 
----------+----------------+---------------------
 Noutbuk | "USB-C"        | USB-C
 Telefon | "USB-C"        | USB-C
```

Bu yerda ikki xil yondashuv ko'rsatilgan: `xususiyatlar -> 'portlar' -> 0` — operatorlarni **zanjir** qilib, avval `portlar` massivini, so'ng uning `0`-indeksidagi (birinchi) elementini oladi (JSON massivlarida ham indeks `0`dan boshlanadi, PostgreSQL massivlaridan farqli — 14.2-darsda ko'rasiz). `#>>` — muqobil, **yo'l** (path) sintaksisi: `'{portlar,0}'` — bu "avval `portlar`ga, keyin uning `0`-elementiga bor" degan yagona ifoda, chuqur ichma-ich JSON tuzilmalar uchun ayniqsa qulay.

### `@>` (containment) va `?` (mavjudlik) — JSON bo'yicha filtrlash

```sql
SELECT nomi FROM mahsulot_xususiyatlari WHERE xususiyatlar @> '{"rangi": "qora"}';
```

```
   nomi   
----------
 Telefon
```

`@>` — "chapdagi JSON, o'ngdagi JSON'ni **o'z ichiga oladimi**" degan savolga javob beradi. Bu — WHERE bandida JSON bo'yicha filtrlashning eng tabiiy usuli (va, 18-bobda ko'rsatilganidek, GIN indeks bilan samarali tezlashtiriladi).

```sql
SELECT nomi FROM mahsulot_xususiyatlari WHERE xususiyatlar ? 'protsessor';
```

```
   nomi   
----------
 Noutbuk
 Telefon
```

`?` — "berilgan kalit JSON ob'ektida **mavjudmi**" degan savolga javob beradi (bu — 2.3-darsda ko'rgan `IS NULL`dan farqli: kalit "yo'q" bo'lishi, kalit "bor, lekin qiymati JSON `null`" bo'lishidan boshqa narsa).

`?` operatorini massiv ichidagi qidiruv uchun ham ishlatish mumkin:

```sql
SELECT nomi FROM mahsulot_xususiyatlari WHERE xususiyatlar -> 'portlar' ? 'HDMI';
```

```
   nomi   
----------
 Noutbuk
```

Faqat Noutbuk'ning `portlar` massivida `'HDMI'` bor — shuning uchun faqat u qaytarildi.

### JSON'ni o'zgartirish — `jsonb_set()` va `-` operatori

```sql
UPDATE mahsulot_xususiyatlari
SET xususiyatlar = jsonb_set(xususiyatlar, '{ram_gb}', '32')
WHERE nomi = 'Noutbuk';

SELECT nomi, xususiyatlar ->> 'ram_gb' AS ram FROM mahsulot_xususiyatlari WHERE nomi = 'Noutbuk';
```

```
   nomi   | ram 
----------+-----
 Noutbuk | 32
```

`jsonb_set(ustun, yol, yangi_qiymat)` — berilgan yo'ldagi qiymatni yangilaydi (butun `xususiyatlar` ustunini qayta yozmasdan). Diqqat qiling: yangi qiymat (`'32'`) ham **JSON qiymati** sifatida beriladi (agar `'"32"'` deb yozilsa, u matn sifatida saqlanardi, son sifatida emas).

Agar yo'l **mavjud bo'lmasa**, standart holatda `jsonb_set` hech narsa qilmaydi — to'rtinchi, ixtiyoriy argument (`true`) bilan yangi kalitni **yaratish**ga majburlash mumkin:

```sql
UPDATE mahsulot_xususiyatlari
SET xususiyatlar = jsonb_set(xususiyatlar, '{ombor_id}', '"A-12"', true)
WHERE nomi = 'Noutbuk';
```

Kalitni o'chirish esa `-` operatori bilan, juda sodda:

```sql
SELECT xususiyatlar - 'ombor_id' AS yangilangan FROM mahsulot_xususiyatlari WHERE nomi = 'Noutbuk';
```

```
                                                     yangilangan                                                      
------------------------------------------------------------------------------------------------------------------
 {"rangi": "kulrang", "ram_gb": 32, "portlar": ["USB-C", "HDMI", "USB-A"], "protsessor": "Intel i7"}
```

(Bu — faqat `SELECT` bilan ko'rsatilgan natija, haqiqiy o'chirish uchun buni `UPDATE ... SET xususiyatlar = xususiyatlar - 'ombor_id'` shaklida yozish kerak bo'lar edi.)

### Oddiy SQL natijasidan JSON yasash — `jsonb_agg()`/`jsonb_build_object()`

Yo'nalish teskarisiga ham ishlaydi: oddiy relyatsion qatorlarni JSON'ga "yig'ish" mumkin — bu, masalan, ilova backend qismiga to'g'ridan-to'g'ri JSON javob qaytarish kerak bo'lganda juda foydali:

```sql
SELECT jsonb_agg(jsonb_build_object('ism', ism, 'lavozim', lavozim)) AS xodimlar_json
FROM xodimlar WHERE bolim_id = 2;
```

```
                                                            xodimlar_json                                                            
----------------------------------------------------------------------------------------------------------------------------------
 [{"ism": "Sardor", "lavozim": "Dasturchi"}, {"ism": "Farrux", "lavozim": "Dasturchi"}, {"ism": "Aziz", "lavozim": "Bosh direktor"}]
```

`jsonb_build_object(kalit1, qiymat1, kalit2, qiymat2, ...)` — har bir qator uchun bitta JSON ob'ekt yaratadi (10.1-darsdagi `string_agg`ga konseptual jihatdan o'xshash — u ham agregat funksiya), `jsonb_agg()` esa bu ob'ektlarni bitta JSON **massiviga** yig'adi. Natijada, bitta SQL so'rovi orqali, to'g'ridan-to'g'ri ilova kutayotgan JSON formatidagi javob olindi.

## Amaliy misol

**Vazifa:** Har bir mahsulot uchun, uning `portlar` massividagi elementlar sonini va `USB-C` porti bor-yo'qligini ko'rsating.

```sql
SELECT nomi,
       jsonb_array_length(xususiyatlar -> 'portlar') AS portlar_soni,
       xususiyatlar -> 'portlar' ? 'USB-C' AS usb_c_bormi
FROM mahsulot_xususiyatlari;
```

## Keng tarqalgan xatolar

**Xato 1:** Har doim `JSON`ni `JSONB`dan afzal ko'rish, chunki u "asl matnni saqlaydi".
❌ Aksariyat holatlarda bu foyda emas, balki keraksiz — siz JSON'ni qayta-qayta o'qiyotgan bo'lasiz, va `JSON` har safar uni qaytadan tahlil qiladi.
✅ Faqat original matn formatini (masalan, kalitlar tartibini) **aniq** saqlash kerak bo'lgan noyob holatlardan tashqari, har doim `JSONB` ishlating.

**Xato 2:** `->` va `->>`ni farqlamasdan, `->`  natijasini to'g'ridan-to'g'ri boshqa turga aylantirishga urinish.
❌ `(xususiyatlar -> 'ram_gb')::int` — bu ba'zan ishlaydi, lekin natija atrofida qo'shimcha tirnoq/formatlash muammolari keltirib chiqarishi mumkin.
✅ Qiymatni boshqa turga aylantirmoqchi bo'lsangiz, har doim `->>`dan boshlang: `(xususiyatlar ->> 'ram_gb')::int`.

**Xato 3:** JSON ob'ektida kalit "yo'qligi" bilan kalitning qiymati JSON `null` bo'lishini adashtirish.
❌ `xususiyatlar ->> 'mavjud_bolmagan_kalit'` va `xususiyatlar ->> 'null_qiymatli_kalit'` — ikkalasi ham SQL `NULL` qaytaradi, lekin ular **kontseptual jihatdan boshqacha**.
✅ Agar farq muhim bo'lsa, `xususiyatlar ? 'kalit'` (mavjudlik) bilan alohida tekshiring.

## Mashq/topshiriq

**(Oson)** `mahsulot_xususiyatlari` jadvalidagi har bir mahsulot uchun `rangi` va `ram_gb` qiymatlarini alohida ustunlar sifatida chiqaring (`->>` ishlatib).

**(O'rtacha)** `ram_gb` qiymati `10`dan katta bo'lgan mahsulotlarni toping (JSON qiymatini son turiga aylantirib, `WHERE` bandida solishtiring).

**(Qiyin)** `mijozlar` jadvalidagi barcha mijozlarni, har biri `{"ism": ..., "shahar": ...}` shaklidagi JSON ob'ektiga aylantirib, ularning barchasini bitta JSON massiviga (`jsonb_agg`) yig'ing.

## Qisqacha xulosa

`JSONB` — PostgreSQL'da yarim-tuzilmali ma'lumotni, qat'iy relyatsion jadval ichida moslashuvchan tarzda saqlash imkonini beradi, va amaliyotda `JSON`dan deyarli har doim afzal ko'riladi (tezroq o'qish, indekslash imkoniyati). `->`/`->>` — qiymat olish uchun, `@>`/`?` — filtrlash uchun, `jsonb_set()`/`-` — o'zgartirish uchun, `jsonb_agg()`/`jsonb_build_object()` esa — oddiy SQL natijasidan JSON yasash uchun ishlatiladi. Keyingi darsda PostgreSQL'ning boshqa maxsus ma'lumot turlarini — massivlar (`ARRAY`), sanab o'tiladigan turlar (`ENUM`) va `UUID`ni — o'rganamiz.
