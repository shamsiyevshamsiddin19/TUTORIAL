# 2.1. `datetime` — Django'ning `timezone.now()` ostida nima yotadi

## Bu darsda nimalarni o'rganasiz

- `datetime.datetime` obyekti bilan sana-vaqtni yaratish va ustida amallar bajarishni o'rganasiz
- **naive** va **aware** datetime orasidagi farqni tushunasiz — bu Django'da eng ko'p adashtiradigan mavzulardan biri
- `USE_TZ` sozlamasi va `django.utils.timezone.now()` nega oddiy `datetime.now()` o'rniga tavsiya etilishini bilib olasiz
- `timedelta` bilan sana ustida hisob-kitob qilishni (masalan "3 kundan keyin") o'rganasiz

## Nazariy qism

### `datetime` asoslari

`datetime` moduli sana va vaqt bilan ishlash uchun standart vosita. Asosiy klass — `datetime.datetime`:

```python
from datetime import datetime, timedelta

hozir = datetime.now()
print(hozir)                        # 2026-09-08 14:32:07.123456
print(hozir.year, hozir.month, hozir.day)   # 2026 9 8

ertaga = hozir + timedelta(days=1)
uch_kundan_keyin = hozir + timedelta(days=3, hours=2)
```

`timedelta` — vaqt oralig'ini ifodalaydi (kun, soat, minut, sekund), va `datetime` obyektlariga qo'shish/ayirish mumkin. Ikki sana orasidagi farqni topish ham `timedelta` qaytaradi:

```python
buyurtma_sana = datetime(2026, 9, 1)
farq = hozir - buyurtma_sana
print(farq.days)   # necha kun o'tgani
```

### Naive va aware datetime — Django'dagi eng muhim farq

`datetime.now()` qaytargan obyekt — **naive** (soddalashtirilgan): u faqat "yil-oy-kun soat:minut" biladi, lekin **qaysi vaqt zonasida** ekanini bilmaydi. Bu, aslida, "soat 14:32" deyish bilan bir xil — Toshkentdami, Londondami, aniq emas.

**Aware** datetime — vaqt zonasi ma'lumoti (`tzinfo`) biriktirilgan holda:

```python
from datetime import datetime, timezone as dt_timezone

naive = datetime.now()                              # tzinfo yo'q
aware = datetime.now(dt_timezone.utc)                # tzinfo = UTC

print(naive.tzinfo)   # None
print(aware.tzinfo)   # datetime.timezone.utc
```

Django ko'p foydalanuvchili, turli mintaqadagi odamlar kirishi mumkin bo'lgan veb-ilova uchun mo'ljallangan — shuning uchun u **doim aware** datetime bilan ishlashni tavsiya qiladi (`settings.py`da `USE_TZ = True`, Django 5'da bu standart holat). Sabab: agar barcha vaqtlar bazada UTC (aware) sifatida saqlansa, keyin foydalanuvchiga uning o'z mintaqasidagi vaqtga aylantirish oson va xatosiz bo'ladi. Aralash (ba'zi joyda naive, ba'zi joyda aware) kod esa `TypeError: can't subtract offset-naive and offset-aware datetimes` xatosiga olib keladi.

### `django.utils.timezone.now()` — nega oddiy `datetime.now()` emas

```python
from django.utils import timezone

hozir = timezone.now()
print(hozir.tzinfo)   # UTC (agar USE_TZ = True bo'lsa)
```

0.1-darsda ko'rganingizdek, `timezone.now()`ning ichida shunga o'xshash kod bor:

```python
def now():
    if settings.USE_TZ:
        return datetime.now(tz=timezone.utc)
    return datetime.now()
```

Ya'ni `timezone.now()` — `settings.USE_TZ`ga qarab, avtomatik ravishda **aware** yoki **naive** datetime qaytaradi, shunda dasturchi sozlamaga mos kelmaydigan qiymat yaratib qo'ymaydi. `models.DateTimeField(auto_now_add=True)` ham ichida aynan shu `timezone.now()`dan foydalanadi.

## Amaliy misol

`onlayn_dokon`da `Buyurtma` modeliga, "buyurtma qachon yetkazib berilishi kutilayotgani"ni hisoblovchi metod qo'shamiz:

```python
# apps/buyurtmalar/models.py
from datetime import timedelta

from django.db import models
from django.utils import timezone


class Buyurtma(models.Model):
    mijoz = models.ForeignKey("mijozlar.Mijoz", on_delete=models.CASCADE)
    yaratilgan_sana = models.DateTimeField(auto_now_add=True)
    yetkazish_muddati_kun = models.PositiveSmallIntegerField(default=3)

    def kutilayotgan_yetkazish_sanasi(self):
        """Buyurtma yaratilgan sanaga yetkazish muddatini qo'shib qaytaradi."""
        return self.yaratilgan_sana + timedelta(days=self.yetkazish_muddati_kun)

    def kechikkanmi(self):
        """Kutilayotgan sana o'tib ketgan, lekin hali yetkazilmagan bo'lsa True."""
        return timezone.now() > self.kutilayotgan_yetkazish_sanasi()
```

Shell'da tekshiramiz:

```python
>>> from apps.buyurtmalar.models import Buyurtma
>>> b = Buyurtma.objects.first()
>>> b.yaratilgan_sana
datetime.datetime(2026, 9, 1, 10, 0, tzinfo=datetime.timezone.utc)
>>> b.kutilayotgan_yetkazish_sanasi()
datetime.datetime(2026, 9, 4, 10, 0, tzinfo=datetime.timezone.utc)
>>> b.kechikkanmi()
True
```

E'tibor bering: `timezone.now()` bilan `self.yaratilgan_sana`ni solishtirish (`>`) muammosiz ishladi — chunki ikkalasi ham **aware**. Agar `b.yaratilgan_sana` naive bo'lganida (masalan qo'lda `datetime.now()` bilan yaratilgan bo'lsa), bu solishtirish xato berardi.

## Keng tarqalgan xatolar

**Xato 1:** Modelda yoki view'da `datetime.now()`ni `timezone.now()` o'rniga ishlatish.

❌ `yaratilgan_sana = datetime.now()` — `USE_TZ = True` bo'lganda bu **naive** datetime yaratadi, keyinroq bazadan olingan (aware) sana bilan solishtirilganda `TypeError: can't compare offset-naive and offset-aware datetimes` xatosiga olib keladi.

✅ Django loyihasida sana-vaqt kerak bo'lganda har doim `django.utils.timezone.now()`dan foydalaning, `datetime.now()`ni deyarli hech qachon to'g'ridan-to'g'ri chaqirmang.

**Xato 2:** Ikki xil turdagi (naive va aware) datetime'ni birga solishtirish yoki ayirish.

❌ `farq = timezone.now() - datetime(2026, 1, 1)` — ikkinchisi naive (`datetime(...)` to'g'ridan-to'g'ri chaqirilgan, `tzinfo` yo'q), birinchisi aware — `TypeError` beradi.

✅ Ikkalasini ham aware qiling: `datetime(2026, 1, 1, tzinfo=timezone.utc)`, yoki Django'ning `django.utils.timezone.make_aware()` funksiyasidan foydalaning: `timezone.make_aware(datetime(2026, 1, 1))`.

**Xato 3:** `timedelta`da oy yoki yilni to'g'ridan-to'g'ri ishlatishga urinish.

❌ `keyingi_oy = hozir + timedelta(months=1)` — `TypeError: unexpected keyword argument 'months'` beradi, chunki `timedelta` faqat kun, soat, minut, sekund, millisekund, mikrosekund va hafta qabul qiladi — oy va yil **doimiy uzunlikka ega emas** (fevral 28/29 kun, boshqa oylar 30/31), shuning uchun standart kutubxonada yo'q.

✅ Oy/yil bilan hisob-kitob uchun `python-dateutil` kutubxonasidagi `relativedelta`dan foydalaning (`pip install python-dateutil`), yoki oddiy holatlar uchun `calendar` modulidan yordam oling.

## Mashq/topshiriq

**(Oson)** Shell'da `from django.utils import timezone; print(timezone.now())` va `from datetime import datetime; print(datetime.now())` ikkalasini chiqarib, `.tzinfo` xossalarini solishtiring.

**(O'rtacha)** `Buyurtma` modeliga `soatlar_qoldi()` metodini qo'shing — u `kutilayotgan_yetkazish_sanasi()` bilan `timezone.now()` orasidagi farqni soatlarda (butun son) qaytarsin (`timedelta.total_seconds() / 3600` dan foydalaning).

**(Qiyin)** `onlayn_dokon`da so'nggi 7 kun ichida yaratilgan barcha buyurtmalarni topuvchi management command yozing: `Buyurtma.objects.filter(yaratilgan_sana__gte=timezone.now() - timedelta(days=7))`. Natijani sana bo'yicha (eng yangisi birinchi) tartiblab chiqaring va har biriga necha kun oldin yaratilganini (`(timezone.now() - b.yaratilgan_sana).days`) ko'rsating.

## Qisqacha xulosa

`datetime.datetime` — sana-vaqtni ifodalaydi, `timedelta` esa vaqt oralig'ini; ikkalasi birga sana ustida hisob-kitob qilish imkonini beradi. Django'da eng muhim tushuncha — **naive** (vaqt zonasisiz) va **aware** (vaqt zonasi biriktirilgan) datetime farqi: `USE_TZ = True` bo'lganda (Django 5'da standart) doim aware qiymatlar bilan ishlash kerak, va buning uchun `datetime.now()` emas, `django.utils.timezone.now()` ishlatiladi. Aralash naive/aware qiymatlar solishtirilsa, `TypeError` chiqadi — bu Django'dagi eng ko'p uchraydigan sana bilan bog'liq xato. Keyingi darsda — foydalanuvchiga vaqtni uning o'z mintaqasida (masalan Toshkent yoki London) ko'rsatish uchun `zoneinfo`ni ko'ramiz.
