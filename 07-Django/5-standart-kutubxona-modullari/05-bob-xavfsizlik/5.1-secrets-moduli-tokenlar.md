# 5.1. `secrets` moduli — parolni tiklash tokeni, API kaliti generatsiyasi

## Bu darsda nimalarni o'rganasiz

- Nega xavfsizlik uchun kerak bo'lgan tasodifiy qiymatlarga oddiy `random` modulini ishlatib bo'lmasligini tushunasiz
- `secrets.token_urlsafe()`, `secrets.token_hex()` va `secrets.choice()` bilan kriptografik xavfsiz tasodifiy qiymat yaratishni o'rganasiz
- Django'ning `get_random_string()` funksiyasi (0.1-darsda ko'rilgan) ostida `secrets` qanday ishlashini bilib olasiz
- Real vazifa — parolni tiklash tokeni va API kaliti generatsiya qiluvchi mexanizm yozasiz

## Nazariy qism

### Nega `random` xavfsizlik uchun yaramaydi

Python'ning oddiy `random` moduli — **pseudo-random** (psevdo-tasodifiy) generator: u matematik algoritm (Mersenne Twister) yordamida "tasodifga o'xshash" ketma-ketlik hosil qiladi, lekin bu ketma-ketlik boshlang'ich qiymatdan (seed) **to'liq bashorat qilinadi**. Agar hujumchi generatorning ichki holatini (yoki hatto bir nechta oldingi natijani) bilsa, keyingi barcha "tasodifiy" qiymatlarni hisoblab chiqarishi mumkin. Oddiy o'yin yoki simulyatsiya uchun bu muammo emas, lekin **parolni tiklash tokeni** yoki **API kaliti** kabi xavfsizlik uchun muhim qiymat uchun — bu jiddiy zaiflik.

```python
import random

# XAVFLI — token/parol uchun ishlatmang!
token = "".join(random.choices("abcdef0123456789", k=32))
```

### `secrets` — kriptografik xavfsiz tasodifiylik

`secrets` moduli (Python 3.6dan) — operatsion tizimning **kriptografik xavfsiz** tasodifiy manbasidan (masalan Linux'da `/dev/urandom`) foydalanadi, bashorat qilib bo'lmaydigan qiymat yaratadi:

```python
import secrets

secrets.token_hex(16)        # 'a3f5c8...` — 32 ta hex belgi (16 bayt)
secrets.token_urlsafe(32)    # 'kQ8x...` — URL'da xavfsiz ishlatsa bo'ladigan string
secrets.choice(["A", "B", "C"])   # tasodifiy bitta elementni tanlaydi
secrets.randbelow(100)       # 0 dan 99 gacha tasodifiy son
```

| Funksiya | Natija turi | Qachon ishlatiladi |
|---|---|---|
| `token_hex(n)` | `n*2` ta hex belgi | Ichki tokenlar, bazada saqlash |
| `token_urlsafe(n)` | taxminan `1.3*n` belgi, URL-xavfsiz | Emailga yuboriladigan havola, URL parametri |
| `choice(ketma-ketlik)` | ketma-ketlik elementi | Bitta elementni tasodifiy tanlash (masalan parol generatori uchun harf) |

### Django'ning `get_random_string()`

0.1-darsda ko'rganingizdek, Django'ning `django.utils.crypto.get_random_string()` funksiyasi zamonaviy versiyalarda `secrets`ga tayanadi (`secrets.choice()` orqali). Bu funksiya Django ichida `SECRET_KEY` generatsiya qilishda (`django-admin startproject` bajarilganda) va sessiya kalitlarini yaratishda ishlatiladi:

```python
from django.utils.crypto import get_random_string

token = get_random_string(length=32)
```

Ya'ni: agar loyihangizda token kerak bo'lsa, ikkita to'g'ri variant bor — standart kutubxonaning o'z `secrets` moduli, yoki Django'ning ustiga qo'shimcha qulayliklar (masalan belgilar to'plamini tanlash) qo'shgan `get_random_string()`. Ikkalasi ham xavfsiz — chunki ikkalasi ham tub-tubida bitta manbaga (operatsion tizimning kriptografik generatoriga) tayanadi.

## Amaliy misol

`onlayn_dokon`da "parolni unutdim" funksiyasi uchun, xavfsiz, muddati cheklangan token yaratamiz:

```python
# apps/mijozlar/models.py
import secrets
from datetime import timedelta

from django.db import models
from django.utils import timezone


class ParolTiklashTokeni(models.Model):
    mijoz = models.ForeignKey("mijozlar.Mijoz", on_delete=models.CASCADE)
    token = models.CharField(max_length=64, unique=True, editable=False)
    yaratilgan_vaqt = models.DateTimeField(auto_now_add=True)
    ishlatilganmi = models.BooleanField(default=False)

    def save(self, *args, **kwargs):
        if not self.token:
            self.token = secrets.token_urlsafe(32)
        super().save(*args, **kwargs)

    def amal_qiladimi(self):
        muddat_tugagan = timezone.now() > self.yaratilgan_vaqt + timedelta(hours=1)
        return not self.ishlatilganmi and not muddat_tugagan
```

View'da tokenni tekshirib, parolni tiklaymiz:

```python
# apps/mijozlar/views.py
from django.contrib.auth.hashers import make_password
from django.http import HttpResponseBadRequest
from django.shortcuts import get_object_or_404, redirect, render

from .models import ParolTiklashTokeni


def parolni_tikla(request, token):
    tiklash = get_object_or_404(ParolTiklashTokeni, token=token)

    if not tiklash.amal_qiladimi():
        return HttpResponseBadRequest("Token muddati o'tgan yoki allaqachon ishlatilgan")

    if request.method == "POST":
        yangi_parol = request.POST["yangi_parol"]
        foydalanuvchi = tiklash.mijoz.foydalanuvchi
        foydalanuvchi.password = make_password(yangi_parol)
        foydalanuvchi.save()

        tiklash.ishlatilganmi = True
        tiklash.save(update_fields=["ishlatilganmi"])

        return redirect("kirish")

    return render(request, "mijozlar/parolni_tikla.html", {"token": token})
```

E'tibor bering: token bazada **to'g'ridan-to'g'ri** (`secrets.token_urlsafe(32)`) saqlanmoqda — bu maqsadga muvofiq, chunki tokenning o'zi allaqachon bashorat qilib bo'lmaydigan, bir martalik, tez muddati o'tadigan qiymat (parolning o'zidan farqli, uni hash qilish shart emas, garchi qo'shimcha ehtiyot chorasi sifatida `hashlib` bilan hashlash ham mumkin — buni 5.2-darsda ko'ramiz).

## Keng tarqalgan xatolar

**Xato 1:** Token yoki API kalit uchun `random`, `uuid.uuid4()` yoki `id`ga asoslangan qiymat ishlatish.

❌ `token = str(uuid.uuid4())` — `uuid4` ham aslida `os.urandom` orqali ishlaydigan, kriptografik jihatdan yetarlicha xavfsiz, lekin **maxsus shu maqsad uchun mo'ljallanmagan** (format qat'iy belgilangan, 122 bit tasodifiylik) — token/parol kabi holatlar uchun `secrets` moduli **to'g'ridan-to'g'ri shu maqsad uchun** yaratilgan va moslashuvchan (kerakli uzunlikni tanlash imkoni).

✅ Xavfsizlik uchun mo'ljallangan tokenlarda har doim `secrets.token_urlsafe()` yoki `secrets.token_hex()`dan foydalaning — bu niyatni ham aniq ko'rsatadi (kodni o'qigan boshqa dasturchi darhol "bu xavfsizlik uchun" deb tushunadi).

**Xato 2:** Token uzunligini juda qisqa qilib tanlash.

❌ `secrets.token_hex(4)` — bu atigi 8 ta hex belgi (32 bit), zamonaviy kompyuter bir necha soniyada barcha variantlarni "sinab ko'rishi" (brute-force) mumkin.

✅ Xavfsizlik uchun kamida 16 bayt (`token_hex(16)` — 32 belgi, yoki `token_urlsafe(32)`) ishlating — bu amalda "sinab topib bo'lmaydigan" darajada katta fazoni beradi.

**Xato 3:** Tokenning muddatini tekshirmaslik yoki bir martalik ekanligini ta'minlamaslik.

❌ `ParolTiklashTokeni`ni yaratib, lekin `amal_qiladimi()` kabi tekshiruvsiz, faqat `token` mavjudligini (`get_object_or_404`) tekshirish — bu holda eski, hatto bir marta ishlatilgan token ham cheksiz qayta ishlatilishi mumkin.

✅ Har doim ikki qo'shimcha tekshiruv qo'shing: **muddat** (masalan 1 soat) va **bir martalik ishlatish belgisi** (`ishlatilganmi`) — token faqat ikkalasi ham to'g'ri bo'lganda amal qilsin (yuqoridagi amaliy misoldagi `amal_qiladimi()` kabi).

## Mashq/topshiriq

**(Oson)** Shell'da `import secrets; secrets.token_hex(16)`ni ikki marta ketma-ket chaqiring va natijalar har safar boshqacha ekanini tasdiqlang.

**(O'rtacha)** `ParolTiklashTokeni`ga `token_uzunligi_tekshiruvi` deb nomlangan validatsiya qo'shing: modelni saqlashdan oldin, `token` maydoni kamida 32 belgidan iborat ekanini tekshirsin, aks holda `ValueError` chaqirsin.

**(Qiyin)** `onlayn_dokon` uchun API kaliti (`ApiKalit` modeli) yarating: har bir kalit `secrets.token_urlsafe(40)` bilan yaratilsin, va model foydalanuvchiga faqat kalit **birinchi marta yaratilganda** to'liq ko'rsatilsin (masalan `create()` classmethod orqali `(obyekt, tolik_kalit)` tuple qaytaring), keyinchalik esa faqat kalitning oxirgi 4 belgisi (`kalit[-4:]`) saqlanib, admin panelda "ko'rsatilsin" (to'liq kalitning o'zi bazada **hash qilingan holda** saqlanishi kerak — buni 5.2-darsda `hashlib` bilan tugallaymiz).

## Qisqacha xulosa

`secrets` moduli — parol, token, API kalit kabi xavfsizlik uchun muhim qiymatlar yaratish uchun mo'ljallangan, chunki u operatsion tizimning kriptografik xavfsiz tasodifiy manbasidan foydalanadi — oddiy `random` moduli esa bashorat qilinishi mumkinligi sababli bunday holatlar uchun **hech qachon** ishlatilmasligi kerak. `token_hex()` va `token_urlsafe()` — eng ko'p ishlatiladigan funksiyalar, Django'ning `get_random_string()`i ham tub-tubida shu modulga tayanadi. Har qanday token — muddati va bir martalik ishlatilishi bo'yicha ham tekshirilishi kerak, aks holda uning xavfsizligi cheklangan bo'lib qoladi. Keyingi darsda — fayl checksumlari va tokenlarni bazada xavfsiz saqlash uchun `hashlib` modulini ko'ramiz.
