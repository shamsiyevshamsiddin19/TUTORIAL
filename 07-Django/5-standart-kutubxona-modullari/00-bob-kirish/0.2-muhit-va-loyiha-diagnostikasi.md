# 0.2. `sys` va `platform` — ishlash muhiti haqida ma'lumot olish

## Bu darsda nimalarni o'rganasiz

- `sys` moduli orqali Python versiyasi, ishga tushirish argumentlari va modul qidirish yo'llarini (`sys.path`) o'qiy olasiz
- `platform` moduli orqali operatsion tizim va protsessor arxitekturasi haqida ma'lumot olasiz
- Django loyihasida "bu server qanday muhitda ishlayapti" degan savolga tez javob beradigan diagnostika buyrug'ini yoza olasiz
- `sys.path` bilan `ModuleNotFoundError` orasidagi bog'liqlikni tushunasiz

## Nazariy qism

### `sys` — Python jarayoni haqidagi ma'lumot

`sys` moduli — ishlab turgan Python jarayonining o'zi haqida ma'lumot beradi: qaysi versiya, qaysi argumentlar bilan ishga tushirilgan, modullarni qayerdan qidiryapti.

```python
>>> import sys
>>> sys.version
'3.12.3 (main, Apr 10 2024, 05:33:47) [GCC 13.2.0]'
>>> sys.version_info
sys.version_info(major=3, minor=12, micro=3, releaselevel='final', serial=0)
>>> sys.platform
'linux'
```

`sys.version_info` — versiyani dasturiy taqqoslash uchun qulay, chunki u tuple kabi ishlaydi:

```python
if sys.version_info < (3, 10):
    raise RuntimeError("Bu loyiha Python 3.10+ talab qiladi")
```

`sys.path` — Python `import` qilganda qaysi papkalarni qidirishini ko'rsatuvchi ro'yxat. `ModuleNotFoundError: No module named 'onlayn_dokon'` xatosining aksariyati aynan shu ro'yxatda kerakli papka yo'qligidan kelib chiqadi:

```python
>>> import sys
>>> sys.path
['', '/home/user/onlayn_dokon', '/usr/lib/python3.12',
 '/home/user/venv/lib/python3.12/site-packages', ...]
```

`manage.py` ishga tushganda, Django avtomatik ravishda loyiha papkasini (`BASE_DIR`) shu ro'yxatga qo'shadi — shuning uchun `onlayn_dokon/settings.py` ichidan `from apps.mahsulotlar.models import Mahsulot` kabi import ishlaydi.

### `platform` — operatsion tizim haqida ma'lumot

`platform` moduli — qaysi operatsion tizimda, qaysi protsessor arxitekturasida ishlab turganingizni aniqlaydi:

```python
>>> import platform
>>> platform.system()
'Linux'
>>> platform.machine()
'x86_64'
>>> platform.python_implementation()
'CPython'
```

Bu ayniqsa deploy paytida foydali: rivojlantirish (development) kompyuteringiz macOS yoki Windows bo'lishi, lekin production server har doim Linux (odatda Ubuntu/Debian, Docker konteyner ichida) bo'lishi mumkin — ikkalasida bir xil ishlaydigan kod yozish uchun, farqlarni bilish kerak (masalan fayl yo'li ajratkichi: Windows'da `\`, Linuxda `/` — buni 1.1-darsda `pathlib` avtomatik hal qilishini ko'ramiz).

### Nega bu Django loyihasida kerak

Real loyihalarda ba'zan "mening kompyuterimda ishlayapti, serverda ishlamayapti" degan holat uchraydi. Sababi ko'pincha muhit farqi: boshqa Python versiyasi, boshqa operatsion tizim, yoki `sys.path`da kutilmagan papka. `sys` va `platform` — bunday muammoni diagnostika qilishning birinchi qadami.

## Amaliy misol

`onlayn_dokon` loyihasiga muhit haqida ma'lumot beruvchi maxsus management command qo'shamiz — bu buyruq production serverga kirib, u yerdagi muhitni tezda tekshirish uchun foydali:

```python
# apps/core/management/commands/muhit_malumoti.py
import sys
import platform

from django.core.management.base import BaseCommand
from django.conf import settings


class Command(BaseCommand):
    help = "Loyiha ishlab turgan muhit haqida diagnostik ma'lumot chiqaradi"

    def handle(self, *args, **options):
        self.stdout.write(self.style.SUCCESS("=== Muhit ma'lumoti ==="))
        self.stdout.write(f"Python versiyasi: {platform.python_version()}")
        self.stdout.write(f"Implementatsiya:  {platform.python_implementation()}")
        self.stdout.write(f"Operatsion tizim: {platform.system()} ({platform.machine()})")
        self.stdout.write(f"DEBUG rejimi:     {settings.DEBUG}")
        self.stdout.write(f"Ishga tushirish yo'li: {sys.executable}")

        if sys.version_info < (3, 10):
            self.stdout.write(self.style.WARNING(
                "Diqqat: Python 3.10 dan eski versiya, ba'zi zamonaviy sintaksis ishlamasligi mumkin"
            ))
```

Terminalda:

```bash
python manage.py muhit_malumoti
```

```
=== Muhit ma'lumoti ===
Python versiyasi: 3.12.3
Implementatsiya:  CPython
Operatsion tizim: Linux (x86_64)
DEBUG rejimi:     False
Ishga tushirish yo'li: /home/user/venv/bin/python
```

`sys.executable` — aynan qaysi Python fayli (qaysi venv) ishga tushganini ko'rsatadi. Bu, masalan, "nega mening `pip install`im ta'sir qilmadi" degan muammoni tezda hal qiladi — ko'pincha sabab noto'g'ri venv faollashtirilgan bo'ladi.

## Keng tarqalgan xatolar

**Xato 1:** Versiyani satr (string) sifatida solishtirish.

❌ `if platform.python_version() > "3.9":` — bu string taqqoslash, `"3.10" > "3.9"` natijasi **`False`** bo'ladi (chunki `"1" < "9"` belgi-ma-belgi solishtiriladi), garchi 3.10 aslida 3.9dan yangi bo'lsa ham.

✅ `sys.version_info` bilan solishtiring: `if sys.version_info >= (3, 10):` — bu tuple sifatida to'g'ri, sonli taqqoslaydi.

**Xato 2:** `sys.path`ga qo'lda papka qo'shishni "doimiy yechim" deb hisoblash.

❌ Har bir faylda `sys.path.append("/home/user/onlayn_dokon")` yozish — bu loyihani boshqa kompyuterga ko'chirganda ishlamay qoladi (yo'l qattiq yozilgan) va Django'ning o'z import mexanizmini chetlab o'tadi.

✅ Django loyihasida bunga deyarli hech qachon ehtiyoj yo'q — `manage.py` va to'g'ri paket strukturasi (har `apps/` ichida `__init__.py`) buni avtomatik hal qiladi; agar `ModuleNotFoundError` chiqsa, muammoni `sys.path.append` bilan "yopish" o'rniga, nega Django uni topa olmayotganini (masalan `INSTALLED_APPS`da yo'qligi) tekshiring.

**Xato 3:** `platform.system()` natijasini katta-kichik harfga e'tibor bermay solishtirish.

❌ `if platform.system() == "linux":` — bu hech qachon `True` bo'lmaydi, chunki natija katta harf bilan boshlanadi: `'Linux'`.

✅ `if platform.system() == "Linux":` yozing, yoki xavfsizroq: `.lower()` qo'llang — `if platform.system().lower() == "linux":`.

## Mashq/topshiriq

**(Oson)** `python manage.py shell`da `sys.version_info` va `platform.python_version()`ni chiqarib, ikkalasi ham bir xil versiyani ko'rsatayotganini tasdiqlang.

**(O'rtacha)** Yuqoridagi `muhit_malumoti` buyrug'iga yana bitta qator qo'shing: `sys.path`dagi elementlar sonini (`len(sys.path)`) chiqaring va shu ro'yxat ichida loyihangizning `BASE_DIR`i borligini (`str(settings.BASE_DIR) in sys.path`) tekshiring.

**(Qiyin)** `muhit_malumoti` buyrug'iga versiya tekshiruvi qo'shing: agar `sys.version_info < (3, 10)` bo'lsa, buyruq `self.style.ERROR(...)` bilan xato chiqarib, `sys.exit(1)` orqali dasturni to'xtatsin (bu, masalan, deploy skriptida "eski Python bilan ishga tushirilmasin" degan himoya bo'lishi mumkin).

## Qisqacha xulosa

`sys` moduli — ishlab turgan Python jarayoni haqida (versiya, ishga tushirish yo'li, modul qidirish yo'llari), `platform` moduli esa operatsion tizim va arxitektura haqida ma'lumot beradi; ikkalasi ham `pip install`siz, doim qo'l ostida. Ular ayniqsa "bu yerda ishlaydi, u yerda ishlamaydi" turidagi muammolarni diagnostika qilishda, va versiyaga bog'liq shartlarni (`sys.version_info` bilan, hech qachon string taqqoslash bilan emas) yozishda foydali. Endi muhitni tanigandan so'ng, keyingi bobda loyihaning o'zi — fayl va papkalar bilan qanday xavfsiz ishlashni ko'ramiz.
