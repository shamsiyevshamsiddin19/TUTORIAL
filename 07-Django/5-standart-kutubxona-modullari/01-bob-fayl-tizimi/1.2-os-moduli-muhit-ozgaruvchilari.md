# 1.2. `os` moduli — muhit o'zgaruvchilari va papka amallari

## Bu darsda nimalarni o'rganasiz

- `os.environ` orqali muhit o'zgaruvchilarini (environment variables) o'qiy olasiz
- Nega maxfiy ma'lumotlar (`SECRET_KEY`, parollar) kodga emas, muhit o'zgaruvchilariga yozilishini tushunasiz
- `os.environ.get()` bilan standart qiymat berishni o'rganasiz
- `os` va `pathlib` qaysi vazifada qaysi biri qulayroq ekanini ajrata olasiz

## Nazariy qism

### `os.environ` — muhit o'zgaruvchilari

Operatsion tizim har bir dasturga **muhit o'zgaruvchilari** (environment variables) deb ataluvchi kalit-qiymat juftliklarini beradi — bular dastur ishga tushishidan oldin terminalda yoki serverning sozlamalarida belgilanadi. Python'da ularga `os.environ` orqali kiriladi — bu oddiy dictionary kabi ishlaydi:

```python
import os

print(os.environ["HOME"])          # /home/user
print(os.environ.get("PATH"))      # /usr/bin:/bin:...
print(os.environ.get("YOQ_KALIT")) # None (xato bermaydi)
```

`os.environ["HOME"]` — agar `HOME` mavjud bo'lmasa, `KeyError` beradi. `os.environ.get("YOQ_KALIT")` — mavjud bo'lmasa, xato bermay `None` qaytaradi; ikkinchi argument bilan standart qiymat ham berish mumkin: `os.environ.get("DEBUG", "False")`.

### Nega maxfiy ma'lumotlar muhit o'zgaruvchisida saqlanadi

`settings.py` faylida to'g'ridan-to'g'ri yozilgan maxfiy ma'lumot (`SECRET_KEY = "abc123"`, ma'lumotlar bazasi paroli) ikki jiddiy muammo tug'diradi: birinchidan, bu fayl odatda Git'ga (GitHub'ga) yuklanadi — demak parol ochiq holda internetda qoladi; ikkinchidan, development va production muhitida turli qiymatlar kerak bo'ladi (masalan development'da `DEBUG=True`, production'da `DEBUG=False`), buni kod ichida `if` bilan yozish qulay emas.

Yechim — qiymatni koddan **ajratish**: kod faqat "bu qiymat qayerdan olinishi kerakligini" biladi (`os.environ`), qiymatning o'zi esa serverning sozlamalarida yoki `.env` faylida (Git'ga qo'shilmaydigan) saqlanadi:

```python
import os

SECRET_KEY = os.environ.get("DJANGO_SECRET_KEY")
DEBUG = os.environ.get("DJANGO_DEBUG", "False") == "True"
```

> **Eslatma:** 4-qismning 2-bobida siz `django-environ` kutubxonasini ko'rgansiz — u aynan shu `os.environ`ni o'rab, qulayroq API (`env.bool()`, `env.list()` kabi avtomatik tur aylantirish) beradi. `django-environ` — tashqi kutubxona, uning ostida esa aynan shu standart `os.environ` ishlaydi. Bu darsda "qora quti" ichida nima borligini ko'rasiz.

### `os` va `pathlib` — qachon qaysi biri

`os` moduli fayl tizimi bilan ishlashning eski, ammo hali ham keng tarqalgan usuli. Django loyihasida asosiy vazifalar bo'yicha tanlov:

| Vazifa | Tavsiya etiladigan modul |
|---|---|
| Fayl/papka yo'llarini qurish, birlashtirish | `pathlib.Path` (1.1-dars) |
| Muhit o'zgaruvchilarini o'qish | `os.environ` |
| Joriy ish papkasini bilish | `os.getcwd()` |
| Fayl/papka nomini o'zgartirish, o'chirish | `os` yoki `pathlib` — ikkalasi ham bor, `pathlib` (`.rename()`, `.unlink()`) obyektga yo'nalgan bo'lgani uchun ko'proq tavsiya etiladi |

Qisqasi: **yangi kod uchun fayl yo'llarida `pathlib`, muhit o'zgaruvchilarida `os.environ`** — bu Django'ning o'zi ham 3.1 versiyadan beri amalda tutgan yo'nalish.

## Amaliy misol

`onlayn_dokon`ning `settings.py`sida, maxfiy va muhitga bog'liq sozlamalarni `os.environ` orqali o'qiymiz:

```python
# onlayn_dokon/settings.py
import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

SECRET_KEY = os.environ.get("DJANGO_SECRET_KEY")
if not SECRET_KEY:
    raise RuntimeError(
        "DJANGO_SECRET_KEY muhit o'zgaruvchisi topilmadi. "
        "Uni serverning sozlamalarida yoki .env faylida belgilang."
    )

DEBUG = os.environ.get("DJANGO_DEBUG", "False") == "True"

ALLOWED_HOSTS = os.environ.get("DJANGO_ALLOWED_HOSTS", "").split(",")

DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": os.environ.get("DB_NAME", "onlayn_dokon"),
        "USER": os.environ.get("DB_USER", "postgres"),
        "PASSWORD": os.environ.get("DB_PASSWORD", ""),
        "HOST": os.environ.get("DB_HOST", "localhost"),
        "PORT": os.environ.get("DB_PORT", "5432"),
    }
}
```

Serverni ishga tushirishdan oldin, terminalda muhit o'zgaruvchilarini belgilaymiz (yoki `.env` fayl + `django-environ` orqali avtomatik yuklaymiz — 4-qism 2-bobda ko'rilgan):

```bash
export DJANGO_SECRET_KEY="haqiqiy-va-uzun-tasodifiy-satr"
export DJANGO_DEBUG="False"
export DJANGO_ALLOWED_HOSTS="onlayn-dokon.uz,www.onlayn-dokon.uz"
python manage.py runserver
```

Agar `DJANGO_SECRET_KEY` belgilanmagan bo'lsa, server ishga tushmaydi va aniq xabar ko'rsatiladi — bu, `KeyError: 'DJANGO_SECRET_KEY'` kabi tushunarsiz xatodan ko'ra ancha foydali, chunki muammo va yechim bir joyda yozilgan.

## Keng tarqalgan xatolar

**Xato 1:** `os.environ` orqali olingan qiymatni har doim string ekanligini unutish.

❌ `DEBUG = os.environ.get("DJANGO_DEBUG", False)` deb yozib, keyin `if DEBUG:` tekshirish — muammo shundaki, agar `DJANGO_DEBUG` muhitda `"False"` (string) sifatida belgilangan bo'lsa, `if "False":` **`True`** deb baholanadi, chunki bo'sh bo'lmagan har qanday string Python'da "rost" hisoblanadi!

✅ Har doim aniq solishtiring: `DEBUG = os.environ.get("DJANGO_DEBUG", "False") == "True"` — natija haqiqiy `bool` bo'ladi.

**Xato 2:** Muhit o'zgaruvchisi yo'q bo'lganda dastur "sekin" buzilishiga yo'l qo'yish.

❌ `SECRET_KEY = os.environ.get("DJANGO_SECRET_KEY")` — agar o'zgaruvchi yo'q bo'lsa, `SECRET_KEY` shunchaki `None` bo'lib qoladi, va xato faqat keyinroq, umuman boshqa joyda (masalan sessiya yaratishda) chiqadi — sababini topish qiyin.

✅ Muhim sozlamalar uchun darhol tekshiring va aniq xato bering (yuqoridagi amaliy misoldagi `if not SECRET_KEY: raise RuntimeError(...)` kabi) — dastur ishga tushmasin, lekin sababi bir qarashda tushunarli bo'lsin.

**Xato 3:** `os.environ`ga dastur ichidan yozib, buni "sozlamani o'zgartirish" deb hisoblash.

❌ `os.environ["DJANGO_DEBUG"] = "True"` — bu faqat joriy Python jarayoni ichida ishlaydi, operatsion tizimning o'ziga yoki boshqa jarayonlarga (masalan Gunicorn worker'lariga) ta'sir qilmaydi; production sozlamasini shunday "dinamik" o'zgartirish — chalkash va xavfli amaliyot.

✅ Muhit o'zgaruvchilarini har doim dastur tashqarisida (`.env` fayl, `systemd` sozlamasi, Docker `environment:` bo'limi) belgilang; kod ichida faqat **o'qing**, yozmang.

## Mashq/topshiriq

**(Oson)** `python manage.py shell`da `import os; print(os.environ.get("PATH"))` bajarib, natijani ko'ring — bu operatsion tizim buyruqlarni qidiradigan papkalar ro'yxati.

**(O'rtacha)** `settings.py`ga `CACHE_TIMEOUT = int(os.environ.get("CACHE_TIMEOUT", "300"))` qatorini qo'shing va nega bu yerda `int()` bilan o'rab olish kerakligini (Xato 1 bilan bog'lab) bir jumlada tushuntiring.

**(Qiyin)** `onlayn_dokon` uchun kichik tekshiruv skripti yozing (`check_env.py`, loyiha tub papkasida): u `DJANGO_SECRET_KEY`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` muhit o'zgaruvchilarining barchasi belgilanganini tekshirsin, yetishmaganlarini ro'yxat qilib chiqarsin va agar kamida bittasi yo'q bo'lsa, `sys.exit(1)` bilan tugasin (0.2-darsdagi `sys`ni eslang).

# check_env.py
import os
import sys

KERAKLI_OZGARUVCHILAR = ["DJANGO_SECRET_KEY", "DB_NAME", "DB_USER", "DB_PASSWORD"]

yetishmagan = [nom for nom in KERAKLI_OZGARUVCHILAR if not os.environ.get(nom)]

if yetishmagan:
    print("Quyidagi muhit o'zgaruvchilari yetishmayapti:")
    for nom in yetishmagan:

## Qisqacha xulosa

`os.environ` — operatsion tizim tomonidan berilgan muhit o'zgaruvchilariga (`dict`ga o'xshash) kirish imkonini beradi, va bu Django loyihalarida `SECRET_KEY`, ma'lumotlar bazasi parollari kabi maxfiy va muhitga bog'liq sozlamalarni koddan ajratishning standart usuli — `django-environ` kabi kutubxonalar aynan shu mexanizm ustiga qurilgan. Muhim qoida: `os.environ`dan olingan qiymat har doim string, shuning uchun uni `bool` yoki `int`ga aylantirishda ehtiyot bo'lish kerak, va muhim sozlama yo'q bo'lganda dastur darhol, aniq xato bilan to'xtashi kerak. Keyingi bobda — sana va vaqt bilan ishlash, va Django'ning `timezone.now()` funksiyasi ostida nima yotishini ko'ramiz.
