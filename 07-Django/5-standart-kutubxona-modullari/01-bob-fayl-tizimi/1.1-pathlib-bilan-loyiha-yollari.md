# 1.1. `pathlib.Path` — `BASE_DIR`, `MEDIA_ROOT` va fayl yo'llarini xavfsiz qurish

## Bu darsda nimalarni o'rganasiz

- `pathlib.Path` obyektining string yo'llardan nima uchun afzalligini tushunasiz
- Django'ning `settings.py`dagi `BASE_DIR` aslida `Path` obyekti ekanini va undan qanday foydalanilishini bilib olasiz
- `/` operatori bilan operatsion tizimdan mustaqil yo'l qurishni o'rganasiz
- Fayl mavjudligini tekshirish, papka yaratish va fayl kengaytmasi bilan ishlashni o'zlashtirasiz

## Nazariy qism

### Nega oddiy string emas, `Path` obyekti

Eski Python kodida fayl yo'llari ko'pincha oddiy string va `os.path` funksiyalari bilan quriladi:

```python
import os
media_path = os.path.join(BASE_DIR, "media", "mahsulotlar", "rasm.jpg")
```

Bu ishlaydi, lekin ikki muammo bor: birinchidan, `/` va `\` (Linux va Windows) farqini har doim eslab yurish kerak — `os.path.join` buni hal qiladi, lekin string birlashtirish (`BASE_DIR + "/media"`) bilan yozilsa, kod faqat bitta operatsion tizimda ishlaydi. Ikkinchidan, string — faqat matn, u "fayl" yoki "papka" ekanini bilmaydi, mavjudligini tekshirish uchun alohida `os.path.exists()` chaqirish kerak.

`pathlib.Path` — yo'lni **obyekt** sifatida ifodalaydi, ustida metodlar bor:

```python
from pathlib import Path

media_path = Path(BASE_DIR) / "media" / "mahsulotlar" / "rasm.jpg"
print(media_path)                 # /home/user/onlayn_dokon/media/mahsulotlar/rasm.jpg
print(media_path.exists())        # True yoki False
print(media_path.suffix)          # .jpg
print(media_path.name)            # rasm.jpg
print(media_path.parent)          # /home/user/onlayn_dokon/media/mahsulotlar
```

`/` operatori — bu oddiy bo'lish uchun ataylab shunday qilingan (Python `__truediv__` metodini `Path` klassida qayta belgilagan): natijada yo'l qurish o'qishga oson, va Windows'da avtomatik `\`ga, Linux/macOS'da `/`ga aylanadi — dasturchi bu haqda umuman o'ylamaydi.

### Django'da `BASE_DIR` — aslida `Path`

Django 3.1dan beri, yangi loyiha yaratganda (`django-admin startproject`), `settings.py`ning boshida shunday qator bo'ladi:

```python
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent
```

`__file__` — `settings.py` faylining o'zining yo'li. `.resolve()` — nisbiy (relative) yo'lni to'liq, absolyut yo'lga aylantiradi. `.parent.parent` — ikki daraja yuqoriga chiqadi (`settings.py` → `onlayn_dokon/` papkasi → loyihaning tub papkasi). Shundan keyin, `settings.py`ning istalgan joyida:

```python
MEDIA_ROOT = BASE_DIR / "media"
STATIC_ROOT = BASE_DIR / "staticfiles"
TEMPLATES = [
    {
        ...
        "DIRS": [BASE_DIR / "templates"],
        ...
    },
]
```

Eski Django versiyalarida (`BASE_DIR = os.path.dirname(...)`) bu string bo'lgan — `pathlib`ga o'tish Django'ning o'zida ham "zamonaviyroq va xavfsizroq" deb topilgani uchun sodir bo'lgan.

### Foydali `Path` metodlari

| Metod/xossasi | Vazifasi |
|---|---|
| `.exists()` | Fayl yoki papka mavjudligini tekshiradi |
| `.is_file()` / `.is_dir()` | Aniq faylmi yoki papkami tekshiradi |
| `.mkdir(parents=True, exist_ok=True)` | Papka (kerak bo'lsa, oraliq papkalar bilan) yaratadi |
| `.suffix` | Fayl kengaytmasi (`.jpg`, `.pdf`) |
| `.stem` | Kengaytmasiz fayl nomi |
| `.glob("*.jpg")` | Papka ichidan naqshga mos fayllarni topadi |

## Amaliy misol

`onlayn_dokon`da har bir `Mahsulot` uchun rasm yuklanganda, uning fayl hajmi va kengaytmasini tekshiruvchi yordamchi funksiya yozamiz:

```python
# apps/mahsulotlar/utils.py
from pathlib import Path

RUXSAT_ETILGAN_KENGAYTMALAR = {".jpg", ".jpeg", ".png", ".webp"}
MAKSIMAL_HAJM_MB = 5


def rasm_faylini_tekshir(fayl_yoli: Path) -> tuple[bool, str]:
    """Mahsulot rasmi talablarga javob berishini tekshiradi.

    Qaytaradi: (to'g'ri_bo'lsa=True/False, xabar)
    """
    fayl_yoli = Path(fayl_yoli)

    if not fayl_yoli.exists():
        return False, "Fayl topilmadi"

    if fayl_yoli.suffix.lower() not in RUXSAT_ETILGAN_KENGAYTMALAR:
        return False, f"Ruxsat etilmagan kengaytma: {fayl_yoli.suffix}"

    hajm_mb = fayl_yoli.stat().st_size / (1024 * 1024)
    if hajm_mb > MAKSIMAL_HAJM_MB:
        return False, f"Fayl juda katta: {hajm_mb:.1f} MB (limit: {MAKSIMAL_HAJM_MB} MB)"

    return True, "OK"
```

Management command orqali sinaymiz — `media/mahsulotlar/` papkasidagi barcha rasmlarni tekshirib chiqamiz:

```python
# apps/mahsulotlar/management/commands/rasmlarni_tekshir.py
from django.conf import settings
from django.core.management.base import BaseCommand

from apps.mahsulotlar.utils import rasm_faylini_tekshir


class Command(BaseCommand):
    help = "media/mahsulotlar/ papkasidagi barcha rasmlarni tekshiradi"

    def handle(self, *args, **options):
        papka = settings.MEDIA_ROOT / "mahsulotlar"

        if not papka.exists():
            self.stdout.write(self.style.WARNING(f"{papka} papkasi mavjud emas"))
            return

        for rasm in papka.glob("*"):
            togri, xabar = rasm_faylini_tekshir(rasm)
            belgi = "✅" if togri else "❌"
            self.stdout.write(f"{belgi} {rasm.name}: {xabar}")
```

```bash
python manage.py rasmlarni_tekshir
```

```

❌ katta-rasm.png: Fayl juda katta: 8.3 MB (limit: 5 MB)
❌ hujjat.pdf: Ruxsat etilmagan kengaytma: .pdf
```

`papka.glob("*")` — `os.listdir` o'rniga to'g'ridan-to'g'ri `Path` obyektlarini qaytaradi, shuning uchun ustida darhol `.suffix`, `.stat()` kabi metodlarni chaqirish mumkin — oraliq `os.path.join` kerak emas.

## Keng tarqalgan xatolar

**Xato 1:** `Path` bilan `+` operatorini ishlatishga urinish.

❌ `BASE_DIR + "media"` — `TypeError: unsupported operand type(s) for +: 'PosixPath' and 'str'` xatosini beradi, chunki `Path` matn emas.

✅ `/` operatoridan foydalaning: `BASE_DIR / "media"`. Yo'lni matnga aylantirish kerak bo'lsa (masalan eski kutubxonaga uzatish uchun), `str(BASE_DIR / "media")` yozing.

**Xato 2:** `.mkdir()`ni `parents=True, exist_ok=True`siz chaqirish.

❌ `Path("media/mahsulotlar/2026").mkdir()` — agar `media/` yoki `media/mahsulotlar/` hali mavjud bo'lmasa, `FileNotFoundError` beradi; agar `2026` papkasi allaqachon bor bo'lsa, `FileExistsError` beradi.

✅ `Path("media/mahsulotlar/2026").mkdir(parents=True, exist_ok=True)` — `parents=True` yetishmayotgan oraliq papkalarni ham yaratadi, `exist_ok=True` esa papka allaqachon mavjud bo'lsa xato bermaydi.

**Xato 3:** Nisbiy (`__file__`ni `.resolve()` qilmasdan) yo'ldan foydalanish.

❌ `BASE_DIR = Path(__file__).parent.parent` (`.resolve()` yo'q) — loyiha turli joydan (masalan `cd /home/user && python onlayn_dokon/manage.py runserver`) ishga tushirilsa, `__file__` nisbiy yo'l bo'lib qolishi va `BASE_DIR` noto'g'ri chiqishi mumkin.

✅ Har doim `.resolve()` qo'shing: `Path(__file__).resolve().parent.parent` — bu `__file__`ni avval absolyut yo'lga aylantiradi, keyingina ota-papkalarga chiqadi. Django'ning o'zi generatsiya qiladigan `settings.py` aynan shunday yozadi — sababsiz emas.

## Mashq/topshiriq

**(Oson)** Django shell'ida `from django.conf import settings; print(settings.BASE_DIR); print(type(settings.BASE_DIR))` bajarib, `BASE_DIR`ning haqiqatan `Path` obyekti ekanini tasdiqlang.

**(O'rtacha)** `rasm_faylini_tekshir` funksiyasiga yana bitta tekshiruv qo'shing: fayl nomi bo'sh joy (probel) o'z ichiga olmasligi kerak (URL'larda muammo tug'diradi). Bo'sh joy bo'lsa, `False, "Fayl nomida bo'sh joy bo'lmasligi kerak"` qaytaring.

**(Qiyin)** `media/mahsulotlar/` papkasidagi barcha ruxsat etilmagan (masalan `.pdf`, `.txt`) fayllarni `media/arxiv/notogri/` papkasiga ko'chiruvchi (nusxalash emas, ko'chirish) management command yozing — `Path.rename()` metodidan foydalaning, va ko'chirishdan oldin maqsad papka mavjud bo'lishini `.mkdir(parents=True, exist_ok=True)` bilan ta'minlang.

## Qisqacha xulosa

`pathlib.Path` — fayl yo'llarini string sifatida emas, obyekt sifatida ifodalaydi, `/` operatori bilan operatsion tizimdan mustaqil yo'l quradi va `.exists()`, `.mkdir()`, `.glob()` kabi metodlar bilan fayl amallarini bevosita bajaradi. Django'ning `settings.py`sidagi `BASE_DIR`, `MEDIA_ROOT`, `STATIC_ROOT` — barchasi aynan `Path` obyekti, shuning uchun ular ustida `/` bilan yangi yo'l qurish odatiy holat. Keyingi darsda — `os` moduli va uning eng ko'p ishlatiladigan qismi, muhit o'zgaruvchilari (`os.environ`) bilan tanishamiz.
