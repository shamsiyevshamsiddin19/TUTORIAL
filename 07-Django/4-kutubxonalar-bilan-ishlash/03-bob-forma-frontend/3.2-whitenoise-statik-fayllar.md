# 3.2. whitenoise — production'da statik fayllarni to'g'ri xizmat qilish

## Bu darsda nimalarni o'rganasiz

- `DEBUG=False` bo'lganda statik fayllar (CSS, JS, rasm) nega avtomatik ishlamay qolishini tushunasiz
- `whitenoise` kutubxonasini o'rnatib, `MIDDLEWARE`ga to'g'ri joyga qo'shishni o'rganasiz
- `STORAGES` orqali siqilgan va keshlanadigan (cache-busting) statik fayllarni sozlashni bilib olasiz
- `collectstatic` buyrug'ini `whitenoise` bilan birga to'g'ri ishlatishni o'rganasiz

## Nazariy qism

### Muammo: DEBUG=False bo'lganda statik fayllar

Development paytida (`DEBUG=True`), Django'ning o'ziga xos dev-serveri (`runserver`) `STATIC_URL` orqali so'ralgan CSS/JS/rasm fayllarni **avtomatik** topib beradi — bu qulay, lekin ataylab **faqat rivojlantirish uchun** mo'ljallangan, tez emas.

`DEBUG=False` (production) holatida esa, Django bu xizmatni **o'chirib qo'yadi** — chunki, an'anaviy yondashuvda, statik fayllarni xizmat qilish vazifasi alohida veb-server (Nginx, Apache) yoki CDN'ga yuklatiladi. Lekin bunday alohida server sozlash har doim ham qulay yoki zarur emas — ayniqsa bitta konteynerli (Docker) yoki soddaroq joylashtirish (masalan Heroku-uslubidagi platformalar) muhitida. Aynan shu bo'shliqni `whitenoise` to'ldiradi: Django ilovasining o'zi, samarali va xavfsiz tarzda, statik fayllarni **to'g'ridan-to'g'ri** xizmat qilishga imkon beradi.

### whitenoise yechimi

```bash
pip install whitenoise
```

```python
# settings.py
MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",   # SecurityMiddleware'dan DARHOL keyin
    "django.contrib.sessions.middleware.SessionMiddleware",
    # ... qolgan middleware'lar
]

STATIC_URL = "static/"
STATIC_ROOT = BASE_DIR / "staticfiles"

STORAGES = {
    "default": {
        "BACKEND": "django.core.files.storage.FileSystemStorage",
    },
    "staticfiles": {
        "BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage",
    },
}
```

`CompressedManifestStaticFilesStorage` ikkita narsani birga qiladi:

1. **Siqish (compression)** — har bir CSS/JS fayl uchun oldindan `.gz` (va qo'llab-quvvatlansa, brotli) versiyasini tayyorlaydi, brauzer so'raganda siqilgan versiya yuboriladi — tezroq yuklanadi.
2. **Cache-busting (manifest)** — har bir faylga, uning tarkibidan hisoblangan **hash**ni nomiga qo'shadi (masalan `style.css` → `style.a3f8c9.css`). Fayl o'zgarsa, hash ham o'zgaradi — bu, brauzer eski, keshlangan versiyani ko'rsatib qolish muammosini butunlay yo'q qiladi.

### collectstatic

```bash
python manage.py collectstatic
```

```
132 static files copied to '/home/dokon/onlayn_dokon/staticfiles', 132 post-processed.
```

Bu buyruq — har bir ilovadagi (`apps/dokon/static/`, va h.k.) barcha statik fayllarni, bitta joyga (`STATIC_ROOT`) yig'adi, va `CompressedManifestStaticFilesStorage` tanlangan bo'lsa, ularni siqib, hash-nomli versiyalarini yaratadi. `whitenoise` esa, ishga tushganda, aynan shu `STATIC_ROOT` papkasidan fayllarni to'g'ridan-to'g'ri, samarali xizmat qiladi.

## Amaliy misol

`onlayn_dokon`ni production rejimida (`DEBUG=False`), alohida veb-serversiz, statik fayllar bilan sinash:

```python
# onlayn_dokon/settings/production.py (2.2-darsdagi struktura)
from .base import *  # noqa

DEBUG = False
MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",
] + MIDDLEWARE[1:]   # base.py'dagi qolganlarini SecurityMiddleware'dan keyinga qo'shamiz

STATIC_ROOT = BASE_DIR / "staticfiles"
STORAGES = {
    "default": {"BACKEND": "django.core.files.storage.FileSystemStorage"},
    "staticfiles": {"BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage"},
}
```

```bash
python manage.py collectstatic --noinput
```

```
132 static files copied to '/home/dokon/onlayn_dokon/staticfiles', 132 post-processed.
```

```bash
DJANGO_SETTINGS_MODULE=onlayn_dokon.settings.production python manage.py runserver
```

Endi, `DEBUG=False` bo'lishiga qaramay, saytga kirilganda CSS/JS to'g'ri yuklanadi — chunki ularni endi Django dev-server emas, `whitenoise` middleware'i xizmat qilyapti. Brauzer developer tools'da (Network bo'limi) fayl nomlarini tekshirsangiz, `style.a3f8c9.css` kabi hash qo'shilgan nomlarni ko'rasiz.

## Keng tarqalgan xatolar

**Xato 1:** `WhiteNoiseMiddleware`ni `MIDDLEWARE` ro'yxatida noto'g'ri joyga qo'yish.

❌ `WhiteNoiseMiddleware` ro'yxat oxiriga qo'shilgan — bu, boshqa middleware'lar (masalan `CommonMiddleware`) statik fayl so'roviga yetib kelmasdan ishlov berishga urinishiga, yoki samaradorlik pasayishiga olib kelishi mumkin.

✅ `WhiteNoiseMiddleware`ni har doim `SecurityMiddleware`dan **darhol keyin**, qolgan barcha middleware'lardan **oldin** joylashtiring — bu, rasmiy hujjatlarda tavsiya etilgan tartib.

**Xato 2:** `collectstatic`ni ishga tushirmasdan production'ga joylashtirish (deploy).

❌ Kod serverga yuklangan, lekin `python manage.py collectstatic` bajarilmagan — `STATIC_ROOT` papkasi bo'sh, va `whitenoise` xizmat qiladigan fayllar yo'q, natijada barcha CSS/JS/rasm so'rovlari `404`ga uchraydi, sayt "chiroyisiz" (stilsiz HTML) ko'rinadi.

✅ Deploy jarayoningizga (qo'lda, yoki Docker/CI skriptida) `collectstatic --noinput`ni **majburiy qadam** sifatida qo'shing — har safar yangi kod joylashtirilganda avtomatik ishga tushishi kerak.

**Xato 3:** `{% static %}` shablon tegidan foydalanmasdan, statik fayl yo'lini qo'lda (hardcoded) yozish.

❌ `<link rel="stylesheet" href="/static/css/style.css">` — `CompressedManifestStaticFilesStorage` ishlatilganda, haqiqiy fayl nomi `style.a3f8c9.css` bo'ladi; qo'lda yozilgan yo'l **mavjud bo'lmagan** faylga ishora qiladi va `404` beradi (yoki, manifest yangilanmagan eski versiyaga ishora qiladi).

✅ Har doim `{% load static %}` va `{% static "css/style.css" %}` shablon tegidan foydalaning — u, joriy manifestga qarab, **to'g'ri**, hash qo'shilgan yo'lni avtomatik generatsiya qiladi.

## Mashq/topshiriq

**(Oson)** `whitenoise`ni o'rnating, `MIDDLEWARE`ga to'g'ri joyga qo'shing, va `python manage.py collectstatic`ni ishga tushirib, nechta fayl nusxalanganini ko'ring.

**(O'rtacha)** `DEBUG=False` bilan `runserver`ni ishga tushiring (`whitenoise` sozlangandan keyin) va biror sahifani ochib, CSS to'g'ri yuklanayotganini (brauzer developer tools, Network bo'limida `200 OK` statusi bilan) tasdiqlang.

**(Qiyin)** `staticfiles/` papkasidagi biror CSS faylini oching va uning nomida hash borligini toping (masalan `style.a3f8c9.css`). Shu faylning tarkibiga (masalan bitta bo'sh qatorga) o'zgartirish kiritib, `collectstatic`ni qayta ishga tushiring — fayl nomidagi hash **o'zgarganini** tasdiqlang, va bu nega brauzer keshi muammosini oldini olishini tushuntiring.

## Qisqacha xulosa

`whitenoise` — Django ilovasining o'ziga, alohida veb-server (Nginx) sozlamasdan, production rejimida (`DEBUG=False`) statik fayllarni samarali xizmat qilish imkonini beradi: `MIDDLEWARE`ga to'g'ri joyga (`SecurityMiddleware`dan keyin) qo'shiladi, `CompressedManifestStaticFilesStorage` esa fayllarni siqadi va har birining nomiga tarkibidan hisoblangan hash qo'shib, brauzer keshi muammosini oldini oladi. `collectstatic`ni deploy jarayonining majburiy qadamiga aylantirish va shablonlarda har doim `{% static %}` tegidan foydalanish — bu tizimning to'g'ri ishlashi uchun shart. Keyingi bobda — `onlayn_dokon`ga foydalanuvchi autentifikatsiyasini kengaytiruvchi kutubxonalarni (`django-allauth`, `django-axes`) qo'shamiz.
