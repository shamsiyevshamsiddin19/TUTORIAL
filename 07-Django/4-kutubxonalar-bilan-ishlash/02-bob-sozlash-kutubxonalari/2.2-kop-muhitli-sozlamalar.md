# 2.2. Ko'p muhitli (development/production) sozlamalar strukturasi

## Bu darsda nimalarni o'rganasiz

- Bitta `settings.py` fayl bilan ishlashning katta loyihalardagi muammosini tushunasiz
- `settings/` papka strukturasiga (`base.py`, `development.py`, `production.py`) o'tishni o'rganasiz
- `DJANGO_SETTINGS_MODULE` orqali qaysi sozlama to'plami ishlatilishini boshqarishni bilib olasiz
- Development va production uchun xavfsizlik sozlamalari qanday farqlanishini ko'rasiz

## Nazariy qism

### Bitta settings.py muammosi

Kichik loyihada, `settings.py` ichida shunga o'xshash kod ko'rinishi mumkin:

```python
# settings.py — o'sib ketishi mumkin bo'lgan uslub
import environ
env = environ.Env()

if env.bool("PRODUCTION", default=False):
    DEBUG = False
    ALLOWED_HOSTS = ["dokon.uz"]
    SECURE_SSL_REDIRECT = True
else:
    DEBUG = True
    ALLOWED_HOSTS = []
```

Loyiha kattalashgani sari, bunday `if/else` bloklari ko'payadi (database, email, cache, logging — hammasi uchun) va fayl o'qishga qiyin, xatoga moyil bo'lib qoladi. Bundan tashqari, "production" sozlamalarini **tasodifan** o'zgartirib qo'yish xavfi ortadi — chunki hamma narsa bitta faylda aralash.

### settings/ papka strukturasi

Yechim — `settings.py` faylini, bir xil nomli **papkaga** aylantirish:

```
onlayn_dokon/
    settings/
        __init__.py
        base.py           # barcha muhitlar uchun UMUMIY sozlamalar
        development.py    # faqat development uchun
        production.py     # faqat production uchun
```

`base.py` — INSTALLED_APPS, MIDDLEWARE, TEMPLATES kabi, deyarli har doim bir xil qoladigan narsalarni saqlaydi:

```python
# onlayn_dokon/settings/base.py
from pathlib import Path
import environ

BASE_DIR = Path(__file__).resolve().parent.parent.parent

env = environ.Env()
environ.Env.read_env(BASE_DIR / ".env")

SECRET_KEY = env("SECRET_KEY")

INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "apps.dokon",
]

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "django.contrib.sessions.middleware.SessionMiddleware",
    # ...
]

LANGUAGE_CODE = "uz"
TIME_ZONE = "Asia/Tashkent"
```

`development.py` — `base.py`dagi hamma narsani meros qilib oladi (`from .base import *`), ustiga faqat **farq qiladigan** qismni qo'shadi:

```python
# onlayn_dokon/settings/development.py
from .base import *  # noqa

DEBUG = True
ALLOWED_HOSTS = ["localhost", "127.0.0.1"]

DATABASES = {
    "default": env.db("DATABASE_URL", default="sqlite:///db.sqlite3"),
}
```

`production.py` — xuddi shunday, lekin xavfsizlikka yo'naltirilgan:

```python
# onlayn_dokon/settings/production.py
from .base import *  # noqa

DEBUG = False
ALLOWED_HOSTS = env.list("ALLOWED_HOSTS")

DATABASES = {
    "default": env.db("DATABASE_URL"),   # default YO'Q — .env yo'q bo'lsa, xato chiqishi KERAK
}

SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
```

### DJANGO_SETTINGS_MODULE orqali tanlash

Django, qaysi sozlama faylini ishlatishni `DJANGO_SETTINGS_MODULE` muhit o'zgaruvchisi orqali biladi. `manage.py` va `wsgi.py`dagi standart qatorni moslashtirish kerak:

```python
# manage.py (o'zgartirilgan qism)
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "onlayn_dokon.settings.development")
```

Serverda esa, muhit o'zgaruvchisi orqali bekor qilinadi (override):

```bash
export DJANGO_SETTINGS_MODULE=onlayn_dokon.settings.production
python manage.py runserver
```

Yoki, buyruq qatoriga to'g'ridan-to'g'ri qo'shib ham berish mumkin:

```bash
DJANGO_SETTINGS_MODULE=onlayn_dokon.settings.production gunicorn onlayn_dokon.wsgi
```

## Amaliy misol

`onlayn_dokon` uchun to'liq migratsiya — bitta `settings.py`dan `settings/` papkasiga o'tish:

```bash
mkdir onlayn_dokon/settings
touch onlayn_dokon/settings/__init__.py
git mv onlayn_dokon/settings.py onlayn_dokon/settings/base.py
```

```python
# onlayn_dokon/settings/base.py — BASE_DIR chuqurligini to'g'rilash kerak
# eski: BASE_DIR = Path(__file__).resolve().parent.parent   (1 daraja)
BASE_DIR = Path(__file__).resolve().parent.parent.parent      # endi 2 daraja (settings/ ichida)
```

```python
# onlayn_dokon/settings/development.py
from .base import *  # noqa

DEBUG = True
ALLOWED_HOSTS = ["localhost", "127.0.0.1"]
DATABASES = {"default": env.db("DATABASE_URL", default="sqlite:///db.sqlite3")}
```

```python
# onlayn_dokon/settings/production.py
from .base import *  # noqa

DEBUG = False
ALLOWED_HOSTS = env.list("ALLOWED_HOSTS")
DATABASES = {"default": env.db("DATABASE_URL")}
SECURE_SSL_REDIRECT = True
```

```python
# manage.py
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "onlayn_dokon.settings.development")
```

```python
# onlayn_dokon/wsgi.py (production serverda ishlaydigan qism)
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "onlayn_dokon.settings.production")
```

Tekshirish:

```bash
python manage.py runserver
# DJANGO_SETTINGS_MODULE ko'rsatilmagan — manage.py'dagi standart (development) ishlatiladi

DJANGO_SETTINGS_MODULE=onlayn_dokon.settings.production python manage.py check --deploy
# production sozlamalari bilan tekshiriladi, DEBUG=False ekani va boshqa xavfsizlik ogohlantirishlari ko'rsatiladi
```

## Keng tarqalgan xatolar

**Xato 1:** `base.py`da `DEBUG` yoki `DATABASES`ni to'g'ridan-to'g'ri belgilab qo'yish.

❌ `DEBUG = True` `base.py`ga yozilgan — `production.py` uni "meros" qilib oladi va agar unutilib qayta belgilanmasa, production serverda ham `DEBUG=True` bo'lib qoladi.

✅ Har bir muhitga xos, farq qiladigan sozlamalarni (`DEBUG`, `DATABASES`, `ALLOWED_HOSTS`) **faqat** `development.py`/`production.py`da belgilang; `base.py`da faqat haqiqatan **hamma joyda bir xil** qoladigan narsalarni qoldiring.

**Xato 2:** `production.py`da `env.db("DATABASE_URL")`ga `default` qiymat berish.

❌ `env.db("DATABASE_URL", default="sqlite:///db.sqlite3")` — production serverda `.env` topilmasa yoki noto'g'ri sozlansa ham, tizim **jim** SQLite'ga o'tib ketadi — bu, production ma'lumotlar bazasi o'rniga vaqtinchalik, bo'sh SQLite fayli bilan ishlashdek jiddiy, sezilmaydigan xatoga olib kelishi mumkin.

✅ Production sozlamalarida **hech qachon** `default` bermang — agar `.env` noto'g'ri bo'lsa, server darhol, aniq xato bilan ishga tushmasligi kerak (jim, noto'g'ri holatda ishlashdan ko'ra xavfsizroq).

**Xato 3:** `manage.py`ni yangilashni unutib, eski `onlayn_dokon.settings`ga ishora qilib qoldirish.

❌ `settings.py` `settings/base.py`ga ko'chirilgan, lekin `manage.py`dagi `DJANGO_SETTINGS_MODULE` hali ham eski `"onlayn_dokon.settings"`ga ishora qiladi — `ModuleNotFoundError` yoki `ImproperlyConfigured` xatosi chiqadi.

✅ `settings.py`ni `settings/` papkasiga aylantirgandan so'ng, **darhol** `manage.py` va `wsgi.py`/`asgi.py`dagi barcha `DJANGO_SETTINGS_MODULE` ishoralarini yangilang (masalan `onlayn_dokon.settings.development`).

## Mashq/topshiriq

**(Oson)** `onlayn_dokon/settings/` papka strukturasini (`base.py`, `development.py`, `production.py`, `__init__.py`) yarating, hozircha `base.py`ga barcha mavjud sozlamalarni ko'chiring.

**(O'rtacha)** `development.py` va `production.py`ga `DEBUG` va `ALLOWED_HOSTS`ni ajrating. `manage.py`ni yangilab, `python manage.py check` xatosiz o'tishini tasdiqlang.

**(Qiyin)** `production.py`ga `SECURE_SSL_REDIRECT = True`, `SESSION_COOKIE_SECURE = True`, `CSRF_COOKIE_SECURE = True` qo'shing. `DJANGO_SETTINGS_MODULE=onlayn_dokon.settings.production python manage.py check --deploy` buyrug'ini ishga tushiring va Django bergan ogohlantirishlarni (agar bo'lsa) o'qib, ularni birma-bir hal qiling.

## Qisqacha xulosa

Bitta `settings.py`ni `settings/` papkasiga (`base.py` — umumiy, `development.py`/`production.py` — muhitga xos) bo'lish, `if/else` bloklarining o'rnini aniq, ajratilgan fayllar bilan almashtiradi va production xavfsizligini oshiradi (masalan, production'da `DATABASE_URL` uchun `default` **berilmasligi** kerak). `DJANGO_SETTINGS_MODULE` muhit o'zgaruvchisi — `manage.py`, `wsgi.py` va serverdagi buyruqlar orqali, qaysi sozlama to'plami ishlatilishini nazorat qiladi. Keyingi bobda — endi sozlamalar tizimi tayyor bo'lgani holda, `onlayn_dokon`ning **forma va frontend** qatlamiga birinchi tashqi kutubxonalarni qo'shamiz.
