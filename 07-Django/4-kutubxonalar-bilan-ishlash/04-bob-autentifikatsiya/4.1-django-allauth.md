# 4.1. django-allauth — email va ijtimoiy tarmoq orqali kirish

## Bu darsda nimalarni o'rganasiz

- Django standart autentifikatsiya tizimining (faqat username orqali kirish) cheklovini tushunasiz
- `django-allauth`ni o'rnatib, **email** orqali ro'yxatdan o'tish/kirishni sozlashni o'rganasiz
- Ijtimoiy tarmoq (Google) orqali kirishni ulashni bilib olasiz
- `ACCOUNT_*` sozlamalari orqali ro'yxatdan o'tish xatti-harakatini moslashtirishni o'rganasiz

## Nazariy qism

### Standart Django autentifikatsiyaning cheklovi

Django'ning o'rnatilgan autentifikatsiya tizimi (11-darsda, 1-qismda ko'rgan) — `username` + `password` asosida ishlaydi. Email orqali kirish, "parolni unutdim" jarayoni, ijtimoiy tarmoq (Google, GitHub) orqali kirish — bularning hech biri **tayyor** kelmaydi, har birini o'zingiz qo'lda yozishingiz kerak bo'ladi. `django-allauth` — aynan shu funksiyalarning barchasini, sinovdan o'tgan, xavfsiz shaklda taqdim etadigan eng mashhur kutubxona.

### django-allauth o'rnatish

```bash
pip install "django-allauth[socialaccount]"
```

```python
# settings.py
INSTALLED_APPS += [
    "django.contrib.sites",       # allauth uchun majburiy
    "allauth",
    "allauth.account",
    "allauth.socialaccount",
    "allauth.socialaccount.providers.google",
]

SITE_ID = 1

AUTHENTICATION_BACKENDS = [
    "django.contrib.auth.backends.ModelBackend",       # standart, admin panel uchun kerak
    "allauth.account.auth_backends.AuthenticationBackend",
]

MIDDLEWARE += [
    "allauth.account.middleware.AccountMiddleware",
]
```

```python
# urls.py
urlpatterns = [
    # ...
    path("accounts/", include("allauth.urls")),
]
```

`django.contrib.sites` — allauth'ning ichki talabi (bir nechta domenni bitta loyihadan boshqarish imkoniyati uchun); kichik loyihada `SITE_ID = 1` bilan cheklaniladi. Bu app qo'shilgach, `python manage.py migrate` bajarish kerak (yangi jadval yaratadi).

### Faqat email orqali ro'yxatdan o'tish/kirish

```python
# settings.py
ACCOUNT_LOGIN_METHODS = {"email"}
ACCOUNT_SIGNUP_FIELDS = ["email*", "password1*", "password2*"]
ACCOUNT_EMAIL_VERIFICATION = "mandatory"   # ro'yxatdan o'tgach, emailni tasdiqlash talab qilinadi
```

Bu sozlamalar bilan, foydalanuvchi endi `username` o'rniga **email** kiritib ro'yxatdan o'tadi va kiradi — `username` maydoni butunlay yashiriladi.

### Ijtimoiy tarmoq orqali kirish (Google misolida)

Google orqali kirishni yoqish uchun, avval [Google Cloud Console](https://console.cloud.google.com/)da OAuth ilovasi yaratib, **Client ID** va **Client Secret** olish kerak. So'ng, Django admin panelida (`/admin/socialaccount/socialapp/`):

- **Provider:** Google
- **Client id:** (Google Cloud Console'dan)
- **Secret key:** (Google Cloud Console'dan)
- **Sites:** joriy sayt (`SITE_ID=1`ga mos) tanlanadi

Shablonda, "Google orqali kirish" tugmasi:

```html
{% load socialaccount %}
<a href="{% provider_login_url 'google' %}" class="btn btn-outline-dark">
    Google orqali kirish
</a>
```

## Amaliy misol

`onlayn_dokon`da mijozlar (`Mijoz`) endi email orqali ro'yxatdan o'tadi va Google orqali ham kira oladi:

```python
# onlayn_dokon/settings/base.py
INSTALLED_APPS = [
    # ...
    "django.contrib.sites",
    "allauth",
    "allauth.account",
    "allauth.socialaccount",
    "allauth.socialaccount.providers.google",
    "apps.dokon",
]

SITE_ID = 1

AUTHENTICATION_BACKENDS = [
    "django.contrib.auth.backends.ModelBackend",
    "allauth.account.auth_backends.AuthenticationBackend",
]

MIDDLEWARE = [
    # ...
    "allauth.account.middleware.AccountMiddleware",
]

ACCOUNT_LOGIN_METHODS = {"email"}
ACCOUNT_SIGNUP_FIELDS = ["email*", "password1*", "password2*"]
ACCOUNT_EMAIL_VERIFICATION = "optional"   # rivojlantirish paytida "optional", productionda "mandatory"

LOGIN_REDIRECT_URL = "bosh_sahifa"
```

```python
# onlayn_dokon/urls.py
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
    path("accounts/", include("allauth.urls")),
    path("", include("apps.dokon.urls")),
]
```

```bash
python manage.py migrate
python manage.py runserver
```

Endi `http://localhost:8000/accounts/signup/` — email orqali ro'yxatdan o'tish sahifasini, `http://localhost:8000/accounts/login/` — kirish sahifasini avtomatik ko'rsatadi (allauth'ning tayyor shablonlaridan foydalanib, ularni keyinchalik o'zingizning dizayningizga moslab qayta yozishingiz mumkin).

## Keng tarqalgan xatolar

**Xato 1:** `AUTHENTICATION_BACKENDS`ga allauth backend'ini qo'shishni unutish.

❌ `INSTALLED_APPS`ga `allauth.account` qo'shilgan, lekin `AUTHENTICATION_BACKENDS` o'zgartirilmagan — ro'yxatdan o'tish sahifasi ochiladi, lekin login jarayonida foydalanuvchi tizimga **kira olmaydi**, chunki Django hamon faqat standart `ModelBackend`dan foydalanadi.

✅ `allauth.account.auth_backends.AuthenticationBackend`ni **standart** `ModelBackend` bilan **birga** (uni almashtirmasdan) `AUTHENTICATION_BACKENDS`ga qo'shing — ikkalasi ham kerak (standart — admin panel uchun, allauth — sayt foydalanuvchilari uchun).

**Xato 2:** `django.contrib.sites` uchun migratsiya bajarmaslik yoki `SITE_ID`ni unutish.

❌ `django.contrib.sites` `INSTALLED_APPS`ga qo'shilgan, lekin `python manage.py migrate` bajarilmagan (yoki `SITE_ID` sozlanmagan) — server ishga tushishda `Site matching query does not exist` yoki shunga o'xshash xato beradi.

✅ `django.contrib.sites`ni qo'shgach, darhol `migrate`ni ishga tushiring va `settings.py`da `SITE_ID = 1`ni belgilang; Django admin panelida `/admin/sites/site/`ga kirib, sayt domenini (production'da haqiqiy domeningizga) yangilashni unutmang.

**Xato 3:** Google Cloud Console'da noto'g'ri "Authorized redirect URI" kiritish.

❌ Google Cloud Console'dagi OAuth sozlamasida redirect URI `http://localhost:8000/accounts/google/login/callback/` o'rniga boshqacha (masalan oxiridagi `/` belgisisiz, yoki `https://` bilan development'da) yozilgan — Google login tugmasi bosilganda, `redirect_uri_mismatch` xatosi chiqadi.

✅ Redirect URI'ni **aynan** allauth talab qilgan formatda (`<domen>/accounts/<provider>/login/callback/`, oxiridagi `/` bilan) kiriting — development uchun `http://localhost:8000/accounts/google/login/callback/`, production uchun haqiqiy domeningiz bilan `https://`.

## Mashq/topshiriq

**(Oson)** `django-allauth`ni o'rnating, kerakli `INSTALLED_APPS`, `AUTHENTICATION_BACKENDS`, `MIDDLEWARE`ni sozlang, `migrate`ni ishga tushiring, va `/accounts/signup/` sahifasini brauzerda oching.

**(O'rtacha)** `ACCOUNT_LOGIN_METHODS = {"email"}` sozlamasini qo'shing va yangi foydalanuvchi email orqali ro'yxatdan o'tishini sinab ko'ring. `username` maydoni endi so'ralmasligini tasdiqlang.

**(Qiyin)** Google Cloud Console'da (yoki sinov uchun, hujjatlarni o'qib) OAuth ilovasi sozlash qadamlarini yozib chiqing, so'ng Django admin orqali "Social Application" qo'shing va `{% provider_login_url 'google' %}` tugmasini login sahifasiga joylashtiring.

## Qisqacha xulosa

`django-allauth` — Django'ning standart, faqat `username`ga asoslangan autentifikatsiya tizimini, email orqali ro'yxatdan o'tish/kirish va ijtimoiy tarmoq (Google va boshqalar) orqali kirish bilan kengaytiradi; `AUTHENTICATION_BACKENDS`ga qo'shimcha backend qo'shish, `django.contrib.sites`ni sozlash va `ACCOUNT_*` sozlamalari orqali xatti-harakatni moslashtirish — asosiy integratsiya qadamlari. Keyingi darsda — endi login tizimi tayyor bo'lgani holda, uni **brute-force** (parolni ketma-ket taxmin qilish) hujumlaridan himoya qiluvchi `django-axes`ni qo'shamiz.
