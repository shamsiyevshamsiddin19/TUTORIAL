# 1.1. requirements.txt va versiya pinning

## Bu darsda nimalarni o'rganasiz

- `requirements.txt` fayli nima uchun kerakligini va uni nega har bir loyihada yuritish shartligini tushunasiz
- `pip freeze` buyrug'i orqali `requirements.txt` yaratishni o'rganasiz
- Versiya belgilash operatorlari (`==`, `>=`, `~=`) orasidagi farqni va har birining oqibatini bilib olasiz
- `requirements.txt` orqali loyihani boshqa (yoki yangi) muhitda aynan bir xil holatda qayta o'rnatishni o'rganasiz

## Nazariy qism

### requirements.txt nima uchun kerak

Har safar `pip install <kutubxona>` bajarganingizda, bu o'rnatish faqat **sizning** venv'ingizda sodir bo'ladi. Loyihani boshqa kompyuterga (yoki serverga, yoki jamoadoshingizga) uzatganingizda, venv papkasining o'zi ko'chirilmaydi (u — juda katta va kompyuterga bog'liq) — shuning uchun **qaysi kutubxonalar va qaysi versiyalarda kerakligi** haqida yozma "retsept" kerak bo'ladi. Aynan shu vazifani `requirements.txt` bajaradi.

### pip freeze — joriy holatni "suratga olish"

```bash
pip freeze
```

```
asgiref==3.8.1
Django==5.2.17
python-slugify==8.0.4
sqlparse==0.5.1
text-unidecode==1.3
```

`pip freeze` — venv'da hozir o'rnatilgan **barcha** paketlarni, ularning **aniq** versiyasi bilan chiqaradi (shu jumladan bilvosita, boshqa paket tortib kelgan `asgiref`, `sqlparse`, `text-unidecode` kabilarni ham). Buni faylga yozib qo'yish uchun:

```bash
pip freeze > requirements.txt
```

### Versiya belgilash operatorlari

| Operator | Misol | Ma'nosi |
|---|---|---|
| `==` | `Django==5.2.17` | Faqat **aynan** shu versiya — eng qat'iy, `pip freeze` shuni ishlatadi |
| `>=` | `Django>=5.0` | Shu versiya yoki undan yangisi — eng bo'sh, kutilmagan yangi (breaking) o'zgarishlarga ochiq |
| `<=` | `Django<=5.2` | Shu versiya yoki undan eskisi |
| `~=` | `Django~=5.2.0` | "Mos keluvchi versiya" — `5.2.0` dan boshlab, lekin `5.3.0`gacha emas (faqat oxirgi raqam o'zgarishi mumkin: patch-yangilanishlar) |
| (belgisiz) | `Django` | Eng so'nggi mavjud versiya — versiyani umuman nazorat qilmaslik |

**Amaliy tavsiya:** ilova (production'ga chiqadigan loyiha) uchun har doim `==` (yoki `~=`) ishlating — bu, "mening kompyuterimda ishlaydi, serverda ishlamaydi" degan klassik muammoning oldini oladi. Faqat qayta ishlatiladigan **kutubxona** (boshqalar `pip install` qiladigan paket) yozayotgan bo'lsangiz, `>=` kabi bo'shroq chegara qo'yish odatiy holat — chunki kutubxonangiz boshqa loyihalar bilan moslashuvchan bo'lishi kerak.

### requirements.txt dan o'rnatish

```bash
pip install -r requirements.txt
```

Bu buyruq faylda ro'yxatlangan **har bir** qatorni ketma-ket o'rnatadi — xuddi siz ularni qo'lda, birma-bir `pip install` qilgandek.

## Amaliy misol

`onlayn_dokon` loyihasida hozirgacha `Django` va `python-slugify` o'rnatilgan deylik. Keling, buni to'g'ri qayd etamiz va boshqa (yangi, "toza") venv'da qayta tiklaymiz:

```bash
# 1) Joriy holatni faylga yozamiz
source venv/bin/activate
pip freeze > requirements.txt
cat requirements.txt
```

```
asgiref==3.8.1
Django==5.2.17
python-slugify==8.0.4
sqlparse==0.5.1
text-unidecode==1.3
```

```bash
# 2) Butunlay yangi, bo'sh venv yaratib, shu fayldan tiklaymiz
deactivate
python3 -m venv venv_test
source venv_test/bin/activate
pip install -r requirements.txt
```

```
Collecting Django==5.2.17 (from -r requirements.txt (line 2))
  ...
Collecting python-slugify==8.0.4 (from -r requirements.txt (line 3))
  ...
Successfully installed Django-5.2.17 asgiref-3.8.1 python-slugify-8.0.4 sqlparse-0.5.1 text-unidecode-1.3
```

```bash
# 3) Tekshiramiz — ikkala venv bir xil paket to'plamiga ega
pip freeze
deactivate
```

`venv_test` — original venv bilan **aynan bir xil** paket va versiyalarga ega bo'ldi, garchi biz hech qaysi paketni qo'lda, nomma-nom o'rnatmagan bo'lsak ham. Ishni tugatgach, sinov uchun yaratilgan `venv_test/` papkasini o'chirib tashlashingiz mumkin.

## Keng tarqalgan xatolar

**Xato 1:** Yangi kutubxona o'rnatib, `requirements.txt`ni yangilashni unutish.

❌ `pip install django-environ` bajarilgan, lekin `pip freeze > requirements.txt` qayta ishga tushirilmagan — natijada boshqa muhitda `pip install -r requirements.txt` bajarilganda, `django-environ` o'rnatilmay qoladi va `ModuleNotFoundError` chiqadi.

✅ Qoidaga aylantiring: **har bir** `pip install`dan so'ng darhol `pip freeze > requirements.txt`ni qayta bajaring (yoki 1.2-darsda ko'rsatiladigan avtomatlashtirilgan vositalardan foydalaning).

**Xato 2:** Versiyalarni umuman belgilamaslik (`requirements.txt`da faqat nomlar, versiyasiz).

❌ `requirements.txt` faylida `Django` (versiyasiz) yozilgan — bir necha oydan keyin, boshqa kompyuterda `pip install -r requirements.txt` bajarilganda, endi **yangi**, ehtimol mos kelmaydigan Django versiyasi o'rnatiladi, va loyihada kutilmagan xatolar chiqadi.

✅ Har doim `pip freeze`dan olingan **aniq** versiyalarni (`==`) saqlang — ayniqsa ilova (production) loyihalarida.

**Xato 3:** `venv/` papkasining o'zini Git'ga qo'shish, `requirements.txt` o'rniga.

❌ `venv/` — yuzlab megabayt, operatsion tizimga bog'liq binar fayllarni o'z ichiga oladi; uni versiyalash tizimiga (Git) qo'shish loyihani og'irlashtiradi va boshqa OS'da ishlamasligi mumkin.

✅ `.gitignore` fayliga `venv/`ni qo'shing, uning o'rniga faqat yengil, matnli `requirements.txt`ni saqlang — u har qanday kompyuterda venv'ni qayta yarata oladi.

## Mashq/topshiriq

**(Oson)** `onlayn_dokon` venv'ida `pip freeze`ni ishga tushiring va natijani `requirements.txt` fayliga yozing. Faylni oching va nechta qator borligini sanang.

**(O'rtacha)** `requirements.txt`da `Django==5.2.17` qatorini qo'lda `Django~=5.2.0`ga o'zgartiring. Bu o'zgarish qanday oqibatga olib kelishini (qaysi kelajakdagi versiyalar hali ham "mos" hisoblanishini) tushuntiring.

**(Qiyin)** Yangi, bo'sh `venv_sinov` yarating, uni faollashtiring, va `onlayn_dokon`ning `requirements.txt` fayli orqali barcha kutubxonalarni o'rnating. So'ng `pip freeze`ni ishga tushirib, natijani asl `requirements.txt` bilan solishtiring (`diff` buyrug'i orqali) — ular bir xil ekanini tasdiqlang.

## Qisqacha xulosa

`requirements.txt` — loyihangiz qaysi kutubxonalarga va qaysi aniq versiyalarga tayanishini yozib qo'yuvchi, `pip freeze > requirements.txt` orqali yaratiladigan va `pip install -r requirements.txt` orqali istalgan boshqa muhitda qayta tiklanadigan "retsept". Versiya belgilash operatorlaridan (`==`, `~=`, `>=`) to'g'risini tanlash — ilova loyihalarida odatda `==` (aniq versiya) — kelajakdagi "mening kompyuterimda ishlaydi" muammolarining oldini oladi. Keyingi darsda — bu faylni qo'lda yangilab yurish o'rniga, jarayonni avtomatlashtiruvchi zamonaviy vositalar (`pip-tools`, Poetry) bilan tanishamiz.
