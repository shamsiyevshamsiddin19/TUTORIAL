# 1.2. Zamonaviy vositalar: pip-tools va Poetry bilan tanishuv

## Bu darsda nimalarni o'rganasiz

- `pip freeze` usulining amaliy cheklovlarini tushunasiz
- `pip-tools` (`pip-compile`, `pip-sync`) qanday ishlashini va nima uchun foydali ekanini bilib olasiz
- Poetry asoslari — `pyproject.toml`, `poetry add`, `poetry.lock` — bilan tanishasiz
- Qaysi vositani qachon tanlash haqida asosli fikr yuritasiz

## Nazariy qism

### pip freeze usulining muammosi

1.1-darsda ko'rgan `pip freeze > requirements.txt` usuli ishlaydi, lekin ikkita amaliy muammosi bor:

1. **To'g'ridan-to'g'ri va bilvosita bog'liqliklar aralashib ketadi.** `requirements.txt` faylida `Django`, `python-slugify` (siz o'zingiz o'rnatgan) va `asgiref`, `text-unidecode` (ular tortib kelgan, bilvosita paketlar) — barchasi bir xil ro'yxatda, farqlanmagan holda turadi. Olti oydan keyin faylga qarab, "men bularning **qaysi birini** o'zim tanlab o'rnatgandim?" — degan savolga javob berish qiyin.
2. **Versiya yangilashda konflikt qo'lda hal qilinadi.** Bitta kutubxonani yangilamoqchi bo'lsangiz, uning boshqa kutubxonalar bilan versiya to'qnashuvi bor-yo'qligini `pip` sizga oldindan aniq ko'rsatmaydi.

### pip-tools yechimi — .in va .txt ajratilishi

`pip-tools` — ikki bosqichli yondashuvni taklif qiladi:

```bash
pip install pip-tools
```

Avval, **faqat o'zingiz to'g'ridan-to'g'ri tanlagan** kutubxonalarni, versiyasiz (yoki bo'sh chegara bilan), `requirements.in` fayliga yozasiz:

```
# requirements.in
Django>=5.2
python-slugify
```

Keyin, `pip-compile` buyrug'i shu asosida **to'liq**, barcha bilvosita bog'liqliklar bilan, izohlangan `requirements.txt`ni **avtomatik** generatsiya qiladi:

```bash
pip-compile requirements.in
```

```
#
# This file is autogenerated by pip-compile
# To update, run: pip-compile requirements.in
#
asgiref==3.8.1
    # via django
django==5.2.17
    # via -r requirements.in
python-slugify==8.0.4
    # via -r requirements.in
sqlparse==0.5.1
    # via django
text-unidecode==1.3
    # via python-slugify
```

E'tibor bering: har bir qator qayerdan (`# via ...`) kelganini ko'rsatadi — endi `asgiref`ning nega borligi (Django tortgan) darhol ko'rinadi. Venv'ni shu faylga **aniq** moslashtirish uchun:

```bash
pip-sync requirements.txt
```

`pip-sync` — `pip install -r`dan farqli, venv'dagi **ortiqcha** (fayl da yo'q) paketlarni ham o'chirib, venv'ni faylga **aynan** moslaydi.

### Poetry — bog'liqlik va loyiha boshqaruvini birlashtiruvchi vosita

Poetry — kengroq vosita: bog'liqliklarni boshqarish bilan bir qatorda, loyiha metama'lumotlarini (`pyproject.toml`), venv yaratishni va hatto paket sifatida chop etishni ham o'z ichiga oladi.

```bash
poetry init          # pyproject.toml yaratadi (savol-javob orqali)
poetry add django    # kutubxona qo'shadi va pyproject.toml'ni yangilaydi
poetry install        # pyproject.toml asosida venv yaratib, hammasini o'rnatadi
```

`pyproject.toml` (qisqartirilgan):

```toml
[tool.poetry.dependencies]
python = "^3.12"
django = "^5.2"
python-slugify = "^8.0"
```

Poetry, `pip-compile`ning `requirements.txt`iga o'xshash, `poetry.lock` faylini avtomatik yaratadi — bu yerda **aniq** versiyalar qayd etiladi, `pyproject.toml`da esa faqat "qabul qilinadigan diapazon" (`^5.2` — `5.x` oralig'i, `pip`dagi `~=` ga yaqin) yoziladi.

### Qaysi vositani tanlash

| Vosita | Qachon mos |
|---|---|
| `pip freeze` (qo'lda) | Juda kichik, o'quv loyihalar — tez, lekin yuqorida sanalgan kamchiliklari bor |
| `pip-tools` | Mavjud `pip`/`requirements.txt` ish jarayoniga **minimal o'zgarish** bilan tartib kiritish kerak bo'lganda |
| Poetry | Yangi loyiha boshidan, to'liq loyiha boshqaruvi (venv, versiyalash, chop etish) bitta vositada kerak bo'lganda |

Bu darslikning qolgan qismida, soddalik uchun, `requirements.txt` (1.1-darsdagi uslub) davom ettiriladi — lekin endi siz uni qachon `pip-tools` yoki Poetry bilan almashtirish mantiqiy ekanini bilasiz.

## Amaliy misol

`onlayn_dokon` uchun `pip-tools`ga o'tish:

```bash
source venv/bin/activate
pip install pip-tools
```

```bash
cat > requirements.in << 'EOF'
Django>=5.2
python-slugify
EOF

pip-compile requirements.in
```

```
asgiref==3.8.1
    # via django
django==5.2.17
    # via -r requirements.in
python-slugify==8.0.4
    # via -r requirements.in
sqlparse==0.5.1
    # via django
text-unidecode==1.3
    # via python-slugify
```

Endi Django'ning yangi minor versiyasi (masalan `5.3`) chiqqanda, sizga faqat kerak:

```bash
pip-compile --upgrade-package django requirements.in
pip-sync requirements.txt
```

— bu ikki qator butun jarayonni (yangi versiyani topish, bilvosita bog'liqliklarni qayta hisoblash, venv'ni yangilash) avtomatlashtiradi.

## Keng tarqalgan xatolar

**Xato 1:** `requirements.in`ni to'g'ridan-to'g'ri `pip install -r requirements.in` bilan ishlatish.

❌ `requirements.in` — atayin versiyasiz yoki bo'sh chegarali; uni to'g'ridan-to'g'ri o'rnatish uchun ishlatish, `pip freeze`dagi "versiyasiz `requirements.txt`" xatosini qaytadan tug'diradi.

✅ Har doim `pip-compile requirements.in` orqali **generatsiya qilingan** `requirements.txt`ni o'rnatish (`pip-sync` yoki `pip install -r requirements.txt`) uchun ishlating; `requirements.in` faqat "niyat"ni yozadi.

**Xato 2:** Bitta loyihada Poetry va oddiy `pip`ni aralashtirib yuborish.

❌ `poetry add django` bilan `pyproject.toml`ga qo'shilgan, lekin keyin kimdir qo'lda `pip install boshqa-kutubxona` bajargan — endi ikki manba (`pyproject.toml` va venv holati) bir-biriga mos kelmaydi.

✅ Loyiha Poetry'ga o'tgan bo'lsa, **barcha** kutubxona qo'shish/o'chirish `poetry add`/`poetry remove` orqali bajarilishi kerak, hech qachon to'g'ridan-to'g'ri `pip install` bilan emas.

**Xato 3:** `poetry.lock` yoki `pip-compile`dan chiqqan `requirements.txt`ni Git'ga qo'shmaslik.

❌ Faqat `pyproject.toml`/`requirements.in` (niyat fayllari) Git'ga qo'shilgan, lock/aniq-versiya fayli — yo'q. Natijada, ikki jamoadosh, bir xil `pyproject.toml`dan, ikki **turli** aniq versiyalar to'plamini olishlari mumkin (agar shu oraliqda yangi versiya chiqqan bo'lsa).

✅ Har doim ham "niyat" faylini (`requirements.in`, `pyproject.toml`), ham "aniq versiya" faylini (`requirements.txt`, `poetry.lock`) Git'ga qo'shing — faqat `venv/`ning o'zi e'tiborsiz qoldiriladi.

## Mashq/topshiriq

**(Oson)** `pip install pip-tools` orqali `pip-tools`ni o'rnating. `requirements.in` fayl yaratib, unga faqat `requests` so'zini yozing, so'ng `pip-compile requirements.in` ishga tushiring va natija (`requirements.txt`) qanday ko'rinishini kuzating.

**(O'rtacha)** `requirements.in`ga yana bitta qator (`python-slugify`) qo'shing, `pip-compile requirements.in`ni qayta ishga tushiring. Yangi `requirements.txt`da qaysi qo'shimcha bilvosita paket(lar) paydo bo'lganini toping va ularning `# via` izohini o'qing.

**(Qiyin)** `poetry init`ni ishga tushiring (savollarga standart javob berib o'ting), so'ng `poetry add django python-slugify` bajaring. `pyproject.toml` va `poetry.lock` fayllarini ochib, `pyproject.toml`dagi versiya belgisi (masalan `^5.2`) bilan `poetry.lock`dagi aniq versiya orasidagi farqni tushuntiring.

## Qisqacha xulosa

`pip freeze`ning "to'g'ridan-to'g'ri va bilvosita bog'liqliklar aralashib ketishi" muammosini `pip-tools` (`requirements.in` → `pip-compile` → izohli `requirements.txt`, `pip-sync` bilan venv'ni aniq moslash) va Poetry (`pyproject.toml` + `poetry.lock`, butun loyiha boshqaruvi bitta vositada) hal qiladi. Kichik/o'quv loyihalar uchun oddiy `pip freeze` yetarli, lekin jiddiy yoki jamoaviy loyihada — ikkala zamonaviy vositadan biri tavsiya etiladi. Keyingi bobdan boshlab, `onlayn_dokon`ga birinchi haqiqiy kutubxonani — sozlamalarni xavfsiz boshqarish uchun `django-environ`ni — qo'shamiz.
