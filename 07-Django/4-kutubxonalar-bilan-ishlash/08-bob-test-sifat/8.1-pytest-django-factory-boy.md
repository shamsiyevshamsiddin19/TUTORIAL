# 8.1. pytest-django va factory_boy

## Bu darsda nimalarni o'rganasiz

- Django'ning standart `unittest`-asosidagi testlaridan `pytest`ga nega o'tish foydali ekanini tushunasiz
- `pytest-django`ni o'rnatib, sozlashni o'rganasiz
- `factory_boy` yordamida test ma'lumotlarini takroriy, oson yaratishni bilib olasiz
- Fixture va factory'larni birgalikda ishlatib, qisqa va o'qishga qulay testlar yozishni o'rganasiz

## Nazariy qism

### Django'ning standart testlaridan farqi

Django'ning o'rnatilgan test tizimi (`django.test.TestCase`) — Python'ning ichki `unittest` modeliga asoslangan: har bir test klass ichida, `self.assertEqual(...)` kabi metodlar bilan yoziladi:

```python
from django.test import TestCase

class MahsulotTest(TestCase):
    def test_narx_manfiy_bolmasligi(self):
        mahsulot = Mahsulot.objects.create(nomi="Non", narxi=5000)
        self.assertEqual(mahsulot.narxi, 5000)
```

Bu ishlaydi, lekin **pytest** — sinov yozishni soddalashtiruvchi, alohida (Django'dan mustaqil) framework, quyidagi afzalliklarga ega: oddiy `assert` so'zi (maxsus `self.assertEqual` metodlari shart emas), qisqaroq sintaksis, va **fixture** tizimi (test uchun kerakli ma'lumotni tayyorlab beruvchi, qayta ishlatiladigan funksiyalar). `pytest-django` — pytest'ni Django loyihalarida ishlatish imkonini beruvchi ko'prik kutubxona.

### pytest uslubida oddiy test

```python
# apps/dokon/tests/test_models.py
import pytest
from apps.dokon.models import Mahsulot


@pytest.mark.django_db   # bu test ma'lumotlar bazasiga murojaat qiladi, deb belgilaydi
def test_mahsulot_yaratish():
    mahsulot = Mahsulot.objects.create(nomi="Non", narxi=5000)
    assert mahsulot.narxi == 5000
    assert str(mahsulot) == "Non"
```

`@pytest.mark.django_db` — **majburiy** belgi: standart holda, pytest testlari ma'lumotlar bazasiga umuman ruxsatga ega emas (bu, tasodifan sinov paytida haqiqiy ma'lumotlarni o'zgartirib qo'yishning oldini oladi); bu belgi bilan, Django har bir test uchun **vaqtinchalik**, testdan keyin avtomatik bekor qilinadigan (rollback) tranzaksiya ochadi.

### Muammo: test ma'lumotlarini qo'lda yaratish

Ko'plab testlarda `Mahsulot`, `Mijoz`, `Buyurtma` kabi obyektlar kerak bo'ladi. Har bir testda ularni qo'lda, barcha majburiy maydonlar bilan yozish — tez zerikarli va takroriy bo'lib qoladi:

```python
mijoz = Mijoz.objects.create(ism="Ali", familiya="Valiyev", email="ali@example.com", telefon="+998901234567")
```

### factory_boy yechimi

```bash
pip install factory_boy
```

`factory_boy` — model uchun "fabrika" klassi yozib, har safar chaqirilganda, **avtomatik**, real ko'rinadigan (lekin tasodifiy) qiymatlar bilan to'ldirilgan obyekt yaratadi:

```python
# apps/dokon/tests/factories.py
import factory
from apps.dokon.models import Mijoz, Mahsulot


class MijozFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Mijoz

    ism = factory.Faker("first_name")
    familiya = factory.Faker("last_name")
    email = factory.Faker("email")
    telefon = factory.Sequence(lambda n: f"+99890{n:07d}")


class MahsulotFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Mahsulot

    nomi = factory.Faker("word")
    narxi = factory.Faker("random_int", min=1000, max=1000000)
```

```python
@pytest.mark.django_db
def test_mijoz_email_unique():
    mijoz1 = MijozFactory()
    mijoz2 = MijozFactory()
    assert mijoz1.email != mijoz2.email   # Faker har safar boshqa qiymat beradi
```

`factory.Faker("email")` — [Faker](https://faker.readthedocs.io/) kutubxonasidan foydalanib, real ko'rinadigan (lekin xayoliy) email generatsiya qiladi; `factory.Sequence` — chaqirilgan tartib raqamiga (`n`) asoslangan, **kafolatlangan noyob** qiymatlar (masalan telefon raqamlari) yaratadi.

## Amaliy misol

`onlayn_dokon`da `Buyurtma` yaratilishini, unga bog'liq barcha obyektlarni factory orqali tayyorlab, sinash:

```python
# apps/dokon/tests/factories.py
import factory
from apps.dokon.models import Mijoz, Mahsulot, Buyurtma, BuyurtmaElementi


class MijozFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Mijoz

    ism = factory.Faker("first_name")
    familiya = factory.Faker("last_name")
    email = factory.Faker("email")


class MahsulotFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Mahsulot

    nomi = factory.Faker("word")
    narxi = factory.Faker("random_int", min=1000, max=500000)
    stock = 10


class BuyurtmaFactory(factory.django.DjangoModelFactory):
    class Meta:
        model = Buyurtma

    mijoz = factory.SubFactory(MijozFactory)   # avtomatik bog'liq Mijoz yaratadi
```

```python
# apps/dokon/tests/test_buyurtma.py
import pytest
from apps.dokon.tests.factories import MijozFactory, MahsulotFactory, BuyurtmaFactory
from apps.dokon.models import BuyurtmaElementi


@pytest.mark.django_db
def test_buyurtma_jami_summa_hisoblanadi():
    mahsulot = MahsulotFactory(narxi=25000)
    buyurtma = BuyurtmaFactory()
    BuyurtmaElementi.objects.create(buyurtma=buyurtma, mahsulot=mahsulot, soni=3)

    assert buyurtma.jami_summani_hisobla() == 75000   # 25000 * 3


@pytest.mark.django_db
def test_buyurtma_mijozsiz_yaratilmaydi():
    mahsulot = MahsulotFactory()
    buyurtma = BuyurtmaFactory()   # SubFactory orqali Mijoz avtomatik yaratildi

    assert buyurtma.mijoz is not None
    assert buyurtma.mijoz.email   # Faker orqali generatsiya qilingan, bo'sh emas
```

```bash
pytest apps/dokon/tests/test_buyurtma.py -v
```

```

apps/dokon/tests/test_buyurtma.py::test_buyurtma_mijozsiz_yaratilmaydi PASSED

================= 2 passed in 0.31s =================
```

`factory.SubFactory(MijozFactory)` — `Buyurtma` yaratilganda, unga bog'liq `Mijoz`ni **avtomatik**, alohida yozilmasdan, tayyorlaydi; test kodi faqat **aslida tekshirilayotgan narsaga** (bu holda, `jami_summani_hisobla()` mantig'iga) e'tibor qaratadi, bog'liq ma'lumotlarni tayyorlash tafsilotlariga emas.

## Keng tarqalgan xatolar

**Xato 1:** `@pytest.mark.django_db` belgisini unutish.

❌ Test ma'lumotlar bazasiga murojaat qiladi (`Mahsulot.objects.create(...)`), lekin `@pytest.mark.django_db` yozilmagan — test `django.db.utils.OperationalError: no such table` yoki shunga o'xshash xato bilan yiqiladi.

✅ Ma'lumotlar bazasiga murojaat qiluvchi **har bir** test funksiyasiga `@pytest.mark.django_db`ni qo'ying; agar bir fayldagi barcha testlar shunga muhtoj bo'lsa, `pytestmark = pytest.mark.django_db`ni fayl boshida bir marta yozish ham mumkin.

**Xato 2:** Factory'da barcha maydonlarni qattiq (hardcoded) qiymat bilan belgilab, `Faker`dan foydalanmaslik.

❌ `email = "test@test.com"` — factory har safar **bir xil** qiymat qaytaradi; ikkita obyekt yaratilganda, agar model'da `email`ga `unique=True` qo'yilgan bo'lsa, ikkinchi `MijozFactory()` chaqiruvi `IntegrityError` bilan yiqiladi.

✅ Noyob bo'lishi kerak bo'lgan maydonlar uchun `factory.Faker(...)` yoki `factory.Sequence(...)`dan foydalaning — bu, har bir chaqiruvda **boshqacha**, real ko'rinadigan qiymat kafolatlaydi.

**Xato 3:** Testda faqat "baxtli yo'l"ni (happy path) tekshirish, chegara holatlarini e'tiborsiz qoldirish.

❌ Faqat `test_buyurtma_jami_summa_hisoblanadi` kabi "hammasi to'g'ri ishlaganda" holatini tekshirish yozilgan; agar `soni=0` yoki manfiy son kiritilsa, yoki `Mahsulot` mavjud bo'lmasa nima bo'lishini tekshiruvchi test yo'q — bunday xatolar production'da, kutilmagan ma'lumot kelganda, sezilmasdan qoladi.

✅ Har bir muhim funksiya uchun, kamida bitta "baxtli yo'l" testidan tashqari, **chegara holatlari**ni ham (bo'sh ma'lumot, manfiy son, mavjud bo'lmagan bog'liq obyekt) sinovdan o'tkazing.

## Mashq/topshiriq

**(Oson)** `pytest` va `pytest-django`ni o'rnating, `pytest.ini` faylini yarating, va `Mahsulot.objects.create(...)`ni tekshiruvchi oddiy testni `@pytest.mark.django_db` bilan yozib, `pytest` buyrug'i orqali ishga tushiring.

**(O'rtacha)** `MahsulotFactory` va `MijozFactory`ni yozing, `Faker` yordamida `nomi`, `narxi`, `email` maydonlarini to'ldiring. Ikkita `MijozFactory()` obyektini yaratib, ularning `email`lari har xil ekanini `assert` bilan tasdiqlang.

**(Qiyin)** `BuyurtmaFactory`da `factory.SubFactory` orqali `Mijoz`ni bog'lang. `soni=0` bilan `BuyurtmaElementi` yaratilsa, `jami_summani_hisobla()` `0` qaytarishini tekshiruvchi chegara holati testini yozing.

## Qisqacha xulosa

`pytest-django` — Django loyihalarida `pytest`ning qisqa sintaksisi (oddiy `assert`, fixture'lar) va boy ekotizimidan foydalanish imkonini beradi, `@pytest.mark.django_db` esa har bir testga ma'lumotlar bazasiga xavfsiz (avtomatik rollback qilinadigan) murojaat huquqini beradi. `factory_boy` — test ma'lumotlarini qo'lda, takroriy yozish o'rniga, `Faker`/`Sequence`/`SubFactory` orqali real ko'rinadigan, noyob va bog'liq obyektlarni avtomatik generatsiya qiladi, natijada testlar qisqaroq va **nimani tekshirayotganiga** e'tiborni jamlagan bo'ladi. Keyingi darsda — yozilgan testlarning loyihaning **qancha qismini** qamrab olganini o'lchash (`coverage.py`) va bog'liqliklardagi xavfsizlik zaifliklarini avtomatik tekshirish (`pip-audit`)ni ko'ramiz.
