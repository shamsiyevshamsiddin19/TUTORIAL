# 0.1. Kutubxona nima, pip va PyPI qanday ishlaydi

## Bu darsda nimalarni o'rganasiz

- Kutubxona (library/package) nima ekanini va nega "hammasini o'zim yozaman" o'rniga tayyor kutubxonalardan foydalanish afzalligini tushunasiz
- PyPI (Python Package Index) nima ekanini va undan qanday qidirishni bilib olasiz
- `pip` orqali kutubxona o'rnatish, ma'lumotini ko'rish, yangilash va o'chirishni o'rganasiz
- Kutubxona o'rnatilganda "orqa tomonda" nima sodir bo'lishini (`site-packages`, bog'liqliklar) tushunasiz

## Nazariy qism

### Kutubxona nima va nega kerak

**Kutubxona** — boshqa dasturchi(lar) yozgan, muayyan vazifani (masalan: rasm bilan ishlash, sana formatlash, HTTP so'rov yuborish) hal qiladigan, siz o'z loyihangizga qo'shib ishlatadigan tayyor kod to'plami. Django'ning o'zi ham — aslida bitta katta kutubxona (aniqrog'i, freymvork).

Nega o'zingiz yozmasdan, kutubxonadan foydalanish kerak:

- **Vaqt tejash** — masalan, rasmni to'g'ri o'lchamga keltirish ko'rinishidan oddiy, lekin format, rang rejimi, EXIF burilish kabi o'nlab nozik holatlarni to'g'ri hal qilish haftalar talab qilishi mumkin; `Pillow` kutubxonasi buni bir necha qatorda hal qiladi.
- **Sinovdan o'tganlik** — mashhur kutubxona minglab loyihada ishlatilgan, ko'plab xato allaqachon topilib tuzatilgan.
- **Community qo'llab-quvvatlashi** — muammoga duch kelsangiz, sizdan oldin ham kimdir duch kelgan va yechim (StackOverflow, GitHub Issues) allaqachon mavjud.

Kamchiligi ham bor: har bir qo'shilgan kutubxona — qo'shimcha **bog'liqlik** (dependency), ya'ni kelajakda versiya yangilanishi, xavfsizlik zaifligi yoki loyihangiz bilan mos kelmasligi mumkin bo'lgan tashqi kod. Shu sababli 0.2-darsda kutubxonani **tanlash mezonlarini** alohida ko'rib chiqamiz.

### PyPI — Python kutubxonalari ombori

**PyPI** (Python Package Index, https://pypi.org) — rasmiy, markazlashgan ombor, u yerda 600 000dan ortiq Python kutubxonasi joylashgan. `pip` buyrug'i standart holda aynan shu yerdan yuklab oladi.

Har bir paket sahifasida (masalan https://pypi.org/project/Pillow/) quyidagilar bo'ladi:

| Qism | Nima uchun kerak |
|---|---|
| **Tavsif (README)** | Kutubxona nima qilishini va asosiy foydalanish misolini ko'rsatadi |
| **Release history** | Barcha chiqarilgan versiyalar va ularning chiqarilgan sanasi |
| **Statistics** | Oxirgi o'rnatishlar soni (mashhurlik ko'rsatkichi) |
| **Project links** | Odatda GitHub repozitoriysiga havola — bu yerda haqiqiy manba kod, Issues (muammolar) va oxirgi commit sanasini ko'rish mumkin |
| **Requires** | Ushbu kutubxona o'zi qaysi boshqa kutubxonalarga tayanishi |

### pip — paket menejeri

`pip` — Python bilan birga keladigan standart paket menejeri. Asosiy buyruqlar:

```bash
pip install python-slugify        # o'rnatish
pip show python-slugify           # o'rnatilgan paket haqida ma'lumot
pip list                          # venv ichida o'rnatilgan barcha paketlar
pip install --upgrade python-slugify   # yangilash
pip uninstall python-slugify      # o'chirish
```

`pip show` natijasi taxminan shunday ko'rinadi:

```
Name: python-slugify
Version: 8.0.4
Summary: A Python slugify application that also handles Unicode
Home-page: https://github.com/un33k/python-slugify
Requires: text-unidecode
Required-by:
```

`Requires` qatori — bu kutubxona o'zi ishlashi uchun boshqa qaysi kutubxonaga (bu yerda `text-unidecode`) tayanishini ko'rsatadi; `pip install` shuni ham avtomatik o'rnatadi. `Required-by` esa — hozircha sizning loyihangizda bu kutubxonaga tayanadigan boshqa paket yo'qligini bildiradi.

### Kutubxona o'rnatilganda nima bo'ladi

`pip install` bajarilganda, kutubxonaning fayllari venv ichidagi `lib/pythonX.Y/site-packages/` papkasiga nusxalanadi. Shundan keyin, `import python_slugify` (yoki paketning haqiqiy modul nomi) — Python shu papkani ham qidirish yo'lida (`sys.path`) ko'radi, shuning uchun kod ichida oddiy `import` orqali foydalanish mumkin bo'ladi.

## Keng tarqalgan xatolar

**Xato 1:** `venv` faollashtirmasdan `pip install` qilish.

❌ Terminalda `(venv)` yozuvi ko'rinmayotganida `pip install python-slugify` bajarilsa, paket **global**, butun tizim Python'iga o'rnatiladi — bu boshqa loyihalar bilan versiya to'qnashuviga olib kelishi mumkin.

✅ Har doim, kutubxona o'rnatishdan oldin, terminal promptida `(venv)` borligini tekshiring. Agar yo'q bo'lsa, avval `source venv/bin/activate` bajaring.

**Xato 2:** O'rnatish nomi bilan import nomini bir xil deb o'ylash.

❌ `pip install python-slugify` dan keyin `import python_slugify` yozish — `ModuleNotFoundError: No module named 'python_slugify'` xatosini beradi.

✅ Har doim kutubxonaning PyPI sahifasidagi "Usage"/"Quick start" qismini tekshiring — u yerda to'g'ri `import` qatori ko'rsatilgan bo'ladi (`python-slugify` uchun bu — `from slugify import slugify`).

**Xato 3:** O'rnatilgan kutubxonani hech qayerda "qayd etmaslik".

❌ `pip install python-slugify` bajarilib, lekin bu haqda hech qanday hujjat (`requirements.txt`) yangilanmasa — boshqa kompyuterda yoki serverda loyihani ishga tushirganda, `ModuleNotFoundError` chiqadi, chunki u yerdagi venv bu kutubxonani "bilmaydi".

✅ Har bir yangi `pip install`dan keyin darhol `requirements.txt`ni yangilang — buni keyingi darsda (1.1) qanday to'g'ri qilishni ko'ramiz.

## Mashq/topshiriq

**(Oson)** `onlayn_dokon` loyihasi venv'ida `python-slugify`ni o'rnating va `pip show python-slugify` orqali uning joriy versiyasini toping.

**(O'rtacha)** Django shell orqali `slugify()` funksiyasidan foydalanib, `"Erkaklar Ko'ylagi — XL o'lcham!"` matnini slug'ga aylantiring. Natijada qanday belgilar (masalan `'`, `!`, bo'sh joy) qanday almashtirilganini kuzating.

**(Qiyin)** `pip install python-slugify==8.0.0` orqali aniq, boshqa versiyani o'rnating (eng so'nggisidan farqli). `pip show python-slugify` orqali versiya haqiqatan `8.0.0` bo'lganini tasdiqlang, so'ng `pip install --upgrade python-slugify` bilan eng so'nggi versiyaga qaytaring.

## Qisqacha xulosa

Kutubxona — boshqa dasturchilar tomonidan yozilgan, sinovdan o'tgan, qayta ishlatsa bo'ladigan kod to'plami; PyPI — bunday kutubxonalarning rasmiy ombori, `pip` esa uni o'rnatish/boshqarish vositasi. `pip install <nom>` kutubxonani venv'ning `site-packages` papkasiga o'rnatadi va uning o'z bog'liqliklarini ham avtomatik tortadi — lekin o'rnatish nomi va Python ichida `import` qilinadigan nom har doim bir xil bo'lavermaydi, shuning uchun har doim kutubxonaning rasmiy hujjatiga qarash kerak. Keyingi darsda — bir xil vazifa uchun bir nechta kutubxona bo'lganda, qaysi birini tanlashni qanday mezonlar bilan hal qilishni ko'ramiz.
