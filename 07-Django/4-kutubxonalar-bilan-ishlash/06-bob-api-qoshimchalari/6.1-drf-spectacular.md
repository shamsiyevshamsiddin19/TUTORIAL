# 6.1. drf-spectacular — avtomatik Swagger/OpenAPI hujjat

## Bu darsda nimalarni o'rganasiz

- Django REST Framework (DRF) nima ekanini va API'ni nega alohida hujjatlashtirish kerakligini tushunasiz
- `drf-spectacular`ni o'rnatib, avtomatik OpenAPI sxemasi generatsiya qilishni o'rganasiz
- Swagger UI va Redoc orqali interaktiv API hujjatini ko'rishni bilib olasiz
- `@extend_schema` orqali sxemaga qo'lda qo'shimcha ma'lumot qo'shishni o'rganasiz

## Nazariy qism

### DRF haqida qisqacha eslatma

Bu boblarda biz `onlayn_dokon`ga **API** qo'shamiz — ya'ni, saytning oddiy HTML sahifalaridan tashqari, boshqa dasturlar (mobil ilova, frontend SPA, boshqa server) JSON formatida ma'lumot olib-yubora oladigan yo'l. Buning uchun eng mashhur kutubxona — **Django REST Framework** (`djangorestframework`), o'zi ham bir kutubxona sifatida o'rnatiladi:

```bash
pip install djangorestframework
```

```python
# settings.py
INSTALLED_APPS += ["rest_framework"]
```

DRF — `Serializer` (model ma'lumotini JSON'ga aylantiruvchi) va `ViewSet`/`APIView` (so'rovlarni qabul qiluvchi) tushunchalariga asoslanadi. Bu darslikning markazi DRF'ning o'zi emas (u alohida katta mavzu), balki DRF **ustiga** qo'shiladigan kutubxonalar — shuning uchun quyida faqat minimal, ishlaydigan misol keltiramiz.

### Nega API'ni hujjatlashtirish kerak

Siz API yozdingiz — lekin uni ishlatadigan boshqa dasturchi (yoki frontend jamoasi) qanday endpointlar borligini, qanday parametr kutilishini, qanday javob qaytishini **qanday biladi**? Qo'lda yozilgan hujjat (masalan Word fayl) tezda eskiradi — kod o'zgaradi, hujjat esa yangilanmay qoladi.

**OpenAPI** (avvalgi nomi Swagger) — API sxemasini tavsiflovchi standart format (JSON/YAML). Bu sxemadan, avtomatik ravishda, interaktiv hujjat sahifasi (Swagger UI) generatsiya qilish mumkin — u har doim **kodning o'zidan** olinadi, shuning uchun hech qachon eskirmaydi.

### drf-spectacular yechimi

```bash
pip install drf-spectacular
```

```python
# settings.py
INSTALLED_APPS += ["drf_spectacular"]

REST_FRAMEWORK = {
    "DEFAULT_SCHEMA_CLASS": "drf_spectacular.openapi.AutoSchema",
}

SPECTACULAR_SETTINGS = {
    "TITLE": "Onlayn Do'kon API",
    "DESCRIPTION": "Onlayn do'kon uchun mahsulot va buyurtma API'si",
    "VERSION": "1.0.0",
}
```

```python
# urls.py
from drf_spectacular.views import SpectacularAPIView, SpectacularSwaggerView, SpectacularRedocView

urlpatterns = [
    # ...
    path("api/schema/", SpectacularAPIView.as_view(), name="schema"),
    path("api/docs/", SpectacularSwaggerView.as_view(url_name="schema"), name="swagger-ui"),
    path("api/redoc/", SpectacularRedocView.as_view(url_name="schema"), name="redoc"),
]
```

Uchta URL — uch xil vazifa: `/api/schema/` xom OpenAPI sxemasini (YAML) qaytaradi, `/api/docs/` — Swagger UI (interaktiv, "Try it out" tugmasi bilan endpointlarni sinab ko'rish mumkin), `/api/redoc/` — Redoc (o'qishga qulayroq, statik hujjat ko'rinishi).

### @extend_schema orqali qo'shimcha ma'lumot

`drf-spectacular` ko'p narsani (model maydonlari, serializer turlari) **avtomatik** aniqlaydi, lekin ba'zida qo'lda tushuntirish kerak bo'ladi — masalan, endpoint nima qilishini so'zlar bilan izohlash:

```python
from drf_spectacular.utils import extend_schema

class MahsulotViewSet(viewsets.ModelViewSet):
    queryset = Mahsulot.objects.all()
    serializer_class = MahsulotSerializer

    @extend_schema(description="Faqat mavjud (stock > 0) mahsulotlarni qaytaradi.")
    @action(detail=False, methods=["get"])
    def mavjud(self, request):
        mahsulotlar = self.queryset.filter(stock__gt=0)
        serializer = self.get_serializer(mahsulotlar, many=True)
        return Response(serializer.data)
```

## Amaliy misol

`onlayn_dokon`ga `Mahsulot` uchun minimal API va uning avtomatik hujjati:

```python
# apps/dokon/serializers.py
from rest_framework import serializers
from .models import Mahsulot


class MahsulotSerializer(serializers.ModelSerializer):
    class Meta:
        model = Mahsulot
        fields = ["id", "nomi", "narxi", "rasm", "stock"]
```

```python
# apps/dokon/api_views.py
from rest_framework import viewsets
from drf_spectacular.utils import extend_schema_view, extend_schema
from .models import Mahsulot
from .serializers import MahsulotSerializer


@extend_schema_view(
    list=extend_schema(description="Barcha mahsulotlar ro'yxati."),
    retrieve=extend_schema(description="Bitta mahsulot haqida to'liq ma'lumot."),
)
class MahsulotViewSet(viewsets.ModelViewSet):
    queryset = Mahsulot.objects.all()
    serializer_class = MahsulotSerializer
```

```python
# onlayn_dokon/urls.py
from rest_framework.routers import DefaultRouter
from drf_spectacular.views import SpectacularAPIView, SpectacularSwaggerView, SpectacularRedocView
from apps.dokon.api_views import MahsulotViewSet

router = DefaultRouter()
router.register("mahsulotlar", MahsulotViewSet)

urlpatterns = [
    # ...
    path("api/", include(router.urls)),
    path("api/schema/", SpectacularAPIView.as_view(), name="schema"),
    path("api/docs/", SpectacularSwaggerView.as_view(url_name="schema"), name="swagger-ui"),
]
```

```bash
python manage.py runserver
```

Endi `http://localhost:8000/api/docs/` sahifasini ochsangiz — barcha `/api/mahsulotlar/` endpointlari (GET ro'yxat, POST yaratish, GET/PUT/DELETE bitta mahsulot), ularning kutilgan JSON tuzilishi, va yuqoridagi izohlar avtomatik ko'rinadi. Kod o'zgarsa (masalan `Mahsulot`ga yangi maydon qo'shilsa), hujjat **qayta yozmasdan**, o'zi yangilanadi.

## Keng tarqalgan xatolar

**Xato 1:** `DEFAULT_SCHEMA_CLASS`ni `REST_FRAMEWORK` sozlamasida ko'rsatishni unutish.

❌ `drf-spectacular` o'rnatilgan, `INSTALLED_APPS`ga qo'shilgan, lekin `REST_FRAMEWORK["DEFAULT_SCHEMA_CLASS"]` sozlanmagan — DRF standart holda eskirgan `AutoSchema`dan foydalanadi, natijada `/api/schema/` sahifasi to'liq yoki to'g'ri ishlamaydi.

✅ `drf-spectacular` o'rnatilgach, `REST_FRAMEWORK = {"DEFAULT_SCHEMA_CLASS": "drf_spectacular.openapi.AutoSchema"}`ni **darhol** qo'shing — bu, o'rnatish jarayonining ajralmas qismi.

**Xato 2:** Serializer'da `fields = "__all__"` ishlatib, keraksiz (yoki maxfiy) maydonlarni tasodifan API orqali oshkor qilish.

❌ `class Meta: fields = "__all__"` — model'ga keyinchalik qo'shilgan har qanday yangi maydon (masalan ichki `xarid_narxi` — tannarx, mijozga ko'rsatilmasligi kerak bo'lgan) **avtomatik** API'da paydo bo'ladi, dasturchi buni sezmasligi mumkin.

✅ Har doim `fields`ni **aniq ro'yxat** sifatida yozing (`fields = ["id", "nomi", "narxi", "rasm", "stock"]`) — shunda yangi model maydoni API'da avtomatik chiqmaydi, uni ataylab qo'shish kerak bo'ladi.

**Xato 3:** `SPECTACULAR_SETTINGS`da `TITLE`/`DESCRIPTION`ni sozlamasdan, "generic" hujjat bilan qolib ketish.

❌ `SPECTACULAR_SETTINGS` umuman qo'shilmagan — Swagger UI sahifasida umumiy "API" nomi ko'rinadi, bu API bilan ishlaydigan boshqa dasturchi uchun tushunarsiz va professional ko'rinmaydi.

✅ Loyihaning boshida, `SPECTACULAR_SETTINGS`ga aniq `TITLE`, `DESCRIPTION`, `VERSION` yozing — bular Swagger UI sahifasining sarlavhasida va tavsifida ko'rinadi.

## Mashq/topshiriq

**(Oson)** `djangorestframework` va `drf-spectacular`ni o'rnating, `INSTALLED_APPS`, `REST_FRAMEWORK`, `SPECTACULAR_SETTINGS`ni sozlang, va `/api/schema/`, `/api/docs/` URL'larini qo'shing.

**(O'rtacha)** `Mahsulot` uchun `MahsulotSerializer` va `MahsulotViewSet` yozing, `router`ga ro'yxatdan o'tkazing. `/api/docs/` sahifasini ochib, `GET /api/mahsulotlar/` endpointini "Try it out" orqali sinab ko'ring.

**(Qiyin)** `MahsulotViewSet`ga, `@action` va `@extend_schema` yordamida, faqat `stock > 0` bo'lgan mahsulotlarni qaytaruvchi `mavjud` degan qo'shimcha endpoint (`/api/mahsulotlar/mavjud/`) qo'shing, tavsif bilan.

## Qisqacha xulosa

`drf-spectacular` — Django REST Framework ustiga qurilgan API'ni, kodning o'zidan (model, serializer, viewset) avtomatik OpenAPI sxemasi generatsiya qilib, hech qachon eskirmaydigan, interaktiv hujjat (Swagger UI, Redoc) bilan ta'minlaydi; `@extend_schema` orqali avtomatik aniqlanmaydigan qo'shimcha ma'lumotlarni qo'lda kiritish mumkin. Keyingi darsda — API'ni filtrlash (`django-filter`) va boshqa domendan (masalan frontend ilova boshqa portda ishlayotganda) so'rov qilish imkonini beruvchi (`django-cors-headers`) kutubxonalarni qo'shamiz.
