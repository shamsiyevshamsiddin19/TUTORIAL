# 5.2. Shablon tilini chuqur o'qish — `{{ }}`, `{% %}`, `extends`/`block`, filtrlar

## Bu darsda nimalarni o'rganasiz

- `{{ }}` (o'zgaruvchi chiqarish) va `{% %}` (mantiq — sikl, shart, meros) orasidagi farqni
- Nuqta (`.`) operatori, shablon ichida, **to'rtta turli narsani** anglashi mumkinligini (lug'at kaliti, atribut, ro'yxat indeksi, metod chaqiruvi) — va Django buni qanday "hal qilishini"
- `{% extends %}` va `{% block %}` — shablon **merosxo'rligi** qanday ishlashini, va `{{ block.super }}`ni
- Eng ko'p ishlatiladigan filtrlarni (`|length`, `|default`, `|floatformat`) va ularning aniq xulqini

## Nazariy qism

### Ikki xil qavs — ikki xil vazifa

Django shablon tilida, ikkita **butunlay boshqa maqsadli** sintaksis bor:

```django
{{ bolim.nomi }}          {# — QIYMAT chiqarish (o'zgaruvchi, natija HTML'ga yoziladi) #}
{% for bolim in bolimlar %}   {# — MANTIQ (sikl, shart, meros — natija HTML'ga TO'G'RIDAN-TO'G'RI yozilmaydi) #}
```

Qoida oddiy: agar siz **biror narsani ko'rsatmoqchi** bo'lsangiz (o'zgaruvchi qiymati) — `{{ }}`; agar siz **biror amalni bajarmoqchi** bo'lsangiz (takrorlash, shart tekshirish, boshqa fayldan meros olish) — `{% %}`. `{# ... #}` — izoh (HTML'ning `<!-- -->`siga o'xshash, lekin HTML chiqishida **umuman ko'rinmaydi**, `<!-- -->`dan farqli o'laroq).

### Nuqta (`.`) operatori — to'rtta ma'noni anglaydi

Python'da, `obj.x`, `obj["x"]`, `obj.metod()` va `royxat[0]` — bularning har biri, **boshqa-boshqa sintaksis**. Django shablon tilida esa, bularning **barchasi — bitta, yagona `.` yozuvi**:

```python
from django.template import Template, Context

t1 = Template("{{ obj.x }}")
print(t1.render(Context({"obj": {"x": "LUGAT"}})))       # lug'at kaliti orqali

class Ob:
    x = "ATRIBUT"
print(t1.render(Context({"obj": Ob()})))                  # ob'ekt atributi orqali

class Ob2:
    def x(self):
        return "METOD"
print(t1.render(Context({"obj": Ob2()})))                 # metod chaqiruvi orqali (QAVSSIZ!)

t2 = Template("{{ royxat.0 }}")
print(t2.render(Context({"royxat": ["BIRINCHI", "IKKINCHI"]})))  # ro'yxat indeksi orqali
```

Natija — hammasi ishlaydi: `LUGAT`, `ATRIBUT`, `METOD`, `BIRINCHI`. Django, `obj.x` ko'rilganda, quyidagi tartibda, **ketma-ket urinib ko'radi**: (1) `obj["x"]` (lug'at kaliti sifatida); (2) `obj.x` (Python atributi sifatida); (3) `obj.x()` (agar `x` — **chaqiriladigan** (callable) bo'lsa, uni **avtomatik chaqiradi**, natijani oladi); (4) `obj[0]` (agar `x` — raqam bo'lsa, ro'yxat indeksi sifatida). Birinchi muvaffaqiyatli variant ishlatiladi, qolganlari sinalmaydi. Aynan shu sabab, 5.1'da ko'rgan `{{ bolim.mahsulotlar.count }}` — qavssiz ishlagan: `count` — Python'da **metod** (`.count()`), lekin shablon uni, "chaqiriladigan narsa" deb topib, **o'zi chaqirgan**.

**Muhim ogohlantirish:** aynan shu sabab, shablon ichida, **argument qabul qiladigan** metodlarni chaqirib bo'lmaydi (masalan, `{{ mahsulot.narxini_hisobla.5 }}` — `narxini_hisobla(5)` degani EMAS, bu, `narxini_hisobla` metodini, argumentsiz chaqirishga urinadi, xato beradi). Argument kerak bo'lsa — bu mantiq, view ichida (Python'da) tayyorlanib, context orqali uzatilishi kerak — shablon, hisoblash uchun emas, faqat **ko'rsatish** uchun mo'ljallangan joy.

### `{% extends %}` va `{% block %}` — shablon merosxo'rligi

3.1-4.2 darslarda, Python klasslarida meros olishni (`class Bolim(models.Model)`) ko'rgan edingiz. Shablonlarda ham, shunga o'xshash g'oya bor — **umumiy "skelet"ni** bitta faylga yozib, boshqa fayllar undan meros oladi:

```html
{# apps/dokon/templates/dokon/asos.html #}
<!DOCTYPE html>
<html lang="uz">
<head>
    <meta charset="UTF-8">
    <title>{% block sarlavha %}Onlayn Do'kon{% endblock %}</title>
</head>
<body>
    <header><h1>Onlayn Do'kon</h1></header>
    <main>
        {% block mazmun %}{% endblock %}
    </main>
</body>
</html>
```

```html
{# apps/dokon/templates/dokon/bolimlar_royxati.html #}
{% extends "dokon/asos.html" %}

{% block sarlavha %}Bo'limlar ro'yxati{% endblock %}

{% block mazmun %}
    <h2>Bo'limlar ({{ bolimlar|length }} ta)</h2>
    ...
{% endblock %}
```

`{% extends "dokon/asos.html" %}` — **har doim, faylning birinchi qatori** bo'lishi kerak (bu — qat'iy qoida). `{% block sarlavha %}...{% endblock %}` — ota shablondagi, shu nom bilan e'lon qilingan "bo'sh joy"ni, **bolаning o'z mazmuni bilan almashtiradi**. Diqqat qiling: `asos.html`da, `{% block sarlavha %}Onlayn Do'kon{% endblock %}` ichida **standart qiymat** (`Onlayn Do'kon`) bor — agar bola shablon, o'sha blokni **umuman qayta yozmasa**, aynan shu standart matn ishlatiladi.

### `{{ block.super }}` — ota blokni **almashtirmasdan, qo'shish**

Ba'zan, bola shablon, ota blokni butunlay o'chirib tashlamasdan, unga **qo'shimcha qilmoqchi** bo'ladi:

```html
{% block mazmun %}{{ block.super }} + QOSHIMCHA{% endblock %}
```

Bu, `asos.html`dagi asl matn (`{% block mazmun %}`ning standart qiymati) + `" + QOSHIMCHA"`ni birlashtirib chiqaradi. Real sinovda (soddalashtirilgan shablon bilan):

```
BOSHI-[ASOSIY + QOSHIMCHA]-OXIRI
```

**Va yana bir, kam ma'lum, lekin muhim qoida** — agar bola shablonda, `{% extends %}`dan keyin, biror matn **hech qanday `{% block %}` ichiga olinmasa**, u matn — **shunchaki, sezilmasdan, e'tiborsiz qoldiriladi** (hech qanday xato, hech qanday ogohlantirish yo'q):

```html
{% extends "parent.html" %}
Bu matn hech qanday blok ichida emas
```

Bu shablonning natijasi — yuqoridagi "Bu matn..." qatori **umuman ko'rinmaydi**, xuddi u yozilmagandek. Sabab: `extends` ishlatilganda, bola shablonning **faqat `{% block %}` ichidagi qismlari** "hisobga olinadi" — qolgan hamma narsa (mabodo tasodifan HTML yoki matn yozib qo'yilgan bo'lsa ham) — Django uchun, shunchaki, mavjud emas.

## Kodni o'qish mashqi

Quyidagi ikkita filtr chaqiruvini ko'ring:

```django
{{ mahsulot.narxi }}
{{ mahsulot.narxi|floatformat:0 }}
```

`mahsulot.narxi` — `models.py`da `DecimalField(max_digits=10, decimal_places=2)` sifatida e'lon qilingan, va bazada `5000000.00` qiymati saqlangan. **Bashorat qiling:** ikkala qatorning natijasi bir xil bo'ladimi, yo'qmi? Agar farq bo'lsa — nima farq qiladi?

<details>
<summary>Javobni ko'rish</summary>

Natijalar **farq qiladi**:
```
5000000.00
5000000
```
`{{ mahsulot.narxi }}` — hech qanday filtrsiz, Python'ning `Decimal` ob'ektini, uning **standart** matn ko'rinishida chiqaradi (`decimal_places=2` bo'lgani uchun, doim ikkita raqam bilan: `5000000.00`). `|floatformat:0` filtri esa, qiymatni, **ko'rsatish maqsadida**, "0 ta kasr raqami" bilan qayta formatlaydi (yaxlitlaydi) — natija `5000000` (nuqtasiz). Muhim: `floatformat` — faqat **ko'rsatilishini** o'zgartiradi, bazadagi yoki Python xotirasidagi asl qiymatning o'ziga hech qanday ta'sir qilmaydi.

</details>

## Amaliy misol

Eng ko'p ishlatiladigan uchta filtrni, real ma'lumot bilan sinaymiz:

```python
from django.template import Template, Context
from apps.dokon.models import Mahsulot

mah = Mahsulot.objects.get(nomi="Noutbuk")
t = Template(
    "Narxi: {{ mahsulot.narxi }} so'm | "
    "floatformat: {{ mahsulot.narxi|floatformat:0 }} | "
    "default sinovi: {{ bosh_qiymat|default:\"noma'lum\" }}"
)
print(t.render(Context({"mahsulot": mah, "bosh_qiymat": ""})))
```

```
Narxi: 5000000.00 so'm | floatformat: 5000000 | default sinovi: noma'lum
```

`|default:"noma'lum"` — agar o'zgaruvchi **"yolg'on" (falsy)** qiymatga ega bo'lsa (`""`, `None`, `0`, `[]`, `False`) — ko'rsatilgan standart matnni chiqaradi. Diqqat: bu, 5.1'dagi "mavjud bo'lmagan o'zgaruvchi — bo'sh matn" holatidan **farq qiladi** — `default` filtri, o'zgaruvchi **mavjud, lekin bo'sh** bo'lganda ishlaydi; agar o'zgaruvchi context'da **umuman yo'q** bo'lsa ham, aslida `default` baribir ishlaydi (chunki mavjud bo'lmagan o'zgaruvchi ham, Django uchun "bo'sh" qiymat sifatida qaraladi) — ammo bu ikki holatni chalkashtirmaslik kerak: birida — qiymat **qasddan** bo'sh, ikkinchisida — **kalit nomi umuman xato** (5.1'dagi asosiy xato manbai).

## Keng tarqalgan xatolar

**Xato 1:** Filtrni, Python funksiyasidek, qavs bilan chaqirishga urinish.
❌ `{{ mahsulot.narxi|floatformat(0) }}`
```
TemplateSyntaxError: Could not parse the remainder: '(0)' from 'floatformat(0)'
```
✅ Filtr argumenti — qavssiz, **ikki nuqta** (`:`) orqali beriladi: `{{ mahsulot.narxi|floatformat:0 }}`.

**Xato 2:** `{% extends %}`ni, faylning birinchi qatori qilib yozmaslik (masalan, oldiga izoh yoki bo'sh qator qo'yish).
❌
```html
{# Bu — mening shablonim #}
{% extends "dokon/asos.html" %}
```
```
TemplateSyntaxError: 'extends' cannot appear more than once in the same template  (yoki boshqa kontekstda — extends e'tiborga olinmasligi)
```
✅ `{% extends %}` — shablon faylining **eng birinchi** qatori bo'lishi shart (izoh ham, undan oldin bo'lmasligi kerak).

**Xato 3:** Bola shablonda, `{% block %}` nomini, ota shablondagi nom bilan **aniq mos kelmaydigan** qilib yozish (masalan, imlo xatosi).
❌ Ota: `{% block mazmun %}`, Bola: `{% block mazmuni %}` (oxiriga "i" qo'shilgan).
Natija: **xato chiqmaydi**, lekin bola shablondagi mazmun, hech qayerda ko'rinmaydi (chunki, yuqorida ko'rganimizdek, blok tashqarisidagi — yoki, bu holda, "mos kelmagan nomli" — mazmun, e'tiborsiz qoldiriladi).
✅ Blok nomlarini, ota va bola shablonlarda, **so'zma-so'z bir xil** yozish — va, iloji bo'lsa, IDE'ning "qidirish" funksiyasi orqali, ota shablondagi barcha blok nomlarini oldindan ro'yxatlab olish.

## Mashq/topshiriq

**(Oson)** `bolimlar_royxati.html`ga, har bir bo'lim nomi yonida, uning nomini **katta harflarda** ko'rsatuvchi filtr qo'shing (maslahat: Django'da tayyor `|upper` filtri bor). Natijani tekshiring.

**(O'rtacha)** `asos.html`dagi `{% block mazmun %}`ni, ikkita shablonda ham (`bolimlar_royxati.html` va `mahsulotlar_royxati.html`), boshida `<p>Sahifa: ...</p>` qatorini `{{ block.super }}`siz qo'shib "kengaytiring" — ya'ni, avvalgi mazmunni yo'qotmasdan, ustiga bitta qator qo'shing. **Bashorat qiling:** `{{ block.super }}`ni unutib qo'ysangiz (faqat yangi mazmunni yozsangiz), avvalgi ro'yxat (bo'limlar/mahsulotlar) hali ham ko'rinadimi?

**(Qiyin)** `Mahsulot` modeliga (4-bobda ko'rganimizdek) yangi metod qo'shing:
```python
def chegirmali_narx(self, foiz):
    return self.narxi * (1 - foiz / 100)
```
Shablonda, `{{ mahsulot.chegirmali_narx }}` (argumentsiz) yozib ko'ring — **bashorat qiling:** bu, 500-xato (`TypeError`, chunki `foiz` argumenti berilmagan) bilan qulaydimi, yoki boshqacha xulq ko'rsatadimi? Keyin, `{{ mahsulot.chegirmali_narx:10 }}` kabi "argument berishga urinib" ko'ring — bu ishlaydimi? Nihoyat, muammoni **to'g'ri** yechish uchun, view ichida, context'ga tayyor natijani (`"chegirmali_narx": mahsulot.chegirmali_narx(10)`) qo'shib uzating.

<details>
<summary>Javoblarni ko'rish</summary>

1.
```django
<strong>{{ bolim.nomi|upper }}</strong>
```
Natija: `ELEKTRONIKA`, `KIYIM-KECHAK` — original katakcha harflar, katta harflarga aylanadi. Bazadagi yoki Python xotirasidagi qiymatga hech qanday ta'sir yo'q — bu, faqat **ko'rsatish** darajasidagi o'zgarish.

2. Ha, `{{ block.super }}`ni unutib qo'ysangiz, **avvalgi ro'yxat butunlay yo'qoladi** — chunki `{% block mazmun %}yangi matn{% endblock %}`, ota shablondagi standart mazmunni **to'liq almashtiradi** (`{{ block.super }}` yozilmasa). Bu — Python klasslaridagi metodni **qayta yozish (override)**ga o'xshaydi: agar siz, meros olib turib, ota metodni chaqirmasangiz (`super().metod()`), ota mantiq **umuman ishlamaydi** — xuddi shu tamoyil, shablon bloklarida ham amal qiladi.

3. **Bashoratingiz, katta ehtimol bilan, noto'g'ri chiqadi** — bu, darsdagi eng "hiylakor" savol! `{{ mahsulot.chegirmali_narx }}` (argumentsiz) — 500-xato **bermaydi**. Real natija:
```python
from django.template import Template, Context

class FakeMahsulot:
    narxi = 5000000
    def chegirmali_narx(self, foiz):
        return self.narxi * (1 - foiz / 100)

t = Template("{{ mahsulot.chegirmali_narx }}")
print(repr(t.render(Context({"mahsulot": FakeMahsulot()}))))
```
```
''
```
**Bo'sh matn — hech qanday xato yo'q!** Sabab — Django shablon motorining, aynan shu holat uchun yozilgan, ataylab qilingan xulqi: `current()`ni argumentsiz chaqirishga urinadi, `TypeError` chiqsa, Django, metodning "imzosi"ni (signature) tekshiradi — agar metod, chindan ham, majburiy argument talab qilsa (aynan bizning holatimizdagi kabi), Django buni **qayta ko'tarmaydi**, aksincha, natijani, oddiy "mavjud bo'lmagan o'zgaruvchi" bilan **bir xil** qiladi — bo'sh matn. Boshqacha aytganda: Django, shablon ichida ishlatilgan metodlarning **argumentsiz chaqirilishi mumkinligini oldindan bilmaydi**, shuning uchun, "ehtiyot chorasi" sifatida, bunday chaqiruvlarni ham, jim, xatosiz "yutib yuboradi". Bu — 5.1'da ko'rgan "kalit nomi xato — jim xato" qoidasidan **ham kengroq** ekan: hatto to'g'ri nomli, lekin **argument talab qiladigan** metod chaqiruvi ham, xuddi shunday, sezilmasdan "yo'qoladi".

`{{ mahsulot.chegirmali_narx:10 }}` — bu, umuman **argument uzatish sifatida talqin qilinmaydi** (Django shablon tili buni tushunmaydi, `:` — faqat filtr argumenti uchun ishlatiladi), va bu safar — **haqiqiy, ochiq xato**:
```
TemplateSyntaxError: Could not parse the remainder: ':10' from 'mahsulot.chegirmali_narx:10'
```
Bu xato — shablon **kompilyatsiya** bosqichida (server ishga tushishi bilanoq, birinchi so'rovda) chiqadi, "jim xato" emas, chunki bu — sintaksis darajasidagi, Django tushunmaydigan yozuv. Xulosa: shablon tilida ikki xil "xatolik darajasi" bor — **sintaksis xatosi** (kompilyatsiyada, doim ochiq, `TemplateSyntaxError`) va **qiymatni aniqlay olmaslik** (ishga tushirishda, ko'pincha jim, bo'sh natija bilan). To'g'ri yechim — argumentli metodlarni, **shablon ichida emas, Python (view) ichida chaqirish**:
```python
def mahsulotlar_royxati(request):
    mahsulotlar = Mahsulot.objects.all()
    context = {
        "mahsulotlar": mahsulotlar,
        # har bir mahsulot uchun alohida hisoblash kerak bo'lsa, view ichida tayyorlanadi
    }
    return render(request, "dokon/mahsulotlar_royxati.html", context)
```
Bu — shablon tilining **falsafasi**ni ko'rsatadi: shablon — faqat "ko'rsatish" uchun, murakkab hisob-kitob va argumentli chaqiruvlar — Python (view) tomonida bajarilishi kerak.

</details>

## Qisqacha xulosa

`{{ }}` — qiymat chiqaradi, `{% %}` — mantiq (sikl, shart, meros) ifodalaydi. Nuqta (`.`) operatori, shablon ichida, lug'at kaliti, ob'ekt atributi, ro'yxat indeksi va (argumentsiz) metod chaqiruvini — bittasi ishlagunicha, ketma-ket sinab ko'radi. `{% extends %}` (har doim birinchi qator) va `{% block %}` — shablon merosxo'rligini beradi; `{{ block.super }}`siz, bola blok, ota blokni **to'liq almashtiradi**; blok tashqarisidagi (yoki mos kelmagan nomli) mazmun — jim, sezilmasdan yo'qoladi. Filtrlar (`|floatformat`, `|default`, `|upper`) — faqat **ko'rsatilishni** o'zgartiradi, asl ma'lumotga ta'sir qilmaydi, va argument qabul qilmaydi (faqat bitta, `:` orqali beriladigan parametr bundan mustasno) — murakkab hisob-kitoblar, view (Python) darajasida bajarilishi kerak. Shu bilan, 05-bob (Views va Templates'ni o'qish) yakunlandi — keyingi bo'limda, Django admin panelini va formalarni "o'qishni" o'rganamiz.
