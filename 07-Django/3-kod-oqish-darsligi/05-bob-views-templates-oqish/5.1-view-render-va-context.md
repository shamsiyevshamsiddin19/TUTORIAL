# 5.1. `render()` va context — View'dan Template'ga ma'lumot qanday "oqadi"

## Bu darsda nimalarni o'rganasiz

- `HttpResponse` bilan `render()` orasidagi farqni — nega ko'pchilik real view `render()` ishlatishini
- **`context`** so'zi aslida nima ekanini — bu, oddiy Python lug'ati (`dict`) ekanini, "sehr" emasligini
- View ichida, bazadan (`Bolim.objects.all()`) ma'lumot olib, uni template'ga qanday "uzatish"ni
- Nega Django template'lari, Python kodidan farqli o'laroq, **xato bermasdan, "jim" ishlayverishini** (bu — keyingi darsda chuqurroq ko'riladigan, muhim xavfsizlik va debug mavzusi)

## Nazariy qism

### `HttpResponse` — qo'lda yozilgan HTML, `render()` — faylga asoslangan HTML

3-bobda siz `HttpResponse("matn")` bilan ishlagan edingiz — bu, Python satrini, to'g'ridan-to'g'ri, javob sifatida qaytaradi. Lekin haqiqiy sahifalar (HTML teglar, ko'p qatorli tuzilma) uchun, matnni Python faylining ichida, qo'shtirnoq ichida yozish — noqulay va xavfli (HTML va Python kodi aralashib ketadi). Shuning uchun Django, alohida **shablon fayllari** (`.html`) va ularni "chizib beruvchi" `render()` funksiyasini taklif qiladi:

```python
from django.http import HttpResponse
from django.shortcuts import render

from .models import Bolim


def bolimlar_royxati(request):
    barcha_bolimlar = Bolim.objects.all()
    context = {"bolimlar": barcha_bolimlar}
    return render(request, "dokon/bolimlar_royxati.html", context)
```

Buni satrma-satr o'qiymiz. `barcha_bolimlar = Bolim.objects.all()` — 4-bobda o'rgangan, oddiy QuerySet (hali bazaga so'rov yubormagan, "dangasa" ob'ekt). `context = {"bolimlar": barcha_bolimlar}` — **bu, oddiy Python lug'ati (`dict`)**, hech qanday maxsus Django klassi emas: kalit (`"bolimlar"`) — bu, template ichida ishlatiladigan **nom**, qiymat (`barcha_bolimlar`) — bu, o'sha nomga "biriktirilgan" haqiqiy ma'lumot. `render(request, "dokon/bolimlar_royxati.html", context)` — uchta argument: (1) `request` — har doim birinchi, keladigan so'rov ob'ekti (nega kerakligini pastda ko'ramiz); (2) shablon faylining **manzili** (`APP_DIRS=True` tufayli, Django buni `apps/dokon/templates/dokon/bolimlar_royxati.html`dan qidiradi — 1-bobda ko'rgan sozlama, endi amalda); (3) `context` — yuqorida tayyorlagan lug'at.

### `render()` — aslida, uchta ishni birlashtirgan qulaylik funksiyasi

`render()` — "sehr" emas, u, aslida, quyidagi uchta qadamni **birlashtirib** bajaradi (Django manba kodida, aynan shu tartibda):

```python
# render() "ichida" (soddalashtirilgan) shu sodir bo'ladi:
from django.template.loader import get_template

template = get_template("dokon/bolimlar_royxati.html")   # 1) faylni topish va o'qish
html_matn = template.render(context, request)              # 2) context bilan "to'ldirish"
return HttpResponse(html_matn)                              # 3) HttpResponse'ga o'rash
```

Bu — muhim, chunki endi tushunarli: **`render()` ham, oxir-oqibat, `HttpResponse` qaytaradi** — u, shunchaki, HTML matnini fayldan o'qib, `context` bilan "to'ldirib", keyin uni `HttpResponse` ichiga joylashtirish jarayonini soddalashtiradi. `request` argumenti nega kerak — chunki `TEMPLATES` sozlamasidagi `context_processors` (1-bobda ko'rgan), har bir shablonga, `request` orqali, qo'shimcha, avtomatik o'zgaruvchilar (masalan, `{{ request.path }}`) qo'shishi mumkin — bu context_processor'lar, aynan `request` ob'ektiga muhtoj.

### Shablon papkasi qayerda — va nega aynan shu joyda

```
apps/dokon/
├── templates/
│   └── dokon/
│       ├── asos.html
│       └── bolimlar_royxati.html
├── views.py
```

**Savol tug'ilishi mumkin:** nega `templates/dokon/...`, nega shunchaki `templates/bolimlar_royxati.html` emas? Bu — ataylab qilingan, muhim konvensiya: agar ikkita turli app'da (masalan, `dokon` va kelajakdagi boshqa app'da) bir xil nomli shablon (`royxat.html`) bo'lsa-yu, ikkalasi ham `templates/`ning **to'g'ridan-to'g'ri ichida** bo'lsa — Django, qaysi birini olishni bilmay, **noto'g'ri app'ning** shablonini yuklab qo'yishi mumkin. `templates/<app_nomi>/...` ichki papka — bu muammoni oldini oladi (xuddi Python'dagi `apps.dokon.urls`ga o'xshab, "app nomi bilan nomlash" — bu yerda ham papka darajasida takrorlanadi).

## Kodni o'qish mashqi

Quyidagi view va shablon **haqiqiy loyihada** ishga tushirilgan, natija — real `curl` chiqishi:

```python
def bolimlar_royxati(request):
    barcha_bolimlar = Bolim.objects.all()
    context = {"bolimlar": barcha_bolimlar}
    return render(request, "dokon/bolimlar_royxati.html", context)
```

Shablon ichida (5.2'da to'liq o'rganamiz) — `{{ bolim.nomi }}` degan qator bor. **Bashorat qiling:** agar siz, `context` lug'atidagi kalitni, ataylab xato yozsangiz — masalan, `context = {"bolim_royxati": barcha_bolimlar}` (`"bolimlar"` o'rniga `"bolim_royxati"`) — nima bo'ladi? Sahifa 500-xato bilan qulaydimi, yoki boshqacha xulq ko'rsatadimi?

<details>
<summary>Javobni ko'rish</summary>

Sahifa **500-xato bilan qulamaydi** — u, muvaffaqiyatli, `200 OK` bilan ochiladi, lekin bo'limlar ro'yxati — **bo'sh** ko'rinadi (`{% for bolim in bolimlar %}` — bo'sh, chunki `bolimlar` degan kalit context'da yo'q). Buni to'g'ridan-to'g'ri tekshirib ko'rish mumkin:

```python
from django.template import Template, Context
t = Template("Qiymat: [{{ mutlaqo_notanish_ozgaruvchi }}] tugadi.")
print(t.render(Context({})))
```
```
Qiymat: [] tugadi.
```

Django shablon tizimi, **mavjud bo'lmagan o'zgaruvchini, xato demasdan, shunchaki bo'sh matn deb hisoblaydi**. Bu — Python kodidan (`views.py`, `models.py`) tubdan farq qiladigan xulq: agar siz Python'da, mavjud bo'lmagan o'zgaruvchini chaqirsangiz, `NameError` — darhol, ochiq xato chiqadi. Shablonlarda esa — **jim, sezilmas xato**. Bu — 8-bobda chuqurroq ko'radigan mavzu: "nega sahifa noto'g'ri ko'rinadi-yu, hech qanday xato yo'q" degan holatlarning eng ko'p uchraydigan sababi — aynan shu, kalit nomidagi kichik xato (`"bolim_royxati"` va `"bolimlar"` — bir harf farqi ham yetarli).

</details>

## Keng tarqalgan xatolar

**Xato 1:** `render()`ga, `context` sifatida, lug'at o'rniga, to'g'ridan-to'g'ri QuerySet yoki boshqa ob'ekt uzatish.
❌
```python
return render(request, "dokon/bolimlar_royxati.html", barcha_bolimlar)  # dict emas!
```
```
TypeError: 'QuerySet' object is not a mapping
```
✅ `context` — har doim, **lug'at** (`{"nom": qiymat}`) bo'lishi kerak, hatto bitta o'zgaruvchi uzatilsa ham: `{"bolimlar": barcha_bolimlar}`.

**Xato 2:** Shablon manzilida, `templates/` papkasining nomini ham qo'shib yozish.
❌
```python
return render(request, "templates/dokon/bolimlar_royxati.html", context)
```
```
django.template.exceptions.TemplateDoesNotExist: templates/dokon/bolimlar_royxati.html
```
✅ `render()`ga uzatiladigan yo'l, **`templates/` papkasining ICHIDAN boshlanadi** — `templates/` so'zining o'zi, yo'lga kiritilmaydi (xuddi 2-bobdagi `INSTALLED_APPS`da `apps.dokon` deb yozilgani, lekin `apps/dokon/apps.py`dagi kabi to'liq fayl yo'li emasligiga o'xshash).

**Xato 3:** `context` lug'atidagi kalit nomini, shablondagi nom bilan mos kelmaydigan qilib yozish (yuqoridagi "Kodni o'qish mashqi"da ko'rganimiz).
❌ `context = {"royxat": barcha_bolimlar}`, lekin shablonda `{% for bolim in bolimlar %}` — nomlar mos emas.
✅ Xato **chiqmaganligi uchun**, buni topish qiyinroq — shuning uchun, view yozayotganda, `context`dagi kalit nomlarini, shablondagi nomlar bilan **atayin solishtirib chiqish** — yaxshi odat.

## Mashq/topshiriq

**(Oson)** `bolimlar_royxati` view'iga, context'ga yana bitta kalit qo'shing: `"jami_bolimlar_soni": barcha_bolimlar.count()`. Shablonga (`{{ jami_bolimlar_soni }}`) qo'shib, sahifani qayta yuklang — to'g'ri sonni ko'rasizmi?

**(O'rtacha)** Yangi view yozing — `mahsulotlar_royxati(request)` — u, `Mahsulot.objects.all()`ni context'ga `"mahsulotlar"` nomi bilan uzatsin, va `dokon/mahsulotlar_royxati.html` nomli, hali mavjud bo'lmagan shablonni chizsin. `urls.py`ga mos yo'l qo'shishni unutmang. Serverni ishga tushirib, `/mahsulotlar/`ga so'rov yuboring — **bashorat qiling**: nima bo'ladi (shablon fayli hali yo'q-ku)?

**(Qiyin)** Oldingi mashqdagi xatoni sinab ko'rgach (haqiqiy xato matnini o'qing), `mahsulotlar_royxati.html`ni yarating — u, `asos.html`dan meros olsin (`{% extends %}`, 5.2'da chuqur o'rganamiz, hozircha `bolimlar_royxati.html`ga qarab nusxa ko'chiring), va har bir mahsulot uchun nomi, narxi va tegishli bo'limining nomini (`{{ mahsulot.bolim.nomi }}` — FK orqali, "oldinga qarab" o'qish) ko'rsatsin.

## Qisqacha xulosa

`render(request, shablon_yoli, context)` — Python fayl (view) bilan HTML fayl (shablon) orasidagi **ko'prik**: `context` — oddiy Python lug'ati, uning kalitlari — shablon ichida ishlatiladigan nomlar. `render()`, "ichida", shablonni topish, uni context bilan "to'ldirish" va natijani `HttpResponse`ga o'rashdan iborat uchta qadamni bajaradi. Shablon fayllari, `<app>/templates/<app_nomi>/...` konvensiyasi bo'yicha joylashadi — bu, nomlar to'qnashuvining oldini oladi. Eng muhim farq — Python kodi (view, model) noto'g'ri nom uchun **darhol, ochiq xato** beradi, shablonlar esa, mavjud bo'lmagan o'zgaruvchini **jim, bo'sh matn** sifatida ko'rsatadi — bu farqni bilish, kelajakda "sahifa noto'g'ri, lekin xato yo'q" degan holatlarni tez topishga yordam beradi. Keyingi darsda (5.2) — shablon tilining o'zini (`{{ }}`, `{% %}`, `extends`/`block`, filtrlar) chuqur o'qiymiz.
