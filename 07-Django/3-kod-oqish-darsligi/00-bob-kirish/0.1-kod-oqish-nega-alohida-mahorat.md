# 0.1. Kod o'qish — nega bu alohida mahorat va muhitni tayyorlash

## Bu darsda nimalarni o'rganasiz

- Nima uchun "kod yozish" va "kod o'qish" — ikki xil, alohida rivojlantiriladigan mahorat ekanini tushunasiz
- Ushbu darslikning boshqa Django kurslaridan **nimasi bilan farq qilishini** aniq bilib olasiz
- `venv` (virtual muhit) nima uchun kerakligini va uni yaratishni o'rganasiz
- Django'ni o'rnatib, uning versiyasini tasdiqlaysiz

## Nazariy qism

### "Yozish" va "o'qish" — ikki xil mahorat

Ko'pchilik dasturlashni o'rganishni "qanday yozish kerak"dan boshlaydi: qanday `for` sikli yoziladi, qanday funksiya e'lon qilinadi, qanday Django view yaratiladi. Bu — muhim, lekin **yetarli emas**. Sabab oddiy: real ishda (ish joyida, jamoada, ochiq-manba loyihada, hatto o'zingiz olti oy oldin yozgan kodingizda ham) siz ko'pincha **boshqa birov yozgan** (yoki o'zingiz unutgan) kodni ochasiz va u bilan ishlashingiz kerak bo'ladi — uni tuzatish, unga funksiya qo'shish, undagi xatoni topish uchun.

Bu — mutlaqo boshqa mahorat. Kod yozganda, siz **bo'sh sahifadan** boshlaysiz va o'z fikringizni amalga oshirasiz. Kod o'qiganda esa, siz **boshqa birovning fikrini**, uning kod orqali "yozib qoldirgan" mantig'ini, orqaga qarab "tiklashingiz" kerak. Bu ko'proq detektiv ishiga o'xshaydi: qanday belgilar bor (fayl nomlari, funksiya nomlari, import'lar), ular bir-biriga qanday bog'langan, va oxir-oqibat bu tizim **nima qiladi**.

### Bu darslik nimasi bilan farq qiladi

Aksariyat Django darsliklari (jumladan, agar siz boshqa Django kursini ko'rgan bo'lsangiz) sizga **"buni qanday qurish kerak"**ni o'rgatadi: "Blog yarataylik", "Bosqichma-bosqich modelni yozamiz". Bu — foydali, lekin siz doim **o'zingiz yozgan** kod bilan ishlaysiz, uni allaqachon tushunasiz, chunki uni o'zingiz "tug'dirgansiz".

Ushbu darslikda esa, deyarli har bir darsda, sizga **tayyor, allaqachon yozilgan kod** ko'rsatiladi, va vazifangiz — uni birinchi navbatda **o'qib, tushunib**, keyingina unga qo'l tekkizish. Markaziy savol har doim quyidagicha bo'ladi: *"Bu kod nima qiladi, nega aynan shu faylda, aynan shu joyda turibdi, va agar men uni o'zgartirsam, nima buziladi?"*

### Nega Python/Django kontekstida bu ayniqsa muhim

Django — bu **"batareyalar qo'shilgan" (batteries-included)** freymvork: u sizga juda ko'p tayyor tuzilma beradi (`settings.py`, `models.py`, `views.py`, `urls.py`, va h.k.), va bu fayllarning **har biri** qat'iy, o'zining o'rni va vazifasiga ega. Yangi boshlovchi uchun eng katta qiyinchilik — ko'pincha Python tilini o'zi emas, balki **"bu narsa qayerda joylashishi kerak"** degan savol. Shuning uchun bu darslikning ikkinchi markaziy mavzusi — har bir kod bo'lagining **"uyi"**ni (qaysi faylga, qaysi papkaga tegishli ekanini) chuqur, mustahkam tushunish.

### Muhitni tayyorlash — `venv`

Har bir Python loyihasi o'zining **virtual muhiti** (`venv`)da ishlashi kerak — bu, loyihalar orasida kutubxona versiyalari to'qnashib qolmasligi uchun (bir loyihada Django 4, boshqasida Django 5 kerak bo'lishi mumkin, va ular bir-biriga xalaqit bermasligi kerak).

```bash
python3 -m venv venv
source venv/bin/activate
```

Bu ikki buyruq: (1) `venv/` nomli papkada, joriy loyiha uchun **mustaqil** Python muhitini yaratadi; (2) uni **faollashtiradi** — shundan keyin `pip install` bilan o'rnatilgan har qanday paket, faqat shu loyihaga tegishli bo'lib qoladi, butun tizimga emas.

### Django'ni o'rnatish

```bash
pip install django
python -c "import django; print('Django versiyasi:', django.get_version())"
```

```
Django versiyasi: 5.2.17
```

Bu — biz ushbu darslik davomida ishlatadigan aniq versiya. Django tez-tez yangilanadi, shuning uchun sizning versiyangiz biroz farq qilishi mumkin — lekin fayl strukturasi va asosiy tushunchalar (bu darslikning markazi) versiyalar orasida deyarli o'zgarmaydi.

**Savol:** Nega Django'ni o'rnatganda, undan tashqari yana ikkita paket (`asgiref`, `sqlparse`) ham avtomatik o'rnatildi? Bu xatomi?

<details>
<summary>Javobni ko'rish</summary>

Yo'q, bu xato emas — bu **bog'liqlik (dependency)** deb ataladi. `django` paketining o'zi, ishlashi uchun, boshqa kichik kutubxonalarga tayanadi: `asgiref` — Django'ning async (asinxron) qobiliyatlari uchun (`asgi.py` faylida ishlatiladi — shu darsning keyingi qismida ko'ramiz), `sqlparse` — Django ORM SQL so'rovlarini formatlash/tahlil qilish uchun. `pip`, `django`ni o'rnatishdan oldin, uning `setup.py`/`pyproject.toml` faylida ko'rsatilgan barcha bog'liqliklarni **avtomatik** aniqlab, ularni ham o'rnatadi. Bu — Python paket menejmentining odatiy, kutilgan xatti-harakati; agar buyruq oxirida `Successfully installed` yozuvi bo'lsa — hammasi muvaffaqiyatli.

</details>

## Amaliy misol

O'zingizning kompyuteringizda (yoki shu darslik davomida ishlatiladigan muhitda) quyidagi to'liq ketma-ketlikni bajaring va har bir buyruq natijasini diqqat bilan o'qing:

```bash
mkdir mening_loyiham && cd mening_loyiham
python3 -m venv venv
source venv/bin/activate
pip install django
python -c "import django; print(django.get_version())"
deactivate
```

`deactivate` — virtual muhitni **o'chirish** buyrug'i (terminal, oddiy, global Python holatiga qaytadi). Buni ishlatib ko'ring va `python -c "import django"` endi xato berishini kuzating — bu, `django` paketi faqat `venv` ichida, global emasligini isbotlaydi.

## Keng tarqalgan xatolar

**Xato 1:** `venv`ni yaratib, lekin `activate` qilishni unutish.
❌ `python3 -m venv venv` bajarilgan, lekin `source venv/bin/activate` chaqirilmagan — natijada `pip install django` **global** tizimga o'rnatiladi, bu esa boshqa loyihalar bilan versiya to'qnashuviga olib kelishi mumkin.
✅ Har doim, `venv` yaratgandan so'ng, **darhol** `source venv/bin/activate`ni bajaring va terminal promptida `(venv)` yozuvi paydo bo'lganini tekshiring — bu, muhit faol ekanining belgisi.

**Xato 2:** Loyihani boshqa kompyuterga ko'chirganda, `venv/` papkasini ham nusxalashga urinish.
❌ `venv/` — juda katta (yuzlab MB) va **kompyuterga bog'liq** papka; uni Git'ga qo'shish yoki qo'lda ko'chirish — noto'g'ri amaliyot.
✅ Buning o'rniga `pip freeze > requirements.txt` orqali o'rnatilgan paketlar ro'yxatini saqlang, va yangi joyda `pip install -r requirements.txt` bilan qayta o'rnating — bu haqda 1-bobda batafsil.

## Mashq/topshiriq

**(Oson)** `python3 -m venv mening_venvim` buyrug'ini bajaring, so'ng `mening_venvim/` papkasi ichida qanday fayl va papkalar paydo bo'lganini (`ls mening_venvim/`) ko'rib chiqing.

**(O'rtacha)** Yangi `venv` yaratib, uni faollashtiring, va `pip install django==5.1` (aniq, boshqa versiya) bilan o'rnating. `python -c "import django; print(django.get_version())"` orqali aynan shu versiya o'rnatilganini tasdiqlang.

**(Qiyin)** Bitta terminalda ikkita alohida `venv` yarating (`venv_a` va `venv_b`), birinchisiga Django 5.1, ikkinchisiga Django 5.2'ni o'rnating. Har birini navbat bilan faollashtirib, `django.get_version()` orqali ikkalasi **mustaqil, bir-biriga ta'sir qilmasdan** turganini isbotlang.

<details>
<summary>Javoblarni ko'rish</summary>

1.
```bash
python3 -m venv mening_venvim
ls mening_venvim/
# Natija: bin/  include/  lib/  pyvenv.cfg  (Linux/Mac'da)
```

2.
```bash
python3 -m venv venv2
source venv2/bin/activate
pip install django==5.1
python -c "import django; print(django.get_version())"
# Natija: 5.1
```

3.
```bash
python3 -m venv venv_a && source venv_a/bin/activate && pip install django==5.1 -q && python -c "import django; print('A:', django.get_version())" && deactivate

python3 -m venv venv_b && source venv_b/bin/activate && pip install django==5.2 -q && python -c "import django; print('B:', django.get_version())" && deactivate
# Natija: "A: 5.1" va "B: 5.2" — ikkalasi mustaqil
```

</details>

## Qisqacha xulosa

Kod yozish va kod o'qish — bir-biridan farqli, alohida mashq qilinishi kerak bo'lgan mahoratlar; bu darslik aynan **ikkinchisiga** — tayyor Django kodini ochib, uni tushunish, undan foydalanish va uni buzmasdan o'zgartirish qobiliyatiga qaratilgan. Har bir Python loyihasi o'z `venv`ida ishlashi, va `pip install django` orqali Django (va uning bog'liqliklari — `asgiref`, `sqlparse`) o'rnatilishi kerak. Keyingi darsda — birinchi Django loyihasini yaratib, u avtomatik hosil qilgan **har bir faylni**, "loyiha xaritasi" sifatida, boshidan-oxirigacha birga o'qib chiqamiz.
