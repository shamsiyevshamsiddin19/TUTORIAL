# 9.1. Kodni o'zgartirishdan oldin — xavfsiz metodologiya

## Bu darsda nimalarni o'rganasiz

- Har qanday o'zgartirishdan OLDIN, **"buni kim, qayerda ishlatadi?"** degan savolga, `grep` orqali, aniq javob topishni
- **"Boshlang'ich holat" (baseline)** — o'zgartirishdan oldin, mavjud xulqni, real so'rov bilan tekshirib qo'yish nega shart
- Funksiya imzosini (nima qaytarishini) o'zgartirish, **hamma chaqiruvchilarni yangilamasa**, aynan qanday, real xatoga olib kelishini
- **Regressiya tekshiruvi** — yangi holatni tuzatgach, **eski, ishlab turgan holatni ham** qayta tekshirish nega shart

## Nazariy qism

### Qoida 1: O'zgartirishdan oldin — `grep` bilan, "buni kim chaqiradi?"

8-bobda ko'rgan `ortacha_narx` funksiyasini, endi, **xavfsizroq** qilib o'zgartirmoqchimiz: bo'sh ro'yxat berilganda, `ZeroDivisionError` ko'tarish o'rniga, `None` qaytarsin. Lekin, **kodni o'zgartirishdan OLDIN**, birinchi savol — "bu funksiyani, loyihaning **boshqa qaysi joylarida** ishlatishmoqda?":

```bash
grep -rn "ortacha_narx" apps/ --include="*.py"
```

```
apps/dokon/xisoblash.py:1:def ortacha_narx(mahsulotlar):
apps/dokon/views.py:6:from .xisoblash import ortacha_narx
apps/dokon/views.py:46:def bolim_ortacha_narxi(request, bolim_id):
apps/dokon/views.py:49:    ortacha = ortacha_narx(mahsulotlar)
```

Bu — bizga, aniq, **haqiqiy** ma'lumot beradi: `ortacha_narx`, loyihada, **faqat bitta** joyda (`views.py`ning 49-qatorida) chaqirilyapti. Agar bu, katta loyiha bo'lganida-yu, `grep` natijasida, **o'ntacha** chaqiruv chiqqanida — bu, "funksiya imzosini o'zgartirish, o'nta joyni ham yangilashni talab qiladi" degani bo'lardi. **Bu — darslikning eng amaliy, eng muhim qoidalaridan biri:** kodni o'zgartirishdan oldin, "buni kim ishlatadi" ekanini, **taxmin qilmasdan, `grep` orqali, aniq bilib olish** — bu, 7-bobda o'rgangan, "notanish kodni o'qish" ko'nikmasining, endi, **o'zgartirish** kontekstidagi davomi.

### Qoida 2: O'zgartirishdan oldin — "boshlang'ich holat"ni yozib qo'yish

O'zgartirishdan oldin, **hozirgi, ishlaydigan xulqni**, real so'rov bilan tekshirib, natijani "yodda" (yoki, qog'ozda) saqlab qo'yamiz:

```bash
curl http://localhost:8000/bolimlar/3/ortacha-narx/
```
```
Elektronika: o'rtacha narx = 2575000.00 so'm, chegirmadagi narx = 2317500.000 so'm
```

Bu — **boshlang'ich holat (baseline)**: "Elektronika" bo'limi, mahsulotlarga ega, va hozir, **to'g'ri** ishlayapti. Bu qadam, ko'p yangi boshlovchilar **o'tkazib yuboradigan**, lekin, juda muhim qadam: agar, o'zgartirishdan keyin, biror narsa "buzilsa", siz, **aniq, qaysi xulq o'zgarganini** solishtira olasiz — "avval, bunday edi, endi — bunday" deb.

### Qoida 3: Kichik qadam bilan o'zgartirish

```python
def ortacha_narx(mahsulotlar):
    if not mahsulotlar:
        return None
    jami = sum(m.narxi for m in mahsulotlar)
    soni = len(mahsulotlar)
    return jami / soni
```

Bitta, aniq, kichik o'zgarish: bo'sh ro'yxat holatini, alohida, boshida, tekshiramiz. Lekin, **diqqat** — biz, hali, `views.py`dagi, yagona chaqiruvchi joyni, **ataylab, hozircha o'zgartirmadik**. Nima bo'lishini, real so'rov bilan tekshiramiz:

```bash
curl http://localhost:8000/bolimlar/4/ortacha-narx/
```

("Kitoblar" bo'limi — mahsulotsiz):

```
Internal Server Error: /bolimlar/4/ortacha-narx/
...
  File ".../apps/dokon/views.py", line 52, in bolim_ortacha_narxi
    chegirmali = ortacha * Decimal("0.9")
                 ~~~~~~~~^~~~~~~~~~~~~~~~
TypeError: unsupported operand type(s) for *: 'NoneType' and 'decimal.Decimal'
```

**Bu — real, kutilgan natija!** 8.1-darsda o'rgangan qoidani qo'llaymiz: oxirgi qator — `TypeError`, "`NoneType` va `decimal.Decimal`ni ko'paytirib bo'lmaydi". Bu, aynan, biz kutgan narsa: `ortacha_narx`, endi, ba'zi holatlarda, `None` qaytaradi, lekin, uni chaqiruvchi kod (`views.py`), bu **yangi imkoniyatni hali bilmaydi** — u, hamon, `ortacha`ni, **doim, son** deb hisoblab, unga arifmetik amal (`* Decimal("0.9")`) qo'llamoqchi bo'lyapti. `grep` natijasi bizga aytgan, yagona chaqiruvchi joy — aynan shu yerda, endi, **yangilanishi kerak**.

### Qoida 4: Barcha chaqiruvchi joylarni yangilash

```python
def bolim_ortacha_narxi(request, bolim_id):
    bolim = get_object_or_404(Bolim, id=bolim_id)
    mahsulotlar = list(bolim.mahsulotlar.all())
    ortacha = ortacha_narx(mahsulotlar)
    if ortacha is None:
        return HttpResponse(f"{bolim.nomi}: bu bo'limda hali mahsulot yo'q")
    chegirmali = ortacha * Decimal("0.9")
    return HttpResponse(
        f"{bolim.nomi}: o'rtacha narx = {ortacha} so'm, chegirmadagi narx = {chegirmali} so'm"
    )
```

`if ortacha is None:` — bu, funksiyaning **yangi shartnomasini** (bo'sh ro'yxat uchun, endi, xato o'rniga, `None` qaytishini) hisobga oladi, va, foydalanuvchiga, tushunarli xabar (`"bu bo'limda hali mahsulot yo'q"`) qaytaradi — 8.1-darsning yakuniy saboqiga mos ravishda, **xatoni yashirmasdan**, balki, uni, to'g'ri, mazmunli holatga aylantirib.

### Qoida 5: Regressiya tekshiruvi — "eski, ishlab turgan holat, hali ham ishlayaptimi?"

O'zgartirishni "tugallandi" deb hisoblashdan oldin, **oldingi, Qoida 2'da yozib qo'ygan, boshlang'ich holatni**, qayta tekshiramiz:

```bash
curl http://localhost:8000/bolimlar/3/ortacha-narx/
```
```
Elektronika: o'rtacha narx = 2575000.00 so'm, chegirmadagi narx = 2317500.000 so'm
```

**Aynan, boshlang'ich holat bilan bir xil natija** — demak, yangi holat (mahsulotsiz bo'lim) uchun tuzatish qilinganda, **eski, avvaldan ishlab turgan holat, buzilmagan**. Bu tekshiruv — **regressiya tekshiruvi** deb ataladi (professional dasturlashda, keng tarqalgan atama): "yangi narsa qo'shildi, lekin, eski narsa buzilmadimi?" Buni **har doim, o'zgartirishdan keyin**, tekshirish — kod bazasini, vaqt o'tishi bilan ham, ishonchli saqlab turishning, eng oddiy, eng samarali usuli.

## Kodni o'qish mashqi

Quyidagi, ikkita, ketma-ket qilingan `git diff`ga o'xshash o'zgarishni ko'ring (soddalashtirilgan ko'rinishda):

Bu — **yagona** o'zgarish, `views.py`ga hech qanday tegilmagan. **Bashorat qiling:** shu, yagona o'zgarishdan so'ng, loyihaning **qaysi qismlari** darhol "buzilishi" xavfi ostida qoladi — faqat, mahsulotsiz bo'lim so'ralganidami, yo boshqa holatlarda ham?

**Faqat, aniq, `mahsulotlar` bo'sh bo'lgan holatlarda.** `ortacha_narx`, mahsulotlar mavjud bo'lgan hollarda, **avvalgidek, xuddi shunday** ishlayveradi (`if not mahsulotlar:` sharti, faqat, bo'sh ro'yxatda ishga tushadi, boshqa hollarda, funksiya, keyingi qatorlarga o'tadi). Bu — muhim, umumiy tamoyil: **yangi shart (`if`) qo'shish, odatda, faqat, o'sha aniq shart bajarilgan hollarda, xulqni o'zgartiradi** — qolgan barcha hollar uchun, funksiya, "orqaga qarab moslashuvchan" (backward-compatible) qoladi. Xavf — faqat, **funksiyani chaqiruvchi kod, yangi imkoniyatni (`None` qaytishi mumkinligini) hisobga olmasa**, aynan o'sha, yangi holatda (bu yerda — mahsulotsiz bo'lim) paydo bo'ladi.

## Amaliy misol

To'liq, real tsiklni, yakuniy marta, ketma-ket ko'ramiz — bu, aynan, yuqorida, Nazariy qismda bajargan ishning, "xulosa" ko'rinishi:

1. **Grep:** `ortacha_narx` — faqat bitta joyda ishlatiladi (`views.py:49`).
2. **Baseline:** `/bolimlar/3/ortacha-narx/` → `200 OK`, "Elektronika: o'rtacha narx = 2575000.00 so'm...".
3. **O'zgarish:** `xisoblash.py`ga, bo'sh-ro'yxat tekshiruvi qo'shildi.
4. **Sinov (yangilanmagan chaqiruvchi bilan):** `/bolimlar/4/ortacha-narx/` → `500`, `TypeError: ... 'NoneType' and 'decimal.Decimal'`.
5. **Tuzatish:** `views.py`ga, `if ortacha is None:` shart qo'shildi.
6. **Sinov (tuzatilgandan keyin):** `/bolimlar/4/ortacha-narx/` → `200 OK`, "Kitoblar: bu bo'limda hali mahsulot yo'q".
7. **Regressiya:** `/bolimlar/3/ortacha-narx/` → hamon, `200 OK`, aynan boshlang'ich natija bilan bir xil.

Bu — yetti qadamli, lekin, har biri, oddiy va tez bajariladigan tsikl — va u, "tasodifan biror narsani buzib qo'yish" xavfini, sezilarli darajada kamaytiradi.

## Keng tarqalgan xatolar

**Xato 1:** Funksiya imzosini (nima qaytarishini) o'zgartirib, chaqiruvchi kodlarni, `grep`siz, "yodimda bor" deb, tekshirmasdan qoldirish.
❌ Katta loyihalarda, bitta funksiya, o'nlab joylarda chaqirilishi mumkin — "hammasini yodda tutish" imkonsiz.
✅ Har doim, `grep -rn "funksiya_nomi"` (yoki, IDE'ning "Find Usages"/"qidiruv" funksiyasi) orqali, **barcha** chaqiruvchi joylarni, ro'yxat sifatida chiqarib olish.

**Xato 2:** Boshlang'ich holatni tekshirmasdan, to'g'ridan-to'g'ri, o'zgartirishga kirishish.
❌ Agar, keyinchalik, biror narsa "kutilmagandek ishlamayapti" degan tuyg'u paydo bo'lsa, "bu, mening o'zgartirishim tufaylimi, yoki, bu, avvaldan ham shunday edimi?" — degan savolga, aniq javob berib bo'lmaydi.
✅ Har doim, o'zgartirishdan oldin, hozirgi xulqni, hech bo'lmasa, bitta-ikkita real so'rov bilan, "suratga olib qo'yish".

**Xato 3:** Faqat, yangi qo'shilgan holatni sinab, "tugadi" deb hisoblab, **eski holatlarni qayta tekshirmaslik**.
❌ Bu — eng ko'p uchraydigan, "men faqat kichik narsa o'zgartirdim, nega boshqa joy buzildi" degan shikoyatlarning sababi.
✅ Har doim, o'zgartirishni "tugallandi" deb e'lon qilishdan oldin, **kamida, avvalgi, asosiy ish stsenariylarini, qayta sinab ko'rish** (regressiya tekshiruvi).

## Mashq/topshiriq

**(Oson)** `apps/dokon/models.py`dagi `Bolim.__str__`ni oching. `grep -rn "__str__" apps/dokon/` buyrug'ini ishga tushiring — necha marta, "aniq, `__str__` nomi bilan" chaqirilgan joy topiladi? Nega, bu son, kam (yoki, hatto, nolga yaqin) bo'lishi mumkin, garchi, `__str__`, chindan ham, ko'p joyda (masalan, admin panelida, shablonlarda `{{ bolim }}` yozilganda) "ishlatilayotgan" bo'lsa ham (maslahat: Python'ning "maxsus metodlar" — `__str__`, `__init__` va h.k. — qanday, **bilvosita** chaqirilishini eslang)?

**(O'rtacha)** `Mahsulot` modeliga, yangi metod qo'shing: `def narxi_som_da(self): return f"{self.narxi} so'm"`. Uni qo'shishdan OLDIN, `grep -rn "narxi_som_da" apps/` ishga tushiring — natija, kutilganidek, **bo'sh** bo'ladi (chunki, metod hali mavjud emas). Bu, sizga, nima haqida ma'lumot beradi (maslahat: yangi metod qo'shish, mavjud metodni o'zgartirishdan, nega **xavfsizroq**)?

**(Qiyin)** `bolim_ortacha_narxi`dagi, `chegirmali = ortacha * Decimal("0.9")` qatorini, ataylab, yana, `chegirmali = ortacha * 0.9` (float bilan) ga "qaytarib qo'ying". `/bolimlar/3/ortacha-narx/`ni qayta so'rab, real xatoni oling, va, uni, 8.1-darsdagi metodologiya bilan (oxirgi qatordan boshlab) tahlil qiling. Bu xato, `Decimal` va `float`ni **umuman aralashtirib bo'lmasligini** ko'rsatadi — PostgreSQL darsligida (`NUMERIC` vs `FLOAT`) va 4.1-darsda ("pul uchun hech qachon `FloatField` ishlatilmaydi") ko'rgan ogohlantirish, endi, Python darajasida ham, qanday "qattiq" cheklov ekanini tushuntiring.

<summary>Javoblarni ko'rish</summary>

1. `grep -rn "__str__" apps/dokon/` — faqat, **ta'rif** joylarini (`def __str__(self):`) topadi, chunki, `__str__`, hech qachon, `bolim.__str__()` shaklida, to'g'ridan-to'g'ri chaqirilmaydi (garchi, texnik jihatdan, mumkin bo'lsa ham). Uning o'rniga, Python, uni, **bilvosita**, `str(bolim)`, `print(bolim)`, yoki, hatto, shablonda `{{ bolim }}` yozilganda, **ichki, avtomatik** ravishda chaqiradi. Bu — muhim saboq: `grep`, faqat, **aniq, matn sifatida yozilgan** chaqiruvlarni topa oladi; Python'ning "sehrli metodlari" (`__str__`, `__init__`, `__eq__` va h.k.) kabi, **bilvosita** ishlatiladigan kod, `grep` orqali, to'liq "ko'rinmasligi" mumkin — bunday hollarda, funksiya/metodning **nomlash konvensiyasini bilish** (masalan, `__` bilan boshlanib tugaydigan metodlar — Python'ning o'zi tomonidan, avtomatik chaqiriladi), `grep`dan ham muhimroq.

2. Bo'sh natija — **kutilgan va yaxshi belgi**: bu, "yangi metod, hali, hech kim tomonidan ishlatilmayapti, demak, uni qo'shish, **hech qanday mavjud kodni buzmaydi**" degani. **Yangi funksiya/metod qo'shish — deyarli har doim, xavfsiz amal** (chunki, hech kim, hali uni chaqirmaydi, demak, "buzadigan" hech narsa yo'q); xavfli qism — aksincha, **mavjud, allaqachon ishlatilayotgan** funksiya/metodning, imzosi yoki xulqini o'zgartirish — aynan shu sababdan, bu dars, "qo'shish" emas, "o'zgartirish"ga urg'u beradi.

3. Real xato:
```
TypeError: unsupported operand type(s) for *: 'decimal.Decimal' and 'float'
```
Bu — Python'ning, ataylab qo'yilgan, **qattiq cheklovi**: `Decimal` va `float`, ikkalasi ham, "sonlarni" ifodalasa-da, ular, **ichki tuzilishi jihatidan, butunlay boshqa** (float — ikkilik kasr taqribiy qiymat, `Decimal` — aniq, o'nlik kasr). Python, ularni, **avtomatik ravishda, bir-biriga aylantirib, ko'paytirishga yo'l qo'ymaydi** — aynan, moliyaviy hisob-kitoblarda, `float`ning yumaloqlash xatolari, `Decimal`ning aniqligini "buzib qo'yishining" oldini olish uchun. Bu — PostgreSQL darsligidagi `NUMERIC`/`FLOAT` ogohlantirishining, Python darajasidagi, **hatto qattiqroq** ko'rinishi: PostgreSQL'da, noto'g'ri turlar aralashtirilsa, ba'zan, "sokin" avtomatik konvertatsiya bo'lishi mumkin, Python'ning `Decimal` klassi esa, bunga, **umuman yo'l qo'ymaydi** — xato, darhol, ochiq ko'rinishda chiqadi.

</details>

## Qisqacha xulosa

Mavjud kodni xavfsiz o'zgartirishning, besh qadamli, oddiy metodologiyasi bor: (1) `grep` orqali, o'zgartirmoqchi bo'lgan funksiya/metodning, **barcha** chaqiruvchi joylarini aniq bilib olish; (2) o'zgartirishdan oldin, hozirgi xulqni, real so'rov bilan, **boshlang'ich holat** sifatida tekshirib qo'yish; (3) o'zgarishni, iloji boricha, **kichik qadamlarda** amalga oshirish; (4) har bir chaqiruvchi joyni, yangi shartnomaga mos qilib, **yangilash**; (5) oxirida, **regressiya tekshiruvi** — eski, ishlab turgan holatlarning ham, hali ishlayotganini tasdiqlash. Yangi funksiya/metod **qo'shish** — deyarli har doim xavfsiz (hech kim, hali uni chaqirmaydi); mavjud, ishlatilayotgan funksiyani **o'zgartirish** — har doim, ehtiyotkorlik talab qiladi. Keyingi darsda — shu metodologiyani, **funksiya qo'shish** (kengaytirish) kontekstida, chuqurroq qo'llaymiz.
