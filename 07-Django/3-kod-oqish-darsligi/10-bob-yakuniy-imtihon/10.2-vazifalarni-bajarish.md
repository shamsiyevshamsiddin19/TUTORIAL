## Amaliy misol

### 1-vazifa: `buyurtma_jami_narxi`dagi `soni` xatosini tuzatish

**Boshlang'ich holat** (10.1-darsdan tanish):

```python
def buyurtma_jami_narxi(buyurtma):
    jami = Decimal("0")
    for band in buyurtma.bandlar.all():
        jami += band.narxi_buyurtma_vaqtida
    return jami
```

**Baseline (tuzatishdan oldin, real natija):**

```
$ curl http://127.0.0.1:8000/buyurtmalar/1/hisob/
Buyurtma #1 — Stol #1: jami hisob = 43000.00 so'm

$ curl http://127.0.0.1:8000/buyurtmalar/2/hisob/
Buyurtma #2 — Stol #2: jami hisob = 15000.00 so'm
```

Diqqat qiling: Buyurtma #2 uchun natija **tasodifan to'g'ri** ko'rinadi (15000 so'm) — chunki u yerda faqat 1 dona Kofe bor (`soni=1`), va `narxi * 1 == narxi`. Bu — xatoning nega uzoq vaqt sezilmasdan qolishi mumkinligining sababi: agar test faqat "1 dona" holatlar bilan qilingan bo'lsa, xato hech qachon ko'rinmaydi. Aynan shu sababdan, real ma'lumotlar bilan (kamida bitta `soni > 1` holati bilan) tekshirish muhim.

**Tuzatish:**

```python
def buyurtma_jami_narxi(buyurtma):
    jami = Decimal("0")
    for band in buyurtma.bandlar.all():
        jami += band.narxi_buyurtma_vaqtida * band.soni
    return jami
```

**Tekshiruv (tuzatishdan keyin, real natija):**

```
$ curl http://127.0.0.1:8000/buyurtmalar/1/hisob/
Buyurtma #1 — Stol #1: jami hisob = 94000.00 so'm
```

Qo'lda hisoblash bilan mos keladi: 2×35000 + 3×8000 = 70000 + 24000 = 94000.

**Regressiya (Buyurtma #2 o'zgarmasligi kerak, chunki uning to'g'ri javobi tasodifan avvaldan ham to'g'ri edi):**

```
$ curl http://127.0.0.1:8000/buyurtmalar/2/hisob/
Buyurtma #2 — Stol #2: jami hisob = 15000.00 so'm
```

O'zgarmadi — bu kutilgan va to'g'ri natija.

### 2-vazifa: `menyu_royxati`ga `mavjud=True` filtrini qo'shish

**Boshlang'ich holat:**

```python
def menyu_royxati(request):

    return render(request, "menyu/menyu_royxati.html", context)
```

**Baseline:**

```

            <li>Kofe — 15000.00 so'm (Ichimliklar)</li>

**Tuzatish** — Django ORM'ning `.filter()` metodi (PostgreSQL darsligidagi `WHERE` bandiga mos keladi):

def menyu_royxati(request):

```

**Tekshiruv:**

            <li>Choy — 8000.00 so'm (Ichimliklar)</li>
            <li>Kofe — 15000.00 so'm (Ichimliklar)</li>
            <li>Lag'mon — 35000.00 so'm (Issiq taomlar)</li>

Endi 3 ta — Manti to'g'ri ravishda yashirildi.

**Muhim eslatma:** bu o'zgarish `admin/` panelida emas. Admin panelida (`MenyuBandiAdmin.list_display`da `mavjud` bor) siz hamon Mantini ko'rasiz va tahrirlay olasiz — bu to'g'ri, chunki admin panelining vazifasi **boshqarish**, mijozga ko'rsatiladigan `menyu_royxati` esa **faqat sotiladigan narsalarni ko'rsatish**. Ikkala view (admin va oddiy) bir xil modeldan foydalanadi, lekin turli maqsadlar uchun turlicha filtrlaydi — bu normal va kutilgan holat.

### 3-vazifa: "Stol holati" — yangi funksiya, view, URL qo'shish

Bu vazifa to'liq 9.2-darsdagi metodologiyani talab qiladi.

**1-qadam: grep bilan tekshirish** — bu nomlar hali ishlatilmaganini tasdiqlash:

```
$ grep -rn "stol_ochiq_buyurtmalar_soni\|stol_holati" buyurtmalar/ menyu/ konfiguratsiya/
(hech qanday natija yo'q)
```

Bo'sh natija — xavfsiz, chunki hech kim hali bu nomlarga bog'liq emas.

**2-qadam: yangi funksiyani `hisoblash.py`ga qo'shish:**

```python
def stol_ochiq_buyurtmalar_soni(stol):
    return stol.buyurtmalar.filter(yopilgan=False).count()
```

Diqqat qiling: `stol.buyurtmalar` — bu `Buyurtma` modelidagi `stol = models.ForeignKey(Stol, ..., related_name="buyurtmalar")`dan kelib chiqadigan **teskari (reverse) bog'lanish** (04-bobda o'rgangan). `.filter(yopilgan=False)` — faqat hali yopilmagan buyurtmalarni tanlaydi, `.count()` — sonini qaytaradi.

**3-qadam: yangi view qo'shish (`views.py`):**

```python
def stol_holati(request, stol_id):
    stol = get_object_or_404(Stol, id=stol_id)
    ochiq_soni = stol_ochiq_buyurtmalar_soni(stol)
    if ochiq_soni == 0:
        return HttpResponse(f"{stol}: bo'sh (ochiq buyurtma yo'q)")
    return HttpResponse(f"{stol}: band ({ochiq_soni} ta ochiq buyurtma)")
```

(Import qatorini yangilashni unutmang: `from .hisoblash import buyurtma_jami_narxi, stol_ochiq_buyurtmalar_soni` va `from .models import Buyurtma, Stol`.)

**4-qadam: yangi URL qo'shish (`urls.py`):**

```python
path("stol/<int:stol_id>/holati/", views.stol_holati, name="stol-holati"),
```

**5-qadam: tekshirish**

```
$ python manage.py check
System check identified no issues (0 silenced).

$ curl http://127.0.0.1:8000/buyurtmalar/stol/1/holati/
Stol #1: band (1 ta ochiq buyurtma)

$ curl http://127.0.0.1:8000/buyurtmalar/stol/2/holati/
Stol #2: bo'sh (ochiq buyurtma yo'q)
```

Stol #1 uchun "band" (chunki Buyurtma #1 `yopilgan=False`), Stol #2 uchun "bo'sh" (chunki Buyurtma #2 `yopilgan=True`, ya'ni yopilgan hisoblanadi, faol emas) — ikkalasi ham kutilgan, to'g'ri natija.

**6-qadam: regressiya — eski endpoint'lar hali ishlaydimi?**

```
$ curl http://127.0.0.1:8000/buyurtmalar/1/hisob/
Buyurtma #1 — Stol #1: jami hisob = 94000.00 so'm

$ curl http://127.0.0.1:8000/menyu/ | grep "<li>" | wc -l
3
```

Ikkalasi ham (1 va 2-vazifalardagi tuzatishlar bilan birga) o'zgarishsiz, to'g'ri ishlayapti. Yangi funksiya qo'shish hech narsani buzmadi.

## Keng tarqalgan xatolar

❌ **1-vazifada, `soni`ni qo'shish o'rniga, `narxi_buyurtma_vaqtida`ning o'zini ko'paytirib yozib qo'yish** (masalan, `band.narxi_buyurtma_vaqtida = band.narxi_buyurtma_vaqtida * band.soni` deb, ma'lumotlar bazasidagi asl narxni o'zgartirib yuborish). Bu — hisoblash funksiyasi bilan ma'lumotni saqlash mas'uliyatini aralashtirib yuborish; `narxi_buyurtma_vaqtida` — buyurtma vaqtidagi **bitta dona** narxi bo'lib qolishi kerak, uni ko'paytirish faqat **hisoblash** bosqichida, vaqtinchalik o'zgaruvchida bo'lishi kerak.

✅ Har doim manba ma'lumotni (model maydonini) o'zgarishsiz qoldiring, faqat hisoblash natijasini (vaqtinchalik o'zgaruvchida) o'zgartiring.

❌ **2-vazifada, filtrni view'da emas, shablonda (`{% if band.mavjud %}`) qilish.** Bu ishlaydi, lekin noto'g'ri joy: agar shu ro'yxat boshqa joyda (masalan API'da) ham kerak bo'lsa, filtr mantig'ini har bir joyda takrorlashga to'g'ri keladi.

✅ Filtrlashni, imkon qadar, ma'lumotlar bazasi darajasida (`.filter()`) bajaring — bu ham to'g'riroq joylashuv, ham (katta ma'lumotlar bilan) tezroq, chunki filtrlash PostgreSQL'ning o'zida bajariladi, Python darajasida emas.

❌ **3-vazifada, yangi funksiyani to'g'ridan-to'g'ri `views.py`ga yozib, `hisoblash.py`ga chiqarmaslik.** Bu ishlaydi, lekin loyihaning o'zi tanlagan konventsiyaga (hisoblash mantig'i alohida faylda) mos kelmaydi — 02-bobda o'rgangan "qaysi kod qayerga" qoidasini buzadi.

✅ Loyihada allaqachon o'rnatilgan konventsiyani (bu holda: og'ir/qayta ishlatiladigan hisoblash — alohida faylda) kuzating va unga rioya qiling, hatto siz shaxsan boshqacha tashkil qilishni afzal ko'rsangiz ham — bu boshqalar (va kelajakdagi o'zingiz) uchun kodni bashorat qilinadigan qiladi.

2-vazifa (menyu filtri) eng qisqa — atigi bitta so'z o'zgardi (`.all()` → `.filter(mavjud=True)`). Bu tasodif emas: Django ORM'ning deklarativ tabiati tufayli, "qaysi qatorlarni olish kerak" degan mantiq odatda juda ixcham ifodalanadi — siz "qanday" filtrlashni emas, "nima" kerakligini aytasiz, va ORM buni SQL'ga o'zi tarjima qiladi. Buni PostgreSQL darsligidagi `WHERE` bandi bilan solishtiring — bu yerdagi `.filter(mavjud=True)` aynan o'sha `WHERE mavjud = true`ning Python ko'rinishi.

### O'rtacha

`stol_holati` view'iga yangi qo'shimcha qiling: agar stol umuman mavjud bo'lmasa (masalan `stol_id=999`), hozir nima bo'lishini bashorat qiling, so'ng buni tasdiqlang. (Eslatma: `get_object_or_404` allaqachon ishlatilgan — bu funksiya nima qilishini 3-4-boblardan eslang.)

<details>
<summary>Javobni ko'rish</summary>

`get_object_or_404(Stol, id=stol_id)` — agar mos `Stol` topilmasa, avtomatik `Http404` xatosini ko'taradi, bu esa Django tomonidan standart "404 sahifa topilmadi" javobiga aylantiriladi. Hech qanday qo'shimcha kod yozish shart emas — bu funksiya buni allaqachon "quti ichida tayyor" (out-of-the-box) qiladi:

```
$ curl -o /dev/null -w "STATUS: %{http_code}\n" http://127.0.0.1:8000/buyurtmalar/stol/999/holati/
STATUS: 404
```

Bu — nima uchun `Stol.objects.get(id=stol_id)` o'rniga (u `DoesNotExist` xatosini ko'tarib, 500-xatoga olib kelardi) `get_object_or_404` afzal ko'rilishining sababi: u foydalanuvchiga tushunarli 404 javobini, dasturchidan qo'shimcha `try/except` yozishni talab qilmasdan, avtomatik beradi.
</details>

### Qiyin

Endi bitta qo'shimcha, haqiqiy vazifani o'zingiz mustaqil bajaring: `buyurtmalar` app'iga, **yangi** `buyurtma_yopish(request, buyurtma_id)` degan view qo'shing — u `Buyurtma.yopilgan`ni `True` qilib belgilaydi va "Buyurtma #N yopildi" degan xabar qaytaradi. Avval grep bilan nom to'qnashuvi yo'qligini tasdiqlang, so'ng funksiyani yozing, URL qo'shing, so'ng uni sinab ko'ring (va Stol #1 uchun `stol_holati` natijasi endi qanday o'zgarishini ham tekshiring — chunki buyurtma yopilishi, o'sha stolning "ochiq buyurtmalar soni"ga bevosita ta'sir qiladi).

<details>
<summary>Javobni ko'rish</summary>

**Grep tekshiruvi:**

```
$ grep -rn "buyurtma_yopish" buyurtmalar/
(hech qanday natija yo'q)
```

**View (`views.py`ga qo'shiladi):**

```python
def buyurtma_yopish(request, buyurtma_id):
    buyurtma = get_object_or_404(Buyurtma, id=buyurtma_id)
    buyurtma.yopilgan = True
    buyurtma.save()
    return HttpResponse(f"Buyurtma #{buyurtma.id} yopildi")
```

**URL (`urls.py`ga qo'shiladi):**

```python
path("<int:buyurtma_id>/yopish/", views.buyurtma_yopish, name="buyurtma-yopish"),
```

**Baseline (yopishdan oldin, Stol #1 holati):**

```
$ curl http://127.0.0.1:8000/buyurtmalar/stol/1/holati/
Stol #1: band (1 ta ochiq buyurtma)
```

**Yangi endpointni chaqirish:**

```
$ curl http://127.0.0.1:8000/buyurtmalar/1/yopish/
Buyurtma #1 yopildi
```

**Ta'sirini tekshirish (Stol #1 holati endi o'zgarishi kerak):**

```
$ curl http://127.0.0.1:8000/buyurtmalar/stol/1/holati/
Stol #1: bo'sh (ochiq buyurtma yo'q)
```

Aynan shu natija — bu, `stol_ochiq_buyurtmalar_soni` funksiyasi bazadan **har safar qayta so'rov** qilishini (natijani keshlamasligini) isbotlaydi: Buyurtma #1'ning `yopilgan` maydoni o'zgarganidan so'ng, keyingi so'rovda darhol yangi holat aks etadi. Bu — Django ORM'ning `related_name` orqali qilingan `.filter()` so'rovlari doim **jonli**, ma'lumotlar bazasidagi joriy holatni aks ettirishini ko'rsatadigan yana bir real, tekshirilgan misol.
</details>
