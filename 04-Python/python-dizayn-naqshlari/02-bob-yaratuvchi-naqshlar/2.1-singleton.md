# Singleton naqshi

## Bu darsda nimalarni o'rganasiz

- Singleton naqshining qaysi muammoni hal qilishini va qachon kerak bo'lishini tushunasiz
- `__new__` orqali klassik Singleton implementatsiyasini yoza olasiz
- Python'ga xos, "pythonic" Singleton usulini (modul darajasida) qo'llay olasiz
- Ko'p oqimli (thread) muhitda Singleton'ning xavfli tomonini va `Lock` bilan yechimini bilasiz
- Singleton naqshining kamchiliklarini (global holat, testlashning qiyinlashishi) baholay olasiz

## Nazariy qism

### Muammo — nega Singleton kerak bo'ladi

Ba'zi obyektlar dastur davomida **faqat bitta** nusxada bo'lishi mantiqan to'g'ri bo'ladi: masalan, dastur konfiguratsiyasi (`Config`), loglash tizimi (`Logger`), yoki ma'lumotlar bazasiga ulanish pooli. Agar shu turdagi klassdan tasodifan **ikki xil nusxa** yaratilsa — ikkisi bir-biridan bexabar, mustaqil holatga ega bo'lib qoladi, bu esa chalkashlik va xatolarga olib keladi (masalan, bir nusxada sozlama o'zgartirilsa, ikkinchisi bundan bexabar qolishi).

**Singleton naqshi** — aynan shu muammoni hal qiladi: u klassdan **faqat bitta** obyekt (instance) yaratilishini **kafolatlaydi** va dasturning istalgan joyidan shu yagona nusxaga **global kirish** imkonini beradi.

### Klassik implementatsiya — `__new__` orqali

Python'da `__init__` — obyekt **allaqachon yaratilgandan keyin** chaqiriladi, lekin `__new__` — obyektning **o'zi yaratilishidan oldin** ishga tushadi (9.2-darsda `__new__` vs `__init__` farqi chuqurroq ko'rilgan). Shu sababli Singleton'ni klassik usulda amalga oshirish uchun aynan `__new__` ni qayta belgilaymiz:

```python
class Singleton:
    _instance = None    # klass darajasidagi atribut — BARCHA obyektlar uchun UMUMIY

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance


class Konfiguratsiya(Singleton):
    def __init__(self):
        # DIQQAT: __init__ har safar Konfiguratsiya() chaqirilganda ishlaydi,
        # __new__ esa faqat BIRINCHI marta haqiqiy obyekt yaratadi!
        if not hasattr(self, "_ishga_tushirilgan"):
            self.sozlamalar = {"debug": False}
            self._ishga_tushirilgan = True


k1 = Konfiguratsiya()
k2 = Konfiguratsiya()
k1.sozlamalar["debug"] = True

print(k1 is k2)                 # True — bu AYNAN BIR XIL obyekt!
print(k2.sozlamalar["debug"])   # True — k1 orqali kiritilgan o'zgarish k2'da ham ko'rinadi
```

E'tibor bering: `__init__` har safar `Konfiguratsiya()` chaqirilganda avtomatik ishga tushadi (chunki Python buni har doim qiladi), shu sababli `hasattr` tekshiruvi orqali **faqat birinchi marta** haqiqiy ishga tushirish (initializatsiya) kodini bajarishga majbur qilamiz — aks holda ikkinchi `Konfiguratsiya()` chaqiriganda `sozlamalar` qayta `{"debug": False}`ga qaytib ketardi.

### Pythonic usul — modul o'zi Singleton

Bu — Python jamoasida **eng ko'p tavsiya qilinadigan** yondashuv, chunki u **til darajasida tabiiy ravishda** Singleton xususiyatiga ega: **Python modullari** `sys.modules` keshi tufayli (3.3-dars va 11.1-darsda chuqur ko'rilgan import mexanizmi) har doim **faqat bir marta** import qilinadi va keyingi `import` chaqiriqlari xotiradagi **bir xil** modul obyektini qaytaradi.

```python
# konfiguratsiya.py — bu MODUL o'zi Singleton vazifasini bajaradi
sozlamalar = {"debug": False}

def sozlamani_ozgartir(kalit, qiymat):
    sozlamalar[kalit] = qiymat
```

```python
# boshqa_fayl.py
import konfiguratsiya

konfiguratsiya.sozlamani_ozgartir("debug", True)
print(konfiguratsiya.sozlamalar)   # {'debug': True}
```

```python
# yana_boshqa_fayl.py
import konfiguratsiya

print(konfiguratsiya.sozlamalar)   # {'debug': True} — XUDDI SHU obyekt, chunki modul FAQAT BIR MARTA yuklanadi
```

Bu usul — hech qanday maxsus klass yozmasdan, **faqat modulning tabiiy xususiyatidan** foydalanadi, shu sababli "haqiqiy pythonic" deb hisoblanadi: ko'p Python loyihalarida (masalan, Django'ning `settings` moduli) aynan shu tamoyil qo'llaniladi.

### Thread-safety muammosi va Lock bilan yechim

Agar Singleton **bir nechta oqim (thread)** tomonidan **bir vaqtda, birinchi marta** chaqirilsa, klassik `__new__` implementatsiyasi muammoli bo'lib qoladi — bu "race condition" (poyga holati, 12.2-darsda `threading` moduli bilan chuqur ko'riladi) deb ataladi:

```python
import threading
import time

# ❌ XAVFLI — ikki oqim BIR VAQTDA cls._instance is None tekshiruvidan "True" natija olishi mumkin
class XavfliSingleton:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            time.sleep(0.01)              # simulyatsiya: obyekt yaratish biroz vaqt oladi
            cls._instance = super().__new__(cls)
        return cls._instance
```

Agar ikki oqim deyarli bir vaqtda `XavfliSingleton()`ni chaqirsa, ikkisi ham `cls._instance is None`ni **True** deb "ko'rishi" va natijada **ikki xil** obyekt yaratilishi mumkin — bu Singleton'ning asosiy kafolatini buzadi.

Yechim — `threading.Lock` yordamida **shu kodni bir vaqtning o'zida faqat bitta oqim bajarishini** ta'minlash:

```python
import threading

class XavfsizSingleton:
    _instance = None
    _qulf = threading.Lock()      # barcha oqimlar UMUMIY qulfdan foydalanadi

    def __new__(cls):
        if cls._instance is None:
            with cls._qulf:                   # faqat BITTA oqim shu blokka kirishi mumkin
                if cls._instance is None:      # "double-checked locking" — qulf ichida QAYTA tekshirish
                    cls._instance = super().__new__(cls)
        return cls._instance
```

Bu yerda **ikki marta tekshirish** (double-checked locking) muhim: tashqi tekshiruv — har bir chaqiriqda qulfni olishdan qochish uchun (performance uchun, chunki obyekt allaqachon yaratilgan bo'lsa, qulf olishning hojati yo'q), ichki tekshiruv — qulf ichiga kirgan paytda **boshqa oqim allaqachon obyekt yaratib qo'yganmi** degan savolga javob berish uchun.

### Real dunyoda qayerda ishlatiladi

Python standart kutubxonasida va mashhur freymvorklarda Singleton (yoki unga juda yaqin g'oya) ko'p joyda ko'rinadi:

- **`logging` moduli** — `logging.getLogger("nomi")` bir xil nom bilan chaqirilsa, har doim **bir xil** logger obyektini qaytaradi (ichida shunga o'xshash kesh mexanizmi ishlaydi).
- **Django `settings`** — loyiha konfiguratsiyasi modul darajasida, yagona nusxada yuklanadi.
- **Ma'lumotlar bazasi ulanish pooli** (`SQLAlchemy`, `psycopg2` pool) — resurs tejash uchun yagona pool obyekti ishlatiladi.

### Kamchiliklari va trade-off'lari

Singleton — eng ko'p **tanqid qilinadigan** naqshlardan biri, chunki:

1. **Global holat** — Singleton aslida "yashirin global o'zgaruvchi"dan boshqa narsa emas, va global holat kodni **kutilmagan joylardan o'zgartirilishi** mumkin bo'lgani uchun xato topishni qiyinlashtiradi.
2. **Testlashning qiyinlashishi** — Singleton'ni unit-testlarda "soxtalashtirish" (mock qilish) qiyin, chunki u butun dastur davomida bitta holatni saqlaydi — bir test ikkinchisiga **ta'sir qilishi** mumkin (test izolyatsiyasi buziladi).
3. **Dependency Inversion'ni buzish xavfi** — agar klasslar Singleton'ga **to'g'ridan-to'g'ri** murojaat qilsa (masalan, `Konfiguratsiya()` ni ichkarida chaqirsa), bu 1.2-darsdagi Dependency Inversion tamoyilini buzadi; **Dependency Injection** (5.3-dars) orqali Singleton obyektini "tashqaridan berish" ko'proq tavsiya etiladi.

## Amaliy misol

Quyida — real loyihalarda tez-tez uchraydigan, loglash tizimi uchun thread-safe Singleton misoli:

```python
# logger_singleton.py
import threading
from datetime import datetime


class LogYozuvchi:
    _instance = None
    _qulf = threading.Lock()

    def __new__(cls):
        if cls._instance is None:
            with cls._qulf:
                if cls._instance is None:
                    cls._instance = super().__new__(cls)
                    cls._instance._tarix = []          # faqat BIRINCHI marta ishga tushadi
        return cls._instance

    def yoz(self, xabar: str, daraja: str = "INFO") -> None:
        vaqt = datetime.now().strftime("%H:%M:%S")
        yozuv = f"[{vaqt}] [{daraja}] {xabar}"
        self._tarix.append(yozuv)
        print(yozuv)

    def tarixni_olish(self) -> list[str]:
        return list(self._tarix)


# modul1.py (dasturning bir qismi, bu yerda simulyatsiya qilinadi)
def foydalanuvchi_royxatdan_otdi(ism: str) -> None:
    logger = LogYozuvchi()
    logger.yoz(f"{ism} ro'yxatdan o'tdi", daraja="INFO")


# modul2.py (dasturning boshqa qismi, LogYozuvchi() ni MUSTAQIL chaqiradi)
def xato_yuz_berdi(xabar: str) -> None:
    logger = LogYozuvchi()                 # XUDDI SHU obyekt qaytadi
    logger.yoz(xabar, daraja="ERROR")


foydalanuvchi_royxatdan_otdi("Ali")
xato_yuz_berdi("Email yuborilmadi")

# Ikkinchi modul birinchi modulning yozgan loglarini ham "ko'radi", chunki ular BIR XIL obyekt:
yakuniy_logger = LogYozuvchi()
print("\nBarcha loglar:")
for yozuv in yakuniy_logger.tarixni_olish():
    print(" ", yozuv)
# [12:30:01] [INFO] Ali ro'yxatdan o'tdi
# [12:30:01] [ERROR] Email yuborilmadi
#
# Barcha loglar:
#   [12:30:01] [INFO] Ali ro'yxatdan o'tdi
#   [12:30:01] [ERROR] Email yuborilmadi
```

## Keng tarqalgan xatolar

**Xato 1:** `__new__`da obyekt yaratilishini tekshirish, lekin `__init__`ning har safar qayta ishga tushishini unutish.
❌
```python
class Singleton:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

class Konfig(Singleton):
    def __init__(self):
        self.sozlamalar = {}    # HAR SAFAR Konfig() chaqirilganda qayta {} ga tushadi!

k1 = Konfig()
k1.sozlamalar["x"] = 1
k2 = Konfig()
print(k1.sozlamalar)    # {} — k2 yaratilganda __init__ qayta ishlab, sozlamalarni TOZALADI!
```
✅ To'g'ri: `__init__` ichida `hasattr(self, "_ishga_tushirilgan")` (yoki shunga o'xshash flag) bilan tekshirib, haqiqiy initializatsiya kodi **faqat birinchi marta** bajarilishini ta'minlang (yuqoridagi "Klassik implementatsiya" bo'limidagi kabi).

**Xato 2:** ko'p oqimli muhitda Lock'siz Singleton yozish.
❌ Yuqoridagi "Thread-safety" bo'limidagi `XavfliSingleton` kabi — ko'p oqimli serverlarda (masalan, Flask/Django'ning ko'p ishchi jarayonlari) bu **tasodifiy ikki nusxa** yaratilishiga olib kelishi mumkin, bu esa topish qiyin bo'lgan "heisenbug" (vaqti-vaqti bilan paydo bo'ladigan xato) yaratadi.
✅ To'g'ri: agar Singleton ko'p oqimli muhitda ishlatilishi mumkin bo'lsa, albatta `threading.Lock` bilan "double-checked locking" naqshini qo'llang.

**Xato 3:** Singleton'ni "hamma global o'zgaruvchiga muqobil" deb, haddan tashqari ko'p ishlatish.
❌ Deyarli har bir klassni Singleton qilib, dastur bo'ylab yashirin global holatlar tarmog'ini yaratish — bu kodni test qilishni va parallel ishlashini (chunki holat umumiy, bir vaqtda ikki test bir-biriga ta'sir qiladi) qiyinlashtiradi.
✅ To'g'ri: Singleton'ni faqat **haqiqatan bitta nusxa bo'lishi SHART** bo'lgan resurslar (konfiguratsiya, ulanish pooli, loglash) uchun ishlatish, va iloji boricha Dependency Injection (5.3-dars) orqali obyektni "tashqaridan uzatish" yondashuvini afzal ko'rish.

## Mashq/topshiriq

**(Oson)** `__new__` orqali klassik usulda `IloyniBoshqaruvchisi` Singleton klassini yozing — unda `holat` degan ro'yxat atributi bo'lsin va `qoshish(element)` metodi orqali shu ro'yxatga element qo'shilsin. Ikki xil joydan yaratilgan nusxalarning bir xil `holat`ni ko'rsatishini tekshiring.

**(O'rtacha)** Modul darajasidagi ("pythonic") Singleton usulidan foydalanib, oddiy "savatcha" (`savatcha.py` moduli) tizimini yozing: `tovar_qoshish(nomi, narxi)` va `jami_narx()` funksiyalari bo'lsin, ma'lumot modul darajasidagi `_tovarlar` ro'yxatida saqlansin.

**(Qiyin)** `XavfsizSingleton` namunasiga asoslanib, `threading` moduli yordamida 10 ta oqim bir vaqtda Singleton obyektini yaratishga urinadigan test yozing va barcha oqimlarda `id()` natijasi bir xil ekanini tasdiqlang (`assert` bilan).

## Qisqacha xulosa

Singleton naqshi — klassdan faqat bitta obyekt yaratilishini va unga dastur bo'ylab global kirishni kafolatlaydigan yaratuvchi naqsh bo'lib, Python'da bu klassik `__new__` orqali (initializatsiyani `hasattr` bilan bir martaga cheklab) yoki ancha "pythonic" tarzda modulning o'zi (`sys.modules` keshi tufayli tabiiy singleton) sifatida amalga oshirilishi mumkin; ko'p oqimli muhitda `threading.Lock` bilan "double-checked locking" zarur, biroq Singleton global holatni yaratishi va testlashni qiyinlashtirishi sababli, uni faqat **haqiqatan yagona nusxa talab qilinadigan** holatlarda (konfiguratsiya, loglash, ulanish pooli) qo'llash va imkon qadar Dependency Injection bilan birga ishlatish tavsiya etiladi.
