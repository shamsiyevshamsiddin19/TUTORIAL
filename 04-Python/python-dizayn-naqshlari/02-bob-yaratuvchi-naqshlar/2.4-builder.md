# Builder naqshi

## Bu darsda nimalarni o'rganasiz

- Builder naqshining qaysi muammoni (ko'p va ixtiyoriy parametrli murakkab obyekt yaratish) hal qilishini tushunasiz
- Klassik "Builder + Director" tuzilmasini yoza olasiz
- "Fluent interface" (method chaining) orqali pythonic Builder yoza olasiz
- Builder'ni Python'ning o'z `dataclass` va kalit so'z argumentlaridan qachon farqlash kerakligini bilasiz

## Nazariy qism

### Muammo — "konstruktor portlashi" (telescoping constructor)

Murakkab obyektlar ko'pincha **ko'p sonli, ko'p qismi ixtiyoriy** parametrga ega bo'ladi. Buni oddiy `__init__` bilan yechishga urinish — **"konstruktor portlashi"** (telescoping constructor) deb ataluvchi anti-patternga olib keladi:

```python
# ❌ Konstruktor portlashi — har bir ixtiyoriy parametr uchun yangi __init__ belgisi
class Pitsa:
    def __init__(self, hajmi, xamir_turi=None, pishloq=None, pomidor_sousi=None,
                 gubernoy=None, zaytun=None, qalampir=None, go_sht=None):
        self.hajmi = hajmi
        self.xamir_turi = xamir_turi or "yupqa"
        self.pishloq = pishloq or False
        self.pomidor_sousi = pomidor_sousi or False
        self.gubernoy = gubernoy or False
        self.zaytun = zaytun or False
        self.qalampir = qalampir or False
        self.go_sht = go_sht or False


# Chaqiruvchi kod — qaysi argument nimani bildirishini eslab qolish DEYARLI IMKONSIZ
pitsa = Pitsa("katta", "qalin", True, True, False, True, False, True)
```

Bu yerdagi muammo aniq: 8-argumentli chaqiriqda **qaysi `True`/`False` nimaga tegishli ekanini** kod o'qiyotgan odam darhol tushuna olmaydi, va argumentlar tartibini bir joyda chalkashtirib qo'yish — osongina sezilmaydigan xatoga olib keladi.

**Builder naqshi** — murakkab obyektni **bosqichma-bosqich**, har bir qadamda **aniq nomlangan metod** orqali qurishni taklif qiladi, bu esa kodni ham **o'qilishi oson**, ham **xatoga chidamli** qiladi.

### Klassik GoF tuzilmasi — Builder + Director

GoF'ning asl g'oyasida ikki klass bor: **Builder** (qurish qadamlarini e'lon qiladi) va **Director** (qurish **tartibini** boshqaradi, Builder metodlarini **qaysi tartibda** chaqirishni biladi):

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass, field


@dataclass
class Uy:
    qavatlar_soni: int = 1
    bogi_bor: bool = False
    basseyn_bor: bool = False
    garaj_bor: bool = False


class UyBuilder(ABC):
    @abstractmethod
    def qavat_qosh(self) -> "UyBuilder": ...
    @abstractmethod
    def bog_qosh(self) -> "UyBuilder": ...
    @abstractmethod
    def basseyn_qosh(self) -> "UyBuilder": ...
    @abstractmethod
    def natijani_olish(self) -> Uy: ...


class OddiyUyBuilder(UyBuilder):
    def __init__(self):
        self._uy = Uy()

    def qavat_qosh(self) -> "UyBuilder":
        self._uy.qavatlar_soni += 1
        return self

    def bog_qosh(self) -> "UyBuilder":
        self._uy.bogi_bor = True
        return self

    def basseyn_qosh(self) -> "UyBuilder":
        self._uy.basseyn_bor = True
        return self

    def natijani_olish(self) -> Uy:
        natija = self._uy
        self._uy = Uy()        # keyingi qurish uchun builder'ni tozalab qo'yish
        return natija


# Director — TAYYOR "retseptlar"ni biladi (qanday tartibda qaysi qadamlar chaqirilishini)
class UyDirektori:
    def __init__(self, builder: UyBuilder):
        self._builder = builder

    def hashamatli_uy_qur(self) -> Uy:
        return (self._builder
                .qavat_qosh()
                .qavat_qosh()
                .bog_qosh()
                .basseyn_qosh()
                .natijani_olish())

    def oddiy_uy_qur(self) -> Uy:
        return self._builder.bog_qosh().natijani_olish()


direktor = UyDirektori(OddiyUyBuilder())
hashamatli = direktor.hashamatli_uy_qur()
print(hashamatli)    # Uy(qavatlar_soni=3, bogi_bor=True, basseyn_bor=True, garaj_bor=False)

oddiy = direktor.oddiy_uy_qur()
print(oddiy)          # Uy(qavatlar_soni=1, bogi_bor=True, basseyn_bor=False, garaj_bor=False)
```

Bu yerda `Director` — **"nima qurilishi kerak"** haqidagi bilimni (masalan, "hashamatli uy — bu 3 qavat + bog + basseyn") saqlaydi, `Builder` esa faqat **"qanday qurish"** (har bir alohida qadamni qanday amalga oshirish) bilan shug'ullanadi — bu ikkisini ajratish 1.2-darsdagi Single Responsibility tamoyiliga mos keladi.

### Pythonic uslub — fluent interface, Director'siz

Amalda, Python loyihalarida **to'liq Director klassini** yaratish ko'pincha ortiqcha bo'ladi — buning o'rniga, Builder'ning o'zi "fluent interface" (method chaining, har bir metod `self`ni qaytaradi — bu uslubni 5.4-darsda dekoratorlar bilan bog'liq tarzda ham ko'rgan edik) orqali to'g'ridan-to'g'ri ishlatiladi:

```python
class SoRovBuilder:
    """HTTP so'rovini bosqichma-bosqich quruvchi, fluent interfeysga ega Builder."""

    def __init__(self, url: str):
        self._url = url
        self._metod = "GET"
        self._sarlavhalar: dict[str, str] = {}
        self._tana: dict | None = None

    def metod(self, metod: str) -> "SoRovBuilder":
        self._metod = metod
        return self

    def sarlavha_qosh(self, kalit: str, qiymat: str) -> "SoRovBuilder":
        self._sarlavhalar[kalit] = qiymat
        return self

    def tana(self, malumot: dict) -> "SoRovBuilder":
        self._tana = malumot
        return self

    def qur(self) -> dict:
        return {
            "url": self._url,
            "metod": self._metod,
            "sarlavhalar": self._sarlavhalar,
            "tana": self._tana,
        }


sorov = (SoRovBuilder("https://api.example.com/users")
         .metod("POST")
         .sarlavha_qosh("Content-Type", "application/json")
         .sarlavha_qosh("Authorization", "Bearer token123")
         .tana({"ism": "Ali"})
         .qur())

print(sorov)
# {'url': 'https://api.example.com/users', 'metod': 'POST',
#  'sarlavhalar': {'Content-Type': 'application/json', 'Authorization': 'Bearer token123'},
#  'tana': {'ism': 'Ali'}}
```

Bu kod **o'z-o'zidan hikoya qiladi** — har bir qatorni o'qigan odam qaysi sarlavha/qiymat qo'shilayotganini **darhol** tushunadi, telescoping constructor'dagi "qaysi `True` nimaga tegishli" muammosi butunlay yo'qoladi.

### Builder va Python'ning tabiiy imkoniyatlari — qachon haqiqatan kerak

Python'da ko'p hollarda to'liq Builder naqshi **shart emas**, chunki tilning o'zida murakkab obyekt yaratishni soddalashtiruvchi vositalar bor:

```python
from dataclasses import dataclass

# Agar BARCHA parametrlar oldindan ma'lum bo'lsa — kalit so'z argumentlari YETARLI,
# Builder shart emas:
@dataclass
class Pitsa:
    hajmi: str
    xamir_turi: str = "yupqa"
    pishloq: bool = False
    zaytun: bool = False


pitsa = Pitsa(hajmi="katta", pishloq=True, zaytun=True)   # kalit so'zlar bilan — allaqachon ANIQ va o'qilishi oson!
```

**Builder haqiqatan kerak bo'ladigan holatlar:**
- Qurish jarayoni **bir nechta bosqich**dan iborat bo'lib, har bosqichda **tekshiruv** yoki **hisoblash** kerak bo'lsa (shunchaki maydonlarni to'ldirish emas).
- Natijaviy obyekt **o'zgarmas (immutable)** bo'lishi kerak, lekin qurish jarayonida **vaqtinchalik o'zgaruvchan holat** kerak bo'lsa.
- Bir xil qurish qadamlaridan **turli xil yakuniy natijalar** (masalan, "oddiy uy" va "hashamatli uy") hosil qilish kerak bo'lsa (bu — aynan Director rolini talab qiladi).

Agar oddiy kalit so'z argumentlari (`**kwargs` yoki `dataclass`) yetarli bo'lsa, Builder qo'shish — 1.1-darsdagi overengineering namunasiga aylanadi.

### Real dunyoda qayerda ishlatiladi

- **`str.format()` / Jinja2 shablonlari** — matnni bosqichma-bosqich, qism-qism yig'ish g'oyasi.
- **SQL so'rov quruvchilari** (SQLAlchemy'ning `Query` obyekti) — `.filter(...).order_by(...).limit(...)` — bu **aynan** fluent-interface Builder naqshi, har bir metod yangi, kengaytirilgan so'rov obyektini (yoki o'zini) qaytaradi.
- **`unittest.mock.Mock`** va test freymvorklaridagi "test ma'lumotlari quruvchilari" (test data builders) — testlar uchun murakkab obyektlarni o'qilishi oson tarzda yaratish.

## Amaliy misol

To'liq, pythonic Builder misoli — email xabarini bosqichma-bosqich quruvchi tizim:

```python
# email_builder.py
from dataclasses import dataclass, field


@dataclass
class Email:
    kimdan: str
    kimga: list[str] = field(default_factory=list)
    mavzu: str = ""
    matn: str = ""
    biriktirmalar: list[str] = field(default_factory=list)
    nusxa: list[str] = field(default_factory=list)


class EmailBuilder:
    def __init__(self, kimdan: str):
        self._email = Email(kimdan=kimdan)

    def kimga_qosh(self, manzil: str) -> "EmailBuilder":
        self._email.kimga.append(manzil)
        return self

    def nusxaga_qosh(self, manzil: str) -> "EmailBuilder":
        self._email.nusxa.append(manzil)
        return self

    def mavzu_oʻrnat(self, mavzu: str) -> "EmailBuilder":
        self._email.mavzu = mavzu
        return self

    def matn_oʻrnat(self, matn: str) -> "EmailBuilder":
        self._email.matn = matn
        return self

    def biriktirma_qosh(self, fayl_nomi: str) -> "EmailBuilder":
        self._email.biriktirmalar.append(fayl_nomi)
        return self

    def qur(self) -> Email:
        if not self._email.kimga:
            raise ValueError("Email'da kamida bitta qabul qiluvchi bo'lishi SHART")   # qurish vaqtidagi TEKSHIRUV
        if not self._email.mavzu:
            raise ValueError("Email mavzusi bo'sh bo'lishi mumkin emas")
        return self._email


# Fluent interface orqali, aniq va xatoga chidamli tarzda email quriladi:
email = (EmailBuilder(kimdan="support@firma.uz")
         .kimga_qosh("ali@example.com")
         .kimga_qosh("vali@example.com")
         .nusxaga_qosh("boshqaruvchi@firma.uz")
         .mavzu_oʻrnat("Buyurtmangiz holati")
         .matn_oʻrnat("Hurmatli mijoz, buyurtmangiz yetkazilmoqda.")
         .biriktirma_qosh("kvitansiya.pdf")
         .qur())

print(email)
# Email(kimdan='support@firma.uz', kimga=['ali@example.com', 'vali@example.com'],
#       mavzu='Buyurtmangiz holati', matn='Hurmatli mijoz, buyurtmangiz yetkazilmoqda.',
#       biriktirmalar=['kvitansiya.pdf'], nusxa=['boshqaruvchi@firma.uz'])

# qur() ichidagi tekshiruv ishlashini ko'ramiz:
try:
    (EmailBuilder(kimdan="support@firma.uz").mavzu_oʻrnat("Sinov").qur())
except ValueError as xato:
    print(f"Xato: {xato}")
# Xato: Email'da kamida bitta qabul qiluvchi bo'lishi SHART
```

## Keng tarqalgan xatolar

**Xato 1:** fluent interfeys metodlarida `return self`ni unutish.
❌
```python
class Builder:
    def qism_qosh(self, qism):
        self._qismlar.append(qism)
        # return self YO'Q!

Builder().qism_qosh("A").qism_qosh("B")   # AttributeError: 'NoneType' object has no attribute 'qism_qosh'
```
✅ To'g'ri: har bir "qurish qadami" metodi, agar u zanjirlanishi (chaining) kerak bo'lsa, albatta `return self` bilan tugashi kerak.

**Xato 2:** bitta Builder obyektini qayta ishlatib, eski holatni "tozalamasdan" qoldirish.
❌
```python
builder = UyBuilder()
uy1 = builder.qavat_qosh().natijani_olish()
uy2 = builder.qavat_qosh().natijani_olish()   # uy2 — uy1'ning holatini HAM o'z ichiga oladi, agar tozalanmasa!
```
✅ To'g'ri: yuqoridagi `OddiyUyBuilder.natijani_olish()` misolidagi kabi, natija qaytarilgandan keyin ichki holatni **yangi, bo'sh** obyektga almashtiring (yoki har safar yangi Builder obyekti yaratishni talab qiling).

**Xato 3:** oddiy, barcha parametrlari oldindan ma'lum bo'lgan obyekt uchun to'liq Builder+Director tuzilmasi yozish.
❌ Faqat 2-3 ta oddiy, ixtiyoriy bo'lmagan parametrli klass uchun alohida `Builder` va `Director` klasslari yaratish — bu ortiqcha murakkablik.
✅ To'g'ri: bunday holatda oddiy `dataclass` va kalit so'z argumentlari (yuqoridagi "Builder va Python'ning tabiiy imkoniyatlari" bo'limidagi kabi) to'liq yetarli.

## Mashq/topshiriq

**(Oson)** `Burger` obyektini (`non`, `gosht`, `pishloq: bool`, `sabzavotlar: list[str]`) fluent interfeys bilan quruvchi `BurgerBuilder` klassini yozing — `pishloq_qosh()`, `sabzavot_qosh(nomi)`, `qur()` metodlari bilan.

**(O'rtacha)** `SoRovBuilder` misoliga `parametr_qosh(kalit, qiymat)` metodini qo'shing (URL query-parametrlarini saqlaydigan `_parametrlar: dict` uchun) va `qur()` metodida, agar `self._metod == "GET"` bo'lib, `self._tana` bo'sh bo'lmasa, `ValueError("GET so'rovida tana bo'lishi mumkin emas")` chiqaradigan tekshiruv qo'shing.

**(Qiyin)** `PizzaDirektori` klassini yozing — u `PizzaBuilder` (metodlari: `xamir_oʻrnat(turi)`, `pishloq_qosh()`, `ingredient_qosh(nomi)`, `qur()`) obyektini oladi va ikki "retsept" metodiga ega bo'lsin: `vegetarian_pitsa_qur()` (xamir — "yupqa", pishloq qo'shiladi, ingredientlar — `["pomidor", "bazilik", "zaytun"]`) va `gosht_pitsa_qur()` (xamir — "qalin", pishloq qo'shiladi, ingredientlar — `["kolbasa", "gubernoy", "qalampir"]`).

## Qisqacha xulosa

Builder naqshi — ko'p va ixtiyoriy parametrli murakkab obyektlarni "konstruktor portlashi" anti-patternidan qochib, bosqichma-bosqich, aniq nomlangan metodlar orqali qurishga imkon beradi; klassik GoF uslubida bu Builder (qanday qurish) va Director (qanday tartibda qurish) klasslariga bo'linadi, Python'da esa ko'pincha soddaroq, `self`ni qaytaruvchi "fluent interface" (method chaining) shaklida uchraydi; agar barcha parametrlar oldindan ma'lum va qurish jarayonida tekshiruv/bosqichlar talab qilinmasa, oddiy `dataclass` va kalit so'z argumentlari Builder'dan ko'ra tabiiyroq yechim bo'lib qoladi.
