# Abstract Factory naqshi

## Bu darsda nimalarni o'rganasiz

- Abstract Factory naqshining qaysi muammoni (bir-biriga mos keluvchi obyektlar OILASINI yaratish) hal qilishini tushunasiz
- Abstract Factory va Factory Method o'rtasidagi asosiy farqni aniq ayta olasiz
- To'liq ishlaydigan Abstract Factory misolini yoza olasiz
- Qaysi vaziyatda bitta Factory Method yetarli, qaysi vaziyatda Abstract Factory kerak bo'lishini aniqlay olasiz

## Nazariy qism

### Muammo — "mos keluvchi obyektlar oilasi"

2.2-darsda ko'rgan Factory Method — **bitta turdagi** obyekt yaratishga mo'ljallangan (masalan, faqat `Transport`). Lekin ba'zan dasturda bir nechta **bir-biriga bog'liq** obyekt turlari bor bo'lib, ular **birgalikda, mos holda** yaratilishi kerak bo'ladi.

Klassik misol — foydalanuvchi interfeysi (UI) elementlari: agar dastur ham **Windows**, ham **macOS** uslubini qo'llab-quvvatlasa, `Tugma`, `Checkbox` va `ScrollBar` kabi elementlarning **barchasi** bir xil uslubda (hammasi Windows yoki hammasi macOS) yaratilishi kerak — **aralash** (bir tugma Windows, boshqa checkbox macOS uslubida) bo'lmasligi kerak.

**Abstract Factory naqshi** — aynan shu muammoni hal qiladi: u **bir nechta bog'liq Factory Method'larni bitta interfeys ichiga** jamlaydi, shunda bitta "oila" tanlanganda, shu oilaga tegishli **barcha** obyektlar **avtomatik mos** keladi.

### Factory Method bilan farqi

Bu farqni aniq tushunib olish juda muhim, chunki ko'p boshlang'ich dasturchilar ularni chalkashtiradi:

| | Factory Method | Abstract Factory |
|---|---|---|
| Nimani yaratadi | **Bitta turdagi** obyekt | **Bir nechta bog'liq turdagi** obyektlar oilasi |
| Tuzilma | Bitta metod (`transport_yarat()`) | Bir nechta metod (`tugma_yarat()`, `checkbox_yarat()`, ...) — hammasi bitta factory klassida |
| Qachon ishlatiladi | Bitta mahsulot turi variatsiyalanadi | Bir nechta mahsulot turi **birgalikda** variatsiyalanishi va **mos kelishi** kerak |

Aslida, Abstract Factory'ning har bir metodi — o'zi alohida **Factory Method** hisoblanadi; farq shundaki, Abstract Factory bu metodlarni **guruhlab**, ularning natijalarining **bir-biriga mosligini** kafolatlaydi.

### To'liq misol — UI elementlari oilasi

```python
from abc import ABC, abstractmethod


# --- Mahsulotlar (Products) — har biri UCHUN abstrakt interfeys ---
class Tugma(ABC):
    @abstractmethod
    def chiz(self) -> str: ...


class Checkbox(ABC):
    @abstractmethod
    def chiz(self) -> str: ...


# --- "Windows oilasi" — barcha elementlar BIR XIL uslubda ---
class WindowsTugma(Tugma):
    def chiz(self) -> str:
        return "[Windows uslubidagi to'rtburchak tugma]"


class WindowsCheckbox(Checkbox):
    def chiz(self) -> str:
        return "[Windows uslubidagi kvadrat checkbox]"


# --- "macOS oilasi" — barcha elementlar BIR XIL uslubda ---
class MacTugma(Tugma):
    def chiz(self) -> str:
        return "(macOS uslubidagi yumaloq tugma)"


class MacCheckbox(Checkbox):
    def chiz(self) -> str:
        return "(macOS uslubidagi doira checkbox)"


# --- Abstract Factory — bir nechta Factory Method'ni GURUHLAYDI ---
class UIFactory(ABC):
    @abstractmethod
    def tugma_yarat(self) -> Tugma: ...

    @abstractmethod
    def checkbox_yarat(self) -> Checkbox: ...


class WindowsUIFactory(UIFactory):
    def tugma_yarat(self) -> Tugma:
        return WindowsTugma()

    def checkbox_yarat(self) -> Checkbox:
        return WindowsCheckbox()


class MacUIFactory(UIFactory):
    def tugma_yarat(self) -> Tugma:
        return MacTugma()

    def checkbox_yarat(self) -> Checkbox:
        return MacCheckbox()


# --- Chaqiruvchi kod — qaysi ANIQ klass ishlatilayotganini BILMAYDI ---
def oyna_chiz(factory: UIFactory) -> None:
    tugma = factory.tugma_yarat()
    checkbox = factory.checkbox_yarat()
    print(tugma.chiz())
    print(checkbox.chiz())


print("--- Windows oynasi ---")
oyna_chiz(WindowsUIFactory())
print("--- macOS oynasi ---")
oyna_chiz(MacUIFactory())
# --- Windows oynasi ---
# [Windows uslubidagi to'rtburchak tugma]
# [Windows uslubidagi kvadrat checkbox]
# --- macOS oynasi ---
# (macOS uslubidagi yumaloq tugma)
# (macOS uslubidagi doira checkbox)
```

Bu yerdagi eng muhim kafolat: `oyna_chiz` funksiyasiga qaysi factory berilsa, **shu oilaning BARCHA elementlari** avtomatik mos keladi — `WindowsUIFactory` bilan ishlaganda hech qachon tasodifan `MacCheckbox` paydo bo'lishi **mumkin emas**, chunki `WindowsUIFactory.checkbox_yarat()` faqat `WindowsCheckbox`ni qaytaradi. Bu — naqshning asosiy qiymati: **oilaviy izchillikni (consistency) kafolatlash**.

### Operatsion tizimga qarab to'g'ri factory'ni tanlash

Amalda, qaysi konkret factory ishlatilishi odatda dastur ishga tushganda **bir marta** aniqlanadi (masalan, operatsion tizimga qarab):

```python
import platform


def ui_factory_olish() -> UIFactory:
    """Bu — Factory Method naqshining o'zi, lekin Abstract Factory'ni TANLASH uchun!"""
    tizim = platform.system()
    if tizim == "Windows":
        return WindowsUIFactory()
    return MacUIFactory()         # soddalik uchun — aks holda Linux uchun ham alohida oila bo'lardi


# Dastur boshida BIR MARTA tanlanadi, keyin butun dastur davomida shu factory ishlatiladi:
joriy_factory = ui_factory_olish()
oyna_chiz(joriy_factory)
```

Bu — qiziqarli nuqta: **Factory Method va Abstract Factory birga ishlatilishi mumkin** — Factory Method qaysi Abstract Factory'ni tanlashga, Abstract Factory esa shu oiladagi aniq mahsulotlarni yaratishga xizmat qiladi.

### Real dunyoda qayerda ishlatiladi

- **GUI freymvorklari** (Tkinter, PyQt) — turli "tema" (theme) yoki platformaga mos vidjetlar oilasini yaratishda.
- **Ma'lumotlar bazasi drayverlari** — `sqlite3`, `psycopg2` kabi modullar har biri o'zining `Connection`, `Cursor` klasslari **oilasini** taqdim etadi, va ular bir-biriga mos (bitta modulning `Connection`i boshqa modulning `Cursor`i bilan ishlamaydi) — bu Abstract Factory g'oyasiga juda yaqin.
- **Turli formatdagi hisobot generatorlari** — PDF uchun `PDFSarlavha`+`PDFJadval`, Excel uchun `ExcelSarlavha`+`ExcelJadval` — har bir format o'z "mos keluvchi" komponentlar oilasiga ega.

## Amaliy misol

To'liq, mustaqil ishlaydigan misol: turli bazalar (test va production) uchun mos keluvchi ulanish va so'rov bajaruvchi obyektlar oilasi:

```python
# db_abstract_factory.py
from abc import ABC, abstractmethod


# --- Mahsulotlar ---
class Ulanish(ABC):
    @abstractmethod
    def ulan(self) -> str: ...


class SorovBajaruvchi(ABC):
    @abstractmethod
    def bajar(self, sorov: str) -> str: ...


# --- "Test muhiti" oilasi — xotirada, tez, xavfsiz ---
class TestUlanish(Ulanish):
    def ulan(self) -> str:
        return "Xotiradagi (in-memory) test bazasiga ulandi"


class TestSorovBajaruvchi(SorovBajaruvchi):
    def bajar(self, sorov: str) -> str:
        return f"[TEST] Simulyatsiya qilindi: {sorov}"


# --- "Production muhiti" oilasi — haqiqiy, ehtiyotkor ---
class ProdUlanish(Ulanish):
    def ulan(self) -> str:
        return "Haqiqiy production bazasiga ulandi (SSL bilan)"


class ProdSorovBajaruvchi(SorovBajaruvchi):
    def bajar(self, sorov: str) -> str:
        return f"[PRODUCTION] Haqiqatan bajarildi: {sorov}"


# --- Abstract Factory ---
class BazaFactory(ABC):
    @abstractmethod
    def ulanish_yarat(self) -> Ulanish: ...

    @abstractmethod
    def sorov_bajaruvchi_yarat(self) -> SorovBajaruvchi: ...


class TestBazaFactory(BazaFactory):
    def ulanish_yarat(self) -> Ulanish:
        return TestUlanish()

    def sorov_bajaruvchi_yarat(self) -> SorovBajaruvchi:
        return TestSorovBajaruvchi()


class ProdBazaFactory(BazaFactory):
    def ulanish_yarat(self) -> Ulanish:
        return ProdUlanish()

    def sorov_bajaruvchi_yarat(self) -> SorovBajaruvchi:
        return ProdSorovBajaruvchi()


class Dastur:
    def __init__(self, factory: BazaFactory):
        self._ulanish = factory.ulanish_yarat()
        self._bajaruvchi = factory.sorov_bajaruvchi_yarat()

    def ishga_tushir(self) -> None:
        print(self._ulanish.ulan())
        print(self._bajaruvchi.bajar("SELECT * FROM foydalanuvchilar"))


print("=== Testlash muhiti ===")
Dastur(TestBazaFactory()).ishga_tushir()

print("\n=== Production muhiti ===")
Dastur(ProdBazaFactory()).ishga_tushir()
# === Testlash muhiti ===
# Xotiradagi (in-memory) test bazasiga ulandi
# [TEST] Simulyatsiya qilindi: SELECT * FROM foydalanuvchilar
#
# === Production muhiti ===
# Haqiqiy production bazasiga ulandi (SSL bilan)
# [PRODUCTION] Haqiqatan bajarildi: SELECT * FROM foydalanuvchilar
```

Bu misol — Abstract Factory'ning juda muhim amaliy foydasini ko'rsatadi: **test va production muhitlari hech qachon aralashib ketmaydi**, chunki har bir `BazaFactory` o'z oilasining **barcha** mos komponentlarini yaratadi.

## Keng tarqalgan xatolar

**Xato 1:** Abstract Factory'ni faqat **bitta** mahsulot turi uchun ishlatish (aslida Factory Method yetarli bo'lgan holatda).
❌
```python
class Factory(ABC):
    @abstractmethod
    def mahsulot_yarat(self) -> Mahsulot: ...   # faqat BITTA metod — bu Abstract Factory emas, oddiy Factory Method!
```
✅ To'g'ri: agar faqat bitta turdagi obyekt variatsiyalansa, 2.2-darsdagi Factory Method yetarli. Abstract Factory faqat **bir nechta bog'liq** mahsulot turi **birgalikda** variatsiyalanganda qo'llanadi.

**Xato 2:** turli oilalarning komponentlarini qo'lda aralashtirib ishlatish.
❌
```python
tugma = WindowsUIFactory().tugma_yarat()
checkbox = MacUIFactory().checkbox_yarat()     # ikki XIL oiladan aralashtirib olish — naqshning maqsadini buzadi!
```
✅ To'g'ri: har doim **bitta** factory obyektini saqlab, undan **barcha** kerakli komponentlarni oling (yuqoridagi `Dastur.__init__` misolidagi kabi) — shunda izchillik avtomatik kafolatlanadi.

**Xato 3:** yangi mahsulot turi (masalan, `ScrollBar`) qo'shishni "oson" deb o'ylash.
❌ Abstract Factory'ga yangi **mahsulot turi** (yangi abstrakt metod, masalan `scrollbar_yarat()`) qo'shish — **BARCHA mavjud konkret factory klasslarini** (`WindowsUIFactory`, `MacUIFactory`, ...) o'zgartirishni talab qiladi, bu OCP'ni buzadi.
✅ To'g'ri: bu — Abstract Factory naqshining **tabiiy cheklovi** ekanini bilib qo'ying: naqsh yangi **oila** (masalan, `LinuxUIFactory`) qo'shishni oson qiladi, lekin yangi **mahsulot turi** qo'shish har doim barcha oilalarni o'zgartirishni talab qiladi — bu trade-off, xato emas, lekin loyihalashda hisobga olinishi kerak.

## Mashq/topshiriq

**(Oson)** `Pitsa` va `Salat` mahsulot interfeyslariga ega, `"Italyan"` va `"Yaponiya"` oshxona oilalarini yarating (`ItalyanOshxonasiFactory`, `YaponOshxonasiFactory`) — har biri mos `pitsa_yarat()` va `salat_yarat()` metodlariga ega bo'lsin (masalan, Italyan — `"Margarita pitsa"`/`"Kaprezze salati"`, Yapon — `"Okonomiyaki"`/`"Sunomono salati"`).

**(O'rtacha)** Yuqoridagi `BazaFactory` misoliga uchinchi oila — `StagingBazaFactory` (staging muhiti, production'ga juda yaqin, lekin alohida ma'lumotlar bilan) qo'shing.

**(Qiyin)** Ikki mahsulot turiga (`Shrift` va `Ranglar_sxemasi`) ega "Tema" (`Theme`) Abstract Factory'sini yozing: `"Qorong'u"` va `"Yorug'"` temalar bo'lsin, har biri mos shrift o'lchami/rangi va fon/matn ranglarini qaytarsin, so'ngra bitta `Sahifa` klassi orqali tanlangan temaga mos "render" qiluvchi (konsolga chop etuvchi) metod yozing.

## Qisqacha xulosa

Abstract Factory naqshi — bir nechta bog'liq Factory Method'ni bitta interfeys ichiga jamlab, bir-biriga mos keluvchi obyektlar **oilasini** yaratishni kafolatlaydi (masalan, bitta platformaga tegishli barcha UI elementlari); u Factory Method'dan farqli ravishda **bitta emas, bir nechta** mahsulot turini birgalikda boshqaradi va shu orqali turli oilalarning tasodifan aralashib ketishining oldini oladi, biroq yangi **mahsulot turi** qo'shish barcha mavjud oilalarni o'zgartirishni talab qilishi — bu naqshning asosiy trade-off'i hisoblanadi.
