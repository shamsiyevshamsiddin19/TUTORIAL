# Factory Method naqshi

## Bu darsda nimalarni o'rganasiz

- Factory Method naqshining qaysi muammoni (obyekt yaratishni "chaqiruvchidan ajratish") hal qilishini tushunasiz
- Klassik GoF uslubida (meros orqali) va pythonic uslubda (funksiya/klassmetod orqali) Factory Method yoza olasiz
- Factory Method'ni to'g'ridan-to'g'ri `ClassName()` chaqirishdan qachon afzal ko'rish kerakligini bilasiz
- Python standart kutubxonasidagi real factory misollarini (`json.loads`, logging) tanib olasiz

## Nazariy qism

### Muammo — nega to'g'ridan-to'g'ri konstruktor chaqirish yetarli emas

Oddiy holatda obyekt yaratish juda sodda: `obj = Klass()`. Lekin ba'zi vaziyatlarda bu **yetarli emas**:

1. Qaysi **aniq klassdan** obyekt yaratilishi — **runtime vaqtida** (dastur ishlayotgan paytda, masalan foydalanuvchi tanlovi, konfiguratsiya fayli yoki tashqi ma'lumot asosida) aniqlanishi kerak bo'ladi.
2. Obyekt yaratish jarayoni **murakkab** bo'ladi — bir nechta qadam, tekshiruv yoki tashqi resursga murojaat talab qilinadi, va bu mantiqni **chaqiruvchi kod ichida takrorlashni** istamaymiz.
3. Kelajakda **yangi turdagi obyektlar** qo'shilishi kutilmoqda, va biz chaqiruvchi kodni **har safar o'zgartirmasdan** (1.2-darsdagi Open/Closed tamoyili) buni amalga oshirishni xohlaymiz.

**Factory Method naqshi** — obyekt yaratish mantiqini **alohida metod/funksiyaga** chiqarib, chaqiruvchi kodni **"qaysi aniq klass yaratilishi"**dan butunlay bexabar qoladigan qilib qo'yadi.

### Klassik GoF uslubi — meros orqali Factory Method

GoF'ning asl g'oyasi — ota klassda **abstrakt factory metod** e'lon qilish, har bir bola klass esa shu metodni **o'zicha** amalga oshiradi:

```python
from abc import ABC, abstractmethod


# "Mahsulot" (Product) — yaratiluvchi obyektlarning umumiy interfeysi
class Transport(ABC):
    @abstractmethod
    def yetkaz(self) -> str: ...


class Yuk_mashinasi(Transport):
    def yetkaz(self) -> str:
        return "Yuk yo'l orqali yetkazildi"


class Kema(Transport):
    def yetkaz(self) -> str:
        return "Yuk dengiz orqali yetkazildi"


# "Yaratuvchi" (Creator) — factory metodni e'lon qiladi, lekin uni AMALGA OSHIRMAYDI
class YetkazishXizmati(ABC):
    @abstractmethod
    def transport_yarat(self) -> Transport:
        """Factory method — har bir bola klass O'ZICHA qaysi Transport yaratishini belgilaydi."""
        ...

    def buyurtmani_yetkaz(self) -> str:
        # Bu metod qaysi ANIQ Transport ishlatilayotganini BILMAYDI — faqat interfeysga ishonadi
        transport = self.transport_yarat()
        return transport.yetkaz()


class YolXizmati(YetkazishXizmati):
    def transport_yarat(self) -> Transport:
        return Yuk_mashinasi()


class DengizXizmati(YetkazishXizmati):
    def transport_yarat(self) -> Transport:
        return Kema()


for xizmat in [YolXizmati(), DengizXizmati()]:
    print(xizmat.buyurtmani_yetkaz())
# Yuk yo'l orqali yetkazildi
# Yuk dengiz orqali yetkazildi
```

E'tibor bering: `buyurtmani_yetkaz` metodi hech qachon `Yuk_mashinasi` yoki `Kema` nomini bilmaydi — u faqat `Transport` abstraksiyasiga (1.2-darsdagi Dependency Inversion tamoyiliga mos) ishonadi. Yangi transport turi (masalan, `Samolyot`) qo'shish uchun faqat **yangi** `YetkazishXizmati` bola klassi yaratiladi, **mavjud** kod o'zgartirilmaydi — bu aynan Open/Closed tamoyilining amalda qo'llanilishi.

### Pythonic uslub — klassmetod yoki oddiy funksiya orqali

Python'da to'liq meros zanjiri qurish ko'pincha **ortiqcha murakkablik** bo'ladi. Ko'proq tarqalgan, sodda yondashuv — **`@classmethod`** yordamida "muqobil konstruktor" yaratish (bu uslubni 4.4-darsda `@classmethod`ning umumiy vazifasi sifatida ko'rgan edik):

```python
from dataclasses import dataclass


@dataclass
class Sana:
    yil: int
    oy: int
    kun: int

    @classmethod
    def satrdan_yarat(cls, satr: str) -> "Sana":
        """Factory method: 'YYYY-MM-DD' formatidagi satrdan Sana obyekti yaratadi."""
        yil, oy, kun = map(int, satr.split("-"))
        return cls(yil, oy, kun)

    @classmethod
    def bugungi_sana_simulyatsiya(cls, timestamp_yil=2026) -> "Sana":
        """Factory method: boshqa manbadan (bu yerda — soddalashtirilgan) Sana yaratadi."""
        return cls(timestamp_yil, 1, 1)


sana1 = Sana.satrdan_yarat("2026-10-17")
sana2 = Sana(2026, 10, 17)                  # oddiy konstruktor ham ishlaydi — ikkisi BIR XIL natija
print(sana1 == sana2)                        # True (dataclass avtomatik __eq__ yaratadi)
```

Bu yerda `Sana.satrdan_yarat(...)` — "nomli konstruktor" (named constructor) vazifasini bajaradi: u `__init__`ning o'zgarmas signaturasini (yil, oy, kun) saqlab qolib, **boshqa formatdagi** ma'lumotdan obyekt yaratish imkonini beradi — bu, masalan, `dict.fromkeys()` yoki `datetime.fromisoformat()` kabi standart kutubxonadagi metodlarning aynan o'zi ishlatadigan yondashuv.

Yana bir keng tarqalgan pythonic usul — **oddiy funksiya** orqali factory:

```python
from abc import ABC, abstractmethod


class Shakl(ABC):
    @abstractmethod
    def chiz(self) -> str: ...


class Kvadrat(Shakl):
    def chiz(self) -> str:
        return "□ Kvadrat chizildi"


class Uchburchak(Shakl):
    def chiz(self) -> str:
        return "△ Uchburchak chizildi"


def shakl_yarat(turi: str) -> Shakl:
    """Oddiy funksiya-factory — eng sodda, eng ko'p ishlatiladigan pythonic usul."""
    moslovchilar = {
        "kvadrat": Kvadrat,
        "uchburchak": Uchburchak,
    }
    if turi not in moslovchilar:
        raise ValueError(f"Noma'lum shakl turi: {turi}")
    return moslovchilar[turi]()


shakl = shakl_yarat("kvadrat")
print(shakl.chiz())    # □ Kvadrat chizildi
```

Bu yerda `moslovchilar` lug'ati — yangi shakl qo'shishni ham ancha osonlashtiradi: elif zanjiri o'rniga, shunchaki lug'atga yangi juftlik qo'shish kifoya (lekin to'liq OCP'ga erishish uchun bu lug'atni tashqi "registratsiya" mexanizmi bilan to'ldirish mumkin — bu haqda 2.3-darsda Abstract Factory bilan birga ko'ramiz).

### Qachon oddiy `Klass()` o'rniga Factory Method ishlatish kerak

Factory Method — har doim kerak emas. Uni qo'llashni **oqlaydigan** holatlar:

- Qaysi aniq klass yaratilishi **runtime ma'lumotiga** (foydalanuvchi kiritgan qiymat, konfiguratsiya, tashqi API javobi) bog'liq bo'lsa.
- Obyekt yaratish bir nechta **qadam** yoki **tekshiruv** talab qilsa (masalan, parametrlarni tekshirish, standart qiymatlarni to'ldirish, bog'liq obyektlarni ham yaratish).
- Kelajakda **yangi turlar** qo'shilishi rejalashtirilgan bo'lsa va chaqiruvchi kodni o'zgartirmaslik muhim bo'lsa.

Agar klass yaratish shunchaki `Klass(arg1, arg2)` bo'lib, hech qanday shartli mantiq yo'q bo'lsa — Factory Method shart emas (1.1-darsdagi overengineering ogohlantirishini eslang).

### Real dunyoda qayerda ishlatiladi

- **`json.loads` / `json.dumps`** — JSON matnidan Python obyektlariga (yoki aksincha) "qaysi turdagi obyekt yaratilishi" ma'lumotning o'ziga qarab ichki tarzda hal qilinadi.
- **`logging.getLogger(nomi)`** — ichki tarzda yangi `Logger` obyekti yaratadi (yoki mavjudini qaytaradi — 2.1-darsdagi Singleton bilan uyg'unlashgan holda).
- **Django ORM'dagi `Model.objects.create(...)`** — ma'lumotlar bazasi yozuvi va Python obyektini bir vaqtda yaratadigan factory metod.

## Amaliy misol

To'liq, real hayotiy misol: turli formatdagi fayllarni o'qiydigan "parser factory" tizimi — yangi format qo'shilganda mavjud kodga tegilmaydi:

```python
# fayl_parser_factory.py
from abc import ABC, abstractmethod


class FaylParser(ABC):
    @abstractmethod
    def oqi(self, mazmun: str) -> dict: ...


class CsvParser(FaylParser):
    def oqi(self, mazmun: str) -> dict:
        qatorlar = mazmun.strip().split("\n")
        sarlavha = qatorlar[0].split(",")
        natija = {"sarlavha": sarlavha, "qatorlar_soni": len(qatorlar) - 1}
        return natija


class JsonParser(FaylParser):
    def oqi(self, mazmun: str) -> dict:
        import json
        return {"malumot": json.loads(mazmun), "format": "json"}


class IniParser(FaylParser):
    def oqi(self, mazmun: str) -> dict:
        natija = {}
        for qator in mazmun.strip().split("\n"):
            if "=" in qator:
                kalit, qiymat = qator.split("=", 1)
                natija[kalit.strip()] = qiymat.strip()
        return natija


class ParserFactory:
    """Markazlashtirilgan factory — kengaytmaga qarab to'g'ri parserni tanlaydi."""
    _parserlar: dict[str, type[FaylParser]] = {
        ".csv": CsvParser,
        ".json": JsonParser,
        ".ini": IniParser,
    }

    @classmethod
    def yarat(cls, fayl_nomi: str) -> FaylParser:
        import os
        kengaytma = os.path.splitext(fayl_nomi)[1]
        if kengaytma not in cls._parserlar:
            raise ValueError(f"Qo'llab-quvvatlanmaydigan fayl turi: {kengaytma}")
        return cls._parserlar[kengaytma]()

    @classmethod
    def registratsiya_qil(cls, kengaytma: str, parser_klassi: type[FaylParser]) -> None:
        """Yangi format qo'shish MAVJUD koddagi hech narsani o'zgartirmaydi (OCP)."""
        cls._parserlar[kengaytma] = parser_klassi


# Foydalanish:
csv_parser = ParserFactory.yarat("malumotlar.csv")
print(csv_parser.oqi("ism,yosh\nAli,25\nVali,30"))
# {'sarlavha': ['ism', 'yosh'], 'qatorlar_soni': 2}

json_parser = ParserFactory.yarat("sozlamalar.json")
print(json_parser.oqi('{"debug": true}'))
# {'malumot': {'debug': True}, 'format': 'json'}


# Yangi format — YAML — qo'shish (mavjud klasslarga TEGILMAYDI):
class YamlParser(FaylParser):
    def oqi(self, mazmun: str) -> dict:
        return {"ogohlantirish": "soddalashtirilgan YAML parser", "qator_soni": len(mazmun.split("\n"))}


ParserFactory.registratsiya_qil(".yaml", YamlParser)
yaml_parser = ParserFactory.yarat("konfig.yaml")
print(yaml_parser.oqi("a: 1\nb: 2"))
# {'ogohlantirish': 'soddalashtirilgan YAML parser', 'qator_soni': 2}
```

## Keng tarqalgan xatolar

**Xato 1:** Factory Method'ni hech qanday shartli mantiq bo'lmagan oddiy obyekt yaratish uchun ishlatish.
❌
```python
class KitobFactory:
    def yarat(self, nomi, muallif):
        return Kitob(nomi, muallif)      # hech qanday qo'shimcha mantiq yo'q — factory keraksiz!
```
✅ To'g'ri: agar yaratish mantiqida hech qanday shartli tanlov yoki qo'shimcha qadam bo'lmasa, shunchaki `Kitob(nomi, muallif)`ni to'g'ridan-to'g'ri chaqiring — factory faqat **haqiqiy murakkablik** bo'lganda qiymat qo'shadi.

**Xato 2:** `@classmethod` factory ichida `cls(...)` o'rniga aniq klass nomini yozish — bu merosni buzadi.
❌
```python
class Hayvon:
    @classmethod
    def nomdan_yarat(cls, nom):
        return Hayvon(nom)    # Hayvon qattiq yozilgan!

class Mushuk(Hayvon):
    pass

m = Mushuk.nomdan_yarat("Pushok")
print(type(m))    # <class 'Hayvon'> — kutilgan Mushuk EMAS!
```
✅ To'g'ri: har doim `cls(nom)` dan foydalaning — bu `classmethod`ning asosiy afzalligi: `cls` chaqirilgan **aniq** klassga (agar `Mushuk.nomdan_yarat(...)` chaqirilsa — `Mushuk`ga) mos keladi.

**Xato 3:** lug'at-asosidagi factory'da noma'lum kalit uchun tushunarsiz xato chiqarish (yoki umuman xato chiqarmaslik).
❌
```python
def shakl_yarat(turi):
    return {"kvadrat": Kvadrat}[turi]()   # noma'lum turi uchun KeyError — tushunarsiz xabar bilan
```
✅ To'g'ri: yuqoridagi "Nazariy qism"dagi misoldagi kabi, avval `turi not in moslovchilar` tekshiruvini qiling va **aniq, tushunarli** `ValueError` xabari bilan chiqaring — bu debug qilishni osonlashtiradi.

## Mashq/topshiriq

**(Oson)** `hayvon_ovozi_yarat(turi)` oddiy funksiya-factory yozing: `"it"` uchun `"Vov-vov!"`, `"mushuk"` uchun `"Myov!"` qaytaradigan mos klasslar (`It`, `Mushuk`, har birida `ovoz_chiqar()` metodi) yaratib, lug'at orqali factory qiling.

**(O'rtacha)** Klassik GoF uslubida (`YetkazishXizmati` misoliga asoslanib) `IchimlikDokoni` abstrakt klassini yozing, unda `ichimlik_yarat()` abstrakt factory metod bo'lsin; `ChoyDokoni` va `KofeDokoni` bola klasslarini yaratib, har biri mos `Ichimlik` (`Choy`, `Kofe`) obyektini qaytarsin.

**(Qiyin)** `ParserFactory` namunasiga o'xshab, `@classmethod` bilan "nomli konstruktorlar" to'plamiga ega `Foydalanuvchi` klassini yozing: `Foydalanuvchi.emaildan_yarat(email)` (ism qismini `@` belgisigacha email'dan oladi) va `Foydalanuvchi.anonim_yarat()` (ism — `"Anonim_<tasodifiy_son>"`, `random.randint` yordamida) metodlarini qo'shing.

## Qisqacha xulosa

Factory Method naqshi — obyekt yaratish mantiqini chaqiruvchi koddan ajratib, qaysi aniq klass yaratilishi runtime ma'lumotiga qarab belgilanishiga imkon beradi; klassik GoF uslubida bu abstrakt factory metod orqali meros bilan amalga oshiriladi, Python'da esa ko'pincha ancha soddaroq, `@classmethod` orqali "nomli konstruktor" yoki oddiy lug'at-asosidagi funksiya shaklida uchraydi; bu naqsh Open/Closed tamoyilini amalda qo'llashning asosiy vositalaridan biri bo'lib, yangi turlar qo'shilishi kutilayotgan yoki yaratish mantig'i murakkab bo'lgan holatlarda qiymat beradi, lekin oddiy, shartsiz obyekt yaratishda ortiqcha murakkablik keltirib chiqaradi.
