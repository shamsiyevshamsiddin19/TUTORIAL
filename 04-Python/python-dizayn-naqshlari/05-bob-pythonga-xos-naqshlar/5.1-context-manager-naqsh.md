# Context Manager naqshi

## Bu darsda nimalarni o'rganasiz

- `with` operatori ortida qanday mexanizm yotganini tushuntira olasiz
- `__enter__`/`__exit__` metodlari bilan o'z context manageringizni yoza olasiz
- `contextlib.contextmanager` dekoratori yordamida generator-asosli, qisqaroq context manager yoza olasiz
- Bir nechta context managerni bitta `with` qatorida birlashtira olasiz
- `__exit__` ichida xatolarni qanday "yutish" (suppress) mumkinligini va bu qachon xavfli bo'lishini bilasiz

## Nazariy qism

### Context manager nima va nega kerak

5.2-darsda (05-bob) `with open(...) as f:` qatorini ko'rgansiz — fayl avtomatik yopiladi, hatto xato yuz bersa ham. Bu sehr emas: `open()` qaytargan obyekt **context manager protokoliga** amal qiladi. **Context manager** — resursni ochish va albatta yopish (fayl, tarmoq ulanishi, ma'lumotlar bazasi tranzaksiyasi, lock) kerak bo'lgan har qanday vaziyat uchun mo'ljallangan naqsh: u "sozlash (setup) → ishlatish → tozalash (teardown), **hatto xato bo'lsa ham**" degan takrorlanuvchi tuzilmani rasmiylashtiradi.

`try`/`finally` bilan ham xuddi shu narsaga erishish mumkin:

```python
f = open("malumot.txt", "w")
try:
    f.write("Salom")
finally:
    f.close()
```

Bu ishlaydi, lekin har safar resurs ishlatganda shu uch qatorni qayta-qayta yozish — zerikarli va xato qilish oson (`finally`ni unutib qo'yish mumkin). Context manager naqshi — shu "sozlash/tozalash" mantiqini **bitta qayta ishlatiladigan obyektga** o'rab qo'yadi, foydalanuvchi esa faqat `with obyekt:` deb yozadi.

### `__enter__` va `__exit__` — protokolning o'zi

Har qanday klass quyidagi ikki magic metodni (4.4-darsda ko'rgan) implementatsiya qilsa, u `with` bilan ishlatilishi mumkin:

```python
class FaylOchuvchi:
    def __init__(self, fayl_nomi, rejim):
        self.fayl_nomi = fayl_nomi
        self.rejim = rejim
        self.fayl = None

    def __enter__(self):
        print(f"[OCHISH] {self.fayl_nomi}")
        self.fayl = open(self.fayl_nomi, self.rejim)
        return self.fayl          # `as` so'zidan keyingi o'zgaruvchiga shu qaytadi

    def __exit__(self, exc_turi, exc_qiymat, traceback):
        print(f"[YOPISH] {self.fayl_nomi}")
        if self.fayl:
            self.fayl.close()
        return False               # False — xato bo'lsa, uni YUTMA, tashqariga chiqar


with FaylOchuvchi("malumot.txt", "w") as f:
    f.write("Salom, context manager!")
# [OCHISH] malumot.txt
# [YOPISH] malumot.txt
```

Bosqichlar aniq:

1. `with X() as y:` qatori chaqirilganda, Python avval `X()`ni yaratadi, so'ng uning `__enter__()` metodini chaqiradi.
2. `__enter__()` qaytargan qiymat — `as y`dagi `y`ga tayinlanadi (`__enter__` `self`ni emas, kerakli obyektni qaytarishi mumkin — yuqorida `self.fayl`ni qaytardik, `FaylOchuvchi` obyektini emas).
3. `with` bloki ichidagi kod bajariladi.
4. Blok **har qanday holatda** (muvaffaqiyatli tugasa ham, istisno chiqsa ham) tugaganda, `__exit__(exc_turi, exc_qiymat, traceback)` chaqiriladi.
5. Agar blok ichida xato bo'lmagan bo'lsa, `__exit__`ga uchta argument ham `None` sifatida keladi.

### `__exit__`ning qaytarish qiymati — eng ko'p chalkashtiriladigan joy

`__exit__` **`True` yoki `False` (yoki `None`, bu `False`ga teng)** qaytarishi mumkin, va bu qaytarish qiymati **juda muhim ma'noga ega**:

```python
class XatoniYutuvchi:
    def __enter__(self):
        return self

    def __exit__(self, exc_turi, exc_qiymat, traceback):
        if exc_turi is ZeroDivisionError:
            print(f"Nolga bo'lish xatosi yutildi: {exc_qiymat}")
            return True            # True — xatoni YUTADI, tashqariga chiqarmaydi!
        return False                # boshqa xatolarni tashqariga chiqaradi


with XatoniYutuvchi():
    natija = 10 / 0
    print("Bu qator ISHGA TUSHMAYDI")      # chunki istisno `10/0`da chiqadi

print("Dastur davom etadi — xato yutilgan")
```

**`return True`** — "men bu istisnoni ko'rdim va uni hal qildim, uni yana ko'tarma (re-raise)" degani. **`return False` (yoki hech narsa qaytarmaslik)** — "men faqat tozalash ishini qildim, istisno odatdagidek yuqoriga tarqalsin" degani. Ko'pincha `False` qaytarish **to'g'ri** tanlov — chunki xatoni "yutib qo'yish" xatoni yashirib, debug qilishni qiyinlashtiradi. Faqat **aniq biladigan, kutilgan** istisno turlarini tanlab yutish kerak.

### `contextlib.contextmanager` — generator orqali qisqa yozish

To'liq klass yozish (ayniqsa oddiy holatlar uchun) ortiqcha ko'rinadi. `contextlib` moduli — 5.3-darsda ko'rgan **generator**lardan foydalanib, context managerni bitta funksiya sifatida yozish imkonini beradi:

```python
from contextlib import contextmanager


@contextmanager
def fayl_ochuvchi(fayl_nomi, rejim):
    print(f"[OCHISH] {fayl_nomi}")
    fayl = open(fayl_nomi, rejim)
    try:
        yield fayl              # `yield`gacha — __enter__, `yield` qiymati — `as` o'zgaruvchisi
    finally:
        print(f"[YOPISH] {fayl_nomi}")
        fayl.close()            # yield'dan keyin — __exit__


with fayl_ochuvchi("malumot.txt", "w") as f:
    f.write("Salom!")
```

Mexanizm shunday: `yield`gacha bo'lgan kod — `__enter__`ning o'rnini bosadi; `yield`ning o'zi — `as` so'zidan keyingi qiymatni beradi; `with` blokidan chiqilgandan so'ng, bajarilish generator ichida **xuddi `yield` qatoridan davom etayotgandek** tiklanadi — shuning uchun `yield`dan keyingi kod (odatda `finally` ichida) `__exit__`ning vazifasini bajaradi. `try`/`finally` ishlatish **shart** — aks holda `with` bloki ichida xato chiqsa, tozalash kodi bajarilmay qoladi.

Xatoni ushlash kerak bo'lsa:

```python
@contextmanager
def xatoni_yutuvchi():
    try:
        yield
    except ZeroDivisionError as xato:
        print(f"Yutildi: {xato}")
        # bu yerda `raise` yozilmasa — xato yutiladi, klass versiyasidagi `return True`ga mos keladi
```

### Bir nechta context managerni birlashtirish

Python 3.1+da `with` bir nechta context managerni vergul bilan ajratib, bitta qatorda qabul qiladi (yoki qavslar bilan ko'p qatorga bo'lish mumkin, Python 3.10+):

```python
with open("manba.txt") as manba, open("natija.txt", "w") as natija:
    natija.write(manba.read().upper())

# Python 3.10+ — qavs bilan ko'p qatorli yozish, uzun nomlar bo'lsa qulay
with (
    open("manba.txt") as manba,
    open("natija.txt", "w") as natija,
):
    natija.write(manba.read().upper())
```

Bular **ichma-ich** joylashganidek ishlaydi: avval `manba` ochiladi, so'ng `natija` ochiladi; chiqishda **teskari tartibda** (avval `natija`, keyin `manba`) yopiladi — bu xuddi ichma-ich yozilgan ikkita `with` blokiga teng:

```python
with open("manba.txt") as manba:
    with open("natija.txt", "w") as natija:
        natija.write(manba.read().upper())
```

`contextlib.ExitStack` — context managerlar sonini **oldindan bilmagan** holatlar uchun (masalan, ro'yxatdagi barcha fayllarni ochish):

```python
from contextlib import ExitStack

fayl_nomlari = ["a.txt", "b.txt", "c.txt"]

with ExitStack() as stack:
    fayllar = [stack.enter_context(open(nom, "w")) for nom in fayl_nomlari]
    for fayl in fayllar:
        fayl.write("ma'lumot")
# `with` blokidan chiqilganda — barcha fayllar ESHIK TARTIBIGA teskari yopiladi
```

### `contextlib.suppress` — kichik, tayyor context manager

```python
from contextlib import suppress

with suppress(FileNotFoundError):
    import os
    os.remove("mavjud_bolmagan_fayl.txt")
# xato chiqmaydi — FileNotFoundError "yutildi"; bu quyidagiga teng:
# try:
#     os.remove(...)
# except FileNotFoundError:
#     pass
```

## Amaliy misol

Ma'lumotlar bazasi tranzaksiyasini simulyatsiya qiluvchi context manager — xato bo'lsa avtomatik "rollback", muvaffaqiyatli bo'lsa "commit":

```python
# tranzaksiya_misoli.py
from contextlib import contextmanager


class SoxtaMB:
    """Haqiqiy MB o'rniga — tranzaksiya g'oyasini ko'rsatish uchun soxta (fake) klass."""

    def __init__(self):
        self._saqlangan = {}
        self._vaqtinchalik = {}

    def yoz(self, kalit, qiymat):
        self._vaqtinchalik[kalit] = qiymat
        print(f"  [YOZISH] {kalit} = {qiymat} (vaqtinchalik buferda)")

    def commit(self):
        self._saqlangan.update(self._vaqtinchalik)
        self._vaqtinchalik.clear()
        print("  [COMMIT] barcha o'zgarishlar doimiy saqlandi")

    def rollback(self):
        self._vaqtinchalik.clear()
        print("  [ROLLBACK] barcha o'zgarishlar bekor qilindi")


class Tranzaksiya:
    """Klass-asosli context manager — commit/rollback avtomatik boshqariladi."""

    def __init__(self, mb: SoxtaMB):
        self.mb = mb

    def __enter__(self):
        print("[TRANZAKSIYA BOSHLANDI]")
        return self.mb

    def __exit__(self, exc_turi, exc_qiymat, traceback):
        if exc_turi is None:
            self.mb.commit()
        else:
            print(f"[XATO ANIQLANDI: {exc_turi.__name__}: {exc_qiymat}]")
            self.mb.rollback()
        return False        # xatoni tashqariga chiqaramiz — "yutmaymiz"


@contextmanager
def tranzaksiya(mb: SoxtaMB):
    """Xuddi shu mantiq — generator-asosli versiya, taqqoslash uchun."""
    print("[TRANZAKSIYA BOSHLANDI] (generator versiyasi)")
    try:
        yield mb
        mb.commit()
    except Exception:
        mb.rollback()
        raise


mb = SoxtaMB()

print("--- Muvaffaqiyatli holat ---")
with Tranzaksiya(mb) as baza:
    baza.yoz("foydalanuvchi_1", "Ali")
    baza.yoz("foydalanuvchi_2", "Vali")

print("\n--- Xatoli holat ---")
try:
    with Tranzaksiya(mb) as baza:
        baza.yoz("foydalanuvchi_3", "Hasan")
        raise ValueError("Tarmoq uzildi!")   # tasavvur qiling — tasodifiy xato
except ValueError as xato:
    print(f"Dasturda ushlandi: {xato}")

print(f"\nYakuniy saqlangan ma'lumotlar: {mb._saqlangan}")
# foydalanuvchi_3 YO'Q — chunki rollback bo'ldi, faqat 1 va 2 saqlandi
```

Chiqish natijasi:

```
--- Muvaffaqiyatli holat ---
[TRANZAKSIYA BOSHLANDI]
  [YOZISH] foydalanuvchi_1 = Ali (vaqtinchalik buferda)
  [YOZISH] foydalanuvchi_2 = Vali (vaqtinchalik buferda)
  [COMMIT] barcha o'zgarishlar doimiy saqlandi

--- Xatoli holat ---
[TRANZAKSIYA BOSHLANDI]
  [YOZISH] foydalanuvchi_3 = Hasan (vaqtinchalik buferda)
[XATO ANIQLANDI: ValueError: Tarmoq uzildi!]
  [ROLLBACK] barcha o'zgarishlar bekor qilindi
Dasturda ushlandi: Tarmoq uzildi!

Yakuniy saqlangan ma'lumotlar: {'foydalanuvchi_1': 'Ali', 'foydalanuvchi_2': 'Vali'}
```

Bu naqsh — Django ORM'ning `transaction.atomic()`, SQLAlchemy'ning `Session.begin()` kabi real vositalarining ichki mantiqiga juda o'xshash (bular Django darsligida batafsil ko'riladi).

## Keng tarqalgan xatolar

**Xato 1:** generator-asosli context managerda `try`/`finally`ni unutish.

❌
```python
@contextmanager
def noto_gri_misol():
    fayl = open("test.txt", "w")
    yield fayl
    fayl.close()      # `yield`dan keyin xato chiqsa, BU QATOR ISHGA TUSHMAYDI!
```
Agar `with` bloki ichida istisno chiqsa, generator ichidagi `yield` qatorida xato "qayta ko'tariladi" (re-raise), va agar `try`/`finally` bo'lmasa, undan keyingi `fayl.close()` hech qachon bajarilmaydi — resurs sizib qoladi (resource leak).

✅ To'g'ri: har doim `yield`ni `try` blokiga, tozalash kodini `finally`ga joylashtiring (yuqoridagi "Nazariy qism"dagi misollarga qarang).

**Xato 2:** `__exit__`dan har doim `True` qaytarish.

❌
```python
class XavfliContextManager:
    def __enter__(self):
        return self
    def __exit__(self, *args):
        return True      # BARCHA xatolarni, qaysi turi bo'lishidan qat'i nazar, yutadi!
```
Bu `with` bloki ichidagi **har qanday** xatoni (shu jumladan `TypeError`, `KeyError` kabi dastur xatolarini ham) jim yutib yuboradi — xato sodir bo'lganini bilmay qolasiz, dastur "muvaffaqiyatli ishlagandek" davom etadi, lekin ma'lumotlar noto'g'ri bo'ladi.

✅ To'g'ri: `exc_turi` qiymatini tekshirib, faqat **aniq kutilgan** istisno turlarinigina (masalan, yuqoridagi `ZeroDivisionError` misoli kabi) `True` bilan yutib, qolganlarida `False` qaytaring.

**Xato 3:** `__enter__`da `self`ni qaytarish zarur deb o'ylash.

❌ (bu xato emas, balki keng tarqalgan **tushunmovchilik**)
```python
class Resurs:
    def __enter__(self):
        return self     # har doim shart emas!
```
Ko'pchilik `__enter__` har doim `self`ni qaytarishi kerak deb o'ylaydi, lekin bu **shart emas** — `__enter__` **istalgan** obyektni qaytarishi mumkin (yuqoridagi `FaylOchuvchi` misolida `self.fayl`ni qaytargandik, `self`ni emas). Agar `as` so'zi ishlatilmasa (`with Resurs(): ...`), qaytarish qiymati umuman e'tiborga olinmaydi.

✅ To'g'ri: `__enter__`dan foydalanuvchiga **nima kerak bo'lsa**, aynan shuni qaytaring — ko'pincha bu `self` bo'ladi (chunki klassning boshqa metodlariga kirish kerak bo'ladi), lekin har doim emas.

## Mashq/topshiriq

**(Oson)** `Vaqt_Olchagich` klass-asosli context manager yozing — `with Vaqt_Olchagich():` bloki ichidagi kod qancha vaqt (soniyalarda) bajarilganini `__exit__`da chop etsin (`time.time()` dan foydalaning).

**(O'rtacha)** `vaqtinchalik_papka` nomli `@contextmanager` yozing — `with vaqtinchalik_papka() as yol:` orqali vaqtinchalik papka (`tempfile.mkdtemp()`) yaratilsin, blok ichida foydalanish mumkin bo'lsin, blok tugagach (xato bo'lsa ham) papka avtomatik o'chirilsin (`shutil.rmtree(yol)`).

**(Qiyin)** `maksimal_urinish` nomli `@contextmanager` yozing — ichida `yield`langan kod bloki istisno chiqarsa, uni **jim yutsin va ekranga ogohlantirish chop etsin**, FAQAT agar istisno turi oldindan berilgan ro'yxatda (`ruxsat_etilgan_xatolar` parametri — masalan `(ValueError, KeyError)`) bo'lsa; boshqa barcha xatolarni oddiy tartibda tashqariga chiqarsin.

## Qisqacha xulosa

Context manager naqshi — "sozlash → ishlatish → albatta tozalash" tuzilmasini `with` operatori orqali rasmiylashtiradi, bu esa resurslarni (fayl, tranzaksiya, lock, ulanish) hatto xato yuz berganda ham to'g'ri yopish/bo'shatishni kafolatlaydi; naqsh ikki yo'l bilan amalga oshiriladi — `__enter__`/`__exit__` magic metodlari orqali to'liq klass sifatida (murakkab holatlar, ko'p holat saqlash kerak bo'lganda), yoki `@contextmanager` dekoratori bilan `yield`ga asoslangan generator sifatida (oddiy, qisqa holatlar uchun); `__exit__`ning `True`/`False` qaytarish qiymati — istisnoni "yutish" yoki "tashqariga chiqarish"ni belgilaydigan muhim qaror nuqtasi, va bu qaror faqat aniq kutilgan xato turlari uchun ongli ravishda qabul qilinishi kerak.
