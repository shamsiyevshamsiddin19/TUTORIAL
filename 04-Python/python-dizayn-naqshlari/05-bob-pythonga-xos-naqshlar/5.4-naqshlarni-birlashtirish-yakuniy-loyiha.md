# Naqshlarni birlashtirish — Yakuniy loyiha: Bildirishnoma tizimi

## Bu darsda nimalarni o'rganasiz

- Bir nechta dizayn naqshini **bitta real loyihada birgalikda** qanday ishlatishni ko'rasiz
- Har bir naqsh loyihaning **aynan qaysi muammosini** va **nega aynan shu naqsh** yordamida hal qilganini tushunasiz
- Naqshlarni "shunchaki ko'rsatish uchun" emas, balki **haqiqiy ehtiyojdan kelib chiqib** tanlashni o'rganasiz — bu kurs davomidagi eng muhim xulosa
- Loyihani bosqichma-bosqich, har bir naqsh alohida qatlam sifatida qanday qurilishini ko'rasiz
- O'z mustaqil loyihangizda qaysi naqshni qachon qo'llashni rejalashtira olasiz

## Loyiha haqida

Biz **Bildirishnoma tizimi (Notification System)** quramiz — turli kanallar (email, SMS, push-xabar) orqali, turli "formatlash strategiyalari" bilan bildirishnoma yuboradigan, va yuborilgan har bir bildirishnomani "kuzatib boruvchilar"ga xabar qiladigan tizim. Bu — kichik miqyosda, lekin real loyihalarda (masalan, internet-do'konning "buyurtma holati o'zgardi" xabarnomalari) aynan shunday tuzilgan tizimlarning soddalashtirilgan ko'rinishi.

Loyihada **beshta** naqsh ishlatiladi, har biri **aniq bir muammoni** hal qilish uchun tanlanadi:

| Naqsh | Qayerda ishlatiladi | Nega aynan shu naqsh |
|---|---|---|
| **Singleton** | `SozlamalarManageri` | Butun dastur davomida bitta, umumiy sozlamalar manbai kerak |
| **Builder** | `BildirishnomaBuilder` | Bildirishnoma ko'p ixtiyoriy maydonga ega (mavzu, matn, ustuvorlik, qo'shimcha fayl) |
| **Factory Method** | `KanalFabrikasi` | Qaysi kanal (email/SMS/push) ishlatilishi runtime'da, sozlamaga qarab aniqlanadi |
| **Strategy** | Formatlash strategiyalari | Bir xil bildirishnomani turli formatda (oddiy matn, HTML, qisqartirilgan) chiqarish kerak |
| **Observer** | `BildirishnomaKuzatuvchisi` | Bildirishnoma yuborilganda, bir nechta mustaqil qism (log, statistika, audit) xabardor bo'lishi kerak |

### 1-qadam: Singleton — markaziy sozlamalar

Dastur davomida faqat **bitta** sozlamalar manbai bo'lishi kerak (masalan, "SMS xizmati yoqilgan/o'chirilgan", "standart til") — bu klassik Singleton vazifasi:

```python
class SozlamalarManageri:
    """Butun dastuda BITTA nusxada mavjud bo'ladigan sozlamalar ombori."""

    _nusxa = None

    def __new__(cls):
        if cls._nusxa is None:
            cls._nusxa = super().__new__(cls)
            cls._nusxa.sozlamalar = {
                "sms_yoqilgan": True,
                "push_yoqilgan": True,
                "standart_til": "uz",
            }
        return cls._nusxa

    def olish(self, kalit):
        return self.sozlamalar.get(kalit)

    def ozgartir(self, kalit, qiymat):
        self.sozlamalar[kalit] = qiymat


# Dastuning istalgan joyida SozlamalarManageri() chaqirilsa — AYNAN BIR XIL obyekt qaytadi
s1 = SozlamalarManageri()
s2 = SozlamalarManageri()
assert s1 is s2
```

### 2-qadam: Builder — bildirishnomani bosqichma-bosqich qurish

Bildirishnoma ko'p (ba'zan ixtiyoriy) maydonga ega — buni oddiy `__init__(self, a, b, c, d, e, f)` bilan yozish o'qilishi qiyin bo'lardi. Builder naqshi — qurish jarayonini o'qilishi oson, zanjirli (chainable) metodlarga bo'lib beradi:

```python
class Bildirishnoma:
    """Yakuniy, tayyor bildirishnoma obyekti — Builder yaratadi."""

    def __init__(self):
        self.qabul_qiluvchi = None
        self.mavzu = ""
        self.matn = ""
        self.ustuvorlik = "oddiy"
        self.qoshimcha_fayl = None

    def __repr__(self):
        return (f"Bildirishnoma(qabul_qiluvchi={self.qabul_qiluvchi!r}, "
                f"mavzu={self.mavzu!r}, ustuvorlik={self.ustuvorlik!r})")


class BildirishnomaBuilder:
    """Bildirishnomani qadam-baqadam, o'qilishi oson tarzda quradi."""

    def __init__(self):
        self._bildirishnoma = Bildirishnoma()

    def qabul_qiluvchiga(self, manzil):
        self._bildirishnoma.qabul_qiluvchi = manzil
        return self          # `self`ni qaytarish — ZANJIRLASH (method chaining) imkonini beradi

    def mavzu_bilan(self, mavzu):
        self._bildirishnoma.mavzu = mavzu
        return self

    def matn_bilan(self, matn):
        self._bildirishnoma.matn = matn
        return self

    def ustuvorlik_bilan(self, ustuvorlik):
        self._bildirishnoma.ustuvorlik = ustuvorlik
        return self

    def fayl_qoshib(self, fayl_yoli):
        self._bildirishnoma.qoshimcha_fayl = fayl_yoli
        return self

    def qur(self):
        return self._bildirishnoma


bildirishnoma = (
    BildirishnomaBuilder()
    .qabul_qiluvchiga("ali@mail.uz")
    .mavzu_bilan("Buyurtmangiz jo'natildi")
    .matn_bilan("Buyurtma #4521 yetkazib berish xizmatiga topshirildi.")
    .ustuvorlik_bilan("yuqori")
    .qur()
)
print(bildirishnoma)
```

### 3-qadam: Strategy — formatlash usullarini almashtirish

Bitta bildirishnomani turli ko'rinishda (oddiy matn, HTML, qisqartirilgan SMS uchun) formatlash kerak. Strategy naqshi — har bir formatlash usulini **mustaqil, almashtirila oladigan** klass qiladi:

```python
from abc import ABC, abstractmethod


class FormatlashStrategiyasi(ABC):
    @abstractmethod
    def formatla(self, bildirishnoma):
        ...


class OddiyMatnStrategiyasi(FormatlashStrategiyasi):
    def formatla(self, bildirishnoma):
        return f"{bildirishnoma.mavzu}\n\n{bildirishnoma.matn}"


class HTMLStrategiyasi(FormatlashStrategiyasi):
    def formatla(self, bildirishnoma):
        return f"<h2>{bildirishnoma.mavzu}</h2><p>{bildirishnoma.matn}</p>"


class QisqaSMSStrategiyasi(FormatlashStrategiyasi):
    def formatla(self, bildirishnoma):
        matn = f"{bildirishnoma.mavzu}: {bildirishnoma.matn}"
        return matn[:70] + "..." if len(matn) > 70 else matn
```

### 4-qadam: Factory Method — qaysi kanal ishlatilishini aniqlash

Qaysi "kanal" (email/SMS/push) ishlatilishi — ko'pincha dastur ishga tushgandan keyin, sozlamaga yoki foydalanuvchi tanloviga qarab aniqlanadi. Factory Method — bu qarorni **bitta joyga** to'playdi, qolgan kod esa "qanday kanal yaratilgani"dan bexabar qoladi:

```python
class Kanal(ABC):
    @abstractmethod
    def yubor(self, manzil, matn):
        ...


class EmailKanali(Kanal):
    def yubor(self, manzil, matn):
        print(f"[EMAIL -> {manzil}]\n{matn}\n")


class SMSKanali(Kanal):
    def yubor(self, manzil, matn):
        print(f"[SMS -> {manzil}] {matn}\n")


class PushKanali(Kanal):
    def yubor(self, manzil, matn):
        print(f"[PUSH -> {manzil}] {matn}\n")


class KanalFabrikasi:
    """Qaysi Kanal klassi yaratilishini — BITTA JOYDA hal qiladi."""

    _KANALLAR = {
        "email": EmailKanali,
        "sms": SMSKanali,
        "push": PushKanali,
    }

    @staticmethod
    def kanal_yarat(kanal_nomi):
        kanal_klassi = KanalFabrikasi._KANALLAR.get(kanal_nomi)
        if kanal_klassi is None:
            raise ValueError(f"Noma'lum kanal: {kanal_nomi}")
        return kanal_klassi()
```

### 5-qadam: Observer — bildirishnoma yuborilganda "xabardor qilish"

Har safar bildirishnoma yuborilganda, bir nechta **mustaqil** qism bundan xabardor bo'lishi kerak: logchi yozib qo'yishi, statistika hisoblagich sonini oshirishi, audit tizimi yozib qo'yishi kerak. Bu qismlarni asosiy yuborish mantiqiga "qotirib qo'yish" (hardcode) o'rniga, Observer naqshi ularni **mustaqil obyektlar** sifatida "obuna qildiradi":

```python
class Kuzatuvchi(ABC):
    @abstractmethod
    def xabar_qil(self, bildirishnoma, kanal_nomi):
        ...


class LogKuzatuvchisi(Kuzatuvchi):
    def xabar_qil(self, bildirishnoma, kanal_nomi):
        print(f"[LOG] {kanal_nomi} orqali '{bildirishnoma.mavzu}' yuborildi")


class StatistikaKuzatuvchisi(Kuzatuvchi):
    def __init__(self):
        self.yuborilgan_soni = 0

    def xabar_qil(self, bildirishnoma, kanal_nomi):
        self.yuborilgan_soni += 1


class BildirishnomaYuboruvchisi:
    """Markaziy koordinator — Factory, Strategy'ni ishlatadi va Kuzatuvchilarga xabar beradi."""

    def __init__(self):
        self._kuzatuvchilar = []

    def kuzatuvchi_qosh(self, kuzatuvchi):
        self._kuzatuvchilar.append(kuzatuvchi)

    def yubor(self, bildirishnoma, kanal_nomi, formatlash_strategiyasi):
        kanal = KanalFabrikasi.kanal_yarat(kanal_nomi)        # Factory Method
        matn = formatlash_strategiyasi.formatla(bildirishnoma)  # Strategy
        kanal.yubor(bildirishnoma.qabul_qiluvchi, matn)

        for kuzatuvchi in self._kuzatuvchilar:                 # Observer
            kuzatuvchi.xabar_qil(bildirishnoma, kanal_nomi)
```

### Hammasini birlashtirish

```python
# bildirishnoma_tizimi.py — barcha naqshlar birgalikda ishlaydi

sozlamalar = SozlamalarManageri()         # Singleton — bitta nusxa

bildirishnoma = (                           # Builder — qadam-baqadam qurish
    BildirishnomaBuilder()
    .qabul_qiluvchiga("ali@mail.uz")
    .mavzu_bilan("Buyurtmangiz jo'natildi")
    .matn_bilan("Buyurtma #4521 yetkazib berish xizmatiga topshirildi.")
    .ustuvorlik_bilan("yuqori")
    .qur()
)

yuboruvchi = BildirishnomaYuboruvchisi()
yuboruvchi.kuzatuvchi_qosh(LogKuzatuvchisi())             # Observer — obuna bo'lish
statistika = StatistikaKuzatuvchisi()
yuboruvchi.kuzatuvchi_qosh(statistika)

if sozlamalar.olish("sms_yoqilgan"):                        # Singleton'dagi sozlamaga qarab
    yuboruvchi.yubor(bildirishnoma, "sms", QisqaSMSStrategiyasi())     # Factory + Strategy

yuboruvchi.yubor(bildirishnoma, "email", HTMLStrategiyasi())            # Factory + Strategy

print(f"Jami yuborilgan bildirishnomalar: {statistika.yuborilgan_soni}")
# [SMS -> ali@mail.uz] Buyurtmangiz jo'natildi: Buyurtma #4521 yetkazib berish xizmatiga topshirild...
# [LOG] sms orqali 'Buyurtmangiz jo'natildi' yuborildi
# [EMAIL -> ali@mail.uz]
# <h2>Buyurtmangiz jo'natildi</h2><p>Buyurtma #4521 yetkazib berish xizmatiga topshirildi.</p>
#
# [LOG] email orqali 'Buyurtmangiz jo'natildi' yuborildi
# Jami yuborilgan bildirishnomalar: 2
```

### Har bir naqsh nega aynan shu yerda ishlatildi — yakuniy tahlil

- **Singleton** `SozlamalarManageri`da — chunki sozlama **butun dastuda bir xil** bo'lishi, va uni har joyda qayta-qayta "o'qish" (masalan, fayldan) emas, **bir marta** yuklab, hammaga ulashish kerak edi.
- **Builder** `Bildirishnoma`da — chunki obyekt **ko'p, ko'pincha ixtiyoriy** maydondan iborat edi, va zanjirli metodlar bilan qurish — `__init__`ga 6-7 argument berishdan ancha o'qilishi oson.
- **Factory Method** `KanalFabrikasi`da — chunki "qaysi kanal klassi ishlatilishi" qarori **bitta joyda** jamlanishi, va yangi kanal (masalan, Telegram) qo'shilganda faqat **shu bitta joy** o'zgarishi kerak edi (Open/Closed tamoyili — 1.2-darsda ko'rilgan).
- **Strategy** formatlash klasslarida — chunki bitta bildirishnoma **turli kontekstda turli formatda** (email uchun HTML, SMS uchun qisqartirilgan) ko'rsatilishi, va bu formatlash mantiqini asosiy yuborish mantiqidan **ajratib** qo'yish kerak edi.
- **Observer** kuzatuvchilarda — chunki "bildirishnoma yuborildi" voqeasiga **qiziqgan tomonlar soni oldindan noma'lum va o'zgaruvchan** edi (bugun log va statistika, ertaga audit ham qo'shilishi mumkin) — `BildirishnomaYuboruvchisi`ning o'zini o'zgartirmasdan, yangi kuzatuvchi qo'shish kifoya.

Bu — naqshlarni o'rganishning **asosiy maqsadi**: ular "shunchaki ishlatish uchun" emas, balki **har biri aniq bir muammoga aniq yechim** sifatida tanlanadi. Agar loyihada faqat bitta kanal, bitta format bo'lsa — Strategy va Factory Method **ortiqcha murakkablik** bo'lardi (1.1-darsda ko'rgan "ortiqcha muhandislik" ogohlantirishini eslang).

## Mashq/topshiriq

**(Oson)** `TelegramKanali` klassini qo'shing (`Kanal`dan meros oling) va `KanalFabrikasi._KANALLAR` lug'atiga `"telegram"` kaliti bilan qo'shing — qo'shimcha hech narsani o'zgartirmasdan ishlashi kerak.

**(O'rtacha)** `AuditKuzatuvchisi` nomli yangi Observer yozing — har bir yuborilgan bildirishnomani `(qabul_qiluvchi, kanal_nomi, mavzu)` tuple sifatida ichki ro'yxatga saqlab boradigan.

**(Qiyin)** `BildirishnomaBuilder`ga validatsiya qo'shing — `qur()` metodi chaqirilganda, agar `qabul_qiluvchi` yoki `matn` bo'sh bo'lsa, `ValueError` chiqarsin ("fail-fast" tamoyili — xatoni iloji boricha erta aniqlash). Bundan tashqari, `KanalFabrikasi`ga yangi `"sms"` kanali uchun — agar `SozlamalarManageri().olish("sms_yoqilgan")` `False` bo'lsa — `kanal_yarat("sms")` chaqirilganda `RuntimeError("SMS kanali o'chirilgan")` chiqaradigan tekshiruv qo'shing.

## Qisqacha xulosa

Real loyihalarda dizayn naqshlari **alohida-alohida, "ko'rsatish uchun"** emas, balki **bir-birini to'ldirib, bitta tizimning turli qatlamlarida** ishlaydi: Singleton — umumiy holatni markazlashtiradi, Builder — murakkab obyekt qurilishini soddalashtiradi, Factory Method — "qaysi klass yaratilishi" qarorini bitta joyga jamlaydi, Strategy — almashtirila oladigan algoritm/formatlash mantiqini ajratadi, Observer — voqea yuz berganda mustaqil tomonlarni xabardor qiladi; har bir naqshni tanlashning yagona to'g'ri mezoni — "bu yerda **aniq qaysi muammo** bor va bu naqsh uni qanday hal qiladi", aks holda naqshlarni o'rinsiz qo'llash kodni soddalashtirish o'rniga uni keraksiz murakkablashtiradi (over-engineering) — bu esa butun ushbu modul davomida takrorlangan eng muhim ogohlantirish bo'lib qoladi.
