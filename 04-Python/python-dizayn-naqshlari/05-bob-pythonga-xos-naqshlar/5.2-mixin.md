# Mixin naqshi

## Bu darsda nimalarni o'rganasiz

- Mixin nima ekanini va u "oddiy meros"dan nimasi bilan farq qilishini tushuntira olasiz
- O'z mixin klasslaringizni loyihalab, ularni boshqa klasslarga "qo'shib" qo'llay olasiz
- Ko'p meros (multiple inheritance) va MRO (Method Resolution Order, 9.2-darsda chuqur ko'rilgan) mixin bilan qanday bog'langanini bilasiz
- Mixin qachon foydali, qachon zararli (anti-pattern'ga aylanishi) bo'lishini ajrata olasiz
- Real loyihalarda (Django/DRF) mixinlar qanday ishlatilishini tasavvur qila olasiz

## Nazariy qism

### Mixin nima — "qo'shimcha qobiliyat" sifatida meros

4.2-darsda meros (inheritance) — "X — Y turi" (is-a) munosabatini ifodalash uchun ishlatilishini ko'rgansiz: `Mushuk(Hayvon)` — "Mushuk — Hayvon turi". **Mixin** — bu tamomila boshqa maqsadda ishlatiladigan meros turi: u "X — Y turi" emas, balki **"X — Y qobiliyatiga ham ega"** (can-do) degan munosabatni ifodalaydi.

Mixin — **mustaqil holda ishlatilishi mo'ljallanmagan**, faqat boshqa klasslarga **qo'shimcha, mustaqil funksionallik** "qo'shib qo'yish" uchun yaratiladigan kichik klass. U odatda:

- o'z holatini (instance state, `__init__`da saqlangan ma'lumot) deyarli saqlamaydi,
- faqat bir nechta metoddan iborat bo'ladi,
- hech qachon o'zi alohida obyekt sifatida yaratilmaydi (`MixinKlass()` deb chaqirilmaydi) — faqat boshqa klass bilan birga meros qilib olinadi.

```python
class LoglashMixin:
    """Istalgan klassga loglash qobiliyatini qo'shadi — mustaqil ishlatilmaydi."""

    def logla(self, xabar):
        sinf_nomi = self.__class__.__name__
        print(f"[{sinf_nomi}] {xabar}")


class Foydalanuvchi(LoglashMixin):
    def __init__(self, ism):
        self.ism = ism

    def kirish(self):
        self.logla(f"{self.ism} tizimga kirdi")   # LoglashMixin'dan meros qilingan metod


f = Foydalanuvchi("Ali")
f.kirish()
# [Foydalanuvchi] Ali tizimga kirdi
```

E'tibor bering: `Foydalanuvchi` — "Foydalanuvchi — LoglashMixin turi" emas (bu mantiqsiz bo'lardi), balki "Foydalanuvchi — loglash **qobiliyatiga ega**" degani.

### Mixin va oddiy meros — nomlash konvensiyasi

Python'da mixin klasslar odatda nomining oxiriga `Mixin` qo'shib belgilanadi (bu — til talabi emas, **konvensiya**, lekin kodni o'qishni ancha osonlashtiradi):

```python
class SerialallashMixin:
    """Obyektni dict'ga aylantirish qobiliyatini qo'shadi."""

    def dictga_aylantir(self):
        return {kalit: qiymat for kalit, qiymat in self.__dict__.items()
                if not kalit.startswith("_")}


class TaqqoslashMixin:
    """Obyektlarni atributlari bo'yicha solishtirish qobiliyatini qo'shadi."""

    def __eq__(self, boshqa):
        if not isinstance(boshqa, self.__class__):
            return NotImplemented
        return self.dictga_aylantir() == boshqa.dictga_aylantir()


class Mahsulot(SerialallashMixin, TaqqoslashMixin):
    def __init__(self, nomi, narxi):
        self.nomi = nomi
        self.narxi = narxi


m1 = Mahsulot("Noutbuk", 5000000)
m2 = Mahsulot("Noutbuk", 5000000)
print(m1.dictga_aylantir())    # {'nomi': 'Noutbuk', 'narxi': 5000000}
print(m1 == m2)                 # True — TaqqoslashMixin orqali, lekin dictga_aylantir SerialallashMixin'dan
```

Bu yerda `Mahsulot` ikki mustaqil mixin'dan **ikkita mustaqil qobiliyat**ni olib, ularni birlashtirib ishlatadi — bu mixinlarning asosiy kuchli tomoni: **kompozitsiyani meros orqali** (composition via inheritance) amalga oshirish.

### MRO — mixinlar bir nechta bo'lganda qanday ishlaydi

9.2-darsda (07-14-boblar, "CPython ich-ichiga") C3 linearizatsiya algoritmi orqali **MRO (Method Resolution Order)** qanday hisoblanishi chuqur ko'rilgan. Mixinlar ko'pincha **bir nechtadan birga** ishlatilgani uchun, qaysi metod birinchi topilishini bilish muhim:

```python
class AMixin:
    def salom(self):
        print("AMixin'dan salom")


class BMixin:
    def salom(self):
        print("BMixin'dan salom")


class Asosiy(AMixin, BMixin):      # tartib MUHIM — chapdan o'ngga qaraladi
    pass


Asosiy().salom()          # AMixin'dan salom — chunki AMixin ro'yxatda BIRINCHI
print(Asosiy.__mro__)
# (<class 'Asosiy'>, <class 'AMixin'>, <class 'BMixin'>, <class 'object'>)
```

**Qoida:** Python MRO'ni "chapdan o'ngga, pastdan yuqoriga" qidiradi — `class Asosiy(AMixin, BMixin)` yozilganda, `AMixin`ning metodlari `BMixin`nikidan **ustun turadi** (agar ikkalasida bir xil nomli metod bo'lsa). Shuning uchun mixin'larni meros ro'yxatida **tartib bilan** yozish kerak — bu ko'pincha "eng muhim/eng maxsus mixin birinchi" qoidasiga amal qiladi.

### `super()` bilan mixin'larni "zanjirlash"

Ba'zan bir nechta mixin **bir xil metodni** o'z hissasini qo'shib ishga tushirishi kerak bo'ladi (masalan, bir nechta `__init__` yoki bir nechta "tekshirish" qadami). Bunda har bir mixin o'z metodida `super()` chaqirib, zanjirni davom ettirishi kerak (3.2 va 4.2-darslarda ko'rgan `super()` tushunchasi):

```python
class VaqtniQoshuvchiMixin:
    def ma_lumot(self):
        natija = super().ma_lumot()         # zanjirdagi KEYINGI klassni chaqiradi
        return f"{natija} | vaqt: hozir"


class IDQoshuvchiMixin:
    def ma_lumot(self):
        natija = super().ma_lumot()
        return f"{natija} | id: {id(self)}"


class Asosiy:
    def ma_lumot(self):
        return "Asosiy ma'lumot"


class ToliqObyekt(VaqtniQoshuvchiMixin, IDQoshuvchiMixin, Asosiy):
    pass


obj = ToliqObyekt()
print(obj.ma_lumot())
# Asosiy ma'lumot | id: ... | vaqt: hozir
```

Bu yerda `super()` chaqiruvlar zanjiri MRO bo'yicha ketma-ket ishlaydi: `VaqtniQoshuvchiMixin.ma_lumot()` → `super().ma_lumot()` chaqiradi, bu — MRO'dagi keyingi klass, `IDQoshuvchiMixin.ma_lumot()`ni ishga tushiradi, u o'z navbatida `Asosiy.ma_lumot()`ni chaqiradi. Natija — **barcha** mixin'larning hissasi qo'shilgan yagona natija. Bu — mixin'larni to'g'ri loyihalashning eng muhim qoidasi: **har bir mixin metodi o'z ishini qilib, keyin `super()`ni chaqirishi kerak**, aks holda zanjir uzilib qoladi.

### Real hayotiy misol — Django/DRF'dagi mixinlar (tushuntirish sifatida)

Mixin naqshi — Django veb-freymvorkida (Django darsligida batafsil ko'riladi) juda keng qo'llaniladi. Masalan, Django'ning class-based view'larida `LoginRequiredMixin` nomli tayyor mixin mavjud:

```python
# BU — HAQIQIY KOD EMAS, faqat TUSHUNTIRISH uchun soxtalashtirilgan misol
class LoginRequiredMixin:
    """Foydalanuvchi tizimga kirmagan bo'lsa, sahifaga kirishni man etadi."""
    def dispatch(self, request, *args, **kwargs):
        if not request.foydalanuvchi.tizimga_kirgan:
            return "Login sahifasiga yo'naltirish"
        return super().dispatch(request, *args, **kwargs)


class ProfilSahifasi(LoginRequiredMixin, Sahifa):   # Sahifa — asosiy view klassi
    def get(self, request):
        return "Profil ma'lumotlari"
```

G'oya shunda: `LoginRequiredMixin` — bu "autentifikatsiya tekshiruvi" qobiliyatini **istalgan** sahifa klassiga bir qatorlik meros bilan qo'shib qo'yadi, kodni nusxalashga (copy-paste) hojat qolmaydi. Xuddi shunday, Django REST Framework (DRF, 08-Django va alohida API darsliklarida ko'riladi) `ListModelMixin`, `CreateModelMixin` kabi mixinlar orqali API'ning CRUD amallarini alohida-alohida, kerakli klasslarga birlashtirib qo'shish imkonini beradi.

## Amaliy misol

Turli "qobiliyat"larni (loglash, JSON serializatsiya, taqqoslash) mustaqil mixin'lar sifatida yozib, ularni bir nechta mutlaqo bog'liq bo'lmagan klassga qo'shamiz:

```python
# mixin_amaliy.py
import json
import time


class LoglashMixin:
    """Har qanday klassga avtomatik loglash qobiliyatini qo'shadi."""

    def logla(self, xabar):
        vaqt = time.strftime("%H:%M:%S")
        print(f"[{vaqt}] [{self.__class__.__name__}] {xabar}")


class JSONMixin:
    """Obyektni JSON formatiga aylantirish qobiliyatini qo'shadi."""

    def json_qil(self):
        ma_lumot = {kalit: qiymat for kalit, qiymat in self.__dict__.items()
                    if not kalit.startswith("_")}
        return json.dumps(ma_lumot, ensure_ascii=False)


class TaqqoslashMixin:
    """Ikki obyektni muhim atributlari bo'yicha solishtirish qobiliyatini qo'shadi."""

    SOLISHTIRISH_MAYDONLARI = ()      # har bir klass o'zi belgilaydi

    def __eq__(self, boshqa):
        if not isinstance(boshqa, self.__class__):
            return NotImplemented
        return all(
            getattr(self, maydon) == getattr(boshqa, maydon)
            for maydon in self.SOLISHTIRISH_MAYDONLARI
        )


class Buyurtma(LoglashMixin, JSONMixin, TaqqoslashMixin):
    SOLISHTIRISH_MAYDONLARI = ("buyurtma_id", "mahsulot")

    def __init__(self, buyurtma_id, mahsulot, narx):
        self.buyurtma_id = buyurtma_id
        self.mahsulot = mahsulot
        self.narx = narx
        self.logla(f"Buyurtma #{buyurtma_id} yaratildi")

    def tasdiqla(self):
        self.logla(f"Buyurtma #{self.buyurtma_id} tasdiqlandi")


class Foydalanuvchi(LoglashMixin, JSONMixin):      # TaqqoslashMixin kerak emas — olinmaydi
    def __init__(self, ism, email):
        self.ism = ism
        self.email = email
        self.logla(f"Foydalanuvchi {ism} ro'yxatdan o'tdi")


b1 = Buyurtma(101, "Noutbuk", 5000000)
# [12:30:01] [Buyurtma] Buyurtma #101 yaratildi
b1.tasdiqla()
# [12:30:01] [Buyurtma] Buyurtma #101 tasdiqlandi
print(b1.json_qil())
# {"buyurtma_id": 101, "mahsulot": "Noutbuk", "narx": 5000000}

b2 = Buyurtma(101, "Noutbuk", 4500000)      # narx boshqa, lekin solishtirish maydonlari bir xil
print(b1 == b2)    # True — chunki faqat buyurtma_id va mahsulot solishtiriladi

foyd = Foydalanuvchi("Dilnoza", "dilnoza@mail.uz")
# [12:30:01] [Foydalanuvchi] Foydalanuvchi Dilnoza ro'yxatdan o'tdi
print(foyd.json_qil())
# {"ism": "Dilnoza", "email": "dilnoza@mail.uz"}
```

Bu misol mixin'larning asosiy afzalligini ko'rsatadi: `Buyurtma` va `Foydalanuvchi` — biri-biri bilan **hech qanday aloqasi yo'q** ikki klass, lekin ular bir xil "qobiliyat"larni (loglash, JSON'ga aylanish) kodni nusxalamasdan, mustaqil mixin'lardan tanlab olib ishlatadi.

## Keng tarqalgan xatolar

**Xato 1:** mixin'ni mustaqil obyekt sifatida yaratishga urinish.

❌
```python
loglash = LoglashMixin()
loglash.logla("test")     # ishlaydi, lekin self.__class__.__name__ — 'LoglashMixin' bo'ladi, bu MA'NOSIZ
```
Mixin **hech qachon** o'zi mustaqil ishlatilishi uchun yaratilmagan — u faqat boshqa klassga "qo'shilgani"da to'liq ma'noga ega bo'ladi (chunki ko'pincha `self`ning boshqa, mixin'da yo'q atribut/metodlariga tayanadi).

✅ To'g'ri: mixin'ni har doim boshqa (asosiy) klass bilan birga meros qiling: `class Buyurtma(LoglashMixin): ...`.

**Xato 2:** meros ro'yxatida mixin'larning tartibini e'tiborsiz qoldirish.

❌
```python
class Asosiy(BazaKlass, LoglashMixin):     # BazaKlass BIRINCHI — bu odatda XATO!
    pass
```
Python konvensiyasi bo'yicha — va MRO mantiqiga ko'ra — mixin'lar odatda **asosiy (baza) klassdan OLDIN** yoziladi (`class Asosiy(LoglashMixin, BazaKlass)`), chunki MRO chapdan o'ngga qidirilganda, mixin'ning metodlari ustunlik qilishi (override qila olishi) kerak bo'ladi, aks holda ba'zi holatlarda `object`ning standart metodlari yoki baza klassning metodi mixin'dan oldin topilib, mixin kutilgan natijani bermaydi.

✅ To'g'ri: `class Asosiy(Mixin1, Mixin2, ..., BazaKlass)` tartibida yozing — mixinlar birinchi, asosiy funksional klass oxirida.

**Xato 3:** mixin ichida `super()`ni chaqirmasdan, zanjirni "uzib qo'yish".

❌
```python
class LoglashMixin:
    def ishla(self):
        print("Loglanmoqda...")
        # super().ishla() chaqirilmadi — zanjirdagi keyingi klasslar ISHGA TUSHMAYDI!


class Hisoblash:
    def ishla(self):
        print("Hisoblanmoqda...")


class Asosiy(LoglashMixin, Hisoblash):
    pass


Asosiy().ishla()   # faqat "Loglanmoqda..." chiqadi — "Hisoblanmoqda..." HECH QACHON chiqmaydi!
```
✅ To'g'ri: har bir mixin metodi oxirida (yoki kerakli joyida) `super().ishla()`ni chaqirishi kerak, shunda MRO zanjiridagi keyingi klassning metodi ham ishga tushadi (yuqoridagi "`super()` bilan mixin'larni zanjirlash" bo'limiga qarang).

## Mashq/topshiriq

**(Oson)** `Vaqt_BelgisiMixin` yozing — har qanday klassga `yaratilgan_vaqt` atributini (`__init__` chaqirilganda avtomatik `time.time()` bilan to'ldirilsin) va `necha_soniya_otdi()` metodini qo'shsin.

**(O'rtacha)** `TekshiruvMixin` yozing — `tekshir()` nomli metodga ega bo'lsin, u klassning `MAJBURIY_MAYDONLAR` nomli tuple-atributida ko'rsatilgan barcha atributlar `None` emasligini tekshirsin, agar biror maydon `None` bo'lsa `ValueError(f"{maydon} to'ldirilmagan")` chiqarsin.

**(Qiyin)** Ikki mustaqil mixin — `KirishChiqishniHisoblashMixin` (har bir metod chaqirilganda "kirish" va "chiqish" loglarini chop etadigan, lekin bu uchun klassning **barcha** metodlarini emas, faqat aniq bitta `bajar()` metodini o'rab oladigan) va `Vaqt_OlchashMixin` (`bajar()` metodining ishlash vaqtini o'lchaydigan) yozing — ikkisi birga ishlatilganda, `super()` zanjiri orqali ikkalasi ham to'g'ri ishlashi kerak.

## Qisqacha xulosa

Mixin — "X — Y turi" emas, balki "X — Y qobiliyatiga ega" munosabatini ifodalovchi, mustaqil ishlatilishi mo'ljallanmagan, faqat boshqa klasslarga qo'shimcha funksionallik "qo'shib qo'yish" uchun yozilgan kichik klass bo'lib, ko'p meros (multiple inheritance) va MRO (C3 linearizatsiya, 9.2-dars) orqali ishlaydi; mixinlar o'zaro mustaqil qobiliyatlarni (loglash, serializatsiya, taqqoslash kabi) kodni nusxalamasdan, turli, bir-biriga bog'liq bo'lmagan klasslarga ulash imkonini beradi, lekin to'g'ri ishlashi uchun meros ro'yxatidagi **tartib** va har bir metod ichida **`super()`ni chaqirish** qoidalariga qat'iy amal qilish shart — bu naqsh Django/DRF kabi real freymvorklarda class-based view'larga funksionallik qo'shishning asosiy usuli hisoblanadi.
