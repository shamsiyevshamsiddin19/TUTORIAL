# Adapter naqshi

## Bu darsda nimalarni o'rganasiz

- Adapter (moslashtiruvchi) naqshi qanday muammoni hal qilishini tushuntira olasiz
- Object Adapter va Class Adapter farqini bilasiz va Python'da nega aynan birinchisi afzal ko'rilishini tushunasiz
- O'zingizning uchinchi-tomon kutubxona uchun adapterni yoza olasiz
- Adapter naqshini Facade bilan adashtirmaysiz
- Python'dagi duck typing Adapterning zarurligini qanday kamaytirishini (lekin yo'q qilmasligini) bilasiz

## Nazariy qism

### Adapter nima — asosiy g'oya

**Adapter** — bir interfeysga ega bo'lgan obyektni, mijoz (client) kod kutayotgan **boshqa** interfeysga moslashtiruvchi "ko'prik" klass. Haqiqiy hayotdagi misol — sayohatga olib yuradigan elektr adapter: rozetka (interfeys) bir mamlakatda boshqacha, vilka (sizning qurilmangiz) boshqacha shaklda, va adapter ikkisini bir-biriga "moslashtiradi", ikkala tomonni ham o'zgartirmasdan.

Dasturlashda muammo odatda shunday paydo bo'ladi: sizda tayyor, ishlaydigan klass bor (masalan, uchinchi-tomon kutubxona yoki eski — legacy — kod), lekin uning metodlari nomi/signature'i sizning tizimingiz kutgan interfeysga mos kelmaydi. Klassning ichki kodini o'zgartirish imkonsiz (kutubxona kodi) yoki xavfli (legacy kod). Yechim — ikkisi orasiga **adapter** qo'yish.

```python
# Mijoz kodi faqat shu interfeysni biladi va kutadi:
class TolovInterfeysi:
    def tolovni_amalga_oshir(self, summa: float) -> bool:
        raise NotImplementedError
```

### Object Adapter — compozitsiya orqali moslashtirish

Tasavvur qiling, uchinchi-tomon kutubxona (masalan, `eski_bank_kutubxonasi`) bunday interfeysga ega — uni o'zgartira olmaysiz:

```python
# Bu — SIZ YOZMAGAN, o'zgartira olmaydigan uchinchi-tomon klass
class EskiBankAPI:
    def pul_otkazish(self, miqdor_tiyin: int, valyuta_kodi: str = "UZS") -> dict:
        print(f"[EskiBankAPI] {miqdor_tiyin} tiyin ({valyuta_kodi}) o'tkazildi")
        return {"status": "OK", "tranzaksiya_id": "TX-001"}
```

E'tibor bering: `EskiBankAPI.pul_otkazish` summa so'mda emas, **tiyinda** kutadi, va `bool` emas, `dict` qaytaradi — bizning `TolovInterfeysi.tolovni_amalga_oshir(summa) -> bool` bilan mos kelmaydi. **Object Adapter** — bu nomuvofiqlikni **compozitsiya** (adapter ichida eski klassning obyektini saqlash) orqali hal qiladi:

```python
class BankAdapter(TolovInterfeysi):
    """EskiBankAPI'ni TolovInterfeysi'ga moslashtiradi."""

    def __init__(self, eski_bank: EskiBankAPI) -> None:
        self._eski_bank = eski_bank          # compozitsiya — "HAS-A" munosabat

    def tolovni_amalga_oshir(self, summa: float) -> bool:
        tiyin = int(summa * 100)              # so'mni tiyinga aylantirish — moslashtirish
        natija = self._eski_bank.pul_otkazish(tiyin, valyuta_kodi="UZS")
        return natija["status"] == "OK"       # dict'ni bool'ga aylantirish — moslashtirish


# Mijoz kodi — faqat TolovInterfeysi'ni biladi, EskiBankAPI haqida hech narsa bilmaydi:
def tolov_qabul_qil(tolov: TolovInterfeysi, summa: float) -> None:
    if tolov.tolovni_amalga_oshir(summa):
        print("To'lov muvaffaqiyatli!")
    else:
        print("To'lov muvaffaqiyatsiz.")


adapter = BankAdapter(EskiBankAPI())
tolov_qabul_qil(adapter, 15000.50)
# [EskiBankAPI] 1500050 tiyin (UZS) o'tkazildi
# To'lov muvaffaqiyatli!
```

### Class Adapter — meros orqali moslashtirish (va nega Python'da kamroq ishlatiladi)

Klassik GoF kitobida yana bir variant bor — **Class Adapter**: adapter eski klassdan **meros oladi** (ko'p meros orqali), compozitsiya o'rniga:

```python
class BankClassAdapter(TolovInterfeysi, EskiBankAPI):
    def tolovni_amalga_oshir(self, summa: float) -> bool:
        tiyin = int(summa * 100)
        natija = self.pul_otkazish(tiyin)     # self orqali — meros qilingani uchun
        return natija["status"] == "OK"
```

Bu ishlaydi, lekin Python jamoasi **Object Adapter**ni afzal ko'radi, va buning aniq sabablari bor:

1. **Ko'p meros murakkabligi (MRO)** — 9.2-darsda ko'rgan C3 linearizatsiya bilan bog'liq muammolar (ismlarning to'qnashishi, metod aniqlanish tartibi) ko'p meros bilan tez ortib ketadi. Compozitsiya bunday muammolarni umuman keltirmaydi.
2. **Qattiq bog'lanish (tight coupling)** — Class Adapter kompilyatsiya/aniqlanish vaqtida `EskiBankAPI`ga "yopishib qoladi". Object Adapter esa runtime'da **istalgan** mos obyektni (hatto soxta/test uchun mock obyektni) qabul qilishi mumkin — bu test yozishni ancha osonlashtiradi.
3. **"Composition over inheritance" tamoyili** — bu nafaqat Adapterga, balki umuman OOP dizaynga tegishli umumiy tamoyil: imkon qadar meros emas, obyektlarni **tarkib** qilib ishlatish, chunki bu moslashuvchanlikni oshiradi va yashirin bog'liqliklarni kamaytiradi.

### Duck typing va Adapterning zarurligi

Python'da **duck typing** tufayli ("agar u o'rdakka o'xshab yurib, o'rdakka o'xshab g'ag'illasa — u o'rdak") ko'p hollarda Adapterga **umuman ehtiyoj yo'q**: agar uchinchi-tomon klassda kerakli metod nomi tasodifan to'g'ri bo'lsa, u hech qanday moslashtirishsiz ham ishlatiladi. Lekin bu Adapterni keraksiz qilmaydi — aksincha, Adapter aynan metod **nomlari va signature'lari mos kelmaganda** kerak bo'ladi (bizning yuqoridagi misolimizda `pul_otkazish` ≠ `tolovni_amalga_oshir`, va parametr birliklari ham farqli). Duck typing — Adapterni **yozish osonroq** qiladi (chunki rasmiy interfeys/`abc` majburiy emas), lekin uning zarurligini yo'qotmaydi.

### Qachon ishlatiladi — real hayotiy misollar

- **To'lov tizimlari** — turli to'lov provayderlarini (Click, Payme, Stripe) yagona `TolovInterfeysi` orqali ishlatish (yuqoridagi misol).
- **Ma'lumotlar bazasi drayverlari** — `sqlite3`, `psycopg2`, `pymysql` har xil interfeysga ega, lekin PEP 249 (DB-API 2.0) ularni **standartlashtiruvchi adapter-shaklidagi shartnoma** sifatida ishlaydi.
- **Legacy kodni yangi tizimga ulash** — eski modulni o'chirib qayta yozish xavfli bo'lganda, uning atrofiga adapter qo'yib, yangi kod bilan "tinch" ishlashini ta'minlash.
- **Uchinchi-tomon JSON API javobini o'z `dataclass`laringizga moslashtirish** — API javobi strukturasi o'zgarganda, faqat adapter qatlamini o'zgartirish kifoya, qolgan kod tegilmaydi.

## Amaliy misol

Ikki xil tashqi ob-havo API'sini (har biri turli formatda javob beradi) yagona interfeys orqali ishlatish:

```python
# obhavo_adapter.py
from __future__ import annotations
from dataclasses import dataclass
from abc import ABC, abstractmethod


@dataclass
class ObHavo:
    """Mijoz kodi kutgan, standartlashtirilgan ma'lumot shakli."""
    shahar: str
    harorat_selsiy: float
    namlik_foiz: int


class ObHavoManbai(ABC):
    @abstractmethod
    def ob_havoni_olish(self, shahar: str) -> ObHavo: ...


# --- Uchinchi-tomon API #1: Fahrenheytda, boshqa kalit nomlari bilan ---
class EskiAPIProvayder:
    def fetch_weather_data(self, city_name: str) -> dict:
        return {"city": city_name, "temp_f": 71.6, "humidity_pct": 45}


class EskiAPIAdapter(ObHavoManbai):
    def __init__(self, provayder: EskiAPIProvayder) -> None:
        self._provayder = provayder

    def ob_havoni_olish(self, shahar: str) -> ObHavo:
        xom = self._provayder.fetch_weather_data(shahar)
        harorat_s = (xom["temp_f"] - 32) * 5 / 9        # F -> C moslashtirish
        return ObHavo(shahar=xom["city"], harorat_selsiy=round(harorat_s, 1),
                      namlik_foiz=xom["humidity_pct"])


# --- Uchinchi-tomon API #2: XML-ga o'xshash ichma-ich lug'at bilan ---
class YangiAPIProvayder:
    def get_current_conditions(self, location: str) -> dict:
        return {"location": {"name": location},
                "readings": {"celsius": 22.3, "relative_humidity": 60}}


class YangiAPIAdapter(ObHavoManbai):
    def __init__(self, provayder: YangiAPIProvayder) -> None:
        self._provayder = provayder

    def ob_havoni_olish(self, shahar: str) -> ObHavo:
        xom = self._provayder.get_current_conditions(shahar)
        return ObHavo(shahar=xom["location"]["name"],
                      harorat_selsiy=xom["readings"]["celsius"],
                      namlik_foiz=xom["readings"]["relative_humidity"])


def ob_havoni_chop_et(manba: ObHavoManbai, shahar: str) -> None:
    oh = manba.ob_havoni_olish(shahar)
    print(f"{oh.shahar}: {oh.harorat_selsiy}°C, namlik {oh.namlik_foiz}%")


manbalar = [EskiAPIAdapter(EskiAPIProvayder()), YangiAPIAdapter(YangiAPIProvayder())]
for manba in manbalar:
    ob_havoni_chop_et(manba, "Toshkent")
# Toshkent: 22.0°C, namlik 45%
# Toshkent: 22.3°C, namlik 60%
```

Ikki butunlay boshqa formatdagi API ham mijoz kodi uchun **bir xil** ko'rinadi — mijoz kodi (`ob_havoni_chop_et`) hech qachon o'zgarmaydi, qaysi provayder ishlatilsa ham.

## Keng tarqalgan xatolar

**Xato 1:** Adapter ichida moslashtirish mantiqini emas, yangi biznes-logikani yozish.
❌ Adapter ichida yangi hisob-kitoblar, validatsiyalar yoki qoida qo'shish — bu Adapterning vazifasi emas.
✅ To'g'ri: Adapter FAQAT bir interfeysni ikkinchisiga "tarjima qiladi" (format, birlik, metod nomi). Biznes-logika mijoz kodida yoki alohida qatlamda bo'lishi kerak.

**Xato 2:** Class Adapter'ni (ko'p meros orqali) odatiy holatda ishlatish.
❌
```python
class Adapter(YangiInterfeys, EskiKlass):   # ko'p meros — MRO murakkabligi
    ...
```
✅ To'g'ri: Python'da deyarli har doim **Object Adapter** (compozitsiya) afzal — `self._eski = EskiKlass()` saqlab, metodlarni chaqirish orqali. Bu test yozishni osonlashtiradi va MRO muammolaridan qochadi.

**Xato 3:** Adapterni Facade bilan adashtirish.
❌ "Adapter — bu murakkab tizimni soddalashtiradigan narsa" deb tushunish.
✅ To'g'ri: Adapter — **bitta mavjud interfeysni boshqasiga moslashtiradi** (interfeyslar soni teng, shakli o'zgaradi). Facade — **ko'p sonli murakkab subtizimlar ustiga yangi, soddaroq interfeys qo'shadi** (keyingi darsda ko'ramiz). Adapter "tarjimon", Facade — "qisqartma yo'l".

## Mashq/topshiriq

**(Oson)** `Kvadrat` klassi faqat `tomoni` atributiga ega. `TortburchakInterfeysi` esa `uzunlik` va `kenglik` metodlarini kutadi. `KvadratAdapter` yozing — u `Kvadrat`ni shu interfeysga moslashtirsin (ikkisi ham `tomoni`ga teng bo'lsin).

**(O'rtacha)** Ikki xil log kutubxonasi bor: `EskiLogger.write_log(msg: str)` va `YangiLogger.log_event(level: str, message: str)`. `LoggerInterfeysi` (yagona metod: `xabar_yoz(matn: str)`) yarating va har ikkisi uchun adapter yozing, `YangiLogger` uchun `level="INFO"` bilan chaqiring.

**(Qiyin)** Uchta turli "shakl" klassi bor: `Doira(radius)` — `yuza()` metodi bilan, `EskiKvadrat(tomoni)` — `maydon_hisobla()` metodi bilan (boshqa nom!), `Uchburchak(asos, balandlik)` — `pin_yuza_metod(a, b)` statik funksiyasi bilan. Yagona `ShaklInterfeysi.yuzasi() -> float` interfeysiga barcha uchtasini moslashtiruvchi adapterlar yozing va ularni bitta ro'yxatda yig'ib, umumiy yuzalar yig'indisini chiqaring.

## Qisqacha xulosa

Adapter naqshi — mos kelmaydigan ikki interfeysni, mavjud kodni o'zgartirmasdan, "tarjimon" klass orqali bir-biriga moslashtiradi; Python'da bu deyarli har doim **Object Adapter** (compozitsiya, `self._eski_obyekt` saqlash) shaklida qilinadi, chunki u Class Adapter'ning ko'p meros murakkabliklaridan (MRO) qochadi va test yozishni osonlashtiradi; duck typing ba'zan Adapterga ehtiyojni kamaytiradi, lekin metod nomlari/signature'lari farqli bo'lganda u hali ham zarur; Adapterni Facade bilan adashtirmaslik kerak — Adapter mavjud interfeysni "tarjima qiladi", Facade esa butunlay yangi, soddalashtirilgan interfeys yaratadi.
