# Decorator naqshi va Python dekorator sintaksisi — farqi nimada?

## Bu darsda nimalarni o'rganasiz

- Klassik OOP **Decorator naqshi** (GoF) qanday ishlashini, obyektlarni runtime'da "o'rab" funksionallik qo'shishini tushuntira olasiz
- Python'ning `@` **dekorator sintaksisi** (5.4-darsda ko'rgan) bilan Decorator naqshi orasidagi **aniq farqni** tushunasiz: biri obyekt darajasida, ikkinchisi funksiya/klass darajasida ishlaydi
- Nega ikkisi "decorator" deb atalishini, lekin ular bir xil narsa emasligini bilasiz
- Decorator naqshini meros (inheritance) o'rniga qachon ishlatishni bilasiz
- Ikki yondashuvni to'g'ri tanlay olasiz: qachon klassik OOP Decorator, qachon Python `@` sintaksisi

## Nazariy qism

### Chalkashlikning ildizi — bitta so'z, ikki xil tushuncha

Dasturlashda "decorator" (dekorator) so'zi **ikki butunlay boshqa narsani** anglatadi, va bu — yangi boshlovchilar uchun eng ko'p chalkashlik keltiradigan joylardan biri:

1. **Decorator naqshi (Design Pattern)** — 1994-yilgi "Gang of Four" kitobidan kelib chiqqan, **OOP tuzilma naqshi**: bir obyektni boshqa obyekt (ham bir xil interfeysga ega) ichiga "o'rab", **runtime'da** unga yangi xatti-harakat qo'shish.
2. **Python `@` dekorator sintaksisi** — 5.4-darsda batafsil ko'rgan, **til darajasidagi funksiya** (yoki klass) ustiga `@nom` yozib, uni **boshqa funksiyaga almashtirish** mexanizmi — asosan **closure** tamoyiliga asoslangan.

Ikkisi orasidagi bog'liqlik — **g'oyaviy o'xshashlik**: ikkisi ham "mavjud narsani o'zgartirmasdan, uni o'rab, kengaytirish" tamoyiliga asoslangan ("composition over inheritance" / "wrapping"). Lekin ular **boshqa darajada, boshqa mexanizm bilan** ishlaydi. Keling, ularni alohida-alohida chuqur ko'rib, keyin to'g'ridan-to'g'ri taqqoslaymiz.

### Decorator naqshi (OOP) — obyektlarni runtime'da o'rash

**Muammo:** `Qahva` klassiga "Sut qo'shilgan", "Shakar qo'shilgan", "Shokolad qo'shilgan" kabi variantlarni qo'shish kerak — va ular **ixtiyoriy kombinatsiyalarda** (sut+shakar, faqat shokolad, sut+shakar+shokolad...) bo'lishi mumkin. Agar meros (inheritance) orqali yechsak:

```python
# YOMON yondashuv — meros orqali, kombinatsiyalar SONI PORTLAYDI
class Qahva: ...
class SutliQahva(Qahva): ...
class ShakarliQahva(Qahva): ...
class SutliShakarliQahva(Qahva): ...          # va h.k. — N qo'shimcha uchun 2^N klass kerak bo'ladi!
```

**Yechim — Decorator naqshi:** har bir "qo'shimcha" alohida klass bo'lib, u **asl obyektni o'z ichiga oladi** (compozitsiya) va **bir xil interfeysni** taqdim etadi, shunda uni yana boshqa Decoratorga o'rash mumkin:

```python
from abc import ABC, abstractmethod


class Ichimlik(ABC):                 # Component — umumiy interfeys
    @abstractmethod
    def narxi(self) -> float: ...

    @abstractmethod
    def tasvir(self) -> str: ...


class Qahva(Ichimlik):                # Concrete Component — "yalang'och" asl obyekt
    def narxi(self) -> float:
        return 12_000

    def tasvir(self) -> str:
        return "Qahva"


class IchimlikDekoratori(Ichimlik):   # Decorator bazaviy klassi — HAM Ichimlik, HAM ichida Ichimlik saqlaydi
    def __init__(self, ichimlik: Ichimlik) -> None:
        self._ichimlik = ichimlik     # runtime'da O'RALADIGAN obyekt

    def narxi(self) -> float:
        return self._ichimlik.narxi()

    def tasvir(self) -> str:
        return self._ichimlik.tasvir()


class SutQoshish(IchimlikDekoratori):          # Concrete Decorator #1
    def narxi(self) -> float:
        return super().narxi() + 3_000          # asl narxga QO'SHIMCHA qiladi

    def tasvir(self) -> str:
        return super().tasvir() + " + sut"


class ShakarQoshish(IchimlikDekoratori):       # Concrete Decorator #2
    def narxi(self) -> float:
        return super().narxi() + 1_000

    def tasvir(self) -> str:
        return super().tasvir() + " + shakar"


# RUNTIME'DA, ixtiyoriy kombinatsiyada, dinamik ravishda "o'rash":
oddiy_qahva = Qahva()
print(oddiy_qahva.tasvir(), "—", oddiy_qahva.narxi())
# Qahva — 12000

murakkab_qahva = ShakarQoshish(SutQoshish(Qahva()))      # ikkita decorator ZANJIR qilindi
print(murakkab_qahva.tasvir(), "—", murakkab_qahva.narxi())
# Qahva + sut + shakar — 16000
```

Bu yerda **asosiy g'oya**: `murakkab_qahva` — bu uchta ICHMA-ICH joylashgan OBYEKT (`ShakarQoshish` obyekti → ichida `SutQoshish` obyekti → ichida `Qahva` obyekti). Har bir `narxi()` chaqiruvi — zanjir bo'ylab **rekursiv** ravishda ichkariga, so'ng tashqariga chiqadi (bu — 3.3-darsdagi Composite naqshidagi rekursiyaga juda o'xshash tuzilma!). Kombinatsiyalar soni endi meros bilan emas, **runtime'da qaysi Decorator'larni qaysi tartibda chaqirish** bilan boshqariladi — bu ancha moslashuvchan.

### Python `@` dekorator sintaksisi — funksiyalarni o'rash (eslatma)

5.4-darsda ko'rganingizdek, Python dekoratori — funksiyani (yoki klassni) qabul qilib, **yangi funksiya** (odatda closure) qaytaruvchi oddiy funksiya, xolos:

```python
from functools import wraps

def vaqtni_olchash(funksiya):
    @wraps(funksiya)
    def orash(*args, **kwargs):
        import time
        boshlanish = time.time()
        natija = funksiya(*args, **kwargs)
        print(f"{funksiya.__name__}: {time.time() - boshlanish:.4f}s")
        return natija
    return orash


@vaqtni_olchash
def hisobla(n):
    return sum(range(n))
```

Bu yerda `hisobla = vaqtni_olchash(hisobla)` — bir marta, **funksiya ta'rifi vaqtida** (ya'ni modul import qilinganda, bir marta) bajariladi. Natija — `hisobla` nomi endi `orash` funksiyasiga ishora qiladi.

### To'g'ridan-to'g'ri taqqoslash jadvali

| Jihat | Decorator naqshi (OOP) | Python `@` dekorator sintaksisi |
|---|---|---|
| Nimani o'raydi | **Obyektlarni** (klass instance'larini) | **Funksiyalarni** (yoki klasslarni) |
| Qachon qo'llaniladi | **Runtime'da**, xohlagan vaqtda, dinamik ravishda (`SutQoshish(Qahva())`) | Odatda **funksiya/klass ta'rifi vaqtida** (bir marta, moduldagi `@` qatori orqali) |
| Mexanizm | Compozitsiya + umumiy interfeys (meros orqali) | Closure (yopilish) — funksiyani funksiyaga o'rab, yangisini qaytarish |
| Kombinatsiya qanday qurilgan | Obyektlarni ICHMA-ICH yaratish: `A(B(C()))` | Bir nechta `@` qator-qator yozish: `@a` `@b` `def f()` |
| Tipik ishlatilishi | Bitta obyektga, turli shartlarda, turli funksionallik "qatlamlarini" qo'shish (UI komponentlar, stream'lar) | Funksiyaga doimiy, qayta ishlatiladigan xatti-harakat qo'shish (loglash, keshlash, ruxsat tekshirish) |
| Klassik misoli | Java'dagi `java.io` stream klasslari (`BufferedInputStream(FileInputStream(...))`) | `@property`, `@staticmethod`, `@lru_cache`, `@app.route` (Flask) |

### Qiziqarli nozik joy — Python klasslarga ham `@` qo'llash mumkin

Chalkashlikni yanada chuqurlashtiruvchi joy shu — Python'da **klass dekoratorlari** ham bor, ular klassning o'ziga `@` orqali qo'llaniladi:

```python
def singleton(klass):
    """Klass dekoratori — klassni Singleton'ga aylantiradi (keyingi bobda chuqur ko'ramiz)."""
    nusxalar = {}
    @wraps(klass, updated=[])
    def olish(*args, **kwargs):
        if klass not in nusxalar:
            nusxalar[klass] = klass(*args, **kwargs)
        return nusxalar[klass]
    return olish


@singleton
class Sozlamalar:
    def __init__(self):
        print("Sozlamalar yuklanmoqda...")


s1 = Sozlamalar()    # Sozlamalar yuklanmoqda...
s2 = Sozlamalar()    # (chiqish yo'q — allaqachon yaratilgan nusxa qaytarildi)
print(s1 is s2)       # True
```

Bu — Python `@` sintaksisining klassga qo'llanilishi, lekin **u hali ham OOP Decorator naqshi EMAS!** Chunki bu yerda `singleton` — klassni **almashtiradigan** (funksiya bilan!) oddiy funksiya, u obyektni "o'rab", bir xil interfeysga ega yangi obyekt yaratmaydi — u butunlay boshqa mexanizm (yopiq lug'at + closure) orqali ishlaydi. Shu sabab, "bu klass ustiga `@` qo'yilgan, demak bu Decorator naqshi" degan xulosa — **noto'g'ri**.

### Qachon qaysi birini tanlash

- **Python `@` sintaksisi** — agar sizga **funksiyalar** uchun, **ta'rif vaqtida** o'rnatiladigan, (ko'pincha) **shartsiz** qo'llaniladigan xatti-harakat kerak bo'lsa: loglash, vaqt o'lchash, keshlash, ruxsat tekshirish, retry.
- **Decorator naqshi (OOP)** — agar sizga **obyektlarga**, **runtime'da**, **dinamik va shartli** ravishda (foydalanuvchi tanloviga, konfiguratsiyaga qarab) turli "qatlamlar" qo'shish kerak bo'lsa, va bu qatlamlar **ixtiyoriy tartibda, ixtiyoriy sonda** birlashtirilishi kerak bo'lsa (masalan, UI komponentlarga chegara, scroll, soya qo'shish — foydalanuvchi interfeysni runtime'da o'zgartirganda).

Amalda, Python ekotizimida **sof OOP Decorator naqshi** nisbatan kamroq uchraydi, chunki ko'p holatlarda uning vazifasini **funksional dekoratorlar + compozitsiya** osonroq bajaradi. Lekin katta GUI freymvorklari (masalan, `tkinter` emas, balki Java Swing'dan kelib chiqqan g'oyalar) va stream-asosli API'larda (fayl/tarmoq oqimlarini "qatlamalash") OOP Decorator hali ham tabiiy yechim bo'lib qoladi.

## Amaliy misol

Ikkala yondashuvni **bir vazifa** (so'rovni qayta ishlashda qo'shimcha funksiyalar qo'shish) ustida yonma-yon ko'rsatish:

```python
# ikki_dekorator_uslubi.py
from functools import wraps
from abc import ABC, abstractmethod


# ====== 1-USLUB: Python @ sintaksisi — FUNKSIYA uchun, ta'rif vaqtida ======
def logla(funksiya):
    @wraps(funksiya)
    def orash(*args, **kwargs):
        print(f"[LOG] {funksiya.__name__} chaqirildi")
        return funksiya(*args, **kwargs)
    return orash


def vaqt_olchash(funksiya):
    @wraps(funksiya)
    def orash(*args, **kwargs):
        import time
        t0 = time.time()
        natija = funksiya(*args, **kwargs)
        print(f"[VAQT] {time.time() - t0:.6f}s")
        return natija
    return orash


@logla
@vaqt_olchash
def sorovni_qayta_ishla(sorov: str) -> str:
    return sorov.upper()


sorovni_qayta_ishla("salom")
# [LOG] sorovni_qayta_ishla chaqirildi
# [VAQT] 0.000002s


# ====== 2-USLUB: OOP Decorator naqshi — OBYEKT uchun, runtime'da, dinamik ======
class SorovIshlovchi(ABC):
    @abstractmethod
    def ishla(self, sorov: str) -> str: ...


class AsosiyIshlovchi(SorovIshlovchi):
    def ishla(self, sorov: str) -> str:
        return sorov.upper()


class IshlovchiDekoratori(SorovIshlovchi):
    def __init__(self, ishlovchi: SorovIshlovchi) -> None:
        self._ishlovchi = ishlovchi

    def ishla(self, sorov: str) -> str:
        return self._ishlovchi.ishla(sorov)


class LogDekoratori(IshlovchiDekoratori):
    def ishla(self, sorov: str) -> str:
        print(f"[LOG] so'rov qabul qilindi: {sorov}")
        return super().ishla(sorov)


class VaqtDekoratori(IshlovchiDekoratori):
    def ishla(self, sorov: str) -> str:
        import time
        t0 = time.time()
        natija = super().ishla(sorov)
        print(f"[VAQT] {time.time() - t0:.6f}s")
        return natija


# RUNTIME'DA — foydalanuvchi sozlamasiga qarab, qaysi dekoratorlar kerak bo'lishi DINAMIK aniqlanadi:
foydalanuvchi_sozlamasi = {"log_yoqilgan": True, "vaqt_olchash_yoqilgan": True}

ishlovchi: SorovIshlovchi = AsosiyIshlovchi()
if foydalanuvchi_sozlamasi["vaqt_olchash_yoqilgan"]:
    ishlovchi = VaqtDekoratori(ishlovchi)        # faqat runtime'da, SHART bajarilsa, qo'shiladi
if foydalanuvchi_sozlamasi["log_yoqilgan"]:
    ishlovchi = LogDekoratori(ishlovchi)

print(ishlovchi.ishla("salom"))
# [LOG] so'rov qabul qilindi: salom
# [VAQT] 0.000001s
# SALOM
```

Bu misol farqni aniq ko'rsatadi: **1-uslub** — `@logla`/`@vaqt_olchash` yozilgan funksiya har doim shu ikki xususiyatga ega (kod yozilganda belgilanadi, o'zgarmas). **2-uslub** — qaysi "dekoratorlar" (OOP ma'noda) qo'llanilishi **runtime'da, `if` shartlari orqali, dinamik** hal qilinadi — foydalanuvchi sozlamasi o'zgarsa, kod qayta yozilmasdan, boshqa kombinatsiya hosil bo'ladi.

## Keng tarqalgan xatolar

**Xato 1:** "Decorator naqshi" va "Python `@` dekorator" atamalarini sinonim deb ishlatish.
❌ Suhbatda/kodda "men decorator pattern ishlataman" deb, aslida oddiy `@decorator_funksiya` yozilgan funksiyani nazarda tutish.
✅ To'g'ri: atamalarni aniq ajrating — "Decorator naqshi" (OOP, obyektlarni o'rash) va "dekorator sintaksisi"/"funksional dekorator" (Python `@`, funksiyalarni o'rash) alohida tushunchalar.

**Xato 2:** OOP Decorator naqshida bazaviy `IchimlikDekoratori` klassida `super().metod()`ni chaqirishni unutib qo'yish.
❌
```python
class SutQoshish(IchimlikDekoratori):
    def narxi(self) -> float:
        return 3_000      # faqat QO'SHIMCHA narxni qaytaryapti, ICHKARIDAGI ichimlik narxi YO'QOLDI!
```
✅ To'g'ri: har doim `super().narxi() + qoshimcha` ko'rinishida yozing — aks holda zanjirdagi oldingi "qatlamlar" natijasi butunlay yo'qoladi.

**Xato 3:** Python `@` sintaksisidan OOP Decorator naqshi kerak bo'lgan joyda foydalanishga urinish — ya'ni runtime'da, foydalanuvchi tanloviga qarab, dinamik "qatlamlar" yig'ishga harakat qilish.
❌
```python
# Runtime'da qaysi dekorator kerakligini bilmasdan, "@" sintaksisi bilan QURISHGA urinish — BU ISHLAMAYDI,
# chunki @ faqat funksiya TA'RIFI vaqtida, bir marta qo'llaniladi, keyin o'zgartirib bo'lmaydi.
```
✅ To'g'ri: agar sizga runtime'da, shartlarga qarab, dinamik ravishda turli kombinatsiyalarda funksionallik qo'shish kerak bo'lsa — bu aynan OOP Decorator naqshining (obyektlarni ichma-ich yaratish) vazifasi, Python `@` sintaksisi bunga mos emas.

## Mashq/topshiriq

**(Oson)** `Pizza` klassi (`narxi() -> 25000`) va uning ustiga `QoShimchaIngredient` bazaviy Decorator klassi yordamida `PishloqQoshish` (+5000) va `KolbasaQoshish` (+8000) yozing. Ikkisini birlashtirib (`KolbasaQoshish(PishloqQoshish(Pizza()))`), yakuniy narxni chiqaring.

**(O'rtacha)** Python `@` sintaksisi bilan `@ishonchlilik_tekshiruvi` dekoratorini yozing — u funksiya argumentlaridan birortasi `None` bo'lsa, funksiyani chaqirmasdan `ValueError`ni chiqarsin. Shu dekoratorni istalgan funksiyaga qo'llab sinab ko'ring.

**(Qiyin)** `Matn` klassi (`chiqar() -> str`, oddiy matnni qaytaradi) uchun OOP Decorator naqshi yordamida ikkita dekorator yozing: `KattaHarflarga` (matnni `.upper()` qiladi) va `Qavs_Ichida` (matnni `[...]` ichiga oladi). Ularni IKKI XIL TARTIBDA birlashtiring (`KattaHarflarga(Qavs_Ichida(Matn()))` va `Qavs_Ichida(KattaHarflarga(Matn()))`) va natijalar nega farq qilishini (tartib muhimligini) tushuntiring.

def ishonchlilik_tekshiruvi(funksiya):

## Qisqacha xulosa

"Decorator" so'zi Python dunyosida ikki butunlay boshqa tushunchani anglatadi: klassik **OOP Decorator naqshi** — obyektlarni compozitsiya orqali, bir xil interfeys saqlab, runtime'da ichma-ich "o'rab", dinamik va shartli ravishda yangi xatti-harakat qo'shish usuli (meros portlashining oldini oladi); Python **`@` dekorator sintaksisi** (5.4-darsda ko'rilgan) — funksiyalarni (yoki klasslarni) closure orqali, ta'rif vaqtida, bir marta o'zgartiruvchi til mexanizmi. Ikkisi g'oyaviy jihatdan ("mavjud narsani o'ramasdan kengaytirish") qarindosh, lekin mexanizmi, qo'llanilish vaqti va moslashuvchanlik darajasi butunlay farq qiladi — shu farqni aniq bilish, ayniqsa suhbatlarda va kod sharhlarida (code review) chalkashlikni oldini oladi.
