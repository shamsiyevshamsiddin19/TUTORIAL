# Facade naqshi

## Bu darsda nimalarni o'rganasiz

- Facade naqshi qanday muammoni (murakkablikni yashirish) hal qilishini tushuntira olasiz
- Murakkab subtizimlar ustiga sodda, yagona kirish nuqtasini loyihalay olasiz
- Facade'ni Adapter'dan aniq farqlay olasiz
- Facade qanday qilib modullar orasidagi bog'liqlikni (coupling) kamaytirishini bilasiz
- Facade'ning kamchiliklarini ("god object" xavfi) tushunasiz

## Nazariy qism

### Facade nima — asosiy g'oya

**Facade** (fransuzcha "bino peshtoqi" degani) — bir nechta murakkab, ko'p sonli klass va metodlardan iborat **subtizim** (subsystem) ustiga qo'yiladigan, **sodda va yagona** interfeys beruvchi klass. Mijoz kodi subtizimning ichki tuzilishi, klasslari soni yoki ular orasidagi chaqiriqlar tartibi haqida hech narsa bilishi shart emas — u faqat Facade'ning bir-ikki metodini chaqiradi, xolos.

Real hayotiy o'xshatish: restoran ofitsianti — siz oshxonada nechta oshpaz ishlashini, taomlar qanday tartibda tayyorlanishini bilishingiz shart emas; siz ofitsiantga (Facade) "Osh buyuraman" deysiz, qolgan murakkablikni u "yashiradi".

### Muammo — Facade'siz kod qanday ko'rinadi

Tasavvur qiling, video konvertatsiya tizimi bor — unda bir nechta mustaqil subtizim klasslari ishlaydi:

```python
class VideoFayl:
    def __init__(self, nomi: str) -> None:
        self.nomi = nomi

class KodekAniqlagich:
    def kodekni_aniqla(self, fayl: VideoFayl) -> str:
        print(f"[Kodek] {fayl.nomi} uchun kodek aniqlanmoqda...")
        return "h264"

class VideoKonverter:
    def konvert_qil(self, fayl: VideoFayl, kodek: str, format: str) -> bytes:
        print(f"[Konverter] {kodek} -> {format} ga o'tkazilmoqda...")
        return b"video-bytes"

class AudioMikser:
    def audio_ajrat(self, fayl: VideoFayl) -> bytes:
        print(f"[Audio] {fayl.nomi}dan audio ajratilmoqda...")
        return b"audio-bytes"

class FaylSaqlagich:
    def saqla(self, nomi: str, malumot: bytes) -> None:
        print(f"[Saqlash] {nomi} ({len(malumot)} bayt) saqlandi")
```

Mijoz kodi bularning HAMMASINI to'g'ri tartibda, to'g'ri parametrlar bilan chaqirishi kerak bo'ladi — bu mijoz kodini subtizim ichki detallariga **qattiq bog'laydi** (tight coupling):

```python
# Facade'siz — mijoz subtizim haqida HAMMA narsani bilishi kerak
fayl = VideoFayl("dars.mov")
kodek = KodekAniqlagich().kodekni_aniqla(fayl)
video = VideoKonverter().konvert_qil(fayl, kodek, "mp4")
audio = AudioMikser().audio_ajrat(fayl)
FaylSaqlagich().saqla("dars.mp4", video)
FaylSaqlagich().saqla("dars_audio.mp3", audio)
```

### Yechim — Facade qatlami

```python
class VideoKonvertatsiyaFacade:
    """Butun subtizim ustidagi YAGONA, sodda kirish nuqtasi."""

    def __init__(self) -> None:
        # Facade subtizimning BARCHA qismlarini o'z ichida yashiradi
        self._kodek_aniqlagich = KodekAniqlagich()
        self._konverter = VideoKonverter()
        self._audio_mikser = AudioMikser()
        self._saqlagich = FaylSaqlagich()

    def mp4ga_aylantir(self, manba_fayl_nomi: str, natija_fayl_nomi: str) -> None:
        fayl = VideoFayl(manba_fayl_nomi)
        kodek = self._kodek_aniqlagich.kodekni_aniqla(fayl)
        video = self._konverter.konvert_qil(fayl, kodek, "mp4")
        audio = self._audio_mikser.audio_ajrat(fayl)
        self._saqlagich.saqla(natija_fayl_nomi, video)
        self._saqlagich.saqla(natija_fayl_nomi.replace(".mp4", "_audio.mp3"), audio)


# Mijoz kodi — ENDI faqat BITTA chaqiriqni biladi:
facade = VideoKonvertatsiyaFacade()
facade.mp4ga_aylantir("dars.mov", "dars.mp4")
```

Mijoz kodi endi `KodekAniqlagich`, `VideoKonverter`, `AudioMikser` haqida **hech narsa bilmaydi** — bu klasslar ichki, Facade orqasida yashiringan. Agar ertaga subtizimga to'rtinchi qadam (masalan, subtitr qo'shish) qo'shilsa, faqat Facade ichidagi `mp4ga_aylantir` o'zgaradi, mijoz kodi esa **bir qatorni ham o'zgartirmaydi**.

### Facade subtizimni yashirmaydi, faqat soddalashtiradi

Muhim nozik joy: Facade subtizim klasslariga **to'g'ridan-to'g'ri kirishni taqiqlamaydi** — xohlagan mijoz hali ham `VideoKonverter()`ni to'g'ridan-to'g'ri chaqira oladi, agar unga aniq nazorat kerak bo'lsa. Facade shunchaki **qo'shimcha, qulay yo'l** taqdim etadi, u yagona yo'l emas. Bu Facade'ni, masalan, Proxy'dan farqlaydi — Proxy ko'pincha asl obyektga **to'g'ridan-to'g'ri kirishni nazorat qiladi/cheklaydi**.

### Real hayotiy misollar

- **Django ORM** — `User.objects.filter(...)` bir qatorli chaqiriq ortida SQL so'rov qurish, bog'lanish pool'ini boshqarish, natijalarni obyektlarga aylantirish kabi o'nlab murakkab qadamlar yashiringan — bu butun ORM katta Facade hisoblanadi.
- **`requests` kutubxonasi** — `requests.get(url)` ortida TCP ulanish, DNS so'rov, SSL handshake, HTTP protokoli, header'larni qurish kabi murakkablik yashiringan.
- **Kompilyatorlar/`subprocess.run()`** — `subprocess.run(["ls"])` — bu `fork()`, `exec()`, pipe boshqarish, signal ishlov berish kabi operatsion tizim darajasidagi murakkab ishlarni yashiradigan Facade.
- **Mikroservislar arxitekturasida "API Gateway"** — bir nechta ichki mikroservisga bitta tashqi so'rov nuqtasi orqali murojaat qilish — bu ham Facade g'oyasining tarmoq darajasidagi ko'rinishi.

## Amaliy misol

Onlayn-do'kon buyurtma tizimi — inventar, to'lov va yetkazib berish subtizimlarini birlashtiruvchi Facade:

```python
# buyurtma_facade.py
from dataclasses import dataclass, field


class Inventar:
    def __init__(self) -> None:
        self._mahsulotlar = {"noutbuk": 5, "sichqoncha": 20}

    def mavjudligini_tekshir(self, mahsulot: str, miqdor: int) -> bool:
        bor = self._mahsulotlar.get(mahsulot, 0) >= miqdor
        print(f"[Inventar] {mahsulot} x{miqdor} — {'mavjud' if bor else 'YETARLI EMAS'}")
        return bor

    def ayirish(self, mahsulot: str, miqdor: int) -> None:
        self._mahsulotlar[mahsulot] -= miqdor
        print(f"[Inventar] {mahsulot} dan {miqdor} ta ayirildi")


class TolovTizimi:
    def tolovni_ol(self, karta_raqami: str, summa: float) -> bool:
        print(f"[To'lov] {karta_raqami[-4:]} kartadan {summa:,.0f} so'm yechib olindi")
        return True


class YetkazibBerish:
    def jonatish_yarat(self, manzil: str) -> str:
        tracking_id = "YB-2026-0042"
        print(f"[Yetkazish] '{manzil}' manziliga jo'natma yaratildi: {tracking_id}")
        return tracking_id


@dataclass
class BuyurtmaNatijasi:
    muvaffaqiyatli: bool
    xabar: str
    tracking_id: str | None = None


class BuyurtmaFacade:
    """Mijoz uchun yagona nuqta: butun buyurtma jarayonini bitta metodga yashiradi."""

    def __init__(self) -> None:
        self._inventar = Inventar()
        self._tolov = TolovTizimi()
        self._yetkazish = YetkazibBerish()

    def buyurtma_ber(self, mahsulot: str, miqdor: int, narx: float,
                      karta: str, manzil: str) -> BuyurtmaNatijasi:
        if not self._inventar.mavjudligini_tekshir(mahsulot, miqdor):
            return BuyurtmaNatijasi(False, "Mahsulot omborda yetarli emas")

        if not self._tolov.tolovni_ol(karta, narx * miqdor):
            return BuyurtmaNatijasi(False, "To'lov amalga oshmadi")

        self._inventar.ayirish(mahsulot, miqdor)
        tracking_id = self._yetkazish.jonatish_yarat(manzil)
        return BuyurtmaNatijasi(True, "Buyurtma muvaffaqiyatli qabul qilindi", tracking_id)


# Mijoz kodi — uch xil subtizim haqida hech narsa bilmaydi:
do_kon = BuyurtmaFacade()
natija = do_kon.buyurtma_ber("noutbuk", 1, 8_500_000, "8600123456789012", "Toshkent, Chilonzor")
print(natija)
# [Inventar] noutbuk x1 — mavjud
# [To'lov] 9012 kartadan 8,500,000 so'm yechib olindi
# [Inventar] noutbuk dan 1 ta ayirildi
# [Yetkazish] 'Toshkent, Chilonzor' manziliga jo'natma yaratildi: YB-2026-0042
# BuyurtmaNatijasi(muvaffaqiyatli=True, xabar='Buyurtma muvaffaqiyatli qabul qilindi', tracking_id='YB-2026-0042')
```

## Keng tarqalgan xatolar

**Xato 1:** Facade'ni Adapter bilan adashtirish.
❌ "Facade — mavjud interfeysni boshqa shaklga keltiradi" deb o'ylash.
✅ To'g'ri: Adapter — **bir** interfeysni boshqa **bir** interfeysga moslashtiradi (1-ga-1). Facade — **ko'p** sonli klass/metodni **bitta yangi, soddalashtirilgan** interfeys ortiga yig'adi (ko'p-ga-1). Facade yangi interfeys **ixtiro qiladi**, Adapter esa mavjudini **tarjima qiladi**.

**Xato 2:** Facade'ni "god object"ga (hamma narsani biladigan, hamma narsani qiladigan ulkan klass) aylantirish.
❌ Facade ichiga asta-sekin biznes-logika, validatsiya, hatto ma'lumotlar bazasi so'rovlarini to'g'ridan-to'g'ri yozib, u 1000+ qatorli "hamma narsa qiluvchi" klassga aylanib qolishi.
✅ To'g'ri: Facade faqat **chaqiriqlarni to'g'ri tartibda yo'naltiruvchi "dirijyor"** bo'lishi kerak — haqiqiy mantiq subtizim klasslarida qolishi lozim. Facade yupqa (thin) qatlam bo'lib qolsin.

**Xato 3:** Mijoz kodga Facade orqasidagi klasslarga to'g'ridan-to'g'ri murojaat qilishni butunlay man etish deb o'ylash.
❌ Facade subtizim klasslarini `private`/yashirin qilib, hech kimga kirish imkonini bermaslik kerak deb o'ylash.
✅ To'g'ri: Facade — bu **qulaylik qatlami**, majburiy devor emas. Ilg'or foydalanuvchiga (yoki test kodiga) kerak bo'lsa, subtizim klasslariga to'g'ridan-to'g'ri murojaat qilish imkoniyati qolishi mumkin — Facade shunchaki odatiy holatlar uchun qisqa yo'l taklif qiladi.

## Mashq/topshiriq

**(Oson)** `Yoritgich.yoq()`/`ochir()`, `Konditsioner.yoq()`/`ochir()`, `MusiqaTizimi.yoq()`/`ochir()` klasslari bor. `UyniTashlabKetishFacade.hammasini_ochir()` metodini yozing — u uchtasini ham o'chirsin.

**(O'rtacha)** Restoran buyurtma tizimi: `Oshxona.taom_tayyorla(nomi)`, `Kassa.hisob_chiqar(narx)`, `Ofitsiant.stolga_olib_bor(stol_raqami)` klasslari bor. `RestoranFacade.buyurtma_xizmati(taom_nomi, narx, stol_raqami)` metodini yozing — u uchtasini to'g'ri tartibda chaqirib, oxirida "Buyurtma yetkazildi" deb chiqarsin.

**(Qiyin)** Avvalgi darsdagi `BuyurtmaFacade`ga yangi qadam qo'shing: agar to'lov miqdori 5,000,000 so'mdan oshsa, qo'shimcha `XavfsizlikTekshiruvi.tekshir(summa)` subtizimini (yangi klass sifatida yozing, har doim `True` qaytarsin, lekin "[Xavfsizlik] tekshirilmoqda..." chiqarsin) chaqiring — bu qadam Facade ICHIDA qo'shilishi kerak, mijoz kodi o'zgarishsiz qolishi shart.

## Qisqacha xulosa

Facade naqshi — bir nechta murakkab subtizim klassi ustiga yupqa, sodda va yagona interfeys qo'yib, mijoz kodini subtizimning ichki tuzilishi va chaqiriqlar tartibidan butunlay ajratadi (decoupling); u Adapterdan farqli o'laroq mavjud interfeysni tarjima qilmaydi, balki **yangi, soddalashtirilgan** interfeys yaratadi; Django ORM, `requests`, `subprocess` kabi ko'plab mashhur kutubxonalar aslida katta Facade'lar hisoblanadi; asosiy xavf — Facade'ni asta-sekin barcha biznes-logikani o'z ichiga oluvchi "god object"ga aylantirib qo'yish, shuning uchun u doim yupqa, faqat yo'naltiruvchi qatlam bo'lib qolishi kerak.
