# Iterator naqshi

## Bu darsda nimalarni o'rganasiz

- Iterator naqshining klassik (GoF) ma'nosini, qanday muammoni hal qilishini tushuntira olasiz
- `__iter__`/`__next__` protokolini qo'lda, naqsh darajasida amalga oshira olasiz
- Nega bu naqsh boshqa barcha naqshlardan farqli — **til darajasida o'rnatilgan** (built-in) ekanini chuqur tushunasiz
- Tashqi (external) va ichki (internal) iteratorlar farqini bilasiz
- Generator'lar Iterator naqshini qanday "avtomatlashtirganini" ko'ra olasiz

## Nazariy qism

### Qanday muammoni hal qiladi

Faraz qiling, sizda o'zingizning maxsus ma'lumot tuzilmangiz bor — masalan, ikkilik daraxt (binary tree) yoki aylana bog'langan ro'yxat (circular linked list). Siz bu tuzilma elementlarini **ketma-ket, bir-bir** aylanib o'tishni (iteratsiya qilishni) xohlaysiz — lekin tuzilmaning **ichki qurilishini** (daraxt tugunlari, havolalar) tashqi kodga ochib bermaysiz.

Tajribasiz yechim — tashqi kodga butun ma'lumotni bitta ro'yxat sifatida qaytarish:

```python
class Daraxt:
    def barcha_elementlar(self) -> list:
        # butun daraxtni DARHOL, to'liq xotirada ro'yxatga aylantiradi
        natija = []
        self._yigish(self.ildiz, natija)
        return natija
```

Muammo: agar daraxt **juda katta** bo'lsa (millionlab tugun), bu usul **butun ma'lumotni bir vaqtda xotiraga yuklaydi** — bu samarasiz, ba'zan imkonsiz. Bundan tashqari, "faqat birinchi 3 ta elementni ko'rish" kabi vazifalar uchun ham, hali ham **butun** daraxt aylanib chiqiladi.

**Iterator naqshi** — bu muammoni hal qiladi: ma'lumot tuzilmasining **o'zidan** ("Aggregate") alohida, "qayerda turganimni eslab turadigan" (ichki holat bilan) kichik yordamchi obyekt — **iterator** — yaratiladi. Bu obyekt faqat ikki narsani biladi: "keyingi element bormi?" va "keyingi elementni ber". Ma'lumot tuzilmasining ichki qurilishi (daraxt, ro'yxat, grafik — qanday bo'lmasin) tashqi kodga **mutlaqo ko'rinmaydi**.

### Klassik (GoF) Iterator — qo'lda yozilgan

```python
class SonlarToplami:
    """Aggregate — ma'lumotni saqlaydigan tuzilma."""

    def __init__(self):
        self._elementlar = []

    def qosh(self, element):
        self._elementlar.append(element)

    def iterator_ol(self):
        return SonlarIteratori(self)

    def __len__(self):
        return len(self._elementlar)

    def elementni_ol(self, indeks):
        return self._elementlar[indeks]


class SonlarIteratori:
    """Iterator — 'qayerda turganini' (indeks) eslab turadigan alohida obyekt."""

    def __init__(self, toplam: SonlarToplami):
        self._toplam = toplam
        self._joriy_indeks = 0

    def keyingisi_bormi(self) -> bool:
        return self._joriy_indeks < len(self._toplam)

    def keyingisini_ol(self):
        element = self._toplam.elementni_ol(self._joriy_indeks)
        self._joriy_indeks += 1
        return element


toplam = SonlarToplami()
toplam.qosh(10)
toplam.qosh(20)
toplam.qosh(30)

iterator = toplam.iterator_ol()
while iterator.keyingisi_bormi():
    print(iterator.keyingisini_ol())
# 10
# 20
# 30
```

Bu yerda — xuddi GoF kitobidagi klassik tuzilma: `SonlarToplami` (Aggregate) — ma'lumotni saqlaydi, `SonlarIteratori` (Iterator) — aylanib o'tish **holatini** (`_joriy_indeks`) o'z ichida saqlaydi. Eng muhimi: **bir xil to'plamda bir vaqtning o'zida bir nechta mustaqil iterator** bo'lishi mumkin — har biri o'z holatini alohida yuritadi, biri boshqasiga ta'sir qilmaydi.

### Muhim falsafiy nuqta: bu naqsh Python tiliga QANDAY QILIB til darajasida singib ketgan

Boshqa barcha naqshlardan (Strategy, Observer, Command) farqli o'laroq, Iterator naqshi — Python'da shunchaki "kutubxona darajasida qulay amalga oshiriladigan g'oya" emas, balki **tilning o'z sintaksisiga, `for` operatoriga quyilgan rasmiy protokol**dir.

Qachon siz:

```python
for element in biror_narsa:
    ...
```

yozsangiz, Python **aynan yuqoridagi GoF naqshini, sahna ortida, avtomatik** bajaradi. Bu quyidagi bayt-kodga deyarli ekvivalent (8-bobda `dis` moduli bilan tasdiqlashingiz mumkin):

```python
_iterator = iter(biror_narsa)      # == biror_narsa.__iter__()  (GoF'dagi "iterator_ol()")
while True:
    try:
        element = next(_iterator)   # == _iterator.__next__()  (GoF'dagi "keyingisini_ol()")
    except StopIteration:           # == GoF'dagi "keyingisi_bormi() False bo'lgani"
        break
    ...
```

**`__iter__`** metodi — GoF'dagi `iterator_ol()`ning rasmiy nomi. **`__next__`** metodi — `keyingisini_ol()`ning rasmiy nomi, lekin `StopIteration` istisnosi orqali "keyingisi yo'q" degan xabarni beradi (alohida `keyingisi_bormi()` metodi shart emas — bu Python'ning o'z, ixchamroq yechimi). Shuning uchun yuqoridagi qo'lda yozilgan misolni **aynan Python protokoliga** moslashtirish mumkin:

```python
class SonlarToplami:
    def __init__(self):
        self._elementlar = []

    def qosh(self, element):
        self._elementlar.append(element)

    def __iter__(self):
        return SonlarIteratori(self)


class SonlarIteratori:
    def __init__(self, toplam):
        self._toplam = toplam
        self._joriy_indeks = 0

    def __iter__(self):
        return self   # iteratorning o'zi ham iterable bo'lishi shart (protokol talabi)

    def __next__(self):
        if self._joriy_indeks >= len(self._toplam._elementlar):
            raise StopIteration
        element = self._toplam._elementlar[self._joriy_indeks]
        self._joriy_indeks += 1
        return element


toplam = SonlarToplami()
toplam.qosh(10)
toplam.qosh(20)
toplam.qosh(30)

for son in toplam:    # ENDI oddiy `for` bilan ishlaydi!
    print(son)
# 10
# 20
# 30

# Bir vaqtning o'zida IKKI mustaqil iterator — GoF'ning asosiy afzalligi saqlanib qolgan:
it1 = iter(toplam)
it2 = iter(toplam)
print(next(it1))   # 10
print(next(it1))   # 20
print(next(it2))   # 10   — it2 o'zining MUSTAQIL holatidan boshlaydi
```

Bu — naqshlar haqida juda muhim falsafiy xulosani ko'rsatadi: **dizayn naqshi — til kambag'alligini qoplash uchun ixtiro qilingan "qolip" emas, balki takrorlanadigan muammoning umumiy yechim g'oyasi.** Agar g'oya yetarlicha foydali va universal bo'lsa (Iterator naqshidagi kabi), til yaratuvchilari uni **tilning o'ziga, rasmiy protokol sifatida** kiritib qo'yishlari mumkin — va aynan shu Python'da `__iter__`/`__next__` bilan sodir bo'lgan. Shu sababdan Java'da "Iterator Pattern" alohida kitob bobi bo'lib o'rganiladi, Python'da esa u — `for` operatorining kundalik, "sezilmas" ishlashi.

### Tashqi (external) va ichki (internal) iteratsiya

Yuqoridagi `while iterator.keyingisi_bormi(): ...` yoki Python'ning `for` tsikli — **tashqi iteratsiya**: aylanib o'tishni boshqaruvchi kod ("chaqiruvchi tomon") har safar o'zi "keyingisini so'raydi". Bunga qarama-qarshi, **ichki iteratsiya** — tuzilmaning o'zi aylanib o'tishni boshqaradi, har bir element uchun sizning funksiyangizni **o'zi chaqiradi**:

```python
# ICHKI iteratsiya misoli — list.sort() qanday ishlashi kabi
class SonlarToplami2:
    def __init__(self, elementlar):
        self._elementlar = elementlar

    def har_biriga(self, funksiya):
        # tuzilmaning O'ZI aylanadi, chaqiruvchi faqat "nima qilish"ni beradi
        for element in self._elementlar:
            funksiya(element)


toplam2 = SonlarToplami2([1, 2, 3])
toplam2.har_biriga(lambda x: print(x * 10))
# 10
# 20
# 30
```

Python'da `map()`, `filter()`, ro'yxat comprehensionlari — barchasi tashqi iteratsiyaga asoslangan (ular `__iter__`/`__next__`ni ishlatadi), lekin `functools.reduce()` va yuqoridagi `har_biriga()` kabi — "funksiyani har bir elementga qo'llash" uslubi — ichki iteratsiyaga yaqinroq. Python madaniyati **tashqi iteratsiyani** (ya'ni, `for`, generatorlar) afzal ko'radi, chunki u o'qilishi oson va `break`/`continue` bilan erkin boshqariladi.

### Generatorlar — Iterator naqshini "avtomatlashtirish"

5.3-darsda (agar kontekstingizda bo'lsa) yoki umumiy Python bilimingizdan ko'rganingizdek, **generator funksiyalar** (`yield` bilan) — `__iter__`/`__next__`ni qo'lda yozishning ancha qisqa, avtomatlashtirilgan usuli:

```python
class SonlarToplami3:
    def __init__(self):
        self._elementlar = []

    def qosh(self, element):
        self._elementlar.append(element)

    def __iter__(self):
        # bu — GENERATOR funksiya: Python avtomatik __next__/StopIteration'ni yaratadi
        for element in self._elementlar:
            yield element


toplam3 = SonlarToplami3()
toplam3.qosh(100)
toplam3.qosh(200)

for son in toplam3:
    print(son)
# 100
# 200
```

Qo'lda yozilgan `SonlarIteratori` klassi (alohida `_joriy_indeks`, `__next__`, `StopIteration`) — bu yerda **bitta** `yield` qatoriga almashtirildi. Python buning ortida sizning o'rningizga avtomatik "iterator klass" yaratadi — bu, aslida, Iterator naqshining **kompilyator darajasida avtomatlashtirilgan** ko'rinishi. Shu bois amaliyotda Python dasturchilari deyarli hech qachon yuqoridagi "qo'lda yozilgan Iterator klassi" uslubini ishlatmaydi — ular to'g'ridan-to'g'ri generator yozadilar, chunki natija bir xil, lekin kod ancha qisqa va xavfsizroq (`StopIteration`ni qo'lda `raise` qilishni unutish xavfi yo'q).

## Amaliy misol

Sahifalab (pagination) ma'lumot o'qish — katta ma'lumotlar bazasidan yozuvlarni bir martada emas, "sahifalab" o'qiydigan, xotirani tejaydigan iterator:

```python
# sahifali_iterator.py
class MalumotlarBazasi:
    """Soxta (fake) ma'lumotlar bazasi — haqiqiy loyihada bu SQL so'rovi bo'lardi."""

    def __init__(self, jami_yozuvlar: int):
        self._barcha_yozuvlar = [f"Yozuv-{i}" for i in range(1, jami_yozuvlar + 1)]

    def sahifani_ol(self, sahifa_raqami: int, sahifa_hajmi: int) -> list[str]:
        boshlanish = (sahifa_raqami - 1) * sahifa_hajmi
        tugash = boshlanish + sahifa_hajmi
        return self._barcha_yozuvlar[boshlanish:tugash]

    def jami_sahifalar(self, sahifa_hajmi: int) -> int:
        import math
        return math.ceil(len(self._barcha_yozuvlar) / sahifa_hajmi)


class SahifaliIterator:
    """Barcha yozuvlarni, LEKIN bir vaqtda faqat bitta sahifani xotirada saqlab, aylanib o'tadi."""

    def __init__(self, baza: MalumotlarBazasi, sahifa_hajmi: int = 10):
        self._baza = baza
        self._sahifa_hajmi = sahifa_hajmi
        self._joriy_sahifa = 1
        self._joriy_buffer: list[str] = []
        self._buffer_indeksi = 0

    def __iter__(self):
        return self

    def __next__(self) -> str:
        if self._buffer_indeksi >= len(self._joriy_buffer):
            # joriy sahifa tugadi — KEYINGI sahifani bazadan so'raymiz (xotirada faqat BITTA sahifa turadi)
            self._joriy_buffer = self._baza.sahifani_ol(self._joriy_sahifa, self._sahifa_hajmi)
            self._buffer_indeksi = 0
            self._joriy_sahifa += 1
            if not self._joriy_buffer:
                raise StopIteration

        yozuv = self._joriy_buffer[self._buffer_indeksi]
        self._buffer_indeksi += 1
        return yozuv


baza = MalumotlarBazasi(jami_yozuvlar=25)
iterator = SahifaliIterator(baza, sahifa_hajmi=10)

for i, yozuv in enumerate(iterator):
    print(yozuv)
    if i >= 4:   # faqat dastlabki 5 tasini ko'rsatamiz
        break
# Yozuv-1
# Yozuv-2
# Yozuv-3
# Yozuv-4
# Yozuv-5
# (e'tibor bering: qolgan 20 ta yozuv HECH QACHON xotiraga yuklanmadi, chunki break bosildi)
```

Bu — Iterator naqshining real foydasi: agar `MalumotlarBazasi`da 10 million yozuv bo'lsa ham, `SahifaliIterator` bir vaqtning o'zida faqat **bitta sahifa** (`sahifa_hajmi` dona yozuv)ni xotirada saqlaydi — qolganini "kerak bo'lganda" so'raydi.

## Keng tarqalgan xatolar

**Xato 1:** `__iter__`da `self`ni emas, yangi obyekt yaratishni unutib, yoki aksincha — holatni noto'g'ri saqlash.
❌
```python
class Toplam:
    def __init__(self):
        self._indeks = 0   # holat KLASSNING O'ZIDA saqlanadi!
        self._elementlar = [1, 2, 3]

    def __iter__(self):
        return self

    def __next__(self):
        if self._indeks >= len(self._elementlar):
            raise StopIteration
        v = self._elementlar[self._indeks]
        self._indeks += 1
        return v
```
Bu klassda aylanib o'tish holati (`_indeks`) **to'plamning o'zida** saqlanadi — demak, bir vaqtning o'zida ikki marta `for x in toplam` qilishga urinsangiz (masalan, ichma-ich tsikl), ikkisi **bir xil `_indeks`ni** ishlatadi va bir-birini "buzadi".
✅ To'g'ri: aylanib o'tish holatini **alohida iterator obyektida** saqlang (yuqoridagi `SonlarToplami`/`SonlarIteratori` misolidagi kabi), `__iter__` har safar **yangi** iterator qaytarsin — shunda bir nechta mustaqil iteratsiya bir vaqtda, bir-biriga ta'sir qilmasdan ishlashi mumkin bo'ladi.

**Xato 2:** `StopIteration`ni `raise` qilishni unutish — cheksiz tsikl.
❌
```python
def __next__(self):
    if self._indeks < len(self._elementlar):
        v = self._elementlar[self._indeks]
        self._indeks += 1
        return v
    # StopIteration raise qilinmadi — None qaytadi!
```
`for` tsikli `StopIteration`ni **kutadi**; agar u o'rniga oddiy `None` qaytarilsa, Python buni "yana bir element bor" deb hisoblaydi va `None`larni cheksiz chop etadi (yoki keyingi kodga qarab, boshqa xatoga olib keladi).
✅ To'g'ri: har doim elementlar tugaganda **aniq** `raise StopIteration` yozing (yoki generator ishlatib, Python'ning o'ziga ishoning).

**Xato 3:** Generator funksiyasini **chaqirib**, natijani ro'yxat deb o'ylash.
❌
```python
def sonlar_generatori():
    yield 1
    yield 2
    yield 3

natija = sonlar_generatori()
print(natija[0])   # TypeError: 'generator' object is not subscriptable
```
Generator funksiyasini chaqirish — **generator obyekti** qaytaradi (lazy, "hali hisoblanmagan" iterator), ro'yxat emas; unga indeks (`[0]`) bilan murojaat qilib bo'lmaydi.
✅ To'g'ri: generatordan qiymat olish uchun `for` tsikli, `next()` yoki `list(natija)` (agar hammasini darhol xotiraga yuklash xavfsiz bo'lsa) ishlating.

## Mashq/topshiriq

**(Oson)** `TeskariIterator` klassini yozing — u ro'yxatni **teskari tartibda** (oxiridan boshigacha) aylanib o'tsin, `__iter__`/`__next__` protokoli bilan qo'lda yozilgan (generator ishlatmasdan).

**(O'rtacha)** `JuftSonlarIteratori` — berilgan ro'yxatdan faqat **juft sonlarni** qaytaradigan iterator klassini yozing (`__iter__`/`__next__` bilan). So'ngra xuddi shu natijani generator funksiya (`yield`) bilan qayta yozing va ikkisini solishtiring.

**(Qiyin)** Ikkilik daraxt (binary tree) uchun "in-order" (chapdan o'ngga, kichikdan kattaga) iterator yozing — daraxt tugunlari `chap`, `qiymat`, `ong` atributlariga ega bo'lsin. Avval generator (`yield`) bilan oddiy rekursiv yechim yozing, so'ngra **rekursivsiz**, qo'lda stack (`list` sifatida) ishlatib, `__next__` protokoli bilan qayta yozing (bu — real dunyoda katta daraxtlarda rekursiya chegarasidan (`RecursionError`) qochish uchun kerak bo'ladigan amaliy texnika).

        self.qiymat, self.chap, self.ong = qiymat, chap, ong

def inorder_generator(tugun):
    if tugun is None:
        return
    yield from inorder_generator(tugun.chap)
    yield tugun.qiymat
    yield from inorder_generator(tugun.ong)

class InorderIterator:
    def __init__(self, ildiz):
        self._stack = []
        self._joriy = ildiz

    def __iter__(self):
        return self

    def __next__(self):
        while self._joriy is not None:
            self._stack.append(self._joriy)
            self._joriy = self._joriy.chap
        if not self._stack:
            raise StopIteration
        tugun = self._stack.pop()
        self._joriy = tugun.ong
        return tugun.qiymat

daraxt = Tugun(5, Tugun(3, Tugun(1), Tugun(4)), Tugun(8))
print(list(inorder_generator(daraxt)))   # [1, 3, 4, 5, 8]
print(list(InorderIterator(daraxt)))     # [1, 3, 4, 5, 8]

## Qisqacha xulosa

Iterator naqshi — ma'lumot tuzilmasining ichki qurilishini yashirib, uni ketma-ket "bir-bir" aylanib o'tish uchun alohida, holatni o'zida saqlaydigan yordamchi obyekt (iterator) yaratish g'oyasi bo'lib, Python'da bu naqsh boshqa barcha naqshlardan farqli ravishda shunchaki "qulay konvensiya" emas, balki **tilning o'z sintaksisiga rasmiy `__iter__`/`__next__`/`StopIteration` protokoli sifatida singdirilgan** — har bir `for` tsikli, aslida, GoF'ning klassik Iterator naqshini sahna ortida avtomatik bajaradi. Generator funksiyalar (`yield`) — bu protokolni qo'lda klass yozishdan ancha qisqa, xavfsiz va "pythonik" tarzda amalga oshirish usuli; naqsh esa, ayniqsa, katta yoki "lazy" (kechiktirilgan) ma'lumotlar bilan ishlashda — butun ma'lumotni darhol xotiraga yuklamasdan, faqat kerakli qismini "so'rab olish" imkonini beradi.
