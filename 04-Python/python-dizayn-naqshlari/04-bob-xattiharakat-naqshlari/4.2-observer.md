# Observer naqshi

## Bu darsda nimalarni o'rganasiz

- Observer (kuzatuvchi) naqshi qanday muammoni hal qilishini tushuntira olasiz
- "Subject" (nashr qiluvchi) va "Observer" (obodachi) rollarini ajrata olasiz
- O'zingizning event-driven (voqealarga asoslangan) tizimingizni yoza olasiz
- Observer naqshining Django signals, GUI freymvorklari va `pub/sub` tizimlarida qanday ishlatilishini bilasiz
- Observer naqshining xavfli tomonlari (xotira sizib chiqishi, tartib muammosi) haqida bilasiz

## Nazariy qism

### Qanday muammoni hal qiladi

Faraz qiling, sizda `HaroratSensori` klassi bor, va harorat o'zgarganda bir nechta joy xabardor bo'lishi kerak: ekranga chiqarish, faylga yozish, va agar harorat juda yuqori bo'lsa — ogohlantirish yuborish. Tajribasiz yechim — sensorning o'zi hammasini bilishi:

```python
class HaroratSensori:
    def harorat_ozgardi(self, yangi_harorat):
        print(f"Ekran: harorat {yangi_harorat}")       # 1-vazifa
        self._faylga_yoz(yangi_harorat)                 # 2-vazifa
        if yangi_harorat > 40:
            self._ogohlantirish_yubor(yangi_harorat)     # 3-vazifa
```

Muammo: `HaroratSensori` — sensor bo'lishi kerak, lekin u endi ekranga chiqarishni, faylga yozishni VA ogohlantirish yuborishni ham "bilishga" majbur. Yangi funksiyalar (masalan, SMS yuborish) qo'shilsa, sensor klassining o'zini o'zgartirishga to'g'ri keladi — bu yana Open/Closed tamoyilining buzilishi, va **yagona mas'uliyat tamoyili (Single Responsibility Principle)**ning ham buzilishi (bir klass bir necha sababga ko'ra o'zgarishga majbur bo'lmasligi kerak).

**Observer naqshi** — buni hal qiladi: "voqea yuz berganda nima qilish kerak" degan mantiqni sensordan **butunlay ajratib**, tashqi "kuzatuvchilar" (observer) ro'yxatiga topshiradi. Sensor faqat "voqea yuz berdi" deb **xabar beradi** (notify), kuzatuvchilarning har biri o'zi nima qilishni biladi.

### Asosiy tuzilma: Subject va Observer

```python
from abc import ABC, abstractmethod


class Observer(ABC):
    """Barcha kuzatuvchilar shu interfeysga amal qiladi."""

    @abstractmethod
    def xabardor_qil(self, harorat: float) -> None:
        ...


class Subject:
    """Nashr qiluvchi (yoki 'observable') — kuzatuvchilarni ro'yxatda saqlaydi."""

    def __init__(self):
        self._kuzatuvchilar: list[Observer] = []

    def obuna_bol(self, kuzatuvchi: Observer) -> None:
        self._kuzatuvchilar.append(kuzatuvchi)

    def obunani_bekor_qil(self, kuzatuvchi: Observer) -> None:
        self._kuzatuvchilar.remove(kuzatuvchi)

    def _xabar_qil(self, harorat: float) -> None:
        for kuzatuvchi in self._kuzatuvchilar:
            kuzatuvchi.xabardor_qil(harorat)


class HaroratSensori(Subject):
    def harorat_ozgardi(self, yangi_harorat: float) -> None:
        self._xabar_qil(yangi_harorat)   # faqat XABAR BERADI, nima qilishni bilmaydi


class EkranKorsatuvchi(Observer):
    def xabardor_qil(self, harorat: float) -> None:
        print(f"[Ekran] Hozirgi harorat: {harorat}°C")


class OgohlantiruvchiTizim(Observer):
    def xabardor_qil(self, harorat: float) -> None:
        if harorat > 40:
            print(f"[OGOHLANTIRISH] Harorat xavfli darajada: {harorat}°C!")


sensor = HaroratSensori()
sensor.obuna_bol(EkranKorsatuvchi())
sensor.obuna_bol(OgohlantiruvchiTizim())

sensor.harorat_ozgardi(25)
# [Ekran] Hozirgi harorat: 25°C

sensor.harorat_ozgardi(45)
# [Ekran] Hozirgi harorat: 45°C
# [OGOHLANTIRISH] Harorat xavfli darajada: 45°C!
```

E'tibor bering: `HaroratSensori` klassi `EkranKorsatuvchi` yoki `OgohlantiruvchiTizim` haqida **hech narsa bilmaydi** — u faqat `Observer` interfeysiga ishonadi. Yangi kuzatuvchi (masalan, `SMSYuboruvchi`) qo'shish uchun — `HaroratSensori` kodini **bir qatorga ham** tegmasdan, shunchaki yangi klass yozib, `obuna_bol()` orqali ro'yxatga qo'shish kifoya.

### "Push" va "Pull" modellari

Yuqoridagi misolda `xabardor_qil(harorat)` — ma'lumotni to'g'ridan-to'g'ri uzatadi (**push model**: subject ma'lumotni o'zi "itarib" beradi). Ba'zan kuzatuvchiga faqat "biror narsa o'zgardi" deb xabar berish, va kuzatuvchining o'zi kerakli ma'lumotni subject'dan **so'rab olishi** (**pull model**) qulayroq bo'ladi — ayniqsa, turli kuzatuvchilarga turli ma'lumot kerak bo'lsa:

```python
class SubjectPull:
    def __init__(self):
        self._kuzatuvchilar = []
        self.harorat = None
        self.namlik = None

    def obuna_bol(self, kuzatuvchi):
        self._kuzatuvchilar.append(kuzatuvchi)

    def holatni_yangila(self, harorat, namlik):
        self.harorat, self.namlik = harorat, namlik
        for k in self._kuzatuvchilar:
            k.yangilanish(self)   # subject'ning O'ZINI uzatadi, ma'lumot emas


class FaqatHaroratKuzatuvchisi:
    def yangilanish(self, subject):
        print(f"Faqat harorat kerak: {subject.harorat}")   # o'zi kerakli maydonni oladi


class FaqatNamlikKuzatuvchisi:
    def yangilanish(self, subject):
        print(f"Faqat namlik kerak: {subject.namlik}")
```

Pull model — kuzatuvchilarga ko'proq moslanuvchanlik beradi (har biri faqat kerakli ma'lumotni oladi), lekin subject'ning butun ichki holatiga ruxsat berish — ba'zan **ortiqcha bog'liqlik** (coupling) yaratishi mumkin. Amalda ko'pincha ikkisining aralashmasi — kichik, aniq "event" obyekti uzatiladi (masalan, `dataclass` bilan).

### Observer naqshi qayerda "yashirin" ishlatiladi

Observer naqshi — zamonaviy dasturlashning **eng ko'p qo'llaniladigan** naqshlaridan biri, chunki u "event-driven" (voqealarga asoslangan) arxitekturaning negizida yotadi:

- **Django signals** (`post_save`, `pre_delete` va h.k.) — model saqlanganda, "signal yuboriladi" va unga "ulangan" (connected) barcha funksiyalar avtomatik chaqiriladi. Bu — Observer naqshining to'g'ridan-to'g'ri qo'llanilishi: `Model` — subject, signalga ulangan funksiyalar — observerlar.
- **GUI freymvorklari** (Tkinter, PyQt) — tugmaga bosilganda `on_click` funksiyalari chaqiriladi — tugma "subject", sizning handler funksiyangiz "observer".
- **Observable property kutubxonalari** (masalan, `RxPy`, yoki frontendda React/Vue'ning reaktivligi) — qiymat o'zgarganda, unga "obuna bo'lgan" barcha joylar avtomatik yangilanadi.
- **`logging` moduli** — `Logger`ga bir nechta `Handler` (fayl, konsol, tarmoq) "qo'shilishi" mumkin, va har bir log xabari **barcha** handler'larga yuboriladi — bu ham, mohiyatan, Observer naqshi.

### Observer naqshining xavflari

**1. Xotira sizib chiqishi (memory leak).** Agar kuzatuvchi `obunani_bekor_qil()` orqali ro'yxatdan chiqarilmasa, subject uni **abadiy** ro'yxatida saqlab turadi — garchi dasturning boshqa qismida unga endi ehtiyoj qolmagan bo'lsa ham. Bu — Python'da `weakref` moduli (7-bobda, CPython ichki mexanizmlarida ko'rilgan) yordamida hal qilinadigan klassik muammo.

**2. Chaqiriq tartibi noma'lum.** Agar bir nechta kuzatuvchi bo'lsa va ular orasida **bog'liqlik** bo'lsa (masalan, A kuzatuvchi B kuzatuvchidan oldin ishlashi kerak bo'lsa), oddiy ro'yxat tartibiga tayanish — ishonchsiz dizayn. Buning uchun ustunlik (priority) tizimi kerak bo'ladi.

**3. "Kaskadli" xatolar.** Agar bir kuzatuvchi xato (`exception`) tashlasa, va kod `for` tsiklida bu xatoni ushlamasa — qolgan barcha kuzatuvchilar xabardor qilinmay qoladi. Shuning uchun real tizimlarda har bir kuzatuvchini alohida `try/except` bilan o'rab olish tavsiya qilinadi.

## Amaliy misol

Yangiliklar portali — foydalanuvchilar mavzuga "obuna bo'ladi" va yangi maqola chiqganda xabardor qilinadi (real dunyoda "pub/sub" tizimlarining soddalashtirilgan ko'rinishi):

```python
# yangiliklar_tizimi.py
from abc import ABC, abstractmethod
from dataclasses import dataclass, field


@dataclass
class Maqola:
    sarlavha: str
    mavzu: str


class Obunachi(ABC):
    @abstractmethod
    def yangi_maqola(self, maqola: Maqola) -> None:
        ...


class EmailObunachisi(Obunachi):
    def __init__(self, email: str):
        self.email = email

    def yangi_maqola(self, maqola: Maqola) -> None:
        print(f"[EMAIL -> {self.email}] Yangi maqola: '{maqola.sarlavha}' ({maqola.mavzu})")


class PushBildirishnoma(Obunachi):
    def __init__(self, qurilma_id: str):
        self.qurilma_id = qurilma_id

    def yangi_maqola(self, maqola: Maqola) -> None:
        print(f"[PUSH -> qurilma {self.qurilma_id}] '{maqola.sarlavha}'")


@dataclass
class MavzuKanali:
    nomi: str
    _obunachilar: list[Obunachi] = field(default_factory=list)

    def obuna_bol(self, obunachi: Obunachi) -> None:
        self._obunachilar.append(obunachi)

    def obunani_bekor_qil(self, obunachi: Obunachi) -> None:
        if obunachi in self._obunachilar:
            self._obunachilar.remove(obunachi)

    def maqola_chiqar(self, sarlavha: str) -> None:
        maqola = Maqola(sarlavha=sarlavha, mavzu=self.nomi)
        for obunachi in self._obunachilar:
            try:
                obunachi.yangi_maqola(maqola)
            except Exception as xato:
                # bitta obunachidagi xato boshqalariga ta'sir qilmasligi uchun
                print(f"[XATO] obunachini xabardor qilishda muammo: {xato}")


texnologiya_kanali = MavzuKanali(nomi="Texnologiya")
ali_email = EmailObunachisi("ali@mail.uz")
vali_push = PushBildirishnoma(qurilma_id="PX-2291")

texnologiya_kanali.obuna_bol(ali_email)
texnologiya_kanali.obuna_bol(vali_push)

texnologiya_kanali.maqola_chiqar("Python 3.14 chiqdi!")
# [EMAIL -> ali@mail.uz] Yangi maqola: 'Python 3.14 chiqdi!' (Texnologiya)
# [PUSH -> qurilma PX-2291] 'Python 3.14 chiqdi!'

texnologiya_kanali.obunani_bekor_qil(vali_push)
texnologiya_kanali.maqola_chiqar("Yangi CPython JIT haqida")
# [EMAIL -> ali@mail.uz] Yangi maqola: 'Yangi CPython JIT haqida' (Texnologiya)
# (vali_push endi xabar olmaydi — obunasi bekor qilingan)
```

## Keng tarqalgan xatolar

**Xato 1:** Kuzatuvchini ro'yxatdan chiqarishni unutish — xotira sizib chiqishi.
❌
```python
def vaqtinchalik_kuzatuvchi_qosh(subject):
    k = VaqtinchalikKuzatuvchi()
    subject.obuna_bol(k)
    # funksiya tugagach, k mahalliy o'zgaruvchi sifatida yo'qoladi,
    # LEKIN subject uni hali ham ro'yxatida saqlab turadi!
```
Katta, uzoq ishlaydigan dasturlarda (masalan, veb-server) bu — vaqt o'tishi bilan xotirani asta-sekin to'ldirib boradigan, aniqlash qiyin bo'lgan xato.
✅ To'g'ri: har bir `obuna_bol()` chaqiruvi uchun, kerak bo'lmay qolganda `obunani_bekor_qil()`ni chaqirishni unutmang (masalan, `try/finally` yoki context manager bilan), yoki kuchli (`list`) o'rniga `weakref.WeakSet` ishlatib, Python'ning o'zi avtomatik tozalashiga imkon bering.

**Xato 2:** `_xabar_qil()` ichida kuzatuvchilar ro'yxatini **o'zgartirish** — `RuntimeError`.
❌
```python
def xabardor_qil(self, harorat):
    if harorat > 100:
        self.subject.obunani_bekor_qil(self)   # tsikl ICHIDA ro'yxatni o'zgartirish!
```
`for kuzatuvchi in self._kuzatuvchilar:` tsikli davom etayotganda ro'yxatning o'zi o'zgartirilsa, Python `RuntimeError: list changed size during iteration` xatosini chiqaradi (yoki ba'zi elementlar "o'tkazib yuboriladi").
✅ To'g'ri: `_xabar_qil()` ichida ro'yxatning **nusxasi** bo'yicha iteratsiya qiling: `for kuzatuvchi in list(self._kuzatuvchilar):`.

**Xato 3:** Observer naqshini har qanday "bog'liqlik" uchun ishlatish, hatto kerak bo'lmaganda.
❌ Ikki klass orasida faqat BITTA, doimiy, oddiy bog'liqlik bor bo'lsa (A har doim B'ni to'g'ridan-to'g'ri chaqirishi mumkin bo'lsa), lekin "kelajakda kerak bo'lishi mumkin" deb to'liq Subject/Observer infratuzilmasi quriladi.
✅ To'g'ri: Observer naqshi — **ko'p, dinamik, oldindan noma'lum** kuzatuvchilar bo'lgandagina o'zini oqlaydi. Agar faqat bitta, qat'iy bog'liqlik bo'lsa — oddiy metod chaqiruvi yetarli; ortiqcha abstraktsiya — ortiqcha murakkablik.

## Mashq/topshiriq

**(Oson)** `Chat` klassini yozing — unga `xabar_yubor(matn)` metodi bo'lsin. `Foydalanuvchi` klassi (observer) — `yangi_xabar(matn)` metodi bilan, xabarni konsolga `f"{ismi} oldi: {matn}"` shaklida chiqarsin. Ikki foydalanuvchini bir chatga obuna qilib sinab ko'ring.

**(O'rtacha)** Aksiya narxi kuzatuvchisini yozing: `Aksiya` klassi (subject) `narx` atributiga ega, `narxni_ozgartir(yangi_narx)` metodi bor. Ikki turdagi kuzatuvchi: `NarxKorsatuvchi` (har doim yangi narxni chop etadi) va `OgohlantiruvchiKuzatuvchi` (faqat narx belgilangan chegaradan PASTGA tushganda ogohlantiradi — chegara konstruktorda beriladi).

**(Qiyin)** Yuqoridagi "xotira sizib chiqishi" muammosini `weakref` bilan hal qiling: `Subject` klassini shunday yozing-ki, u kuzatuvchilarni oddiy `list` o'rniga `weakref.WeakSet`da saqlasin, shunda kuzatuvchi obyektga boshqa hech qayerda havola (reference) qolmasa, u avtomatik ro'yxatdan "yo'qolsin" (garbage collector tomonidan yig'ib olinganda).

## Qisqacha xulosa

Observer naqshi — "nimadir yuz berdi" (voqea) va "shu voqeaga qanday javob berish kerak" degan mantiqni bir-biridan ajratib, nashr qiluvchi (subject) o'ziga obuna bo'lgan kuzatuvchilar (observer) ro'yxatini saqlab, voqea yuz berganda ularning har biriga umumiy interfeys orqali xabar beradigan dizayn; bu Single Responsibility va Open/Closed tamoyillariga rioya qilishga yordam beradi va Django signals, GUI hodisalari, `logging` handler'lari kabi ko'plab "event-driven" tizimlarning negizida yotadi. Naqshning asosiy xavflari — obunani bekor qilishni unutib xotira sizdirish, tsikl davomida ro'yxatni o'zgartirish va kerak bo'lmagan joyda ortiqcha abstraktsiya yaratishdir — shuning uchun uni faqat haqiqatan ham ko'p, dinamik kuzatuvchilar kutilgandagina qo'llash tavsiya etiladi.
