# Command naqshi

## Bu darsda nimalarni o'rganasiz

- Command (buyruq) naqshi qanday muammoni hal qilishini tushuntira olasiz
- So'rovni ("nima qilish kerak") obyekt sifatida qadoqlashni amalda qo'llay olasiz
- Undo/redo (bekor qilish/qaytarish) mexanizmini Command naqshi bilan quray olasiz
- Buyruqlarni navbatga (queue) joylashtirish va kechiktirib bajarish g'oyasini tushunasiz
- Command naqshining GUI, CLI va makro-yozib olish tizimlarida qo'llanilishini bilasiz

## Nazariy qism

### Qanday muammoni hal qiladi

Oddiy matn muharriri tasavvur qiling: foydalanuvchi "qalin qilish" (bold), "o'chirish" (delete), "qo'yish" (paste) kabi amallarni bajaradi. Tajribasiz yechim — har bir tugma to'g'ridan-to'g'ri mos metodni chaqiradi:

```python
class Tugma:
    def bosildi(self):
        muharrir.matnni_ochirish()   # to'g'ridan-to'g'ri chaqiruv
```

Muammo: agar "Undo" (bekor qilish) tugmasi kerak bo'lsa — nima qilingan edi? Qaysi amal oxirgi bo'lgan? Uni qanday "qaytarish" mumkin? To'g'ridan-to'g'ri metod chaqiruvlari bilan bu savollarga javob berish uchun maxsus, chalkash logika yozishga to'g'ri keladi, chunki **bajarilgan amal haqida hech qanday ma'lumot saqlanmagan** — u shunchaki chaqirilib, "yo'qolgan".

**Command naqshi** — har bir "amalni" ("nima qilish kerak" + "buni qanday bajarish kerak" + ixtiyoriy ravishda "buni qanday bekor qilish kerak") **alohida obyekt** sifatida qadoqlaydi. Bu obyektni saqlash, navbatga qo'yish, loglashtirish, keyinroq bajarish yoki — eng muhimi — **bekor qilish** mumkin bo'ladi, chunki endi amalning o'zi haqida to'liq ma'lumot bor.

### Asosiy tuzilma: Command interfeysi

```python
from abc import ABC, abstractmethod


class Buyruq(ABC):
    """Har bir konkret buyruq shu interfeysga amal qiladi."""

    @abstractmethod
    def bajar(self) -> None:
        ...

    @abstractmethod
    def bekor_qil(self) -> None:
        ...


class Matn:
    """'Receiver' — buyruq haqiqatda kimga nisbatan bajariladi."""

    def __init__(self):
        self.mazmun = ""

    def qosh(self, parcha: str) -> None:
        self.mazmun += parcha

    def ochir(self, uzunlik: int) -> None:
        self.mazmun = self.mazmun[:-uzunlik]


class MatnQoshishBuyrugi(Buyruq):
    def __init__(self, matn: Matn, parcha: str):
        self.matn = matn
        self.parcha = parcha

    def bajar(self) -> None:
        self.matn.qosh(self.parcha)

    def bekor_qil(self) -> None:
        self.matn.ochir(len(self.parcha))   # qo'shilgan narsani teskari o'chirish


muharrir_matni = Matn()
buyruq = MatnQoshishBuyrugi(muharrir_matni, "Salom")
buyruq.bajar()
print(muharrir_matni.mazmun)    # Salom

buyruq.bekor_qil()
print(muharrir_matni.mazmun)    # (bo'sh satr)
```

Bu yerda **uch rol** bor:
1. **Buyruq (Command)** — `MatnQoshishBuyrugi` — "nima qilish kerak" va "buni qanday bekor qilish kerak"ni biladi.
2. **Qabul qiluvchi (Receiver)** — `Matn` — amal haqiqatda bajariladigan obyekt.
3. **Chaqiruvchi (Invoker)** — buyruqni `bajar()`ni chaqiradigan tashqi kod (masalan, tugma) — u buyruqning **ichini** bilmaydi, faqat `bajar()`/`bekor_qil()` metodlarini chaqiradi.

### Buyruqlar tarixi — Undo/Redo stack

Command naqshining eng kuchli tomoni — bajarilgan buyruqlarni **ro'yxatga** (stack) saqlab, keyin ularni teskari tartibda bekor qilish imkoniyati:

```python
class BuyruqlarTarixi:
    def __init__(self):
        self._bajarilganlar: list[Buyruq] = []
        self._bekor_qilinganlar: list[Buyruq] = []

    def bajar(self, buyruq: Buyruq) -> None:
        buyruq.bajar()
        self._bajarilganlar.append(buyruq)
        self._bekor_qilinganlar.clear()   # yangi amal — "redo" tarixini tozalaydi

    def orqaga(self) -> None:
        if not self._bajarilganlar:
            print("Bekor qilish uchun amal yo'q")
            return
        buyruq = self._bajarilganlar.pop()
        buyruq.bekor_qil()
        self._bekor_qilinganlar.append(buyruq)

    def oldinga(self) -> None:
        if not self._bekor_qilinganlar:
            print("Qaytarish uchun amal yo'q")
            return
        buyruq = self._bekor_qilinganlar.pop()
        buyruq.bajar()
        self._bajarilganlar.append(buyruq)


matn = Matn()
tarix = BuyruqlarTarixi()

tarix.bajar(MatnQoshishBuyrugi(matn, "Salom"))
tarix.bajar(MatnQoshishBuyrugi(matn, " Dunyo"))
print(matn.mazmun)    # Salom Dunyo

tarix.orqaga()
print(matn.mazmun)    # Salom   ("  Dunyo" bekor qilindi)

tarix.oldinga()
print(matn.mazmun)    # Salom Dunyo   (qaytarildi)
```

`BuyruqlarTarixi` klassi — **chaqiruvchi (invoker)** bo'lib, buyruqlarning IKKI tomonlama (bajarilgan/bekor qilingan) stackini boshqaradi. Bu — har qanday professional matn muharriri, grafik dastur (Photoshop, Figma) yoki IDE'dagi Ctrl+Z/Ctrl+Y mexanizmining asosidagi aniq g'oya.

### Buyruqlarni kechiktirib bajarish va navbat (queue)

Command naqshining yana bir muhim foydasi — buyruqni **darhol emas, keyinroq** bajarish imkoniyati, chunki u — oddiy obyekt, uni ro'yxatga, navbatga, hattoki faylga saqlash mumkin:

```python
import queue
import threading
import time


vazifalar_navbati: queue.Queue = queue.Queue()


class EmailYuborishBuyrugi(Buyruq):
    def __init__(self, qabul_qiluvchi: str, matn: str):
        self.qabul_qiluvchi = qabul_qiluvchi
        self.matn = matn

    def bajar(self) -> None:
        print(f"Email yuborildi: {self.qabul_qiluvchi} -> {self.matn}")

    def bekor_qil(self) -> None:
        print("Email yuborilgandan keyin bekor qilib bo'lmaydi")


def ishchi():
    while True:
        buyruq = vazifalar_navbati.get()
        if buyruq is None:
            break
        buyruq.bajar()
        vazifalar_navbati.task_done()


ishchi_thread = threading.Thread(target=ishchi)
ishchi_thread.start()

# Buyruqlar DARHOL emas, navbatga qo'yiladi — ishchi o'zi vaqti kelganda bajaradi
vazifalar_navbati.put(EmailYuborishBuyrugi("ali@mail.uz", "Xush kelibsiz!"))
vazifalar_navbati.put(EmailYuborishBuyrugi("vali@mail.uz", "Buyurtmangiz qabul qilindi"))

vazifalar_navbati.join()
vazifalar_navbati.put(None)
ishchi_thread.join()
```

Bu misol — Command naqshining **"amal" va "uni bajarish vaqti/joyi" bir-biridan mustaqil** bo'lishi mumkinligini ko'rsatadi: buyruqlar boshqa joyda (masalan, veb-so'rov handlerida) yaratiladi, lekin ularni haqiqatda bajaruvchi ("worker") butunlay boshqa joyda, boshqa vaqtda ishlaydi. Bu — zamonaviy "task queue" tizimlari (Celery, RQ)ning asosidagi g'oya.

### Makro-buyruq (Composite + Command)

Bir nechta buyruqni **bitta** buyruq sifatida guruhlash ham mumkin (bu — 3.4-darsda ko'riladigan Composite naqshining Command bilan birlashmasi):

```python
class MakroBuyruq(Buyruq):
    def __init__(self, buyruqlar: list[Buyruq]):
        self.buyruqlar = buyruqlar

    def bajar(self) -> None:
        for buyruq in self.buyruqlar:
            buyruq.bajar()

    def bekor_qil(self) -> None:
        # TESKARI tartibda bekor qilish — oxirgi bajarilgan birinchi bekor qilinadi
        for buyruq in reversed(self.buyruqlar):
            buyruq.bekor_qil()


matn2 = Matn()
makro = MakroBuyruq([
    MatnQoshishBuyrugi(matn2, "Assalomu "),
    MatnQoshishBuyrugi(matn2, "alaykum"),
])
makro.bajar()
print(matn2.mazmun)    # Assalomu alaykum
makro.bekor_qil()
print(matn2.mazmun)    # (bo'sh satr) — ikkisi ham teskari tartibda bekor qilindi
```

Bu — real matn muharrirlarida "find & replace barcha o'rinlarda" kabi, bir necha o'zgarishni **bitta Undo bosilganda hammasi birga qaytarilishi** kerak bo'lgan holatlar uchun aynan kerakli yechim.

## Amaliy misol

"Aqlli uy" (smart home) boshqaruv tizimi — turli qurilmalar uchun buyruqlar, pult esa qaysi qurilma ekanini bilmaydi:

```python
# aqlli_uy.py
from abc import ABC, abstractmethod


class Buyruq(ABC):
    @abstractmethod
    def bajar(self) -> None: ...
    @abstractmethod
    def bekor_qil(self) -> None: ...


class Chiroq:
    def __init__(self, xona: str):
        self.xona = xona
        self.yonilgan = False

    def yoq(self):
        self.yonilgan = True
        print(f"[{self.xona}] chiroq YONDI")

    def ochir(self):
        self.yonilgan = False
        print(f"[{self.xona}] chiroq O'CHDI")


class ChiroqniYoqishBuyrugi(Buyruq):
    def __init__(self, chiroq: Chiroq):
        self.chiroq = chiroq

    def bajar(self) -> None:
        self.chiroq.yoq()

    def bekor_qil(self) -> None:
        self.chiroq.ochir()


class ChiroqniOchirishBuyrugi(Buyruq):
    def __init__(self, chiroq: Chiroq):
        self.chiroq = chiroq

    def bajar(self) -> None:
        self.chiroq.ochir()

    def bekor_qil(self) -> None:
        self.chiroq.yoq()


class AqlliPult:
    """Invoker — har bir tugmaga BIRON buyruq 'o'rnatiladi', pult buyruq mazmunini bilmaydi."""

    def __init__(self):
        self._tarix: list[Buyruq] = []

    def tugma_bos(self, buyruq: Buyruq) -> None:
        buyruq.bajar()
        self._tarix.append(buyruq)

    def oxirgisini_bekor_qil(self) -> None:
        if self._tarix:
            self._tarix.pop().bekor_qil()


mehmonxona_chirogi = Chiroq("Mehmonxona")
pult = AqlliPult()

pult.tugma_bos(ChiroqniYoqishBuyrugi(mehmonxona_chirogi))
# [Mehmonxona] chiroq YONDI

pult.oxirgisini_bekor_qil()
# [Mehmonxona] chiroq O'CHDI
```

## Keng tarqalgan xatolar

**Xato 1:** `bekor_qil()` metodida oldingi holatni saqlamasdan, "teskari amalni" qo'pol hisoblash.
❌
```python
class QiymatniKopaytirishBuyrugi(Buyruq):
    def __init__(self, obyekt, koeffitsient):
        self.obyekt = obyekt
        self.koeffitsient = koeffitsient

    def bajar(self):
        self.obyekt.qiymat *= self.koeffitsient

    def bekor_qil(self):
        self.obyekt.qiymat /= self.koeffitsient   # agar koeffitsient 0 bo'lsa — ZeroDivisionError!
```
Agar `koeffitsient` 0 bo'lsa, `bajar()` qiymatni 0ga aylantiradi, lekin `bekor_qil()` 0 ga bo'lishga urinib xato beradi — asl qiymat **abadiy yo'qolgan**.
✅ To'g'ri: ayniqsa qaytarib bo'lmaydigan (lossy) amallarda, `bekor_qil()` uchun oldingi holatni `bajar()` chaqirilishidan OLDIN saqlab qo'ying: `self._eski_qiymat = self.obyekt.qiymat` va `bekor_qil()`da shu qiymatni qaytaring.

**Xato 2:** Buyruq obyektini **qayta ishlatish** (bitta buyruqni ikki marta bajarish), holat saqlangan buyruqlarda xato beradi.
❌
```python
buyruq = MatnQoshishBuyrugi(matn, "test")
buyruq.bajar()
buyruq.bajar()   # IKKI marta qo'shiladi, lekin bekor_qil() faqat BIR martalik "test"ni oladi deb kutiladi
buyruq.bekor_qil()   # faqat bitta "test" o'chadi, biri qolib ketadi
```
✅ To'g'ri: har bir `bajar()` chaqiruvi uchun **yangi** buyruq obyekti yarating, yoki buyruq ichida necha marta bajarilganini hisoblab, `bekor_qil()`da shuncha marta teskari amalni bajaring.

**Xato 3:** Chaqiruvchi (invoker) buyruqning ICHKI implementatsiyasini "bilib qolishi" (interfeysni buzish).
❌
```python
class AqlliPult:
    def tugma_bos(self, buyruq):
        if isinstance(buyruq, ChiroqniYoqishBuyrugi):   # invoker buyruq TURINI tekshiradi!
            buyruq.chiroq.yoq()   # to'g'ridan-to'g'ri ICHKI atributga kirish
        else:
            buyruq.bajar()
```
Bu — Command naqshining butun maqsadini yo'qqa chiqaradi: invoker endi har bir yangi buyruq turi haqida bilishga majbur, aynan Strategy/Command naqshlari oldini olishga harakat qilgan `if/elif` zanjiri qaytib keladi.
✅ To'g'ri: invoker **faqat** `Buyruq` interfeysi (`bajar()`/`bekor_qil()`) orqali ishlasin, qaysi konkret klass ekanligi mutlaqo muhim bo'lmasin.

## Mashq/topshiriq

**(Oson)** `Kalkulyator` klassi yozing (`natija` atributi bilan). `QoshishBuyrugi` va `AyirishBuyrugi` klasslarini — har biri `bajar()` va `bekor_qil()` bilan — yozing. Ikkita buyruqni ketma-ket bajarib, so'ngra ikkisini ham bekor qilib ko'ring.

**(O'rtacha)** Yuqoridagi `AqlliPult`ga `MakroBuyruq`dan foydalanib, "Hammasini o'chirish" tugmasini qo'shing — u bir nechta xonadagi chiroqlarni **bitta** buyruq sifatida o'chirsin, va bitta `oxirgisini_bekor_qil()` chaqiruvi bilan **barchasi** qaytib yonsin.

**(Qiyin)** Buyruqlar jurnalini (log) fayl sifatida saqlash imkonini beruvchi tizim yozing: har bir `Buyruq` obyekti `tasvir()` metodiga ega bo'lsin (masalan, `"ChiroqniYoqishBuyrugi: Mehmonxona"`), va `BuyruqlarTarixi.bajar()` metodi har safar buyruq bajarilganda uning tasvirini ichki `list`ga ("jurnal") qo'shib borsin. `jurnalni_chiqar()` metodi — barcha bajarilgan amallarni vaqt tartibida chop etsin.

## Qisqacha xulosa

Command naqshi — "nima qilish kerak" degan so'rovni (buyruq, uni bajaruvchi obyekt va ixtiyoriy ravishda uni bekor qilish mantiqi bilan birga) alohida obyekt sifatida qadoqlab, chaqiruvchi (invoker) kodni buyruqning ichki tafsilotlaridan butunlay ajratadi; bu — Undo/Redo stacklari, buyruqlarni navbatga qo'yib keyinroq bajarish, va bir nechta amalni bitta "makro-buyruq" sifatida guruhlashni tabiiy ravishda imkon qiladi. Naqshning asosiy xavfi — qaytarib bo'lmaydigan amallarda eski holatni saqlashni unutish yoki bitta buyruq obyektini noto'g'ri qayta ishlatishdir; to'g'ri qo'llanganda esa, u matn muharrirlari, GUI/CLI tizimlari va task queue (Celery kabi) arxitekturalarining markazida yotadi.
