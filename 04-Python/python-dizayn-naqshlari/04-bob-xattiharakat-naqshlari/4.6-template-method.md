# Template Method naqshi

## Bu darsda nimalarni o'rganasiz

- Template Method naqshi qanday muammoni hal qilishini tushuntira olasiz
- Algoritm "skeletini" bazaviy klassda, o'zgaruvchi qadamlarni subklasslarda qoldirish uslubini qo'llay olasiz
- `abc.ABC` va `@abstractmethod` orqali Template Method'ni majburiy qiladigan "qattiq kontrakt" qura olasiz
- "Hook" (ilgak) metodlar — ixtiyoriy override qilinadigan qadamlar — tushunchasini bilasiz
- Template Method va Strategy naqshlari orasidagi farqni (meros vs kompozitsiya) tushuntira olasiz

## Nazariy qism

### Qanday muammoni hal qiladi

Faraz qiling, sizda bir nechta turdagi hisobot tayyorlash jarayoni bor: PDF hisobot, CSV hisobot, HTML hisobot. Barcha hisobotlar **bir xil umumiy qadamlardan** o'tadi: "ma'lumotni olish" → "ma'lumotni qayta ishlash" → "formatlash" → "saqlash". Lekin har bir qadamning **konkret bajarilishi** hisobot turiga qarab farq qiladi.

Tajribasiz yechim — har bir hisobot turi uchun **butun jarayonni boshidan oxirigacha** qayta yozish:

```python
class PdfHisobot:
    def yaratish(self):
        malumot = self._malumotni_ol()
        qayta_ishlangan = self._qayta_ishla(malumot)
        formatlangan = self._pdf_formatla(qayta_ishlangan)
        self._saqla(formatlangan, "pdf")

class CsvHisobot:
    def yaratish(self):
        malumot = self._malumotni_ol()          # TAKRORLANGAN!
        qayta_ishlangan = self._qayta_ishla(malumot)   # TAKRORLANGAN!
        formatlangan = self._csv_formatla(qayta_ishlangan)
        self._saqla(formatlangan, "csv")          # TAKRORLANGAN!
```

Muammo: "ma'lumotni olish", "qayta ishlash" va "saqlash" qadamlari **ikki joyda bir xil**, faqat "formatlash" farq qiladi — lekin kod **ikki marta** yozilgan. Agar "qayta ishlash" logikasi o'zgarsa (masalan, yangi filtr qo'shilsa), **har bir** hisobot klassida alohida-alohida o'zgartirishga to'g'ri keladi — bu klassik **kod takrorlanishi** (DRY tamoyilining buzilishi).

**Template Method naqshi** — buni hal qiladi: umumiy algoritm **ketma-ketligini** ("skelet") **bazaviy klassda, bir marta** yozib qo'yadi, va faqat **farq qiladigan qadamlarni** abstrakt metodlar sifatida belgilaydi — ularning konkret bajarilishini subklasslarga topshiradi.

### Asosiy tuzilma

```python
from abc import ABC, abstractmethod


class HisobotYaratuvchi(ABC):
    """Bazaviy klass — algoritm SKELETINI belgilaydi, u O'ZGARMAS."""

    def yaratish(self) -> str:   # bu — TEMPLATE METHOD, override QILINMAYDI
        malumot = self._malumotni_ol()
        qayta_ishlangan = self._qayta_ishla(malumot)
        formatlangan = self._formatla(qayta_ishlangan)   # FARQ QILADIGAN qadam
        self._saqla(formatlangan)
        return formatlangan

    def _malumotni_ol(self) -> list:
        print("Ma'lumotlar bazasidan ma'lumot olinmoqda...")
        return [10, 20, 30, 40]

    def _qayta_ishla(self, malumot: list) -> list:
        print("Ma'lumot tozalanmoqda va saralanmoqda...")
        return sorted(malumot)

    @abstractmethod
    def _formatla(self, malumot: list) -> str:
        """Faqat SHU qadam subklasslarga qoldiriladi."""
        ...

    def _saqla(self, formatlangan: str) -> None:
        print(f"Saqlandi: {formatlangan[:30]}...")


class PdfHisobot(HisobotYaratuvchi):
    def _formatla(self, malumot: list) -> str:
        return f"[PDF HUJJATI] Ma'lumotlar: {malumot}"


class CsvHisobot(HisobotYaratuvchi):
    def _formatla(self, malumot: list) -> str:
        return ",".join(str(x) for x in malumot)


pdf = PdfHisobot()
pdf.yaratish()
# Ma'lumotlar bazasidan ma'lumot olinmoqda...
# Ma'lumot tozalanmoqda va saralanmoqda...
# Saqlandi: [PDF HUJJATI] Ma'lumotlar: [1...

csv = CsvHisobot()
csv.yaratish()
# Ma'lumotlar bazasidan ma'lumot olinmoqda...
# Ma'lumot tozalanmoqda va saralanmoqda...
# Saqlandi: 10,20,30,40...
```

E'tibor bering: `yaratish()` metodi — **template method** (naqsh nomi aynan shu metoddan kelgan) — bazaviy klassda **bir marta** yozilgan, va u **hech qachon** subklasslarda qayta yozilmaydi (override qilinmaydi). Faqat `_formatla()` — farq qiladigan **yagona** qadam — har bir subklassda alohida belgilanadi. `_malumotni_ol()`, `_qayta_ishla()`, `_saqla()` — bitta joyda yozilgan, **barcha** hisobot turlariga avtomatik tegishli.

### `abc.ABC` bilan bog'liqligi — majburiy kontrakt

4.5-darsda (OOP bobida) ko'rgan `abc.ABC` va `@abstractmethod` — Template Method naqshining **eng tabiiy hamkori**. `@abstractmethod` deb belgilangan qadam (`_formatla`) — Python'ga **majburiy** ravishda har bir subklassda override qilinishini "majburlaydi":

```python
hisobot = HisobotYaratuvchi()   # TypeError!
# TypeError: Can't instantiate abstract class HisobotYaratuvchi
# with abstract method _formatla
```

Agar subklass `_formatla()`ni unutib qoldirsa, Python **darhol, obyekt yaratilishi paytida** xato beradi — bu xatoni "keyinroq, `yaratish()` chaqirilganda `AttributeError` yoki `NotImplementedError` bilan" topishdan ko'ra ancha xavfsizroq. `abc.ABC` — Template Method naqshini "ixtiyoriy tavsiya"dan "til darajasida nazorat qilinadigan kontrakt"ga aylantiradi.

### Hook metodlar — ixtiyoriy qadamlar

Ba'zan algoritmning bir qadami **majburiy emas**, balki **ixtiyoriy** ravishda override qilinishi mumkin bo'lishi kerak — bunga **hook (ilgak) metod** deyiladi. Hook — abstrakt emas, lekin **standart (bo'sh yoki minimal) implementatsiyaga** ega bo'ladi, shunda subklass uni e'tiborsiz qoldirsa ham xato bermaydi:

```python
class HisobotYaratuvchi(ABC):
    def yaratish(self) -> str:
        malumot = self._malumotni_ol()
        qayta_ishlangan = self._qayta_ishla(malumot)
        formatlangan = self._formatla(qayta_ishlangan)
        if self._emailga_yuborish_kerakmi():    # HOOK orqali shartli qadam
            self._emailga_yubor(formatlangan)
        self._saqla(formatlangan)
        return formatlangan

    def _emailga_yuborish_kerakmi(self) -> bool:
        return False   # STANDART holat — hech kim majburlanmaydi override qilishga

    def _emailga_yubor(self, formatlangan: str) -> None:
        print(f"Email yuborildi: {formatlangan[:20]}...")

    # ... qolgan metodlar yuqoridagidek


class EmailliPdfHisobot(HisobotYaratuvchi):
    def _formatla(self, malumot):
        return f"[PDF] {malumot}"

    def _emailga_yuborish_kerakmi(self) -> bool:   # HOOK override qilindi
        return True   # bu TUR uchun email yuborish YOQILGAN


class OddiyCsvHisobot(HisobotYaratuvchi):
    def _formatla(self, malumot):
        return ",".join(map(str, malumot))
    # _emailga_yuborish_kerakmi() OVERRIDE QILINMAGAN — standart False ishlatiladi, XATO BERMAYDI
```

Farqni aniq ko'ring: `_formatla()` — **abstrakt**, uni override qilmaslik `TypeError`ga olib keladi (majburiy qadam). `_emailga_yuborish_kerakmi()` — **hook**, uni override qilmaslik xavfsiz, shunchaki standart xatti-harakat (`False`) ishlatiladi (ixtiyoriy qadam). Bu ikki tur — Template Method naqshining **moslashuvchanligini** ta'minlaydigan asosiy vosita: algoritmning qaysi qismlari **shart**, qaysilari **ixtiyoriy** ekanligini aniq ajratish.

### Template Method va Strategy — meros vs kompozitsiya

Template Method va Strategy — ikkisi ham "algoritmning bir qismini almashtirish" haqida, lekin **mutlaqo boshqa mexanizm** orqali:

| | Template Method | Strategy |
|---|---|---|
| Mexanizm | **Meros** (inheritance) — subklass yaratiladi | **Kompozitsiya** (composition) — obyekt tashqaridan "in'ektsiya" qilinadi |
| Nima o'zgaradi | Algoritmning **bir qismi** (bazaviy klass bog'lab qo'ygan qolgan qismlar o'zgarmaydi) | **Butun algoritm** (strategiya to'liq almashtiriladi) |
| Moslashuvchanlik | Runtime'da o'zgartirib bo'lmaydi — subklass **kompilyatsiya/yozilish vaqtida** belgilanadi | Runtime'da osongina almashtiriladi (`obyekt.strategiya = yangi_strategiya`) |
| Qachon tanlanadi | Qadamlar ketma-ketligi **qattiq, o'zgarmas** bo'lishi, lekin ba'zi qadamlar farqlanishi kerak bo'lsa | Butun algoritm mustaqil "modul" sifatida almashtirilishi kerak bo'lsa |

4.1-darsda ko'rgan "kompozitsiya merosdan ko'ra ko'proq afzal (favor composition over inheritance)" tamoyiliga ko'ra, zamonaviy Python kodida ko'pincha Strategy Template Method'dan ko'ra afzal ko'riladi — lekin Template Method hali ham **qadamlar ketma-ketligi qattiq belgilangan**, faqat alohida bosqichlar farqlanishi kerak bo'lgan holatlarda (masalan, test freymvorklarining `setUp()`/`test_*()`/`tearDown()` tuzilishi) juda tabiiy va keng qo'llaniladi.

## Amaliy misol

Ma'lumotlarni qayta ishlash quvuri (data pipeline) — turli manbalardan (CSV, API) o'qib, bir xil umumiy jarayon bilan tozalaydigan tizim:

```python
# malumot_quvuri.py
from abc import ABC, abstractmethod


class MalumotQuvuri(ABC):
    """Shablon — barcha quvurlar BIR XIL qadamlardan o'tadi."""

    def ishga_tushir(self) -> dict:
        xom_malumot = self._oqish()
        tozalangan = self._tozalash(xom_malumot)
        tekshirilgan = self._validatsiya(tozalangan)
        natija = self._hisoblash(tekshirilgan)
        self._hisobot_chiqar(natija)
        return natija

    @abstractmethod
    def _oqish(self) -> list:
        """Qayerdan o'qish — manbaga qarab FARQ QILADI."""
        ...

    def _tozalash(self, malumot: list) -> list:
        # umumiy tozalash — hamma quvurlar uchun BIR XIL
        return [x for x in malumot if x is not None]

    def _validatsiya(self, malumot: list) -> list:
        # hook — standart holatda hech narsa qilmaydi
        return malumot

    def _hisoblash(self, malumot: list) -> dict:
        return {
            "jami": sum(malumot),
            "soni": len(malumot),
            "ortacha": sum(malumot) / len(malumot) if malumot else 0,
        }

    def _hisobot_chiqar(self, natija: dict) -> None:
        print(f"Natija: jami={natija['jami']}, o'rtacha={natija['ortacha']:.2f}")


class CsvQuvuri(MalumotQuvuri):
    def __init__(self, qator: str):
        self.qator = qator

    def _oqish(self) -> list:
        print("CSV qatordan o'qilmoqda...")
        return [float(x) if x.strip() else None for x in self.qator.split(",")]


class ApiQuvuri(MalumotQuvuri):
    def __init__(self, soxta_javob: list):
        self.soxta_javob = soxta_javob   # haqiqiy loyihada bu — tarmoq so'rovi javobi

    def _oqish(self) -> list:
        print("API'dan ma'lumot olinmoqda...")
        return self.soxta_javob

    def _validatsiya(self, malumot: list) -> list:
        # API quvuri uchun QO'SHIMCHA qoida: manfiy qiymatlar olib tashlanadi
        print("API ma'lumoti qo'shimcha tekshirilmoqda (manfiylar olib tashlanadi)...")
        return [x for x in malumot if x >= 0]


csv_quvuri = CsvQuvuri("10,20,,30,40")
csv_quvuri.ishga_tushir()
# CSV qatordan o'qilmoqda...
# Natija: jami=100.0, o'rtacha=25.00

api_quvuri = ApiQuvuri([5, -3, 10, 15, -1])
api_quvuri.ishga_tushir()
# API'dan ma'lumot olinmoqda...
# API ma'lumoti qo'shimcha tekshirilmoqda (manfiylar olib tashlanadi)...
# Natija: jami=30, o'rtacha=10.00
```

`ApiQuvuri` — `_validatsiya()` hook metodini override qilib, **faqat o'ziga xos** qo'shimcha qoidani qo'shdi, qolgan barcha qadamlar (`_tozalash`, `_hisoblash`, `_hisobot_chiqar`) — `CsvQuvuri` bilan **bitta** umumiy kodda ishlaydi.

## Keng tarqalgan xatolar

**Xato 1:** Template method'ning o'zini subklassda override qilish — naqshning butun maqsadini yo'qotish.
❌
```python
class XatoliQuvur(MalumotQuvuri):
    def ishga_tushir(self):   # TEMPLATE METHOD'ning o'zini qayta yozish!
        malumot = self._oqish()
        return {"jami": sum(malumot)}   # boshqa barcha qadamlar (validatsiya, hisobot) YO'QOLDI
```
Agar subklass template method'ning o'zini override qilsa, bazaviy klassning butun g'oyasi — "umumiy algoritmni bir marta yozish" — yo'qoladi, va siz yana boshidagi muammoga (kod takrorlanishi) qaytasiz.
✅ To'g'ri: template method (`ishga_tushir`) **hech qachon** override qilinmasligi kerak — faqat belgilangan qadam metodlari (`_oqish`, `_validatsiya` va h.k.) override qilinadi. Ba'zi loyihalarda bu qoidani buzishning oldini olish uchun template method nomi oldiga `final_` kabi konvensiya qo'yiladi (Python'da haqiqiy `final` kalit so'zi yo'q, lekin `typing.final` dekoratori — statik tekshiruvchilar (`mypy`) uchun bu niyatni bildiradi).

**Xato 2:** Abstrakt qadam va hook metodni farqlamaslik.
❌
```python
class MalumotQuvuri(ABC):
    def _validatsiya(self, malumot):
        pass   # hech narsa qilmaydi, LEKIN @abstractmethod deb belgilanmagan va
               # ba'zi subklasslar buni UNUTIB QO'YADI, natija kutilmagan bo'ladi
```
Agar bir qadam **albatta** har bir subklassda alohida belgilanishi kerak bo'lsa, lekin u `@abstractmethod` emas, oddiy `pass`li metod sifatida yozilsa — subklass yozuvchisi uni "ixtiyoriy" deb o'ylab, unutib qo'yishi mumkin, va bu **jim** (silent) xatoga olib keladi, chunki Python hech qanday ogohlantirish bermaydi.
✅ To'g'ri: agar qadam **majburiy** bo'lsa — `@abstractmethod` bilan belgilang (Python obyekt yaratilishida xato beradi). Agar **ixtiyoriy** bo'lsa — oddiy metod sifatida, mazmunli standart xatti-harakat bilan qoldiring, va buni **hook** deb hujjatlashtiring (docstring orqali).

**Xato 3:** Juda ko'p, mayda qadamlarga bo'lib, algoritmni o'qib bo'lmas qilib qo'yish.
❌ Agar `yaratish()` metodi 15 ta alohida `self._qadam1()`, `self._qadam2()`, ... chaqiruvidan iborat bo'lsa, va har biri bitta qatorlik bo'lsa — bu "ortiqcha mo''jaz bo'lish" (over-engineering): algoritm mantig'ini tushunish uchun 15 ta metodni alohida ochib o'qishga majbur bo'lasiz.
✅ To'g'ri: qadamlarni **faqat haqiqatda farqlanishi kerak bo'lgan** joylarda ajratib, qolgan mantiqni to'g'ridan-to'g'ri template method ichida (yoki yirik, mantiqiy guruhlangan yordamchi metodlarda) qoldiring — granularity (mayda-chuyda bo'linish darajasi) amaliy zaruratga mos bo'lsin.

## Mashq/topshiriq

**(Oson)** `OvqatTayyorlash` abstrakt klassini yozing — `tayyorla()` template method bo'lsin: "Suv qaynatish" → `_asosiy_ingredientni_qosh()` (abstrakt) → "Servirovka qilish". `ChoyTayyorlash` va `KofeTayyorlash` subklasslarini yozing.

**(O'rtacha)** Yuqoridagi `OvqatTayyorlash`ga hook metod qo'shing: `_qoshimcha_kerakmi() -> bool` (standart `False`), agar `True` bo'lsa, `_qoshimcha_qosh()` chaqirilsin. `ShakarliChoyTayyorlash` subklassini yozing — u hook'ni `True` qilib, `_qoshimcha_qosh()`da "Shakar qo'shildi" chop etsin.

**(Qiyin)** Oddiy test freymvorkini Template Method bilan yozing: `TestHolati` abstrakt klassi — `ishga_tushir()` template method: `_sozlash()` (hook, standart bo'sh) → `_test()` (abstrakt) → `_tozalash()` (hook, standart bo'sh), va agar `_test()` `AssertionError` tashlasa, `ishga_tushir()` uni ushlab "FAIL" deb, aks holda "PASS" deb chop etsin — HAR QANDAY holatda (muvaffaqiyatli yoki muvaffaqiyatsiz) `_tozalash()` albatta chaqirilishini ta'minlang.

## Qisqacha xulosa

Template Method naqshi — algoritmning o'zgarmas, umumiy ketma-ketligini ("skeletini") bazaviy klassda bir marta yozib, faqat haqiqatan farq qiladigan qadamlarni abstrakt metodlar (`@abstractmethod` bilan majburiy) yoki hook metodlar (ixtiyoriy, standart xatti-harakat bilan) sifatida subklasslarga qoldirish g'oyasidir; bu kod takrorlanishini yo'qotadi va `abc.ABC` bilan birgalikda "qaysi qadam majburiy, qaysi ixtiyoriy" degan qattiq kontrakt yaratadi. Strategy naqshidan farqli ravishda, u **meros** orqali ishlaydi (runtime'da emas, subklass yozilish vaqtida belgilanadi) va algoritmning faqat **bir qismini**, butunini emas, almashtirishga mo'ljallangan — shu sababli u qadamlar ketma-ketligi qattiq, lekin ayrim bosqichlari farqlanishi kerak bo'lgan holatlarda (hisobot generatorlari, test freymvorklari, ma'lumot quvurlari) eng tabiiy yechim bo'lib qoladi.
