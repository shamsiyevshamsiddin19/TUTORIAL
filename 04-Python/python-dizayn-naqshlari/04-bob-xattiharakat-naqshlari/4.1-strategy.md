# Strategy naqshi

## Bu darsda nimalarni o'rganasiz

- Strategy (strategiya) naqshi qanday muammoni hal qilishini tushuntira olasiz
- Klassik OOP (interfeys + klasslar) va "pythonik" (oddiy funksiyalar) Strategy'ni farqlay olasiz
- Algoritmni runtime'da (dastur ishlab turganda) almashtirishni amalda qo'llay olasiz
- `sorted()`, `key=` kabi standart kutubxona funksiyalarida Strategy naqshining qanday "yashirin" ishlatilganini ko'ra olasiz
- Strategy naqshining qachon ortiqcha murakkablik keltirishini bilasiz

## Nazariy qism

### Qanday muammoni hal qiladi

Faraz qiling, sizda narxni hisoblaydigan funksiya bor, va chegirma turi bir necha xil: "oddiy mijoz" uchun chegirma yo'q, "doimiy mijoz" uchun 10%, "VIP mijoz" uchun 20% + bonus ball. Tajribasiz yechim — hammasini bitta funksiya ichiga `if/elif` zanjiri bilan joylash:

```python
def narxni_hisobla(narx, mijoz_turi):
    if mijoz_turi == "oddiy":
        return narx
    elif mijoz_turi == "doimiy":
        return narx * 0.9
    elif mijoz_turi == "vip":
        return narx * 0.8 - 5   # qo'shimcha bonus chegirma
    else:
        raise ValueError(f"Noma'lum mijoz turi: {mijoz_turi}")
```

Bu yechim ishlaydi, lekin **yopiq-ochiq tamoyilini (Open/Closed Principle)** buzadi: har safar yangi mijoz turi qo'shilganda, shu funksiyaning **ichini** o'zgartirishga majbur bo'lasiz — va bu funksiya qanchalik ko'p joyda ishlatilsa, o'zgartirish shunchalik xavfli bo'ladi (boshqa mijoz turlarini sinab ko'rmasdan buzib qo'yish xavfi). Bundan tashqari, test yozish qiyinlashadi — har bir `if` shoxobchasini alohida sinash uchun butun funksiyani chaqirishga majbursiz.

**Strategy naqshi** — aynan shu muammoni hal qiladi: har bir algoritmni (har bir "chegirma qoidasini") **alohida, almashtiriladigan obyekt** sifatida ажратиб oladi, va asosiy kod ("kontekst") faqat umumiy interfeys orqali, qaysi aniq algoritm ishlatilayotganini bilmasdan ishlaydi.

### Klassik (GoF) Strategy — interfeys orqali

```python
from abc import ABC, abstractmethod


class ChegirmaStrategiyasi(ABC):
    """Barcha chegirma strategiyalari shu interfeysga amal qiladi."""

    @abstractmethod
    def hisobla(self, narx: float) -> float:
        ...


class OddiyMijoz(ChegirmaStrategiyasi):
    def hisobla(self, narx: float) -> float:
        return narx


class DoimiyMijoz(ChegirmaStrategiyasi):
    def hisobla(self, narx: float) -> float:
        return narx * 0.9


class VipMijoz(ChegirmaStrategiyasi):
    def hisobla(self, narx: float) -> float:
        return max(narx * 0.8 - 5, 0)


class Buyurtma:
    """Kontekst — strategiyani ICHKI bilmaydi, faqat interfeys orqali chaqiradi."""

    def __init__(self, narx: float, strategiya: ChegirmaStrategiyasi):
        self.narx = narx
        self.strategiya = strategiya   # strategiya TASHQARIDAN "in'ektsiya" qilinadi

    def yakuniy_narx(self) -> float:
        return self.strategiya.hisobla(self.narx)


buyurtma1 = Buyurtma(100, DoimiyMijoz())
buyurtma2 = Buyurtma(100, VipMijoz())
print(buyurtma1.yakuniy_narx())    # 90.0
print(buyurtma2.yakuniy_narx())    # 75.0
```

Bu yerda `Buyurtma` klassi — **kontekst**. U qaysi chegirma qoidasi ishlatilayotganini bilmaydi, faqat `ChegirmaStrategiyasi` interfeysiga ishonadi (bu — **Liskov almashtirish tamoyili**ning amaliy ko'rinishi: har qanday subklass asl klass o'rnida ishlashi kerak). Yangi mijoz turi qo'shish uchun — yangi klass yoziladi, **mavjud kod umuman o'zgarmaydi**. Bu — Open/Closed tamoyilining to'g'ridan-to'g'ri qo'llanilishi.

### Pythonik Strategy — funksiyalar birinchi darajali obyekt bo'lgani uchun

Ko'pgina GoF naqshlari Java/C++ kabi tillarda "funksiyalarni mustaqil obyekt sifatida uzatib bo'lmasligi" muammosini aylanib o'tish uchun ixtiro qilingan — shuning uchun ularda strategiyaning har biri uchun **butun bir klass** yozishga majbursiz. Python'da funksiyalar — **birinchi darajali obyektlar** (3.1-darsda ko'rganingizdek): ularni o'zgaruvchiga saqlash, argument sifatida uzatish mumkin. Shuning uchun Strategy naqshi Python'da ko'pincha ancha soddalashadi:

```python
def oddiy_mijoz(narx: float) -> float:
    return narx


def doimiy_mijoz(narx: float) -> float:
    return narx * 0.9


def vip_mijoz(narx: float) -> float:
    return max(narx * 0.8 - 5, 0)


class Buyurtma:
    def __init__(self, narx: float, strategiya):
        self.narx = narx
        self.strategiya = strategiya   # endi bu — oddiy FUNKSIYA, klass emas

    def yakuniy_narx(self) -> float:
        return self.strategiya(self.narx)   # funksiyani to'g'ridan-to'g'ri chaqiramiz


buyurtma = Buyurtma(100, vip_mijoz)
print(buyurtma.yakuniy_narx())    # 75.0

# Hattoki lambda bilan ham — ad-hoc strategiya:
buyurtma2 = Buyurtma(200, lambda narx: narx * 0.5)
print(buyurtma2.yakuniy_narx())    # 100.0
```

Natija **aynan bir xil**, lekin abstract klass, uch dona subklass — hammasi yo'qoldi. Bu — "naqshni bilish" bilan "naqshni ko'r-ko'rona, har qanday tilda bir xil shaklda qo'llash" o'rtasidagi farqni ko'rsatadi: **naqsh — muammoning yechimi g'oyasi, konkret implementatsiya tilga qarab farq qiladi.**

### Standart kutubxonada yashiringan Strategy: `sorted(key=...)`

`sorted()` funksiyasi — bu Strategy naqshining juda keng tarqalgan, har kuni ishlatiladigan ko'rinishi:

```python
talabalar = [
    {"ism": "Ali", "ball": 85},
    {"ism": "Vali", "ball": 72},
    {"ism": "Guli", "ball": 93},
]

# "qanday saralash" — bu STRATEGIYA, va u key= orqali TASHQARIDAN uzatiladi
ball_boyicha = sorted(talabalar, key=lambda t: t["ball"])
ism_boyicha = sorted(talabalar, key=lambda t: t["ism"])
teskari_ball = sorted(talabalar, key=lambda t: t["ball"], reverse=True)
```

`sorted()` funksiyasining o'zi — **kontekst**: u ro'yxatni qanday saralashni bilmaydi, faqat `key` orqali berilgan funksiyaga (strategiyaga) ishonib, har bir element uchun "taqqoslash kaliti"ni so'raydi. Xuddi shu g'oya — `max()`, `min()`, `list.sort()` va hatto `functools.cmp_to_key`da ham qo'llaniladi. **Strategy naqshini "ixtiro qilish" shart emas — Python'ning o'zi standart funksiyalarida uni allaqachon qo'llagan.**

### Qachon klassik (klass-asosli), qachon funksional Strategy

| Holat | Tavsiya qilinadi |
|---|---|
| Strategiya **holatga ega** bo'lishi kerak (masalan, sozlamalar, ichki keshi bor) | Klass (`__init__`da holatni saqlash mumkin) |
| Strategiya — oddiy, sof hisoblash (holat yo'q) | Funksiya yoki `lambda` |
| Strategiyalar oilasi katta, kelajakda ko'p kengayishi kutiladi, interfeys muhim | `ABC` bilan klass (IDE yordamida, aniq kontrakt) |
| Strategiya faqat bir joyda, bir martalik ishlatiladi | Inline `lambda` yoki oddiy funksiya, alohida klass shart emas |

## Amaliy misol

To'lov tizimida turli to'lov usullari (karta, hamyon, kredit) — Strategy naqshi bilan, real loyihadagidek:

```python
# tolov_strategiyasi.py
from abc import ABC, abstractmethod
from dataclasses import dataclass


class TolovStrategiyasi(ABC):
    @abstractmethod
    def tolovni_amalga_oshir(self, summa: float) -> str:
        ...

    @abstractmethod
    def komissiya(self, summa: float) -> float:
        ...


class KartaOrqaliTolov(TolovStrategiyasi):
    def __init__(self, karta_raqami: str):
        self.karta_raqami = karta_raqami[-4:]   # faqat oxirgi 4 raqamni saqlaymiz

    def komissiya(self, summa: float) -> float:
        return summa * 0.015   # 1.5% bank komissiyasi

    def tolovni_amalga_oshir(self, summa: float) -> str:
        jami = summa + self.komissiya(summa)
        return f"Karta (****{self.karta_raqami}) orqali {jami:.2f} so'm yechib olindi"


class HamyonOrqaliTolov(TolovStrategiyasi):
    def __init__(self, balans: float):
        self.balans = balans

    def komissiya(self, summa: float) -> float:
        return 0.0   # ichki hamyonda komissiya yo'q

    def tolovni_amalga_oshir(self, summa: float) -> str:
        if summa > self.balans:
            raise ValueError("Hamyonda mablag' yetarli emas")
        self.balans -= summa
        return f"Hamyondan {summa:.2f} so'm yechildi (qoldiq: {self.balans:.2f})"


class KreditOrqaliTolov(TolovStrategiyasi):
    def komissiya(self, summa: float) -> float:
        return summa * 0.05   # kredit uchun yuqori komissiya

    def tolovni_amalga_oshir(self, summa: float) -> str:
        jami = summa + self.komissiya(summa)
        return f"Kredit hisobidan {jami:.2f} so'm yechib olindi (foiz qo'shilgan)"


@dataclass
class Savatcha:
    jami_summa: float
    strategiya: TolovStrategiyasi   # strategiya TASHQARIDAN beriladi

    def tolovni_yopish(self) -> str:
        return self.strategiya.tolovni_amalga_oshir(self.jami_summa)


savatcha1 = Savatcha(250_000, KartaOrqaliTolov("8600123412341234"))
savatcha2 = Savatcha(100_000, HamyonOrqaliTolov(balans=150_000))

print(savatcha1.tolovni_yopish())
# Karta (****1234) orqali 253750.00 so'm yechib olindi
print(savatcha2.tolovni_yopish())
# Hamyondan 100000.00 so'm yechildi (qoldiq: 50000.00)

# Runtime'da strategiyani ALMASHTIRISH — Strategy naqshining asosiy afzalligi:
savatcha1.strategiya = KreditOrqaliTolov()
print(savatcha1.tolovni_yopish())
# Kredit hisobidan 262500.00 so'm yechib olindi (foiz qo'shilgan)
```

E'tibor bering: `Savatcha` klassi hech qachon `if isinstance(strategiya, KartaOrqaliTolov)` kabi tekshiruv qilmaydi — u faqat `strategiya.tolovni_amalga_oshir(...)`ni chaqiradi, qaysi klass ekanligi mutlaqo muhim emas (bu — **duck typing**, 4.3-darsda ko'rgan polimorfizmning amaliy natijasi).

## Keng tarqalgan xatolar

**Xato 1:** Strategy o'rniga katta `if/elif` zanjirini saqlab qolish, "hozircha ishlayapti" deb.
❌
```python
def tolov(summa, usul):
    if usul == "karta":
        ...
    elif usul == "hamyon":
        ...
    # har yangi usul uchun shu funksiyani o'zgartirish kerak bo'ladi
```
Bu kod kichik loyihada ishlaydi, lekin usullar soni oshgani sayin funksiya tobora kattalashadi, test qilish qiyinlashadi va bitta usuldagi xato boshqa usullarni sinamasdan production'ga chiqib ketish xavfi oshadi.
✅ To'g'ri: har bir usulni alohida strategiya (klass yoki funksiya) sifatida ajratib, kontekst faqat umumiy interfeys orqali chaqirsin.

**Xato 2:** Strategiyalarni interfeyssiz, "o'xshash lekin bir xil bo'lmagan" metodlar bilan yozish.
❌
```python
class A:
    def hisoblash(self, narx): ...

class B:
    def hisobla(self, narx): ...   # metod nomi boshqacha!
```
`Buyurtma` klassi `strategiya.hisobla(...)`ni chaqirganda, `A` obyekti bilan ishlatilganda `AttributeError` beradi, chunki metod nomi mos kelmaydi.
✅ To'g'ri: `ABC` va `@abstractmethod` bilan **aniq interfeys** belgilang, shunda har bir subklass bir xil metod imzosiga amal qilishga majbur bo'ladi — yoki hech bo'lmaganda, barcha strategiyalarda metod nomini qo'lda bir xil qilib yozishga qattiq rioya qiling.

**Xato 3:** Strategiyani kontekst klassi ICHIDA yaratish (hardcode qilish), tashqaridan in'ektsiya qilmaslik.
❌
```python
class Buyurtma:
    def __init__(self, narx):
        self.narx = narx
        self.strategiya = DoimiyMijoz()   # qattiq "qotirilgan" (hardcoded)!
```
Bu holda Strategy naqshining asosiy maqsadi — runtime'da almashtirish imkoniyati — butunlay yo'qoladi, chunki `Buyurtma` doim faqat `DoimiyMijoz` strategiyasi bilan ishlaydi.
✅ To'g'ri: strategiyani konstruktor orqali (yoki `setter` bilan) tashqaridan qabul qiling — bu "dependency injection" tamoyili (5.3-darsda batafsil ko'riladi).

## Mashq/topshiriq

**(Oson)** `MasofaStrategiyasi` — matnni yozish uslubini tanlaydigan ikkita funksiya yozing: `katta_harflar(matn)` va `kichik_harflar(matn)`. So'ngra `Xabar` klassini yozing — u `matn` va `strategiya` (funksiya) qabul qilsin, `chiqar()` metodi strategiyani qo'llab natijani qaytarsin.

**(O'rtacha)** Fayl siqish (compression) uchun Strategy naqshini yozing: `ZipStrategiyasi` va `TarStrategiyasi` klasslari (har biri `siqish(fayl_nomi)` metodi bilan, haqiqiy siqish shart emas — faqat `f"{fayl_nomi}.zip siqildi"` kabi matn qaytarsin yetarli), va `FaylMenejeri` klassi — strategiyani runtime'da `strategiyani_ozgartir()` metodi bilan almashtirsin.

**(Qiyin)** Validatsiya tizimini Strategy naqshi bilan yozing: `UzunlikValidatori`, `RaqamBorligiValidatori`, `MaxsusBelgiValidatori` — har biri `tekshir(parol: str) -> bool` metodiga ega. `ParolTekshiruvchisi` klassi — strategiyalar **ro'yxatini** (bir nechta strategiyani birgalikda!) qabul qilsin va `barchasi_otdimi(parol)` metodi — faqat barcha strategiyalar `True` qaytarsa `True` qaytarsin.

## Qisqacha xulosa

Strategy naqshi — bir xil vazifani bajaradigan, lekin ichki algoritmi har xil bo'lgan kod bo'laklarini alohida, almashtiriladigan obyektlar (yoki Python'da — oddiy funksiyalar) sifatida ajratib, asosiy ("kontekst") kodni ulardan mustaqil qiladi; bu Open/Closed tamoyiliga rioya qilishga, `if/elif` zanjirlarini yo'qotishga va algoritmni runtime'da almashtirishga imkon beradi. Python'da funksiyalar birinchi darajali obyekt bo'lgani uchun, ko'p hollarda butun bir klass ierarxiyasi shart emas — `sorted(key=...)` kabi standart funksiyalarning o'zi Strategy naqshining kundalik, "yashirin" qo'llanilishidir. Keyingi darslarda ko'radigan Observer va Command naqshlari ham — xuddi shu "xatti-harakatni obyekt/funksiya sifatida ajratish" g'oyasining davomi.
