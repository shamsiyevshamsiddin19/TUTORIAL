# State naqshi

## Bu darsda nimalarni o'rganasiz

- State (holat) naqshi qanday muammoni hal qilishini tushuntira olasiz
- Obyektning holatiga qarab xatti-harakatini o'zgartirishni, katta `if/elif` zanjirisiz, yoza olasiz
- Holatlar orasidagi o'tishlarni (transition) qat'iy nazorat qila olasiz
- State naqshi va Strategy naqshining qanchalik o'xshash, lekin maqsadi jihatidan farqli ekanini tushuntira olasiz
- `Enum` bilan oddiy holat belgilash va to'liq State naqshi orasidagi farqni bilasiz

## Nazariy qism

### Qanday muammoni hal qiladi

Onlayn-do'kondagi buyurtma hayot sikli tasavvur qiling: `yangi` → `tolov_qilindi` → `yetkazilmoqda` → `yetkazildi`, yoki istalgan vaqtda `bekor_qilindi`. Har bir holatda **ruxsat etilgan amallar boshqacha**: masalan, "bekor qilish" faqat `yangi` yoki `tolov_qilindi` holatida mumkin, `yetkazildi` holatida — mumkin emas. Tajribasiz yechim:

```python
class Buyurtma:
    def __init__(self):
        self.holat = "yangi"

    def bekor_qil(self):
        if self.holat == "yangi" or self.holat == "tolov_qilindi":
            self.holat = "bekor_qilindi"
            print("Buyurtma bekor qilindi")
        elif self.holat == "yetkazilmoqda":
            print("Xato: yo'lda turgan buyurtmani bekor qilib bo'lmaydi")
        elif self.holat == "yetkazildi":
            print("Xato: yetkazilgan buyurtmani bekor qilib bo'lmaydi")
        # ... va BOSHQA har bir metod (tolovni_tasdiqla, yukla, va h.k.) uchun
        # xuddi shunday if/elif zanjirini TAKRORLASH kerak bo'ladi!
```

Muammo: `holat` qiymatiga qarab tekshiruv — **har bir metod ichida takrorlanadi**. Yangi holat (masalan, `"qaytarilmoqda"`) qo'shilsa, **barcha** metodlarni (bekor_qil, tolovni_tasdiqla, yukla, ...) birma-bir ochib, har birida `if/elif` zanjiriga yangi shoxcha qo'shishga to'g'ri keladi — bu xatolarga, unutilgan joylarga juda moyil.

**State naqshi** — buni hal qiladi: har bir holatni **alohida klass** sifatida ajratib, "shu holatda qaysi amal qanday ishlaydi" mantig'ini **shu holat klassining o'ziga** joylashtiradi. Asosiy obyekt (`Buyurtma`) endi faqat "joriy holat obyekti"ga ishora qiladi va barcha so'rovlarni unga **topshiradi** (delegate qiladi) — xuddi Strategy naqshidagi kabi, lekin farqi — **holat o'zi, o'z vazifasini bajarib bo'lgach, keyingi holatga o'tishni ham o'zi boshqaradi**.

### Asosiy tuzilma

```python
from abc import ABC, abstractmethod


class BuyurtmaHolati(ABC):
    @abstractmethod
    def tolovni_tasdiqla(self, buyurtma: "Buyurtma") -> None:
        ...

    @abstractmethod
    def yukla(self, buyurtma: "Buyurtma") -> None:
        ...

    @abstractmethod
    def bekor_qil(self, buyurtma: "Buyurtma") -> None:
        ...


class YangiHolat(BuyurtmaHolati):
    def tolovni_tasdiqla(self, buyurtma: "Buyurtma") -> None:
        print("To'lov tasdiqlandi")
        buyurtma.holatni_ozgartir(TolovQilinganHolat())

    def yukla(self, buyurtma: "Buyurtma") -> None:
        print("Xato: avval to'lov qilinishi kerak")

    def bekor_qil(self, buyurtma: "Buyurtma") -> None:
        print("Buyurtma bekor qilindi")
        buyurtma.holatni_ozgartir(BekorQilinganHolat())


class TolovQilinganHolat(BuyurtmaHolati):
    def tolovni_tasdiqla(self, buyurtma: "Buyurtma") -> None:
        print("Xato: to'lov allaqachon tasdiqlangan")

    def yukla(self, buyurtma: "Buyurtma") -> None:
        print("Buyurtma yuklandi, yetkazishga jo'natildi")
        buyurtma.holatni_ozgartir(YetkazilmoqdaHolat())

    def bekor_qil(self, buyurtma: "Buyurtma") -> None:
        print("To'lov qaytarildi, buyurtma bekor qilindi")
        buyurtma.holatni_ozgartir(BekorQilinganHolat())


class YetkazilmoqdaHolat(BuyurtmaHolati):
    def tolovni_tasdiqla(self, buyurtma: "Buyurtma") -> None:
        print("Xato: to'lov allaqachon tasdiqlangan")

    def yukla(self, buyurtma: "Buyurtma") -> None:
        print("Xato: buyurtma allaqachon yo'lda")

    def bekor_qil(self, buyurtma: "Buyurtma") -> None:
        print("Xato: yo'ldagi buyurtmani bekor qilib bo'lmaydi")


class BekorQilinganHolat(BuyurtmaHolati):
    def tolovni_tasdiqla(self, buyurtma): print("Xato: buyurtma bekor qilingan")
    def yukla(self, buyurtma): print("Xato: buyurtma bekor qilingan")
    def bekor_qil(self, buyurtma): print("Buyurtma allaqachon bekor qilingan")


class Buyurtma:
    """Kontekst — joriy holatga SO'ROVLARNI TOPSHIRADI, o'zi qaror qabul qilmaydi."""

    def __init__(self):
        self._holat: BuyurtmaHolati = YangiHolat()   # boshlang'ich holat

    def holatni_ozgartir(self, yangi_holat: BuyurtmaHolati) -> None:
        self._holat = yangi_holat
        print(f"  -> Yangi holat: {yangi_holat.__class__.__name__}")

    def tolovni_tasdiqla(self) -> None:
        self._holat.tolovni_tasdiqla(self)

    def yukla(self) -> None:
        self._holat.yukla(self)

    def bekor_qil(self) -> None:
        self._holat.bekor_qil(self)


buyurtma = Buyurtma()
buyurtma.yukla()               # Xato: avval to'lov qilinishi kerak
buyurtma.tolovni_tasdiqla()    # To'lov tasdiqlandi -> Yangi holat: TolovQilinganHolat
buyurtma.yukla()               # Buyurtma yuklandi... -> Yangi holat: YetkazilmoqdaHolat
buyurtma.bekor_qil()           # Xato: yo'ldagi buyurtmani bekor qilib bo'lmaydi
```

E'tibor bering: `Buyurtma` klassi endi **hech qanday** `if holat == "..."` tekshiruvini o'z ichida saqlamaydi. Har bir holatda "nima qilinishi mumkin, nima mumkin emas, va keyin qaysi holatga o'tiladi" — **shu holatning o'z klassida** joylashgan. Yangi holat (masalan, `QaytarilmoqdaHolat`) qo'shish — faqat **yangi klass yozish**, mavjud kodga tegmasdan.

### State va Strategy — nima farqi bor

Kod darajasida State va Strategy naqshlari **deyarli bir xil ko'rinadi** — ikkisi ham "kontekst" obyekti ichida almashtiriladigan yordamchi obyektga ega. Lekin **maqsad va boshqaruv** farq qiladi:

| | Strategy | State |
|---|---|---|
| Kim almashtiradi | **Tashqi kod** (kontekstdan tashqarida) strategiyani tanlaydi | **Holatning o'zi** keyingi holatga o'tishni hal qiladi |
| Holatlar bir-birini "bilishi" | Strategiyalar bir-biridan **mutlaqo mustaqil**, bir-birini bilmaydi | Holatlar ko'pincha **bir-biriga o'tishni** bilishi kerak (`YangiHolat` — `TolovQilinganHolat`ni yaratadi) |
| Maqsad | Bir xil vazifani **bajarish usulini** tanlash (masalan, saralash algoritmi) | Obyektning **ichki hayot sikli**ni, bosqichlar ketma-ketligini modellashtirish |
| Tipik misol | To'lov usuli, saralash kaliti | Buyurtma holati, TCP ulanish holati, oyinchi (`o'ynayapti`/`pauza`/`tugadi`) |

Qisqa qilib aytganda: **Strategy — "qanday qilish" haqida, State — "qayerda turganimiz va keyin qayerga o'tishimiz" haqida.**

### Oddiy holatlar uchun — `Enum` yetarli bo'lishi mumkin

Agar holatlar soni kam, o'tishlar mantiqi sodda bo'lsa, to'liq State naqshi (har bir holat uchun alohida klass) — **ortiqcha murakkablik** bo'lishi mumkin. Shu holatda `Enum` (4.4-darsda ko'rilgan) bilan oddiygina belgilab, bitta joyda tekshirish ko'pincha yetarli:

```python
from enum import Enum, auto


class LampaHolati(Enum):
    OCHIRILGAN = auto()
    YONGAN = auto()


class Lampa:
    def __init__(self):
        self.holat = LampaHolati.OCHIRILGAN

    def tugmani_bos(self):
        if self.holat == LampaHolati.OCHIRILGAN:
            self.holat = LampaHolati.YONGAN
            print("Lampa yondi")
        else:
            self.holat = LampaHolati.OCHIRILGAN
            print("Lampa o'chdi")
```

Bu yerda faqat **ikki** holat va **bitta** oddiy o'tish mavjud — to'liq State naqshi (ikkita klass, abstract interfeys) bu oddiy vazifa uchun shart emas. **State naqshini qachon qo'llash kerakligi mezoni:** holatlar soni ko'p (3+), har bir holatda ruxsat etilgan amallar sezilarli farq qiladi, va/yoki o'tish mantiqi vaqt o'tishi bilan murakkablashishi kutilsa — to'liq naqsh o'zini oqlaydi.

## Amaliy misol

Media pleer — `to'xtatilgan`/`o'ynayapti`/`pauzada` holatlari, har birida tugmalar boshqacha ishlaydi:

```python
# media_pleer.py
from abc import ABC, abstractmethod


class PleerHolati(ABC):
    @abstractmethod
    def oynat(self, pleer: "MediaPleer") -> None: ...
    @abstractmethod
    def pauza_qil(self, pleer: "MediaPleer") -> None: ...
    @abstractmethod
    def toxtat(self, pleer: "MediaPleer") -> None: ...


class ToxtatilganHolat(PleerHolati):
    def oynat(self, pleer):
        print(f"▶ Ijro etilmoqda: {pleer.joriy_qoshiq}")
        pleer.holatni_ozgartir(OynayotganHolat())

    def pauza_qil(self, pleer):
        print("Hech narsa ijro etilmayapti, pauza qilib bo'lmaydi")

    def toxtat(self, pleer):
        print("Allaqachon to'xtatilgan")


class OynayotganHolat(PleerHolati):
    def oynat(self, pleer):
        print("Allaqachon ijro etilmoqda")

    def pauza_qil(self, pleer):
        print(f"⏸ Pauza: {pleer.joriy_qoshiq}")
        pleer.holatni_ozgartir(PauzadagiHolat())

    def toxtat(self, pleer):
        print(f"⏹ To'xtatildi: {pleer.joriy_qoshiq}")
        pleer.holatni_ozgartir(ToxtatilganHolat())


class PauzadagiHolat(PleerHolati):
    def oynat(self, pleer):
        print(f"▶ Davom ettirilmoqda: {pleer.joriy_qoshiq}")
        pleer.holatni_ozgartir(OynayotganHolat())

    def pauza_qil(self, pleer):
        print("Allaqachon pauzada")

    def toxtat(self, pleer):
        print(f"⏹ To'xtatildi: {pleer.joriy_qoshiq}")
        pleer.holatni_ozgartir(ToxtatilganHolat())


class MediaPleer:
    def __init__(self, qoshiq: str):
        self.joriy_qoshiq = qoshiq
        self._holat: PleerHolati = ToxtatilganHolat()

    def holatni_ozgartir(self, yangi_holat: PleerHolati) -> None:
        self._holat = yangi_holat

    def oynat(self): self._holat.oynat(self)
    def pauza_qil(self): self._holat.pauza_qil(self)
    def toxtat(self): self._holat.toxtat(self)


pleer = MediaPleer("Imagine Dragons - Believer")
pleer.oynat()         # ▶ Ijro etilmoqda: Imagine Dragons - Believer
pleer.pauza_qil()      # ⏸ Pauza: Imagine Dragons - Believer
pleer.pauza_qil()      # Allaqachon pauzada
pleer.oynat()         # ▶ Davom ettirilmoqda: Imagine Dragons - Believer
pleer.toxtat()        # ⏹ To'xtatildi: Imagine Dragons - Believer
```

## Keng tarqalgan xatolar

**Xato 1:** Holat o'tishini kontekst klassida qoldirish, holat klasslarida emas.
❌
```python
class Buyurtma:
    def yukla(self):
        if isinstance(self._holat, TolovQilinganHolat):   # kontekst holat TURINI tekshiradi!
            print("yuklandi")
            self._holat = YetkazilmoqdaHolat()
        else:
            self._holat.yukla(self)
```
Bu — State naqshining asosiy maqsadini yo'qqa chiqaradi: kontekst yana har bir holat haqida "bilishga" majbur bo'lib qoladi, yangi holat qo'shilganda kontekst kodini o'zgartirishga to'g'ri keladi.
✅ To'g'ri: o'tish mantig'ini **har doim** holat klassining ichida (`self.holatni_ozgartir(...)` chaqiruvi orqali) saqlang, kontekst faqat `self._holat.yukla(self)` deb **topshiradi**.

**Xato 2:** Holat obyektlarini har safar yangi yaratish o'rniga, ularni **ulashilgan holatda** (shared mutable state) saqlashga harakat qilish — agar holat klassida o'zgaruvchi atribut bo'lsa, xato.
❌
```python
# Agar holat klassi o'zida o'zgaruvchan ma'lumot saqlasa:
class OynayotganHolat(PleerHolati):
    def __init__(self):
        self.ijro_vaqti = 0   # bu holat obyekti BIR NECHA pleer orasida ulashilsa — muammo!

YAGONA_OYNAYOTGAN = OynayotganHolat()   # singleton sifatida bir nechta pleerga berilsa

pleer1.holatni_ozgartir(YAGONA_OYNAYOTGAN)
pleer2.holatni_ozgartir(YAGONA_OYNAYOTGAN)   # ikkisi BIR XIL holat obyektini "ulashadi"!
```
Agar holat klassi o'zida hech qanday o'zgaruvchan ma'lumot saqlamasa (yuqoridagi asosiy misollardagi kabi), holatlarni **bir marta yaratib, qayta ishlatish** (hatto modul darajasidagi konstantalar sifatida) xavfsiz va samarali — lekin agar holat o'zida ma'lumot saqlasa, **har bir kontekst uchun alohida holat nusxasi** yaratilishi shart.
✅ To'g'ri: holat klasslari odatda "stateless" (o'z ichida o'zgaruvchan ma'lumot saqlamaydigan) qilib loyihalanadi — barcha kerakli ma'lumot kontekst (`pleer`) orqali uzatiladi, shunda holat obyektlarini xavfsiz qayta ishlatish (yoki hatto Singleton qilish) mumkin bo'ladi.

**Xato 3:** Har bir metod uchun **barcha** holat klasslarida bir xil xato xabarini qo'lda takrorlash — DRY tamoyilining buzilishi.
❌ Har bir holat klassida bir xil `print("Xato: bu amal joriy holatda mumkin emas")` qatorini qayta-qayta yozish.
✅ To'g'ri: `BuyurtmaHolati` abstract klassida **default** (standart) implementatsiya bering — faqat ruxsat etilgan holatlarda uni **override** qiling:
```python
class BuyurtmaHolati(ABC):
    def tolovni_tasdiqla(self, buyurtma):
        print(f"Xato: {self.__class__.__name__}da bu amal mumkin emas")   # DEFAULT

class YangiHolat(BuyurtmaHolati):
    def tolovni_tasdiqla(self, buyurtma):   # faqat KERAKLI holatda override qilinadi
        buyurtma.holatni_ozgartir(TolovQilinganHolat())
```

## Mashq/topshiriq

**(Oson)** Svetofor (traffic light) uchun State naqshini yozing: `QizilHolat`, `SarikHolat`, `YashilHolat` — har birida `keyingisiga_otish()` metodi bo'lsin, tartib: qizil → yashil → sariq → qizil (davriy).

**(O'rtacha)** Bankomat (ATM) uchun State naqshini yozing: `KartaKutilmoqdaHolat` (faqat `karta_kiritildi()` qabul qiladi), `PinKutilmoqdaHolat` (faqat `pin_kiritildi(pin)` qabul qiladi, noto'g'ri bo'lsa `KartaKutilmoqdaHolat`ga qaytadi), `PulBerishHolat` (faqat `pul_so'raldi(summa)` qabul qiladi, so'ngra avtomatik `KartaKutilmoqdaHolat`ga qaytadi).

**(Qiyin)** Yuqoridagi `BuyurtmaHolati` tizimiga **tarix** (history) qo'shing: `Buyurtma` klassi barcha o'tgan holatlarni (`list` sifatida, vaqt belgisi — `datetime` bilan birga) saqlab borsin, va `tarixni_korsat()` metodi — buyurtma qachon qaysi holatga o'tganini to'liq chop etsin.

## Qisqacha xulosa

State naqshi — obyektning xatti-harakatini uning **ichki holatiga** qarab o'zgartirish uchun, har bir holatni alohida klass sifatida ajratib, "shu holatda qaysi amal qanday ishlaydi va keyin qaysi holatga o'tiladi" mantig'ini shu holat klassining ichiga joylashtiradi; kontekst obyekti esa faqat joriy holatga so'rovlarni topshiradi, hech qanday `if holat == ...` tekshiruvini o'z ichida saqlamaydi. Kod ko'rinishi jihatidan Strategy naqshiga juda o'xshash bo'lsa-da, farqi — holatlarning o'zi keyingi holatga o'tishni **boshqarishida**; oddiy, kam sondagi holatlar uchun esa to'liq naqsh o'rniga `Enum` bilan oddiy tekshiruv ko'pincha yetarli va sodda yechim bo'ladi.
