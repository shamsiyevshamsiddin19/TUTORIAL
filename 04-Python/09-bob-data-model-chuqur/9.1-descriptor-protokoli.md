# Descriptor protokoli — `property`, metod va funksiyaning siri

## Bu darsda nimalarni o'rganasiz

- **Descriptor protokoli** (`__get__`, `__set__`, `__delete__`) nima ekanini va qanday ishlashini bilib olasiz
- **Data descriptor** va **non-data descriptor** orasidagi farqni va bu farq nima uchun muhimligini tushunasiz
- 4-bobda ishlatgan `@property`ning haqiqatda **qanday** ishlashini — o'zingiz descriptor yozib — tushunasiz
- Nega oddiy funksiya klass ichida "metod"ga aylanishini (`self` avtomatik uzatilishini) descriptor orqali tushunasiz

## Nazariy qism

### Bitta savol — ko'p sirlarni ochadi

4.3-darsda `@property` dekoratorini ishlatgan bo'lishingiz mumkin — u oddiy metodni "atribut kabi" chaqirish imkonini beradi. Lekin savol tug'iladi: **`@property` qanday qilib buni amalga oshiradi?** Va yana bir savol: nega `obyekt.metod()` yozganingizda, Python avtomatik ravishda `self`ni birinchi argument sifatida uzatadi (4.1-darsda ko'rganingizdek)? Bu ikkala savolning javobi **bitta xuddi shu mexanizm** — **descriptor protokoli**.

**Manba:** Ushbu dars Python rasmiy "Descriptor HowTo Guide" (docs.python.org/3/howto/descriptor.html) hujjati asosida tuzilgan — bu, Raymond Hettinger (CPython'ning uzoq yillik yadro dasturchisi) tomonidan yozilgan, descriptor mavzusidagi eng nufuzli manba.

### Descriptor nima

**Descriptor** — bu, oddiy qilib aytganda, quyidagi maxsus metodlardan **kamida bittasini** amalga oshiruvchi har qanday klass:

- **`__get__(self, obyekt, obyekt_turi)`** — atribut **o'qilganda** chaqiriladi
- **`__set__(self, obyekt, qiymat)`** — atributga qiymat **yozilganda** chaqiriladi
- **`__delete__(self, obyekt)`** — atribut **o'chirilganda** (`del`) chaqiriladi

Descriptor'ning "sehri" shunda: agar bu metodlar **klass darajasidagi** atributda mavjud bo'lsa, Python odatiy "avval instance `__dict__`ini tekshir" qoidasini **chetlab o'tib**, descriptor metodlarini chaqiradi.

```python
class OddiyDescriptor:
    def __get__(self, obyekt, obyekt_turi=None):
        print(f"__get__ chaqirildi: obyekt={obyekt}, tur={obyekt_turi}")
        return 42

    def __set__(self, obyekt, qiymat):
        print(f"__set__ chaqirildi: qiymat={qiymat}")


class MeningKlassim:
    x = OddiyDescriptor()   # descriptor KLASS ATRIBUTI sifatida o'rnatiladi


obj = MeningKlassim()
print(obj.x)        # __get__ chaqiriladi -> "42" chop etiladi
obj.x = 100          # __set__ chaqiriladi -> "qiymat=100" chop etiladi
```

Diqqat qiling: `obj.x = 100` yozilganda, aslida `obj.__dict__`ga hech narsa yozilmaydi — buning o'rniga `OddiyDescriptor.__set__` chaqiriladi! Bu — descriptor'ning eng muhim xususiyati: u atributga murojaatni **to'liq nazorat qilish** imkonini beradi.

### Data vs non-data descriptor — nega bu farq muhim

Descriptorlar ikki turga bo'linadi, va bu farq **atribut qidiruv tartibini** belgilaydi:

- **Data descriptor** — `__get__` **va** `__set__` (yoki `__delete__`) ikkalasini ham amalga oshiradi.
- **Non-data descriptor** — faqat `__get__`ni amalga oshiradi (masalan, oddiy funksiyalar — pastda ko'ramiz).

Python'da atribut qidiruv tartibi (`obj.x` yozilganda) quyidagicha:

1. Avval `type(obj).__mro__` (9.2-darsda ko'radigan MRO) bo'ylab **data descriptor** qidiriladi — topilsa, **darhol** shu ishlatiladi (instance `__dict__`idan ham ustun!).
2. Topilmasa, `obj.__dict__` tekshiriladi — instance'ning o'z atributi bo'lsa, shu qaytariladi.
3. Hali ham topilmasa, klass bo'ylab **non-data descriptor** yoki oddiy klass atributi qidiriladi.

```python
class DataDescriptor:
    def __get__(self, obj, tur=None):
        return "descriptor'dan"
    def __set__(self, obj, qiymat):
        pass  # __set__ borligi uni DATA descriptor qiladi


class Sinov:
    x = DataDescriptor()

s = Sinov()
s.__dict__['x'] = "instance dict'dan"   # to'g'ridan-to'g'ri instance __dict__ga yozamiz

print(s.x)   # "descriptor'dan" — DATA descriptor instance __dict__'dan HAM USTUN!
```

Bu — ko'pchilik uchun kutilmagan xatti-harakat, lekin aynan shu tufayli `@property` (data descriptor) har doim ishonchli ishlaydi — hech kim, tasodifan `obj.__dict__['x'] = ...` yozib, property mantiqini "chetlab o'ta olmaydi".

### `@property` — descriptor orqali qo'lda yozib ko'ramiz

Endi 4.3-darsda "qora quti" sifatida ishlatgan `@property`ni **o'zimiz, descriptor orqali** yozib ko'ramiz:

```python
class MeningPropertyIm:
    """@property dekoratorining SODDALASHTIRILGAN, o'zimiz yozgan versiyasi."""

    def __init__(self, getter):
        self.getter = getter

    def __get__(self, obj, tur=None):
        if obj is None:
            return self
        return self.getter(obj)


class Doira:
    def __init__(self, radius):
        self._radius = radius

    @MeningPropertyIm   # o'zimiz yozgan "property"
    def yuza(self):
        return 3.14159 * self._radius ** 2


d = Doira(5)
print(d.yuza)   # 78.53975 — funksiya emas, TO'G'RIDAN-TO'G'RI QIYMAT, chunki
                  # d.yuza yozilganda Python __get__(d, Doira) ni chaqiradi,
                  # bu esa self.getter(d), ya'ni asl yuza(d) funksiyasini chaqiradi!
```

Bu — aynan `@property`ning ishlash mantig'i (standart kutubxonadagi haqiqiy `property` klassi, albatta, ancha to'liqroq — u `setter`, `deleter`ni ham qo'llab-quvvatlaydi, lekin asosiy g'oya **bir xil**: `__get__` orqali "funksiyani chaqirib, natijasini qiymat sifatida qaytarish").

### Eng ajoyibi: **funksiyaning o'zi** — non-data descriptor!

Endi eng chuqur savolga javob beramiz: nega `obj.metod()` chaqirilganda `self` avtomatik uzatiladi? Javob: **Python funksiyalari (`function` turi) — o'zlari non-data descriptor**, ular `__get__`ni amalga oshiradi:

```python
def oddiy_funksiya(self):
    return f"Men {self} obyektiga bog'landim"

class Sinov:
    metod = oddiy_funksiya   # oddiy funksiyani klass atributi sifatida qo'shamiz

s = Sinov()
print(s.metod)          # <bound method ...> — BOG'LANGAN metod obyekti!
print(s.metod())         # "Men <...Sinov object...> obyektiga bog'landim"
```

`s.metod` yozilganda, Python `oddiy_funksiya.__get__(s, Sinov)`ni chaqiradi, va bu **"bound method"** (bog'langan metod) deb ataluvchi yangi, kichik obyekt yaratadi — bu obyekt `s`ni "eslab qoladi" va chaqirilganda uni avtomatik ravishda birinchi argument (`self`) sifatida uzatadi. Ya'ni **butun OOP'dagi `self` mexanizmi — bu descriptor protokolining bevosita natijasi**, alohida, maxsus "til qoidasi" emas!

```python
# Buni qo'lda ham ko'rish mumkin:
funksiya = Sinov.__dict__['metod']   # klass __dict__idan XOM funksiyani olamiz
print(type(funksiya))                # <class 'function'>

boglangan = funksiya.__get__(s, Sinov)   # __get__ ni QO'LDA chaqiramiz
print(type(boglangan))                    # <class 'method'>
print(boglangan())                        # xuddi s.metod() kabi ishlaydi!
```

### `staticmethod` va `classmethod` — ular ham descriptor

`@staticmethod` va `@classmethod` ham xuddi shu tarzda, descriptor orqali ishlaydi: `staticmethod.__get__` — hech qanday `self`/`cls` bog'lamasdan, xom funksiyani qaytaradi; `classmethod.__get__` — instance emas, **klassning o'zini** birinchi argument (`cls`) sifatida bog'laydi. Bu — 4-bobda ko'rgan bu ikki dekoratorning "sehri" — barchasi bitta umumiy protokol (descriptor)ning turli qo'llanilishlari, xolos.

## Amaliy misol

To'liq, amaliy foydali descriptor — kirish qiymatlarini avtomatik tekshiruvchi ("validating descriptor"):

```python
# descriptor_validatsiya.py

class MusbatSon:
    """Bu descriptor faqat MUSBAT sonlarni qabul qiladigan atribut yaratadi.
    Bir necha klassda qayta ishlatilishi mumkin — bu descriptor'ning
    eng katta amaliy afzalligi: mantiqni BIR JOYDA yozib, KO'P joyda
    qayta ishlatish."""

    def __set_name__(self, egasi_klass, nom):
        # Python 3.6+da avtomatik chaqiriladi: descriptor qaysi nom bilan
        # bog'langanini "biladi" (masalan "narx", "miqdor")
        self.nom = "_" + nom

    def __get__(self, obj, tur=None):
        if obj is None:
            return self
        return getattr(obj, self.nom, None)

    def __set__(self, obj, qiymat):
        if not isinstance(qiymat, (int, float)):
            raise TypeError(f"{self.nom[1:]} son bo'lishi kerak, {type(qiymat).__name__} berildi")
        if qiymat <= 0:
            raise ValueError(f"{self.nom[1:]} musbat bo'lishi kerak, {qiymat} berildi")
        setattr(obj, self.nom, qiymat)


class Mahsulot:
    narx = MusbatSon()      # qayta ishlatish 1
    miqdor = MusbatSon()    # qayta ishlatish 2 — bir xil klassda ham muammosiz!

    def __init__(self, nom, narx, miqdor):
        self.nom = nom
        self.narx = narx        # bu yerda __set__ avtomatik chaqiriladi va tekshiriladi
        self.miqdor = miqdor

    def jami(self):
        return self.narx * self.miqdor


mahsulot = Mahsulot("Noutbuk", 5_000_000, 3)
print(f"{mahsulot.nom}: jami {mahsulot.jami():,} so'm")

try:
    mahsulot.narx = -100   # ValueError chaqiradi — descriptor tekshiradi!
except ValueError as e:
    print("Xatolik ushlandi:", e)

try:
    mahsulot.miqdor = "ko'p"   # TypeError chaqiradi
except TypeError as e:
    print("Xatolik ushlandi:", e)
```

Bu — descriptor'ning **haqiqiy** amaliy qiymati: validatsiya mantig'ini bitta joyda yozib, uni istalgancha atributda va klassda qayta ishlatish mumkin — `@property` bilan har bir atribut uchun alohida getter/setter yozishga qaraganda ancha ixchamroq.

## Keng tarqalgan xatolar

**Xato 1:** Descriptor holatini **descriptor obyektining o'zida** saqlash (instance emas).
❌
```python
class NotoGriDescriptor:
    def __init__(self):
        self.qiymat = None   # BU YERDA saqlash — barcha instance'lar UCHUN UMUMIY bo'ladi!

    def __get__(self, obj, tur=None):
        return self.qiymat

    def __set__(self, obj, qiymat):
        self.qiymat = qiymat

class Sinov:
    x = NotoGriDescriptor()   # BITTA descriptor obyekti barcha Sinov instance'lari uchun umumiy!

a = Sinov()
b = Sinov()
a.x = 10
print(b.x)   # 10 — XATO! b o'zining alohida x'ga ega bo'lishi kerak edi!
```
✅ To'g'ri: qiymatni descriptor obyektida emas, **har bir instance'ning o'z `__dict__`ida** saqlang (yuqoridagi amaliy misoldagi `MusatSon` kabi, `setattr(obj, self.nom, qiymat)` orqali) — chunki descriptor obyekti **klass darajasida bitta**, barcha instance'lar orasida umumiy.

**Xato 2:** `__get__`da `obj is None` holatini (klass darajasida murojaat qilinganda) tekshirmaslik.
❌
```python
def __get__(self, obj, tur=None):
    return obj.qandaydir_atribut   # obj None bo'lsa (masalan Klass.x chaqirilsa) -> AttributeError!
```
✅ To'g'ri: `Klass.x` (instance'siz, to'g'ridan-to'g'ri klass orqali) chaqirilganda, `obj` — `None` bo'ladi. Yaxshi descriptor'lar bu holatni tekshirib, odatda descriptor'ning o'zini qaytaradi (yuqoridagi misollardagi kabi) — bu introspeksiya (`help()`, dokumentatsiya vositalari) uchun muhim.

**Xato 3:** Non-data va data descriptor orasidagi ustunlik tartibini bilmasdan, instance `__dict__` orqali descriptor'ni "qayta yozish" mumkin deb o'ylash.
❌ `@property` (data descriptor) bilan yaratilgan atributni `obj.__dict__['x'] = yangi_qiymat` orqali "almashtirishga" urinish va bu ishlaydi deb kutish.
✅ To'g'ri: data descriptor'lar (shu jumladan `@property`) **har doim** instance `__dict__`dan ustun turadi — shuning uchun ular "chinakam himoyalangan" hisoblanadi. Faqat **non-data** descriptor'lar (masalan, oddiy metodlar) instance `__dict__`ga bo'ysunadi — shuning uchun, masalan, `obj.metod = boshqa_funksiya` yozib, bitta obyektning metodini "qayta yozish" texnik jihatdan mumkin (garchi bu kamdan-kam yaxshi amaliyot bo'lsa).

## Mashq/topshiriq

**(Oson)** Oddiy descriptor yozing (`__get__` va `__set__` bilan) — u har safar o'qilganda va yozilganda konsolga xabar chiqarsin (masalan `"O'qildi"`, `"Yozildi: <qiymat>"`). Uni bitta klassda sinab ko'ring.

**(O'rtacha)** `__set_name__` metodidan foydalanib, faqat **belgilangan uzunlikdan oshmaydigan** satrlarni qabul qiluvchi `MaksimalUzunlik` nomli descriptor yozing (masalan, konstruktorda `MaksimalUzunlik(50)` orqali maksimal uzunlik beriladi). Uni `Foydalanuvchi` klassida `ism` va `email` atributlari uchun ikki marta qayta ishlating.

**(Qiyin)** `LazyProperty` nomli descriptor yozing — bu, oddiy `@property`dan farqli, natijani **faqat birinchi murojaatda** hisoblab, keyingi murojaatlarda **keshlangan** qiymatni qaytarsin (ya'ni qimmat hisoblash faqat bir marta bajarilsin). Buni sinash uchun, ichida `time.sleep(1)` bilan "qimmat" hisoblashni simulyatsiya qiluvchi metodli klass yarating va ikkinchi murojaat birinchisidan sezilarli tezroq ekanini `time` bilan o'lchab ko'rsating.

import time

class LazyProperty:
    def __init__(self, funksiya):
        self.funksiya = funksiya
        self.nom = funksiya.__name__

    def __get__(self, obj, tur=None):
        if obj is None:
            return self
        if self.nom not in obj.__dict__:
            print(f"({self.nom} hisoblanmoqda...)")
            obj.__dict__[self.nom] = self.funksiya(obj)
            # E'TIBOR: keshlangan qiymatni to'g'ridan-to'g'ri obj.__dict__ga
            # yozamiz — bu esa LazyProperty NON-DATA descriptor (faqat __get__
            # bor) bo'lgani uchun, KEYINGI murojaatlarda instance __dict__
            # descriptor'dan USTUN bo'lib, __get__ UMUMAN chaqirilmaydi —
            # aynan shu orqali "keshlash" avtomatik ishlaydi!
        return obj.__dict__[self.nom]


class QimmatHisoblash:
    @LazyProperty
    def natija(self):
        time.sleep(1)
        return 42

obj = QimmatHisoblash()

boshlanish = time.perf_counter()
print(obj.natija)
print(f"1-murojaat: {time.perf_counter() - boshlanish:.3f} soniya")

boshlanish = time.perf_counter()
print(obj.natija)
print(f"2-murojaat: {time.perf_counter() - boshlanish:.6f} soniya (keshdan!)")

## Qisqacha xulosa

Descriptor protokoli (`__get__`, `__set__`, `__delete__`) — Python'da atributlarga murojaatni klass darajasida to'liq nazorat qilish imkonini beruvchi mexanizm bo'lib, u nafaqat `@property`ning, balki **butun OOP tizimidagi eng asosiy sehr** — oddiy funksiyaning `self`ga avtomatik bog'lanishining ham asosidir (funksiyalar — o'zlari non-data descriptor). Data descriptor (`__set__`ga ega) instance `__dict__`dan ustun turadi, non-data descriptor esa unga bo'ysunadi — aynan shu farq `@property`ning "chetlab o'tib bo'lmaydigan" ishonchliligini, va oddiy metodlarning instance darajasida "qayta yozilishi mumkinligini" izohlaydi. Keyingi darsda biz OOP'ning yana bir "sehri" — `super()` va meros — qanday ishlashini chuqur ko'ramiz.
