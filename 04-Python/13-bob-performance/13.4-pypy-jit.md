# 13.4. PyPy va JIT-kompilyatsiya

## Bu darsda nimalarni o'rganasiz

- JIT (Just-In-Time) kompilyatsiya g'oyasi — AOT (Ahead-Of-Time) kompilyatsiyadan farqi
- PyPy — muqobil Python implementatsiyasi, uning tracing JIT mexanizmi
- CPython'ning o'zining yangi eksperimental JIT'i (3.13+, copy-and-patch texnikasi)
- PyPy'ni qachon ishlatish mos, qachon mos emas
- CPython vs PyPy amaliy taqqoslash

## Nazariy qism

**Manba:** [PEP 659 — Specializing Adaptive Interpreter](https://peps.python.org/pep-0659/) (8-bobda ko'rilgan), [Tony Baloney — "Python 3.13 gets a JIT"](https://tonybaloney.github.io/posts/python-gets-a-jit.html), PyPy rasmiy dokumentatsiyasi.

### AOT vs JIT kompilyatsiya — eslatma

C yoki Cython (13.3-darsda ko'rganimizdek) — bular **AOT (Ahead-Of-Time)** kompilyatsiya: kod ishga tushishidan oldin, alohida bosqichda, to'liq mashina kodiga aylantiriladi. Standart CPython esa bytecode'ni **interpretatsiya** qiladi — har safar dastur ishga tushganda, ceval loop (8.3-darsda ko'rgan) har bir bytecode instruksiyani "tushunib", mos C funksiyasini chaqiradi.

**JIT (Just-In-Time)** kompilyatsiya — bu ikkisining o'rtasidagi yondashuv: dastur **ishlab turgan paytida**, interpretator qaysi kod ko'p marta takrorlanayotganini ("issiq" — hot — kod yo'llarini) kuzatadi, va faqat o'sha qismlarni real vaqtda mashina kodiga aylantiradi, keyingi bajarilishlarda esa to'g'ridan-to'g'ri shu tezkor mashina kodini ishlatadi. Bu — Java'ning HotSpot VM'i, JavaScript dvigatellari (V8) va boshqa ko'p zamonaviy til implementatsiyalarida qo'llaniladigan strategiya.

### PyPy — muqobil Python implementatsiyasi

**PyPy** — CPython'dan butunlay mustaqil, alohida yozilgan Python implementatsiyasi (o'zi ham katta qismi Python'ga o'xshash "RPython" tilida yozilgan) bo'lib, uning markazida **tracing JIT** kompilyatori yotadi. PyPy'ning ishlash prinsipi:

1. Dastur boshida PyPy oddiy interpretator sifatida ishlaydi (CPython'ga o'xshab).
2. PyPy qaysi tsikllar (loop) ko'p marta bajarilayotganini kuzatadi ("hot loop" aniqlash).
3. Agar bir tsikl yetarlicha ko'p marta (odatda minglab marta) bajarilgan bo'lsa, PyPy o'sha tsiklning **bitta konkret bajarilish yo'lini** (trace — masalan, "bu tsiklda har doim `x` int, `y` ham int bo'lgan") kuzatib, shu asosda **ixtisoslashtirilgan mashina kodi** generatsiya qiladi.
4. Keyingi safar shu tsikl bajarilganda, agar sharoitlar (tip taxminlari) hali ham to'g'ri bo'lsa, PyPy to'g'ridan-to'g'ri generatsiya qilingan tezkor mashina kodini ishlatadi — bytecode interpretatsiyasi umuman chetlab o'tiladi.
5. Agar taxmin noto'g'ri chiqib qolsa (masalan, `x` endi `int` emas, `str` bo'lib qoldi), JIT "sekin yo'l"ga (interpretatsiyaga) qaytadi — bu **"guard failure"** deb ataladi.

Bu yondashuv PyPy'ga sof Python (raqamli hisoblash-og'ir, tsikl-og'ir) kodlarda CPython'dan o'rtacha **4-10 barobar**, ba'zi maxsus holatlarda hatto undan ham ko'proq tezlik berishga imkon beradi — hech qanday kod o'zgartirishsiz, faqat interpretatorni almashtirish orqali.

### PyPy'ning cheklovlari

PyPy hamma narsani "bepul" tezlashtirmaydi:

- **C kengaytma modullari bilan mosligi cheklangan.** NumPy, pandas kabi CPython C-API'ga qattiq bog'langan kutubxonalar PyPy'da to'liq yoki samarali ishlamasligi mumkin (garchi zamonaviy PyPy versiyalari `cpyext` moslashtiruvchi qatlami orqali ko'p C kengaytmalarni qo'llab-quvvatlasa ham, bu qatlam qo'shimcha overhead qo'shadi va ba'zan CPython'dagidan sekinroq bo'lishi mumkin).
- **Qisqa muddatli skriptlarda foyda kam.** JIT "isinishi" (warm-up) — ya'ni tsiklni "issiq" deb aniqlash va uni kompilyatsiya qilish — vaqt oladi. Agar dastur juda tez tugasa (masalan, kichik CLI skript), JIT hatto ishga tushishga ulgurmasdan dastur allaqachon tugab qolishi mumkin — bu holatlarda PyPy CPython'dan **sekinroq** bo'lishi ham mumkin (JIT infratuzilmasining o'zi qo'shimcha xotira/vaqt sarflaydi).
- **Xotira sarfi ko'proq bo'lishi mumkin** — JIT tomonidan generatsiya qilingan mashina kodi va kuzatuv (tracing) infratuzilmasi qo'shimcha xotira talab qiladi.

### CPython'ning o'z JIT'i (3.13+)

**Manba:** [Tony Baloney — "Python 3.13 gets a JIT"](https://tonybaloney.github.io/posts/python-gets-a-jit.html).

Python 3.13'dan boshlab, CPython'ning o'ziga ham **eksperimental JIT** kompilyatori qo'shildi — bu PyPy'nikidan butunlay boshqacha texnika bilan ishlaydi: **"copy-and-patch"**. Bu usul:

1. Har bir bytecode operatsiyasi uchun C kodi oldindan (CPython qurilishi vaqtida) mashina kodi **shabloni (template)**ga kompilyatsiya qilinadi, unda "teshiklar" (holes) — keyinroq to'ldiriladigan o'zgaruvchan qiymatlar joyi — qoldiriladi.
2. Dastur ishlab turganda, "issiq" deb aniqlangan (odatda orqaga sakrash — `JUMP_BACKWARD` — opkodiga ega, ya'ni tsikl) kod yo'llari uchun CPython bu oldindan tayyorlangan shablonlarni **nusxalab (copy)**, kerakli qiymatlar bilan **"teshiklarni to'ldirib" (patch)**, ularni bir-biriga bog'laydi.

Bu — PyPy'ning to'liq tracing JIT'idan ancha soddaroq va "arzonroq" yondashuv: kompilyatsiya vaqti tezroq, murakkablik kamroq, lekin generatsiya qilingan kodning o'zi PyPy darajasidagi chuqur ixtisoslashuvga ega emas. Shuning uchun dastlabki natijalar mo''tadil — mualliflarning o'lchovlariga ko'ra dastlabki versiyalarda taxminan **2-9%** tezlashish kuzatilgan, chuqur o'zgarish emas, balki **kelajakdagi chuqurroq optimallashtirishlar uchun infratuzilma** sifatida qaraladi.

Bu JIT hozircha **ixtiyoriy va eksperimental**: uni yoqish uchun CPython'ni maxsus `--enable-experimental-jit` bayrog'i bilan qurish kerak, standart Python distributivlarida standart holatda o'chirilgan. Bu 8-bobda ko'rgan PEP 659 (specializing adaptive interpreter — bytecode'ni runtime'da "ixtisoslashtirish", lekin hamon interpretatsiya, mashina kodi generatsiya qilmaslik) bilan **birga** ishlaydi — ular bir-birini to'ldiruvchi, alohida optimallashtirish qatlamlari.

### PyPy vs CPython JIT — konseptual farq

| | PyPy | CPython JIT (3.13+) |
|---|---|---|
| Yondashuv | To'liq tracing JIT (real vaqtda taxminlarga asoslangan kod generatsiyasi) | Copy-and-patch (oldindan tayyorlangan shablonlarni yig'ish) |
| Yetuklik | 15+ yildan beri ishlab chiqilgan, production-ready | Yangi, eksperimental (3.13/3.14) |
| Tezlashish | 4-10x (ba'zi ish yuklarida) | ~2-9% (hozirgi bosqichda) |
| C kengaytma mosligi | Cheklangan/sekinroq (`cpyext` qatlami) | To'liq (bu — CPython'ning o'zi) |
| Standart holat | Alohida interpretator, o'rnatish kerak | CPython ichida, ixtiyoriy bayroq bilan |

## Amaliy misol

```python
"""
pypy_jit_demo.py — CPU-bog'liq, tsikl-og'ir kodni yaratish,
uni turli interpretatorlarda (CPython, agar mavjud bo'lsa PyPy)
solishtirish uchun mo'ljallangan.

Bu skriptni ham "python3 pypy_jit_demo.py" (standart CPython),
ham "pypy3 pypy_jit_demo.py" (agar PyPy o'rnatilgan bo'lsa) bilan
ishga tushirib solishtiring.
"""
import sys
import time


def tsikl_ogir_hisoblash(n: int) -> float:
    """Sof Python, faqat asosiy arifmetika — JIT uchun "ideal" holat."""
    natija = 0.0
    for i in range(n):
        natija += (i * 1.0000001) ** 0.5
        if i % 3 == 0:
            natija -= 0.5
    return natija


def demo():
    print("Interpretator:", sys.implementation.name)
    print("Versiya:", sys.version)

    boshlanish = time.perf_counter()
    natija = tsikl_ogir_hisoblash(20_000_000)
    vaqt = time.perf_counter() - boshlanish

    print(f"Natija: {natija:.4f}")
    print(f"Vaqt: {vaqt:.3f}s")

    if sys.implementation.name == "pypy":
        print(
            "PyPy: birinchi ishga tushirishda JIT 'isinish' vaqti bo'lishi mumkin — "
            "agar shu funksiyani ikkinchi marta chaqirsangiz, sezilarli tezroq bo'ladi."
        )
        # JIT "isingandan" keyingi vaqtni ham o'lchash:
        boshlanish = time.perf_counter()
        tsikl_ogir_hisoblash(20_000_000)
        ikkinchi_vaqt = time.perf_counter() - boshlanish
        print(f"Ikkinchi chaqiruv vaqti (JIT isingandan keyin): {ikkinchi_vaqt:.3f}s")


if __name__ == "__main__":
    demo()
```

Taxminiy natija (mashinaga qarab farqlanadi):

```
# python3 (standart CPython 3.12) bilan:
Vaqt: 4.812s

# pypy3 bilan:
Vaqt: 0.623s   # birinchi chaqiruv — JIT hali "isimoqda"
Ikkinchi chaqiruv vaqti (JIT isingandan keyin): 0.198s   # ancha tezroq
```

## Keng tarqalgan xatolar

1. **"PyPy har doim tezroq" deb umumlashtirish.** Qisqa, tez tugaydigan skriptlarda, yoki C kengaytmalarga (NumPy kabi) og'ir bog'liq kodda PyPy foyda bermasligi, hatto sekinroq bo'lishi ham mumkin. PyPy eng katta foydani **uzoq ishlaydigan, sof-Python, tsikl-og'ir** dasturlarda (masalan, uzoq muddat ishlaydigan server, ilmiy simulyatsiya) beradi.

2. **JIT "isinish" (warm-up) vaqtini hisobga olmasdan tezlik solishtirish.** PyPy'ning birinchi bir necha ming iteratsiyasi hali interpretatsiya rejimida (sekinroq) bajariladi — faqat "issiq" deb aniqlangandan keyin tezlashadi. Qisqa benchmark'lar bu isinish vaqtini o'z ichiga olib, noto'g'ri (kam) tezlashish ko'rsatishi mumkin.

3. **CPython'ning eksperimental JIT'ini "PyPy o'rnini bosadi" deb kutish.** Hozirgi bosqichda (2-9% tezlashish) CPython JIT'i PyPy darajasidagi tezlikni bermaydi — bu ikki loyiha turli maqsad va yetuklik bosqichida.

## Mashq/topshiriq

1. Agar tizimingizda PyPy o'rnatish imkoni bo'lsa (`apt install pypy3` yoki [python.org](https://www.pypy.org/) orqali), yuqoridagi `pypy_jit_demo.py`ni ham `python3`, ham `pypy3` bilan ishga tushirib, real tezlik farqini o'lchang.

2. `tsikl_ogir_hisoblash` funksiyasini shunday o'zgartiringki, u tsikl ichida turli tiplarni (ba'zan `int`, ba'zan `str`) aralashtirsin. Nima uchun bu PyPy JIT'ining samaradorligini pasaytirishi mumkinligini "guard failure" tushunchasiga tayanib tushuntiring.

3. Nima uchun NumPy bilan yozilgan, allaqachon vektorlashtirilgan kod (masalan, `arr.sum()`) uchun PyPy CPython'ga nisbatan deyarli hech qanday qo'shimcha tezlik bermasligini tushuntiring.

**Javoblar:**

1. (Amaliy mashq — natija mashinaga bog'liq, lekin odatda PyPy sof-Python tsikllarida sezilarli, ko'pincha bir necha barobar tezroq chiqadi.)

2.
```python
def tsikl_aralash_tip(n):
    natija = 0
    for i in range(n):
        if i % 1000 == 0:
            natija = str(natija)  # ba'zan str
        else:
            natija = i  # odatda int
    return natija
```
PyPy'ning tracing JIT'i tsiklni kuzatganda, "bu tsiklda `natija` doim `int`" degan **taxmin (guard)** asosida ixtisoslashtirilgan mashina kodi generatsiya qiladi. Agar tur kutilmaganda o'zgarsa (masalan, `str`ga aylansa), bu taxmin **buziladi (guard failure)** — JIT o'zining tezkor, ixtisoslashtirilgan yo'lidan "sekin yo'l"ga (umumiy, tip-tekshiruvchi interpretatsiyaga) qaytishga majbur bo'ladi. Agar bu almashinish tez-tez sodir bo'lsa, JIT foyda o'rniga hatto qo'shimcha overhead (guard tekshiruvlari, qayta kompilyatsiya) qo'shishi mumkin.

3. NumPy'ning `arr.sum()` kabi metodlari allaqachon C (yoki Cython) darajasida, vektorlashtirilgan, past darajadagi tsikllar bilan amalga oshirilgan — bu tsikllar Python bytecode darajasida umuman "ko'rinmaydi" (PyPy yoki CPython interpretatori bu tsiklni kuzata olmaydi, chunki u allaqachon tayyor mashina kodida, C kutubxonasi ichida bajariladi). PyPy JIT'i faqat **Python darajasidagi** bytecode tsikllarni tezlashtira oladi — u NumPy'ning ichki C tsiklini "qayta yozib" tezlashtira olmaydi. Shuning uchun allaqachon to'liq vektorlashtirilgan NumPy kodida PyPy va CPython o'rtasida deyarli hech qanday farq bo'lmaydi — ikkalasi ham xuddi shu tayyor C kodini chaqiradi.

## Qisqacha xulosa

JIT kompilyatsiya — dastur ishlab turgan paytida "issiq" kod yo'llarini real vaqtda tezkor mashina koddiga aylantirish strategiyasi. PyPy — CPython'dan mustaqil, yetuk **tracing JIT**ka ega Python implementatsiyasi bo'lib, sof-Python, tsikl-og'ir kodlarda 4-10x tezlashish berishi mumkin, lekin C kengaytmalar bilan cheklangan moslik va JIT "isinish" vaqti kabi cheklovlarga ega. CPython'ning o'zi Python 3.13'dan boshlab eksperimental, hali ancha soddaroq **copy-and-patch** JIT'iga ega bo'ldi — hozircha mo''tadil (2-9%) tezlashish beradi, lekin kelajakda kengayishi mumkin bo'lgan infratuzilma sifatida qaraladi. Ikkala JIT yondashuvi ham C kengaytma (NumPy kabi) darajasidagi allaqachon vektorlashtirilgan kodga qo'shimcha tezlik bera olmaydi — ular faqat sof Python bytecode bajarilishini tezlashtiradi. Amaliy qoida: uzoq ishlaydigan, sof-Python, hisoblash-og'ir dastur uchun PyPy'ni sinab ko'rish arziydi; agar loyiha C kengaytmalarga qattiq bog'liq bo'lsa, standart CPython (kerak bo'lsa Cython bilan birga) odatda amaliyroq tanlov bo'lib qoladi.
