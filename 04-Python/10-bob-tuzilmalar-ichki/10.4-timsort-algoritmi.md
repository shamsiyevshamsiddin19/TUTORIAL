# Timsort — `sorted()` ortidagi algoritm

## Bu darsda nimalarni o'rganasiz

- Python'ning `sorted()` va `list.sort()` funksiyalari qaysi algoritmni ishlatishini bilib olasiz
- **Timsort** nima ekanini, va u nega faqat "nazariy jihatdan tez" emas, balki **real dunyodagi ma'lumotlar uchun** maxsus optimallashtirilganini tushunasiz
- "Run" (ketma-ket qismlar), "merge" (birlashtirish) va "galloping mode" tushunchalarini o'rganasiz
- `key` parametrining ichki ishlashini (Schwartzian transform) va uning nega tezlikka ta'sir qilishini bilasiz

## Nazariy qism

### Nega maxsus algoritm kerak edi

Ko'p dasturlash tillarida saralash uchun **quicksort** yoki **merge sort** kabi klassik algoritmlar ishlatiladi. Lekin Python (aniqrog'i, CPython) 2002-yildan beri **Timsort** deb ataluvchi, Tim Peters (Python jamoasining faxriysi, "Zen of Python"ning muallifi) tomonidan **maxsus Python uchun ixtiro qilingan** gibrid algoritmni ishlatadi. Timsort — endi Java (Java 7+) va Android platformasida ham standart saralash algoritmiga aylangan — bu uning amaliy samaradorligining dalili.

**Manba:** Ushbu dars Tim Peters'ning rasmiy Timsort tavsifi (CPython manba kodidagi `Objects/listsort.txt`) va umumiy algoritmlar nazariyasi asosida tuzilgan.

### Asosiy kuzatuv: real ma'lumotlar kamdan-kam "tasodifiy"

Klassik saralash algoritmlari (masalan, quicksort) odatda **eng yomon holat** yoki **o'rtacha (tasodifiy) holat**ka optimallashtirilgan. Lekin Tim Peters'ning kuzatuvi shu edi: **amaliyotdagi haqiqiy ma'lumotlar** (masalan, log fayllar, foydalanuvchi ro'yxatlari, vaqt bo'yicha tartiblangan yozuvlar) kamdan-kam **butunlay tasodifiy** bo'ladi — ularda ko'pincha allaqachon **qisman saralangan** ketma-ketliklar ("run"lar) mavjud bo'ladi. Timsort aynan shu haqiqatdan foydalanadi.

### Algoritm qanday ishlaydi — asosiy qadamlar

**1-qadam: "Run"larni topish.** Timsort avval massivni chapdan o'ngga skanerlab, **allaqachon tartiblangan** (o'suvchi yoki kamayuvchi) ketma-ket bo'laklarni — **"run"** — topadi. Kamayuvchi run'lar avtomatik teskarisiga aylantiriladi (bu — O(1) qo'shimcha xotira bilan, joyida bajariladi).

```
Massiv:  [3, 7, 9, 12, 2, 8, 15, 1, 5, 6, 20, 18, 4]
Run 1:   [3, 7, 9, 12]           (o'suvchi)
Run 2:   [2, 8, 15]              (o'suvchi)
Run 3:   [1, 5, 6, 20]           (o'suvchi)
Run 4:   [18, 4]  -> [4, 18]     (kamayuvchi edi, teskarisiga aylantirildi)
```

**2-qadam: kichik run'larni kengaytirish.** Agar tabiiy run juda qisqa (odatda 64 elementdan kam) bo'lsa, Timsort uni **kirish saralash** (insertion sort) yordamida sun'iy ravishda minimal uzunlikkacha kengaytiradi — chunki kirish saralash **kichik** massivlarda (kesh-samaradorligi va past "overhead" tufayli) merge sort'dan ham tezroq ishlaydi.

**3-qadam: run'larni "aqlli" birlashtirish (merge).** Endi Timsort bu run'larni **juftlab birlashtira** boshlaydi — xuddi klassik merge sort kabi, lekin **qaysi run'larni birlashtirish tartibi** run'lar uzunligiga qarab, maxsus qoidalar (stack-asosli invariantlar) bilan boshqariladi, bu esa umumiy vaqt va xotira murakkabligini optimal darajada ushlab turadi.

### Murakkablik: eng yomon O(N log N), eng yaxshi O(N)

Timsort'ning eng katta afzalligi — uning **adaptivligi**:

- **Eng yomon holat** (butunlay tasodifiy ma'lumot): O(N log N) — bu, klassik merge sort/quicksort bilan bir xil, kafolatlangan yuqori chegara.
- **Eng yaxshi holat** (massiv allaqachon to'liq saralangan, yoki deyarli saralangan): **O(N)** — chiziqli vaqt! Chunki agar butun massiv **bitta katta run** bo'lib chiqsa, hech qanday birlashtirish kerak bo'lmaydi.

```python
import time

def vaqtni_olchash(royxat, tavsif):
    boshlanish = time.perf_counter()
    sorted(royxat)
    tugash = time.perf_counter()
    print(f"{tavsif}: {tugash - boshlanish:.5f} soniya")


n = 1_000_000

tasodifiy = list(range(n))
import random
random.shuffle(tasodifiy)
vaqtni_olchash(tasodifiy, "Tasodifiy tartibda (eng yomon holatga yaqin)")

allaqachon_saralangan = list(range(n))
vaqtni_olchash(allaqachon_saralangan, "Allaqachon saralangan (eng yaxshi holat, deyarli O(N))")

teskari_tartibda = list(range(n, 0, -1))
vaqtni_olchash(teskari_tartibda, "To'liq teskari tartibda (Timsort buni ANIQLAYDI!)")
```

Diqqat qiling: **teskari tartibdagi** massiv ham juda tez saralanadi — chunki bu, Timsort nuqtai nazaridan, shunchaki **bitta kamayuvchi run**, u darhol aniqlanib, O(N) vaqtda teskarisiga aylantiriladi.

### "Galloping mode" — tezlashtirish uchun qo'shimcha hiyla

Ikkita run'ni birlashtirishda, agar Timsort **bitta run'dan** ketma-ket ko'p (odatda 7 tadan ortiq) elementning ustunlik qilishini payqasa, u **"galloping" (sakrab qidirish) rejimi**ga o'tadi — bu rejimda u har bir elementni birma-bir solishtirish o'rniga, **eksponensial sakrashlar** (1, 2, 4, 8, ... element oldinga) orqali qidiruvni tezlashtiradi, so'ng ikkilik qidiruv (binary search) bilan aniq joyni topadi. Bu — ayniqsa ikkita run'ning "hajmlari" juda notekis bo'lgan holatlarda katta tezlik yutug'i beradi.

### `key` parametri — Schwartzian transform

`sorted(royxat, key=funksiya)` chaqirilganda, Python **naiv** yondashuv — har bir solishtirishda `funksiya`ni qayta-qayta chaqirish — o'rniga, **Schwartzian transform** (yoki "decorate-sort-undecorate") deb ataluvchi optimallashtirishni qo'llaydi:

1. **Decorate:** har bir element uchun **bir marta** `key(element)` hisoblanadi, va `(key(element), element)` juftliklari vaqtinchalik ro'yxatga yig'iladi.
2. **Sort:** bu juftliklar ro'yxati **kalitlar bo'yicha** saralanadi (Timsort bilan).
3. **Undecorate:** saralangan juftliklardan asl elementlar qaytarib olinadi.

```python
import time

def sekin_kalit(x):
    # "qimmat" hisoblashni simulyatsiya qilamiz
    total = 0
    for _ in range(1000):
        total += x
    return total

royxat = list(range(10000, 0, -1))

boshlanish = time.perf_counter()
natija = sorted(royxat, key=sekin_kalit)
tugash = time.perf_counter()
print(f"sorted() key bilan: {tugash - boshlanish:.4f} soniya")
# key FUNKSIYASI faqat 10,000 marta chaqiriladi (har element uchun BIR MARTA),
# N log N marta EMAS (garchi solishtirishlar soni N log N bo'lsa ham) —
# aynan Schwartzian transform tufayli!
```

Bu optimallashtirish tufayli, `key` funksiyasi qanchalik "qimmat" bo'lmasin, u har bir element uchun faqat **bir marta** chaqiriladi, saralash jarayonidagi ko'plab solishtirishlar davomida emas.

### `sorted()` vs `list.sort()` — farq

`sorted(iterable)` — **yangi** ro'yxat qaytaradi, asl ma'lumotni o'zgartirmaydi (istalgan iterable — list, tuple, generator — bilan ishlaydi). `royxat.sort()` — ro'yxatni **joyida** (in-place) saralaydi, `None` qaytaradi, va faqat `list` obyektlarida mavjud. `list.sort()` — yangi ro'yxat yaratmagani uchun odatda biroz xotira-samaraliroq:

```python
asl = [3, 1, 2]
yangi = sorted(asl)   # asl O'ZGARMAYDI, yangi ro'yxat qaytadi
print(asl, yangi)      # [3, 1, 2] [1, 2, 3]

asl.sort()              # asl RO'YXATNING O'ZI o'zgaradi
print(asl)               # [1, 2, 3]
```

## Amaliy misol

Timsort'ning "qisman saralangan" ma'lumotlarga moslashuvchanligini o'lchash orqali ko'rsatish:

```python
# timsort_demo.py
import random
import time


def olchash(royxat, tavsif):
    nusxa = royxat.copy()
    boshlanish = time.perf_counter()
    nusxa.sort()
    tugash = time.perf_counter()
    print(f"{tavsif:<50}{tugash - boshlanish:.5f} soniya")


def demo():
    n = 500_000

    print(f"\n{n:,} elementli massivlarni saralash:\n")

    # 1. To'liq tasodifiy
    tasodifiy = list(range(n))
    random.shuffle(tasodifiy)
    olchash(tasodifiy, "To'liq tasodifiy")

    # 2. Allaqachon saralangan
    saralangan = list(range(n))
    olchash(saralangan, "Allaqachon to'liq saralangan")

    # 3. "Deyarli" saralangan — faqat 1% elementlar joyidan siljitilgan
    deyarli_saralangan = list(range(n))
    for _ in range(n // 100):
        i, j = random.randint(0, n - 1), random.randint(0, n - 1)
        deyarli_saralangan[i], deyarli_saralangan[j] = deyarli_saralangan[j], deyarli_saralangan[i]
    olchash(deyarli_saralangan, "Deyarli saralangan (1% aralashtirilgan)")

    # 4. Bir necha uzun, saralangan bloklardan iborat
    bloklar = []
    blok_hajmi = n // 10
    for i in range(10):
        blok = list(range(i * blok_hajmi, (i + 1) * blok_hajmi))
        bloklar.extend(blok)
    olchash(bloklar, "10 ta ketma-ket saralangan blokdan iborat")


if __name__ == "__main__":
    demo()
```

Bu dastur ishga tushirilganda, siz aniq ko'rasiz: **to'liq tasodifiy** massiv eng sekin saralanadi, **allaqachon saralangan** — eng tez (deyarli O(N)), va **"deyarli saralangan"**/**"bloklardan iborat"** holatlar oralig'ida joylashadi — bu aynan Timsort'ning "run"larni izlab, ulardan foydalanish strategiyasining natijasidir.

## Keng tarqalgan xatolar

**Xato 1:** `sorted()` va `list.sort()`ni farqlamasdan, "qaysi biri tezroq" deb noto'g'ri savol berish.
❌ "sort() sorted()dan tezroq, doim shuni ishlataman" deb, `sorted()` kerak bo'lgan holatlarda ham (masalan, asl ma'lumotni saqlab qolish kerak bo'lganda) `sort()`ni majburan qo'llash.
✅ To'g'ri: tanlov **tezlikka emas, ehtiyojga** asoslanishi kerak — agar asl ro'yxat kerak bo'lmasa va joyida o'zgartirish mumkin bo'lsa, `sort()` (biroz kam xotira, yangi ro'yxat yaratmaydi); agar asl ma'lumot saqlanishi kerak bo'lsa, yoki `list` bo'lmagan iterable bilan ishlansa (masalan generator), `sorted()`.

**Xato 2:** `key` funksiyasini yozishda, uni "har bir solishtirishda chaqiriladi" deb, ichida keraksiz murakkab, qayta-qayta hisoblanadigan mantiq yozish.
❌
```python
sorted(royxat, key=lambda x: qimmat_hisoblash(x) + yana_bir_qimmat_hisoblash(x))
```
Bu, albatta, `key` faqat bir marta har element uchun chaqirilgani tufayli **allaqachon** samarali, lekin agar `qimmat_hisoblash` natijasi **boshqa joyda ham** kerak bo'lsa, uni oldindan hisoblab, alohida ro'yxatda saqlash tavsiya etiladi.
✅ To'g'ri: `key` funksiyasi ichida faqat **kerakli hisoblashni** qiling — Schwartzian transform tufayli bu allaqachon optimal, lekin agar bir xil natija boshqa joyda ham ishlatilsa, uni keshlash (masalan `functools.lru_cache`, 5.4-darsda ko'rgan) qo'shimcha tezlik berishi mumkin.

**Xato 3:** Katta hajmdagi ma'lumotni saralashdan oldin uni maxsus tartibga keltirishga "yordam berish" uchun keraksiz qo'shimcha ish qilish.
❌ "Timsort qisman saralangan ma'lumotni yaxshi ko'radi" deb, saralashdan oldin ma'lumotni "qo'lda, qisman tartiblashga" harakat qilish (masalan, oddiy bubble sort bilan "bir oz" tartiblab, keyin `sort()` chaqirish).
✅ To'g'ri: Timsort'ning o'zi **allaqachon** eng samarali tarzda run'larni topadi va ulardan foydalanadi — qo'shimcha "yordam" odatda ortiqcha ish va sekinlashuvga olib keladi. Agar ma'lumot **tabiiy ravishda** (masalan, vaqt tartibida yig'ilgan log yozuvlari) qisman saralangan bo'lsa, Timsort buni **o'zi**, avtomatik ravishda sezib, foydalanadi.

## Mashq/topshiriq

**(Oson)** 10,000 elementli tasodifiy va allaqachon saralangan ikkita ro'yxat yarating, `time` moduli bilan ikkalasini saralash vaqtini solishtiring va necha barobar farq borligini hisoblang.

**(O'rtacha)** `sorted()`ga `key` parametri sifatida, ichida `print()` chaqiruvi bo'lgan funksiya bering (masalan, `key=lambda x: (print(f"key({x})"), x)[1]`), va 20 elementli ro'yxatni saralang. Nechta marta `key` chaqirilganini sanab, bu sonni "N log N" (taxminiy solishtirishlar soni) bilan solishtiring — Schwartzian transform tufayli bu ikkisi **teng emasligini** ko'rsating.

**(Qiyin)** O'z qo'lingiz bilan (Timsort'ning **soddalashtirilgan** versiyasi sifatida) quyidagi funksiyani yozing: berilgan ro'yxatni avval "run"larga bo'ling (ketma-ket o'suvchi bo'laklarni toping), so'ng bu run'larni `heapq.merge()` (standart kutubxonadagi, ko'p saralangan ketma-ketlikni birlashtiruvchi funksiya) yordamida birlashtiring. Natijani standart `sorted()` bilan solishtirib, ikkalasi bir xil natija berishini tasdiqlang.

import heapq

def runlarga_bolish(royxat):
    if not royxat:
        return []
    runlar = []
    joriy_run = [royxat[0]]
    for element in royxat[1:]:
        if element >= joriy_run[-1]:
            joriy_run.append(element)
        else:
            runlar.append(joriy_run)
            joriy_run = [element]
    runlar.append(joriy_run)
    return runlar

def soddalashtirilgan_timsort(royxat):
    runlar = runlarga_bolish(royxat)
    return list(heapq.merge(*runlar))

sinov_royxati = [5, 6, 7, 1, 2, 8, 9, 3, 4]
natija = soddalashtirilgan_timsort(sinov_royxati)
print(natija)
print(natija == sorted(sinov_royxati))   # True

## Qisqacha xulosa

Python'ning `sorted()` va `list.sort()` funksiyalari CPython'ning maxsus, Tim Peters ixtiro qilgan **Timsort** algoritmini ishlatadi — bu algoritm ma'lumotdagi tabiiy "run"larni (allaqachon tartiblangan bo'laklarni) topib, ularni aqlli tarzda birlashtiradi, va shu tufayli **eng yomon holatda** klassik O(N log N) kafolatini saqlab qolgan holda, **real dunyodagi, qisman tartiblangan ma'lumotlarda** ancha tezroq (eng yaxshi holatda O(N)gacha) ishlaydi. `key` parametri esa Schwartzian transform orqali samarali amalga oshiriladi — kalit funksiyasi har bir element uchun faqat **bir marta** chaqiriladi, N log N marta emas. Ushbu darsni yakunlab, 10-bob — kundalik ishlatiladigan `list`, `dict`/`set`, `str` va saralashning haqiqiy, ichki mexanizmlarini to'liq qamrab oldi.
