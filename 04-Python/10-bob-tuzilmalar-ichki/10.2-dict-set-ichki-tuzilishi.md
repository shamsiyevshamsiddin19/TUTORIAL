# `dict`/`set` ichida: hash-jadval, ochiq adreslash, tartib saqlanishi

## Bu darsda nimalarni o'rganasiz

- CPython `dict`ining nega Python 3.6'dan beri **"kompakt"** (compact) tuzilmaga ega ekanini va bu nima anglatishini bilib olasiz
- **Hash-jadval**, **hash kolliziyasi** va **ochiq adreslash (open addressing)** tushunchalarini tushunasiz
- Nega Python 3.7'dan beri `dict` **kiritilish tartibini saqlashi** kafolatlanganini, va bu qanday "tasodifiy bonus" emas, balki ataylab qilingan dizayn natijasi ekanini bilasiz
- `dict`/`set` uchun **yaxshi `__hash__`** yozishning nima uchun muhimligini amaliy misolda ko'rasiz

## Nazariy qism

### Nega `dict` va `set` bunchalik tez (O(1))

2.3-darsda `dict` va `set`ning O(1) o'rtacha qidiruv tezligiga ega ekanini o'rgangan bo'lishingiz mumkin — bu, `list`da elementni topish uchun uni **boshidan oxirigacha ko'rib chiqish** (O(N)) kerak bo'lgani bilan solishtirganda, katta farq. Bu tezlik — **hash-jadval** (hash table) deb ataluvchi ma'lumot tuzilmasi tufayli mumkin bo'ladi.

**Manba:** Ushbu dars "Python behind the scenes #10: how Python dictionaries work" (tenthousandmeters.com) tahlili, CPython'ning `Objects/dictobject.c` fayli va Python rasmiy hujjatlari asosida tuzilgan.

### Hash-jadval — asosiy g'oya

Hash-jadvalning asosiy g'oyasi: har bir kalitni (`key`) **hash funksiyasi** orqali bir sonli qiymatga (`hash(kalit)`) aylantiramiz, va shu son asosida, kalit **qayerda saqlanishi kerakligini** to'g'ridan-to'g'ri hisoblab topamiz — massiv bo'ylab **qidirish** o'rniga. Bu — nega dict/set qidiruvi elementlar sonidan (deyarli) mustaqil, doimiy tezlikda (O(1)) ishlashining asosiy sababi:

```python
mening_lugatim = {"olma": 5, "banan": 3, "uzum": 10}

print(hash("olma"))    # masalan: 8362862017685372139 (har ishga tushirishda farq qiladi — PYTHONHASHSEED)
print(hash("banan"))   # boshqa katta son
```

**Muhim:** Python satrlarning hash qiymati **xavfsizlik maqsadida** (hash-flooding hujumlaridan himoyalanish uchun) har safar dastur ishga tushganda **tasodifiy** o'zgaradi (`PYTHONHASHSEED` orqali boshqariladi) — shuning uchun `hash("olma")`ning aniq qiymatiga **hech qachon** tayanmang, u faqat **bitta dastur ishga tushishi davomida** izchil bo'ladi.

### Python 3.6+ "kompakt dict" — ikki qavatli tuzilma

Python 3.5'gacha `dict` — har bir "katak" (slot) to'liq `(hash, kalit, qiymat)` uchligini saqlaydigan, "siyrak" (sparse) massiv edi — bu ko'p bo'sh joy sarflardi. Python 3.6'dan boshlab (CPython'ning ichki optimallashtirishi sifatida boshlangan, keyin rasmiy til xususiyatiga aylangan) `dict` **ikki qismli** tuzilmaga o'tdi:

```
1) "Siyrak" indekslar massivi (kichik, faqat indekslarni saqlaydi):
   [-1, -1, 2, -1, 0, -1, 1, -1]   <- har biri 1-8 bayt (dict kattaligiga qarab)

2) "Zich" yozuvlar massivi (haqiqiy ma'lumot, KIRITILGAN TARTIBDA):
   [0] (hash_olma, "olma", 5)
   [1] (hash_banan, "banan", 3)
   [2] (hash_uzum, "uzum", 10)
```

Kalitni qidirish uchun: avval `hash(kalit)` hisoblanadi, undan **siyrak indekslar massividagi** joy aniqlanadi (`hash % jadval_hajmi` orqali), va o'sha joydagi son — bu kalit **zich yozuvlar massividagi qaysi pozitsiyada** ekanini ko'rsatadi. Bu dizaynning ikki katta afzalligi bor:

1. **Xotira tejaladi:** siyrak massiv faqat kichik indekslarni (masalan 1 bayt) saqlaydi, to'liq `(hash, kalit, qiymat)` uchligini emas.
2. **Kiritilish tartibi tabiiy ravishda saqlanadi:** chunki zich yozuvlar massivi elementlarni **qo'shilgan tartibda, ketma-ket** saqlaydi (o'chirilganlar hisobga olinmasa) — bu Python 3.7'dan beri **rasmiy kafolat** bo'lgan "dict tartibni saqlaydi" xususiyatining texnik asosi!

### Hash kolliziyasi va ochiq adreslash (open addressing)

Ikkita turli kalitning hash qiymati (yoki hattoki `hash % jadval_hajmi` natijasi) **bir xil** chiqib qolishi mumkin — bu **kolliziya** deb ataladi. CPython buni **ochiq adreslash** (open addressing) strategiyasi bilan hal qiladi: agar kerakli joy band bo'lsa, CPython **maxsus formuladagi navbatdagi joyni** ("probe" — zond) tekshiradi, va shu joy bo'shashguncha (yoki kalit topilguncha) davom etadi:

```
probe = (5 * probe + 1 + perturb) & mask
perturb >>= 5   # har safar kamayadi, hash'ning yuqori bitlarini ham hisobga oladi
```

Bu formula — **pseudo-random probing** deb ataladi: u oddiy "keyingi joy" (linear probing) o'rniga, hashning turli bitlarini ishlatib, "klasterlanish" (bir joyga to'planib qolish) muammosini kamaytiradi.

### Qayta o'lchamlash (resizing)

Hash-jadval to'lib borgan sari (odatda **2/3** to'lganda), qidiruv samaradorligi pasaya boshlaydi (ko'proq kolliziyalar). Shuning uchun CPython jadval **2/3** to'lganda avtomatik ravishda uni **kattaroq** (odatda hozirgi hajmning bir necha barobari) jadvalga **qayta quradi** — barcha kalitlarni yangi, kattaroq jadvalga qayta joylashtiradi. Jadval hajmi har doim **2 ning darajasi** (8, 16, 32, 64, ...) bo'ladi.

```python
import sys

d = {}
oldingi = sys.getsizeof(d)
for i in range(20):
    d[i] = i
    joriy = sys.getsizeof(d)
    if joriy != oldingi:
        print(f"{i}-kalitda dict QAYTA QURILDI: {oldingi} -> {joriy} bayt")
        oldingi = joriy
```

### Nega o'zgarmas (immutable) obyektlar odatiy hash-lash uchun mos

`dict`ning kaliti (yoki `set`ning elementi) bo'lish uchun obyekt **hashable** (hash-lanadigan) bo'lishi kerak, va bu — deyarli har doim **immutable** bo'lishni talab qiladi. Sabab — agar kalit **o'zgartirilsa** (masalan, `list` bo'lsa va uning ichi o'zgartirilsa), uning hash qiymati ham o'zgargan bo'lardi, va u endi hash-jadvalda "topilmas" bo'lib qolardi (chunki u boshqa joyga qo'yilgan edi, eski hash asosida):

```python
try:
    lugat = {[1, 2]: "qiymat"}   # TypeError: unhashable type: 'list'
except TypeError as e:
    print("Xatolik:", e)

# Lekin tuple (immutable) — mumkin:
lugat = {(1, 2): "qiymat"}
print(lugat[(1, 2)])   # "qiymat"
```

O'zingizning klassingiz uchun `__eq__`ni qayta belgilasangiz, standart `__hash__` **avtomatik o'chib qoladi** (Python bunday xavfli nomuvofiqlikning oldini olish uchun) — agar klassingiz hashable bo'lishi kerak bo'lsa, `__hash__`ni ham **qo'lda, `__eq__` bilan izchil** tarzda belgilashingiz kerak:

```python
class Nuqta:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, boshqa):
        return isinstance(boshqa, Nuqta) and self.x == boshqa.x and self.y == boshqa.y

    def __hash__(self):
        # MUHIM QOIDA: agar ikki obyekt __eq__ bo'yicha TENG bo'lsa,
        # ularning __hash__ qiymati ham HAR DOIM BIR XIL bo'lishi SHART!
        return hash((self.x, self.y))


a = Nuqta(1, 2)
b = Nuqta(1, 2)
print(a == b)          # True
print(hash(a) == hash(b))   # True — SHART bajarilgan

toplam = {a}
print(b in toplam)   # True — chunki a va b bir xil hash VA bir xil qiymatga ega
```

## Amaliy misol

Hash-jadval afzalligini `list` bilan solishtirib, va noto'g'ri yozilgan `__hash__`/`__eq__` qanday amaliy muammo keltirib chiqarishini ko'rish:

```python
# dict_set_ichki_demo.py
import timeit


def list_vs_set_qidiruv(n=10_000):
    royxat = list(range(n))
    toplam = set(range(n))
    qidirilayotgan = n - 1   # eng yomon holat — list uchun oxirigacha borish kerak

    vaqt_list = timeit.timeit(lambda: qidirilayotgan in royxat, number=1000)
    vaqt_set = timeit.timeit(lambda: qidirilayotgan in toplam, number=1000)

    print(f"{n} elementli to'plamda 1000 marta qidirish:")
    print(f"  list ('in' operatori): {vaqt_list:.4f} soniya  (O(N) — chiziqli)")
    print(f"  set  ('in' operatori): {vaqt_set:.4f} soniya  (O(1) — deyarli o'zgarmas)")
    print(f"  set {vaqt_list / vaqt_set:.0f}x tezroq!")


class NOTOGRI_Nuqta:
    """__eq__ bor, lekin __hash__ QOLDIRILMAGAN — Python buni AVTOMATIK
    hashable-EMAS qiladi, chunki __eq__ni qayta belgilash __hash__ni
    O'CHIRIB QO'YADI (agar aniq belgilanmasa)."""
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, boshqa):
        return self.x == boshqa.x and self.y == boshqa.y
    # __hash__ YOZILMAGAN!


def notogri_hash_muammosi():
    print("\n--- Noto'g'ri __hash__/__eq__ muammosi ---")
    try:
        toplam = {NOTOGRI_Nuqta(1, 2)}
        print("Bu qatorga umuman yetib kelmasligi kerak edi!")
    except TypeError as e:
        print("Kutilgan xatolik:", e)


if __name__ == "__main__":
    list_vs_set_qidiruv()
    notogri_hash_muammosi()
```

## Keng tarqalgan xatolar

**Xato 1:** `hash()` qiymatini dasturlar orasida (masalan, faylga yozib, keyingi ishga tushirishda o'qib) doimiy deb hisoblash.
❌
```python
# fayl1.py (bugun ishga tushirilgan)
print(hash("salom"))   # masalan: -1234567890

# fayl2.py (ertaga ishga tushirilgan, boshqa PYTHONHASHSEED bilan)
print(hash("salom"))   # BUTUNLAY BOSHQA son!
```
✅ To'g'ri: `hash()` qiymatini hech qachon dastur ishga tushirilishlar orasida saqlanadigan, doimiy identifikator sifatida ishlatmang (masalan, ma'lumotlar bazasida kalit sifatida). Agar doimiy, takrorlanadigan hash kerak bo'lsa, `hashlib` moduli (masalan `hashlib.sha256`) ishlatilishi kerak.

**Xato 2:** Mutable obyektni (masalan, o'z klassingizning instance'ini, unda hech qanday `__hash__`/`__eq__` almashtirilmagan bo'lsa ham) `dict` kaliti sifatida ishlatib, keyin uni o'zgartirish.
❌
```python
class Sozlama:
    def __init__(self, nom):
        self.nom = nom

s = Sozlama("A")
lugat = {s: "qiymat"}
s.nom = "B"   # standart __hash__ id() ga asoslangani uchun bu holatda MUAMMO YO'Q,
               # lekin agar __eq__/__hash__ni qiymat asosida qayta yozgan bo'lsangiz-u,
               # keyin qiymatni o'zgartirsangiz — dict SIZNI TOPA OLMAY QOLADI!
```
✅ To'g'ri: agar klassingizda `__eq__`/`__hash__`ni **qiymat asosida** qayta belgilagan bo'lsangiz, uning instance'larini `dict` kaliti yoki `set` elementi sifatida ishlatgandan **keyin**, hash-ga ta'sir qiluvchi atributlarni o'zgartirmang — bu klassik "hash barqarorligi buzilishi" xatosi.

**Xato 3:** Katta hajmdagi ma'lumotda `x in royxat` (list) ishlatib, "nima uchun sekin" deb hayron bo'lish.
❌
```python
ruxsat_etilgan_id_lar = [1, 5, 20, 45, ...]  # 50,000 ta element
if foydalanuvchi_id in ruxsat_etilgan_id_lar:   # HAR safar O(N) qidiruv!
    ...
```
✅ To'g'ri: agar tez-tez "borligini tekshirish" kerak bo'lsa, `list` o'rniga `set`dan foydalaning: `ruxsat_etilgan_id_lar = {1, 5, 20, 45, ...}` — bu 2.5-darsda ko'rgan "qaysi tuzilmani qachon tanlash" mavzusining bevosita, ichki sabab bilan asoslangan davomi.

## Mashq/topshiriq

**(Oson)** `dict` yarating, unga 10 ta kalit-qiymat juftligini turli tartibda qo'shing, so'ng `list(lugat.keys())` chiqarib, ular **aynan siz qo'shgan tartibda** ekanini tasdiqlang.

**(O'rtacha)** `timeit` yordamida, 100,000 elementli `list` va `set`da **oxirgi** elementni qidirishni (eng yomon holat `list` uchun) solishtiring va necha marta `set` tezroq ekanini hisoblang.

**(Qiyin)** `Kitob` klassini yozing (`isbn` va `nom` atributlari bilan). `__eq__`ni faqat `isbn` bo'yicha solishtiradigan qilib, va `__hash__`ni `isbn` asosida, **`__eq__` bilan izchil** tarzda yozing. Ikkita, `isbn` bir xil, lekin `nom` boshqacha bo'lgan `Kitob` obyekti yarating, ularni `set`ga qo'shing va to'plamda faqat **bitta** element qolishini (chunki ular "teng" hisoblanadi) isbotlang.

## Qisqacha xulosa

Python 3.6+dagi `dict` (va shunga o'xshash `set`) — ikki qavatli, "kompakt" hash-jadval: kichik indekslar massivi kalitning zich yozuvlar massividagi o'rnini ko'rsatadi, va aynan shu **zich massivning kiritilgan tartibda saqlanishi** — `dict`ning Python 3.7'dan beri rasmiy kafolatlangan tartib saqlash xususiyatining texnik sababidir. Kolliziyalar **ochiq adreslash** (pseudo-random probing) orqali, jadval to'lib borgani sari esa **avtomatik qayta o'lchamlash** orqali boshqariladi — bu ikkalasi birgalikda O(1) o'rtacha qidiruv tezligini ta'minlaydi. Har qanday obyektni `dict` kaliti yoki `set` elementi sifatida ishlatish uchun u **hashable** bo'lishi, va agar `__eq__` qayta yozilsa, `__hash__` ham **izchil** tarzda qayta yozilishi kerak — bu qoidaning buzilishi eng nozik va topish qiyin bo'lgan xatolarga olib kelishi mumkin.
