# Kompilyatsiya quvuri: source → AST → bytecode

## Bu darsda nimalarni o'rganasiz

- `python skript.py` buyrug'ini bosganingizda, fayl ishga tushishidan oldin nechta bosqichdan o'tishini bilib olasiz
- **AST** (Abstract Syntax Tree — mavhum sintaksis daraxti) nima ekanini va `ast` moduli bilan uni qanday ko'rishni o'rganasiz
- **Code object** (kod obyekti) nima ekanini va u qanday ma'lumot saqlashini bilasiz
- Python nega "interpretatsiya qilinadigan til" deyilsa-da, aslida oraliq **kompilyatsiya** bosqichidan o'tishini tushunasiz

## Nazariy qism

### "Interpretatsiya qilinadigan til" — chala haqiqat

Ko'pincha "Python — interpretatsiya qilinadigan til, C esa — kompilyatsiya qilinadigan til" deyiladi, va bu juda soddalashtirilgan tasavvurga olib keladi: go'yo Python interpretatori har bir qatorni o'qib, darhol, hech qanday oraliq bosqichsiz bajaraveradi. **Aslida bunday emas.** CPython — Python kodini avval **bytecode** deb ataluvchi, past darajadagi, ammo hali ham platformadan mustaqil bo'lgan oraliq tilga **kompilyatsiya qiladi**, va aynan shu bytecode'ni interpretatsiya qiladi (ijro etadi). Ya'ni CPython — bir vaqtning o'zida ham kompilyator, ham interpretator.

**Manba:** Ushbu dars CPython'ning rasmiy `InternalDocs/` hujjatlari, `ast` va `dis` modullari rasmiy hujjatlari (docs.python.org) hamda "Python behind the scenes" turkumidagi (tenthousandmeters.com) chuqur tahlillar asosida tuzilgan.

### To'liq quvur: source kod → bytecode → natija

```
1. Source kod (matn, .py fayl)
        │  Tokenlashtirish (lexer) — matnni "so'zlar" (token)ga bo'lish
        ▼
2. Tokenlar oqimi
        │  Parsing (sintaksis tahlili)
        ▼
3. AST (Abstract Syntax Tree) — kodning daraxt ko'rinishidagi tuzilmasi
        │  Kompilyatsiya (compiler)
        ▼
4. Bytecode — code object ichidagi, past darajadagi buyruqlar ketma-ketligi
        │  Ijro (interpretatsiya) — ceval.c ichidagi katta sikl (8.3-darsda)
        ▼
5. Natija
```

Bu bosqichlarning **1-3** qismi — "kompilyatsiya", 4-5 qismi — "interpretatsiya (ijro)". Muhim farq shundaki, C kabi tillarda 4-bosqich mashina kodiga (protsessor to'g'ridan-to'g'ri tushunadigan buyruqlarga) aylantiriladi va alohida, oldindan (dastur ishga tushishidan oldin) bajariladi; Python'da esa bytecode — protsessor emas, balki **CPython'ning o'zi yozgan virtual mashina (VM)** tushunadigan buyruqlar, va bu kompilyatsiya odatda **dastur ishga tushirilgan zahoti, avtomatik** sodir bo'ladi (garchi natija — `.pyc` fayllar — keshlanishi ham mumkin, 11.2-darsda ko'ramiz).

### 1-2 bosqich: tokenlashtirish va parsing

Bu bosqichlar Python matnini "tushunarli bo'laklar"ga, so'ng grammatik tuzilmaga aylantiradi. Buni o'zingiz ham `tokenize` moduli bilan ko'rishingiz mumkin:

```python
import tokenize
import io

kod = "x = 1 + 2"
for tok in tokenize.generate_tokens(io.StringIO(kod).readline):
    print(tok)
# NAME 'x', OP '=', NUMBER '1', OP '+', NUMBER '2', NEWLINE, ...
```

### 3-bosqich: AST — kodning "daraxt" ko'rinishi

Tokenlar oqimidan **AST** (Abstract Syntax Tree) quriladi — bu Python kodining, matn emas, balki **ierarxik daraxt** shaklidagi tasviri. Har bir tugun (node) — bir amal yoki ifodani bildiradi (masalan "qo'shish", "funksiya chaqiruvi", "if operatori"). AST'ni standart `ast` moduli bilan bevosita ko'rishingiz mumkin:

```python
import ast

kod = "x = 1 + 2 * 3"
daraxt = ast.parse(kod)
print(ast.dump(daraxt, indent=4))
```

Natija (soddalashtirilgan):

```
Module(
    body=[
        Assign(
            targets=[Name(id='x', ctx=Store())],
            value=BinOp(
                left=Constant(value=1),
                op=Add(),
                right=BinOp(
                    left=Constant(value=2),
                    op=Mult(),
                    right=Constant(value=3))))])
```

Diqqat qiling: `2 * 3` — `1 +` dan **ichkarida** joylashgan, chunki amallar ustuvorligi (operator precedence, 1.1-darsda ko'rgan) — matematik amallar tartibi (avval ko'paytirish, keyin qo'shish) — AST darajasida allaqachon **daraxt tuzilishi** orqali hal qilingan. Bu — AST'ning eng muhim vazifasi: matndagi noaniqlikni (masalan, qavslarsiz `1 + 2 * 3` qanday guruhlanishi kerakligini) bir martalik, keyingi bosqichlar uchun aniq tuzilmaga aylantirish.

### AST bilan nima qilish mumkin — amaliy foyda

AST — nafaqat CPython ichida ishlatiladi, balki dasturchilar ham uni to'g'ridan-to'g'ri ishlatishlari mumkin: kod tahlil qiluvchi vositalar (linterlar, `flake8`, `pylint`), avtomatik kod formatlash vositalari (`black`), va hattoki kodni dinamik ravishda o'zgartiruvchi vositalar — barchasi AST bilan ishlaydi.

```python
import ast

kod = """
def salom(ism):
    print(f"Salom, {ism}!")
"""

daraxt = ast.parse(kod)

# Barcha funksiya ta'riflarini topish (oddiy "linter" mantiqi)
for tugun in ast.walk(daraxt):
    if isinstance(tugun, ast.FunctionDef):
        print(f"Funksiya topildi: {tugun.name}, {len(tugun.args.args)} ta argument")
```

### 4-bosqich: AST'dan bytecode'ga

AST tayyor bo'lgach, CPython kompilyatori uni **code object**ga aylantiradi. Code object — kompilyatsiyaning yakuniy mahsuloti: u ichida haqiqiy bytecode buyruqlari (`co_code`), o'zgarmas qiymatlar (`co_consts`), o'zgaruvchi nomlari (`co_varnames`, `co_names`) va boshqa metama'lumotlar saqlanadi.

```python
def misol_funksiya(x, y):
    natija = x + y
    return natija

code_obj = misol_funksiya.__code__

print("Bytecode (xom bayt ko'rinishida):", code_obj.co_code)
print("Konstantalar:", code_obj.co_consts)
print("Lokal o'zgaruvchilar:", code_obj.co_varnames)
print("Argumentlar soni:", code_obj.co_argcount)
print("Fayl nomi:", code_obj.co_filename)
print("Boshlanish qatori:", code_obj.co_firstlineno)
```

Bu code obyektning **inson o'qiy oladigan** ko'rinishini keyingi darsda (8.2) `dis` moduli bilan ko'ramiz — chunki `co_code`ning o'zi shunchaki bayt qatori (`b'\x97\x00|\x00|\x01z\x00}\x02|\x02...'` kabi) bo'lib, uni to'g'ridan-to'g'ri o'qish qiyin.

### Har bir "kod bloki" — o'z code obyektiga ega

Muhim tafsilot: har bir modul, har bir funksiya, har bir klass tanasi — **o'zining alohida** code obyektiga ega. Funksiya ichidagi funksiya (nested function) ham o'z code obyektiga ega, va tashqi funksiyaning `co_consts` ro'yxatida ichki code obyektga havola saqlanadi:

```python
def tashqi():
    def ichki():
        return 42
    return ichki

print(tashqi.__code__.co_consts)
# (None, <code object ichki at 0x...>) — ichki() funksiyaning code obyekti
# tashqi() ning konstantalar ro'yxatida saqlanadi!
```

## Amaliy misol

Bir xil dasturning har bir bosqichini (source → AST → code object → bytecode metama'lumotlari) ketma-ket ko'rish:

```python
# kompilyatsiya_bosqichlari.py
import ast
import dis


kod_matni = """
def eng_katta(a, b):
    if a > b:
        return a
    else:
        return b
"""

print("=" * 60)
print("1-BOSQICH: Source kod")
print("=" * 60)
print(kod_matni)

print("=" * 60)
print("2-BOSQICH: AST (Abstract Syntax Tree)")
print("=" * 60)
daraxt = ast.parse(kod_matni)
print(ast.dump(daraxt, indent=2))

print("\n" + "=" * 60)
print("3-BOSQICH: Compile() orqali code obyekt olish")
print("=" * 60)
kod_obyekti = compile(kod_matni, filename="<demo>", mode="exec")
# exec() code obyektni haqiqatan bajaradi — bu funksiya ta'rifini "ro'yxatdan o'tkazadi"
nomlar_maydoni = {}
exec(kod_obyekti, nomlar_maydoni)
eng_katta_funksiya = nomlar_maydoni["eng_katta"]

print("Funksiyaning ichki code obyekti:")
ichki_code = eng_katta_funksiya.__code__
print("  co_varnames:", ichki_code.co_varnames)
print("  co_consts:", ichki_code.co_consts)
print("  co_names:", ichki_code.co_names)

print("\n" + "=" * 60)
print("4-BOSQICH: Bytecode (dis moduli orqali — 8.2-darsda batafsil)")
print("=" * 60)
dis.dis(eng_katta_funksiya)

print("\n" + "=" * 60)
print("5-BOSQICH: Haqiqiy ijro")
print("=" * 60)
print("eng_katta(10, 25) =", eng_katta_funksiya(10, 25))
```

Bu dastur `compile()` ichki funksiyasi orqali AST'ni to'g'ridan-to'g'ri code obyektga aylantiradi va shu code obyektni `exec()` bilan bajaradi — bu aynan Python interpretatori `python skript.py` buyrug'ida **avtomatik ravishda** bajaradigan ishning ochiq, qo'lda takrorlangan versiyasi.

## Keng tarqalgan xatolar

**Xato 1:** "Python — interpretatsiya qilinadigan til, demak har bir qator alohida-alohida o'qib bajariladi" deb tushunish.
❌ Shu asosda, masalan, funksiyaning ustidan (ta'rifidan) o'tishda ichidagi kodning sintaksis xatolari darhol aniqlanmaydi degan noto'g'ri xulosaga kelish.
✅ To'g'ri: Python moduli **butunligicha** (yoki funksiya butunligicha) avval AST'ga, keyin bytecode'ga kompilyatsiya qilinadi — shuning uchun funksiya ichidagi **sintaksis** xatosi (masalan noto'g'ri qavs) modul yuklanayotganda darhol aniqlanadi, hattoki o'sha funksiya hech qachon chaqirilmasa ham. Faqat **runtime** xatolari (masalan, mavjud bo'lmagan o'zgaruvchiga murojaat) funksiya haqiqatan chaqirilganda paydo bo'ladi.

**Xato 2:** `compile()`/`exec()`/`eval()` funksiyalarini ishonchsiz, tashqi manbadan kelgan matn bilan ehtiyotsiz ishlatish.
❌
```python
foydalanuvchi_kiritgan = input("Formulani kiriting: ")
natija = eval(foydalanuvchi_kiritgan)   # XAVFLI! foydalanuvchi ixtiyoriy kod bajarishi mumkin
```
✅ To'g'ri: `eval()`/`exec()` foydalanuvchidan kelgan, ishonchsiz matn ustida **hech qachon** ishlatilmasligi kerak — bu xavfsizlik teshigi (12-bobda ko'rgan xavfsiz terminal odatlariga o'xshab, bu ham "ishonchsiz manbadan kelgan kodni ishga tushirish" muammosi). Matematik ifodalarni xavfsiz baholash uchun maxsus kutubxonalar (`ast.literal_eval` — faqat literal qiymatlar uchun, yoki maxsus parser) ishlatilishi kerak.

**Xato 3:** Har bir funksiya chaqiruvida kod **qaytadan** AST'ga va bytecode'ga kompilyatsiya qilinadi deb o'ylash.
❌ "Funksiyani sikl ichida chaqirsam, har safar qaytadan kompilyatsiya bo'ladi, shuning uchun sekin" deb funksiyani "qo'lda inline qilish".
✅ To'g'ri: kompilyatsiya **bir marta**, modul birinchi yuklanganda (yoki `.pyc` keshdan yuklanganda — 11.2-dars) sodir bo'ladi. Funksiya chaqirilganda faqat uning **allaqachon tayyor** code obyekti asosida yangi frame (8.3-dars) yaratiladi va bytecode ijro etiladi — qaytadan kompilyatsiya bo'lmaydi.

## Mashq/topshiriq

**(Oson)** `ast.parse()` yordamida `"x = 5 if True else 10"` ifodasining AST'ini chop eting (`ast.dump(daraxt, indent=2)` bilan) va daraxtda `IfExp` tugunini toping.

**(O'rtacha)** `ast.walk()` yordamida berilgan kod matnidagi **barcha** ishlatilgan o'zgaruvchi nomlarini (`ast.Name` tugunlari) yig'ib, takrorlanmas ro'yxat sifatida chop etuvchi funksiya yozing.

**(Qiyin)** `compile()` va `exec()` yordamida oddiy "kalkulyator" yarating: foydalanuvchidan faqat sonlar va `+`, `-`, `*`, `/` belgilaridan iborat matematik ifoda oling, uni **avval** `ast.parse()` bilan tahlil qiling va daraxtda faqat `ast.Constant`, `ast.BinOp`, `ast.Add`, `ast.Sub`, `ast.Mult`, `ast.Div`, `ast.Expression` tugunlari borligini tekshiring (xavfsizlik uchun), va faqat shundan keyin `eval(compile(daraxt, "<kalkulyator>", "eval"))` bilan hisoblang.

## Qisqacha xulosa

Python kodi ishga tushirilganda, u avval **tokenlashtirilib**, so'ng **AST** (Abstract Syntax Tree) — kodning daraxt ko'rinishidagi, noaniqliksiz tuzilmasiga aylantiriladi, keyin bu daraxt **code obyekt**iga (bytecode + metama'lumotlar) kompilyatsiya qilinadi, va faqat shu bytecode CPython VM tomonidan **interpretatsiya** qilinadi — ya'ni Python bir vaqtning o'zida ham kompilyator, ham interpretator. `ast` moduli bu jarayonning ochiq oynasi bo'lib, kod tahlil qiluvchi vositalar (linter, formatter) va hattoki xavfsiz "sandbox" hisoblagichlar yaratish uchun ishlatilishi mumkin. Keyingi darsda biz aynan bytecode'ning o'zini — `dis` moduli yordamida — o'qishni o'rganamiz.
