# `dis` moduli — bytecode'ni o'qishni o'rganish

## Bu darsda nimalarni o'rganasiz

- `dis.dis()` yordamida istalgan Python funksiyasining bytecode'ini chop etishni o'rganasiz
- Eng ko'p uchraydigan bytecode buyruqlarini (`LOAD_FAST`, `STORE_FAST`, `BINARY_OP`, `CALL`, ...) tushunasiz
- Bytecode orqali "aynan qanday kod tezroq ishlaydi" degan savolga **o'zingiz** javob topishni o'rganasiz
- Python versiyalari orasida bytecode qanday o'zgarib borishini (masalan 3.11+da katta o'zgarishlar) bilib olasiz

## Nazariy qism

### `dis` — "disassembler" (bytecode ochuvchi)

`dis` — Python standart kutubxonasidagi modul bo'lib, u code obyektning xom bayt ko'rinishidagi bytecode'ini (`co_code`) **inson o'qiy oladigan** matn ko'rinishiga o'giradi. Bu — C/assembly dunyosidagi "disassembler" tushunchasining Python'dagi analogi.

**Manba:** Ushbu dars Python rasmiy hujjatlari (`docs.python.org/3/library/dis.html`) va CPython'ning `InternalDocs/interpreter.md` fayli asosida tuzilgan. **Muhim eslatma:** bytecode formatining o'zi — CPython'ning **implementatsiya tafsiloti**, u Python versiyasidan versiyaga o'zgarishi mumkin (va o'zgarib ham turadi — masalan Python 3.11'da opcode'lar soni va formati sezilarli o'zgargan). Shuning uchun bu dars sizga **kodning aynan qaysi opcode'ga aylanishini yodlash** emas, balki **bytecode qanday o'qilishini va undan qanday xulosa chiqarishni** o'rgatadi.

### Eng oddiy misol

```python
import dis

def qoshish(a, b):
    return a + b

dis.dis(qoshish)
```

Natija (Python 3.12 uchun, versiyaga qarab bir oz farq qilishi mumkin):

```
  2           0 RESUME                   0

  3           2 LOAD_FAST                0 (a)
              4 LOAD_FAST                1 (b)
              6 BINARY_OP                0 (+)
             10 RETURN_VALUE
```

Buni qatorma-qator o'qiymiz:

- **Chap ustun (2, 3)** — bu bytecode qaysi Python **manba qatori**ga tegishli (2-qator — `def` qatori, 3-qator — `return` qatori). Bu — xatolik yuz berganda Python sizga aniq qator raqamini ko'rsata olishining sababi!
- **O'rtadagi ustun (0, 2, 4, 6, 10)** — bytecode'dagi **bayt ofset**i (har bir buyruq necha baytdan boshlanadi).
- **Buyruq nomlari** (`RESUME`, `LOAD_FAST`, `BINARY_OP`, `RETURN_VALUE`) — bajariladigan **opcode**lar.
- **Qavs ichidagi qiymatlar** (`(a)`, `(b)`, `(+)`) — `dis` modulining o'zi qo'shgan, o'qishni osonlashtiruvchi izohlar (haqiqiy bytecode'da faqat sonli indekslar bor).

### Stack-asosli VM — bytecode nimaga asoslangan

CPython'ning bytecode VM'i — **stack-asosli** (stack-based) virtual mashina: deyarli har bir operatsiya qiymatlarni **stack** (steк — oxiri-kirgan-birinchi-chiqadigan navbat)dan oladi va natijani yana stack'ga qo'yadi. Yuqoridagi misolda:

1. `LOAD_FAST 0 (a)` — `a` o'zgaruvchisining qiymatini stack'ga **qo'yadi** (push).
2. `LOAD_FAST 1 (b)` — `b`ning qiymatini ham stack'ga qo'yadi. Endi stack'da ikkita qiymat bor.
3. `BINARY_OP 0 (+)` — stack'dan **ikkita** qiymatni oladi (pop), ularni qo'shadi, natijani stack'ga qaytadan qo'yadi.
4. `RETURN_VALUE` — stack'ning tepasidagi qiymatni funksiyaning natijasi sifatida qaytaradi.

Bu — deyarli **barcha** stack-asosli VM'larning (Java Virtual Machine, .NET CLR va boshqalar) umumiy tamoyili: registrlar (protsessor registrlari kabi nomlangan joylar) o'rniga, hamma narsa vaqtinchalik "stack"da saqlanadi.

### Eng muhim opcode'lar — lug'at

| Opcode | Ma'nosi |
|---|---|
| `LOAD_FAST` | Lokal o'zgaruvchini stack'ga qo'yish (tez, chunki indeks orqali, nom qidiruvisiz) |
| `LOAD_GLOBAL` | Global (yoki built-in) o'zgaruvchini stack'ga qo'yish (sekinroq, nom bo'yicha qidiruv) |
| `LOAD_CONST` | Konstantani (`co_consts`dan) stack'ga qo'yish |
| `STORE_FAST` | Stack'ning tepasidagi qiymatni lokal o'zgaruvchiga saqlash |
| `BINARY_OP` | Ikkilik amal (`+`, `-`, `*`, ...) — Python 3.11+da barcha arifmetik amallar shu **bitta** opcode ostida birlashtirilgan (parametr orqali qaysi amal ekani ko'rsatiladi) |
| `COMPARE_OP` | Solishtirish amali (`<`, `==`, ...) |
| `CALL` | Funksiya (yoki metod) chaqirish |
| `RETURN_VALUE` | Funksiyadan qiymat qaytarish |
| `POP_JUMP_IF_FALSE` | Shartli sakrash — `if`/`while` mantig'ining asosi |
| `JUMP_BACKWARD` | Orqaga sakrash — sikllarning asosi |
| `BUILD_LIST`, `BUILD_TUPLE`, `BUILD_MAP` | Ro'yxat/tuple/lug'at yaratish |

### `LOAD_FAST` vs `LOAD_GLOBAL` — nega lokal o'zgaruvchilar tezroq

Bytecode orqali **amaliy** xulosa chiqarish mumkin bo'lgan eng klassik misol — nega funksiya ichida lokal o'zgaruvchiga murojaat qilish, global o'zgaruvchiga murojaat qilishdan **tezroq**:

```python
import dis

x = 10  # global o'zgaruvchi

def lokal_versiya():
    y = 10  # lokal o'zgaruvchi
    return y + y

def global_versiya():
    return x + x

print("--- Lokal versiya ---")
dis.dis(lokal_versiya)

print("\n--- Global versiya ---")
dis.dis(global_versiya)
```

`lokal_versiya`da `LOAD_FAST` ishlatiladi — bu, mohiyatan, oddiy **massiv indeksi** bo'yicha o'qish (`co_varnames`dagi o'zgaruvchilar massividan, O(1) tezlikda). `global_versiya`da esa `LOAD_GLOBAL` ishlatiladi — bu **lug'at bo'yicha nom qidiruvi** (modulning `__dict__`ida, va agar u yerda topilmasa, `builtins` modulida ham qidiriladi). Lug'at qidiruvi (hattoki O(1) o'rtacha bo'lsa ham) massiv indeksidan sekinroq — chunki u hash hisoblash va solishtirishni talab qiladi (10.2-darsda dict ichki tuzilishini ko'rganda buni chuqurroq tushunasiz).

Bu — **nega ko'p marta murojaat qilinadigan global qiymatni funksiya boshida lokal o'zgaruvchiga "keshlash" tezlikni oshirishi mumkinligi**ning texnik sababi:

```python
import math
import time

def sekinroq(n):
    natija = 0
    for i in range(n):
        natija += math.sqrt(i)   # har iteratsiyada math.sqrt GLOBAL qidiruv orqali topiladi
    return natija

def tezroq(n):
    sqrt = math.sqrt   # BIR MARTA lokal o'zgaruvchiga saqlab olamiz
    natija = 0
    for i in range(n):
        natija += sqrt(i)         # endi LOKAL qidiruv — tezroq
    return natija
```

### Python 3.11+ katta o'zgarish: PEP 659 va yangi bytecode

Python 3.11'da bytecode formatiga katta o'zgarishlar kiritildi — bu haqida 8.4-darsda batafsil to'xtalamiz, lekin shuni bilish kifoya: Python 3.10'da alohida bo'lgan `BINARY_ADD`, `BINARY_SUBTRACT`, `BINARY_MULTIPLY` kabi o'nlab opcode'lar 3.11'da yagona `BINARY_OP` ostida birlashtirildi (aniq amal — parametr orqali), va bu o'zgarishlarning asosiy maqsadi — **specializing adaptive interpreter** (moslashuvchan interpretator) uchun poydevor yaratish edi.

## Amaliy misol

Turli konstruksiyalarning bytecode'ini solishtirish orqali amaliy xulosalar chiqarish:

```python
# dis_demo.py
import dis


def royxat_comprehension():
    return [i * 2 for i in range(10)]


def royxat_append():
    natija = []
    for i in range(10):
        natija.append(i * 2)
    return natija


def sikl_bilan_qidiruv(elementlar, qidirilayotgan):
    return qidirilayotgan in elementlar


def if_elif_zanjiri(x):
    if x == 1:
        return "bir"
    elif x == 2:
        return "ikki"
    else:
        return "boshqa"


print("=" * 60)
print("List comprehension vs qo'lda append() sikli")
print("=" * 60)
print("\n--- List comprehension ---")
dis.dis(royxat_comprehension)
print("\n--- Qo'lda append() ---")
dis.dis(royxat_append)
# Comprehension odatda kamroq, ixchamroq bytecode ishlatadi — bu 2.4-darsda
# aytilgan "comprehension'lar odatda tezroq" iddaosining bytecode darajasidagi isboti.

print("\n" + "=" * 60)
print("if/elif zanjiri qanday sakrash (jump) buyruqlariga aylanadi")
print("=" * 60)
dis.dis(if_elif_zanjiri)
```

Bu dasturni ishga tushirib, `for` sikli bilan `append()` chaqirish (`CALL` opcode'i har iteratsiyada) va list comprehension (ichki, maxsus optimallashtirilgan mexanizm) o'rtasidagi bytecode farqini o'z ko'zingiz bilan ko'rasiz.

## Keng tarqalgan xatolar

**Xato 1:** Bytecode'ning aniq nomlarini (masalan `BINARY_ADD`) yodlab, ularga kod yozishda tayanish.
❌ "Python 3.10'da `BINARY_ADD` bor edi" deb, buni versiyalar orasida o'zgarmas fakt sifatida ishlatish.
✅ To'g'ri: bytecode — **implementatsiya tafsiloti**, versiyadan versiyaga o'zgaradi (3.11'da katta o'zgarish bo'lganidek). `dis` moduli — tushunish va profilaktik tahlil uchun ajoyib vosita, lekin unga asoslangan kod (masalan, opcode nomini string sifatida tekshiradigan kod) versiyalar orasida ishlamay qolishi mumkin.

**Xato 2:** Bytecode'dagi buyruqlar sonini "tezlik" bilan to'g'ridan-to'g'ri tenglashtirish.
❌ "Bu funksiyada 10 ta bytecode buyrug'i bor, u funksiyada 15 ta — demak birinchisi tezroq" degan xulosaga kelish.
✅ To'g'ri: har bir bytecode buyrug'ining **o'zi bajarilish narxi turlicha** (masalan, `CALL` — funksiya chaqirish — `LOAD_FAST`dan ancha "og'ir"). Bytecode sonini emas, balki **qaysi turdagi** opcode'lar (ayniqsa `CALL`, `LOAD_GLOBAL` kabi nisbatan qimmat operatsiyalar) borligini va real vaqtni (`timeit`, 13-bob) hisobga olish kerak.

**Xato 3:** `dis.dis()`ni faqat funksiyalar uchun ishlaydi deb o'ylash.
❌ Modul yoki klass darajasidagi kodni tahlil qila olmaslik.
✅ To'g'ri: `dis.dis()` funksiya, metod, modul (`compile()` orqali olingan code obyekt), hattoki satr ko'rinishidagi kod (`dis.dis("x = 1 + 1")`) uchun ham ishlaydi — u `dis`ga uzatilgan narsaning turiga qarab avtomatik moslashadi.

## Mashq/topshiriq

**(Oson)** Ikki argumentni ko'paytiradigan oddiy funksiya yozing va `dis.dis()` orqali uning bytecode'ini chop eting. Nechta `LOAD_FAST` va nechta `BINARY_OP` borligini toping.

**(O'rtacha)** `while` sikli bilan `for` siklining bytecode'ini solishtiring (masalan, ikkalasi ham 0 dan 9 gacha sanaydigan variantda). `JUMP_BACKWARD` (yoki shunga o'xshash sakrash) buyrug'i qayerda ekanini toping va nima uchun sikllar bytecode darajasida "sakrash" orqali amalga oshirilishini tushuntiring.

**(Qiyin)** Quyidagi ikkita funksiyaning bytecode'ini solishtiring: biri `str` qo'shish uchun `+` operatoridan sikl ichida foydalanadi (`natija = natija + qism`), ikkinchisi `str.join()` metodidan foydalanadi. Bytecode darajasida qaysi yondashuvda `CALL` va `BINARY_OP` operatsiyalari ko'proq sikl ichida takrorlanishini aniqlang, va bu nima uchun `str.join()` odatda tezroq ekanligini (satrlar immutable ekanini 7.4-darsdan eslang) tushuntirib bering.

## Qisqacha xulosa

`dis` moduli CPython'ning stack-asosli bytecode VM'i ishlatadigan buyruqlarni (`LOAD_FAST`, `BINARY_OP`, `CALL`, sakrash buyruqlari va h.k.) inson o'qiy oladigan shaklda ko'rsatadi, va bu orqali "nega bu kod tezroq" degan savolga taxmin emas, **dalil** bilan javob berish mumkin bo'ladi — masalan, lokal o'zgaruvchilarning (`LOAD_FAST`, massiv indeksi) global o'zgaruvchilardan (`LOAD_GLOBAL`, lug'at qidiruvi) tezroq ekanini, yoki `str.join()`ning sikl ichidagi `+` dan nega samaraliroq ekanini bytecode darajasida ko'rish mumkin. Shu bilan birga, bytecode formatining o'zi CPython versiyasiga bog'liq implementatsiya tafsiloti ekanini yodda tutish kerak — u yodlash uchun emas, **tushunish va tahlil qilish** uchun vosita.
