# 12.2. `threading` moduli chuqur

## Bu darsda nimalarni o'rganasiz

- `threading.Thread` qanday OS darajasidagi oqim (native thread) yaratadi
- Qulflar (`Lock`, `RLock`), sharoit o'zgaruvchilari (`Condition`), hodisalar (`Event`), semaforlar (`Semaphore`)
- O'lik qulf (deadlock) qanday paydo bo'ladi va undan qanday qochish mumkin
- `queue.Queue` — thread-safe navbat orqali producer-consumer pattern
- `threading.local()` — har bir oqim uchun alohida ma'lumot saqlash
- `concurrent.futures.ThreadPoolExecutor` — yuqori darajadagi abstraksiya

## Nazariy qism

**Manba:** Python rasmiy dokumentatsiyasi (`threading` va `concurrent.futures` modullari), CPython manba kodi (`Modules/_threadmodule.c`).

### `Thread` obyekti va OS oqimlari

`threading.Thread` — bu Python'ning yupqa qatlami OS (operatsion tizim) darajasidagi haqiqiy oqim ustida (POSIX'da `pthread`, Windows'da native thread). `Thread(target=funksiya).start()` chaqirilganda CPython C darajasida `pthread_create()` (yoki Windows ekvivalenti) chaqiradi — bu haqiqiy, yadro tomonidan boshqariladigan bajarilish oqimi, "engil" (green thread) yoki koroutina emas.

12.1-darsda ko'rganimizdek, GIL barcha bu oqimlarning Python bytecode bajarishini ketma-ketlashtiradi — lekin har bir oqim baribir o'zining C darajasidagi stack'iga, va OS jadval tuzuvchisi (scheduler) tomonidan mustaqil boshqarilishga ega. Bu shuni anglatadiki, oqimlar orasidagi almashinuv **determinist emas** — istalgan bytecode instruksiyadan keyin GIL boshqa oqimga o'tib ketishi mumkin, va aynan qachon bo'lishi OS scheduler'iga bog'liq.

### Poyga sharoiti (race condition) va `Lock`

Agar bir nechta oqim umumiy o'zgaruvchan holatni (masalan, oddiy `int` hisoblagich, yoki `list`) **ketma-ket bo'lmagan tarzda** o'zgartirsa, natija predictable bo'lmay qoladi. Eng oddiy yechim — `threading.Lock`:

```python
import threading

hisoblagich = 0
qulf = threading.Lock()

def orttirish():
    global hisoblagich
    for _ in range(100_000):
        with qulf:          # faqat bitta oqim bu blokka kira oladi
            hisoblagich += 1
```

`Lock` ikkita holatga ega: qulflangan va qulflanmagan. `acquire()` (yoki `with qulf:`) qulf bo'shashini kutadi, so'ng uni egallaydi; `release()` uni bo'shatadi. Agar bitta oqim `Lock`ni ikkinchi marta (o'zi allaqachon egallab turgan holda) `acquire()` qilishga urinsa — bu **o'zini-o'zi qulflab qo'yish (self-deadlock)** bo'ladi, chunki oddiy `Lock` qayta-kirish (reentrant) emas.

### `RLock` — qayta kirish mumkin bo'lgan qulf

Agar bir xil oqim bir nechta ichma-ich funksiyada bir xil qulfni qayta-qayta egallashi kerak bo'lsa (masalan, rekursiv metod), `threading.RLock` ishlatiladi — u qaysi oqim uni necha marta egallaganini hisoblab boradi, va faqat bir xil sondagi `release()` chaqirilgandan keyingina to'liq bo'shaydi.

### O'lik qulf (deadlock)

Klassik deadlock ikkita (yoki undan ko'p) oqim ikkita qulfni **teskari tartibda** so'raganda yuz beradi:

```
Oqim A: qulf_1.acquire() → qulf_2.acquire()  (kutadi)
Oqim B: qulf_2.acquire() → qulf_1.acquire()  (kutadi)
```

Agar A `qulf_1`ni, B esa `qulf_2`ni bir vaqtda egallab olsa, ikkalasi ham abadiy bir-birini kutib qoladi — dastur "osilib qoladi". Bu muammoning eng ishonchli yechimi — **barcha oqimlarda qulflarni doim bir xil, global tartibda so'rash** (masalan, har doim avval `qulf_1`, keyin `qulf_2`). Murakkab tizimlarda `threading.RLock` bilan timeout (`acquire(timeout=5)`) ishlatib, muvaffaqiyatsizlikni aniqlash va qayta urinish strategiyasi ham qo'llaniladi.

### `Condition`, `Event`, `Semaphore`

- **`threading.Event`** — eng sodda signalizatsiya: bitta bayroq (`set()`/`clear()`/`is_set()`), boshqa oqimlar `wait()` bilan bayroq o'rnatilishini kutadi. Odatda "ishni boshlash signali" yoki "to'xtatish so'rovi" uchun ishlatiladi.

- **`threading.Condition`** — `Lock` bilan birlashtirilgan, murakkabroq "kutish + bildirish" naqshi uchun (masalan, producer-consumer): oqim `wait()` bilan qulfni vaqtincha bo'shatib uxlaydi, boshqa oqim `notify()`/`notify_all()` bilan uyg'otadi.

- **`threading.Semaphore(n)`** — bir vaqtning o'zida faqat `n` ta oqimga resursga kirish huquqini beradi (masalan, bir vaqtda maksimal 5 ta tarmoq ulanishini cheklash).

### `queue.Queue` — thread-safe navbat

Ko'p oqimli dasturlarda eng xavfsiz va tez-tez tavsiya etiladigan naqsh — umumiy o'zgaruvchini to'g'ridan-to'g'ri qulflar bilan boshqarish o'rniga, **`queue.Queue`** orqali ma'lumot uzatish (producer-consumer pattern). `Queue` o'zi ichki `Lock` va `Condition` bilan to'liq thread-safe qilingan — dasturchi hech qanday qo'shimcha sinxronlash yozishi shart emas:

```python
import queue
import threading

navbat = queue.Queue()

def ishlab_chiqaruvchi():
    for i in range(10):
        navbat.put(i)
    navbat.put(None)  # "tugadi" signali

def isteʼmolchi():
    while True:
        element = navbat.get()
        if element is None:
            break
        print("Qayta ishlandi:", element)
```

### `threading.local()` — oqimga xos ma'lumot

Ba'zan har bir oqim o'zining mustaqil holatiga ega bo'lishi kerak (masalan, veb-server'da har bir so'rovni qayta ishlaydigan oqim o'z ma'lumotlar bazasi ulanishiga ega bo'lishi kerak). `threading.local()` shu uchun mo'ljallangan — u har bir oqim uchun **alohida** atribut qiymatlarini saqlaydigan maxsus obyekt yaratadi, garchi kod bir xil o'zgaruvchi nomidan foydalansa ham:

```python
import threading

ulanish_maʼlumoti = threading.local()

def db_ulanishini_olish():
    if not hasattr(ulanish_maʼlumoti, "ulanish"):
        ulanish_maʼlumoti.ulanish = f"Ulanish#{threading.get_ident()}"
    return ulanish_maʼlumoti.ulanish
```

### `concurrent.futures.ThreadPoolExecutor`

Har bir vazifa uchun qo'lda `Thread` yaratish, boshqarish va yig'ish (`join()`) og'ir va xatoga moyil. `ThreadPoolExecutor` bu jarayonni avtomatlashtiradi — oldindan belgilangan sondagi "ishchi" oqimlar puli (pool) vazifalarni navbatdan olib bajaradi:

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def veb_sorov(url):
    # I/O-bog'liq ish (GIL bo'shatiladi)
    ...
    return f"{url}: 200 OK"

urllar = ["https://a.com", "https://b.com", "https://c.com"]
with ThreadPoolExecutor(max_workers=3) as executor:
    kelajaklar = {executor.submit(veb_sorov, u): u for u in urllar}
    for kelajak in as_completed(kelajaklar):
        print(kelajak.result())
```

## Amaliy misol

```python
"""
threading_demo.py — Lock, deadlock, Queue va ThreadPoolExecutor
naqshlarini ko'rsatuvchi to'liq demo.
"""
import threading
import time
from concurrent.futures import ThreadPoolExecutor
from queue import Queue


def qulfsiz_va_qulfli_hisoblash():
    """Poyga sharoitini va Lock yechimini solishtirish."""
    def orttirish(hisoblagich_ref, qulf=None, n=200_000):
        for _ in range(n):
            if qulf:
                with qulf:
                    hisoblagich_ref[0] += 1
            else:
                hisoblagich_ref[0] += 1

    # Qulfsiz — natija noaniq (odatda kutilgandan kam)
    hisoblagich = [0]
    threadlar = [threading.Thread(target=orttirish, args=(hisoblagich,)) for _ in range(4)]
    for t in threadlar:
        t.start()
    for t in threadlar:
        t.join()
    print(f"Qulfsiz, 4 oqim x 200_000: kutilgan=800000, olindi={hisoblagich[0]}")

    # Qulfli — har doim to'g'ri
    hisoblagich = [0]
    qulf = threading.Lock()
    threadlar = [
        threading.Thread(target=orttirish, args=(hisoblagich, qulf)) for _ in range(4)
    ]
    for t in threadlar:
        t.start()
    for t in threadlar:
        t.join()
    print(f"Qulf bilan, 4 oqim x 200_000: kutilgan=800000, olindi={hisoblagich[0]}")


def producer_consumer_demo():
    navbat: Queue = Queue()
    natijalar = []

    def ishlab_chiqaruvchi():
        for i in range(5):
            navbat.put(i * i)
            time.sleep(0.01)
        navbat.put(None)

    def isteʼmolchi():
        while True:
            element = navbat.get()
            if element is None:
                break
            natijalar.append(element)

    ishlab = threading.Thread(target=ishlab_chiqaruvchi)
    isteʼmol = threading.Thread(target=isteʼmolchi)
    ishlab.start()
    isteʼmol.start()
    ishlab.join()
    isteʼmol.join()
    print("Producer-consumer natijasi:", natijalar)


def executor_demo():
    def ish(n):
        time.sleep(0.1)
        return n * n

    with ThreadPoolExecutor(max_workers=4) as executor:
        natijalar = list(executor.map(ish, range(8)))
    print("ThreadPoolExecutor natijasi:", natijalar)


if __name__ == "__main__":
    qulfsiz_va_qulfli_hisoblash()
    producer_consumer_demo()
    executor_demo()
```

Chiqishi taxminan:

```
Qulfsiz, 4 oqim x 200_000: kutilgan=800000, olindi=734281   # noaniq, ishga tushirishdan ishga tushirishga o'zgaradi
Qulf bilan, 4 oqim x 200_000: kutilgan=800000, olindi=800000  # har doim to'g'ri
Producer-consumer natijasi: [0, 1, 4, 9, 16]
ThreadPoolExecutor natijasi: [0, 1, 4, 9, 16, 25, 36, 49]
```

## Keng tarqalgan xatolar

1. **Umumiy holatni qulfsiz o'zgartirish, chunki "GIL bor-ku, xavfsiz bo'lishi kerak" deb o'ylash.** GIL faqat bitta bytecode instruksiyani atomik qiladi, lekin `x += 1` kabi ko'p qadamli operatsiyalarni emas (12.1-darsda ko'rdik). Har doim umumiy o'zgaruvchan holatni `Lock` yoki `Queue` bilan himoya qiling.

2. **Qulflarni turli tartibda so'rash natijasida deadlock.** Agar loyihada bir nechta qulf bo'lsa, ularni so'rash tartibini kod bazasi bo'ylab izchil saqlang, yoki imkon qadar bitta qulfdan foydalaning.

3. **`Thread`ni `daemon=True` qilmasdan, dastur asosiy oqim tugagach ham "osilib qolishi".** Agar fon oqimi (background thread) cheksiz tsiklda ishlasa va uni `daemon=True` deb belgilamasangiz, Python dasturi hatto asosiy kod tugagandan keyin ham chiqmaydi (interpretator barcha demon bo'lmagan oqimlar tugashini kutadi).

## Mashq/topshiriq

1. Yuqoridagi `qulfsiz_va_qulfli_hisoblash()` funksiyasini `threading.RLock` bilan qayta yozing va nima uchun bu holatda (oddiy, rekursiv bo'lmagan increment) `Lock` bilan `RLock` orasida amaliy farq yo'qligini, lekin `RLock`ning bir oz qo'shimcha overhead'i borligini tushuntiring.

2. Ikkita qulf (`qulf_a`, `qulf_b`) va ikkita oqim yordamida qasddan **deadlock** yarating (oqim 1: `qulf_a` so'ng `qulf_b`; oqim 2: `qulf_b` so'ng `qulf_a`, orada `time.sleep(0.1)` bilan poyga oynasini kengaytiring), so'ng buni tuzatish uchun ikkala oqimda ham bir xil tartibni (`qulf_a` so'ng `qulf_b`) qo'llang.

3. `threading.local()`dan foydalanib, 3 ta oqim har biri o'z "hisoblagichi" bilan mustaqil ishlashini, va ular bir-birining qiymatiga ta'sir qilmasligini ko'rsating.

**Javoblar:**

1.
```python
qulf = threading.RLock()  # Lock o'rniga
```
Bu holatda amaliy farq yo'q, chunki bitta oqim `with qulf:` blokiga faqat bir marta, ichma-ich emas kiradi. `RLock` qo'shimcha ravishda "qaysi oqim, necha marta egallagan" ma'lumotini ichida saqlaydi — bu oddiy `Lock`ka nisbatan bir oz ko'proq xotira va hisoblash (counter yuritish) talab qiladi, shuning uchun sodda, rekursiv bo'lmagan holatlarda oddiy `Lock` afzalroq (arzonroq).

2.
```python
qulf_a = threading.Lock()
qulf_b = threading.Lock()

def oqim_1():
    with qulf_a:
        time.sleep(0.1)
        with qulf_b:   # bu yerda oqim_2 allaqachon qulf_b'ni ushlab olgan bo'lishi mumkin -> deadlock
            print("oqim_1 ikkalasini ham oldi")

def oqim_2():
    with qulf_b:
        time.sleep(0.1)
        with qulf_a:   # deadlock
            print("oqim_2 ikkalasini ham oldi")

# Tuzatish: ikkala oqimda ham bir xil tartib
def oqim_2_tuzatilgan():
    with qulf_a:       # avval qulf_a, xuddi oqim_1 kabi
        time.sleep(0.1)
        with qulf_b:
            print("oqim_2 ikkalasini ham oldi (xavfsiz)")
```

3.
```python
maxsus_maʼlumot = threading.local()

def ish(boshlangich):
    maxsus_maʼlumot.hisoblagich = boshlangich
    for _ in range(5):
        maxsus_maʼlumot.hisoblagich += 1
        time.sleep(0.01)
    print(f"{threading.current_thread().name}: {maxsus_maʼlumot.hisoblagich}")

threadlar = [
    threading.Thread(target=ish, args=(boshlangich,), name=f"Oqim-{boshlangich}")
    for boshlangich in (0, 100, 1000)
]
for t in threadlar:
    t.start()
for t in threadlar:
    t.join()
# Chiqish: Oqim-0: 5, Oqim-100: 105, Oqim-1000: 1005 — har biri mustaqil
```

## Qisqacha xulosa

`threading.Thread` haqiqiy OS oqimlarini yaratadi, lekin GIL ular orasidagi Python bytecode bajarilishini ketma-ketlashtiradi — shuning uchun `threading` moduli birinchi navbatda I/O-bog'liq parallellik uchun mo'ljallangan. Umumiy holatni himoya qilish uchun `Lock` (yoki qayta-kirish kerak bo'lsa `RLock`) ishlatiladi; qulflarni izchil tartibda so'rash deadlock'dan qochish kaliti. `queue.Queue` producer-consumer naqshlarida qo'lda qulflashdan ko'ra xavfsizroq va soddaroq yechim beradi, `threading.local()` esa har bir oqimga mustaqil holat beradi. Amaliy loyihalarda qo'lda `Thread` boshqarish o'rniga, odatda `concurrent.futures.ThreadPoolExecutor` kabi yuqori darajadagi abstraksiyalar afzal ko'riladi.
