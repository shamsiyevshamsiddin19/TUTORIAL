# Shartli operatorlar

## Bu darsda nimalarni o'rganasiz

- `if`/`elif`/`else` bilan, skriptga qaror qabul qilish mantig'ini qo'shasiz
- `test` (`[ ]`) shartlarini — sonlarni, matnlarni va fayllarni solishtirishni o'rganasiz
- Skriptga, argument berilmagan holatni, avtomatik tekshirishni o'rgatasiz

## Nazariy qism

### Nega shart operatorlari kerak

Avvalgi darsdagi skriptlar, doim, bir xil ketma-ketlikda ishlaydi — argument berilgan yoki berilmaganidan qat'i nazar. Haqiqiy foydali skriptlar esa, odatda, **vaziyatga qarab**, turlicha harakat qilishi kerak: "agar fayl mavjud bo'lsa — buni qil, aks holda — boshqasini qil". Aynan shu vazifani, `if` operatori bajaradi.

### `if`/`elif`/`else` sintaksisi

```bash
if [ shart ]; then
    # shart to'g'ri bo'lsa, shu yerdagi buyruqlar bajariladi
elif [ boshqa-shart ]; then
    # birinchi shart noto'g'ri, bu esa to'g'ri bo'lsa
else
    # hech qaysi shart to'g'ri bo'lmasa
fi
```

**Muhim sintaktik qoidalar:** `[` va `]` belgilaridan **keyin va oldin, albatta probel** bo'lishi kerak; blok, doim `fi` (`if`ning teskarisi) bilan yopiladi; `elif` va `else` — ixtiyoriy (kerak bo'lmasa, yozilmasligi mumkin).

### `test` shartlari — solishtirish operatorlari

`[ shart ]` ichida, quyidagi operatorlar eng ko'p ishlatiladi:

**Sonlarni solishtirish:**

| Operator | Ma'nosi |
|---|---|
| `-eq` | teng (equal) |
| `-ne` | teng emas (not equal) |
| `-gt` | katta (greater than) |
| `-lt` | kichik (less than) |
| `-ge` | katta yoki teng |
| `-le` | kichik yoki teng |

**Matnlarni solishtirish:**

| Operator | Ma'nosi |
|---|---|
| `=` | teng |
| `!=` | teng emas |
| `-z` | bo'sh (matn uzunligi nol) |
| `-n` | bo'sh emas |

**Fayllarni tekshirish:**

| Operator | Ma'nosi |
|---|---|
| `-f` | fayl mavjud va u — oddiy fayl |
| `-d` | fayl mavjud va u — papka |
| `-e` | umuman mavjud (fayl yoki papka) |

**Mantiqiy birlashtiruvchilar:** `&&` (VA), `||` (YOKI) — bir nechta shartni birlashtirish uchun.

## Amaliy misol

Avvalgi darsdagi `argument-sanash.sh` skriptini, endi, **haqiqiy** shart operatori bilan yozamiz:

```bash
nano ~/skriptlar/argument-tekshirish.sh
```

```bash
#!/bin/bash

if [ $# -lt 3 ]; then
    echo "Xato: kamida 3 ta argument bering!"
    echo "Siz berdingiz: $#"
else
    echo "Yetarli argument berildi: $# ta"
    echo "Argumentlar: $@"
fi
```

```bash
chmod u+x ~/skriptlar/argument-tekshirish.sh
~/skriptlar/argument-tekshirish.sh a b
~/skriptlar/argument-tekshirish.sh a b c d
```

Birinchi chaqiruv (2 ta argument): `Xato: kamida 3 ta argument bering!`
Ikkinchi chaqiruv (4 ta argument): `Yetarli argument berildi: 4 ta`

Endi, fayl mavjudligini tekshiruvchi skript yozamiz:

```bash
nano ~/skriptlar/fayl-tekshir.sh
```

```bash
#!/bin/bash

fayl="$1"

if [ -z "$fayl" ]; then
    echo "Xato: fayl nomini argument sifatida bering."
elif [ -f "$fayl" ]; then
    echo "'$fayl' — mavjud va u oddiy fayl."
elif [ -d "$fayl" ]; then
    echo "'$fayl' — mavjud, ammo u papka, fayl emas."
else
    echo "'$fayl' — tizimda mavjud emas."
fi
```

```bash
chmod u+x ~/skriptlar/fayl-tekshir.sh
~/skriptlar/fayl-tekshir.sh ~/skriptlar/salom.sh
~/skriptlar/fayl-tekshir.sh ~/skriptlar
~/skriptlar/fayl-tekshir.sh ~/mavjud-bolmagan-fayl.txt
~/skriptlar/fayl-tekshir.sh
```

Har biri, mos ravishda: "oddiy fayl", "papka", "mavjud emas", "argument berilmagan" xabarlarini chiqaradi.

## Keng tarqalgan xatolar

❌ **`[` dan keyin yoki `]`dan oldin probel qo'ymaslik** (masalan, `if [$# -lt 3]; then`).
✅ `[` va `]` atrofida, doim probel bo'lsin: `if [ $# -lt 3 ]; then`.

**Nega xato:** Bash'da, `[` — aslida, **oddiy buyruq** (`test` buyrug'ining boshqa nomi) hisoblanadi, va u, o'z argumentlaridan, probel orqali ajratilishi kerak — probelsiz yozilsa, bash, `[$#` degan, mavjud bo'lmagan buyruqni qidiradi, va xato beradi.

❌ **Sonlarni solishtirishda, `-eq`, `-lt` o'rniga, `=`, `<` kabi belgilarni ishlatish** (masalan, `if [ $yosh > 18 ]`).
✅ **Sonlar** uchun — `-eq`, `-ne`, `-gt`, `-lt`, `-ge`, `-le`; **matnlar** uchun — `=`, `!=`. Ularni aralashtirmang.

**Nega xato:** `[ ]` ichida, `>` va `<` belgilari, sonli solishtirish emas, balki, **fayl nomlarini** qayta yo'naltirish (4-bobda o'rgangan `>`) sifatida talqin qilinishi mumkin — bu, kutilmagan, tushunish qiyin xatolarga olib keladi.

❌ **O'zgaruvchini, `[ ]` ichida, tirnoqsiz ishlatish** (masalan, `if [ -z $fayl ]` — `"$fayl"` o'rniga).
✅ `[ ]` ichida, o'zgaruvchilarni, doim tirnoq ichiga oling: `if [ -z "$fayl" ]`.

**Nega xato:** Agar o'zgaruvchi **bo'sh** bo'lsa (masalan, argument berilmagan bo'lsa), tirnoqsiz `$fayl`, aslida hech narsaga aylanadi, va `[ -z ]` — kutilgan bitta emas, **noto'g'ri sondagi argument** bilan chaqiriladi — bu, "unary operator expected" kabi tushunarsiz xatoga olib keladi. Tirnoq, bo'sh qiymatni ham, "bo'sh matn" sifatida, to'g'ri uzatadi.

## Mashq/topshiriq

**(Oson)** `~/skriptlar/yosh-tekshir.sh` skriptini yozing — u, birinchi argumentni (yosh) qabul qilib, agar u `18`dan katta yoki teng bo'lsa "Siz kattasiz" deb, aks holda "Siz voyaga yetmagansiz" deb chiqaradigan bo'lsin.

**(O'rtacha)** `~/skriptlar/papka-yasovchi.sh` skriptini yozing — u, birinchi argument sifatida papka nomini qabul qiladi. Agar shu nomdagi papka **allaqachon mavjud** bo'lsa, "Bu papka allaqachon mavjud" deb yozsin; aks holda, `mkdir` bilan uni yaratib, "Papka yaratildi: [nom]" deb yozsin.

**(Qiyin)** `~/skriptlar/son-tekshir.sh` skriptini yozing — u, ikkita sonni argument sifatida qabul qiladi va, `elif` zanjiridan foydalanib, ular orasidagi munosabatni ("Birinchi son kattaroq", "Ikkinchi son kattaroq" yoki "Ikkalasi teng") aniqlab chiqarsin. Qo'shimcha ravishda, agar argumentlar soni 2 tadan kam bo'lsa, hisoblashdan oldin, xato xabarini chiqarib, skriptni to'xtatsin (maslahat: bunday holatlarda, skriptni, `exit 1` buyrug'i bilan, muddatidan oldin to'xtatish mumkin).

## Qisqacha xulosa

`if [ shart ]; then ... elif [ shart ]; then ... else ... fi` — bash skriptga, vaziyatga qarab, turlicha harakat qilish imkonini beradi; `[ ]` ichida, sonlar `-eq`/`-gt`/`-lt` kabi, matnlar `=`/`!=` kabi, fayllar esa `-f`/`-d`/`-e` kabi operatorlar bilan tekshiriladi, va bu bloklarni yozishda, `[`/`]` atrofidagi probellar hamda o'zgaruvchilarni tirnoq ichiga olish — eng ko'p uchraydigan sintaktik xatolarning oldini oladi.
