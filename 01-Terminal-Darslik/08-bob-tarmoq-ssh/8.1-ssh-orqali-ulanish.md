# SSH orqali ulanish

## Bu darsda nimalarni o'rganasiz

- `ssh` bilan, masofadagi serverga, terminal orqali ulanasiz
- SSH kaliti (SSH key) nima ekanini va u nega paroldan xavfsizroq ekanini tushunasiz
- `ssh-keygen` bilan, o'z SSH kalit juftligingizni yaratasiz
- `ssh-copy-id` bilan, kalitni serverga joylashtirib, parolsiz ulanishni sozlaysiz

## Nazariy qism

### `ssh` — terminal orqali, boshqa kompyuterга "kirish"

**SSH** (Secure Shell) — tarmoq orqali, boshqa (masofadagi) kompyuterga, **xavfsiz, shifrlangan** ulanish o'rnatish protokoli. `ssh` orqali ulanganingizda, siz, xuddi o'sha kompyuterda, to'g'ridan-to'g'ri terminal ochgandek, unda buyruqlar yoza olasiz — garchi, u, dunyoning istalgan burchagida joylashgan bo'lsa ham.

Asosiy sintaksis:

```bash
ssh foydalanuvchi@server-manzili
```

Masalan: `ssh shamsiddin@192.168.1.100` yoki `ssh admin@mening-serverim.uz`.

### Parol orqali ulanish — oddiy, ammo kamroq xavfsiz

Standart holatda, `ssh`, ulanishda, serverdagi foydalanuvchi parolini so'raydi. Bu, ishlaydi, ammo ikkita kamchiligi bor: parolni har safar qo'lda kiritish kerak (bu, ayniqsa avtomatlashtirilgan skriptlar uchun noqulay), va parollar, umuman, kuchli shifrlash kalitlariga qaraganda, "buzilishga" ancha zaifroq.

### SSH kaliti — parolsiz, xavfsizroq usul

SSH kaliti tizimi, ikkita bog'liq faylga asoslanadi:

- **Yopiq kalit (private key)** — sizning kompyuteringizda saqlanadi, hech qачон, hech kimga berilmaydi
- **Ochiq kalit (public key)** — ulanmoqchi bo'lgan serverga joylashtiriladi, u "ochiq" bo'lsa ham xavfsiz

Ulanish paytida, server, sizning kompyuteringizdagi yopiq kalitning, serverdagi ochiq kalitga **mos kelishini** matematik tekshiradi — agar mos kelsa, sizni, **parolsiz**, avtomatik kiritadi. Bu — nafaqat qulay (parol yozish shart emas), balki, paroldan ancha xavfsizroq — chunki, yopiq kalitni "taxmin qilib topish", parolni topishdan ancha qiyinroq.

### `ssh-keygen` — kalit juftligini yaratish

```bash
ssh-keygen -t ed25519
```

Bu, sizdan, kalit fayllari qayerga saqlanishini (odatda, standart joyni — `Enter` bosib qabul qilish kifoya) va, kalitni himoya qiluvchi qo'shimcha parol (passphrase — ixtiyoriy, bo'sh qoldirsa ham bo'ladi) so'raydi. Natijada, ikkita fayl yaratiladi: `~/.ssh/id_ed25519` (yopiq kalit) va `~/.ssh/id_ed25519.pub` (ochiq kalit).

### `ssh-copy-id` — ochiq kalitni serverga joylashtirish

```bash
ssh-copy-id foydalanuvchi@server-manzili
```

Bu buyruq, sizning ochiq kalitingizni, avtomatik ravishda, serverdagi to'g'ri joyga (`~/.ssh/authorized_keys`) qo'shadi (buning uchun, oxirgi marta, parolni qo'lda kiritishingiz kerak bo'ladi). Shundan keyin, o'sha serverga, `ssh` orqali, **parolsiz** ulanish mumkin bo'ladi.

## Amaliy misol

Avval, o'zingizda SSH kaliti mavjud yoki yo'qligini tekshiramiz:

```bash
ls -la ~/.ssh
```

Agar `id_ed25519` yoki `id_rsa` kabi fayllar ko'rinmasa, yangi kalit yaratamiz:

```bash
ssh-keygen -t ed25519 -C "shamsiddin@mening-kompyuterim"
```

(`-C` bayrog'i — kalitga, izoh sifatida, izlash uchun qulay yorliq qo'shadi, masalan, email manzil.)

Barcha savollarga, `Enter` bosib, standart javoblarni qabul qilamiz (yoki, qo'shimcha xavfsizlik uchun, `passphrase` kiritamiz).

Yaratilgan kalitlarni tekshiramiz:

```bash
ls -la ~/.ssh
cat ~/.ssh/id_ed25519.pub
```

(`id_ed25519.pub` — bu, **ochiq** kalit, uni ko'rsatish/ulashish xavfsiz; `id_ed25519` — bu, **yopiq** kalit, uni hech qachon hech kimga ko'rsatmang.)

Endi, faraz qilaylik, sizda, ulanish uchun, `mening-serverim.uz` manzilida, `shamsiddin` nomli foydalanuvchi mavjud (bu — misol, haqiqiy serverga ulanish uchun, o'zingizga tegishli, haqiqiy manzil va foydalanuvchi kerak bo'ladi):

```bash
ssh shamsiddin@mening-serverim.uz
```

Birinchi marta ulanganda, tizim, serverning "identifikatsiyasini" tasdiqlashni so'rashi mumkin (`Are you sure you want to continue connecting?`) — bu, normal holat, `yes` deb javob bering.

Ochiq kalitni, serverga joylashtiramiz (kelajakda, parolsiz ulanish uchun):

```bash
ssh-copy-id shamsiddin@mening-serverim.uz
```

Bu, oxirgi marta, parolni so'raydi. Shundan keyin:

```bash
ssh shamsiddin@mening-serverim.uz
```

— endi, **hech qanday parolsiz**, to'g'ridan-to'g'ri ulanadi.

## Keng tarqalgan xatolar

❌ **Yopiq kalitni (`id_ed25519`, kengaytmasiz fayl), boshqa birortasiga, jumladan `.pub` bilan tugaydigan faylni yuborish o'rniga, xato bilan yuborish yoki ulashish.**
✅ Faqat, `.pub` bilan tugaydigan faylni (ochiq kalitni) ulashing/ko'chiring; kengaytmasiz nomli fayl — har doim, **maxfiy** bo'lib qolishi shart.

**Nega xato:** Yopiq kalit, sizning "shaxsingizni" tasdiqlaydigan, eng muhim maxfiy ma'lumot — agar u, boshqa birov qo'liga tushsa, ular, sizning nomingizdan, siz ulangan **barcha** serverlarga, parolsiz kira olishadi.

❌ **`ssh`ga, `foydalanuvchi@` qismini yozishni unutib, faqat server manzilini yozish** (masalan, `ssh mening-serverim.uz`), va serverda, tizim, sizning **mahalliy** kompyuteringizdagi foydalanuvchi nomi bilan ulanishga urinishi.
✅ Har doim, aniq belgilash uchun, `foydalanuvchi@server-manzili` formatini ishlating.

**Nega xato:** `ssh`, agar `foydalanuvchi@` qismi ko'rsatilmasa, standart holatda, sizning **hozirgi, mahalliy** kompyuteringizdagi foydalanuvchi nomidan foydalanadi — agar serverda, aynan shu nomli foydalanuvchi mavjud bo'lmasa, ulanish, "Permission denied" yoki "user not found" xatosi bilan muvaffaqiyatsiz tugaydi.

❌ **`ssh-keygen`ni, allaqachon mavjud kalit ustidan, uni almashtirishi mumkinligini tushunmasdan, qayta ishga tushirish.**
✅ Yangi kalit yaratishdan oldin, `ls -la ~/.ssh` bilan, mavjud kalitlar bor-yo'qligini tekshiring — agar mavjud bo'lsa, va u ishlab turgan bo'lsa, uni almashtirish shart emas.

**Nega xato:** Agar mavjud kalit, ustidan yangisi yozilsa (standart nom bilan saqlansa), va eski kalit, allaqachon bir nechta serverga joylashtirilgan bo'lsa, o'sha serverlarga, endi, **yangi** kalit bilan ulanib bo'lmaydi — chunki, ularda, eski (endi mavjud bo'lmagan) kalitning ochiq nusxasi saqlangan.

## Mashq/topshiriq

**(Oson)** `ls -la ~/.ssh` bilan, o'zingizda, mavjud SSH kalitlari bor-yo'qligini tekshiring, va agar mavjud bo'lsa, `cat` bilan, ochiq kalitingizni (`.pub` bilan tugaydigan fayl) ko'ring.

**(O'rtacha)** Agar hali kalit yaratmagan bo'lsangiz, `ssh-keygen -t ed25519` bilan, o'zingizga yangi kalit juftligini yarating, va yaratilgan ikkita faylning (yopiq va ochiq) farqini tushuntirib bering.

**(Qiyin)** Agar sizda, ulanish uchun ruxsatingiz bo'lgan, haqiqiy masofaviy server (masalan, bulutli xizmat orqali olingan test server) mavjud bo'lsa, unga, avval parol orqali `ssh` bilan ulanib ko'ring, so'ng `ssh-copy-id` bilan kalitingizni joylashtirib, keyingi ulanishda, parolsiz kira olishingizni tasdiqlang. (Agar hozircha haqiqiy server mavjud bo'lmasa, shu jarayonning barcha bosqichlarini, qadam-baqadam, qanday bajarilishini, o'z so'zlaringiz bilan yozib chiqing.)

1. `ls -la ~/.ssh` — mavjud fayllar ko'rinadi (masalan, `id_ed25519`, `id_ed25519.pub`); `cat ~/.ssh/id_ed25519.pub` — uzun, `ssh-ed25519 AAAA...` bilan boshlanadigan matn chiqadi — bu, xavfsiz tarzda ulashish mumkin bo'lgan, ochiq kalit.
2. `ssh-keygen -t ed25519` — savollarga `Enter` bilan javob berib, yangi kalit yaratiladi. Farq: yopiq kalit (`id_ed25519`) — faqat sizning kompyuteringizda qolishi kerak, ochiq kalit (`id_ed25519.pub`) esa — ulanmoqchi bo'lgan serverlarga xavfsiz joylashtirilishi mumkin.
3. Qadamlar: `ssh foydalanuvchi@server` (parol bilan ulanish, parolni kiritish), keyin lokal terminaldan (serverdan chiqib) `ssh-copy-id foydalanuvchi@server` (oxirgi marta parol so'raladi), so'ng, qayta `ssh foydalanuvchi@server` — endi parolsiz, avtomatik ulanadi.

## Qisqacha xulosa

`ssh foydalanuvchi@server` — masofadagi kompyuterga, xavfsiz, shifrlangan ulanish o'rnatadi, va terminal orqali, xuddi u yerda o'tirgandek ishlash imkonini beradi; parol o'rniga, `ssh-keygen` bilan yaratilgan, yopiq (hech kimga berilmaydigan) va ochiq (serverga joylashtiriladigan) kalit juftligidan foydalanish, ham xavfsizroq, ham qulayroq (parolsiz) ulanishni ta'minlaydi, va `ssh-copy-id`, ochiq kalitni, serverga, bitta buyruqda joylashtirib beradi.
