# Tizim xizmatlari (systemctl)

## Bu darsda nimalarni o'rganasiz

- Tizim xizmati (service) nima ekanini va u oddiy jarayondan nima bilan farqlanishini tushunasiz
- `systemctl status` bilan, xizmatning holatini tekshirasiz
- `systemctl start/stop/restart` bilan xizmatni boshqarasiz
- `systemctl enable` bilan, xizmatni, tizim yoqilganda avtomatik ishga tushiriladigan qilib sozlaysiz

## Nazariy qism

### Xizmat (service) — fonda, doimiy ishlaydigan dastur

Ko'plab dasturlar (masalan, veb-server, ma'lumotlar bazasi, tarmoq xizmatlari), sizning to'g'ridan-to'g'ri boshqaruvingizsiz, tizim **orqa fonida, doimiy** ishlab turishi kerak — kompyuter yoqilgandan, o'chirilgunga qadar. Bunday dasturlar, **xizmat (service)** deb ataladi. Avvalgi darsda ko'rilgan oddiy `&` bilan fonga yuborilgan jarayondan farqli, xizmat — tizim tomonidan **rasmiy boshqariladi**: u, tizim yoqilganda avtomatik ishga tushishi, muammo yuz berganda avtomatik qayta ishga tushirilishi mumkin.

### `systemd` va `systemctl`

Ko'pchilik zamonaviy Linux distributivlarida (Ubuntu, Debian, Fedora va boshqalar), xizmatlarni boshqarish uchun **`systemd`** deb ataluvchi tizim ishlatiladi, va u bilan ishlash uchun — **`systemctl`** buyrug'i qo'llaniladi.

### Eng ko'p ishlatiladigan `systemctl` buyruqlari

| Buyruq | Vazifasi |
|---|---|
| `systemctl status <xizmat>` | Xizmatning joriy holatini (ishlayapti/to'xtatilgan, oxirgi jurnal yozuvlari bilan) ko'rsatadi |
| `sudo systemctl start <xizmat>` | Xizmatni **ishga tushiradi** |
| `sudo systemctl stop <xizmat>` | Xizmatni **to'xtatadi** |
| `sudo systemctl restart <xizmat>` | Xizmatni **to'xtatib, qayta ishga tushiradi** (masalan, sozlamalar o'zgargandan keyin) |
| `sudo systemctl enable <xizmat>` | Xizmatni, tizim **yoqilganda, avtomatik** ishga tushiriladigan qilib belgilaydi |
| `sudo systemctl disable <xizmat>` | Avtomatik ishga tushirishni **bekor qiladi** |

E'tibor bering: xizmatning **holatini ko'rish** (`status`) uchun `sudo` shart emas, lekin uni **o'zgartirish** (`start`, `stop`, `restart`, `enable`, `disable`) uchun, odatda `sudo` talab qilinadi — chunki bu, tizim darajasidagi o'zgarish.

### `enable` va `start` orasidagi farq — muhim tushuncha

Bu ikkisi, ko'pincha chalkashtiriladi, ammo ular **butunlay boshqa** narsani anglatadi:

- `start` — xizmatni, **hozir, shu zahoti** ishga tushiradi (ammo, kompyuter qayta yoqilsa, avtomatik ishlamaydi)
- `enable` — xizmatni, **kelajakda, tizim yoqilganda**, avtomatik ishga tushiriladigan qilib "belgilaydi" (ammo, agar hozir ishlamayotgan bo'lsa, `enable`ning o'zi uni darhol ishga tushirmaydi)

Shuning uchun, ko'pincha, ikkalasi birga ishlatiladi: `sudo systemctl enable --now <xizmat>` — bu, xizmatni, ham hozir ishga tushiradi, ham kelajakda avtomatik ishlaydigan qiladi.

## Amaliy misol

Tizimda, odatda mavjud bo'ladigan, `cron` (rejalashtirilgan vazifalar) xizmatining holatini tekshiramiz:

```bash
systemctl status cron
```

Natija (misol, xizmat ishlab turgan holatda):

```
● cron.service - Regular background program processing daemon
     Loaded: loaded (/lib/systemd/system/cron.service; enabled; vendor preset: enabled)
     Active: active (running) since Wed 2026-08-19 09:00:00 +05; 5h ago
```

`Active: active (running)` — xizmat ishlab turibdi degani; `enabled` — u, tizim yoqilganda, avtomatik ishga tushishga sozlangan degani.

Xizmatni to'xtatamiz (sinov uchun, ehtiyot bo'lib, faqat tavsiya etilgan, ahamiyatsiz xizmat bilan ishlang):

```bash
sudo systemctl stop cron
systemctl status cron
```

Natijada, `Active: inactive (dead)` ko'rinadi.

Qayta ishga tushiramiz:

```bash
sudo systemctl start cron
systemctl status cron
```

Endi, `Active: active (running)` yana ko'rinadi.

Xizmatni qayta ishga tushiramiz (masalan, sozlamalar o'zgargandan keyin qilinadigan amal):

```bash
sudo systemctl restart cron
```

## Keng tarqalgan xatolar

❌ **`stop` bilan `disable`ni bir xil narsa deb hisoblash** — xizmatni `stop` qilib, uni "butunlay o'chirdim, endi u hech qachon ishlamaydi" deb o'ylash.
✅ `stop` — faqat **hozirgi** ishlashni to'xtatadi; agar kompyuter qayta yoqilsa, va xizmat `enabled` holatida bo'lsa, u **yana avtomatik ishga tushadi**. Butunlay to'xtatib qo'yish uchun, `stop` **va** `disable`ni birga ishlating.

**Nega xato:** `stop` va `enable`/`disable` — ikkita **mustaqil** sozlama: biri — "hozir ishlayaptimi", ikkinchisi — "kelajakda avtomatik ishga tushadimi". Bittasini o'zgartirish, ikkinchisiga ta'sir qilmaydi.

❌ **Sozlamalarni o'zgartirgandan keyin, xizmatni `restart` qilishni unutish**, va o'zgarishlar nega "ishlamayapti" deb hayron bo'lish.
✅ Konfiguratsiya faylini tahrirlagandan so'ng, doim, tegishli xizmatni `sudo systemctl restart <xizmat>` bilan qayta ishga tushiring.

**Nega xato:** Ko'pchilik xizmatlar, sozlamalarini, faqat **ishga tushganda** o'qiydi — konfiguratsiya faylini o'zgartirish, xizmat **allaqachon ishlab turgan bo'lsa**, avtomatik qayta yuklanmaydi.

❌ **`systemctl start`/`stop` oldiga `sudo` qo'ymasdan, "Permission denied" yoki shunga o'xshash xato olish.**
✅ Xizmatni o'zgartiruvchi (`start`, `stop`, `restart`, `enable`, `disable`) buyruqlar oldiga, doim `sudo` qo'shing; faqat `status` uchun bu shart emas.

**Nega xato:** Xizmatlarni boshqarish — tizim darajasidagi amal, va oddiy foydalanuvchi huquqi, buni bajarish uchun yetarli emas — bu, aynan 3.2-darsda o'rgangan `sudo` mantig'iga to'g'ri keladi.

## Mashq/topshiriq

**(Oson)** `ssh` xizmatining (agar o'rnatilgan bo'lsa, nomi ba'zi tizimlarda `ssh`, ba'zilarida `sshd`) holatini `systemctl status` bilan tekshiring.

**(O'rtacha)** Tizimingizda ishlab turgan (holati `active (running)`) bo'lgan, kamida uchta xizmatning nomini toping (maslahat: `systemctl list-units --type=service --state=running` buyrug'i, barcha ishlab turgan xizmatlarni ro'yxatlaydi).

**(Qiyin)** `cron` (yoki tizimingizda mavjud, ahamiyatsiz boshqa bir xizmat) xizmatini: avval `stop` qiling, holatini tekshiring (`inactive` bo'lishi kerak), so'ng `disable` qiling (holati `enabled`dan `disabled`ga o'zgarishini `systemctl status` orqali kuzating), va nihoyat, uni yana ishga qaytarish uchun, **bitta buyruqda**, `enable --now` bilan qayta yoqing.

<details>
<summary>Javoblarni ko'rish</summary>

1. `systemctl status ssh` (yoki `systemctl status sshd`).
2. `systemctl list-units --type=service --state=running` — natijada, ishlayotgan xizmatlar ro'yxati, nomlari bilan chiqadi.
3. `sudo systemctl stop cron`, `systemctl status cron` (`inactive`), `sudo systemctl disable cron`, `systemctl status cron` (endi `disabled` deb ko'rsatiladi), so'ng `sudo systemctl enable --now cron` — bu, xizmatni, bir vaqtning o'zida, ham `enabled` qiladi, ham darhol ishga tushiradi.

</details>

## Qisqacha xulosa

Tizim xizmatlari — orqa fonda, doimiy ishlashi kerak bo'lgan dasturlar bo'lib, `systemctl` orqali boshqariladi: `status` — holatni ko'rish (sudo shart emas), `start`/`stop`/`restart` — hozirgi ishlashni boshqarish, `enable`/`disable` esa — xizmatning, tizim yoqilganda **avtomatik** ishga tushish-tushmasligini belgilaydi; bu ikki tushunchani (hozirgi holat va avtomatik ishga tushirish) aniq ajratib bilish, xizmatlarni to'g'ri boshqarishning kaliti hisoblanadi.
