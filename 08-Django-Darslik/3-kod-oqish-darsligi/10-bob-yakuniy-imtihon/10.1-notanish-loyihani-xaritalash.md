### `menyu/models.py`

```python
from django.db import models


class Toifa(models.Model):
    nomi = models.CharField(max_length=50)

    class Meta:
        verbose_name_plural = "Toifalar"

    def __str__(self):
        return self.nomi


class MenyuBandi(models.Model):
    toifa = models.ForeignKey(Toifa, on_delete=models.CASCADE, related_name="bandlar")
    nomi = models.CharField(max_length=100)
    narxi = models.DecimalField(max_digits=10, decimal_places=2)
    mavjud = models.BooleanField(default=True)

    def __str__(self):
        return self.nomi
```

### `buyurtmalar/models.py`

```python
from django.db import models

from menyu.models import MenyuBandi


class Stol(models.Model):
    raqami = models.IntegerField(unique=True)

    def __str__(self):
        return f"Stol #{self.raqami}"


class Buyurtma(models.Model):
    stol = models.ForeignKey(Stol, on_delete=models.CASCADE, related_name="buyurtmalar")
    ochilgan_vaqt = models.DateTimeField(auto_now_add=True)
    yopilgan = models.BooleanField(default=False)

    def __str__(self):
        return f"Buyurtma #{self.id} — {self.stol}"


class BuyurtmaBandi(models.Model):
    buyurtma = models.ForeignKey(Buyurtma, on_delete=models.CASCADE, related_name="bandlar")
    band = models.ForeignKey(MenyuBandi, on_delete=models.PROTECT)
    soni = models.IntegerField(default=1)
    narxi_buyurtma_vaqtida = models.DecimalField(max_digits=10, decimal_places=2)

    def __str__(self):
        return f"{self.band} x{self.soni}"
```

### `buyurtmalar/views.py`

from django.http import HttpResponse

from .hisoblash import buyurtma_jami_narxi

## Kodni o'qish mashqi

Kodni ishga tushirmasdan, faqat yuqoridagi fayllarni o'qib, quyidagi savollarga javob bering. Har biridan keyin javobni tekshiring.

**1-savol:** Brauzerda `http://127.0.0.1:8000/menyu/` manziliga kirsangiz, sahifada nechta taom ko'rinadi — 3 tami yoki 4 tami? Nega?

<details>
<summary>Javobni ko'rish</summary>

Bashorat: **4 ta** ko'rinadi (Manti ham, garchi `mavjud=False` bo'lsa ham). Sabab: `menyu_royxati` view'ida `MenyuBandi.objects.all()` chaqirilgan — `mavjud` maydoni bo'yicha hech qanday filtrlash yo'q. Modelda `mavjud` maydoni bor bo'lishi, uni **avtomatik** hisobga olinishini anglatmaydi — filtrlashni dasturchi aniq yozishi kerak. Bu — 10.2-darsda tuzatiladigan haqiqiy xato.
</details>

**2-savol:** `http://127.0.0.1:8000/buyurtmalar/1/hisob/` manziliga kirsangiz, qanday matn qaytadi deb o'ylaysiz? Qo'lda hisoblab, natijani bashorat qiling.

<details>
<summary>Javobni ko'rish</summary>

Qo'lda hisoblash: Buyurtma #1'da 2x Lag'mon (35000 dan) + 3x Choy (8000 dan) = 70000 + 24000 = **94000** so'm bo'lishi kerak edek tuyuladi.

Lekin `buyurtma_jami_narxi` funksiyasini diqqat bilan o'qing:

```python
def buyurtma_jami_narxi(buyurtma):
    jami = Decimal("0")
    for band in buyurtma.bandlar.all():
        jami += band.narxi_buyurtma_vaqtida
    return jami
```

`band.soni`ga hech qayerda ko'paytirilmagan! Funksiya har bir band uchun faqat `narxi_buyurtma_vaqtida`ni qo'shadi — nechta buyurtma qilinganini (`soni`) hisobga olmaydi. Demak, real natija: 35000 + 8000 = **43000** so'm bo'ladi, to'g'ri javob (94000) emas. Bu — 10.2-darsda tuzatiladigan ikkinchi haqiqiy xato.

Bu savolning maqsadi: "kod nima qilishi **kerak**" bilan "kod nima qil**yapti**" o'rtasidagi farqni, faqat o'qib turib sezish mumkinligini ko'rsatish — 8-9-boblarda o'rgangan diqqat bilan o'qish odati aynan shu yerda ishga tushadi.
</details>

**3-savol:** Agar siz `BuyurtmaBandi`dagi `band` maydonini (`ForeignKey(MenyuBandi, on_delete=models.PROTECT)`) o'chirilgan `MenyuBandi`ni o'chirishga harakat qilsangiz, nima bo'ladi? 4.2-darsda o'rgangan uchta `on_delete` variantidan qaysi biri qo'llanilgan va bu amalda nimani anglatadi?

<details>
<summary>Javobni ko'rish</summary>

`on_delete=models.PROTECT` qo'llanilgan. 4.2-darsda o'rganganingizdek, bu — agar shu `MenyuBandi`ga bog'liq kamida bitta `BuyurtmaBandi` mavjud bo'lsa, `MenyuBandi.delete()` chaqirilganda Django `ProtectedError` xatosini ko'taradi va o'chirishga yo'l qo'ymaydi. Bu — biznes-mantiq nuqtai nazaridan to'g'ri qaror: allaqachon buyurtma qilingan taomni (masalan Lag'mon) menyudan butunlay o'chirib tashlash, o'tmishdagi buyurtma tarixini "osilib qolgan" (dangling) holatga keltirar edi. Shu sababli taomni butunlay o'chirish o'rniga, odatda `mavjud=False` qilib belgilash (aynan shu loyihada bor bo'lgan maydon!) to'g'riroq yechim.
</details>

**4-savol:** Agar siz yangi, "buyurtmaga izoh (masalan, 'piyozsiz')" qo'shmoqchi bo'lsangiz, buni qaysi faylga, qaysi modelga yozgan bo'lardingiz — `Buyurtma`gami yoki `BuyurtmaBandi`gami? Nega?

<details>
<summary>Javobni ko'rish</summary>

`BuyurtmaBandi`ga — chunki "piyozsiz" kabi izoh bitta **aniq taomga** (masalan aynan shu Lag'monga) tegishli, butun buyurtmaga emas (buyurtmada boshqa taomlar ham bo'lishi mumkin, ularning har biriga alohida izoh kerak bo'lishi mumkin). Agar izohni `Buyurtma`ga qo'shsangiz, bitta buyurtmadagi barcha taomlar uchun faqat bitta umumiy izoh maydoni bo'lar edi — bu, agar buyurtmada bir nechta taom bo'lsa, yetarli emas. Bu savol — 02-bobda o'rgangan "qaysi kod qayerga" mantig'ining model darajasidagi ko'rinishi: yangi ma'lumot **qaysi narsaga tegishli ekanligini** aniqlash, uni to'g'ri modelga joylashtirish kalitidir.
</details>

**5-savol:** `buyurtmalar/models.py` faylining eng yuqorisida `from menyu.models import MenyuBandi` qatori bor. Agar, aksincha, `menyu/models.py` faylida `from buyurtmalar.models import Buyurtma` deb yozilgan bo'lsa (ya'ni ikkala app bir-birini import qilsa), nima bo'lishi mumkin edi?

<details>
<summary>Javobni ko'rish</summary>

Bu — **circular import** (aylanma import) muammosiga olib kelishi mumkin edi: Python `menyu.models`ni yuklashga urinadi → u `buyurtmalar.models`ni import qilishga harakat qiladi → `buyurtmalar.models` esa (bizning haqiqiy loyihamizda) `menyu.models`ni import qiladi → lekin `menyu.models` hali to'liq yuklanib bo'lmagan (chunki aynan shu yuklanish jarayonining o'zi hali davom etyapti) → `ImportError: cannot import name ... from partially initialized module`. Shu sababli loyihalarda odatda bog'lanish faqat **bitta yo'nalishda** oqishi kerak: bu loyihada `buyurtmalar` (buyurtmalar taomlarga muhtoj) `menyu`ga bog'liq, lekin `menyu` `buyurtmalar`ga bog'liq emas — bu mantiqiy ham, chunki taom tushunchasi buyurtma tushunchasisiz ham mustaqil mavjud bo'la oladi, aksincha emas.
</details>

## Amaliy misol

Yuqoridagi 2-savol — bu darsning markaziy amaliy namunasi: siz kodni ishga tushirmasdan, faqat diqqat bilan o'qib, real xatoni (soni'ga ko'paytirilmaganini) topa oldingiz. Bu — aynan shu darslikning butun maqsadi bo'lgan ko'nikma: **kodni ishga tushirishdan oldin, uni o'qib tushunish orqali xatoni sezish**.

Keyingi darsda (10.2) siz bu xatoni — va yana bir nechtasini — haqiqatan ham tuzatasiz, va yangi funksiya qo'shasiz, so'ngra har birini real serverda tekshirasiz.

## Keng tarqalgan xatolar

❌ **"Menda bu loyiha yo'q, ishga tushira olmayman, demak tahlil qila olmayman" deb o'ylash.** Aslida, ko'pincha kodni o'qish orqali (hatto ishga tushirmasdan) muhim xatolarni topish mumkin — 2-savol buning isboti.

✅ Har doim avval **statik o'qish** (kodning o'zini diqqat bilan o'qish) bilan boshlang, keyin, agar imkon bo'lsa, ishga tushirib tasdiqlang. Ikkalasi ham kerak, lekin birinchisi ko'pincha ikkinchisisiz ham ko'p narsani ochib beradi.

❌ **Modelda maydon borligini ko'rib, "demak bu maydon albatta ishlatiladi" deb faraz qilish.** `mavjud` maydoni borligi, uni har bir view avtomatik hisobga olishini kafolatlamaydi — 1-savol buni ko'rsatadi.

✅ Har bir view/query'ni alohida tekshiring: u qaysi maydonlarni **haqiqatan** filtrlaydi, qaysilarini e'tiborsiz qoldiradi.

❌ **Funksiya nomidan ("jami_narxi") uning to'g'ri ishlashini faraz qilish.** Nom — bu hujjat emas, va'da emas. Faqat kodning o'zi haqiqatni aytadi.

✅ Har doim funksiya *nomi* emas, *tanasi* (implementatsiyasi)ni o'qing — ayniqsa pul, miqdor kabi muhim hisob-kitoblarda.
