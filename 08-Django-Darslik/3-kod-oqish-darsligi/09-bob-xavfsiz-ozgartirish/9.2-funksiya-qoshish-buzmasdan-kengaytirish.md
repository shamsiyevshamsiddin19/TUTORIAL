# 9.2. Funksiya qo'shish — mavjudni buzmasdan kengaytirish

## Bu darsda nimalarni o'rganasiz

9.1-darsda siz **mavjud** kodni o'zgartirishning xavfsiz metodologiyasini o'rgandingiz: grep bilan barcha chaqiruvchilarni topish, baseline olish, kichik o'zgartirish, hamma chaqiruvchini yangilash, regressiya testi.

Bu darsda esa teskari — lekin bog'liq — savolga javob topasiz: **kodga YANGI narsa qo'shganda nima uchun ba'zan hech narsa buzilmaydi, ba'zan esa xuddi shu "qo'shish" harakati bilan hamma narsa buziladi?**

O'rganasiz:
- Nima uchun **butunlay yangi funksiya** qo'shish deyarli har doim xavfsiz (va buni grep bilan qanday isbotlash mumkin)
- Modelga yangi **maydon** qo'shishda `default=` nima uchun "xavfsizlik kamari" vazifasini bajaradi
- Mavjud funksiyaga yangi **parametr** qo'shishda `default` qiymat bermaslik nima uchun barcha eski chaqiruvchilarni sindiradi — va buni qanday oldini olish
- Context lug'atiga (dictionary) yangi kalit qo'shish nima uchun har doim xavfsiz, lekin **mavjud kalitni nomini o'zgartirish** nima uchun eng xavfli, sezilmaydigan (silent) buzilish turi

## Nazariy qism

### "Qo'shish" ikki xil bo'ladi

Kod bazasiga biror narsa "qo'shish" deganda odatda ikkita mutlaqo boshqacha operatsiyani nazarda tutamiz, va ularning xavfsizlik darajasi ham boshqacha:

**1-tur: Hech kim hali bilmaydigan, hech kim hali chaqirmaydigan yangi narsa qo'shish.**

Masalan: yangi funksiya, yangi view, yangi URL, yangi model. Bunday qo'shish deyarli har doim xavfsiz, chunki — ta'rifga ko'ra — hozircha uni hech kim chaqirmayapti. Sizning yangi kodingiz ishlamay qolsa ham, u faqat **o'zi** ishlamaydi; mavjud, ishlab turgan hech narsani buzmaydi.

Buni isbotlashning aniq usuli bor: **grep bilan tekshirish**. Agar siz `mening_yangi_funksiyam` nomini kod bazasida grep qilsangiz va u hali qayerda ham ishlatilmagan bo'lsa (chunki siz hali yozmagansiz!), demak hech qanday mavjud kod unga bog'liq emas — uni qo'shish 100% xavfsiz.

**2-tur: Mavjud, allaqachon ishlatilayotgan narsaning "shaklini" kengaytirish.**

Masalan: mavjud modelga yangi maydon qo'shish, mavjud funksiyaga yangi parametr qo'shish, mavjud view'ning context lug'atiga yangi kalit qo'shish. Bu holatda siz yangi narsa qo'shyapsiz, lekin **eski, allaqachon ishlab turgan chaqiruvchilar bilan bir joyda** — va shu yerda xavf boshlanadi.

Bu ikkinchi tur o'zi ham ikkiga bo'linadi:

- **Backward-compatible (orqaga mos) kengaytirish** — eski chaqiruvchilar hech narsa sezmaydi, chunki yangi narsa ixtiyoriy (`default=` yoki `null=True` yoki `param=None` bilan).
- **Backward-incompatible (orqaga mos bo'lmagan) kengaytirish** — eski chaqiruvchilar sindiriladi, chunki yangi narsa majburiy qilib qo'yilgan.

Keling, buni uchta real holatda — model maydoni, funksiya parametri, context kaliti — ketma-ket, jonli test qilib ko'ramiz.

### 1-holat: Modelga yangi maydon qo'shish

`Mahsulot` modeliga yangi `chegirma_foizi` (chegirma foizi) maydonini qo'shamiz:

```python
class Mahsulot(models.Model):
    bolim = models.ForeignKey(Bolim, on_delete=models.CASCADE, related_name="mahsulotlar")
    nomi = models.CharField(max_length=100)
    narxi = models.DecimalField(max_digits=10, decimal_places=2)
    ombordagi_soni = models.IntegerField(default=0)
    chegirma_foizi = models.IntegerField(default=0)   # <-- YANGI
```

`default=0` borligi uchun `makemigrations` hech qanday savol bermaydi:

```
$ python manage.py makemigrations dokon
Migrations for 'dokon':
  apps/dokon/migrations/0009_mahsulot_chegirma_foizi.py
    + Add field chegirma_foizi to mahsulot
```

4.1-darsda siz `null=True`/`default=` bo'lmagan majburiy maydon qo'shsangiz, Django interaktiv rejimda savol berishini ko'rgan edingiz ("It is impossible to add a non-nullable field..."). Bu yerda esa `default=0` borligi uchun Django "muammo yo'q, mavjud har bir qatorga avtomatik 0 qo'yaman" deb, hech narsa so'ramasdan davom etadi.

Migratsiyadan keyin, mavjud mahsulotlarni tekshiramiz:

```
>>> from apps.dokon.models import Mahsulot
>>> for m in Mahsulot.objects.all():
...     print(m.id, m.nomi, m.narxi, 'chegirma_foizi=', m.chegirma_foizi)
4 Noutbuk 5000000.00 chegirma_foizi= 0
5 Sichqoncha 150000.00 chegirma_foizi= 0
```

Diqqat qiling: bu mahsulotlar `chegirma_foizi` maydoni **mavjud bo'lmagan paytda** yaratilgan edi. Lekin migratsiya ularga avtomatik `0` qiymatini yozib qo'ydi. Hech qanday forma, hech qanday admin sahifasi, hech qanday API — buzilmadi, chunki hammasi eski holatda ishlashda davom etaveradi (`chegirma_foizi` ular uchun shunchaki "ko'rinmas", 0 bo'lib turaveradi).

**Agar `default=0` o'rniga hech narsa bermaganimizda edi**, Django `makemigrations` interaktiv rejimda savol berardi: "bo'sh bo'lib qolgan qatorlar uchun qanday qiymat qo'yay?" — va agar buni avtomatlashtirilgan (masalan CI/CD) muhitda qilsangiz, jarayon to'xtab qolardi.

### 2-holat: Butunlay yangi funksiya qo'shish

Endi `xisoblash.py` fayliga yangi, chegirmali narxni hisoblaydigan funksiya qo'shamiz. Avval — 9.1-darsda o'rgangan qoidaga ko'ra — grep bilan tekshiramiz, bu nom hali qayerda ham ishlatilmaganini tasdiqlaymiz:

```
$ grep -rn "chegirmali_narx_hisobla" apps/dokon/
(hech qanday natija yo'q)
```

Bo'sh natija — bu funksiya hali mavjud emas, demak uni qo'shish **hech kimga ta'sir qilmaydi**, chunki hech kim hali uni chaqirmaydi:

```python
from decimal import Decimal


def chegirmali_narx_hisobla(mahsulot):
    chegirma_ulushi = Decimal(mahsulot.chegirma_foizi) / Decimal("100")
    chegirma_summasi = mahsulot.narxi * chegirma_ulushi
    return mahsulot.narxi - chegirma_summasi
```

Buni yangi view va yangi URL orqali ulaymiz:

```python
# views.py
def mahsulot_chegirmali_narxi(request, mahsulot_id):
    mahsulot = get_object_or_404(Mahsulot, id=mahsulot_id)
    chegirmali = chegirmali_narx_hisobla(mahsulot)
    return HttpResponse(
        f"{mahsulot.nomi}: asl narx = {mahsulot.narxi} so'm, "
        f"chegirma = {mahsulot.chegirma_foizi}%, "
        f"chegirmali narx = {chegirmali} so'm"
    )
```

```python
# urls.py
path(
    "mahsulotlar/<int:mahsulot_id>/chegirmali-narx/",
    views.mahsulot_chegirmali_narxi,
    name="mahsulot-chegirmali-narx",
),
```

```
>>> m = Mahsulot.objects.get(id=5)
>>> m.chegirma_foizi = 20
>>> m.save()
```

### 3-holat (ogohlantiruvchi misol): funksiyaga majburiy parametr qo'shish

Endi ataylab xato qilib ko'ramiz — bu darslikning eng qimmatli qismi ko'pincha aynan shu yerda: **nima buzilishini his qilish**.

`ortacha_narx` funksiyasi (8-9-boblardan tanish) hozir shunday:

```python
def ortacha_narx(mahsulotlar):
    if not mahsulotlar:
        return None
    jami = sum(m.narxi for m in mahsulotlar)
    soni = len(mahsulotlar)
    return jami / soni
```

Avval — har doimgidek — grep bilan barcha chaqiruvchilarni topamiz:

```
$ grep -rn "ortacha_narx" apps/dokon/
apps/dokon/xisoblash.py:4:def ortacha_narx(mahsulotlar):
apps/dokon/views.py:8:from .xisoblash import ortacha_narx
apps/dokon/views.py:51:    ortacha = ortacha_narx(mahsulotlar)
```

Bitta real chaqiruvchi bor: `views.py`ning 51-qatorida, `ortacha_narx(mahsulotlar)` — argumentsiz, faqat `mahsulotlar` bilan.

Endi funksiyaga **default qiymatsiz** yangi majburiy parametr qo'shamiz:

```python
def ortacha_narx(mahsulotlar, valyuta):   # <-- default yo'q!
    ...
```

`bolim_ortacha_narxi` view'ini o'zgartirmasdan turib, `/bolimlar/3/ortacha-narx/` manziliga so'rov yuboramiz:

```
$ curl http://127.0.0.1:8000/bolimlar/3/ortacha-narx/
(500 Internal Server Error, HTML traceback)
```

Server logida real xato:

```
TypeError: ortacha_narx() missing 1 required positional argument: 'valyuta'
```

Bu — 8.1-darsda o'rgangan "tracebackni oxiridan boshiga o'qish" texnikasi bilan bir zumda tashxis qo'yiladigan xato: eski chaqiruvchi (`views.py:51`) yangi, majburiy parametrni bilmaydi, chunki u yozilgan paytda bu parametr mavjud emas edi.

**Tuzatish — yangi parametrga default qiymat berish:**

```python
def ortacha_narx(mahsulotlar, valyuta="so'm"):
    ...
```

Qayta tekshiramiz — eski chaqiruvchi, o'zgarishsiz, hech qanday `valyuta` argumentisiz:

```
$ curl http://127.0.0.1:8000/bolimlar/3/ortacha-narx/
Elektronika: o'rtacha narx = 2575000.00 so'm, chegirmadagi narx = 2317500.000 so'm
```

Ishladi — chunki `valyuta="so'm"` default qiymati borligi uchun, uni bermagan eski chaqiruvchilar avtomatik `"so'm"` qiymatini oladi. Yangi kod yozayotganlar esa xohlasa `ortacha_narx(mahsulotlar, valyuta="dollar")` deb, yangi imkoniyatdan foydalanishi mumkin.

**Xulosa:** funksiyaga yangi parametr qo'shish o'zi xavfli emas — xavfli bo'lgani **default qiymatsiz, majburiy qilib qo'shish**. Qoida oddiy: agar eski chaqiruvchilarni o'zgartirishni xohlamasangiz (yoki imkoningiz bo'lmasa), yangi parametrga har doim default bering.

### 4-holat: eng xavfli — sezilmaydigan (silent) buzilish

Yuqoridagi `TypeError` — bu "yaxshi" xato turi, chunki u sizga **qichqirib** aytadi: nimadir buzildi. Lekin Django template tizimida (5.2-darsni eslang) bundan ham xavfliroq narsa bor: **xato bermay, shunchaki noto'g'ri natija berish**.

`bolimlar_royxati` view'ida context lug'ati shunday:

```python
def bolimlar_royxati(request):
    barcha_bolimlar = Bolim.objects.all()
    context = {
        "bolimlar": barcha_bolimlar,
        "jami_bolimlar_soni": barcha_bolimlar.count(),
    }
    return render(request, "dokon/bolimlar_royxati.html", context)
```

Va shablon (`bolimlar_royxati.html`) ichida:

```html
<p>Jami: {{ jami_bolimlar_soni }} ta bo'lim</p>
```

Baseline (asl holat):

```
$ curl http://127.0.0.1:8000/bolimlar/ | grep "Jami:"
<p>Jami: 2 ta bo'lim</p>
```

Endi context kalitini **nomini o'zgartiramiz** (bu ham "kengaytirish" turiga o'xshab tuyuladi — aslida esa mavjud narsani buzish):

```python
context = {
    "bolimlar": barcha_bolimlar,
    "bolimlar_soni": barcha_bolimlar.count(),   # nomi o'zgartirildi
}
```

Shablonni esa o'zgartirmadik (u hali ham `jami_bolimlar_soni` deb kutmoqda). Natija:

```
$ curl -o /dev/null -w "STATUS: %{http_code}\n" http://127.0.0.1:8000/bolimlar/
STATUS: 200

$ curl http://127.0.0.1:8000/bolimlar/ | grep "Jami:"
<p>Jami:  ta bo'lim</p>
```

**Status 200. Hech qanday xato. Hech qanday traceback.** Faqat sahifada raqam o'rnida bo'sh joy qoldi. 5.2-darsda o'rgangan Django template mexanizmi shu yerda ham ishlaydi: shablon mavjud bo'lmagan context o'zgaruvchisini so'raganda, Django xato bermaydi — jim (silently) bo'sh qatorni (`string_if_invalid`) qaytaradi.

Bu — darslikdagi eng muhim ogohlantirish: **`TypeError` sizni himoya qiladi (chunki uni ko'rasiz va tuzatasiz). Silent (sezilmaydigan) buzilish sizni himoya qilmaydi** — chunki hech narsa qizil rangda chiqmaydi, testlar (agar aniq shu qatorni tekshirmasa) o'tib ketishi mumkin, va foydalanuvchi noto'g'ri (yoki bo'sh) ma'lumotni ko'rib qoladi, siz esa bundan bexabar qolasiz.

**Qoida:** context lug'atiga **yangi** kalit qo'shish — xavfsiz (1-turdagi qo'shish, hech kim hali bilmaydi). Context lug'atidagi **mavjud** kalitni nomini o'zgartirish yoki o'chirish — bu refaktoring, va 9.1-darsdagi to'liq metodologiyani talab qiladi: shablonlarda (va boshqa view'larda, agar bo'lsa) ushbu kalit qayerda ishlatilganini qidirib topish, so'ng hammasini birga yangilash.

## Kodni o'qish mashqi

Quyidagi ikkita o'zgarishni ko'rib chiqing va har biri uchun "xavfsizmi yoki xavflimi" deb bashorat qiling, keyin fikringizni tekshiring.

**A o'zgarish:**

```python
# ESKI
def hisobla_soliq(narx):
    return narx * Decimal("0.12")

# YANGI
def hisobla_soliq(narx, stavka=Decimal("0.12")):
    return narx * stavka
```

<details>
<summary>Javobni ko'rish</summary>

**Xavfsiz.** `stavka` parametri default qiymat bilan qo'shilgan. Eski barcha chaqiruvchilar (`hisobla_soliq(narx)`, argumentsiz) avvalgidek `0.12` stavkasini olishda davom etadi — xulq-atvor 100% bir xil qoladi. Bu — funksiyani backward-compatible tarzda kengaytirishning to'g'ri namunasi (xuddi darsdagi `ortacha_narx(mahsulotlar, valyuta="so'm")` kabi).
</details>

**B o'zgarish:**

```python
# ESKI
def hisobla_soliq(narx):
    return narx * Decimal("0.12")

# YANGI
def hisobla_soliq(narx, mamlakat):
    stavkalar = {"UZ": Decimal("0.12"), "US": Decimal("0.07")}
    return narx * stavkalar[mamlakat]
```

<details>
<summary>Javobni ko'rish</summary>

**Xavfli.** `mamlakat` — default qiymatsiz, majburiy parametr. Barcha eski `hisobla_soliq(narx)` chaqiruvlari (argumentsiz) darhol `TypeError: hisobla_soliq() missing 1 required positional argument: 'mamlakat'` xatosiga uchraydi. Bu xavfsiz qilish uchun yo `mamlakat="UZ"` kabi default berish kerak, yoki 9.1-darsdagi metodologiya bo'yicha — grep orqali barcha chaqiruvchilarni topib, har biriga yangi argumentni qo'lda qo'shish kerak.
</details>

## Keng tarqalgan xatolar

❌ **"Men faqat maydon qo'shyapman, bu xavfsiz" deb, `default=` bermasdan modelga majburiy maydon qo'shish.** Bu `makemigrations`ni interaktiv rejimda to'xtatib qo'yadi (yoki avtomatlashtirilgan muhitda butunlay quladi).

✅ Yangi maydonga har doim `default=` (yoki `null=True`, agar "qiymat yo'q" ma'noli bo'lsa) bering — mavjud qatorlar uchun.

❌ **Funksiyaga yangi parametr qo'shganda, uni "oxiriga" emas, "boshiga" yoki o'rtasiga default'siz qo'shish** — bu nafaqat `TypeError`ga, balki ba'zida (agar chaqiruvchilar pozitsion argument ishlatgan bo'lsa) noto'g'ri qiymat noto'g'ri parametrga tushib, **noto'g'ri, lekin xatosiz** natija berishga olib kelishi mumkin.

✅ Yangi parametrni har doim oxiriga, default qiymat bilan qo'shing: `def f(eski_param, yangi_param=None):`.

❌ **Context lug'atidagi kalitni "tozalash" yoki "qisqartirish" maqsadida nomini o'zgartirib, shablonni tekshirmaslik.** Bu — server 200 qaytaradigan, lekin ma'lumot yo'qolgan, eng sezilmaydigan xato turi.

✅ Context kalitini nomini o'zgartirishdan oldin, 9.1-darsdagi kabi, `grep -rn "eski_kalit_nomi" apps/*/templates/` bilan barcha shablonlarni toping va birga yangilang.

❌ **"Yangi funksiya qo'shdim, demak hech narsa tekshirmasam ham bo'ladi" deb o'ylash.** Yangi funksiyaning o'zi xavfsiz bo'lishi mumkin, lekin uni **ulagan** joy (yangi view, yangi URL, import qatori) xato bo'lishi mumkin — masalan import nomini xato yozish yoki URL patternini boshqa bir mavjud pattern bilan mos kelib qolishi.

✅ Yangi kod qo'shgandan keyin ham, hech bo'lmasa `python manage.py check` va asosiy sahifalarni bir marta qo'lda (yoki curl bilan) tekshiring — "yangi qo'shdim" degani "test qilish shart emas" degani emas.

## Mashq/topshiriq

### Oson

`Mijoz` modeliga yangi `email_xabarnoma` (email orqali xabar olish-olmasligi) maydonini `BooleanField(default=True)` bilan qo'shing. `makemigrations` buyrug'ini ishga tushiring va u interaktiv savol bermasligiga ishonch hosil qiling. Keyin `python manage.py shell` orqali yangi mijoz yarating (`Mijoz.objects.create(...)`) va uning `email_xabarnoma` qiymati avtomatik `True` bo'lganini tekshiring.

<details>
<summary>Javobni ko'rish</summary>

```python
class Mijoz(models.Model):
    ism = models.CharField(max_length=50)
    familiya = models.CharField(max_length=50)
    email = models.EmailField(unique=True)
    telefon = models.CharField(max_length=20, blank=True)
    email_xabarnoma = models.BooleanField(default=True)
```

```
$ python manage.py makemigrations dokon
Migrations for 'dokon':
  apps/dokon/migrations/0010_mijoz_email_xabarnoma.py
    + Add field email_xabarnoma to mijoz
```

Hech qanday savol berilmadi (`default=True` borligi uchun). Migratsiyadan keyin:

```
>>> from apps.dokon.models import Mijoz
>>> m = Mijoz.objects.create(ism='Dilshod', familiya='Karimov', email='dilshod@example.com')
>>> m.email_xabarnoma
```

```python
def chegirmali_narx_hisobla(mahsulot, dumaloqlash=None):
    chegirma_ulushi = Decimal(mahsulot.chegirma_foizi) / Decimal("100")
    chegirma_summasi = mahsulot.narxi * chegirma_ulushi
    natija = mahsulot.narxi - chegirma_summasi
```

### Qiyin

`bolimlar_royxati` view'idagi context lug'atida `"jami_bolimlar_soni"` kalitini `"bolimlar_soni"`ga o'zgartiring (shablonni **o'zgartirmang**). Avval bashorat qiling: server nima qaytaradi — xatomi, yo'qmi? Agar xato bo'lmasa, sahifada aniq nima ko'rinadi? So'ng `curl` bilan tekshirib, bashoratingizni tasdiqlang yoki rad eting. Oxirida o'zgarishni bekor qiling (kalitni asl nomiga qaytaring).

<details>
<summary>Javobni ko'rish</summary>

Ko'pchilik "xato chiqadi" deb bashorat qiladi — lekin bu **noto'g'ri**. Real natija:

```
$ curl -o /dev/null -w "STATUS: %{http_code}\n" http://127.0.0.1:8000/bolimlar/
STATUS: 200

$ curl http://127.0.0.1:8000/bolimlar/ | grep "Jami:"
<p>Jami:  ta bo'lim</p>
```

Status — `200`, xato yo'q. Lekin sahifada raqam o'rniga bo'sh joy qoldi (`Jami:  ta bo'lim`, ikkita bo'sh joy orasida hech narsa yo'q). Sabab — 5.2-darsda o'rganilgan Django shablon mexanizmi: shablon `{{ jami_bolimlar_soni }}`ni context'da qidiradi, topolmaydi, va xato berish o'rniga jim ravishda bo'sh qatorni qo'yadi.

Bu darsning eng muhim xulosasi: **context kalitini nomini o'zgartirish — status kod orqali sezilmaydigan, faqat sahifa mazmunini qo'lda (yoki avtomatik testlar bilan) tekshirganda topiladigan xato turi**.

Bekor qilish:

```python
context = {
    "bolimlar": barcha_bolimlar,
    "jami_bolimlar_soni": barcha_bolimlar.count(),
}
```
</details>

## Qisqacha xulosa

Kodga biror narsa "qo'shish" ikki xil bo'ladi: **butunlay yangi** narsa (funksiya, view, URL, model) qo'shish deyarli har doim xavfsiz, chunki hali hech kim uni chaqirmaydi — buni grep bilan isbotlash mumkin. **Mavjud narsani kengaytirish** (model maydoni, funksiya parametri, context kaliti) esa ehtiyot talab qiladi: `default=` yoki `null=True` bilan qilingan kengaytirish backward-compatible (eski chaqiruvchilar sezmaydi), default'siz majburiy qilib qo'shish esa eski chaqiruvchilarni sindiradi.

Ikki xil "sinish" bor: **ovozli** (`TypeError`, traceback, status 500 — buni darhol ko'rasiz va tuzatasiz) va **jim/sezilmaydigan** (status 200, lekin noto'g'ri yoki bo'sh natija — context kalitini nomini o'zgartirishda bo'lgani kabi). Ikkinchisi ancha xavfli, chunki hech narsa "qizil" bo'lib chiqmaydi. Shu sababli, har qanday "qo'shish" dan keyin ham — hatto u xavfsiz tuyulsa ham — kamida asosiy sahifalarni jonli tekshirish odat bo'lishi kerak.
