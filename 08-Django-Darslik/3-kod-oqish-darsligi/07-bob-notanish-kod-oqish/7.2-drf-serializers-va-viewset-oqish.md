# 7.2. DRF: `serializers.py` va `ModelViewSet` — butunlay yangi naqshni o'qish

## Bu darsda nimalarni o'rganasiz

- `ModelViewSet` — bitta, kichkina klass, nega **oltita** turli HTTP amalini (list, create, retrieve, update, partial_update, destroy) avtomatik "beradi"
- `router.register()` — `urls.py`da, `path()` yozuvlari **umuman yo'qligi**, lekin baribir, ko'plab URL'lar ishlayotganini
- `serializers.py` — bu, aslida, `forms.py`ga juda o'xshash, lekin HTML o'rniga **JSON** bilan ishlaydigan "tarjimon"
- `read_only`/`write_only` maydonlar — bitta ma'lumot, o'qish va yozishda, nega **boshqa-boshqa ko'rinishda** bo'lishi mumkinligini

## Nazariy qism

### `serializers.py` — `forms.py`ning, JSON uchun "egizagi"

```python
from rest_framework import serializers

from .models import Kitob, Muallif


class MuallifSerializer(serializers.ModelSerializer):
    class Meta:
        model = Muallif
        fields = ["id", "ism", "familiya"]


class KitobSerializer(serializers.ModelSerializer):
    muallif = MuallifSerializer(read_only=True)
    muallif_id = serializers.PrimaryKeyRelatedField(
        queryset=Muallif.objects.all(), source="muallif", write_only=True
    )
    mavjud_nusxalar = serializers.ReadOnlyField()

    class Meta:
        model = Kitob
        fields = ["id", "sarlavha", "muallif", "muallif_id", "nashr_yili",
                  "nusxalar_soni", "band_qilingan_soni", "mavjud_nusxalar"]
```

Agar siz, 6.2-darsdagi `MijozForm(forms.ModelForm)`ni eslasangiz — bu, **aynan o'sha g'oya**, faqat, natija HTML o'rniga, **JSON** bo'ladi: `class Meta: model = ...` — qaysi modeldan "quriladi"; `fields = [...]` — qaysi maydonlar kiritiladi. Lekin bu yerda, ikkita, **maxsus e'lon qilingan** maydon bor, va ular — darsning markazi:

`muallif = MuallifSerializer(read_only=True)` — bu, `Kitob.muallif` (ForeignKey)ni, oddiy son (`muallif_id`) sifatida emas, balki **to'liq, ichma-ich (nested) ob'ekt** sifatida ko'rsatadi (`{"id": 1, "ism": "Abdulla", "familiya": "Qodiriy"}`). `read_only=True` — bu maydon, faqat **o'qish** (GET so'rovlarida ko'rsatish) uchun, uni orqali, **yangi kitob yaratib bo'lmaydi**.

`muallif_id = serializers.PrimaryKeyRelatedField(..., write_only=True)` — bu, aksincha, faqat **yozish** (POST/PUT so'rovlarida, kiritish) uchun: mijoz, yangi kitob yaratganda, to'liq muallif ob'ektini emas, faqat, uning **ID raqamini** (`"muallif_id": 1`) yuboradi. `source="muallif"` — bu, "bu maydondan kelgan qiymat, aslida, model darajasida, `muallif` atributiga yozilsin" degani (nomlar boshqacha bo'lgani uchun, bu — ularni "bog'lash").

**Xulosa:** bitta, mantiqiy narsa (kitobning muallifi) — API'da, **ikkita, alohida maydon** orqali ifodalangan: biri — o'qish uchun (to'liq ma'lumot bilan, qulay), ikkinchisi — yozish uchun (faqat ID, sodda). Bu — DRF'da **juda keng tarqalgan naqsh**, lekin uni birinchi marta ko'rgan odam uchun, chalkash tuyulishi mumkin.

### `ModelViewSet` — bitta klass, oltita amal

```python
from rest_framework import viewsets

from .models import Kitob, Muallif
from .serializers import KitobSerializer, MuallifSerializer


class KitobViewSet(viewsets.ModelViewSet):
    queryset = Kitob.objects.all()
    serializer_class = KitobSerializer
```

Bor-yo'g'i, ikki qator (`queryset`, `serializer_class`) — lekin bu, **oltita** turli amalni beradi: `GET /api/kitoblar/` (ro'yxat), `POST /api/kitoblar/` (yangi yaratish), `GET /api/kitoblar/3/` (bitta kitobni olish), `PUT /api/kitoblar/3/` (to'liq yangilash), `PATCH /api/kitoblar/3/` (qisman yangilash), `DELETE /api/kitoblar/3/` (o'chirish). Buni, 5-6-boblarda yozgan, **har bir amal uchun alohida, qo'lda yozilgan function-based view**lar bilan solishtiring — bu yerda, Django/DRF, "CRUD (Create-Read-Update-Delete) — bu, deyarli har doim bir xil naqsh" degan taxminga asoslanib, hamma narsani **avtomatik** yasaydi.

### `router.register()` — `urls.py`da, `path()`siz URL'lar

```python
from rest_framework.routers import DefaultRouter

from .views import KitobViewSet, MuallifViewSet

router = DefaultRouter()
router.register("mualliflar", MuallifViewSet)
router.register("kitoblar", KitobViewSet)

urlpatterns = router.urls
```

Bu — 2-3-boblarda ko'rgan, `path("...", views...)` yozuvlaridan **butunlay boshqa** naqsh: bu yerda, hech qanday alohida `path()` chaqiruvi yo'q! `router.register("kitoblar", KitobViewSet)` — DRF'ga, "`KitobViewSet`dan, **standart CRUD URL to'plamini, o'zing yasab chiq**" deydi. `urlpatterns = router.urls` — bu, `router` **o'zi yasagan**, to'liq `urlpatterns` ro'yxatini, oddiy Python o'zgaruvchisiga o'xshab, qaytaradi. "Notanish kod"ni o'qiyotganda, agar `urls.py`da, `path()` chaqiruvlari **kam yoki umuman yo'q** bo'lsa — bu, deyarli har doim, **router** ishlatilayotganining belgisi.

## Kodni o'qish mashqi

Quyidagi so'rovni ko'ring:

```bash
curl -X POST http://localhost:8001/api/kitoblar/ \
  -H "Content-Type: application/json" \
  -d '{"sarlavha": "Test", "muallif": {"ism": "X", "familiya": "Y"}, "nashr_yili": 2000, "nusxalar_soni": 1}'
```

Diqqat qiling: bu yerda, `"muallif_id": 1` o'rniga, **`"muallif": {...}`** (to'liq, ichma-ich ob'ekt) yuborilgan — xuddi, GET so'rovda qaytadigan formatga o'xshab. **Bashorat qiling:** bu so'rov, muvaffaqiyatli (`201`) bo'ladimi, yo xato beradimi? Agar xato bo'lsa — qanday xato?

<details>
<summary>Javobni ko'rish</summary>

Xato beradi, `400 Bad Request`:
```json
{"muallif_id": ["This field is required."]}
```

Sabab — yuqorida ko'rganimizdek, `muallif` maydoni, serializer'da, `read_only=True` deb belgilangan: DRF, **yozish (input) paytida, `read_only` maydonlarni butunlay e'tiborga olmaydi** (hatto, siz, so'rov tanasida, uni to'liq, to'g'ri formatda yuborgan bo'lsangiz ham!). Yozish uchun, faqat `muallif_id` (`write_only=True`, bu — yozish uchun **majburiy**, chunki u, `PrimaryKeyRelatedField` sifatida, `required` standart holatda `True`) ishlatiladi. Bu — 6.2-darsdagi, "forma maydoni nomi, kalit nomi bilan aniq mos kelishi kerak" qoidasining, DRF'dagi, yanada qat'iyroq ko'rinishi: **`read_only` va `write_only`, bir xil "mantiqiy narsa" uchun ham, chindan ham, ikkita mustaqil "yo'l" ekanini** ko'rsatadi.

## Amaliy misol

To'liq CRUD zanjirini, real so'rovlar bilan sinaymiz. **Create** (`muallif_id` bilan, to'g'ri):

```bash
curl -X POST http://localhost:8001/api/kitoblar/ -H "Content-Type: application/json" \
  -d '{"sarlavha": "Sarob", "muallif_id": 1, "nashr_yili": 1934, "nusxalar_soni": 2}'
```
```json
{"id":3,"sarlavha":"Sarob","muallif":{"id":1,"ism":"Abdulla","familiya":"Qodiriy"},"nashr_yili":1934,"nusxalar_soni":2,"band_qilingan_soni":0,"mavjud_nusxalar":2}
```
```
STATUS: 201
```

Diqqat qiling: **kiritishda** `muallif_id: 1` (son) yuborilgan, lekin **javobda**, `muallif`, to'liq ob'ekt (`{"id":1,"ism":...}`) sifatida qaytgan — bu, yuqorida tushuntirilgan, o'qish/yozish assimetriyasining, amaldagi ko'rinishi.

**Qisman yangilash** (`PATCH` — faqat bitta maydon):

```bash
curl -X PATCH http://localhost:8001/api/kitoblar/3/ -H "Content-Type: application/json" -d '{"nusxalar_soni": 5}'
```
```json
{"id":3, ..., "nusxalar_soni":5, ...}
```
```
STATUS: 200
```

Faqat `nusxalar_soni` yuborilgan bo'lsa ham, xato yo'q — `PATCH`, `PUT`dan farqli, **faqat yuborilgan maydonlarni** yangilaydi (`PUT` esa, yuborilmagan maydonlarni, odatda, xato yoki standart qiymat bilan talab qiladi).

**O'chirish**:

```bash
curl -X DELETE http://localhost:8001/api/kitoblar/3/
```
```
STATUS: 204
```

`204 No Content` — 3.2-darsda ko'rgan status kodlar oilasidan: `2xx` — muvaffaqiyat, lekin `204`, maxsus ravishda, "muvaffaqiyatli, lekin qaytariladigan **tana (body) yo'q**" degani (`200`dan farqli — `200`da, odatda, biror JSON tana bo'ladi).

## Keng tarqalgan xatolar

**Xato 1:** `read_only=True` maydonni, `Meta.fields`ga qo'shishni unutish (yoki, aksincha, uni umuman `fields`ga kiritmaslik).
❌ Agar `KitobSerializer.Meta.fields`da, `"muallif"` yo'q bo'lsa — GET so'rovlarida, muallif ma'lumoti **umuman ko'rinmaydi**, hech qanday xato yo'q (JSON'da, shunchaki, o'sha kalit yo'q).
✅ `Meta.fields`ni yozganda, har bir, alohida e'lon qilingan (`muallif = ...`) maydonni ham, ro'yxatga **qo'shishni unutmaslik**.

**Xato 2:** `PrimaryKeyRelatedField`da, `queryset`ni unutish.
❌
```python
muallif_id = serializers.PrimaryKeyRelatedField(source="muallif", write_only=True)  # queryset yo'q!
```
```
AssertionError: Relational field must provide a `queryset` argument, override `get_queryset`, or set read_only=`True`.
```
Bu — server ishga tushishi bilanoq (birinchi so'rovda) chiqadigan, ochiq xato: DRF, "qaysi ID'lar **haqiqiy, mavjud** `Muallif`larga tegishli" ekanini tekshirish uchun, `queryset`ga muhtoj — aks holda, "1" degan raqam kelganda, u haqiqatan ham mavjud `Muallif`ga tegishli ekanini qanday bilish kerakligi noaniq qoladi.
✅ Har bir yozish uchun mo'ljallangan, bog'langan (`PrimaryKeyRelatedField`) maydonga, albatta `queryset` berish.

**Xato 3:** `router.register()`da, prefiks (`"kitoblar"`) va `ViewSet`ni **teskari tartibda** yozish.
❌ `router.register(KitobViewSet, "kitoblar")` — bu, `TypeError` yoki noto'g'ri ishlaydigan marshrutlashga olib keladi, chunki `register()`, birinchi argument sifatida, **har doim, URL prefiksini (matn)** kutadi.
✅ Tartibni yodda saqlash: `router.register("url-prefiksi", ViewSetKlassi)`.

## Mashq/topshiriq

**(Oson)** Agar 7.1-darsning 1-mashqini bajarmagan/saqlamagan bo'lsangiz, avval, `kitoblar/models.py`dagi `Muallif`ga, `@property kitoblar_soni` (`self.kitoblar.count()` qaytaruvchi) qo'shing. So'ng, `MuallifSerializer`ga, `kitoblar_soni = serializers.ReadOnlyField()` maydonini qo'shing. `/api/mualliflar/`ni qayta so'rab, natijada, endi `"kitoblar_soni"` kaliti borligini tasdiqlang. **Ehtiyot chorasi:** agar serializer'ga `ReadOnlyField()`ni qo'shib, lekin modelga mos `@property`/maydonni qo'shishni **unutsangiz**, natija — bo'sh qiymat emas, balki, real xato: `AttributeError`, chunki `ReadOnlyField`, `instance.kitoblar_soni`ni, bevosita, Python orqali o'qishga urinadi, va u yerda, chindan ham, hech narsa yo'q bo'lib chiqadi.

**(O'rtacha)** `KitobViewSet`ga, `http_method_names = ["get", "post"]` qo'shing (bu, DRF'ning, `ModelViewSet`dan meros olingan, standart atributi). **Bashorat qiling:** shundan so'ng, `PATCH`/`DELETE` so'rovlari, qanday status kod bilan javob beradi?

**(Qiyin)** `azolar` app'ida, `kitob_olish`/`kitob_qaytarish` — function-based view'lar (5-6-boblardagi uslub). Ularni, DRF'ning `@api_view(["POST"])` dekoratori yordamida, "DRF uslubiga" o'tkazing — funksiyaning o'zi deyarli o'zgarmasin, faqat, `JsonResponse` o'rniga, `rest_framework.response.Response` ishlatilsin. Ikkala uslubni solishtirib, qaysi holatlarda, function-based (oddiy) yondashuv, `ModelViewSet`dan **ko'ra qulayroq** ekanini, o'z so'zlaringiz bilan tushuntiring (maslahat: `kitob_olish`, oddiy CRUD emas, **maxsus biznes-mantiqqa** ega).

<details>
<summary>Javoblarni ko'rish</summary>

1.
```python
class MuallifSerializer(serializers.ModelSerializer):
    kitoblar_soni = serializers.ReadOnlyField()

    class Meta:
        model = Muallif
        fields = ["id", "ism", "familiya", "kitoblar_soni"]
```
`/api/mualliflar/` natijasida: `{"id":1,"ism":"Abdulla","familiya":"Qodiriy","kitoblar_soni":2}`. `serializers.ReadOnlyField()`, xuddi `Meta.model`dagi haqiqiy maydonlar kabi emas, balki, model ob'ektidagi **istalgan atributni** (oddiy maydon, `@property`, yoki hatto metod) "topib, o'qib chiqadi" — bu yerda, `Muallif.kitoblar_soni` `@property`sini.

2. `PATCH`/`DELETE` so'rovlari, endi, real, sinalgan natija bilan, `405 Method Not Allowed` bilan rad etiladi (3.2-darsda ko'rgan status kod, endi DRF darajasida):
```json
{"detail": "Method \"PATCH\" not allowed."}
```
```json
{"detail": "Method \"DELETE\" not allowed."}
```
`http_method_names` — `ModelViewSet`ning, qaysi HTTP metodlariga **umuman javob berishini** cheklaydi; bu — real loyihalarda, masalan, "bu resursni faqat o'qish mumkin, o'zgartirib yoki o'chirib bo'lmaydi" kabi qoidalarni, kod yozmasdan, **bitta atribut** orqali o'rnatish uchun ishlatiladi.

3.
```python
from rest_framework.decorators import api_view
from rest_framework.response import Response

@api_view(["POST"])
def kitob_olish(request, azo_id, kitob_id):
    azo = get_object_or_404(Azo, id=azo_id)
    kitob = get_object_or_404(Kitob, id=kitob_id)
    if kitob.mavjud_nusxalar <= 0:
        return Response({"xato": "Bu kitobning mavjud nusxasi qolmagan."}, status=400)
    Ijara.objects.create(azo=azo, kitob=kitob)
    return Response({"xabar": "Kitob muvaffaqiyatli olindi", "kitob": kitob.sarlavha})
```
**Xulosa:** `ModelViewSet` — modelning **to'g'ridan-to'g'ri, standart CRUD amallari** (yarat/o'qi/yangila/o'chir) uchun juda qulay, chunki bu amallar, deyarli har doim, bir xil naqshga tushadi. Lekin `kitob_olish` kabi, **maxsus biznes-mantiqqa ega** (mavjudlikni tekshirish, ikkita modelni bog'lash, signalni ishga tushirish) amallar uchun, `ModelViewSet`ning avtomatik naqshlariga "sig'dirishga urinish" — ko'pincha, oddiy function-based view yozishdan **ko'ra murakkabroq** bo'lib chiqadi. To'g'ri qoida: **oddiy CRUD — `ModelViewSet`; maxsus mantiq — oddiy, qo'lda yozilgan view** (`@api_view` bilan yoki bilansiz).

</details>

## Qisqacha xulosa

`serializers.py` — `forms.py`ning, JSON uchun mo'ljallangan hamkasbi: `ModelSerializer`, modeldan, avtomatik validatsiya va (de)serializatsiya qoidalarini quradi; `read_only`/`write_only` maydonlar, bir xil ma'lumotning, o'qish va yozishda **boshqa-boshqa ko'rinishini** ta'minlaydi. `ModelViewSet` — bitta, kichik klass orqali, standart CRUD amallarining **barchasini** avtomatik beradi; `router.register()`, `urls.py`da, qo'lda yozilgan `path()`lar o'rniga, shu amallarga mos URL'larni **o'zi yasaydi** — shuning uchun, notanish loyihada, `urls.py`da `path()` kam yoki yo'qligini ko'rsangiz, bu, deyarli har doim, router ishlatilganining belgisi. Bu bo'lim bilan, darslikning "notanish kod o'qish" markaziy sinovi yakunlandi — siz, hech qachon yozmagan loyihani, sistematik tarzda (fayl tuzilmasi → `models.py` → `urls.py`/`views.py` → yashirin signal/manager'lar) o'qib, uning to'liq ish mantig'ini tiklay oldingiz. Keyingi bo'limda — xatolarni (traceback'larni) o'qib, sababini tezda topish mahoratini chuqurlashtiramiz.
