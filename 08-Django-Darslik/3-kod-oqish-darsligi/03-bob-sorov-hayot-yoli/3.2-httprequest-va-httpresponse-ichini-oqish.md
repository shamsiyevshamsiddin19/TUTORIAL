# 3.2. `HttpRequest` va `HttpResponse` ichini o'qish

## Bu darsda nimalarni o'rganasiz

- Har bir view funksiyasi qabul qiladigan `request` ob'ekti — aslida **nima olib yurishini** ko'rasiz
- `request.GET`dan qiymat olishning ikki usuli (`[]` va `.get()`) orasidagi **muhim farqni**, real xato orqali tushunasiz
- `HttpResponse` va `JsonResponse` ob'ektlarining ichki tuzilishini (status kod, sarlavhalar, kontent) o'qiysiz
- Notanish view kodini ko'rganingizda, undagi `request.META`, `request.headers`, `request.GET` kabi yozuvlarni **tushunib** o'qiy oladigan bo'lasiz

## Nazariy qism

### `request` — bu shunchaki nom emas, bu — ob'ekt

O'tgan darsda ko'rganimizdek, har bir view funksiyasi shunday boshlanadi: `def bosh_sahifa(request):`. Yangi boshlovchilar ko'pincha `request`ni shunchaki "majburiy argument" deb qabul qiladi va uning **ichida nima borligini** o'ylab ko'rmaydi. Aslida, `request` — bu, kelayotgan HTTP so'rovi haqidagi **barcha** ma'lumotni o'zida saqlagan, to'liq Python ob'ekti (`HttpRequest` klassidan).

`views.py`ga vaqtincha diagnostika qatorlarini qo'shib, bitta haqiqiy so'rovda bu ob'ekt ichida nima borligini ko'ramiz:

```python
def bosh_sahifa(request):
    print(">>> request.method:", request.method)
    print(">>> request.path:", request.path)
    print(">>> request.GET:", request.GET)
    print(">>> request.headers['User-Agent']:", request.headers.get("User-Agent"))
    return HttpResponse("Onlayn do'kon — bosh sahifa")
```

So'rovni maxsus so'rov parametrlari va sarlavha bilan yuboramiz:

```bash
curl "http://127.0.0.1:8000/?shahar=Toshkent&limit=5" -A "TestBrowser/1.0"
```

```
>>> request.method: GET
>>> request.path: /
>>> request.GET: <QueryDict: {'shahar': ['Toshkent'], 'limit': ['5']}>
>>> request.headers['User-Agent']: TestBrowser/1.0
```

Buni o'qiymiz: `request.method` — HTTP metodini (`GET`, `POST`, va h.k.) beradi; `request.path` — so'ralgan manzilning **faqat yo'l qismini** (domensiz, so'rov parametrlarisiz); `request.GET` — URL'dagi `?shahar=Toshkent&limit=5` qismidan hosil bo'lgan, **lug'atga o'xshash** (`QueryDict`) ob'ekt; `request.headers` — brauzer (yoki `curl`) yuborgan barcha HTTP sarlavhalarini o'z ichiga oladi, biz undan `User-Agent`ni (kim so'rov yuboryapti — brauzermi, dastur mi) o'qib oldik.

### `request.GET` — `[]` yoki `.get()`? Bu — muhim tanlov

`request.GET` — oddiy Python lug'ati emas, balki `QueryDict` — va undan qiymat olishning ikki yo'li, **butunlay boshqa** natija berishi mumkin:

```python
>>> from django.http import QueryDict
>>> qd = QueryDict("shahar=Toshkent&limit=5")
>>> qd.get("shahar")
'Toshkent'
>>> qd.get("yoq_param")
None
>>> qd.get("yoq_param", "standart")
'standart'
>>> qd["yoq_param"]
```

```
django.utils.datastructures.MultiValueDictKeyError: 'yoq_param'
```

Bu — **juda muhim** farq: `.get("kalit")` — agar kalit topilmasa, xotirjam `None` (yoki siz ko'rsatgan standart qiymatni, masalan `"standart"`ni) qaytaradi; `["kalit"]` (kvadrat qavs) esa — agar kalit topilmasa, **`MultiValueDictKeyError`** xatosini tashlaydi va, agar bu xato ushlanmasa, butun view'ni "qulatadi" (foydalanuvchi 500-xato sahifasini ko'radi).

**Amaliy qoida:** foydalanuvchi kiritishi **majburiy bo'lmagan** so'rov parametrlari (masalan, filtrlash, saralash) uchun — har doim `.get()`ni, standart qiymat bilan birga, ishlating: `request.GET.get("shahar", "")`.

### `HttpResponse` — javobning "ichi"

Xuddi shunday, view'dan qaytariladigan `HttpResponse` ham — o'zining ichki tuzilishiga ega ob'ekt:

```python
>>> from django.http import HttpResponse
>>> r = HttpResponse("Salom")
>>> r.status_code
200
>>> r['Content-Type']
'text/html; charset=utf-8'
```

Diqqat qiling: agar biz `status`ni ko'rsatmasak, Django **standart holda** `200` (muvaffaqiyat) va `Content-Type: text/html`ni o'rnatadi. Buni o'zgartirish — oddiy:

```python
>>> r2 = HttpResponse("Topilmadi", status=404)
>>> r2.status_code
404
```

### `JsonResponse` — API'lar uchun maxsus javob

Keyinchalik (DRF va API mavzularida) tez-tez uchraydigan yana bir javob turi — `JsonResponse`:

```python
>>> from django.http import JsonResponse
>>> r3 = JsonResponse({"nomi": "Noutbuk", "narxi": 8500000})
>>> r3.status_code
200
>>> r3['Content-Type']
'application/json'
>>> r3.content
b'{"nomi": "Noutbuk", "narxi": 8500000}'
```

`JsonResponse` — sizga berilgan Python lug'atini **avtomatik ravishda** JSON matniga aylantiradi (`content` — bu, brauzerga jismonan yuboriladigan **bayt** ma'lumot, `b'...'` prefiksiga e'tibor bering) va `Content-Type`ni to'g'ri (`application/json`) o'rnatadi — bu, `HttpResponse(json.dumps(...))` yozishdan ancha qulayroq va xavfsizroq (masalan, u ba'zi xavfsizlik tekshiruvlarini ham o'z ichiga oladi).

## Kodni o'qish mashqi

Quyida — (xayoliy) hamkasbingiz yozgan view:

```python
def mahsulotlarni_royxati(request):
    shahar = request.GET["shahar"]
    return HttpResponse(f"{shahar} shahridagi mahsulotlar")
```

**Savol:** Bu view'ga `curl http://127.0.0.1:8000/mahsulotlar/` (hech qanday `?shahar=...` qo'shmasdan) so'rov yuborilsa, nima bo'ladi? Buni, shu darsda o'qiganlaringizga tayanib, bashorat qiling.

<details>
<summary>Javobni ko'rish</summary>

Xato chiqadi — `MultiValueDictKeyError: 'shahar'`, va bu, ushlanmagani uchun, Django tomonidan **500 (Internal Server Error)**ga aylantiriladi (foydalanuvchi xato sahifasini ko'radi). Sabab — `request.GET["shahar"]` (kvadrat qavs bilan) ishlatilgan, va `shahar` parametri so'rovda **umuman yo'q**. To'g'ri yozilishi: `request.GET.get("shahar", "barcha")` — bu holda, parametr bo'lmasa, kod xato bermay, "barcha" (yoki boshqa mantiqiy standart qiymat) bilan davom etaveradi.

## Amaliy misol

Xavfsiz, `.get()` asosidagi versiyani yozib, sinaymiz:

```python
def mahsulotlarni_royxati(request):
    shahar = request.GET.get("shahar", "barcha shaharlar")
    limit = request.GET.get("limit", "10")
    return HttpResponse(f"Shahar: {shahar}, limit: {limit}")
```

```bash
curl "http://127.0.0.1:8000/mahsulotlar/"
curl "http://127.0.0.1:8000/mahsulotlar/?shahar=Samarqand"
curl "http://127.0.0.1:8000/mahsulotlar/?shahar=Samarqand&limit=3"
```

```
Shahar: barcha shaharlar, limit: 10
Shahar: Samarqand, limit: 10
Shahar: Samarqand, limit: 3
```

Endi kod, parametr berilmagan holatda ham **qulamaydi**, balki oqilona standart qiymat bilan ishlayveradi — bu, real, foydalanuvchiga ochiq API/sahifalar uchun **majburiy** amaliyot (chunki siz foydalanuvchi qanday so'rov yuborishini hech qachon 100% nazorat qila olmaysiz).

## Keng tarqalgan xatolar

**Xato 1:** `request.POST` (forma ma'lumotlari) ni `GET` so'rovda o'qishga urinish.
❌ `GET` so'rovda `request.POST` — har doim **bo'sh** `QueryDict` bo'ladi (chunki `POST` va `GET` — HTTP'da ikki **butunlay boshqa** ma'lumot uzatish kanali). Bu xato, ayniqsa, forma yuborilganda "hech narsa kelmayapti" degan tushunarsiz muammoga olib keladi.
✅ Har doim, qaysi turdagi so'rovdan (`GET` — URL orqali, `POST` — forma tanasi orqali) qaysi ma'lumot kutilayotganini aniq belgilang, va kerak bo'lsa, `request.method`ni tekshirib, mos ravishda `request.GET` yoki `request.POST`ni o'qing.

**Xato 2:** `HttpResponse`ga, kontent sifatida, oddiy Python lug'atini to'g'ridan-to'g'ri berish.
❌ `HttpResponse({"nomi": "Noutbuk"})` — brauzerga, JSON o'rniga, Python lug'atining **matn ko'rinishi** (`{'nomi': 'Noutbuk'}`, noto'g'ri qo'shtirnoq bilan) yuboriladi — bu, hech qanday dastur (frontend, boshqa API) tomonidan to'g'ri **tahlil qilinmaydigan** format.
✅ JSON qaytarish kerak bo'lganda, har doim `JsonResponse(lugat)`dan foydalaning — u, formatlashni va to'g'ri `Content-Type`ni o'zi hal qiladi.

**Xato 3:** `request.GET.get("limit")`dan olingan qiymatni, uni sonlar bilan solishtirishdan oldin, songa aylantirmasdan ishlatish.
❌ `request.GET.get("limit", 10)` — URL'dan kelgan qiymat **har doim matn (string)** bo'ladi (`"5"`, `10` emas), hatto standart qiymat sifatida son bersangiz ham, haqiqiy URL'dan kelganda u baribir matn bo'ladi; `"5" > 3` kabi solishtirish `TypeError` beradi.
✅ Sonli parametrlarni, ulardan foydalanishdan oldin, har doim `int(request.GET.get("limit", "10"))` kabi, ochiq ravishda songa aylantiring (va, foydalanuvchi noto'g'ri qiymat — masalan, `?limit=abc` — yuborsa nima bo'lishini ham o'ylab ko'ring, bu — 8-bobda `forms.py` mavzusida chuqurroq yechiladi).

## Mashq/topshiriq

**(Oson)** `apps/dokon/views.py`dagi `bosh_sahifa`ga, `request.method`ni tekshirib, agar u `"GET"` bo'lmasa (masalan, kimdir `POST` yuborsa), `HttpResponse("Faqat GET qo'llab-quvvatlanadi", status=405)` qaytaradigan shart qo'shing. `curl -X POST http://127.0.0.1:8000/` bilan sinang — natija sizni **hayratda qoldirishi** mumkin (agar shunday bo'lsa, sababini shu darsda o'qigan 3.1-darsdagi middleware bilimingizga tayanib izohlang).

**(O'rtacha)** Yangi view yozing — `mahsulot_json(request)` — `JsonResponse({"nomi": "Sichqoncha", "narxi": 150000, "mavjud": True})` qaytaruvchi. Uni `urls.py`ga `path("api/mahsulot/", views.mahsulot_json)` sifatida ulang, `curl`orqali chaqirib, `Content-Type` sarlavhasi haqiqatan `application/json` ekanini (`curl -I` bilan) tasdiqlang.

**(Qiyin)** `request.GET.get("limit", "10")` orqali olingan qiymatni songa aylantirib, agar u haqiqiy son bo'lmasa (masalan, foydalanuvchi `?limit=abc` yuborsa), aniq xato o'rniga, `HttpResponse("Noto'g'ri limit qiymati", status=400)` qaytaradigan view yozing (maslahat: `try/except ValueError` blokidan foydalaning). `curl "http://127.0.0.1:8000/?limit=abc"` bilan sinab, natijani tekshiring.

## Qisqacha xulosa

`request` — shunchaki argument emas, balki so'rov haqidagi **barcha** ma'lumotni (`method`, `path`, `GET`, `POST`, `headers`) olib yuruvchi to'liq ob'ekt; `request.GET`dan qiymat olishda, `[]` (majburiy, xato tashlaydigan) va `.get()` (xavfsiz, standart qiymat bilan) orasidagi farqni bilish — real loyihalarda ko'plab "500 xato" muammolarining oldini oladi. `HttpResponse` — `status_code` va sarlavhalarga ega ob'ekt bo'lib, standart holda `200` va `text/html` qaytaradi; `JsonResponse` esa, Python lug'atini avtomatik, to'g'ri formatlangan JSON'ga aylantiradi. Bu ikki ob'ektni (`request` va javob) chuqur tushunish — 03-bobning, va butun "so'rov hayot yo'li" mavzusining, yakuniy bosqichi edi. Keyingi (4-)bobda — endi **`models.py`ni chuqur o'qishga**, va real `onlayn_dokon` ma'lumotlar bazasi modellarini yaratishga o'tamiz.
