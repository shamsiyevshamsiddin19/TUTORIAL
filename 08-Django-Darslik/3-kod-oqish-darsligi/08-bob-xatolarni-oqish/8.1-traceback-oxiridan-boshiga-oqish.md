# 8.1. Traceback'ni oxiridan boshiga o'qish

## Bu darsda nimalarni o'rganasiz

- Python traceback'i — nega, **yuqoridan pastga emas, pastdan yuqoriga** o'qilishi kerak
- Traceback ichida, **"sizning kodingiz"** va **"framework kodi"** qatorlarini qanday ajratishni
- Bitta, real xato misolida, "qayerdan boshlab, qayerga qarab yurish kerak" degan, aniq, qadamma-qadam usulni
- Shu darslikda, 00-07-boblarda uchragan xatolarni, endi, **yangi ko'z bilan**, tezroq "o'qiy olishni"

## Nazariy qism

### Traceback — bu, "qo'ng'iroqlar tarixi", oxiridan yozilgan

Yangi, kichik xato yaratamiz. `apps/dokon/xisoblash.py`:

```python
def ortacha_narx(mahsulotlar):
    jami = sum(m.narxi for m in mahsulotlar)
    soni = len(mahsulotlar)
    return jami / soni
```

`apps/dokon/views.py`:

```python
from .xisoblash import ortacha_narx


def bolim_ortacha_narxi(request, bolim_id):
    bolim = get_object_or_404(Bolim, id=bolim_id)
    mahsulotlar = list(bolim.mahsulotlar.all())
    ortacha = ortacha_narx(mahsulotlar)
    return HttpResponse(f"{bolim.nomi}: o'rtacha narx = {ortacha} so'm")
```

Agar `bolim`da, **birorta ham mahsulot** bo'lmasa (`mahsulotlar` — bo'sh ro'yxat), real, sinalgan natija:

```
Internal Server Error: /bolimlar/4/ortacha-narx/
Traceback (most recent call last):
  File ".../django/core/handlers/exception.py", line 55, in inner
    response = get_response(request)
               ^^^^^^^^^^^^^^^^^^^^^
  File ".../django/core/handlers/base.py", line 197, in _get_response
    response = wrapped_callback(request, *callback_args, **callback_kwargs)
               ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  File ".../apps/dokon/views.py", line 49, in bolim_ortacha_narxi
    ortacha = ortacha_narx(mahsulotlar)
              ^^^^^^^^^^^^^^^^^^^^^^^^^
  File ".../apps/dokon/xisoblash.py", line 4, in ortacha_narx
    return jami / soni
           ~~~~~^~~~~~
ZeroDivisionError: division by zero
```

Bu — birinchi marta ko'rgan odam uchun, **qo'rqinchli va uzun** ko'rinishi mumkin. Lekin, uni o'qishning, aniq, oddiy usuli bor:

### Qoida 1: Har doim, **eng oxirgi qatordan** boshlang

```
ZeroDivisionError: division by zero
```

Bu — **eng muhim, birinchi o'qiladigan** qator: `<XatoTuri>: <xato haqida qisqacha xabar>`. Bu, sizga, ikkita narsani darhol aytadi: (1) **qanday** xato (`ZeroDivisionError` — nolga bo'lish); (2) **nima uchun** (`division by zero`). Ko'p hollarda, tajribali dasturchi ham, shu bitta qatorni o'qib, muammoning **turini** darhol tushunadi — qolgan qatorlar, faqat, "qayerda, aniq" ekanini ko'rsatadi.

### Qoida 2: Keyin, **bir qator yuqoriga** ko'tariling — "qaysi qatorda, aniq"

```
  File ".../apps/dokon/xisoblash.py", line 4, in ortacha_narx
    return jami / soni
           ~~~~~^~~~~~
```

Bu — xato **aynan qaysi faylda, qaysi qatorda, qaysi funksiyada** sodir bo'lganini ko'rsatadi: `xisoblash.py`, 4-qator, `ortacha_narx` funksiyasi ichida. `~~~~~^~~~~~` belgisi (Python 3.11+da qo'shilgan, yangi xususiyat) — **aniq, qaysi qism** (`jami / soni`dagi `/` operatori) xatoga sabab bo'lganini, vizual ravishda ko'rsatadi.

### Qoida 3: Undan yuqoriga — "kim, uni chaqirgan" (chaqiruv zanjiri)

```
  File ".../apps/dokon/views.py", line 49, in bolim_ortacha_narxi
    ortacha = ortacha_narx(mahsulotlar)
```

Bu, bir qator yuqorida: `views.py`ning 49-qatori, `ortacha_narx`ni **chaqirgan** joy. Traceback, xuddi shunday, **pastdan yuqoriga**, "kim, kimni chaqirgan" zanjirini ko'rsatadi — eng pastda, xato **sodir bo'lgan** joy, undan yuqorida — uni **chaqirgan** joy, undan ham yuqorida — **uni ham chaqirgan** joy, va hokazo, toki, so'rovning "boshlanish nuqtasi"gacha (bizning holatimizda, Django'ning ichki `handlers/exception.py`, `handlers/base.py` — bu, 3-bobda ko'rgan, so'rov-javob zanjirining, o'zi).

### Qoida 4: "Bu — mening kodimmi, yo framework kodimi?"

Traceback'da, **fayl yo'llariga** e'tibor bering:
```
.../django/core/handlers/exception.py   ← FRAMEWORK kodi (Django'ning o'zi)
.../django/core/handlers/base.py        ← FRAMEWORK kodi
.../apps/dokon/views.py                 ← SIZNING kodingiz
.../apps/dokon/xisoblash.py             ← SIZNING kodingiz
```

**Muhim, amaliy qoida:** 99% hollarda, xatoning **haqiqiy sababi**, sizning **o'z kodingizdagi** (`apps/...`, `venv/`dan tashqarida) eng **pastki** qatorda joylashgan — bu misolda, `xisoblash.py`ning 4-qatori. Django'ning ichki qatorlari (`handlers/exception.py` va h.k.) — bu, shunchaki, "so'rov, sizning kodingizga qanday yetib kelgani"ni ko'rsatadigan, **zanjirning bir qismi**; ularni o'zgartirish shart emas (va, odatda, mumkin ham emas) — ularga, faqat, "qayerdan kelganini tushunish uchun" qarab o'tiladi.

## Kodni o'qish mashqi

Quyida — 3.2-darsda (siz allaqachon ko'rgan!) uchragan, real traceback'ning bir qismi:

```
File ".../django/core/handlers/exception.py", line 55, in inner
    response = get_response(request)
File ".../django/core/handlers/base.py", line 197, in _get_response
    response = wrapped_callback(request, *callback_args, **callback_kwargs)
File ".../django/middleware/csrf.py", line 459, in process_view
    return self._reject(request, REASON_NO_CSRF_COOKIE)
```

Bu yerda, **oxirgi (eng pastki) qator, na `apps/dokon/...`, na sizning kodingizga tegishli** — u, `django/middleware/csrf.py`ga tegishli! **Bashorat qiling:** bu, nima degani — bu xato, sizning kodingizdagi bug'mi, yoki boshqa narsami? Bunday holatda, qanday harakat qilish kerak?

<details>
<summary>Javobni ko'rish</summary>

Bu — sizning kodingizdagi **bug emas**! Bu — 3.2-darsda ko'rgan, `CsrfViewMiddleware`ning, **ataylab, to'g'ri ishlagan** natijasi: forma, CSRF token'siz yuborilgan, va middleware, buni **atayin, xavfsizlik maqsadida** bloklagan. Bu — muhim, umumiy qoida: **traceback'ning eng pastki qatori, "framework kodi"ga tegishli bo'lsa, bu, ko'pincha, xato SIZNING kodingizda EMAS**, balki, siz, framework'ni **kutilmagan tarzda** ishlatayotganingizni bildiradi (bu holatda — CSRF token'siz POST yuborish). Bunday holatda, birinchi savol — "framework, nima uchun, bu xatoni **ataylab** ko'targan?" (odatda, xato xabarining o'zi — `Forbidden (CSRF token missing.)` — buni tushuntiradi), ikkinchi savol esa — "men, o'z kodimda, framework kutgan shartni **qayerda buzganman**?" (bu holatda — shablonda, `{% csrf_token %}`ni unutish).

</details>

## Amaliy misol

Darslikning oldingi boblarida uchragan, uchta real xatoni, endi, **traceback mantig'i** bilan qayta ko'rib chiqamiz:

**1) 1.1-darsdan** (middleware tartibi buzilganda):
```
django.core.exceptions.ImproperlyConfigured: The Django authentication middleware
requires session middleware to be installed...
```
Bu — `Exception Type: Value` qatorining o'zi, aniq, tushunarli: "authentication middleware, session middleware talab qiladi". Traceback'ni ko'rmasdan ham, **xato xabarining o'zidan**, muammo aniq: `MIDDLEWARE` ro'yxatida, tartib noto'g'ri.

**2) 2.1-darsdan** (`apps.py`da `name` maydoni xato bo'lganda):
```
django.core.exceptions.ImproperlyConfigured: Cannot import 'dokon'. Check that
'apps.dokon.apps.DokonConfig.name' is correct.
```
Bu — xato xabarining o'zi, **aniq faylni va aniq atributni** (`apps.dokon.apps.DokonConfig.name`) ko'rsatadi — traceback'ning "pastki qismi"ga borishning ham hojati yo'q, xabar, o'zi, yechimni deyarli aytib turibdi.

**3) 4.1-darsdan** (`null=True`siz, `None` saqlashga urinilganda):
```
django.db.utils.IntegrityError: null value in column "joylashuv" of relation "dokon_bolim"
violates not-null constraint
DETAIL:  Failing row contains (2, IT, null).
```
Bu — Qoida 4'ning yana bir ko'rinishi: bu xato, `django.db.utils`da "ko'tarilgan" (chaqirilgan), lekin uning **haqiqiy sababi** — PostgreSQL'ning o'zi (`DETAIL:` qatori — bu, Python emas, PostgreSQL'ning xabari, `psycopg2` orqali "ko'tarilgan"). Bu — traceback'lar, ba'zan, **bir nechta til/tizim chegarasidan o'tishi** mumkinligini ko'rsatadi: Python → `psycopg2` → PostgreSQL.

**Xulosa:** har uchala holatda ham, eng samarali yondashuv — **avval, oxirgi qatorni (xato turi + xabar) diqqat bilan o'qish**, va, faqat, agar xabar o'zi yetarli bo'lmasa, traceback bo'ylab, pastdan yuqoriga, **o'z kodingiz** joylashgan qatorlarni qidirib chiqish.

## Keng tarqalgan xatolar

**Xato 1:** Traceback'ni, **yuqoridan pastga**, birinchi qatordan boshlab o'qishga urinish.
❌ Yuqoridagi 3-qator misolida, agar yuqoridan boshlansa, o'quvchi, avval, `django/core/handlers/exception.py`ga "yopishib qoladi" — bu esa, hech qachon, muammoning haqiqiy sababi emas.
✅ Har doim, **oxirgi qatordan** (xato turi va xabari) boshlash, so'ng, kerak bo'lsa, yuqoriga ko'tarilish.

**Xato 2:** Traceback'dagi, `venv/lib/...` yoki `site-packages/...` ichidagi fayllarni, "o'zim buzilgan kod" deb, tahrirlashga urinish.
❌ Kutubxona (masalan, Django'ning o'zi yoki `djangorestframework`) fayllarini, to'g'ridan-to'g'ri tahrirlash — hech qachon, to'g'ri yechim emas (va, keyingi `pip install --upgrade` bilan, o'zgarishlar **yo'qolib ketadi**).
✅ Kutubxona kodidagi qatorlar — faqat, "yo'l xaritasi" sifatida o'qiladi; haqiqiy tuzatish, deyarli har doim, **o'zingizning kodingizda** (yoki, sozlamalarda) bo'ladi.

**Xato 3:** Xato xabarini o'qimasdan, darhol, internetdan (yoki AI'dan) "tayyor javob" qidirishga urinish.
❌ Bu, ko'pincha, vaqtni behuda sarflaydi, chunki, xato xabarining o'zi, ko'p hollarda (yuqoridagi 1- va 2-misollarda ko'rganimizdek), **aniq, tushunarli va o'ziga xos** bo'ladi.
✅ Avval, xato xabarini, **so'zma-so'z, diqqat bilan** o'qish — bu, ko'pincha, qidiruv qilishdan tezroq va samaraliroq.

## Mashq/topshiriq

**(Oson)** `apps/dokon/xisoblash.py`dagi `ortacha_narx` funksiyasiga, ataylab, yana bir xato kiritib ko'ring: `soni`ni `len(mahsulotlar)` o'rniga, `len(mahsulot)` (ko'plik emas, birlik — mavjud bo'lmagan nom) deb yozing. Server ishga tushirib, real traceback'ni oling — bu safar, **qaysi xato turi** chiqadi (`ZeroDivisionError` emas)?

**(O'rtacha)** Yuqoridagi traceback'da (asosiy, `ZeroDivisionError` misolida), nechta "qator guruhi" (`File "...", line ..., in ...` + kod qatori) borligini sanang. Ulardan, nechtasi — Django'ning ichki kodi, nechtasi — sizning (`apps/dokon/...`) kodingiz? Shu nisbatga qarab, "muammo qayerda" ekanini, traceback'ning **yarmini o'qimasdan** ham aytib bera olasizmi?

**(Qiyin)** `bolim_ortacha_narxi` view'iga, **yana bir qatlam** qo'shing — `xisoblash.py`ga, `ortacha_narx`ni chaqiradigan, yangi `xavfsiz_ortacha_narx(mahsulotlar)` funksiyasini yozing, u, `try/except ZeroDivisionError`, xatoni **ushlab**, `0` qaytarsin. View'ni, shu yangi funksiyani chaqiradigan qilib o'zgartiring. Endi, mahsulotsiz bo'limga so'rov yuboring — traceback endi chiqadimi? Nega, bu holatda, **"xatoni yashirish" — har doim ham, yaxshi yechim emasligini**, tushuntiring (maslahat: foydalanuvchi, "o'rtacha narx = 0 so'm" degan, **noto'g'ri ma'lumotni**, xato bilan emas, muvaffaqiyat bilan qanday qabul qiladi).

<details>
<summary>Javoblarni ko'rish</summary>

1. `len(mahsulot)` — `mahsulot` degan nom, funksiya ichida **umuman e'lon qilinmagan** (faqat `mahsulotlar` bor). Natija:
```
NameError: name 'mahsulot' is not defined
```
Bu — `ZeroDivisionError`dan **butunlay boshqa** xato turi, va u, hatto, bo'limda mahsulotlar bo'lsa ham (`jami`ni hisoblashda emas, keyingi qatorda) chiqadi — chunki, Python, `soni = len(mahsulot)` qatoriga yetganda, `mahsulot` nomi hech qayerda yo'qligini darhol aniqlaydi.

2. Asosiy misolda, **to'rtta** qator guruhi bor: ikkitasi (`handlers/exception.py`, `handlers/base.py`) — Django'ning ichki kodi; ikkitasi (`views.py`, `xisoblash.py`) — sizning kodingiz. Nisbat — **50/50**, lekin, muhim qoida shundaki: qaysi nisbat bo'lishidan qat'i nazar, **har doim, eng pastki, "sizning kod" qatoriga** e'tibor qaratish kifoya — bu holatda, `xisoblash.py`ning 4-qatori, muammoning haqiqiy manzili.

3.
```python
def xavfsiz_ortacha_narx(mahsulotlar):
    try:
        return ortacha_narx(mahsulotlar)
    except ZeroDivisionError:
        return 0
```
Ha, endi, traceback **chiqmaydi** — foydalanuvchi, `"Kitoblar: o'rtacha narx = 0 so'm"` degan, `200 OK` javobni oladi. Lekin bu — **muammoli**: `0 so'm` — bu, "haqiqatan ham, mahsulotlar 0 so'mlik" degani emas, balki, "mahsulot **umuman yo'q**" degani — va bu ikkala holat, foydalanuvchi uchun, **butunlay boshqa ma'noga** ega! Xatoni "yutib yuborish" (xato turini aniq bilmasdan, `except:` yoki noto'g'ri qiymat bilan "tuzatish"), ko'pincha, **haqiqiy muammoni, ko'zga ko'rinmas qilib, keyinga suradi** — bu, darslikning eng muhim, yakuniy saboqlaridan biri: **traceback — dushman emas, u — sizga, aynan qayerda, aynan nima noto'g'ri ekanini aytib beruvchi, eng ishonchli xabarchi**. To'g'ri yechim — xatoni "yashirish" emas, balki, uni **to'g'ri hal qilish** (masalan, `"Bu bo'limda hali mahsulot yo'q"` degan, tushunarli xabar qaytarish, `0 so'm` emas).

</details>

## Qisqacha xulosa

Python traceback'i — **pastdan yuqoriga** o'qiladi: eng oxirgi qator (xato turi + xabar) — eng muhim, birinchi o'qiladigan ma'lumot; undan bir qator yuqorida — xato **aniq qaysi qatorda** sodir bo'lgani; undan ham yuqorida — uni **kim chaqirgan** (chaqiruv zanjiri, toki so'rovning boshlanishigacha). Fayl yo'llariga qarab, "bu — mening kodimmi, yo framework kodimi" ekanini ajratish mumkin — muammoning haqiqiy manzili, deyarli har doim, sizning **o'z kodingizdagi**, eng pastki qatorda. Traceback'ni tushunish uchun, uni to'liq "yodlash" shart emas — muntazam, sistematik yondashuv (oxiridan boshlash, keyin, kerak bo'lsa, yuqoriga ko'tarilish) yetarli. Keyingi darsda — xatoni **topgandan keyin**, uni tuzatish uchun kerak bo'ladigan vositalarni (`breakpoint()`, `print` debugging, `logging`) o'rganamiz.
