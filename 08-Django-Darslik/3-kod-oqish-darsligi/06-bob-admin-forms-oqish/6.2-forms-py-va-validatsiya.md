# 6.2. `forms.py`ni o'qish — foydalanuvchi kiritgan ma'lumot qanday tekshiriladi

## Bu darsda nimalarni o'rganasiz

- `forms.ModelForm` — modeldan, **avtomatik ravishda**, to'liq forma qanday "quriladi"
- `is_valid()`, `cleaned_data`, `errors` — validatsiya jarayonining uchta asosiy bosqichi
- Nega `ModelForm`, `unique=True` kabi model cheklovlarini, bazaga so'rov yubormasdan **oldindan** biladi
- `{% csrf_token %}` — 3-bobda ko'rgan `CsrfViewMiddleware`ning, endi **shablon tomonidagi** ko'rinishi
- View ichida, GET va POST so'rovlarini, **bitta funksiyada**, qanday ajratib boshqarishni

## Nazariy qism

### `ModelForm` — modeldan, formani "o'qib chiqarish"

Yangi fayl, `apps/dokon/forms.py`:

```python
from django import forms

from .models import Mijoz


class MijozForm(forms.ModelForm):
    class Meta:
        model = Mijoz
        fields = ["ism", "familiya", "email", "telefon"]
```

Bu — atigi olti qator, lekin juda ko'p ishni "ichida" bajaradi. `class Meta: model = Mijoz` — Django'ga, "bu formani, `Mijoz` modelidan **avtomatik yasab chiq**" deydi. `fields = [...]` — modelning **qaysi maydonlari**, formaga kiritilishini belgilaydi (masalan, `id`ni odatda kiritmaymiz — u, foydalanuvchi tomonidan emas, baza tomonidan avtomatik beriladi).

Bu formani, `shell`da, hech qanday HTML yoki view'siz sinaymiz:

```python
from apps.dokon.forms import MijozForm

f1 = MijozForm(data={"ism": "Olim", "familiya": "Karim", "email": "olim@example.com", "telefon": ""})
print(f1.is_valid())
```
```
True
```

`is_valid()` — bu, formaning **markaziy metodi**: u, `data`dagi har bir qiymatni, mos model maydonining qoidalari bo'yicha tekshiradi (masalan, `email` — haqiqiy email formatidami, `ism` — bo'sh emasmi, uzunligi `max_length=50`dan oshmaydimi) va `True`/`False` qaytaradi.

### `cleaned_data` — "tozalangan", ishonchli ma'lumot

```python
print(f1.cleaned_data)
```
```
{'ism': 'Olim', 'familiya': 'Karim', 'email': 'olim@example.com', 'telefon': ''}
```

`cleaned_data` — bu, `is_valid()` **muvaffaqiyatli** (`True`) bo'lgandan KEYIN paydo bo'ladigan, Python lug'ati: bu yerdagi qiymatlar, `f1.data`dagi **xom** (odatda, matn ko'rinishidagi) qiymatlardan farqli, allaqachon **to'g'ri Python turlariga aylantirilgan va tekshirilgan** (masalan, `DateField` uchun — `str` emas, haqiqiy `datetime.date` ob'ekti). Muhim qoida: **`is_valid()` chaqirilmasdan turib, `cleaned_data`ga murojaat qilib bo'lmaydi** — u hali mavjud emas.

### `unique=True` — `ModelForm`, buni **oldindan** biladi

Eng qiziqarli sinov — 4.2-darsda, `Mijoz.email`ga `unique=True` qo'ygan edik. Endi, allaqachon bazada mavjud email bilan, yangi forma yuboramiz:

```python
f4 = MijozForm(data={"ism": "Ikkinchi", "familiya": "Odam", "email": "olim@example.com", "telefon": ""})
print(f4.is_valid())     # False
print(f4.errors)
```
```
<ul class="errorlist"><li>email<ul class="errorlist" id="id_email_error"><li>Mijoz with this Email already exists.</li></ul></li></ul>
```

Bu — muhim: `ModelForm`, `is_valid()` chaqirilganda, `Meta.model`dagi maydon cheklovlarini (`unique=True`, `max_length`, `blank`) **avtomatik ravishda, bazaga qo'shimcha so'rov yuborib**, tekshiradi — siz, buni qo'lda yozmagansiz! Bu — modelga bir marta yozilgan qoida (`unique=True`), endi **uchta joyda** amal qilishini ko'rsatadi: (1) bazada — `UNIQUE CONSTRAINT` sifatida (4.1-4.2'da ko'rganimiz); (2) admin panelida — xato sifatida (6.1'da bilvosita ko'rgan); (3) endi — formada ham, **bazaga yozishdan OLDIN**, foydalanuvchiga tushunarli xabar sifatida.

### View ichida — GET va POST'ni ajratib boshqarish

```python
from django.shortcuts import redirect, render

from .forms import MijozForm


def mijoz_royxatga_olish(request):
    if request.method == "POST":
        form = MijozForm(request.POST)
        if form.is_valid():
            form.save()
            return redirect("dokon:mijoz-royxatga-olish-muvaffaqiyat")
    else:
        form = MijozForm()
    return render(request, "dokon/mijoz_form.html", {"form": form})
```

Bu — Django'dagi, **eng keng tarqalgan** view naqshi (pattern), satrma-satr o'qiymiz: `request.method == "POST"` — 3.2-darsda ko'rgan `HttpRequest.method`. Agar `POST` bo'lsa — foydalanuvchi, formani **to'ldirib, yuborgan**: `MijozForm(request.POST)` — kiritilgan ma'lumotni formaga "bog'laydi" (bu — **"bound" forma**, yuqoridagi `shell` misolidagi kabi). `form.is_valid()` — tekshiradi; agar `True` — `form.save()` (bu, ichida, xuddi 4-bobdagi `Bolim.objects.create()`ga o'xshash, yangi `Mijoz` qatorini bazaga yozadi) va `redirect(...)` — muvaffaqiyat sahifasiga yo'naltiradi (3-bobda ko'rgan, `HttpResponseRedirect`ning qulaylik funksiyasi). Agar so'rov `POST` **emas** (ya'ni, `GET` — sahifa birinchi marta ochilganda) — `MijozForm()` (ma'lumotsiz, **"unbound" forma**) yaratiladi — bu, hali hech narsa tekshirilmagan, faqat **bo'sh HTML maydonlarini chizish** uchun ishlatiladi.

**Muhim, nozik nuqta:** agar `POST` bo'lsa-yu, `form.is_valid()` — `False` bo'lsa (xato bor), kod, `if`dan **chiqib ketadi**, va oxirgi qatorga — `return render(...)`ga yetib boradi. Bu — ataylab: xato bo'lganda, **xato xabarlari bilan to'lgan, o'sha forma** (`form`, `request.POST`dan yaratilgan holicha), qayta ko'rsatiladi — foydalanuvchi, o'z xatosini ko'rib, tuzatishi mumkin, hamma narsani qaytadan kiritishga majbur bo'lmaydi.

## Kodni o'qish mashqi

Shablonda, forma shunday chiziladi:

```django
<form method="post">
    {% csrf_token %}
    {{ form.as_p }}
    <button type="submit">Saqlash</button>
</form>
```

**Bashorat qiling:** `{% csrf_token %}` qatorini, ataylab **olib tashlab**, formani shu holda yuborsangiz (POST so'rov), nima bo'ladi? Buni, 3.2-darsda o'rgangan `CsrfViewMiddleware` bilan bog'lang.

<details>
<summary>Javobni ko'rish</summary>

So'rov, **view funksiyasining o'zi ishga tushishidan OLDIN**, `403 Forbidden` bilan rad etiladi:

```
Forbidden (CSRF token missing.)
```

Bu — 3.2-darsda ko'rgan, aynan o'sha xulq: `CsrfViewMiddleware`, `MIDDLEWARE` ro'yxatida, view'dan **oldin** turadi (2-bobda ko'rgan middleware zanjiri), va har bir "xavfli" so'rov (`POST`, `PUT`, `DELETE`) uchun, formada `{% csrf_token %}` orqali yuborilgan **maxfiy token**ni talab qiladi. `{% csrf_token %}` shablon tegi — aynan shu, yashirin `<input type="hidden" name="csrfmiddlewaretoken" value="...">` maydonini chiqaradi. Agar bu teg yo'q bo'lsa — brauzer, hech qanday tokenni yubormaydi, va middleware, so'rovni, `mijoz_royxatga_olish` funksiyasi hali **chaqirilmasdan turib**, to'xtatadi.

</details>

## Amaliy misol

To'liq zanjirni, real HTTP so'rovlar bilan sinaymiz. Avval, GET so'rov — bo'sh forma:

```bash
curl http://localhost:8000/mijoz/yangi/
```

Natijada (qisqartirilgan):
```html
<input type="hidden" name="csrfmiddlewaretoken" value="...">
<p>
    <label for="id_ism">Ism:</label>
    <input type="text" name="ism" maxlength="50" required id="id_ism">
</p>
<p>
    <label for="id_email">Email:</label>
    <input type="email" name="email" maxlength="254" required id="id_email">
</p>
<p>
    <label for="id_telefon">Telefon:</label>
    <input type="text" name="telefon" maxlength="20" id="id_telefon">
</p>
```

**Diqqat qiling:** `{{ form.as_p }}`, har bir maydonni, `<p>` ichiga o'rab, **avtomatik** chizadi — va bu yerda, 4.1-4.2'dagi model ta'riflari, to'g'ridan-to'g'ri HTML atributlariga aylanadi: `ism = CharField(max_length=50)` → `maxlength="50" required`; `email = EmailField(unique=True)` → `type="email" required`; `telefon = CharField(max_length=20, blank=True)` → `required` **YO'Q** (chunki `blank=True`)! Bu — 4.1-darsda o'rgangan `blank=True`ning, endi **formalar darajasidagi**, haqiqiy ma'nosi: `blank=True` — aynan shu, "HTML input majburiy emas" xulqini keltirib chiqaradi.

Endi, CSRF token bilan, to'g'ri POST:

```bash
curl -b cookies.txt -c cookies.txt -d "csrfmiddlewaretoken=...&ism=Aziz&familiya=Vali&email=aziz@example.com&telefon=" http://localhost:8000/mijoz/yangi/
```
```
STATUS: 302
Location: /mijoz/muvaffaqiyat/
```

`302` — `redirect()`ning natijasi (3-bobda ko'rgan). Endi, **xuddi shu email** bilan, yana bir marta:

```
STATUS: 200
```

(302 emas!) — sahifa, qayta, **forma bilan**, xato xabari bilan qaytadi:
```html
<ul class="errorlist"><li>Mijoz with this Email already exists.</li></ul>
```

## Keng tarqalgan xatolar

**Xato 1:** View'da, `if request.method == "POST"` shartisiz, to'g'ridan-to'g'ri, har doim `MijozForm(request.POST)` yaratish.
❌
```python
def mijoz_royxatga_olish(request):
    form = MijozForm(request.POST)   # GET so'rovda, request.POST — BO'SH QueryDict!
    ...
```
GET so'rovda, `request.POST` — bo'sh (lekin `None` emas, oddiy bo'sh `QueryDict`) — shuning uchun, sahifa birinchi ochilganda ham, forma, "bog'langan" holatda, barcha maydonlar "majburiy, lekin bo'sh" xato bilan ko'rinadi.
✅ `request.method`ni albatta tekshirish — GET uchun bo'sh forma, POST uchun ma'lumot bilan bog'langan forma.

**Xato 2:** `is_valid() == False` bo'lganda ham, `redirect()`ni chaqirishga urinish yoki, aksincha, muvaffaqiyatli holatda `render()`ni qaytarish.
❌
```python
if form.is_valid():
    form.save()
render(request, "dokon/mijoz_form.html", {"form": form})   # return unutilgan!
```
Bu — Python darajasidagi xato: funksiya, hech narsa qaytarmasa (`return`siz), Django, `ValueError: The view ... didn't return an HttpResponse object` xatosini beradi.
✅ Har doim, funksiyaning **har bir yo'lida** (muvaffaqiyat ham, xato ham), aniq `return` bo'lishini tekshirish.

**Xato 3:** `{{ form.as_p }}` ichida, `<form>` tegining o'zini yoki `{% csrf_token %}`ni unutish.
❌ `{{ form.as_p }}` — faqat, **maydonlarning o'zini** chizadi (`<p>` ichida) — na `<form method="post">` tegini, na `{% csrf_token %}`ni, na "Saqlash" tugmasini avtomatik qo'shmaydi. Bularning barchasini, shablon ichida, **qo'lda** yozish kerak.
✅ To'g'ri tuzilma — har doim: `<form method="post">` → `{% csrf_token %}` → `{{ form.as_p }}` → `<button type="submit">`.

## Mashq/topshiriq

**(Oson)** `MijozForm`ga, `Meta` ichida, `widgets = {"telefon": forms.TextInput(attrs={"placeholder": "+998 90 123 45 67"})}` qo'shing. Sahifani qayta yuklab, HTML manbasida, `telefon` maydonida, endi `placeholder` atributi borligini tasdiqlang.

**(O'rtacha)** `MijozForm`ga, o'z, qo'shimcha validatsiya qoidangizni qo'shing — `email`, faqat `@gmail.com` yoki `@mail.ru` bilan tugashi kerak (misol uchun). Buning uchun, `clean_email(self)` metodini yozing:
```python
def clean_email(self):
    email = self.cleaned_data["email"]
    if not (email.endswith("@gmail.com") or email.endswith("@mail.ru")):
        raise forms.ValidationError("Faqat @gmail.com yoki @mail.ru email'lar qabul qilinadi.")
    return email
```
**Bashorat qiling:** `clean_<maydon_nomi>` nomlash qoidasi — Django uchun **tasodifiymi**, yoki bu, muayyan maydonni qanday topishi uchun **qat'iy shart**mi?

**(Qiyin)** View'ga, `form.is_valid()` **muvaffaqiyatsiz** bo'lganda, `context`ga qo'shimcha `"xatolar_soni": len(form.errors)` qo'shing va shablonda ko'rsating. Buni, ataylab, ikkita xato birdan yuzaga keladigan ma'lumot bilan sinang (masalan, `ism=""` VA `email="notogri"`). Nechta xato ko'rsatiladi — bittami, ikkitami? Nega?

<details>
<summary>Javoblarni ko'rish</summary>

1.
```python
class MijozForm(forms.ModelForm):
    class Meta:
        model = Mijoz
        fields = ["ism", "familiya", "email", "telefon"]
        widgets = {
            "telefon": forms.TextInput(attrs={"placeholder": "+998 90 123 45 67"}),
        }
```
Natijada: `<input type="text" name="telefon" placeholder="+998 90 123 45 67" maxlength="20" id="id_telefon">`. `widgets` — har bir maydonning, HTML'da **qanday input sifatida** chizilishini (va uning qo'shimcha atributlarini) boshqaradi — bu, `Meta.fields`dan farqli, "qaysi maydonlar" emas, "ular qanday ko'rinishi" haqida.

2. **Qat'iy shart, tasodifiy emas.** Django, `is_valid()` chaqirilganda, formaning har bir `clean_<maydon_nomi>` nomli metodini, **avtomatik, o'zi qidirib topadi va chaqiradi** — bu, Python'ning "nom bo'yicha avtomatik chaqirish" konvensiyasi (Django'da juda ko'p joyda uchraydigan naqsh — `get_FOO_display()`ga o'xshash). Agar metod nomini, masalan, `clean_email_manzili` deb yozsangiz (`clean_email` o'rniga) — Django, uni **hech qachon chaqirmaydi**, va sizning qo'shimcha qoidangiz, **jim, sezilmasdan e'tiborsiz qoldiriladi** — forma, validatsiyangiz umuman yo'qdek, oddiy email formatini tekshirib, `True` qaytaveradi. Bu — darslikning yana bir marta ta'kidlaydigan mavzusi: **nom konvensiyalari, Django'da ko'pincha, "sehr" emas, balki qat'iy, lekin yozma bo'lmagan shartnoma**.

3. **Ikkita xato ham ko'rsatiladi**, bittasi emas:
```python
{"ism": ["This field is required."], "email": ["Enter a valid email address."]}
```
`len(form.errors)` — `2`. Sabab: Django formalari, **birinchi xatoda to'xtamaydi** — u, har bir maydonni, **mustaqil ravishda, alohida** tekshiradi va, barcha xatolarni, bitta `is_valid()` chaqiruvida **to'plab** qaytaradi. Bu — foydalanuvchi tajribasi uchun muhim: agar forma, birinchi xatoda to'xtasa, foydalanuvchi, xatolarni **birma-bir, ko'p marta yuborib** tuzatishga majbur bo'lardi; Django esa, hammasini **bir martada** ko'rsatadi.

</details>

## Qisqacha xulosa

`ModelForm` — `models.py`dagi model ta'rifidan, to'liq HTML forma va uning validatsiya qoidalarini **avtomatik** yasaydi: `max_length`, `blank`, `unique` kabi, 4-bobda ko'rgan model cheklovlari, endi, forma darajasida ham, foydalanuvchiga tushunarli xato xabarlari sifatida ishlaydi. `is_valid()` — tekshiruvni ishga tushiradi, `cleaned_data` — faqat muvaffaqiyatli tekshiruvdan keyin mavjud bo'ladigan, "tozalangan" ma'lumot, `errors` — muvaffaqiyatsizlik sababi. View'da, GET (bo'sh forma) va POST (tekshiriladigan, saqlanadigan forma) — har doim, `request.method` orqali ajratiladi. `{% csrf_token %}` — 3-bobdagi `CsrfViewMiddleware`ning shablon tomonidagi hamkori: usiz, POST so'rov, view ishga tushishidan oldin, `403`ga uchraydi. `clean_<maydon_nomi>` — Django'ning, nom bo'yicha avtomatik chaqiradigan, qo'shimcha validatsiya konvensiyasi. Shu bilan, 06-bob (Admin va Forms'ni o'qish) yakunlandi — keyingi bo'limda, darslikning markaziy sinovi: **siz yozmagan, notanish** loyihani (`kutubxona_api`) birga "xaritalash" boshlanadi.
