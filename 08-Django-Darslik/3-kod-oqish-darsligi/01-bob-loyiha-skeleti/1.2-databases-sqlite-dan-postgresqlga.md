# 1.2. `DATABASES`ni o'qib-o'zgartirish — SQLite'dan PostgreSQL'ga o'tish

## Bu darsda nimalarni o'rganasiz

- `DATABASES` lug'atining har bir kalitini (`ENGINE`, `NAME`, `USER`...) o'qib, ma'nosini tushunasiz
- Maxfiy ma'lumotlarni (parol) kodga yozmasdan, `.env` fayli orqali **ajratish** naqshini o'rganasiz
- Loyihani PostgreSQL darsligidagi `dokon_bazasi`ga o'xshash **real PostgreSQL** bazasiga ulaysiz
- `.env` fayl yo'qolganda yoki noto'g'ri bo'lganda chiqadigan xatoni o'qib, sababini aniqlaysiz

## Nazariy qism

### `DATABASES` — standart holat

O'tgan darsda ko'rganimizdek, yangi Django loyihasida bu sozlama shunday bo'ladi:

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
    }
}
```

Buni o'qiymiz: `DATABASES` — bu **lug'at** (dictionary), va uning ichida kamida bitta kalit — `"default"` — bo'lishi shart (loyihada bir nechta baza bo'lsa, boshqa nomlar ham qo'shilishi mumkin, lekin bu — ilg'or mavzu). `"default"`ning o'zi ham lug'at: `"ENGINE"` — Django'ga **qaysi baza turi** bilan gaplashishni aytadi (`sqlite3`, `postgresql`, `mysql`, va h.k. — bu, aslida, Python modul yo'li); `"NAME"` — SQLite uchun, bu shunchaki **fayl yo'li** (`db.sqlite3` — loyiha ildizida yaratiladigan oddiy fayl).

SQLite — sinov/o'rganish uchun juda qulay (o'rnatish, alohida server kerak emas), lekin real (production) loyihalarda deyarli hech qachon ishlatilmaydi — chunki u bir vaqtning o'zida ko'p yozuv (concurrent write) va katta hajmdagi ma'lumot bilan yaxshi ishlamaydi. Shuning uchun endi, PostgreSQL darsligida chuqur o'rgangan **haqiqiy PostgreSQL**ga o'tamiz.

### Maxfiylikni kodga "qotib qolishdan" ajratish — `.env` naqshi

Eng oddiy (lekin **noto'g'ri**) yo'l — parolni to'g'ridan-to'g'ri `settings.py`ga yozish:

```python
# ❌ HECH QACHON BUNDAY QILMANG:
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": "onlayn_dokon",
        "USER": "postgres",
        "PASSWORD": "django12345",  # ochiq matn holida, Git'ga tushib qoladi!
        "HOST": "localhost",
        "PORT": "5432",
    }
}
```

Muammo: `settings.py` — odatda Git orqali GitHub'ga yuklanadigan fayl. Agar parol shu yerda **ochiq matn** holida yozilsa, u butun internetga (agar repo public bo'lsa) yoki hech bo'lmaganda loyihaning barcha ishtirokchilariga ko'rinadi. To'g'ri yechim — parolni **alohida, Git'ga qo'shilmaydigan** faylda saqlash. Loyiha ildizida `.env` nomli fayl yaratamiz:

```bash
# .env
DB_NAME=onlayn_dokon
DB_USER=postgres
DB_PASSWORD=django12345
DB_HOST=localhost
DB_PORT=5432
```

Va `python-dotenv` kutubxonasini o'rnatamiz:

```bash
pip install psycopg2-binary python-dotenv
```

`psycopg2-binary` — Django'ning PostgreSQL bilan "gaplashishi" uchun kerakli **drayver** (`ENGINE = "django.db.backends.postgresql"` ichida, sahna orqasida, aynan shu kutubxona ishlatiladi). `python-dotenv` — `.env` faylini o'qib, uning ichidagi qiymatlarni Python'ning `os.environ`iga yuklaydigan kichik yordamchi.

### `settings.py`ni o'zgartiramiz — kodni satrma-satr yozamiz

`BASE_DIR` e'lon qilingandan keyin, quyidagi ikki qatorni qo'shamiz:

```python
from dotenv import load_dotenv
import os

load_dotenv(BASE_DIR / ".env")
```

`load_dotenv(BASE_DIR / ".env")` — `.env` faylini o'qib, ichidagi har bir qatorni (`DB_NAME=onlayn_dokon` kabi) "muhit o'zgaruvchisi" (`environment variable`) sifatida joriy Python jarayoniga yuklaydi. Shundan keyin, `DATABASES`ni shunday o'zgartiramiz:

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": os.environ.get("DB_NAME"),
        "USER": os.environ.get("DB_USER"),
        "PASSWORD": os.environ.get("DB_PASSWORD"),
        "HOST": os.environ.get("DB_HOST"),
        "PORT": os.environ.get("DB_PORT"),
    }
}
```

`os.environ.get("DB_NAME")` — muhit o'zgaruvchilari orasidan `DB_NAME` nomli qiymatni **qidiradi va qaytaradi** (agar topilmasa, `None` qaytaradi — buni pastda, "xatoni o'qish" bo'limida sinaymiz). Diqqat qiling: `settings.py`ning o'zida endi **hech qanday** haqiqiy parol yoki maxfiy ma'lumot yo'q — faqat "qayerdan olish kerakligi" haqidagi **ko'rsatma**. Bu — Django loyihalarida eng keng tarqalgan, standart amaliyot.

### `.gitignore` — `.env`ni Git'dan yashirish

```
venv/
__pycache__/
*.pyc
.env
db.sqlite3
```

`.gitignore` faylidagi `.env` qatori — Git'ga, bu faylni **hech qachon** kuzatmaslikni (va tasodifan `git add .` bilan qo'shilib ketmasligini) buyuradi. Shu tufayli, har bir dasturchi (yoki server), o'zining **shaxsiy** `.env` faylini yaratadi — parollar hech qachon umumiy kodga aralashmaydi.

## Kodni o'qish mashqi

Tasavvur qiling: sizga quyidagi ikki fayl beriladi, lekin `.env` fayli **yo'q** (masalan, uni tasodifan o'chirib qo'yibsiz):

```python
# settings.py (parcha)
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": os.environ.get("DB_NAME"),
        "USER": os.environ.get("DB_USER"),
        "PASSWORD": os.environ.get("DB_PASSWORD"),
        "HOST": os.environ.get("DB_HOST"),
        "PORT": os.environ.get("DB_PORT"),
    }
}
```

**Savol:** `.env` fayli yo'q bo'lsa, `os.environ.get("DB_USER")` nima qaytaradi? Bu, keyinchalik, `python manage.py migrate` buyrug'ida qanday xatoga olib kelishi mumkin (bashorat qiling)?

<details>
<summary>Javobni ko'rish</summary>

`.env` fayli yo'q (yoki `load_dotenv` uni topolmasa) bo'lganda, `os.environ`da `DB_USER` kaliti umuman **mavjud emas**, shuning uchun `os.environ.get("DB_USER")` — `None` qaytaradi (`.get()` metodi, `[]` operatoridan farqli, kalit topilmasa xato bermaydi, shunchaki `None` beradi). `DATABASES["default"]["USER"] = None` bo'lgach, psycopg2, ulanish o'rnatayotganda, **`USER`ni butunlay ko'rsatmagandek** ishlaydi — bu holatda u, operatsion tizim darajasidagi joriy foydalanuvchi nomiga (masalan, `root`) "orqaga qaytadi" (fallback). Agar PostgreSQL'da shunday nomli rol (`role`) mavjud bo'lmasa — ulanish xatosi chiqadi. Buni pastda haqiqatan sinaymiz.

</details>

## Amaliy misol

To'liq ketma-ketlikni bajaramiz: avval baza yaratamiz, keyin `migrate`, keyin natijani PostgreSQL'ning o'zidan tekshiramiz.

```bash
sudo -u postgres psql -c "CREATE DATABASE onlayn_dokon;"
python manage.py migrate
```

```

```

Endi, Django orqali emas, PostgreSQL darsligidan tanish bo'lgan `psql` orqali, jadvallar haqiqatan yaratilganini tasdiqlaymiz:

```bash
sudo -u postgres psql -d onlayn_dokon -c "\dt"
```

Bu — juda muhim tasdiq: Django'ning `migrate` buyrug'i, aslida, **sahna orqasida**, PostgreSQL darsligida siz qo'lda yozgan `CREATE TABLE` buyruqlariga o'xshash SQL'ni **avtomatik generatsiya qilib**, PostgreSQL'ga yuboradi. `auth_user` jadvali — bu, Django'ning o'rnatilgan foydalanuvchi modeli (11-bobda batafsil); `django_migrations` — bajarilgan har bir migratsiyani "qayd qiluvchi" jadval (PostgreSQL darsligidagi 17-18-boblarda o'rgangan tushunchalarga tayanib, buni o'zingiz `SELECT * FROM django_migrations;` bilan tekshirib ko'rishingiz mumkin).

Endi, `.env` faylini vaqtincha yo'qotib, bashoratimizni tekshiramiz:

```bash
mv .env .env.zaxira
python manage.py migrate
```

```
django.db.utils.OperationalError: connection to server on socket "/var/run/postgresql/.s.PGSQL.5432" failed: FATAL:  role "root" does not exist
```

Aynan bashorat qilganimizdek: `DB_USER` topilmagani uchun, ulanish operatsion tizim foydalanuvchisi nomiga (bu holatda `root`) "orqaga qaytdi", va PostgreSQL'da bunday nomli foydalanuvchi (`role`) yo'qligi sababli, ulanish rad etildi. `.env`ni qaytarib, tuzatamiz:

```bash
mv .env.zaxira .env
python manage.py migrate
```

```
No migrations to apply.
```

## Keng tarqalgan xatolar

**Xato 1:** `.env` faylini `.gitignore`ga qo'shishni unutish.
❌ Parol, GitHub'ga (yoki boshqa umumiy joyga) tasodifan yuklanib ketadi — bu, jiddiy xavfsizlik muammosi.
✅ `.env`ni **darhol**, hatto uni yaratishdan oldin, `.gitignore`ga qo'shib qo'ying — bu odatni birinchi kundanoq shakllantiring.

**Xato 2:** `psycopg2-binary` o'rniga oddiy `psycopg2`ni o'rnatishga urinish va build xatolariga uchrash.
❌ `psycopg2` (binary qo'shimchasisiz) — kompyuteringizda PostgreSQL'ning C kutubxonalarini talab qiladi, va ular yo'q bo'lsa, o'rnatish xato bilan tugaydi.
✅ Rivojlantirish (development) muhitida har doim `psycopg2-binary`dan foydalaning — u, kerakli barcha narsani o'z ichiga olib keladi, alohida sozlash talab qilmaydi.

**Xato 3:** `os.environ.get("DB_PASSWORD")` o'rniga `os.environ["DB_PASSWORD"]` (kvadrat qavs bilan) ishlatish.
❌ Agar `.env`da `DB_PASSWORD` topilmasa, `os.environ["DB_PASSWORD"]` — `None` emas, balki **`KeyError`** xatosini tashlaydi, va bu xato, `settings.py` yuklanayotganda, butun loyihani ishga tushirishning boshida buziladi.
✅ `.get()` metodini ishlatish, xatoni "yumshoqroq" qiladi (natija `None` bo'ladi, dastur darhol qulamaydi) — garchi, ikkala holatda ham, oxir-oqibat ulanish xatosi chiqishi mumkin bo'lsa-da, `.get()` bilan xato qayerdan kelayotganini aniqlash osonroq.

## Mashq/topshiriq

**(Oson)** `.env` fayliga yangi qator qo'shing: `DB_PORT=5433` (noto'g'ri port). `python manage.py migrate`ni ishga tushirib, chiqqan xatoni o'qib, u nimani anglatishini tushuntiring. Keyin portni `5432`ga qaytaring.

**(O'rtacha)** `.env` faylidagi `DB_PASSWORD` qatorini butunlay o'chiring (qatorni o'zini o'chiring, faylni emas). `python manage.py migrate`ni ishga tushiring va chiqqan xato, shu darsda ko'rgan "`.env` butunlay yo'q" holatidan **qanday farq qilishini** aniqlang.

**(Qiyin)** `settings.py`da, `DATABASES`ning `"PORT"` qatorini butunlay olib tashlang (kalitning o'zini o'chiring, faqat qiymatini emas). `python manage.py migrate`ni ishga tushirib ko'ring — bu ishlaydimi yoki yo'qmi, va nega? (Maslahat: PostgreSQL'ning standart porti haqida PostgreSQL darsligidan eslang.)

<details>
<summary>Javoblarni ko'rish</summary>

1. Xato: `django.db.utils.OperationalError: connection to server at "localhost" (127.0.0.1), port 5433 failed: Connection refused` — chunki PostgreSQL, standart holda, faqat `5432`-portda "tinglaydi"; `5433`da hech qanday server yo'q, shuning uchun ulanish so'rovi rad etiladi.

2. Xato: `django.db.utils.OperationalError: connection to server at "localhost" (127.0.0.1), port 5432 failed: fe_sendauth: no password supplied`. `DB_USER=postgres` qatori hali ham to'g'ri o'qiladi (`USER` — to'g'ri), lekin `DB_PASSWORD` qatori umuman yo'qligi sababli, `os.environ.get("DB_PASSWORD")` — `None` qaytaradi, va psycopg2, `PASSWORD=None` bilan ulanishga uringanda, PostgreSQL serveriga hatto so'rov **yubormasdanoq**, o'zi darhol "parol berilmagan" xatosini tashlaydi (`fe_sendauth` — psycopg2'ning ichki, mijoz tomonidagi tekshiruvi). Bu, oldingi mashqdagi "butunlay `.env` yo'q" holatidan **farqli**: u yerda muammo `USER`da edi (`root` degan noto'g'ri foydalanuvchi nomiga qaytish), bu yerda esa `USER` to'g'ri (`postgres`), lekin `PASSWORD` yo'q — va xato xabarining o'zi ham buni aniq ko'rsatadi.

3. Bu ishlaydi! Chunki `"PORT"` kaliti `DATABASES`da umuman ko'rsatilmasa, Django (va psycopg2), PostgreSQL'ning **standart porti** — `5432`ni ishlatadi. Bu — PostgreSQL darsligining 0-bobida ham eslatilgan standart port bilan mos keladi, shuning uchun, agar sizning PostgreSQL serveringiz standart portda ishlab tursa, `PORT`ni umuman ko'rsatmasangiz ham hammasi ishlayveradi.

</details>

## Qisqacha xulosa

`DATABASES` — Django'ga qaysi baza bilan, qanday ma'lumotlar orqali ulanishni aytuvchi lug'at; `ENGINE` baza turini, qolgan kalitlar (`NAME`, `USER`, `PASSWORD`, `HOST`, `PORT`) — ulanish tafsilotlarini belgilaydi. Maxfiy ma'lumotlarni (parol) to'g'ridan-to'g'ri `settings.py`ga yozish o'rniga, ularni `.env` faylida saqlab, `python-dotenv` orqali `os.environ.get(...)` bilan o'qish — standart, xavfsiz amaliyot; `.env` esa har doim `.gitignore`ga qo'shilishi shart. Biz jonli ko'rganimizdek, `.env`dagi noto'g'ri yoki yo'qolgan qiymat, aniq, o'qib tushuniladigan xatoga olib keladi (`role "root" does not exist` — `USER` yo'qolganda; port xatosi — noto'g'ri `PORT`da) — bu xatolarni o'qishni o'rganish, real loyihalarda vaqtingizni soatlab tejaydi. Endi loyihamiz haqiqiy PostgreSQL'ga ulangan holda, keyingi (2-)bobda birinchi **app**imizni yaratamiz va uning ichidagi har bir faylning aniq vazifasini o'rganamiz.
