# 0.1. Standart kutubxona nima va Django uning ustiga qanday qurilgan

## Bu darsda nimalarni o'rganasiz

- Python **standart kutubxonasi** (standard library) nima ekanini va uni tashqi kutubxonalardan nima farqlashini tushunasiz
- Django kodining ichida standart kutubxona qayerlarda "yashiringan holda" ishlatilayotganini aniqlaysiz
- `python -c "import sys; print(...)"` orqali qaysi modullar standart ekanini o'zingiz tekshirishni o'rganasiz
- Bu darslikning qolgan qismi qanday qurilganini va nimaga tayyorlanish kerakligini bilib olasiz

## Nazariy qism

### Standart kutubxona nima

**Standart kutubxona** — Python bilan birga, hech qanday `pip install`siz keladigan modullar to'plami. Python'ni kompyuteringizga o'rnatganingizda, `os`, `datetime`, `json`, `re`, `logging`, `decimal`, `uuid` kabi yuzlab modul allaqachon mavjud bo'ladi. 4-qismda ko'rgan `django-environ`, `Pillow`, `Celery` — bularning barchasi **tashqi** (third-party) kutubxona: PyPI'dan yuklab olinadi, `requirements.txt`da qayd etiladi, versiyasi alohida boshqariladi. Standart kutubxona esa — Python tarqatmasining bir qismi, uning versiyasi Python versiyasiga bog'liq (masalan `zoneinfo` faqat Python 3.9dan boshlab bor).

Farqni bitta buyruq bilan ko'rish mumkin:

```python
>>> import os, django
>>> os.__file__
'/usr/lib/python3.12/os.py'          # Python o'rnatmasining ichida
>>> django.__file__
'/home/user/venv/lib/python3.12/site-packages/django/__init__.py'  # venv, pip orqali
```

`os` — Python o'rnatmasining o'zida, `django` — `site-packages` ichida, ya'ni `pip install` orqali kelgan.

### Django standart kutubxona ustiga qanday qurilgan

Django — o'zi mustaqil "sehr" emas, ko'p joyda standart kutubxona ustidan yupqa, qulay qatlam. Ba'zi misollar:

| Django imkoniyati | Ostida yotgan standart modul |
|---|---|
| `timezone.now()` | `datetime.datetime.now(tz=...)` |
| `models.TextChoices` / `IntegerChoices` | `enum.Enum` |
| `models.UUIDField` | `uuid.UUID` |
| `models.DecimalField` | `decimal.Decimal` |
| `models.JSONField` | `json.dumps` / `json.loads` |
| `LOGGING` sozlamasi | `logging` moduli (`Logger`, `Handler`, `Formatter`) |
| Parol hashlash (`make_password`) | `hashlib` (PBKDF2 ichida) |
| `RegexValidator` | `re` moduli |
| `manage.py` buyruqlari | `argparse` |

Bu jadval — butun darslikning "xaritasi". Har bir bob shu qatorlardan bittasini ochib, nafaqat Django API'sini, balki uning **ostidagi mexanizmni** ko'rsatadi. Buni bilish nima beradi? Masalan, `TextChoices` qanday ishlashini bilsangiz, `enum`ning istalgan imkoniyatini (masalan `.value`, iteratsiya) unda ham qo'llay olasiz — Django hujjatini yodlashga hojat qolmaydi, chunki asosini tushunasiz.

### Nega buni alohida o'rganish kerak

Standart kutubxonani "keyin o'rganaman" deb qoldirish odatiy xato — chunki u har doim **kod ichida yashirin** bo'ladi: hech qachon "standart kutubxona darsi" alohida ko'rinmaydi, u `views.py`, `models.py`, `management/commands/` ichida tarqoq holda uchraydi. Natijada ko'p Django dasturchisi `timezone.now()`ni ishlatadi, lekin nega u `datetime.now()`dan farq qilishini bilmaydi; `UUIDField`ni ko'radi, lekin qachon `id` o'rniga uni tanlash kerakligini bilmaydi. Bu darslik aynan shu bo'shliqni to'ldiradi.

## Amaliy misol

`onlayn_dokon` loyihasi Django shell'ida (`python manage.py shell`) Django qaysi standart modullardan foydalanib turganini o'zingiz "ushlab ko'ring":

```python
>>> from django.utils import timezone
>>> import inspect
>>> print(inspect.getsource(timezone.now))
def now():
    return datetime.now(tz=get_current_timezone() if settings.USE_TZ else None)
```

`timezone.now` funksiyasining manba kodi — ichida oddiy `datetime.now()` chaqiruvi, faqat `USE_TZ` sozlamasiga qarab vaqt zonasi (`tz`) qo'shiladi yoki qo'shilmaydi. Xuddi shu tarzda `TextChoices`ning nima ekanini tekshiramiz:

```python
>>> from django.db import models
>>> models.TextChoices.__mro__
(<enum 'TextChoices'>, <class 'str'>, <enum 'Choices'>, <enum 'Enum'>, <class 'object'>)
```

`__mro__` (Method Resolution Order) ro'yxatida `enum.Enum` borligi — `TextChoices`ning aslida standart `enum` ustiga qurilganini isbotlaydi. 02- va 04-boblarda bu ikkalasini chuqur ko'ramiz.

## Keng tarqalgan xatolar

**Xato 1:** Standart kutubxona modulini import qilish uchun `pip install` qidirish.

❌ `import datetime` xatolik bersa (masalan xato modul nomi tufayli), dasturchi "buni o'rnatish kerakmi" deb PyPI'da qidiradi.

✅ Avval `python -c "import <modul>"` bilan tekshiring — agar bu xato bermasa, modul standart va hech narsa o'rnatish shart emas; xato boshqa joyda (masalan nom xato yozilgan: `datetim`).

**Xato 2:** Django funksiyasini "qora quti" deb hisoblab, hech qachon uning manba kodiga qaramaslik.

❌ `timezone.now()` nega ba'zan `datetime.now()`dan boshqacha natija berishini tushunmasdan, xatoni tasodifiy `try/except` bilan "yopib qo'yish".

✅ `inspect.getsource()` yoki IDE'dagi "go to definition" orqali Django funksiyasining manba koduga qarash — ko'pincha bir necha qatorlik oddiy kod ekanini ko'rasiz.

**Xato 3:** Standart kutubxona versiyasi Python versiyasiga bog'liqligini unutish.

❌ `zoneinfo`dan production serverda foydalanish, lekin serverda Python 3.8 o'rnatilgan — `ModuleNotFoundError: No module named 'zoneinfo'`.

✅ Loyiha qaysi Python versiyasida ishlashini (`python --version`) va yangi modul qaysi versiyadan boshlab qo'shilganini (Python hujjatidagi "Changed in version" belgisi) doim tekshiring.

## Mashq/topshiriq

**(Oson)** `python manage.py shell`da `import json; print(json.__file__)` bajaring va natijada `site-packages` so'zi yo'qligini tasdiqlang — bu `json`ning standart kutubxona ekanini isbotlaydi.

**(O'rtacha)** `inspect.getsource(...)` yordamida Django'ning `django.utils.crypto.get_random_string` funksiyasining manba kodini toping va u qaysi standart modulga (`random` yoki `secrets`) tayanishini aniqlang.

**(Qiyin)** `onlayn_dokon` loyihangizdagi istalgan bitta `models.py` faylini oching va undagi importlarni ikki guruhga ajrating: standart kutubxona (masalan `from decimal import Decimal`) va tashqi/Django (`from django.db import models`). Nima uchun bunday ajratish import tartibini (odatda: standart → tashqi → lokal) tushunishga yordam berishini bir jumlada tushuntiring.

## Qisqacha xulosa

Standart kutubxona — Python bilan birga keladigan, `pip install` talab qilmaydigan modullar to'plami, va Django ko'p joyda aynan shu modullar ustiga qurilgan: `timezone.now()` — `datetime` ustidan, `TextChoices` — `enum` ustidan, parol hashlash — `hashlib` ustidan. Bu darslik davomida siz Django'da kundalik ishlatadigan har bir imkoniyatning "ostiga" tushib, uni ishlatuvchi standart modulni alohida o'rganasiz — bu nafaqat Django'ni chuqurroq tushunishga, balki tashqi kutubxonasiz ko'proq vazifani yechishga yordam beradi. Keyingi darsda — loyiha qaysi muhitda (qaysi Python versiyasi, qaysi operatsion tizim) ishlab turganini `sys` va `platform` yordamida qanday bilib olishni ko'ramiz.
