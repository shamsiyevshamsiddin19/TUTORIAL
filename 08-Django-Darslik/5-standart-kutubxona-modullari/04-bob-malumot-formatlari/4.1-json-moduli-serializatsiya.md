# 4.1. `json` moduli — `JSONField`, API javoblarini qo'lda serializatsiya qilish

## Bu darsda nimalarni o'rganasiz

- `json.dumps()` va `json.loads()` bilan Python obyektlarini JSON matniga va aksincha aylantirishni o'rganasiz
- Python va JSON turlari orasidagi mosliklar va nomosliklarni (masalan `Decimal`, `datetime`) bilib olasiz
- Django'ning `JSONField`i va `JsonResponse`i ostida `json` moduli qanday ishlatilishini tushunasiz
- O'z maxsus obyektingizni (masalan `Decimal`) JSON'ga aylantiruvchi maxsus encoder yoza olasiz

## Nazariy qism

### `json.dumps` va `json.loads`

`json` moduli Python obyektlari bilan JSON matni (string) orasida aylantirish qiladi:

```python
import json

malumot = {"nomi": "Krossovka", "narxi": 450000, "mavjud": True, "ranglari": ["qora", "oq"]}

matn = json.dumps(malumot)
print(matn)          # '{"nomi": "Krossovka", "narxi": 450000, "mavjud": true, "ranglari": ["qora", "oq"]}'
print(type(matn))    # <class 'str'>

qayta = json.loads(matn)
print(qayta)          # {'nomi': 'Krossovka', 'narxi': 450000, 'mavjud': True, 'ranglari': ['qora', 'oq']}
```

`dumps` (dump string) — Python obyektini JSON matniga "tashlaydi"; `loads` (load string) — JSON matnidan Python obyektini "yuklaydi". Fayl bilan ishlash uchun `json.dump(obj, fayl)` va `json.load(fayl)` (`s`siz) versiyalari ham bor — ular to'g'ridan-to'g'ri fayl obyekti bilan ishlaydi.

### Python va JSON turlari mosligi

| Python | JSON |
|---|---|
| `dict` | object (`{...}`) |
| `list`, `tuple` | array (`[...]`) |
| `str` | string |
| `int`, `float` | number |
| `True` / `False` | `true` / `false` |
| `None` | `null` |

Muhim: JSON'da **sana, `Decimal`, `set` kabi turlar yo'q**. `json.dumps()` bunday obyektni uchratsa, `TypeError: Object of type Decimal is not JSON serializable` beradi:

```python
>>> from decimal import Decimal
>>> json.dumps({"narx": Decimal("450000.00")})
TypeError: Object of type Decimal is not JSON serializable
```

### O'z encoder yozish

Bunday holatda, Python obyektini JSON'ga "qanday aylantirish kerakligini" ko'rsatuvchi maxsus **encoder** yozish mumkin:

```python
import json
from decimal import Decimal


class DjangoUslubidagiEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, Decimal):
            return str(obj)
        return super().default(obj)


json.dumps({"narx": Decimal("450000.00")}, cls=DjangoUslubidagiEncoder)
# '{"narx": "450000.00"}'
```

Aynan shu g'oya — Django'ning o'zining `DjangoJSONEncoder` klassida ishlatilgan (`django.core.serializers.json.DjangoJSONEncoder`), u `Decimal`, `datetime`, `UUID` kabi turlarni avtomatik to'g'ri aylantiradi.

### Django'da `JSONField` va `JsonResponse`

`JSONField` — modelda tuzilishi oldindan qat'iy belgilanmagan ma'lumotni (masalan mahsulotning turli xil bo'lishi mumkin bo'lgan xususiyatlari: o'lcham, rang, material) saqlash uchun ishlatiladi:

```python
from django.db import models


class Mahsulot(models.Model):
    nomi = models.CharField(max_length=200)
    xususiyatlari = models.JSONField(default=dict, blank=True)
    # masalan: {"olcham": "42", "rang": "qora", "material": "charm"}
```

Django bu maydonni saqlashda `json.dumps()`ga, o'qishda `json.loads()`ga o'xshash mexanizmdan foydalanadi (aslida `DjangoJSONEncoder`), shuning uchun Python `dict`/`list` sifatida to'g'ridan-to'g'ri ishlatish mumkin — qo'lda `json.dumps`/`loads` chaqirish shart emas.

API javob qaytarishda esa `JsonResponse` ichida ham `json.dumps` ishlatiladi:

```python
from django.http import JsonResponse


def mahsulot_json(request, mahsulot_id):
    mahsulot = Mahsulot.objects.get(id=mahsulot_id)
    return JsonResponse({
        "nomi": mahsulot.nomi,
        "narxi": str(mahsulot.narxi),   # Decimal -> str, chunki JsonResponse standart json.JSONEncoder ishlatadi
        "xususiyatlari": mahsulot.xususiyatlari,
    })
```

## Amaliy misol

`onlayn_dokon`da tashqi to'lov tizimidan (masalan Payme/Click) kelgan **webhook** so'rovini qo'lda tahlil qilamiz — bu holatda DRF yoki Django formalari emas, xom JSON matnni to'g'ridan-to'g'ri `json` moduli bilan o'qish kerak bo'ladi:

```python
# apps/tolovlar/views.py
import json
import logging

from django.http import HttpResponse, JsonResponse
from django.views.decorators.csrf import csrf_exempt

from apps.buyurtmalar.models import Buyurtma

logger = logging.getLogger(__name__)


@csrf_exempt
def tolov_webhook(request):
    try:
        malumot = json.loads(request.body)
    except json.JSONDecodeError:
        logger.warning("Tolov webhook: JSON o'qib bo'lmadi, request.body=%r", request.body[:200])
        return HttpResponse(status=400)

    buyurtma_uuid = malumot.get("buyurtma_id")
    holat = malumot.get("holat")

    if not buyurtma_uuid or not holat:
        return JsonResponse({"xato": "buyurtma_id yoki holat yetishmayapti"}, status=400)

    try:
        buyurtma = Buyurtma.objects.get(tashqi_id=buyurtma_uuid)
    except Buyurtma.DoesNotExist:
        return JsonResponse({"xato": "Bunday buyurtma topilmadi"}, status=404)

    if holat == "tolandi":
        buyurtma.tolov_holati = "tolandi"
        buyurtma.save(update_fields=["tolov_holati"])

    return JsonResponse({"natija": "ok"})
```

`request.body` — HTTP so'rovning xom (bytes) tanasi; `json.loads()` uni to'g'ridan-to'g'ri (bytes ham, str ham) qabul qiladi. Bu yerda `json.loads()`ni `try/except json.JSONDecodeError` bilan o'rash muhim — tashqi tizimdan kelgan ma'lumotga hech qachan ishonib bo'lmaydi, u har doim buzilgan yoki bo'sh bo'lishi mumkin.

## Keng tarqalgan xatolar

**Xato 1:** `json.loads()`ni xatoni ushlamasdan chaqirish.

❌ `malumot = json.loads(request.body)` — agar tashqi tizim bo'sh body yoki noto'g'ri formatdagi matn yuborsa, `json.JSONDecodeError` chiqadi va agar bu `try/except` bilan ushlanmasa, foydalanuvchiga (yoki webhook yuboruvchi tashqi xizmatga) `500 Internal Server Error` qaytadi — bu diagnostikasi qiyin muammo.

✅ Tashqaridan kelgan JSON'ni har doim `try/except json.JSONDecodeError` bilan o'rang va aniq `400 Bad Request` qaytaring (yuqoridagi amaliy misoldagi kabi).

**Xato 2:** `Decimal` yoki `datetime`ni to'g'ridan-to'g'ri `json.dumps()`ga uzatish.

❌ `json.dumps({"narx": mahsulot.narxi})` — `mahsulot.narxi` `Decimal` bo'lgani uchun `TypeError` beradi.

✅ Yoki qo'lda `str()`ga aylantiring (`str(mahsulot.narxi)`), yoki Django'ning `DjangoJSONEncoder`idan foydalaning: `json.dumps({"narx": mahsulot.narxi}, cls=DjangoJSONEncoder)` (`django.core.serializers.json.DjangoJSONEncoder`) — bu `Decimal`, `datetime`, `UUID`larni avtomatik to'g'ri aylantiradi.

**Xato 3:** `json.dumps()`ning natijasini formatlashsiz, tushunarsiz holda log yoki fayl sifatida saqlash.

❌ Katta, ichma-ich `dict`ni `json.dumps(malumot)` bilan bitta uzun qatorga yozib, keyin uni qo'lda o'qishga urinish — juda noqulay.

✅ O'qish/debug uchun `json.dumps(malumot, indent=2, ensure_ascii=False)` ishlating — `indent=2` chiroyli formatlaydi, `ensure_ascii=False` esa ASCII bo'lmagan harflarni `\uXXXX` kabi kodlar o'rniga to'g'ridan-to'g'ri (o'qiladigan holda) chiqaradi.

## Mashq/topshiriq

**(Oson)** `json.dumps({"tavsif": "Narx — 120 000 so'm"}, ensure_ascii=False)` va `ensure_ascii=True` (standart) bilan natijalarni solishtirib, `—` (em dash) belgisi ikkalasida qanday ko'rinishini solishtiring.

**(O'rtacha)** `Mahsulot.xususiyatlari` (`JSONField`) ichiga `{"olcham": "42", "rang": "qora"}` kabi ma'lumot saqlangan mahsulotlarni, `xususiyatlari__rang="qora"` filtri bilan (Django JSONField ichki qidiruvi) topuvchi so'rov yozing.

**(Qiyin)** `tolov_webhook` view'iga qo'shimcha xavfsizlik qatlami qo'shing: webhook so'rovi header'ida kelgan `X-Webhook-Signature`ni (`request.headers.get(...)`) va `json.dumps(malumot, sort_keys=True)` natijasidan `hmac`/`hashlib` bilan hisoblangan imzoni solishtirib, mos kelmasa `403` qaytaring (`sort_keys=True` nega kerakligini — imzo hisoblashda kalitlar tartibi har doim bir xil bo'lishi kerakligini — bir jumlada tushuntiring).

1.
```python
>>> json.dumps({"tavsif": "Narx — 120 000 so'm"}, ensure_ascii=False)
'{"tavsif": "Narx — 120 000 so\'m"}'
>>> json.dumps({"tavsif": "Narx — 120 000 so'm"})
'{"tavsif": "Narx \\u2014 120 000 so\'m"}'
```
`ensure_ascii=True` (standart) — ASCII bo'lmagan har bir belgini (bu yerda em dash) `\u`-bilan boshlanadigan escape-kodga aylantiradi; `ensure_ascii=False` — belgini o'zgarishsiz, o'qiladigan holda qoldiradi. Log yoki debug uchun `False` qulayroq.

2.
```python
Mahsulot.objects.filter(xususiyatlari__rang="qora")
```
Django JSONField ichidagi kalitlarga `__` (double underscore) orqali to'g'ridan-to'g'ri murojaat qilish mumkin — bu ORM darajasida `json` qidiruv operatorlariga aylanadi.

3.
```python
import hashlib
import hmac
import json

SIRLI_KALIT = b"tolov-tizimi-bilan-kelishilgan-maxfiy-kalit"


def imzoni_tekshir(malumot: dict, kelgan_imzo: str) -> bool:
    matn = json.dumps(malumot, sort_keys=True).encode()
    kutilgan_imzo = hmac.new(SIRLI_KALIT, matn, hashlib.sha256).hexdigest()
    return hmac.compare_digest(kutilgan_imzo, kelgan_imzo)
```
`sort_keys=True` shart, chunki `dict`dagi kalitlar tartibi (odatda) qo'shilish tartibiga bog'liq — agar imzo hisoblovchi va tekshiruvchi tomon boshqa-boshqa tartibda serializatsiya qilsa, bir xil ma'lumot uchun boshqa-boshqa matn (demak boshqa-boshqa imzo) hosil bo'lib, tekshiruv doim muvaffaqiyatsiz chiqadi.

## Qisqacha xulosa

`json` moduli Python obyektlarini (`dict`, `list`, `str`, son, `bool`, `None`) JSON matniga (`dumps`) va aksincha (`loads`) aylantiradi, lekin `Decimal`, `datetime`, `UUID` kabi turlarni to'g'ridan-to'g'ri qo'llab-quvvatlamaydi — bularni yo qo'lda `str()`ga aylantirish, yo Django'ning `DjangoJSONEncoder`idan foydalanish kerak. Django'ning `JSONField`i va `JsonResponse`i ichida aynan shu mexanizm ishlaydi, lekin tashqi tizimdan (masalan to'lov webhook) kelgan xom JSON bilan ishlaganda, `json.loads()`ni har doim `try/except json.JSONDecodeError` bilan himoyalash kerak — chunki tashqi ma'lumotga hech qachan ishonib bo'lmaydi. Keyingi darsda — CSV eksport va `TextChoices` ostidagi `enum` moduli bilan tanishamiz.
