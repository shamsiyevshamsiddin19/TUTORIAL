# 3.1. `re` moduli — validatorlar, `RegexValidator` ichida nima ishlaydi

## Bu darsda nimalarni o'rganasiz

- Muntazam ifodalar (regular expressions) yordamida matn naqshlarini tekshirishni o'rganasiz
- `re.match()`, `re.search()` va `re.fullmatch()` orasidagi farqni tushunasiz
- Django'ning `RegexValidator` va o'rnatilgan validatorlari (`URLValidator`, `EmailValidator`) ostida `re` qanday ishlashini bilib olasiz
- Real vazifa — mahsulot artikuli (SKU) va telefon raqamini tekshiruvchi o'z validatoringizni yozasiz

## Nazariy qism

### Muntazam ifoda (regex) nima

**Regex** — matn ichida naqsh (pattern) qidirish uchun mini-til. Masalan, "faqat katta harflar va raqamlardan iborat, 6-10 belgili" degan qoidani oddiy `if` bilan yozish uzun va xatoga moyil bo'ladi, regex bilan esa bir qatorda ifodalanadi:

```python
import re

naqsh = r"^[A-Z0-9]{6,10}$"
print(bool(re.match(naqsh, "SKU12345")))   # True
print(bool(re.match(naqsh, "sku123")))     # False (kichik harf bor)
```

Eng ko'p ishlatiladigan belgilar:

| Belgi | Ma'nosi |
|---|---|
| `^` / `$` | Qator boshi / oxiri |
| `\d` | Istalgan raqam (`[0-9]`) |
| `\w` | Harf, raqam yoki pastki chiziq |
| `+` | 1 yoki undan ko'p marta |
| `*` | 0 yoki undan ko'p marta |
| `{6,10}` | 6 dan 10 tagacha marta |
| `[A-Z]` | A dan Z gacha istalgan harf |
| `\s` | Bo'sh joy (probel, tab) |

`r"..."` — "raw string" (xom satr): regex ichida `\d`, `\w` kabi teskari chiziqli belgilar ko'p uchraydi, `r` prefiksi Python'ga ularni maxsus belgi (masalan `\n` — yangi qator) deb emas, aynan yozilganidek o'qishni buyuradi. Regex yozganda `r"..."`ni deyarli har doim ishlatish kerak.

### `match`, `search`, `fullmatch` — farqi

```python
matn = "Buyurtma raqami: SKU12345"

re.match(r"SKU\d+", matn)       # None — match faqat QATOR BOSHIDAN qidiradi
re.search(r"SKU\d+", matn)      # topadi — search QATOR ICHIDAN istalgan joyda qidiradi
re.fullmatch(r"SKU\d+", "SKU12345")  # topadi — fullmatch BUTUN qatorga mos kelishini talab qiladi
```

Validatsiya uchun (masalan "bu butun maydon to'g'ri formatdami") odatda **`fullmatch`** yoki `^`/`$` bilan o'ralgan `match` ishlatiladi — chunki `search` faqat naqsh qayerdadir uchrashini tekshiradi, butun qatorni emas.

### Django'da `RegexValidator`

Django modellar va formalar uchun tayyor validatorlar beradi, ularning aksariyati ichida aynan `re` ishlaydi:

```python
from django.core.validators import RegexValidator

telefon_validatori = RegexValidator(
    regex=r"^\+998\d{9}$",
    message="Telefon raqam +998XXXXXXXXX formatida bo'lishi kerak",
)
```

`RegexValidator.__call__` ichida (soddalashtirilgan holda) shunga o'xshash kod bor:

```python
def __call__(self, value):
    if not re.search(self.regex, str(value)):
        raise ValidationError(self.message)
```

`EmailValidator`, `URLValidator` kabi Django'ning o'rnatilgan validatorlari ham — tub-tubida aynan shu `re` moduliga tayanadi, faqat murakkabroq, ko'p holatni (masalan xalqaro domenlar) qamrab oluvchi tayyor naqshlar bilan.

## Amaliy misol

`onlayn_dokon`da `Mahsulot` modeliga, artikul (SKU) formatini tekshiruvchi validator qo'shamiz — format: 3 ta katta harf, tire, 4-6 ta raqam (masalan `SHM-12345`):

```python
# apps/mahsulotlar/validators.py
import re

from django.core.exceptions import ValidationError

SKU_NAQSHI = re.compile(r"^[A-Z]{3}-\d{4,6}$")


def sku_formatini_tekshir(qiymat: str) -> None:
    if not SKU_NAQSHI.fullmatch(qiymat):
        raise ValidationError(
            f"'{qiymat}' — noto'g'ri SKU format. To'g'ri format: SHM-12345 "
            "(3 katta harf, tire, 4-6 raqam)"
        )
```

`re.compile()` — naqshni oldindan "kompilyatsiya" qiladi va qayta ishlatishda tezroq ishlaydi; naqsh bir necha marta chaqirilsa (masalan har bir modelni saqlashda), buni modul darajasida bir marta `compile` qilib, keyin `.fullmatch()`/`.match()` chaqirish yaxshi amaliyot.

```python
# apps/mahsulotlar/models.py
from django.db import models

from .validators import sku_formatini_tekshir


class Mahsulot(models.Model):
    nomi = models.CharField(max_length=200)
    sku = models.CharField(max_length=12, unique=True, validators=[sku_formatini_tekshir])
    narxi = models.DecimalField(max_digits=10, decimal_places=2)
```

Shell'da sinaymiz:

```python
>>> from apps.mahsulotlar.models import Mahsulot
>>> m = Mahsulot(nomi="Krossovka", sku="shm-123", narxi="450000")
>>> m.full_clean()
ValidationError: {'sku': ["'shm-123' — noto'g'ri SKU format. ..."]}
>>> m.sku = "SHM-12345"
>>> m.full_clean()   # xato bermaydi
```

## Keng tarqalgan xatolar

**Xato 1:** `r` prefiksisiz regex yozish.

❌ `re.match("\d+", "123")` — bu ko'pincha ishlaydi, lekin ba'zi kombinatsiyalarda (masalan `"\b"` — so'z chegarasi) `DeprecationWarning` yoki kutilmagan natija beradi, chunki Python avval `\d`, `\b`ni o'zining escape-belgisi sifatida talqin qilishga urinadi.

✅ Har doim `r"..."` (raw string) yozing: `re.match(r"\d+", "123")` — bu odat sifatida shakllantirilishi kerak, hech qachon istisno qilmang.

**Xato 2:** `match()` butun qatorni tekshiradi deb noto'g'ri o'ylash.

❌ `re.match(r"\d+", "123abc")` — bu `None` emas, **muvaffaqiyatli moslik** qaytaradi (`"123"` qismini topadi), chunki `match` faqat boshidan mos kelishini talab qiladi, oxirigacha emas — natijada `"123abc"` kabi noto'g'ri qiymat "to'g'ri" deb qabul qilinishi mumkin.

✅ Butun qator naqshga mos kelishini talab qilish uchun `re.fullmatch(r"\d+", "123abc")` (bu holda `None` qaytaradi) yoki naqshni `^...$` bilan o'rang: `re.match(r"^\d+$", "123abc")`.

**Xato 3:** Har bir chaqiruvda regex naqshini qayta yaratish (unumdorlik muammosi).

❌ Funksiya ichida `re.match(r"^[A-Z]{3}-\d{4,6}$", qiymat)` — har safar funksiya chaqirilganda Python naqshni qaytadan tahlil qiladi; ko'p sonli obyektni (masalan 10 000 ta mahsulotni) tekshirishda bu sezilarli sekinlashuvga olib kelishi mumkin.

✅ Naqshni modul darajasida bir marta `re.compile()` qiling (yuqoridagi amaliy misoldagi `SKU_NAQSHI` kabi) va keyin faqat `.fullmatch()`/`.match()` chaqiring — natija bir xil, lekin tezroq.

## Mashq/topshiriq

**(Oson)** `re.fullmatch(r"^\+998\d{9}$", "+998901234567")` va `re.fullmatch(r"^\+998\d{9}$", "998901234567")` (birinchisida `+` bor, ikkinchisida yo'q) natijalarini solishtirib, nega ikkinchisi `None` qaytarishini tushuntiring.

**(O'rtacha)** `sku_formatini_tekshir` validatoriga qo'shimcha talab qo'shing: tiredan keyingi raqamlar `0` bilan boshlanmasin (masalan `SHM-0123` noto'g'ri, `SHM-1230` to'g'ri). Naqshni shunga mos yangilang.

**(Qiyin)** `onlayn_dokon`da mijoz izohi (`Buyurtma.izoh` maydoni) ichidan barcha telefon raqamlarini (`+998` bilan boshlanuvchi, 9 ta raqamli) topib, ro'yxat qilib qaytaruvchi funksiya yozing — `re.findall()`dan foydalaning (bu darsda ko'rilmagan, hujjatdan o'qib chiqing: u `search`dan farqli, **barcha** moslarni ro'yxat qilib qaytaradi).

## Qisqacha xulosa

`re` moduli — matnni belgilangan naqshga mos kelish-kelmasligini tekshirish yoki naqshga mos qismlarni topish uchun ishlatiladi; `re.compile()` bilan naqshni oldindan tayyorlab, keyin `.match()` (boshidan), `.search()` (istalgan joyda) yoki `.fullmatch()` (butun qator) chaqiriladi. Django'ning `RegexValidator`, `EmailValidator`, `URLValidator` kabi o'rnatilgan validatorlari tub-tubida aynan shu `re` moduliga tayanadi — o'z maxsus formatingiz (masalan SKU, telefon raqam) bo'lsa, xuddi shu usulda o'z `RegexValidator`ingizni yoki funksiya-validatorni yozishingiz mumkin. Keyingi darsda — pul miqdorlarini aniq hisoblash (`decimal`) va noyob identifikatorlar (`uuid`) bilan tanishamiz.
