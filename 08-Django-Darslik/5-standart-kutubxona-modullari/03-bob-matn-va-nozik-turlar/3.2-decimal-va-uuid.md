# 3.2. `decimal` va `uuid` — pul miqdorlarini aniq hisoblash, noyob identifikatorlar

## Bu darsda nimalarni o'rganasiz

- Nega pul miqdorlari uchun `float` emas, `decimal.Decimal` ishlatilishini tushunasiz
- `Decimal` ustida arifmetik amallar va dumaloqlashni (rounding) to'g'ri bajarishni o'rganasiz
- `uuid.uuid4()` bilan noyob identifikator yaratishni va `id` (auto-increment) o'rniga qachon ishlatilishini bilib olasiz
- Django'ning `DecimalField` va `UUIDField` bu ikki modulga qanday tayanishini ko'rasiz

## Nazariy qism

### Nega `float` pul uchun xavfli

Kompyuterlar `float` (o'nlik kasr) sonlarni ikkilik (binary) tizimda saqlaydi, va ko'p o'nlik kasrlar (masalan `0.1`) ikkilik tizimda **aniq** ifodalanmaydi — taxminiy qiymat saqlanadi. Bu odatiy hisoblarda sezilmasligi mumkin, lekin pul bilan ishlaganda jiddiy xatolarga olib keladi:

```python
>>> 0.1 + 0.2
0.30000000000000004
>>> 450000 * 1.15   # 15% ustama qo'shish
517500.0000000001
```

Agar `onlayn_dokon`da narxlar shunday hisoblansa, ko'p yillik yig'indi kichik-kichik xatolar tufayli sezilarli darajada noto'g'ri chiqishi mumkin — bu moliyaviy hisobotda jiddiy muammo.

### `decimal.Decimal` — aniq o'nlik arifmetika

`decimal` moduli sonlarni ikkilik emas, **o'nlik** (inson hisoblagandagidek) tizimda saqlaydi — natijada `0.1 + 0.2` aynan `0.3` bo'ladi:

```python
from decimal import Decimal

narx = Decimal("450000")
ustama = Decimal("1.15")
print(narx * ustama)   # 517500.00
```

**Muhim qoida:** `Decimal` yaratganda son emas, **string** uzatiladi: `Decimal("450000")`, `Decimal("0.1")`. Agar `Decimal(0.1)` (float bilan) yozilsa, `float`ning o'zidagi noaniqlik allaqachon ichkariga kirib bo'lgan bo'ladi:

```python
>>> Decimal("0.1")
Decimal('0.1')
>>> Decimal(0.1)
Decimal('0.1000000000000000055511151231257827021181583404541015625')
```

### Django'da `DecimalField`

```python
narxi = models.DecimalField(max_digits=10, decimal_places=2)
```

`max_digits=10` — jami raqamlar soni (butun va kasr qism birga), `decimal_places=2` — kasr qismidagi raqamlar soni (tiyin darajasigacha). Django bu maydonni Python'da avtomatik `Decimal` obyekti sifatida qaytaradi:

```python
>>> mahsulot.narxi
Decimal('450000.00')
>>> type(mahsulot.narxi)
<class 'decimal.Decimal'>
```

Shuning uchun `Mahsulot.objects.first().narxi * 1.15` yozish xato: `Decimal` bilan `float`ni ko'paytirish `TypeError: unsupported operand type(s)` beradi — Python ataylab bu ikkisini aralashtirishga yo'l qo'ymaydi, chunki natija noaniq bo'lib qolishi mumkin.

### `uuid` — noyob identifikator

Standart Django modeli `id`si — avtomatik oshib boruvchi son (`1, 2, 3, ...`). Bu ko'p holatda yetarli, lekin ba'zan muammo tug'diradi: agar `id` URL'da ko'rinsa (`/buyurtma/145/`), raqobatchi yoki tashqi odam "145dan oldin nechta buyurtma bo'lgan" degan ma'lumotni taxmin qila oladi, va ketma-ket raqamlarni "sanab" boshqa buyurtmalarni topishga urinishi mumkin.

`uuid.uuid4()` — 128 bitli, deyarli takrorlanmaydigan tasodifiy identifikator yaratadi:

```python
import uuid

print(uuid.uuid4())   # 3fa85f64-5717-4562-b3fc-2c963f66afa6
```

Bu qiymatni taxmin qilish amalda imkonsiz (2^122 xil variant), shuning uchun URL'da yoki tashqi API'da xavfsiz ko'rsatish mumkin. Django'da:

```python
buyurtma_id = models.UUIDField(default=uuid.uuid4, editable=False, unique=True)
```

**Muhim:** `default=uuid.uuid4` — qavssiz yozilishi kerak (funksiyaning o'zi, natijasi emas), chunki Django har bir yangi obyekt yaratilganda bu funksiyani **o'zi chaqiradi**. Agar `default=uuid.uuid4()` (qavs bilan) yozilsa, funksiya bir marta, modul yuklanganda chaqiriladi, va **barcha** yangi obyektlar bitta xil UUID oladi — bu jiddiy xato.

## Amaliy misol

`onlayn_dokon`da `Buyurtma` modeliga ikkita o'zgarish kiritamiz: narxni `Decimal` bilan to'g'ri hisoblaymiz, va tashqi (mijozga ko'rsatiladigan) identifikator sifatida UUID qo'shamiz:

```python
# apps/buyurtmalar/models.py
import uuid
from decimal import Decimal

from django.db import models


class Buyurtma(models.Model):
    id = models.BigAutoField(primary_key=True)          # ichki, tezkor bog'lanishlar uchun
    tashqi_id = models.UUIDField(
        default=uuid.uuid4, editable=False, unique=True
    )                                                      # URL/API uchun, taxmin qilib bo'lmaydigan
    umumiy_summa = models.DecimalField(max_digits=12, decimal_places=2, default=Decimal("0.00"))

    def summani_hisobla(self):
        jami = sum(
            (element.narx * element.miqdor for element in self.elementlar.all()),
            start=Decimal("0.00"),
        )
        self.umumiy_summa = jami
        self.save(update_fields=["umumiy_summa"])
```

`urls.py`da ichki `id` o'rniga `tashqi_id` (UUID) ishlatamiz:

```python
# apps/buyurtmalar/urls.py
from django.urls import path

from . import views

urlpatterns = [
    path("buyurtma/<uuid:tashqi_id>/", views.buyurtma_batafsil, name="buyurtma-batafsil"),
]
```

```python
# apps/buyurtmalar/views.py
from django.shortcuts import get_object_or_404, render

from .models import Buyurtma


def buyurtma_batafsil(request, tashqi_id):
    buyurtma = get_object_or_404(Buyurtma, tashqi_id=tashqi_id)
    return render(request, "buyurtmalar/batafsil.html", {"buyurtma": buyurtma})
```

Natijada URL `/buyurtma/3fa85f64-5717-4562-b3fc-2c963f66afa6/` kabi ko'rinadi — `/buyurtma/145/` kabi ketma-ket raqamdan farqli, boshqa buyurtmalarni "sanab topish" imkonsiz, va Django `<uuid:...>` yo'l konvertori orqali UUID formatini avtomatik tekshiradi (noto'g'ri format bo'lsa, 404 qaytaradi).

## Keng tarqalgan xatolar

**Xato 1:** `Decimal`ni `float` bilan aralashtirib ishlatish.

❌ `narx = Decimal("450000") * 1.15` (`1.15` — oddiy float) — `TypeError: unsupported operand type(s) for *: 'decimal.Decimal' and 'float'` beradi.

✅ Ikkalasini ham `Decimal` qiling: `Decimal("450000") * Decimal("1.15")`. Agar qiymat foydalanuvchi kiritgan formadan kelsa (odatda string), `Decimal(request.POST["narx"])` to'g'ridan-to'g'ri ishlaydi — chunki string qabul qilinadi.

**Xato 2:** `default=uuid.uuid4()` — funksiyani qavs bilan chaqirib qo'yish.

❌ `tashqi_id = models.UUIDField(default=uuid.uuid4())` — bu holda `uuid.uuid4()` migratsiya yaratilganda **bir marta** ishlaydi, va shu bitta UUID qiymati barcha keyingi obyektlarga standart sifatida beriladi — bu `unique=True` bilan birga darhol `IntegrityError`ga olib keladi (ikkinchi obyekt saqlanganda, chunki UUID takrorlanadi).

✅ Har doim qavssiz: `default=uuid.uuid4` — Django funksiyaning o'zini saqlab qo'yadi va har bir yangi obyekt uchun **qayta chaqiradi**.

**Xato 3:** `UUIDField`ni asosiy kalit (`primary_key=True`) sifatida hech o'ylab ko'rmasdan ishlatish.

❌ Katta jadvalda (masalan millionlab qatorli `Buyurtma`) `primary_key=True, default=uuid.uuid4` — UUID tasodifiy tartibda joylashgani uchun, ma'lumotlar bazasining indeksi (B-tree) doim "tartibsiz joyga" yozishga majbur bo'ladi, bu katta hajmda avtomatik oshib boruvchi `id`ga nisbatan sezilarli sekinroq bo'lishi mumkin.

✅ Ko'p hollarda eng yaxshi kombinatsiya — ichki, tezkor `id` (`BigAutoField`, jadval ichidagi bog'lanishlar uchun) + tashqi ko'rinadigan `UUIDField` (URL/API uchun, yuqoridagi amaliy misoldagi kabi) — ikkalasining afzalligini birlashtiradi.

## Mashq/topshiriq

**(Oson)** Shell'da `from decimal import Decimal; print(Decimal("100") / Decimal("3"))` bajaring va natijada nechta raqam ko'rsatilganini kuzating — standart aniqlik (`decimal.getcontext().prec`) nechaga tengligini toping.

**(O'rtacha)** `BuyurtmaElementi` modeliga `jami_narx()` metodini qo'shing — u `self.narx * self.miqdor` (miqdor — `PositiveIntegerField`) ni `Decimal` sifatida qaytarsin, va agar `miqdor` 0 bo'lsa, `Decimal("0.00")` qaytarsin (nolga bo'lish xatosidan ehtiyot bo'lish shart emas, chunki bu ko'paytirish, lekin mantiqiy tekshiruv sifatida).

**(Qiyin)** `onlayn_dokon`da mijoz o'zining eski (raqamli `id` bilan yozilgan) buyurtma havolasini ochsa (masalan eski `/buyurtma/145/`), uni yangi UUID-asosidagi URL'ga (`/buyurtma/<uuid>/`) muvofiq yo'naltiruvchi (`redirect`) view yozing — buning uchun `Buyurtma`da eski `id`ni ham saqlashda davom eting va `get_object_or_404(Buyurtma, id=eski_id)` orqali topib, `redirect("buyurtma-batafsil", tashqi_id=buyurtma.tashqi_id)` qiling.

## Qisqacha xulosa

`decimal.Decimal` — pul kabi aniqlik talab qiladigan hisob-kitoblar uchun ishlatiladi, chunki `float`dan farqli, o'nlik kasrlarni aniq (yumaloqlash xatosiz) saqlaydi — har doim string bilan yaratilishi kerak (`Decimal("450000")`, `Decimal(450000)` emas). `uuid.uuid4()` — taxmin qilib bo'lmaydigan noyob identifikator yaratadi va odatda tashqi ko'rinadigan (URL, API) identifikator sifatida, ichki tezkor `id`ga qo'shimcha ravishda ishlatiladi. Django'ning `DecimalField` va `UUIDField`lari — aynan shu ikki standart modulning ustidan qulay qatlam. Keyingi bobda — ma'lumotlarni formatlash: `json` va CSV eksport, hamda `TextChoices` ostidagi `enum`ni ko'ramiz.
