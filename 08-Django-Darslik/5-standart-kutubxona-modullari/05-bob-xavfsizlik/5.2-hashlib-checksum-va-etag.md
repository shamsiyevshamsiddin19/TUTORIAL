# 5.2. `hashlib` — fayl checksum, ETag, parol hashlashning ichki mexanizmi

## Bu darsda nimalarni o'rganasiz

- Hash funksiyasi nima ekanini va uni shifrlashdan (encryption) nima farqlashini tushunasiz
- `hashlib.sha256()` bilan fayl va matn uchun checksum hisoblashni o'rganasiz
- Django'ning parol hashlash mexanizmi (`make_password`) ostida `hashlib` qanday ishlatilishini bilib olasiz
- Katta faylni xotiraga to'liq yuklamasdan, bo'lak-bo'lak (chunk) hash qilishni o'rganasiz

## Nazariy qism

### Hash funksiyasi nima

**Hash funksiyasi** — istalgan uzunlikdagi ma'lumotni (matn, fayl) qat'iy uzunlikdagi, "raqamli barmoq izi" deb ataluvchi qiymatga aylantiradi. Uning uchta muhim xossasi bor: (1) bir xil kirish har doim bir xil natija beradi, (2) kirishdagi bitta belgining o'zgarishi ham natijani butunlay o'zgartiradi, (3) natijadan kirishni **teskari hisoblab topib bo'lmaydi** (bir tomonlama funksiya).

```python
import hashlib

hash1 = hashlib.sha256(b"Onlayn Dokon").hexdigest()
hash2 = hashlib.sha256(b"onlayn Dokon").hexdigest()  # faqat bitta harf kichik

print(hash1)   # 7f2c... (64 ta hex belgi)
print(hash2)   # butunlay boshqacha qiymat
```

**Muhim farq — hash shifrlash emas:** shifrlashda (`encryption`) ma'lumotni kalit bilan qaytarib ochish (decrypt) mumkin; hashda esa bunday yo'l **yo'q** — bu ataylab shunday qilingan, chunki hash asosan "ma'lumot o'zgarmaganini tekshirish" yoki "parolni qayta ochmasdan solishtirish" uchun ishlatiladi.

### `hashlib` bilan ishlash

```python
import hashlib

# Matn uchun
h = hashlib.sha256()
h.update(b"birinchi qism ")
h.update(b"ikkinchi qism")
print(h.hexdigest())

# Qulay qisqa yo'l
print(hashlib.sha256(b"butun matn").hexdigest())
```

`.update()`ni bir necha marta chaqirish mumkin — natija xuddi barcha qismlarni birlashtirib bitta marta hash qilingandek bo'ladi. Bu xossa katta fayllarni **bo'lak-bo'lak** (chunk) o'qib hash qilishda foydali — butun faylni xotiraga yuklash shart emas:

```python
def fayl_checksumini_hisobla(fayl_yoli, blok_hajmi=8192):
    h = hashlib.sha256()
    with open(fayl_yoli, "rb") as f:
        for blok in iter(lambda: f.read(blok_hajmi), b""):
            h.update(blok)
    return h.hexdigest()
```

`iter(lambda: f.read(blok_hajmi), b"")` — faylni 8 KB'lik bo'laklarga bo'lib o'qiydi, `f.read()` bo'sh bayt (`b""`) qaytarganda (fayl tugaganda) to'xtaydi. Bu, masalan, gigabaytlab video fayl uchun ham xotirada faqat 8 KB joy egallashini ta'minlaydi.

### Django parolni qanday hash qiladi

Foydalanuvchi ro'yxatdan o'tganda, Django parolni **hech qachon ochiq matnda saqlamaydi**. `django.contrib.auth.hashers.make_password()` funksiyasi (soddalashtirilgan mantiq bilan):

```python
import hashlib
import secrets

def soddalashtirilgan_parol_hash(parol: str) -> str:
    tuz = secrets.token_hex(8)          # "salt" — har bir parolga xos, tasodifiy qo'shimcha
    h = hashlib.sha256((tuz + parol).encode()).hexdigest()
    return f"{tuz}${h}"
```

Django haqiqatda `sha256`dan ko'ra murakkabroq, maxsus "sekin" algoritm (standart holda **PBKDF2**, ichida `hashlib.sha256` ishlatiladi) qo'llaydi — chunki oddiy tez hash (`sha256` yolg'iz) parolni **brute-force** (barcha variantlarni sinab ko'rish) orqali topishni juda tezlashtiradi. PBKDF2 esa hisoblashni ataylab minglab marta takrorlaydi, natijada bir parolni sinash sekinlashadi, ommaviy hujum amalda foydasiz bo'lib qoladi. **Tuz** (salt) — har bir foydalanuvchi uchun boshqacha tasodifiy qo'shimcha, u bir xil parolli ikki foydalanuvchining hash qiymati bir xil bo'lib qolishining oldini oladi.

**Muhim xulosa:** o'z loyihangizda **hech qachon** foydalanuvchi parolini qo'lda `hashlib.sha256(parol).hexdigest()` bilan hash qilmang — Django'ning `make_password()`/`check_password()` funksiyalaridan foydalaning, ular tuz qo'shish va sekin algoritmni to'g'ri, xavfsiz qo'llaydi.

## Amaliy misol

`onlayn_dokon`da mijoz yuklagan fayl (masalan shartnoma nusxasi) o'zgartirilmaganini tekshirish uchun checksum saqlaymiz, va API javoblarida `ETag` sarlavhasi orqali brauzer keshini samarali boshqaramiz:

```python
# apps/hujjatlar/models.py
import hashlib

from django.db import models


class YuklanganHujjat(models.Model):
    fayl = models.FileField(upload_to="hujjatlar/")
    checksum = models.CharField(max_length=64, editable=False, blank=True)

    def save(self, *args, **kwargs):
        if self.fayl and not self.checksum:
            h = hashlib.sha256()
            for blok in self.fayl.chunks():   # Django FileField.chunks() — avtomatik bo'lak-bo'lak o'qiydi
                h.update(blok)
            self.checksum = h.hexdigest()
            self.fayl.seek(0)   # keyingi saqlash uchun fayl "kursorini" boshiga qaytarish
        super().save(*args, **kwargs)

    def ozgartirilganmi(self):
        h = hashlib.sha256()
        for blok in self.fayl.chunks():
            h.update(blok)
        joriy = h.hexdigest()
        self.fayl.seek(0)
        return joriy != self.checksum
```

API view'da `ETag` orqali keshni boshqarish:

```python
# apps/mahsulotlar/views.py
import hashlib

from django.http import HttpResponse, JsonResponse

from .models import Mahsulot


def mahsulotlar_royxati_json(request):
    mahsulotlar = list(Mahsulot.objects.values("id", "nomi", "narxi"))
    tarkib_belgisi = hashlib.sha256(str(mahsulotlar).encode()).hexdigest()

    if request.headers.get("If-None-Match") == tarkib_belgisi:
        return HttpResponse(status=304)   # "O'zgarmagan" — brauzer o'z keshidan foydalansin

    response = JsonResponse(mahsulotlar, safe=False)
    response["ETag"] = tarkib_belgisi
    return response
```

`ETag` — "bu tarkibning hozirgi holati shu hash" degan ma'noni bildiradi; brauzer keyingi so'rovda `If-None-Match` sarlavhasi bilan oldingi hashni yuboradi, va agar tarkib o'zgarmagan bo'lsa (hash bir xil), server to'liq javob o'rniga qisqa `304 Not Modified` qaytaradi — bu tarmoq trafigini tejaydi.

## Keng tarqalgan xatolar

**Xato 1:** Parolni o'zining `hashlib` bilan qo'lda hash qilish.

❌ `foydalanuvchi.password = hashlib.sha256(parol.encode()).hexdigest()` — tuz (salt) yo'q, algoritm juda tez (brute-force uchun qulay), va Django'ning o'z autentifikatsiya tizimi (`authenticate()`) bu formatni tushunmaydi.

✅ Har doim `django.contrib.auth.hashers.make_password()` (yaratishda) va `check_password()` (tekshirishda), yoki `User.objects.create_user(...)` / `user.set_password(...)` metodlaridan foydalaning — ular hammasi to'g'ri, xavfsiz mexanizmni chaqiradi.

**Xato 2:** Katta faylni `.read()` bilan to'liq xotiraga yuklab, keyin hash qilish.

❌ `hashlib.sha256(fayl.read()).hexdigest()` — agar fayl 2 GB bo'lsa, butun 2 GB xotiraga yuklanadi, bu serverni sekinlashtiradi yoki hatto xotira yetishmasligiga olib kelishi mumkin.

✅ Amaliy misoldagi kabi, faylni bo'lak-bo'lak (`chunks()` yoki `iter(lambda: f.read(8192), b"")`) o'qib, `.update()` bilan hisoblang.

**Xato 3:** Ikki hashni oddiy `==` bilan solishtirish (xavfsizlik kontekstida).

❌ `if kutilgan_hash == kelgan_hash:` — bu funksional jihatdan to'g'ri ishlaydi, lekin xavfsizlik nuqtai nazaridan **"timing attack"**ga ochiq: Python'ning `==` operatori stringlarni chapdan o'ngga solishtiradi va birinchi mos kelmagan belgida darhol to'xtaydi, natijada javob vaqti (necha mikrosekund ketgani) hash qanchalik "to'g'ri boshlanganini" oshkor qilishi mumkin.

✅ Xavfsizlik uchun muhim solishtirishlarda (token, imzo, parol hash) `hmac.compare_digest(a, b)`dan foydalaning — u doim bir xil vaqt sarflaydigan (constant-time) solishtirish qiladi, mos kelish-kelmasligidan qat'iy nazar.

## Mashq/topshiriq

**(Oson)** Shell'da `hashlib.sha256(b"onlayn_dokon").hexdigest()`ni ikki marta ketma-ket chaqirib, natijalar **bir xil** ekanini tasdiqlang (bu — `secrets.token_hex()`dan asosiy farq: hash **deterministik**, token esa tasodifiy).

**(O'rtacha)** `fayl_checksumini_hisobla` funksiyasini shunday o'zgartiring — u `sha256` o'rniga argument sifatida algoritm nomini qabul qilsin (masalan `algoritm="sha256"` yoki `"md5"`), va `hashlib.new(algoritm)` orqali mos hash obyektini yaratsin.

**(Qiyin)** `YuklanganHujjat.ozgartirilganmi()` metodidan foydalanib, management command yozing: barcha `YuklanganHujjat` obyektlarini aylanib chiqib, checksumi saqlangan qiymat bilan mos kelmaydiganlarini (fayl tizimida qo'lda almashtirilgan bo'lishi mumkin) topib, ularning nomi va ID'sini ogohlantirish (`self.style.WARNING`) sifatida chiqaring.

## Qisqacha xulosa

`hashlib` — matn yoki faylni qat'iy uzunlikdagi, bir tomonlama "barmoq izi"ga aylantiradi; bu fayl o'zgarmaganini tekshirish (checksum), keshni boshqarish (`ETag`) va — eng muhimi — Django'ning parol hashlash mexanizmi (`make_password`, ichida `hashlib` va tuz bilan PBKDF2) uchun asos bo'ladi. Katta fayllar bilan ishlaganda `.update()`ni bo'lak-bo'lak chaqirish xotirani tejaydi, xavfsizlik uchun muhim solishtirishlarda esa oddiy `==` o'rniga `hmac.compare_digest()` ishlatiladi. Parolni hech qachon o'zingiz qo'lda hash qilmang — Django'ning tayyor, sinovdan o'tgan mexanizmiga ishoning. Keyingi bobda — xotirada fayl generatsiya qilish (`io.BytesIO`) va vaqtinchalik fayllar (`tempfile`, `shutil`) bilan tanishamiz.
