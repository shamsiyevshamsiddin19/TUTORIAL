# 6.2. django-filter va django-cors-headers

## Bu darsda nimalarni o'rganasiz

- API endpointlarida qo'lda filtrlash kodi yozishning muammosini tushunasiz
- `django-filter`ni DRF bilan integratsiya qilib, URL parametrlari orqali avtomatik filtrlashni o'rganasiz
- CORS (Cross-Origin Resource Sharing) nima ekanini va brauzer nega uni bloklashini tushunasiz
- `django-cors-headers`ni sozlab, boshqa domendagi frontend'ga API'dan foydalanish ruxsatini berishni o'rganasiz

## Nazariy qism

### Muammo: qo'lda filtrlash kodi

6.1-darsda yaratilgan `/api/mahsulotlar/` endpointi — **barcha** mahsulotlarni qaytaradi. Lekin real loyihada, frontend ko'pincha "faqat shu narx oralig'idagi", "faqat shu bo'limdagi" mahsulotlarni so'raydi. Buni qo'lda yozish mumkin:

```python
def list(self, request):
    queryset = self.queryset
    narx_min = request.query_params.get("narx_min")
    if narx_min:
        queryset = queryset.filter(narxi__gte=narx_min)
    # ... har bir yangi filtr uchun yana bir if
```

Bu yondashuv — har bir yangi filtr uchun qo'lda `if` yozish, xato qilish oson (masalan noto'g'ri turga o'girish), va tezda "shishib" ketadi.

### django-filter yechimi

```bash
pip install django-filter
```

```python
# settings.py
INSTALLED_APPS += ["django_filters"]

REST_FRAMEWORK = {
    # ... (6.1-darsdagi DEFAULT_SCHEMA_CLASS bilan birga)
    "DEFAULT_FILTER_BACKENDS": ["django_filters.rest_framework.DjangoFilterBackend"],
}
```

```python
# apps/dokon/filters.py
import django_filters
from .models import Mahsulot


class MahsulotFilter(django_filters.FilterSet):
    narx_min = django_filters.NumberFilter(field_name="narxi", lookup_expr="gte")
    narx_max = django_filters.NumberFilter(field_name="narxi", lookup_expr="lte")

    class Meta:
        model = Mahsulot
        fields = ["bolim", "narx_min", "narx_max"]
```

```python
# apps/dokon/api_views.py
class MahsulotViewSet(viewsets.ModelViewSet):
    queryset = Mahsulot.objects.all()
    serializer_class = MahsulotSerializer
    filterset_class = MahsulotFilter
```

Endi `GET /api/mahsulotlar/?bolim=2&narx_min=10000&narx_max=50000` — hech qanday qo'shimcha `if` yozmasdan, avtomatik ishlaydi. `FilterSet` klassi — Django formasi kabi, deklarativ tarzda, qaysi maydonlar bo'yicha va qanday (`gte`, `lte`, `icontains`, va h.k.) filtrlash mumkinligini belgilaydi.

### CORS nima va nega kerak

Sizning `onlayn_dokon` API'ingiz `http://localhost:8000`da ishlayapti. Frontend jamoasi esa, alohida React ilovasini `http://localhost:3000`da ishga tushirgan va sizning API'ingizga `fetch()` orqali so'rov yubormoqchi. Brauzer bu so'rovni **bloklaydi** — chunki bu ikki manzil turli **origin** (domen+port kombinatsiyasi) hisoblanadi, va brauzerning **Same-Origin Policy** xavfsizlik qoidasi, standart holda, bir origin'dagi JavaScript kodning boshqa origin'ga so'rov yuborishini taqiqlaydi (aks holda, zararli sayt sizning bank sahifangizga, sizning nomingizdan, fon rejimida so'rov yubora olardi).

**CORS** — serverning, "menga qaysi origin'lardan so'rov yuborishga ruxsat bor" deb, maxsus HTTP sarlavha (`Access-Control-Allow-Origin`) orqali brauzerga aytishi. Bu sarlavha bo'lmasa, brauzer konsolida taniqli xato chiqadi:

```
Access to fetch at 'http://localhost:8000/api/mahsulotlar/' from origin
'http://localhost:3000' has been blocked by CORS policy: No
'Access-Control-Allow-Origin' header is present on the requested resource.
```

### django-cors-headers yechimi

```bash
pip install django-cors-headers
```

```python
# settings.py
INSTALLED_APPS += ["corsheaders"]

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "corsheaders.middleware.CorsMiddleware",   # CommonMiddleware'dan OLDIN
    "django.middleware.common.CommonMiddleware",
    # ... qolganlari
]

CORS_ALLOWED_ORIGINS = [
    "http://localhost:3000",
    "https://dokon-frontend.example.com",
]
```

`CorsMiddleware`ning joyi muhim: u `CommonMiddleware`dan **oldin** turishi kerak (rasmiy hujjatlarda tavsiya etilgan tartib). `CORS_ALLOWED_ORIGINS` — **aniq**, ro'yxatga olingan origin'larga ruxsat beradi; bu, xavfsizlik nuqtai nazaridan, "hammaga ruxsat" (`CORS_ALLOW_ALL_ORIGINS = True`) dan ancha xavfsizroq.

## Amaliy misol

`onlayn_dokon` API'siga filtrlash va CORS qo'shish:

```python
# apps/dokon/filters.py
import django_filters
from .models import Mahsulot


class MahsulotFilter(django_filters.FilterSet):
    narx_min = django_filters.NumberFilter(field_name="narxi", lookup_expr="gte")
    narx_max = django_filters.NumberFilter(field_name="narxi", lookup_expr="lte")
    nomi = django_filters.CharFilter(field_name="nomi", lookup_expr="icontains")

    class Meta:
        model = Mahsulot
        fields = ["bolim", "narx_min", "narx_max", "nomi"]
```

```python
# apps/dokon/api_views.py
from rest_framework import viewsets
from .models import Mahsulot
from .serializers import MahsulotSerializer
from .filters import MahsulotFilter


class MahsulotViewSet(viewsets.ModelViewSet):
    queryset = Mahsulot.objects.all()
    serializer_class = MahsulotSerializer
    filterset_class = MahsulotFilter
```

```python
# onlayn_dokon/settings/base.py
INSTALLED_APPS = [
    # ...
    "django_filters",
    "corsheaders",
    "rest_framework",
    "drf_spectacular",
]

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "corsheaders.middleware.CorsMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",
    "django.contrib.sessions.middleware.SessionMiddleware",
    "django.middleware.common.CommonMiddleware",
    # ...
]

REST_FRAMEWORK = {
    "DEFAULT_SCHEMA_CLASS": "drf_spectacular.openapi.AutoSchema",
    "DEFAULT_FILTER_BACKENDS": ["django_filters.rest_framework.DjangoFilterBackend"],
}
```

```python
# onlayn_dokon/settings/development.py
from .base import *  # noqa

CORS_ALLOWED_ORIGINS = ["http://localhost:3000"]
```

Sinov — `curl` orqali filtrlashni tekshirish:

```bash
curl "http://localhost:8000/api/mahsulotlar/?narx_min=50000&nomi=telefon"
```

```json
[
    {"id": 3, "nomi": "Telefon g'ilofi", "narxi": "55000.00", "rasm": null, "stock": 12}
]
```

Faqat nomi "telefon" so'zini o'z ichiga olgan (katta-kichik harflarga sezgir bo'lmagan holda) va narxi 50000 dan katta yoki teng mahsulotlar qaytdi.

## Keng tarqalgan xatolar

**Xato 1:** `CorsMiddleware`ni `MIDDLEWARE` ro'yxatida noto'g'ri joyga qo'yish.

❌ `CorsMiddleware` `CommonMiddleware`dan **keyin** joylashtirilgan — ba'zi holatlarda CORS sarlavhalari to'g'ri qo'shilmasligi yoki `APPEND_SLASH` bilan bog'liq muammolar yuzaga kelishi mumkin.

✅ `CorsMiddleware`ni har doim `CommonMiddleware`dan **oldin**, mumkin qadar `MIDDLEWARE` ro'yxatining boshiga yaqin joylashtiring.

**Xato 2:** `CORS_ALLOW_ALL_ORIGINS = True`ni production'da ishlatib qo'yish.

❌ Tezroq ishlashi uchun (yoki "keyin to'g'rilayman" deb), `CORS_ALLOW_ALL_ORIGINS = True` production sozlamalarida qoldirilgan — bu, **istalgan** sayt sizning API'ingizga, foydalanuvchi nomidan (agar autentifikatsiya cookie orqali bo'lsa) so'rov yuborishiga yo'l ochib beradi, xavfsizlik zaifligi hisoblanadi.

✅ Production'da har doim `CORS_ALLOWED_ORIGINS`ni **aniq ro'yxat** sifatida belgilang — faqat haqiqatan sizning frontend'ingiz joylashgan domenlarni kiriting; `CORS_ALLOW_ALL_ORIGINS`ni faqat vaqtinchalik, development paytida, va ehtiyotkorlik bilan ishlating.

**Xato 3:** `FilterSet`da `fields`ga oddiy model maydonini ro'yxatga olib, lekin qanday taqqoslash (`lookup_expr`) kerakligini aniqlashtirmaslik natijasida noto'g'ri natija kutish.

❌ `fields = ["narxi"]` — bu, standart holda, faqat **aniq mos kelish** (`narxi=50000`) bo'yicha filtrlaydi, "50000 dan katta" kabi so'rovlarni qo'llab-quvvatlamaydi; dasturchi `?narxi__gte=50000` yozib, ishlamasligidan hayron qoladi (DRF/django-filter bunday URL sintaksisini avtomatik tushunmaydi).

✅ Oraliq (`gte`/`lte`) yoki qisman mos kelish (`icontains`) kerak bo'lgan har bir maydon uchun, yuqoridagi misoldagi kabi, **aniq nomlangan** `NumberFilter`/`CharFilter` yozing (`narx_min`, `narx_max`, `nomi`) — bu, API foydalanuvchisi uchun ham tushunarliroq URL beradi.

## Mashq/topshiriq

**(Oson)** `django-filter`ni o'rnating, `MahsulotFilter`ni yozing (`bolim` bo'yicha aniq filtr), `MahsulotViewSet`ga `filterset_class` sifatida bog'lang. `GET /api/mahsulotlar/?bolim=1` so'rovini sinab ko'ring.

**(O'rtacha)** `django-cors-headers`ni o'rnating, `CorsMiddleware`ni to'g'ri joyga qo'shing, `CORS_ALLOWED_ORIGINS = ["http://localhost:3000"]`ni sozlang. Brauzer konsolida (yoki `curl -H "Origin: http://localhost:3000" -I http://localhost:8000/api/mahsulotlar/` orqali) `Access-Control-Allow-Origin` sarlavhasi javobda borligini tasdiqlang.

**(Qiyin)** `MahsulotFilter`ga, `narx_min`/`narx_max`dan tashqari, mahsulot nomi bo'yicha qisman qidiruv (`nomi__icontains`) qo'shing. Uchala filtrni birga ishlatib (`?narx_min=10000&narx_max=100000&nomi=telefon`), natijani tekshiring.

## Qisqacha xulosa

`django-filter` — API endpointlarida, har bir filtr uchun qo'lda `if` yozish o'rniga, deklarativ `FilterSet` klassi orqali URL parametrlaridan avtomatik filtrlashni ta'minlaydi; `django-cors-headers` esa, brauzerning Same-Origin siyosati sababli bloklanadigan, boshqa domendagi (masalan alohida frontend ilova) so'rovlarga, aniq belgilangan `CORS_ALLOWED_ORIGINS` ro'yxati orqali, xavfsiz ravishda ruxsat beradi. Shu bilan 06-bob (API qo'shimchalari) yakunlandi — keyingi bobda `onlayn_dokon`ga og'ir yoki uzoq davom etadigan vazifalarni fon rejimida bajarish (`Celery`+`Redis`) va tez-tez so'raladigan ma'lumotlarni keshlash (`django-redis`) imkoniyatlarini qo'shamiz.
