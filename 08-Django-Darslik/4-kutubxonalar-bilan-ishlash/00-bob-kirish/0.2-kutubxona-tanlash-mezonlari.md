# 0.2. Kutubxonani qanday tanlash va baholash mezonlari

## Bu darsda nimalarni o'rganasiz

- Bir xil vazifa uchun bir nechta kutubxona bo'lganda, ularni qanday mezonlar bilan solishtirishni bilib olasiz
- GitHub repozitoriysidagi "sog'lomlik belgilari"ni (yulduzlar, oxirgi commit, ochiq issue'lar) o'qishni o'rganasiz
- Litsenziya turlari orasidagi tijorat loyihasi uchun muhim farqni tushunasiz
- Kutubxonaning Django versiyasi bilan mosligini oldindan tekshirishni o'rganasiz

## Nazariy qism

### Nega tanlash muhim

PyPI'da, masalan, ".env fayldan sozlama o'qish" vazifasi uchun kamida uchta mashhur kutubxona bor: `django-environ`, `python-decouple`, `django-configurations`. Har biri vazifani bajaradi, lekin noto'g'ri tanlov loyihaga uzoq muddatda qimmatga tushishi mumkin: kutubxona yangilanishni to'xtatsa, Django'ning yangi versiyasi bilan ishlamay qolsa, yoki loyihangiz litsenziyasi bilan mos kelmasa.

### Asosiy mezonlar

| Mezon | Nima uchun tekshiriladi | Qayerdan ko'riladi |
|---|---|---|
| **Faollik (activity)** | Loyiha "tashlab qo'yilmaganmi" | GitHub'da oxirgi commit sanasi — 1-2 yildan beri commit yo'q bo'lsa, ehtiyot bo'ling |
| **Mashhurlik** | Qanchalik ko'p sinovdan o'tgan | GitHub yulduzlari, PyPI oylik yuklab olishlar soni |
| **Ochiq muammolar (issues)** | Sifat va qo'llab-quvvatlash tezligi | Ochiq/yopiq issue nisbati; maintainer javob berayaptimi |
| **Litsenziya** | Tijorat loyihasida ishlatish mumkinmi | PyPI sahifasidagi "License" maydoni yoki repozitoriydagi `LICENSE` fayli |
| **Framework moslik** | Sizning Django versiyangiz bilan ishlaydimi | PyPI'dagi "Classifiers" ro'yxati (`Framework :: Django :: 5.0`) yoki README'dagi mos versiyalar jadvali |
| **Hujjatlashtirilganlik** | Tez o'rganib, to'g'ri ishlatish mumkinmi | README sifat darajasi, alohida docs sayti (masalan Read the Docs) bormi |

### Litsenziyalar — qisqacha

| Litsenziya | Ma'nosi |
|---|---|
| **MIT, BSD** | Deyarli cheklovsiz — tijorat loyihasida, o'zgartirib, o'zingiznikidek ishlating, faqat mualliflik bildirishini saqlang |
| **Apache 2.0** | MIT'ga o'xshash, qo'shimcha patent himoyasi bilan |
| **GPL / AGPL** | "Copyleft" — agar kodingizga shu kutubxonani ulasangiz, ba'zi holatlarda **o'z loyihangizni ham** ochiq manba qilib chiqarishni talab qilishi mumkin — tijorat, yopiq-manba loyihada ehtiyot bo'ling |

Aksariyat mashhur Django kutubxonalari (shu darslikda ko'radiganlarimiz jumladan) MIT yoki BSD litsenziyasida — lekin **har doim tekshiring**, ayniqsa katta/kompaniya loyihasida.

## Amaliy misol

Real misol: ".env sozlamalarini o'qish" vazifasi uchun uchta variant:

| Kutubxona | Yulduz (~) | Oxirgi release | Litsenziya | Xususiyat |
|---|---|---|---|---|
| `django-environ` | 3000+ | faol, muntazam | MIT | `.env` + tur konvertatsiya (`env.bool()`, `env.db()` — hatto `DATABASE_URL`ni to'g'ridan-to'g'ri parslaydi) |
| `python-decouple` | 900+ | faol | MIT | Sodda, Django'ga bog'liq emas (har qanday Python loyihasida ishlaydi), lekin `DATABASE_URL` kabi murakkab parsing yo'q |
| `django-configurations` | 2500+ | kamroq faol | BSD | Klass-asosidagi sozlamalar (`class Production(Base)`) — kuchli, lekin o'rganish egri chizig'i balandroq |

**Xulosa (bu darslik uchun):** `onlayn_dokon` Django-ga maxsus loyiha va `DATABASE_URL`ni to'g'ridan-to'g'ri parslash kerak bo'lgani uchun, 02-bobda **`django-environ`**ni tanlaymiz — u Django ekotizimiga eng chuqur integratsiya qilingan va faol qo'llab-quvvatlanadi.

## Keng tarqalgan xatolar

**Xato 1:** Faqat yulduzlar soniga qarab tanlash.

❌ Kutubxona 5000 yulduzga ega, lekin oxirgi commit 3 yil oldin bo'lgan — bu, ko'pincha, loyiha "tashlab qo'yilgan" (abandoned) degani, va yangi Django versiyasi bilan ishlamasligi mumkin.

✅ Yulduzlar bilan birga har doim **oxirgi commit/release sanasini** tekshiring. Faol, kamroq yulduzli kutubxona ko'pincha eskirgan, ko'p yulduzli kutubxonadan yaxshiroq tanlov.

**Xato 2:** Litsenziyani tekshirmasdan tijorat (yopiq-manba) loyihaga qo'shish.

❌ GPL litsenziyali kutubxona yopiq-manba, sotiladigan mahsulotga qo'shiladi — bu huquqiy muammoga olib kelishi mumkin (litsenziya shartiga qarab).

✅ Kutubxona qo'shishdan oldin, litsenziyasini tekshiring; noaniq bo'lsa, MIT/BSD/Apache litsenziyali muqobilini qidiring yoki huquqshunosdan maslahat oling.

**Xato 3:** Django versiyasi bilan mosligini tekshirmaslik.

❌ Loyiha Django 5.2'da ishlaydi, lekin tanlangan kutubxona so'nggi marta Django 3.2 uchun test qilingan — o'rnatishda ishlaydigandek ko'rinishi mumkin, lekin ishlash vaqtida kutilmagan xatolar chiqishi mumkin.

✅ PyPI sahifasidagi "Classifiers" bo'limida `Framework :: Django` qatorlarini yoki README'dagi moslik jadvalini tekshiring, kerak bo'lsa kutubxonaning GitHub'idagi test konfiguratsiyasini (`tox.ini`, CI fayllari) ko'ring.

- **C**: MIT litsenziya
- **D**: AGPL-3.0 litsenziya

**(Qiyin)** Sizga PDF generatsiya qiluvchi kutubxona kerak. Quyidagi ma'lumotlarga asoslanib, qaysi birini tanlaysiz va nega (kamida ikkita mezonni sabab qilib ko'rsating)?
- **E**: 1200 yulduz, oxirgi release 3 oy oldin, "Framework :: Django :: 5.0" classifier bor, hujjatlar sayti bor, MIT

## Qisqacha xulosa

Kutubxona tanlashda yulduzlar soni yagona mezon emas — faollik (oxirgi commit/release), litsenziya turi, Django versiyasi bilan moslik va hujjatlashtirilganlik darajasi birgalikda baholanishi kerak; ayniqsa tijorat, yopiq-manba loyihalarda litsenziyani (GPL/AGPL'dan ehtiyot bo'lib) tekshirish muhim. Keyingi bobdan boshlab, aynan shu mezonlar bilan tanlangan, `onlayn_dokon` loyihasiga mos keluvchi kutubxonalarni birma-bir ko'rib chiqamiz — birinchi navbatda, ularning barchasini to'g'ri **qayd etib borish** (1.1-dars, `requirements.txt`) bilan boshlaymiz.
