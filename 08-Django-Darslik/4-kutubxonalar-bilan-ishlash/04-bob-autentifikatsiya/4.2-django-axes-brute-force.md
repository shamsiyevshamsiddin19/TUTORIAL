# 4.2. django-axes — brute-force hujumlaridan himoya

## Bu darsda nimalarni o'rganasiz

- Brute-force hujumi nima ekanini va himoyasiz login sahifasi nega xavfli ekanini tushunasiz
- `django-axes`ni o'rnatib, `AUTHENTICATION_BACKENDS` va `MIDDLEWARE`ga to'g'ri joyga qo'shishni o'rganasiz
- `AXES_FAILURE_LIMIT`, `AXES_COOLOFF_TIME` kabi sozlamalarni bilib olasiz
- Bloklangan foydalanuvchini qanday qayta ochishni o'rganasiz

## Nazariy qism

### Brute-force hujumi nima

**Brute-force** — hujumchi login sahifasiga, dastur (bot) yordamida, **minglab** turli parolni ketma-ket, avtomatik ravishda kiritib ko'rishga urinishi. Agar login sahifasi hech qanday cheklovsiz bo'lsa, hujumchi, yetarlicha vaqt sarflab, oxir-oqibat to'g'ri parolni "toppish" ehtimoli oshadi — ayniqsa foydalanuvchilar oddiy, taxmin qilinadigan parollar ishlatgan bo'lsa.

Django'ning o'zi, standart holda, login urinishlari sonini **cheklamaydi** — bu himoyani qo'shish dasturchining vazifasi. `django-axes` — aynan shu vazifani bajaradigan, keng qo'llaniladigan kutubxona: muayyan IP-manzil yoki foydalanuvchi nomidan ketma-ket bir necha marta noto'g'ri parol kiritilsa, login imkoniyatini **vaqtincha bloklaydi**.

### django-axes yechimi

```bash
pip install django-axes
```

```python
# settings.py
INSTALLED_APPS += ["axes"]

AUTHENTICATION_BACKENDS = [
    "axes.backends.AxesStandaloneBackend",   # HAR DOIM birinchi o'rinda
    "django.contrib.auth.backends.ModelBackend",
    "allauth.account.auth_backends.AuthenticationBackend",
]

MIDDLEWARE = [
    # ... barcha boshqa middleware'lar
    "axes.middleware.AxesMiddleware",   # HAR DOIM oxirgi o'rinda
]
```

`AxesStandaloneBackend` — har bir login urinishini birinchi bo'lib "ko'rib chiqadi": agar foydalanuvchi hozir bloklangan bo'lsa, parol to'g'ri bo'lsa ham, kirishga ruxsat bermaydi. Shuning uchun u ro'yxatning **eng boshida** turishi shart — aks holda, boshqa backend (masalan allauth'niki) undan oldin "ha, parol to'g'ri" deb qaror qilib yuborishi mumkin.

### Asosiy sozlamalar

```python
AXES_FAILURE_LIMIT = 5          # 5 marta noto'g'ri urinishdan keyin bloklash
AXES_COOLOFF_TIME = 1           # 1 soatdan keyin avtomatik ochiladi
AXES_LOCKOUT_PARAMETERS = ["ip_address", "username"]   # IP + username kombinatsiyasi bo'yicha bloklash
```

```bash
python manage.py migrate axes
```

`AXES_LOCKOUT_PARAMETERS = ["ip_address", "username"]` — bloklash **faqat** bitta IP'dan, bitta aniq foydalanuvchi nomiga qilingan urinishlarga tegishli bo'lishini bildiradi (shunday qilib, bitta ofisdagi ko'p xodim, bir xil IP orqali, turli hisoblarga bemalol kira oladi — faqat bitta hisobga qarshi ketma-ket xato urinish bloklaydi).

### Bloklangan foydalanuvchini qayta ochish

```bash
python manage.py axes_reset                    # BARCHA bloklarni tozalaydi
python manage.py axes_reset_username shams      # faqat bitta username uchun
python manage.py axes_reset_ip 192.168.1.10     # faqat bitta IP uchun
```

Django admin panelida ham (`INSTALLED_APPS`da `axes` bo'lgani uchun) `/admin/axes/accessattempt/` orqali barcha urinishlar ro'yxatini ko'rish va kerakli yozuvni qo'lda o'chirish mumkin.

## Amaliy misol

`onlayn_dokon`da login himoyasini sozlash va sinash:

```python
# onlayn_dokon/settings/base.py
INSTALLED_APPS = [
    # ...
    "axes",
    "allauth",
    "allauth.account",
]

AUTHENTICATION_BACKENDS = [
    "axes.backends.AxesStandaloneBackend",
    "django.contrib.auth.backends.ModelBackend",
    "allauth.account.auth_backends.AuthenticationBackend",
]

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",
    "django.contrib.sessions.middleware.SessionMiddleware",
    "allauth.account.middleware.AccountMiddleware",
    # ... qolgan middleware'lar
    "axes.middleware.AxesMiddleware",   # ENG OXIRIDA
]

AXES_FAILURE_LIMIT = 5
AXES_COOLOFF_TIME = 1
```

```bash
python manage.py migrate axes
```

Sinov — login sahifasiga ataylab 5 marta noto'g'ri parol kiritamiz:

```
1-urinish: "Please enter a correct email and password."
2-urinish: "Please enter a correct email and password."
3-urinish: "Please enter a correct email and password."
4-urinish: "Please enter a correct email and password."
5-urinish: "Please enter a correct email and password."
6-urinish (parol TO'G'RI bo'lsa ham): "Account locked: too many login attempts. Contact an administrator to unlock your account."
```

Bloklashni bekor qilish:

```bash
python manage.py axes_reset_username mijoz@example.com
```

```
1 access attempt(s) removed.
```

Shundan keyin, foydalanuvchi to'g'ri parol bilan yana kira oladi.

## Keng tarqalgan xatolar

**Xato 1:** `AxesStandaloneBackend`ni `AUTHENTICATION_BACKENDS` ro'yxatining birinchisi qilib qo'ymaslik.

❌ `AUTHENTICATION_BACKENDS`da `axes.backends.AxesStandaloneBackend` oxirga yoki o'rtaga qo'yilgan — undan **oldingi** backend (masalan `ModelBackend`) parolni tekshirib, "to'g'ri" deb qaror chiqarib yuborishi mumkin, shuning uchun `axes` bloklashni **hech qachon** amalga oshira olmaydi.

✅ `AxesStandaloneBackend`ni har doim `AUTHENTICATION_BACKENDS` ro'yxatining **eng birinchi** elementi qiling.

**Xato 2:** `AxesMiddleware`ni `MIDDLEWARE` ro'yxatining boshiga yoki o'rtasiga qo'yish.

❌ `AxesMiddleware` boshqa middleware'lardan (masalan sessiya, autentifikatsiya middleware'laridan) oldin joylashtirilgan — rasmiy hujjatlarga ko'ra, bu noto'g'ri ishlashga olib kelishi mumkin.

✅ `AxesMiddleware`ni har doim `MIDDLEWARE` ro'yxatining **eng oxirgi** elementi qiling.

**Xato 3:** Rivojlantirish (development) paytida o'zini bloklab qo'yib, qanday ochishni bilmaslik.

❌ Dasturchi o'zi, sinov paytida, parolni bir necha marta xato kiritib, o'z hisobini bloklab qo'ygan — va `AXES_COOLOFF_TIME=1` (1 soat) tugashini kutib o'tiradi, ish jarayoni to'xtaydi.

✅ Rivojlantirish paytida bloklanib qolsangiz, `python manage.py axes_reset`ni ishga tushiring — bu darhol barcha bloklarni tozalaydi, 1 soat kutish shart emas. Development muhitida `AXES_FAILURE_LIMIT`ni vaqtincha kattaroq (masalan 20) qilib qo'yish ham mumkin.

## Mashq/topshiriq

**(Oson)** `django-axes`ni o'rnating, `AUTHENTICATION_BACKENDS` va `MIDDLEWARE`ni to'g'ri sozlang, `migrate axes`ni ishga tushiring.

**(O'rtacha)** Login sahifasiga ataylab 5 marta noto'g'ri parol kiriting va hisobingiz bloklanganini tasdiqlang. So'ng `python manage.py axes_reset`ni ishga tushirib, qayta kira olishingizni tekshiring.

**(Qiyin)** `AXES_FAILURE_LIMIT`ni `3`ga, `AXES_COOLOFF_TIME`ni `0.1`ga (6 daqiqa) o'zgartiring. Django admin panelidagi `/admin/axes/accessattempt/` sahifasiga kirib, bloklangan urinish yozuvini toping va uni **qo'lda**, buyruqsiz, admin panel orqali o'chirib ko'ring.

## Qisqacha xulosa

`django-axes` — login sahifasini brute-force hujumlaridan, muayyan IP/foydalanuvchi nomi kombinatsiyasi bo'yicha ketma-ket noto'g'ri urinishlar sonini cheklab (`AXES_FAILURE_LIMIT`) va vaqtinchalik bloklab (`AXES_COOLOFF_TIME`) himoya qiladi; to'g'ri ishlashi uchun `AxesStandaloneBackend` `AUTHENTICATION_BACKENDS`ning **birinchisi**, `AxesMiddleware` esa `MIDDLEWARE`ning **oxirgisi** bo'lishi shart. `axes_reset` buyruqlari (yoki admin panel) orqali bloklarni istalgan vaqtda qo'lda tozalash mumkin. Shu bilan 04-bob (autentifikatsiya) yakunlandi — keyingi bobda `onlayn_dokon`ning mahsulot rasmlari bilan ishlash imkoniyatlarini (`Pillow`, `django-storages`) kengaytiramiz.
