# 7.2. django-redis — keshlash

## Bu darsda nimalarni o'rganasiz

- Keshlash (caching) nima ekanini va u nega sahifa tezligini sezilarli oshirishini tushunasiz
- `django-redis`ni o'rnatib, Django'ning kesh tizimini Redis'ga ulashni o'rganasiz
- Butun sahifani, funksiya natijasini va template qismini keshlashning uch usulini bilib olasiz
- Kesh **eskirishi** (invalidation) muammosini va uni qanday to'g'ri boshqarishni o'rganasiz

## Nazariy qism

### Keshlash nima va nega kerak

`onlayn_dokon`ning bosh sahifasida "Eng ko'p sotilgan 10 ta mahsulot" degan blok bor deylik. Bu ro'yxatni hisoblash — bir nechta jadvalni (`Buyurtma`, `BuyurtmaElementi`, `Mahsulot`) birlashtiruvchi (JOIN), agregatsiya (`SUM`, `COUNT`) talab qiluvchi, nisbatan "og'ir" so'rov. Bu ro'yxat kuniga bir marta ham o'zgarmasligi mumkin (ma'lumotlar bazasidagi buyurtmalar asosida sekin o'zgaradi), lekin sahifa **har safar** yangi mijoz tashrif buyurganda shu og'ir so'rovni qayta bajaradi — bu, server resurslarini behuda sarflaydi.

**Keshlash** — natijani (bu holda, 10 ta mahsulot ro'yxatini) bir marta hisoblab, tezkor xotirada (Redis) saqlab qo'yish, va keyingi so'rovlarda, ma'lumotlar bazasiga umuman murojaat qilmasdan, saqlangan natijani **darhol** qaytarish g'oyasi. Redis — bu yerda ham (7.1-darsdagi Celery broker vazifasidan farqli) **kesh ombori** sifatida ishlatiladi — bitta Redis serveri ikkala vazifani ham bajarishi mumkin (odatda turli "database raqami" bilan ajratiladi).

### django-redis o'rnatish va sozlash

```bash
pip install django-redis
```

```python
# settings.py
CACHES = {
    "default": {
        "BACKEND": "django_redis.cache.RedisCache",
        "LOCATION": env("REDIS_CACHE_URL", default="redis://localhost:6379/1"),
        "OPTIONS": {
            "CLIENT_CLASS": "django_redis.client.DefaultClient",
        },
    }
}
```

E'tibor bering: `LOCATION`dagi manzil oxiri `/1` — bu, 7.1-darsdagi Celery broker (`/0`) bilan **bir xil** Redis serverida, lekin **alohida** "bazada" ishlashni bildiradi (Redis'da 0-15 oralig'ida raqamlangan bazalar bo'ladi) — shunday qilib, kesh ma'lumotlari va Celery navbati bir-biriga aralashmaydi.

### Uch xil keshlash usuli

**1. Funksiya natijasini keshlash** — eng ko'p ishlatiladigan, aniq nazorat beruvchi usul:

```python
from django.core.cache import cache

def eng_kop_sotilganlar():
    natija = cache.get("eng_kop_sotilganlar")
    if natija is None:
        natija = list(
            Mahsulot.objects.annotate(sotilgan=Sum("buyurtmaelementi__soni"))
            .order_by("-sotilgan")[:10]
        )
        cache.set("eng_kop_sotilganlar", natija, timeout=3600)   # 1 soat
    return natija
```

`cache.get(key)` — kalit bo'yicha saqlangan qiymatni qidiradi; topilmasa (`None`), og'ir hisoblash bajariladi va `cache.set(key, qiymat, timeout)` orqali saqlanadi. `timeout=3600` — 1 soatdan keyin kesh **avtomatik** eskiradi (o'chadi), keyingi so'rov qayta hisoblaydi.

**2. View darajasida keshlash** — butun sahifa natijasini keshlaydi:

```python
from django.views.decorators.cache import cache_page

@cache_page(60 * 15)   # 15 daqiqa
def bosh_sahifa(request):
    # ...
    return render(request, "bosh_sahifa.html", context)
```

**3. Template qismini keshlash** — sahifaning faqat bir bo'lagini (masalan yon panel):

```html
{% load cache %}
{% cache 3600 mashhur_mahsulotlar %}
    {% for mahsulot in eng_kop_sotilganlar %}
        <div>{{ mahsulot.nomi }}</div>
    {% endfor %}
{% endcache %}
```

### Kesh eskirishi (invalidation) muammosi

Dasturlashdagi mashhur gap: *"Kompyuter fanida ikkita qiyin narsa bor: keshni bekor qilish va nomlarga ism qo'yish."* Muammo shunda: agar yangi buyurtma tushib, "eng ko'p sotilganlar" ro'yxati o'zgarishi kerak bo'lsa-yu, kesh hali 1 soat "yangi" hisoblansa — foydalanuvchi **eskirgan** ma'lumotni ko'radi. Buni ikki yo'l bilan boshqarish mumkin: (a) qisqaroq `timeout` qo'yish (masalan 5 daqiqa — ma'lumot biroz eskirishi mumkin, lekin muammo emas), yoki (b) ma'lumot o'zgargan **payt**da, kodning o'zida, keshni qo'lda o'chirish:

```python
from django.core.cache import cache

def buyurtma_yaratish(request):
    buyurtma = Buyurtma.objects.create(...)
    cache.delete("eng_kop_sotilganlar")   # eskirgan keshni darhol o'chiramiz
    return redirect(...)
```

## Amaliy misol

`onlayn_dokon`ning bosh sahifasida "eng ko'p sotilgan mahsulotlar" blokini keshlash:

```python
# apps/dokon/services.py
from django.core.cache import cache
from django.db.models import Sum
from .models import Mahsulot

KESH_KALITI = "eng_kop_sotilganlar"
KESH_MUDDATI = 60 * 30   # 30 daqiqa


def eng_kop_sotilganlarni_olish():
    natija = cache.get(KESH_KALITI)
    if natija is None:
        natija = list(
            Mahsulot.objects.annotate(sotilgan=Sum("buyurtmaelementi__soni"))
            .filter(sotilgan__isnull=False)
            .order_by("-sotilgan")[:10]
        )
        cache.set(KESH_KALITI, natija, timeout=KESH_MUDDATI)
    return natija


def sotilganlar_keshini_tozalash():
    cache.delete(KESH_KALITI)
```

```python
# apps/dokon/views.py
from .services import eng_kop_sotilganlarni_olish

def bosh_sahifa(request):
    context = {"mashhur_mahsulotlar": eng_kop_sotilganlarni_olish()}
    return render(request, "dokon/bosh_sahifa.html", context)
```

```python
# apps/dokon/signals.py — buyurtma yaratilganda avtomatik keshni tozalash
from django.db.models.signals import post_save
from django.dispatch import receiver
from .models import Buyurtma
from .services import sotilganlar_keshini_tozalash


@receiver(post_save, sender=Buyurtma)
def buyurtma_saqlanganda(sender, instance, created, **kwargs):
    if created:
        sotilganlar_keshini_tozalash()
```

Sinov — Django shell orqali kesh ishlashini tekshirish:


Ikkinchi chaqiruv ~40 marta tezroq — chunki ma'lumotlar bazasiga umuman murojaat qilinmadi, natija to'g'ridan-to'g'ri Redis'dan (xotiradan) o'qildi.

## Keng tarqalgan xatolar

**Xato 1:** Kesh kalitini (key) statik, hardcoded satr sifatida yozib, turli parametrlar uchun bir xil keshdan foydalanib qo'yish.

❌ `cache.set("mahsulotlar", natija)` — agar bu funksiya turli parametr bilan (masalan turli `bolim_id` uchun) chaqirilsa, barcha chaqiruvlar **bir xil** kesh kalitini ishlatadi, natijada birinchi bo'lim uchun hisoblangan natija, ikkinchi bo'lim so'ralganda ham (noto'g'ri) qaytariladi.

✅ Kesh kalitiga parametrlarni **kiriting**: `cache.set(f"mahsulotlar_bolim_{bolim_id}", natija)` — har bir noyob parametr kombinatsiyasi uchun alohida kalit.

**Xato 2:** `timeout=None` (cheksiz) qo'yib, keshni hech qachon avtomatik eskirmaydigan qilib qo'yish.

❌ `cache.set(key, natija, timeout=None)` — ma'lumot **hech qachon** o'zi eskirmaydi; agar qo'lda `cache.delete()` chaqirilishi unutilsa (masalan yangi kod yo'lida), foydalanuvchilar **abadiy eskirgan** ma'lumotni ko'rishda davom etadi.

✅ Har doim **oqilona** `timeout` qiymati bering (daqiqalar yoki soatlar) — bu, hatto invalidation kodida xato bo'lsa ham, ma'lumot oxir-oqibat o'zi yangilanishini kafolatlaydi ("eventual consistency").

**Xato 3:** Har doim o'zgarib turadigan (masalan foydalanuvchiga xos) ma'lumotni keshlash.

❌ `@cache_page(60*15)` butun "Mening profilim" sahifasiga qo'yilgan — bu sahifa **har bir foydalanuvchi uchun boshqacha**; Django'ning standart kesh kaliti URL'ga asoslangani uchun, birinchi foydalanuvchi ko'rgan sahifa, keyingi **boshqa** foydalanuvchiga ham (noto'g'ri!) ko'rsatilishi mumkin.

✅ Foydalanuvchiga xos yoki tez-tez o'zgaradigan sahifalarni **keshlamang**; faqat barcha (yoki ko'pchilik) foydalanuvchi uchun bir xil, kamdan-kam o'zgaradigan ma'lumotni (mahsulotlar ro'yxati, statistika) keshlang.

## Mashq/topshiriq

**(Oson)** `django-redis`ni o'rnating, `CACHES` sozlamasini qo'shing (Celery'nikidan alohida Redis baza raqami bilan). Django shell orqali `cache.set("test", "salom")` va `cache.get("test")`ni sinab ko'ring.

**(O'rtacha)** `eng_kop_sotilganlarni_olish()` funksiyasini yozing, uni ikki marta ketma-ket chaqirib, ikkinchi chaqiruv sezilarli tezroq ekanini `time.time()` yordamida o'lchang.

**(Qiyin)** `post_save` signalini yozib, yangi `Buyurtma` yaratilganda, `eng_kop_sotilganlar` keshini avtomatik tozalang. Keshni to'ldiring, yangi buyurtma yarating, va keshning **darhol** tozalanganini (`cache.get(...)` `None` qaytarishini) tasdiqlang.

## Qisqacha xulosa

`django-redis` — Django'ning ichki kesh tizimini Redis'ga ulab, tez-tez so'raladigan, lekin kamdan-kam o'zgaradigan ma'lumotlarni (funksiya natijasi, butun sahifa, yoki template qismi) xotirada saqlab, ma'lumotlar bazasiga takroriy og'ir so'rovlar yubormaslikka yordam beradi; asosiy qiyinchilik — **qachon** keshni eskirgan deb hisoblash (invalidation), buni oqilona `timeout` va kerak bo'lganda qo'lda `cache.delete()` (masalan signal orqali) bilan boshqarish mumkin. Shu bilan 07-bob (fon vazifalar va kesh) yakunlandi — keyingi bobda `onlayn_dokon`ning **sifatini** ta'minlaydigan kutubxonalarni (`pytest-django`, `factory_boy`, `coverage.py`) ko'rib chiqamiz.
