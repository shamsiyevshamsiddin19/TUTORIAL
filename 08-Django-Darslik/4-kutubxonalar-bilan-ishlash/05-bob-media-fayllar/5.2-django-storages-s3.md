# 5.2. django-storages + boto3 — bulutli saqlash (S3-mos xizmatlar)

## Bu darsda nimalarni o'rganasiz

- Production'da media fayllarni **server diskida** saqlashning nega muammoli ekanini tushunasiz
- `django-storages` va `boto3`ni o'rnatib, S3-mos xizmat bilan integratsiya qilishni o'rganasiz
- `STORAGES` sozlamasi orqali `default` (media) storage'ni bulutga o'tkazishni o'rganasiz
- AWS kalitlarini xavfsiz, `.env` orqali saqlashni (2.1-darsdagi bilim asosida) qo'llaysiz

## Nazariy qism

### Muammo: local disk storage

3.2-darsda `whitenoise` orqali **statik** fayllarni (loyihaning o'zi bilan keladigan CSS/JS) to'g'ri xizmat qilishni ko'rdik. Lekin **media** fayllar (foydalanuvchi yuklagan mahsulot rasmlari) — butunlay boshqa holat: ular runtime'da, foydalanuvchi tomonidan yaratiladi.

Agar bu fayllar serverning oddiy diskida saqlansa, ikkita jiddiy muammo bo'lishi mumkin:

1. **Konteynerli (Docker) muhitda fayllar yo'qoladi.** Docker konteyneri, standart holda, **vaqtinchalik** (ephemeral) — konteyner qayta ishga tushirilganda (masalan yangi kod deploy qilinganda), diskdagi barcha o'zgarishlar (shu jumladan yuklangan rasmlar) yo'qoladi, agar alohida "volume" ulanmagan bo'lsa.
2. **Ko'p-server (load balancer) muhitda fayllar ko'rinmaydi.** Agar loyihangiz bir nechta server nusxasida (load balancer orqasida) ishlasa, bitta serverga yuklangan rasm, foydalanuvchi keyingi so'rovda **boshqa** serverga yo'naltirilsa, u yerda "topilmaydi".

Yechim — media fayllarni serverning o'z diskida emas, **markazlashgan**, barcha serverlar bir xil kira oladigan bulutli saqlash xizmatida (Amazon S3 yoki unga mos boshqa xizmatlar) saqlash.

### django-storages + boto3 yechimi

```bash
pip install django-storages boto3
```

`boto3` — Amazon Web Services (AWS) bilan ishlash uchun rasmiy Python kutubxonasi; `django-storages` — Django'ning fayl saqlash tizimini (Storage API) turli bulutli xizmatlarga (S3, Google Cloud Storage, Azure) ulaydigan "ko'prik".

```
# .env
AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
AWS_STORAGE_BUCKET_NAME=onlayn-dokon-media
AWS_S3_REGION_NAME=eu-north-1
```

```python
# settings.py
STORAGES = {
    "default": {
        "BACKEND": "storages.backends.s3.S3Storage",
    },
    "staticfiles": {
        "BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage",
    },
}

AWS_ACCESS_KEY_ID = env("AWS_ACCESS_KEY_ID")
AWS_SECRET_ACCESS_KEY = env("AWS_SECRET_ACCESS_KEY")
AWS_STORAGE_BUCKET_NAME = env("AWS_STORAGE_BUCKET_NAME")
AWS_S3_REGION_NAME = env("AWS_S3_REGION_NAME")
AWS_S3_FILE_OVERWRITE = False   # bir xil nomli fayl yuklansa, eskisini bosib yozmaydi, nom o'zgartiradi
AWS_DEFAULT_ACL = None          # bucket sozlamasiga tayanadi (odatda xususiy)
```

`STORAGES["default"]` — Django 4.2'dan boshlab, `MEDIA`ga tegishli barcha `FileField`/`ImageField` qaysi "backend" orqali saqlanishini belgilaydi. Shu qatorni almashtirish bilan, kodning **qolgan qismini** (modellar, view'lar) o'zgartirmasdan, fayllar avtomatik S3'ga yo'naltiriladi.

### Development uchun local, production uchun S3

2.2-darsda qurgan `settings/` strukturasidan foydalanib, bu farqni muhitlar orasida ajratamiz:

```python
# onlayn_dokon/settings/development.py
from .base import *  # noqa
# STORAGES o'zgartirilmaydi — standart FileSystemStorage, media/ papkasida
```

```python
# onlayn_dokon/settings/production.py
from .base import *  # noqa

STORAGES = {
    "default": {"BACKEND": "storages.backends.s3.S3Storage"},
    "staticfiles": {"BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage"},
}
AWS_ACCESS_KEY_ID = env("AWS_ACCESS_KEY_ID")
AWS_SECRET_ACCESS_KEY = env("AWS_SECRET_ACCESS_KEY")
AWS_STORAGE_BUCKET_NAME = env("AWS_STORAGE_BUCKET_NAME")
AWS_S3_REGION_NAME = env("AWS_S3_REGION_NAME")
```

Shunday qilib, rivojlantirish paytida (development) fayllar hamon oddiy, mahalliy `media/` papkasida saqlanadi (tez, oson tekshirish uchun), production'da esa avtomatik S3'ga o'tadi — kodning boshqa hech qanday qismini o'zgartirmasdan.

## Amaliy misol

`onlayn_dokon`ning `Mahsulot.rasm` maydoni — production'da S3'ga saqlanadigan holga keltirish:

```bash
pip install django-storages boto3
```

```
# .env (faqat production serverda mavjud bo'ladi, .env.example'da bo'sh qoldiriladi)
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=...
AWS_STORAGE_BUCKET_NAME=onlayn-dokon-media
AWS_S3_REGION_NAME=eu-north-1
```

```python
# onlayn_dokon/settings/production.py
from .base import *  # noqa

INSTALLED_APPS += ["storages"]

STORAGES = {
    "default": {"BACKEND": "storages.backends.s3.S3Storage"},
    "staticfiles": {"BACKEND": "whitenoise.storage.CompressedManifestStaticFilesStorage"},
}

AWS_ACCESS_KEY_ID = env("AWS_ACCESS_KEY_ID")
AWS_SECRET_ACCESS_KEY = env("AWS_SECRET_ACCESS_KEY")
AWS_STORAGE_BUCKET_NAME = env("AWS_STORAGE_BUCKET_NAME")
AWS_S3_REGION_NAME = env("AWS_S3_REGION_NAME")
AWS_S3_FILE_OVERWRITE = False
```

```bash
DJANGO_SETTINGS_MODULE=onlayn_dokon.settings.production python manage.py shell
```

```python
>>> from apps.dokon.models import Mahsulot
>>> m = Mahsulot.objects.first()
>>> m.rasm.url
'https://onlayn-dokon-media.s3.eu-north-1.amazonaws.com/mahsulotlar/krossovka.jpg'
```

Admin panel orqali rasm qayta yuklansangiz, u endi serverning o'z diskiga emas, to'g'ridan-to'g'ri S3 bucket'iga yuklanadi — `m.rasm.url` ham S3 manzilini qaytaradi, serverning o'z domenini emas.

## Keng tarqalgan xatolar

**Xato 1:** AWS kalitlarini to'g'ridan-to'g'ri `settings.py`ga yozib qo'yish.

❌ `AWS_SECRET_ACCESS_KEY = "wJalrXUtnFEMI/K7MDENG..."` — kod ichida, qattiq yozilgan (hardcoded). Bu, 2.1-darsda o'rgangan asosiy qoidani buzadi: agar kod Git'ga tushsa, AWS hisobingizga **to'liq** kirish huquqiga ega kalit ochiq qoladi — bu hatto `SECRET_KEY`dan ham xavfliroq (moliyaviy zarar yetkazish mumkin).

✅ AWS kalitlarini **har doim** `.env` orqali, `env("AWS_ACCESS_KEY_ID")` uslubida o'qing — bu darslikda hech qachon istisno qilinmaydigan qoida.

**Xato 2:** S3 bucket'ni "hammaga ochiq" (public) qilib, maxfiy fayllarni ham shu tarzda saqlash.

❌ Bucket sozlamasi barcha fayllarni internetdan **istalgan kishi** ko'rishi mumkin qilib qo'yilgan — agar shu bucket'da foydalanuvchi hujjatlari (masalan pasport nusxasi) ham saqlansa, bu jiddiy maxfiylik buzilishi.

✅ Faqat haqiqatan ommaviy bo'lishi kerak bo'lgan fayllar (mahsulot rasmlari kabi) uchun ochiq ruxsatdan foydalaning; maxfiy fayllar uchun `django-storages`ning **vaqtinchalik, imzolangan URL** (presigned URL) imkoniyatidan foydalaning — bu mavzu chuqurroq, AWS hujjatlarida batafsil yoritilgan.

**Xato 3:** Development va production uchun **bitta xil** S3 bucket ishlatish.

❌ Rivojlantirish paytidagi sinov fayllari (masalan "test.jpg" nomli tasodifiy rasmlar) production bucket'iga tushib qoladi — bu, haqiqiy mahsulot rasmlari orasida chalkashlik va tartibsizlik tug'diradi.

✅ Har bir muhit (development, staging, production) uchun **alohida** bucket (masalan `onlayn-dokon-media-dev`, `onlayn-dokon-media-prod`) yarating — `.env` fayllar orqali oson ajratiladi.

## Mashq/topshiriq

**(Oson)** `django-storages` va `boto3`ni o'rnating, `requirements.txt`ni yangilang.

**(O'rtacha)** `production.py`da `STORAGES["default"]`ni S3'ga sozlang, `.env.example`ga kerakli 4 ta AWS o'zgaruvchisini (qiymatlarsiz) qo'shing.

**(Qiyin)** `AWS_S3_FILE_OVERWRITE = False` sozlamasining nima uchun kerakligini tushuntiring: agar ikkita foydalanuvchi, bir xil nomli (`rasm.jpg`) faylni ketma-ket yuklasa, bu sozlama yoqilgan va o'chirilgan holatlarda nima farq qilishini yozib bering.

<details>
<summary>Javoblarni ko'rish</summary>

1-2. `pip install django-storages boto3`; `production.py`ga yuqoridagi "Amaliy misol"dagi `STORAGES`, `AWS_*` qatorlari qo'shiladi; `.env.example`ga `AWS_ACCESS_KEY_ID=`, `AWS_SECRET_ACCESS_KEY=`, `AWS_STORAGE_BUCKET_NAME=`, `AWS_S3_REGION_NAME=` (qiymatlarsiz) qo'shiladi.

3. `AWS_S3_FILE_OVERWRITE = False` bo'lganda: ikkinchi "rasm.jpg" yuklanganda, `django-storages` avtomatik **noyob** nom generatsiya qiladi (masalan `rasm_A3f8Kd.jpg`) — ikkala fayl ham saqlanib qoladi, birinchisi yo'qolmaydi. `True` bo'lsa (yoki sozlanmagan standart holatda ba'zi versiyalarda): ikkinchi fayl **birinchisining ustidan yozib yuboriladi** — birinchi foydalanuvchining rasmi butunlay yo'qoladi, bu odatda kutilmagan, xohlanmagan xatti-harakat.

## Qisqacha xulosa

`django-storages` (+ `boto3`) — Django'ning `STORAGES["default"]` sozlamasi orqali, media fayllarni serverning o'z diskidan, markazlashgan bulutli xizmatga (S3-mos) ko'chirish imkonini beradi — bu, konteynerli va ko'p-serverli production muhitlarida fayllarning yo'qolib qolmasligini ta'minlaydi. AWS kalitlari **har doim** `.env` orqali saqlanishi, development va production uchun **alohida** bucket ishlatilishi, va `AWS_S3_FILE_OVERWRITE = False` orqali fayllarning tasodifan bir-birini bosib yozib yubormasligi — asosiy xavfsizlik va ishonchlilik qoidalari. Bu bilan 05-bob yakunlandi — keyingi bobda `onlayn_dokon`ning API qatlamini (`drf-spectacular`, `django-filter`, `django-cors-headers` bilan) kengaytiramiz.
